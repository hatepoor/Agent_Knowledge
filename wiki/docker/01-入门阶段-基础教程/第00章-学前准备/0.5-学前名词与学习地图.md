## 一、最小可用心智模型

如果只允许记住一张图，就是这张。**Docker 的一切都在回答三个问题：跑什么、怎么跑、在哪跑。**

```
Dockerfile ──build──→ 镜像(image) ──run──→ 容器(container)
   ↑                      ↑                    ↑
"怎么造"               "造出什么"           "跑起来是什么"
                          │
                        push/pull
                          ↓
                    仓库(registry)
                      "存哪里"

容器运行时的三个附加要素：
  ├── 卷(volume)     → 数据存在哪（容器删了数据还在）
  ├── 网络(network)  → 怎么和别的容器/外界通信
  └── 资源限制        → 能用多少 CPU / 内存
```

**三句话记住核心：**

| 名词 | 一句话 |
|------|--------|
| 镜像 | 只读模板，是"菜谱" |
| 容器 | 镜像的运行实例，是"做出来的菜"，可起很多份 |
| 仓库 | 镜像的存放处，是"图书馆" |

| 名词 | 一句话 | 详解位置 |
|------|--------|----------|
| **命名空间 / namespace** | 内核机制，让进程"看不见"别人的进程、网络、文件系统。**容器隔离的来源** | [[docker/02-中段阶段-专题精讲/容器安全加固/专题概览]] |
| **控制组 / cgroup** | 内核机制，限制进程组能用多少 CPU/内存。**资源限制的来源** | [[docker/02-中段阶段-专题精讲/资源限制与性能/专题概览]] |
| **runc / containerd** | 真正负责创建进程的底层程序 | [[docker/01-入门阶段-基础教程/第00章-学前准备/0.2-Docker的组成与运行架构]] |

> ⚠️ **关于 2.5 节的阅读顺序**：`namespace` 和 `cgroup` 在入门阶段**不会展开讲**，只是让你"眼熟"。看到教程里出现这两个词却不解其意，是正常的——它们在第 02 中段的 [[docker/02-中段阶段-专题精讲/容器安全加固/专题概览]] 与 [[docker/02-中段阶段-专题精讲/资源限制与性能/专题概览]] 会讲透。

## 三、入门阶段学习地图

```
第00章 学前准备              ← 你在这里
  └─ 装好环境、跑通第一个容器、看懂报错、认识名词
        ↓ 没有前置知识要求，但必须走完
第01章 镜像与容器基础操作
  └─ 会管镜像、会控制容器生命周期、会看日志与进程
        ↓ 先会"用别人的镜像"
第02章 镜像构建与 Dockerfile
  └─ 会写自己的 Dockerfile，理解分层与缓存
        ↓ 有了自己的镜像
第03章 数据卷与容器网络
  └─ 数据不丢、容器能互通、端口正确暴露
        ↓ 单容器能力补齐
第04章 多容器编排 Compose
  └─ 一条命令起一套服务
        ↓ 到这里"能独立容器化一套服务"
第05章 资源限制与日常维护
  └─ 会限资源、会看占用、会清理、会排错
        ↓ 为进入中段阶段做准备
  中段阶段（平行专题，可跳读）
```

### 每章解决什么问题

| 章 | 一句话目标 | 学完的标志 |
|----|-----------|-----------|
| 第00章 | 打通环境 | 能跑通 `hello-world`，能判断报错层次 |
| 第01章 | 会用给的镜像 | 能拉镜像、起容器、看日志、进容器 |
| 第02章 | 会造自己的镜像 | 能写出一个可以部署的 Dockerfile |
| 第03章 | 解决数据与通信 | 数据不丢、容器能互相调用 |
| 第04章 | 解决多容器协作 | 一条 `docker compose up -d` 起全栈 |
| 第05章 | 解决运维问题 | 能限资源、能排查、能清理 |

### 依赖关系（为什么必须按顺序）

```
第00章 ─→ 第01章 ─→ 第02章
                └──→ 第03章 ─→ 第04章 ─→ 第05章
```

| 依赖 | 原因 |
|------|------|
| 第01章 ← 第00章 | 不装好环境，命令都敲不了 |
| 第02章 ← 第01章 | 不知道镜像是什么，无法理解 Dockerfile 在构建什么 |
| 第03章 ← 第01章 | 卷与网络都是 `docker run` 的参数，要先会 `run` |
| 第04章 ← 第03章 | Compose 就是把卷与网络的写法搬进配置文件 |
| 第05章 ← 全部 | 排错需要前面所有概念 |

## 四、初学者最常见的 8 个认知误区

| # | 误区 | 事实 | 详解 |
|---|------|------|------|
| 1 | 容器是"轻量级虚拟机" | 完全不同的机制：容器是**进程级隔离**，没有独立内核 | [[docker/01-入门阶段-基础教程/第00章-学前准备/0.1-容器与Docker是什么]] |
| 2 | 容器删了数据就没了 | **只有没挂卷的容器**才是这样。数据卷独立于容器 | [[docker/01-入门阶段-基础教程/第03章-数据卷与容器网络/3.1-数据卷与绑定挂载]] |
| 3 | `docker run` 和 `docker start` 是一回事 | `run` 是**创建新容器**，`start` 是**启动已有的** | [[docker/01-入门阶段-基础教程/第01章-镜像与容器基础操作/1.2-容器的创建与运行]] |
| 4 | `docker ps` 看不到就是没跑 | 退出码非 0 的容器要用 `docker ps -a` 才看得到 | [[docker/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]] |
| 5 | 容器里应该跑多个服务 | 一个容器一个主进程是推荐做法；多服务拆多容器 | [[docker/01-入门阶段-基础教程/第04章-多容器编排Compose/4.1-Compose是什么与文件结构]] |
| 6 | 用 `latest` 标签最省事 | `latest` 不保证是最新版，只是**没指定时的默认值**。生产必须固定版本 | [[docker/01-入门阶段-基础教程/第01章-镜像与容器基础操作/1.1-镜像的获取与管理]] |
| 7 | 容器之间可以用 `localhost` 互访 | `localhost` 在容器里指**它自己**。要用**服务名**或容器名 | [[docker/01-入门阶段-基础教程/第03章-数据卷与容器网络/3.2-容器网络模型]] |
| 8 | `-p 80:8080` 和 `-p 8080:80` 差不多 | 完全不同。**左边宿主，右边容器**，写反就访问不到 | [[docker/01-入门阶段-基础教程/第03章-数据卷与容器网络/3.3-端口映射与访问]] |

## 五、三条学习建议

1. **每个命令都亲手敲一遍。** Docker 是纯操作技能。看会了和敲会了是两件事——特别是端口映射、卷挂载这两个点，不亲手验证过就一定会写错。
2. **读命令时逐段拆解。** 看到一条长命令，先按"哪个是容器名、哪个是宿主的、哪个是容器的"逐段标注。这是最高效的训练方式。
3. **遇到不认识的名词立刻查，不要跳过。** [[docker/Docker命令与术语手册]] 就是为此存在的。跳过三次之后，整篇就读不懂了。

## 小结

| 要点 | 内容 |
|------|------|
| 最小心智模型 | Dockerfile →（build）镜像 →（run）容器；仓库负责存取；卷/网络/资源限制是运行期的三个附加维度 |
| 三件套 | 镜像（模板）、容器（实例）、仓库（存放处） |
| 六章顺序 | 00 环境 → 01 用镜像 → 02 造镜像 → 03 数据与网络 → 04 编排 → 05 运维 |
| 底层术语 | `namespace` / `cgroup` 只求眼熟，中段才展开 |
| 最大误区 | 把容器当虚拟机；用 `localhost` 互访容器；端口映射写反；不用 `--rm` 积累垃圾容器 |
