# 跑通第一个容器

## 学习目标

读完并动手完成本篇，你应当能够：

1. 在自己的机器上装出可用的 Docker 环境，并说清 Windows 上为什么必须依赖 WSL 2
2. 用三条命令确认环境是健康的
3. 成功启动一个 nginx 容器，并从浏览器访问到它
4. 配置镜像加速器，解决"拉取超时"问题

## 一、Windows 用户：先做三项检查

Windows 上 Docker 的安装门槛主要不在 Docker 本身，而在**系统是否满足前提**。先把这三项确认完，能避开 90% 的安装失败。

### 检查 1：系统版本

| 要求 | 说明 |
|------|------|
| **Windows 11** | 23H2（build 22631）或更高 |
| **Windows 10** | 22H2（build 19045），且为 **Pro / Enterprise / Education** 版 |
| **Windows 家庭版** | 可以安装，但**只能运行 Linux 容器**，无法运行 Windows 容器 |
| **Windows Server** | ❌ **不支持 Docker Desktop**，需改用服务端方案 |

查看方法：按 `Win + R`，输入 `winver`，回车。

### 检查 2：硬件虚拟化是否已开启

容器在 Windows 上跑在一个轻量 Linux 虚拟机里，所以**必须开启硬件虚拟化**（这是 CPU 的功能，需要在 BIOS/UEFI 里开）。

**检查方式**：打开任务管理器（`Ctrl + Shift + Esc`）→「性能」→「CPU」→ 看右下角是否有「虚拟化：已启用」。

若显示"已禁用"，需要重启进入 BIOS/UEFI，找到 `Intel VT-x` / `AMD-V`（或叫 `SVM Mode`、`Virtualization Technology`）并启用。

### 检查 3：WSL 2 是否可用

WSL 全称 **Windows Subsystem for Linux**（Windows 上的 Linux 子系统），版本 2 提供真正的 Linux 内核。

```bash
wsl --version
```

要求 **WSL 2.1.5 或更高**。若没装或版本过低：

```bash
wsl --install            # 首次安装（会自动启用所需 Windows 功能，可能需重启）
wsl --update             # 更新到最新版
wsl --set-default-version 2   # 确保默认用 WSL 2
```

**其他要求**：64 位处理器且支持 SLAT、内存至少 8 GB。

## 二、安装 Docker Desktop（Windows / macOS）

| 平台 | 获取方式 |
|------|----------|
| Windows | 从 <https://www.docker.com/products/docker-desktop/> 下载 `Docker Desktop Installer.exe` |
| macOS | 同页面下载对应芯片版本（Apple 芯片 / Intel 芯片） |

**Windows 安装要点**

1. 双击安装包，安装程序会问安装模式：
   - **per-user**（当前版本默认）：装到 `%LOCALAPPDATA%\Programs\DockerDesktop`，**不需要管理员权限**
   - **all users**：需要提权，且需把用户加入 `docker-users` 组
2. 安装向导的配置页会让选择后端：钩选 **"Use WSL 2 instead of Hyper-V"**（推荐）
3. 安装完成后**必须手动启动 Docker Desktop**（它不会自动启动）

> ⚠️ **关于 `docker-users` 组的警告**：加入该组等于**授予宿主机管理员等价权限**（因为可以起特权容器）。只给确实需要的人加。

**验证 Docker Desktop 已就绪**：托盘出现鲸鱼图标，且状态为 `Engine running`。

## 三、安装 Docker Engine（Linux）

Linux 上不需要 Docker Desktop（那是给 Windows/macOS 补 Linux 环境用的），直接装 Engine。

### 方式 A：官方便捷脚本（最快，适合个人开发机）

```bash
curl -fsSL https://get.docker.com | sh
```

### 方式 B：官方软件源（推荐生产使用，可受控升级）

按发行版从 <https://docs.docker.com/engine/install/> 选择对应步骤（apt / dnf / yum / zypper）。

### 装完必做的两件事

```bash
# ① 把当前用户加入 docker 组 —— 免去每条命令前都加 sudo
sudo usermod -aG docker $USER
#    注意：必须重新登录（或执行 newgrp docker）才生效

# ② 设置开机自启并立即启动
sudo systemctl enable --now docker

# ③ 验证
docker run --rm hello-world
```

> ⚠️ **安全提示**：`docker` 组成员可访问 docker socket，等价于 root 权限。在多用户共享的服务器上，这需要谨慎评估——见 [[docker/02-中段阶段-专题精讲/容器安全加固/专题概览]]。

## 四、验证环境：三条命令

安装完成后，按顺序跑这三条。**每一条都在验证不同层次**（回忆 0.2 节的架构）。

### 命令 1：版本检查

```bash
docker version
```

**看什么**：输出分 `Client` 与 `Server` 两段。

```
Client:
 Version:           29.8.1
Server:  Docker Engine
 Engine:
  Version:          29.8.1
```

| 现象 | 含义 | 处理 |
|------|------|------|
| 只有 `Client` 段，`Server` 报 `Cannot connect...` | 客户端装好了，服务端没起来 | 启动 Docker Desktop；Linux 上 `sudo systemctl start docker` |
| 两端版本不一致且相差大 | 可能是远程连接或残留配置 | Linux 上检查 `docker context ls` |
| `docker: command not found` | 客户端都没装好 | 检查安装与 PATH |

### 命令 2：环境信息

```bash
docker info
```

**看什么**：确认关键信息符合预期。

| 字段 | 应该看到什么 | 若不对 |
|------|--------------|--------|
| `Server Version` | 有版本号 | 服务端未运行 |
| `Storage Driver` | `overlay2` 或 `containerd` 相关字样 | 异常值需查存储后端 |
| `Cgroup Version` | `2`（现代系统） | `1` 是旧系统，部分限制行为不同 |
| `Total Memory` | 与宿主机内存量级一致 | —— |
| `Registry Mirrors` | 配置加速器后有值 | 见下节 |

### 命令 3：端到端验证

```bash
docker run --rm hello-world
```

出现 `Hello from Docker!` 就算通了。这条命令干了完整的一轮：**从仓库拉镜像 → 创建容器 → 运行 → 输出 → 自动删除**（`--rm`）。

| 报错 | 原因 |
|------|------|
| `WARNING: retrying in ...` 反复出现 | 网络问题，配置镜像加速器 |
| `permission denied`（Linux） | 未加入 docker 组，或未重新登录 |

## 五、配置镜像加速器（国内环境强烈建议）

### 为什么会慢

`docker pull` 要从 Docker Hub 拉取，国内访问经常超时。解决办法是**配置镜像加速器**（也叫 registry mirror，第三方镜像源）。

### Linux 配置方式

编辑 `/etc/docker/daemon.json`（不存在则新建）：

```json
{
  "registry-mirrors": ["https://<你的加速器地址>"],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

> 后半段的日志配置**不要省略**：默认日志不做轮转，长期运行的容器会把宿主机磁盘写满（见 [[docker/01-入门阶段-基础教程/第05章-资源限制与日常维护/5.2-磁盘占用与日志清理]]）。

重载配置：

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | grep -A 2 "Registry Mirrors"   # 确认生效
```

### Windows / macOS 配置方式

Docker Desktop →「Settings」→「Docker Engine」，在 JSON 里加入同样的 `registry-mirrors` 字段，点「Apply & Restart」。

> **加速器地址会变动**，且部分公共加速器已停止服务。请以你实际可用的地址为准，或使用云厂商提供的专属加速地址。

### ⚠️ 加速器不是万能的

| 局限 | 说明 |
|------|------|
| 只加速**拉取**，不加速推送 | `docker push` 仍走原路线 |
| 可能**不包含所有镜像** | 冷门镜像仍需回源，可能失败 |
| **降低可信度** | 第三方镜像源的镜像内容不受 Docker 官方保证 |
| 生产环境应自建 | 用 Harbor 等搭建私有仓库，见 [[docker/02-中段阶段-专题精讲/CI-CD与镜像分发/专题概览]] |

## 六、跑第一个真正有用的容器：nginx

`hello-world` 只是探测，现在跑一个会持续提供服务的容器。

```bash
docker run -d --name my-web -p 8080:80 nginx:1.27-alpine
```

**逐段拆解这条命令**（这就是"读命令"的能力训练）：

| 片段 | 含义 | 为什么这么写 |
|------|------|--------------|
| `docker run` | 创建并启动一个新容器 | —— |
| `-d` | 后台运行（detached） | 不加的话，终端会被 nginx 日志占住，`Ctrl+C` 会把容器也停掉 |
| `--name my-web` | 给容器取名 `my-web` | 不写会得到随机名，后续命令要复制粘贴一串随机字符串 |
| `-p 8080:80` | 把宿主的 8080 端口映射到容器的 80 端口 | **左边是宿主，右边是容器，顺序别反** |
| `nginx:1.27-alpine` | 用 nginx 镜像的 `1.27-alpine` 标签 | 指定具体版本 + `alpine` 变体（体积小）。**生产不用 `latest`** |

然后验证：

```bash
docker ps
```

应看到 `my-web` 状态为 `Up`，端口列显示 `0.0.0.0:8080->80/tcp`。

打开浏览器访问 **<http://localhost:8080>**，看到 nginx 欢迎页即成功。

### 顺手做完这四步（都是日常高频操作）

```bash
docker logs my-web                       # 看日志
docker exec -it my-web sh                # 进容器（alpine 用 sh，不是 bash）
                                           # 进去后敲 ls /etc/nginx，然后 exit
docker stop my-web                       # 停止
docker rm my-web                         # 删除
```

> **注意 `stop` 与 `rm` 是两件事**：`stop` 只是停机（容器还在，`docker ps -a` 能看到），`rm` 才是销毁。初学者常忘记 `rm`，时间长了会积累一堆停止的容器——这也是为什么临时任务推荐加 `--rm`。

### `-it` 与 `-d` 的选择原则

| 场景 | 用什么 | 原因 |
|------|--------|------|
| 长期服务（Web、数据库） | `-d` | 不需要交互，不该占住终端 |
| 临时进 shell 调试 | `-it` | 需要交互 |
| 跑一次性脚本 | `--rm`（可加 `-it`） | 跑完自动清理 |
| **同时用 `-d` 和 `-it`** | ❌ 不推荐 | 语义矛盾，实践中容易困惑 |

## 七、安装阶段常见卡点汇总

| 现象 | 根本原因 | 解决 |
|------|----------|------|
| Docker Desktop 卡在 "Starting..." 很久 | WSL 未就绪或磁盘镜像路径不可访问 | `wsl --update`；检查设置里的磁盘位置是否可写 |
| 提示需要开启虚拟化 | BIOS 中虚拟化未开 | 进 BIOS 开 VT-x / AMD-V |
| `wsl --version` 报错或版本过低 | WSL 未装或过旧 | `wsl --install` / `wsl --update` |
| 拉取镜像一直 `retrying` | 网络受限 | 配置镜像加速器 |
| C 盘迅速变满 | 镜像与容器数据默认存在 C 盘 | Docker Desktop 设置里把磁盘镜像位置改到其他盘 |
| Linux 上每条命令都要 `sudo` | 未加入 docker 组或未重新登录 | `sudo usermod -aG docker $USER` 后**重新登录** |
| 装了 Docker Desktop 还想装 Engine | 二者冲突 | Windows/macOS 用 Desktop，Linux 用 Engine，**不要混装** |

> **关于 C 盘空间的补充**：Docker 的镜像、容器可写层、具名卷全部占用 Docker 的数据目录（Windows 上在虚拟磁盘文件里，Linux 上默认 `/var/lib/docker`）。磁盘占用分析与清理见 [[docker/01-入门阶段-基础教程/第05章-资源限制与日常维护/5.2-磁盘占用与日志清理]]。

## 小结

| 要点 | 内容 |
|------|------|
| Windows 前提 | WSL 2.1.5+、系统版本达标、BIOS 虚拟化已开、≥8 GB 内存 |
| 家庭版差异 | 只能跑 Linux 容器，不能跑 Windows 容器 |
| 安装选型 | Windows/macOS 用 Docker Desktop；Linux 用 Docker Engine |
| 验证三连 | `docker version` → `docker info` → `docker run --rm hello-world` |
| 镜像加速器 | 解决拉取超时；只加速拉取；生产应自建私有仓库 |
| 第一条实用命令 | `docker run -d --name my-web -p 8080:80 nginx:1.27-alpine` |
| 端口方向 | `-p 宿主:容器`，**左宿主右容器** |

## 练习

1. **完整走一遍**：安装 → `docker version` → `docker info` → `hello-world` → 启动 nginx → 浏览器访问 → `stop` → `rm`。每一步都记录看到的输出。
2. **读命令**：不看本篇，说出这条命令每个片段的含义：
   ```bash
   docker run -d --name db -p 5432:5432 -e POSTGRES_PASSWORD=secret postgres:18
   ```
   （提示：`-e` 是设置环境变量，见 [[docker/Docker命令与术语手册]]）
3. **制造一个错误**：故意把镜像名写错（如 `ngix`），观察报错，判断它属于哪一层。
4. **验证端口方向**：把 `-p 8080:80` 改成 `-p 9090:80`，重新启动容器，确认访问端口变成了 `9090`。
