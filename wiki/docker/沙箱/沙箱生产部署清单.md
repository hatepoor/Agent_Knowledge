# 沙箱生产部署清单

从开发到生产，Docker 沙箱需要逐项确认的关键配置。

## 一、镜像管理

| 检查项 | 说明 |
|--------|------|
| □ 使用 slim/alpine 镜像 | `python:3.11-slim`（~50MB）而非 `python:3.11`（~350MB） |
| □ 固定镜像版本 | 用 `python:3.11.9-slim` 而非 `python:3.11-slim`（避免版本漂移） |
| □ 使用镜像 digest | `python:3.11-slim@sha256:abc...` 防止供应链攻击 |
| □ CI 中集成漏洞扫描 | `trivy image --severity HIGH,CRITICAL` |
| □ 非 root 用户 | `USER 1000:1000` |
| □ 预装依赖 | 常用 pip 包预装到自定义镜像，避免每次执行时安装 |

**Dockerfile 模板**：

```dockerfile
FROM python:3.11.9-slim-bookworm@sha256:abc123...

RUN pip install --no-cache-dir \
    pandas==2.2.0 numpy==1.26.3 requests==2.31.0

RUN useradd --create-home --shell /bin/bash sandbox
USER sandbox
WORKDIR /workspace
```

## 二、资源限制

| 检查项 | 推荐值 | docker-py 参数 |
|--------|--------|---------------|
| □ 内存上限 | 256m | `mem_limit="256m"` |
| □ CPU 上限 | 1.0 核 | `nano_cpus=int(1.0 * 1e9)` |
| □ 进程数上限 | 50 | `pids_limit=50` |
| □ 磁盘 I/O 上限 | 10MB/s | `device_read_bps` / `device_write_bps` |
| □ 文件描述符上限 | 200 | `ulimits=[Ulimit("nofile", soft=100, hard=200)]` |
| □ 执行超时 | 30s | `timeout=30` |
| □ /workspace 大小上限 | 100m | `tmpfs={"/workspace": "size=100m"}` |

## 三、安全加固

| 检查项 | 配置 |
|--------|------|
| □ 根文件系统只读 | `read_only=True` |
| □ 禁用所有 capability | `cap_drop=["ALL"]` |
| □ 禁止权限提升 | `security_opt=["no-new-privileges"]` |
| □ 默认禁用网络 | `network_mode="none"` |
| □ skills 目录只读挂载 | `Mount(..., read_only=True)` |
| □ `/tmp` 不可执行 | `tmpfs={"/tmp": "size=50m,noexec"}` |
| □ 禁止挂载敏感路径 | `_validate_mount()` 校验 |
| □ 执行完自动销毁 | `remove=True` |
| □ 密钥只通过 env 传递 | `env={...}`，不写入文件 |
| □ 启用 Content Trust | `DOCKER_CONTENT_TRUST=1` |

## 四、监控与运维

| 检查项 | 指标 |
|--------|------|
| □ 结构化日志 | structlog，每条含 `container_id`/`exit_code`/`duration_ms` |
| □ 执行成功率 | `success / total`，告警阈值 < 95% |
| □ P50/P95/P99 延迟 | 监控分位延迟，告警阈值 P99 > 5s |
| □ 容器创建失败率 | 镜像拉取/daemon 异常告警 |
| □ OOM 事件 | `exit_code=137`（SIGKILL）触发告警 |
| □ 超时事件 | `exit_code=-1` 或异常分类 |
| □ Docker daemon 健康 | `docker info` 定期检查 |

## 五、容错设计

| 检查项 | 策略 |
|--------|------|
| □ 执行重试 | 瞬时 Docker 异常（连接重置）重试 2 次，指数退避 |
| □ 优雅降级 | Docker daemon 不可用时，回退到 `exec()`（本地受信环境） |
| □ 超时不重试 | 超时 = 代码问题，重试无用，直接返回失败 |
| □ 连接池 | `docker.from_env()` 创建一次，全局复用 |

## 六、Skills 集成

| 检查项 | 说明 |
|--------|------|
| □ skills 目录结构 | `skills/` 下按功能分 .md 和 .py |
| □ 挂载验证 | 启动时检查 `skills/` 是否存在，不存在给出清晰错误 |
| □ skill 大小限制 | 单个 skill 文件 < 100KB，大文件拒绝加载 |
| □ skill 版本管理 | frontmatter 含 version 字段，支持 stable/canary 双版本 |

## 七、依赖与运行环境

```txt
# requirements.txt（生产最小集）
docker>=7.1.0
langchain>=1.0.0
langchain-deepseek>=0.1.0
structlog>=24.0.0
python-dotenv>=1.0.0
```

```bash
# 启动前验证
docker info > /dev/null 2>&1 || { echo "Docker daemon 未运行"; exit 1; }
docker pull python:3.11-slim  # 预拉镜像
```

## 八、CI/CD 集成

```yaml
# .github/workflows/test.yml
- name: Test Sandbox
  run: |
    docker build -t agent-sandbox:test .
    python -m pytest tests/test_sandbox.py -v

- name: Security Scan
  run: |
    trivy image --severity HIGH,CRITICAL agent-sandbox:test
    # 有 CRITICAL 漏洞则 CI 失败
    trivy image --exit-code 1 --severity CRITICAL agent-sandbox:test
```
