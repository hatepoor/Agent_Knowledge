# Docker 学习知识库

> 本目录是一套**按学习路径三阶段组织**的 Docker 学习资料，与 [[postgresql/README|PostgreSQL 学习知识库]] 采用同构的组织方式。
>
> **一句话定位**：带你从**零基础**学到"**能独立构建镜像、用 Compose 编排多容器、把服务跑进生产**"。

## 〇、从这里开始（零基础请先读这一段）

**本套文档不假设你认识任何名词、任何命令、任何参数。**

**三条阅读原则**

1. **零基础从第 00 章开始，按章节序号推进。** 入门阶段的知识是**线性依赖**的——先懂镜像才能懂容器，先懂容器才能懂网络与卷，先懂单个容器才能懂 Compose。跳读一定会卡。
2. **每页开头的「前置知识」是必读清单，不是参考建议。** 读不懂某页，绝大多数情况是前置没读。
3. **读不懂不一定是你的问题。** 如果你发现有名词、命令、参数被"用了却没讲"，这是本套文档明确要避免的缺陷——**请直接指出，会立即补齐**。

**关于难度**：本套文档按三阶段组织，难度差别很大。

| 阶段 | 面向 | 看不懂时怎么办 |
|------|------|----------------|
| 入门 | 零基础 → 能构建镜像、能编排多容器 | 从第 00 章顺序读 |
| 中段 | 已有基础 → 会优化、会加固、会上生产 | 属于平行专题，可只挑需要的看 |
| 进阶（规划中） | 想理解容器隔离的内核原理 | **入门没学完不要看**，看不懂是正常的 |

## 一、版本基线（截至 2026-09）

Docker 的版本号体系容易混淆，先看清这张表：

| 组件 | 当前版本 | 说明 |
|------|----------|------|
| **Docker Engine** | ✅ **29.8.1**（2026-09-15） | 服务端运行时核心，即 `dockerd`。29.0 于 2025-11-10 发布 |
| **Docker Compose** | ✅ **v5.5.1**（2026-09-03） | 多容器编排工具，命令是 `docker compose`（**有空格**） |
| **Docker Desktop** | ✅ **4.91.0**（2026-09-13） | Windows / macOS 上的桌面发行包，内含 Engine 29.8.0 + Compose 5.5.1 + containerd 2.3.4 |
| **containerd** | ✅ 2.3.x | 真正干活的容器运行时，由 Engine 调用 |

**必须先知道的四个版本变更**（网上老教程大量过时，这是最常见的踩坑来源）：

| 变更 | 事实 | 后果 |
|------|------|------|
| **`docker-compose` 已被 `docker compose` 取代** | Compose v1（Python 写的，连字符命令）已废弃；v2（2020）与 v5（2025）都是 Go 写的子命令形式 | 看到教程写 `docker-compose up`，改成 `docker compose up` |
| **Compose v5 与 v2 功能等同** | v5 的唯一区别是提供了官方 Go SDK，可直接在程序里调用 Compose | 不必因为自己是 v2 而焦虑"是不是落后了" |
| **containerd 镜像存储成为新安装的默认** | 镜像存储后端由 Docker 自研存储切换到 containerd，两者镜像**不完全互通** | 老教程里 `docker save`／`docker load` 的行为可能与描述有差异 |
| **Engine 29 提高了 API 最低版本** | 最低 Engine API 提升到 1.44，**Moby/Docker 版本低于 v25 不再兼容** | 老版本的 Python `docker` SDK 连新版 Engine 会报 API 版本错误 |

> 本知识库内容以 **Engine 25+ / Compose v2+ / Docker Desktop 4.3x+** 为兼容目标，凡涉及版本差异之处均显式标注（如 `Compose v2.20+`），便于按你实际部署的版本取用。

**Windows 用户额外注意**：Docker Desktop 在 Windows 上依赖 **WSL 2**（Windows Subsystem for Linux，Windows 上的 Linux 子系统）。具体要求见 [[docker/01-入门阶段-基础教程/第00章-学前准备/0.3-跑通第一个容器]]。

## 三、为什么入门阶段要"换一种组织方式"

这不是形式主义，而是因为三类知识的结构本身不同：

1. **入门知识是线性的**——镜像讲完才能讲容器，容器讲完才能讲网络与卷。所以用**带序号的章节**强化学科顺序。
2. **中段知识是网状的**——"镜像怎么瘦身"和"网络怎么隔离"没有先后依赖，它们各自回答"某类需求该怎么做"。所以用**平行专题**，每篇自包含，可跳读。
3. **沙箱知识是场景化的**——它是"把 Docker 用于 Agent 安全"这一个具体场景的完整方案，前置门槛明确。所以**独立成专区**，不与通用教程混放。

## 四、如何使用

1. **零基础从第 00 章开始** —— [[docker/01-入门阶段-基础教程/第00章-学前准备/0.1-容器与Docker是什么]]。第 00 章不要求任何前置知识，只解决"能装好、能跑通、能看懂报错"。
2. **先读** [[docker/学习路线图]] —— 确定自己当前所处阶段与下一目标。
3. **按阶段推进** —— 入门**必须按章节顺序**；中段按需抽取；沙箱专区在前两者之后再看。
4. **卡住时查两处** —— 不认识**命令/名词**查 [[docker/Docker命令与术语手册]]；忘记**语法/参数**查 [[docker/速查索引]]。
5. **动手优先** —— 每篇末的练习都要在真实环境上敲一遍。Docker 是纯操作型技能，**仅阅读无法形成能力**。
