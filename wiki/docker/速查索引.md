# Docker 速查索引

> 语法速查。写命令、写 Dockerfile、写 compose.yaml 时先查这里，不必回翻教程。

## 一、命令总览（按操作对象分组）

| 对象 | 常用命令 |
|------|----------|
| 容器 · 生命周期 | `docker run` / `create` / `start` / `stop` / `restart` / `kill` / `rm` / `pause` / `unpause` / `wait` / `rename` / `update` |
| 容器 · 观察 | `docker ps [-a]` / `logs [-f] [--tail N]` / `stats` / `top` / `inspect` / `port` / `diff` / `events` |
| 容器 · 交互 | `docker exec -it <容器> <命令>` / `attach` / `cp` |
| 镜像 | `docker pull` / `push` / `images` / `rmi` / `tag` / `build` / `history` / `inspect` / `save` / `load` / `search` / `login` / `logout` |
| 卷 | `docker volume create` / `ls` / `inspect` / `rm` / `prune` |
| 网络 | `docker network create` / `ls` / `inspect` / `connect` / `disconnect` / `rm` / `prune` |
| 系统 | `docker system df` / `prune` / `info` / `version` / `builder prune` / `context ls` |
| 编排 | `docker compose up` / `down` / `ps` / `logs` / `exec` / `run` / `build` / `pull` / `config` / `restart` / `stop` |
| 构建进阶 | `docker buildx build --platform linux/amd64,linux/arm64` / `docker buildx ls` / `docker buildx create` |

## 二、`docker run` 骨架与参数分区

```bash
docker run [选项] <镜像名>[:tag] [命令] [命令参数...]
#          ↑ 全部选项放镜像名前           ↑ 镜像后的是"命令"，会覆盖 CMD
```

| 分区 | 参数 | 记忆点 |
|------|------|--------|
| **运行方式** | `-d` 后台 / `-it` 交互 / `--rm` 退出即删 | `-d` 与 `-it` **互斥**（同一容器二选一） |
| **命名与标识** | `--name <名>` / `--label k=v` / `--hostname <名>` | 不写 `--name` 会随机起名 |
| **端口** | `-p 8080:80` / `-P` | 左侧宿主、右侧容器；**顺序别写反** |
| **存储** | `-v <卷名或宿主路径>:<容器路径>[:ro]` / `--mount type=...,src=...,dst=...` / `--tmpfs /path` | `ro` 表示只读挂载 |
| **环境** | `-e KEY=value` / `--env-file .env` | 密钥优先用 `--env-file` 或 secrets |
| **网络** | `--network <网络名>` / `--add-host` / `--dns` | 自定义网络内可用**容器名**互访 |
| **资源限制** | `-m 512m` / `--memory-swap` / `--cpus=1.5` / `--cpuset-cpus="0,1"` / `--pids-limit=100` / `--ulimit nofile=1024:1024` | 不限制 = 可吃满宿主机 |
| **重启策略** | `--restart no` / `on-failure[:N]` / `always` / `unless-stopped` | 长期服务用 `unless-stopped` |
| **安全** | `--user 1000:1000` / `--read-only` / `--cap-drop ALL` / `--security-opt no-new-privileges` / `--privileged`（禁） | 见 [[docker/02-中段阶段-专题精讲/容器安全加固/专题概览]] |
| **日志** | `--log-driver json-file` / `--log-opt max-size=10m` / `--log-opt max-file=3` | **不加会写满磁盘** |
| **健康与启动** | `--health-cmd` / `--health-interval` / `--entrypoint` / `-w` | 覆盖 `ENTRYPOINT` 用 `--entrypoint` |

## 三、容器状态流转

```
docker create ──┐
                ├──→ created ──docker start──→ running ──docker stop──→ exited
docker run ─────┘                                │  ↑                    │
                                                 │  └──docker start──────┘
                                          docker pause
                                                 ↓
                                             paused ──docker unpause──→ running

running/exited ──docker rm (+ -f)──→ 删除
容器主进程退出(退出码 n) ──→ exited (n)   ← 常见 0 / 1 / 137 / 143
```

## 四、Dockerfile 骨架（推荐顺序）

```dockerfile
# 1) 基础镜像：指定具体版本，不用 latest
FROM python:3.12-slim

# 2) 元数据
LABEL maintainer="you@example.com"

# 3) 构建期变量（仅构建期有效）
ARG APP_HOME=/app

# 4) 环境变量（构建期 + 运行期）
ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

# 5) 工作目录（优于 RUN cd）
WORKDIR ${APP_HOME}

# 6) 先复制依赖清单 → 装依赖（利用缓存）
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

# 7) 再复制源码（源码变动不破坏上一步缓存）
COPY . .

# 8) 切非 root 用户（安全）
RUN useradd -m appuser && chown -R appuser ${APP_HOME}
USER appuser

# 9) 声明端口（仅文档性质）
EXPOSE 8000

# 10) 健康检查
HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD python -c "import urllib.request;urllib.request.urlopen('http://127.0.0.1:8000/health')" || exit 1

# 11) 启动命令（前台运行，不要用 nohup/&）
ENTRYPOINT ["python", "-m", "uvicorn"]
CMD ["app:app", "--host", "0.0.0.0", "--port", "8000"]
```

**多阶段构建骨架**

```dockerfile
# ---- 构建阶段 ----
FROM node:22 AS builder
WORKDIR /src
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# ---- 运行阶段（只带走产物）----
FROM nginx:1.27-alpine
COPY --from=builder /src/dist /usr/share/nginx/html
EXPOSE 80
```

**构建命令**

```bash
docker build -t <名字>:<tag> .                       # 基本用法，末尾 . 是构建上下文
docker build -f Dockerfile.prod -t app:prod .        # 指定 Dockerfile
docker build --build-arg ENV=prod -t app:prod .      # 传构建期变量
docker build --no-cache -t app:clean .               # 不用缓存
docker build --target builder -t app:debug .         # 只构建到某个阶段
docker build --platform linux/amd64 -t app:amd64 .   # 指定目标架构
```

## 五、compose.yaml 骨架模板

```yaml
name: myservice                 # 项目名，影响容器名前缀

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        ENV: production
    ports:
      - "8000:8000"             # 一定加引号
    volumes:
      - ./data:/app/data        # 绑定挂载
      - app-cache:/app/.cache   # 具名卷
    environment:
      - DB_HOST=db              # 服务名即主机名
      - DB_PORT=5432
    env_file:
      - .env                    # 密钥走这里，不要写进 yaml
    depends_on:
      db:
        condition: service_healthy    # 等"健康"而非仅"启动"
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 3s
      retries: 3
      start_period: 10s
    deploy:
      resources:
        limits:
          cpus: "1.0"
          memory: 512M
    networks:
      - backend

  db:
    image: postgres:18
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret       # 生产改用 secrets
      POSTGRES_DB: appdb
    volumes:
      - pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    networks:
      - backend

volumes:
  pgdata:
  app-cache:

networks:
  backend:
    driver: bridge
```

**常用命令**

```bash
docker compose up -d                 # 起全部服务（后台）
docker compose up -d --build         # 先重建镜像再起
docker compose ps                    # 看状态
docker compose logs -f app           # 追某个服务日志
docker compose exec app bash         # 进某个服务
docker compose run --rm app python x.py   # 一次性执行（不映射端口）
docker compose config                # 打印合并后的最终配置（排错）
docker compose down                  # 停并删容器与网络
docker compose down -v               # 连卷一起删（数据丢失）
docker compose up -d --scale app=3   # 扩到 3 个副本
```

**多文件合并（覆盖优先级从左到右递增）**

```bash
docker compose -f compose.yaml -f compose.prod.yaml up -d
# 约定：基础文件 compose.yaml + 覆盖文件 compose.override.yaml（自动加载）
```

## 六、常用官方镜像与关键参数

| 镜像 | 常用启动命令 | 关键点 |
|------|--------------|--------|
| `postgres:18` | `docker run -d --name pg -e POSTGRES_PASSWORD=secret -e POSTGRES_DB=app -p 5432:5432 -v pgdata:/var/lib/postgresql/data postgres:18` | 数据目录 `/var/lib/postgresql/data` **必须挂卷** |
| `redis:7-alpine` | `docker run -d --name redis -p 6379:6379 -v redisdata:/data redis:7-alpine` | 数据在 `/data`；默认无密码 |
| `nginx:1.27-alpine` | `docker run -d --name web -p 8080:80 -v ./html:/usr/share/nginx/html:ro nginx:1.27-alpine` | 静态目录 `/usr/share/nginx/html` |
| `python:3.12-slim` | `docker run -it --rm -v "$PWD":/app -w /app python:3.12-slim bash` | `-slim` 比完整版小得多 |
| `node:22-alpine` | `docker run -it --rm -v "$PWD":/app -w /app node:22-alpine sh` | Alpine 用 `sh` 不是 `bash` |
| `alpine:3.21` | `docker run -it --rm alpine sh` | 最小基础镜像（约 5 MB），无 bash/curl |
| `hello-world` | `docker run --rm hello-world` | 验证环境是否正常 |

## 七、环境配置速查

**镜像加速器**（`~/.docker/daemon.json`，Windows 在 Docker Desktop 设置里改；改完需重启 Docker）

```json
{
  "registry-mirrors": ["https://<你的加速器地址>"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
```

**常用检查命令**

```bash
docker version            # 客户端与服务端版本（两端不一致是故障源）
docker info               # 存储驱动、内核版本、资源总量、加速器是否生效
docker system df          # 各类资源占多少磁盘
docker system df -v       # 细分到每个镜像/容器/卷
```

**端口与地址速记**

| 场景 | 写法 |
|------|------|
| 宿主访问容器服务 | `localhost:<宿主端口>`（即 `-p` 冒号左边的端口） |
| 容器内访问其他服务 | `<服务名>:<容器内端口>`（同一自定义网络内） |
| 容器访问宿主服务（Linux） | `172.17.0.1:<端口>`；Windows/macOS 用 `host.docker.internal` |
| 容器内不要用 | `localhost` 访问"别的容器" —— 那指它自己 |

## 八、危险命令清单（执行前必须确认）

| 命令 | 后果 |
|------|------|
| `docker system prune -a --volumes` | 删除所有无引用的镜像、容器、网络、**卷（数据）** |
| `docker volume prune` | 删除所有无容器使用的**卷**，数据不可恢复 |
| `docker compose down -v` | 删除本项目卷，数据库数据丢失 |
| `docker rm -f $(docker ps -aq)` | 强删所有容器（含正在运行的服务） |
| `docker rmi -f $(docker images -q)` | 强删所有镜像，需重新拉取 |
| `docker run --privileged ...` | 容器获得宿主几乎全部权限，**生产禁用** |
| `docker run -v /:/host ...` | 把宿主根目录暴露给容器，等于放弃隔离 |

> 记忆原则：**带 `prune`、`-v`（删除卷）、`-f` 的组合，执行前先把命令读一遍，确认对象范围。**
