# 沙箱错误处理与容错

沙箱执行不可靠——容器可能创建失败、代码可能超时、Docker daemon 可能不可用。生产级容错需要分层处理。

## 一、异常分类

```python
class SandboxError(Exception): pass
class SandboxTimeout(SandboxError): pass
class SandboxOOM(SandboxError): pass
class SandboxDaemonError(SandboxError): pass
class SandboxImageError(SandboxError): pass
```

**三类异常的处理策略**：

| 异常 | 是否重试 | 策略 |
|------|---------|------|
| Docker daemon 不可用 | 是（2 次） | 指数退避重试 + 降级为本地执行 |
| 容器创建失败（镜像问题） | 否 | 告警 + 尝试重新拉取镜像 |
| 代码执行超时 | 否 | 返回超时信息给 Agent |
| OOM（exit_code=137） | 否 | 提示 Agent 减小输入或拆分任务 |
| 代码本身异常（exit_code=1） | 否 | 返回 stderr 给 Agent 自行修正 |

## 二、重试机制

```python
import time

class DockerSandbox:
    MAX_RETRIES = 2
    RETRY_BACKOFF = 1.0     # 初始退避秒数

    def execute(self, code: str, **kwargs) -> SandboxResult:
        last_error = None

        for attempt in range(self.MAX_RETRIES + 1):   # 共 3 次尝试
            try:
                return self._execute_once(code, **kwargs)

            except docker.errors.DockerException as e:
                # Docker daemon 瞬时异常 → 重试
                last_error = e
                if attempt < self.MAX_RETRIES:
                    delay = self.RETRY_BACKOFF * (2 ** attempt)
                    time.sleep(delay)
                    continue
                # 重试耗尽 → 降级
                return self._fallback_execute(code)

            except SandboxTimeout:
                # 超时不重试
                return SandboxResult(
                    exit_code=-1,
                    stderr="执行超时，请简化代码或拆分任务",
                    duration_ms=0,
                )

            except SandboxOOM:
                return SandboxResult(
                    exit_code=137,
                    stderr="内存不足（OOM），请减小输入或限制数据量",
                    duration_ms=0,
                )

        raise SandboxDaemonError(f"Docker daemon 不可用: {last_error}")

    def _execute_once(self, code: str, **kwargs) -> SandboxResult:
        """单次执行（可能因 daemon 瞬时异常失败）"""
        timeout = kwargs.get("timeout", self.config.timeout)
        try:
            container = self.client.containers.run(
                image=self.config.image,
                command=["python", "-c", code],
                mem_limit=self.config.memory_limit,
                timeout=timeout,
                remove=True,
                ...
            )
            return SandboxResult(stdout=container.decode("utf-8"), exit_code=0)
        except requests.exceptions.ConnectionError as e:
            raise docker.errors.DockerException(str(e))
```

**重试的指数退避时序**：

```
第 1 次: 立即
[失败] 等待 1.0s
第 2 次: ~1.0s
[失败] 等待 2.0s
第 3 次: ~3.0s
[失败] → 降级为本地执行
```

## 三、优雅降级

当 Docker daemon 完全不可用时，回退到受限的本地执行：

```python
def _fallback_execute(self, code: str) -> SandboxResult:
    """Docker 不可用时降级为本地 subprocess 执行（仅受信环境！）"""
    import subprocess

    logger.warning("sandbox.fallback", reason="docker_daemon_unavailable")

    try:
        result = subprocess.run(
            ["python", "-c", code],
            capture_output=True, text=True,
            timeout=10,      # 降到 10s，本地执行更危险
        )
        return SandboxResult(
            stdout=result.stdout,
            stderr=result.stderr,
            exit_code=result.exit_code,
            duration_ms=0,
        )
    except subprocess.TimeoutExpired:
        return SandboxResult(exit_code=-1, stderr="本地降级执行超时")
```

> **生产警告**：降级到本地执行仅在受信内网环境中启用。公网 SaaS 绝不降级，直接返回 503。

## 四、超时处理

```python
# docker-py 的超时只杀死容器进程，不保证 Python 层面立即返回
# 需双重保险

def execute(self, code: str, timeout: int = 30, **kwargs) -> SandboxResult:
    with concurrent.futures.ThreadPoolExecutor(max_workers=1) as executor:
        future = executor.submit(self._execute_once, code, timeout=timeout, **kwargs)
        try:
            return future.result(timeout=timeout + 5)  # 额外 5s 缓冲
        except concurrent.futures.TimeoutError:
            return SandboxResult(exit_code=-1, stderr="沙箱执行超时（含清理缓冲）")
```

## 五、Supervisor 守护

`docker.from_env()` 返回的连接不容错——如果 Docker daemon 在运行中挂了，所有后续调用都会失败。加一个健康检查：

```python
class DockerSandbox:
    def __init__(self, config):
        self.config = config
        self._connect()

    def _connect(self):
        """建立连接，5 秒超时"""
        try:
            self.client = docker.from_env(timeout=5)
            self.client.ping()  # 立即测试连通性
        except Exception as e:
            raise SandboxDaemonError(f"无法连接 Docker daemon: {e}")

    def health_check(self) -> bool:
        """定期健康检查"""
        try:
            self.client.ping()
            return True
        except Exception:
            try:
                self._connect()  # 尝试重连
                return True
            except Exception:
                return False
```

## 六、Agent 侧的错误处理

tool 返回给 Agent 的错误信息要**可操作**——Agent 看到后应该知道如何修正：

```python
@tool
def sandbox_execute(code: str, language: str = "python") -> str:
    result = sandbox.execute(code, language=language)

    if result.exit_code == -1 and "超时" in result.stderr:
        return (
            "[超时] 代码运行超过 30 秒。请：\n"
            "1. 简化代码逻辑\n"
            "2. 减少处理的数据量\n"
            "3. 拆分任务为多个小步骤"
        )
    elif result.exit_code == 137:
        return (
            "[OOM] 内存不足。请：\n"
            "1. 减少输入数据的大小\n"
            "2. 用生成器代替列表\n"
            "3. 分批处理数据"
        )
    elif result.exit_code != 0:
        return f"[错误 {result.exit_code}]\n{result.stderr}"
    else:
        return result.stdout
```

## 七、告警规则

| 指标 | 条件 | 行动 |
|------|------|------|
| Docker daemon 不可用 | 健康检查连续 3 次失败 | PagerDuty 告警 + 切降级模式 |
| 执行成功率持续下降 | 5 分钟窗口 < 90% | 检查镜像/Daemon 状态 |
| OOM 率飙升 | > 5% 执行 OOM | 调大 `memory_limit` 或拆分任务 |
| 超时率飙升 | > 5% 执行超时 | 检查 Agent 是否陷入循环 |
