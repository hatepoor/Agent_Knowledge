# 沙箱调试与故障排查指南

沙箱出问题时，容器层的错误信息往往被 docker-py 包裹。这份指南覆盖 8 类常见故障的诊断流程和修复方案。

## 一、容器启动失败

### 症状

```
docker.errors.ImageNotFound: Image "python:3.11-slim" not found
docker.errors.APIError: 500 Server Error
```

### 诊断流程

```
容器启动失败
  ├── 镜像不存在？ → docker images | grep python
  ├── Docker daemon 未运行？ → docker info
  ├── 磁盘空间不足？ → df -h
  └── 权限问题？ → docker ps（是否需要 sudo）
```

### 修复

```bash
# 1. 检查 daemon
docker info > /dev/null 2>&1
echo $?  # 0 = 正常

# 2. 手动拉取镜像
docker pull python:3.11-slim

# 3. 检查磁盘
df -h /var/lib/docker

# 4. 权限（Linux）
sudo usermod -aG docker $USER
# 重新登录后生效
```

```python
# 代码中加预检
def _ensure_image(self):
    try:
        self.client.images.get(self.config.image)
    except docker.errors.ImageNotFound:
        logger.warning("image.not_found", image=self.config.image)
        self.client.images.pull(self.config.image)
    except docker.errors.DockerException as e:
        logger.error("daemon.unavailable", error=str(e))
        raise SandboxDaemonError(f"Docker daemon 不可用: {e}")
```

## 二、代码执行超时

### 症状

```
SandboxResult(exit_code=-1, stderr="执行超时，请简化代码")
```

### 诊断

| 可能原因 | 验证方法 |
|---------|---------|
| 代码死循环 | 手动执行同一段代码 |
| 数据量过大 | 检查输入数据大小 |
| 网络等待（禁网但代码试图联网） | 检查代码中是否有 `requests.get()` |
| CPU 限制太低 | 临时调高 `cpu_limit` 测试 |

### 修复

```python
# 1. 区分"真超时"和"假超时"
def execute_with_diagnosis(self, code: str, timeout: int = 30):
    start = time.time()
    result = self.execute(code, timeout=timeout)
    if result.exit_code == -1 and "超时" in result.stderr:
        # 真超时：代码确实运行超过 30s
        logger.warning("sandbox.timeout", code_preview=code[:200], timeout=timeout)
        return "代码执行超时。建议：1. 简化逻辑 2. 减少数据量 3. 拆分任务"
    return result.stdout

# 2. 分段执行（把长任务拆成小步）
```

## 三、OOM（内存不足）

### 症状

```
SandboxResult(exit_code=137, stderr="内存不足（OOM）")
```

> `exit_code=137` = 128 + 9（SIGKILL），容器因超过 `mem_limit` 被 OOM killer 杀掉。

### 诊断

```python
# 判断是否 OOM
if result.exit_code == 137:
    # OOM 确认
    logger.error("sandbox.oom",
        memory_limit=self.config.memory_limit,
        code_preview=code[:200],
    )
```

| 可能原因 | 修复 |
|---------|------|
| 一次性加载大文件 | 改用流式读取（`pd.read_csv(chunksize=1000)`） |
| list 过大 | 改用生成器 |
| 内存泄漏 | 检查全局变量、循环引用 |
| `mem_limit` 太低 | 调到 512m 或 1g |

### 修复

```python
# 返回可操作的错误信息给 Agent
if result.exit_code == 137:
    return (
        "[OOM] 内存不足。请：\n"
        "1. 用 `pd.read_csv(chunksize=1000)` 分块读取\n"
        "2. 用生成器代替列表\n"
        "3. 处理完后手动 `del` 大变量"
    )
```

## 四、代码执行异常（exit_code != 0）

### 症状

```
SandboxResult(exit_code=1, stderr="NameError: name 'pd' is not defined")
```

### 诊断

这是最常见的场景——代码本身有 bug。**不要重试**，直接把 stderr 返回给 Agent 让它修正：

```python
@tool
def sandbox_execute(code: str, language: str = "python") -> str:
    result = sandbox.execute(code, language=language)
    if result.exit_code != 0 and result.exit_code != 137:
        # 代码异常 → 返回 stderr，Agent 会根据错误信息修正
        return f"[代码错误 {result.exit_code}]\n{result.stderr}\n\n请根据错误修正代码后重试。"
    return result.stdout
```

### 常见 exit_code 含义

| exit_code | 含义 | 处理 |
|-----------|------|------|
| 0 | 成功 | 正常返回 |
| 1 | 通用错误（语法/逻辑/NameError） | 返回 stderr 给 Agent |
| 2 | 命令行参数错误 | 检查 language 参数 |
| 137 | OOM（SIGKILL） | 提示减小数据量 |
| 143 | 超时（SIGTERM） | 提示简化代码 |
| -1 | 沙箱本身异常 | 检查 Docker daemon |

## 五、网络相关故障

### 症状

```
# 代码中调 requests.get() 但网络被禁
ConnectionError: Failed to establish a connection
```

### 诊断

```python
# 检查是否是网络问题
if "Connection" in result.stderr or "Network" in result.stderr:
    if not self.config.network_enabled:
        return "[网络禁用] 沙箱默认禁网。如需网络，使用 sandbox_execute_network 工具。"
```

### 修复

```python
# 提供一个带网络的专用 tool
@tool
def sandbox_execute_network(code: str) -> str:
    """在沙箱中执行需要网络的代码（如调 API）。此工具会启用网络访问。"""
    result = sandbox.execute(code, network_enabled=True, timeout=60)
    return result.stdout or result.stderr
```

## 六、文件挂载问题

### 症状

```
FileNotFoundError: /skills/code_review.md
```

### 诊断

```python
# 检查挂载
def verify_mounts(self):
    """启动时验证 skills 目录"""
    skills_dir = Path(self.config.skills_mount)
    if not skills_dir.exists():
        raise RuntimeError(
            f"Skills 目录不存在: {skills_dir.absolute()}\n"
            f"请创建目录或修改 config.skills_mount"
        )
    if not skills_dir.is_dir():
        raise RuntimeError(f"Skills 路径不是目录: {skills_dir}")

    # 检查权限
    try:
        list(skills_dir.iterdir())
    except PermissionError:
        raise RuntimeError(f"Skills 目录无读取权限: {skills_dir}")
```

### 修复

```bash
# 1. 确认目录存在
ls -la ./skills_data/

# 2. 确认 Docker 有权挂载（Docker Desktop 需要在 Settings 中授权）
# Docker Desktop → Settings → Resources → File Sharing → 添加项目目录

# 3. 在容器内验证
docker run --rm -v ./skills_data:/skills python:3.11-slim ls /skills/
```

## 七、Docker daemon 不可用

### 症状

```
docker.errors.DockerException: Error while fetching server API version
ConnectionError: UnixHTTPConnectionPool(host='localhost', port=None)
```

### 诊断

```bash
# 检查 daemon 状态
docker info

# 检查 socket
ls -la /var/run/docker.sock   # Linux
# 或 Docker Desktop 状态
```

### 修复

```python
# 加健康检查 + 自动重连
class DockerSandbox:
    def health_check(self) -> bool:
        try:
            self.client.ping()
            return True
        except Exception:
            try:
                self.client = docker.from_env(timeout=5)
                self.client.ping()
                logger.info("daemon.reconnected")
                return True
            except Exception:
                logger.error("daemon.unavailable")
                return False

# 定期检查（每 60 秒）
import threading
def start_health_monitor(sandbox):
    def monitor():
        while True:
            if not sandbox.health_check():
                # 触发告警
                logger.error("daemon.down", action="alert")
            time.sleep(60)
    threading.Thread(target=monitor, daemon=True).start()
```

## 八、调试技巧

### 8.1 手动复现容器

```bash
# 手动启动同配置的容器进行交互式调试
docker run --rm -it \
  --memory=256m \
  --cpus=1.0 \
  --network=none \
  --read-only \
  --tmpfs /workspace:size=100m \
  -v ./skills_data:/skills:ro \
  python:3.11-slim bash

# 在容器内手动执行代码
python -c "print('hello')"
```

### 8.2 查看 Docker 日志

```bash
# 查看容器日志（remove=True 的容器看不到日志，需要临时去掉）
docker logs <container_id>

# 查看 Docker daemon 日志
journalctl -u docker.service -f       # Linux
# 或 Docker Desktop → Troubleshoot → Show logs
```

### 8.3 启用调试模式

```python
class DebugDockerSandbox(DockerSandbox):
    """调试用：不自动删除容器，打印完整命令"""

    def execute(self, code: str, **kwargs):
        # 临时关闭 remove=True，方便排查
        logger.debug("sandbox.code", code=code, kwargs=kwargs)
        result = super().execute(code, remove=False, **kwargs)
        logger.debug("sandbox.result",
            exit_code=result.exit_code,
            stdout=result.stdout[:500],
            stderr=result.stderr[:500],
        )
        # 手动清理
        # self.client.containers.get(result.container_id).remove(force=True)
        return result
```

### 8.4 逐步缩小问题范围

```
问题: sandbox_execute 返回空输出
  │
  ├── 容器是否启动？ → docker ps -a（看是否有退出的容器）
  ├── 代码是否执行？ → 在代码末尾加 print("DONE")
  ├── stdout 是否被截断？ → 检查代码中是否有大量 print
  └── encoding 问题？ → 用 result.stdout.encode('utf-8') 检查
```

## 九、故障排查速查表

| 症状 | 可能原因 | 第一步检查 |
|------|---------|-----------|
| ImageNotFound | 镜像未拉取 | `docker images` |
| ConnectionError | daemon 未运行 | `docker info` |
| exit_code=137 | OOM | 调大 `mem_limit` |
| exit_code=143 | 超时 | 调大 `timeout` 或简化代码 |
| exit_code=1 | 代码 bug | 看 `stderr` |
| FileNotFoundError | 挂载失败 | `docker run -v ... ls /skills/` |
| 空输出 | print 被缓冲 | 代码中加 `sys.stdout.flush()` |
| 中文乱码 | encoding | `PYTHONIOENCODING=utf-8` |
