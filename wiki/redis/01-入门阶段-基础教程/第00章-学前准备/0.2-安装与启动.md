# 安装与启动

## 学习目标

读完本篇，你应当能够：

1. 用 Docker 在本机跑起一个 Redis 8.x 服务（推荐路径）
2. 用 `redis-server` / `redis-cli` 启动服务并验证连通（`PING` → `PONG`）
3. 知道 Windows 上为什么没有"官方原生安装包"，以及正确替代方案

## 一、路线选择（Windows 用户必读）

Redis 官方**只发布 Linux/macOS 版本**，Windows 没有官方原生构建。你在网上搜到的 "Redis for Windows" 多是停更多年的旧移植版（停留在 5.x），**不要用**。

| 路线 | 适用 | 说明 |
|------|------|------|
| ✅ **Docker 容器**（本篇主推） | 已装 Docker Desktop | 一条命令，版本任意选，和你知识库里的 Docker 体系无缝衔接 |
| ✅ WSL2 内安装 | 想要更接近 Linux 生产环境 | 在 WSL2 的 Ubuntu 里 `apt install redis-server`，版本由发行版决定 |
| ❌ Windows 原生旧移植版 | 不适用 | 版本陈旧（5.x），与 8.x 行为差异大 |

> 下文统一以 **Docker 路线**演示。WSL2 路线中的 `redis-server` 启动、`redis-cli` 验证步骤完全相同。

---

## 二、用 Docker 启动 Redis

> 没学过 Docker 的概念（镜像、容器、端口映射）也没关系，这里只需照抄命令；想系统学习见 [[docker/01-入门阶段-基础教程/第00章-学前准备/0.1-容器与Docker是什么]]。

```bash
docker run -d --name my-redis -p 6379:6379 redis:8.2
```

逐段解释：

| 片段 | 含义 |
|------|------|
| `-d` | 后台运行（detached），不占住当前终端 |
| `--name my-redis` | 给容器起名，方便后续 `docker stop my-redis` |
| `-p 6379:6379` | 端口映射：宿主机 6379 → 容器 6379。**不映射则宿主机程序连不上** |
| `redis:8.2` | 镜像名:标签。`redis` 是 Docker Hub 官方镜像名；`8.2` 是扩展支持到 2030 年的稳定版本线 |

验证容器活着：

```bash
docker ps                       # STATUS 列显示 Up 即在运行
docker logs my-redis            # 看到 "Ready to accept connections tcp" 即就绪
```

### 让数据活过容器重启（挂载卷）

容器删除后数据即消失。开发期想保留数据，把容器内 `/data` 目录挂到宿主机卷（卷的概念见 [[docker/01-入门阶段-基础教程/第03章-数据卷与容器网络/3.1-数据卷与绑定挂载]]）：

```bash
docker run -d --name my-redis -p 6379:6379 -v redis-data:/data redis:8.2
```

> Redis 默认**会**开启快照持久化（往 `/data` 写 RDB 文件；RDB 是什么属于中段内容，现在只需知道"挂了卷数据更保险"）。

## 三、不用 Docker：Linux/WSL2 直接安装

```bash
# Ubuntu / Debian
sudo apt update && sudo apt install redis-server
sudo systemctl status redis-server    # 查看服务状态

# macOS (Homebrew)
brew install redis
brew services start redis
```

## 四、验证连通：PING → PONG

`redis-cli`（Redis Command Line Interface，官方命令行客户端）随服务端一起安装。Docker 路径下有两种用法：

```bash
# 用法 A：进入容器内的 redis-cli（最省事）
docker exec -it my-redis redis-cli

# 用法 B：宿主机装了 redis-cli，直连映射端口
redis-cli ping
```

进入交互模式后：

```
127.0.0.1:6379> PING
PONG
```

看到 `PONG` 就说明服务端已正常响应。顺手完成你的第一次读写：

```
127.0.0.1:6379> SET hello world
OK
127.0.0.1:6379> GET hello
"world"
```

- `SET key value`：写入一个键值对（详见 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.3-String字符串]]）
- 返回 `OK` 表示命令执行成功；`GET` 返回存的值

## 五、服务端与配置文件一瞥

| 程序 | 作用 |
|------|------|
| `redis-server` | 服务端本体。`redis-server` 直接启动用默认配置；`redis-server /path/redis.conf` 用指定配置文件启动 |
| `redis-cli` | 命令行客户端 |
| `redis.conf` | 配置文件：端口、内存上限、持久化开关等。Docker 镜像内置默认配置，入门阶段不用改 |

常用默认值：端口 `6379`、绑定 `127.0.0.1`（只接受本机连接，这是安全默认）、16 个逻辑数据库 `db0`~`db15`（db 概念见 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.1-Key与Value的世界观]]）。

## 六、陷阱

1. **`-p 6379:6379` 忘了写** → 宿主机程序报 "Connection refused"，但 `docker ps` 看容器一切正常。这是最常见的新手卡点。
2. **端口被占用** → 报 `bind: address already in use`：本机已有一个 Redis（或另一个容器占了 6379）。用 `docker ps` 与 `netstat -ano | findstr 6379`（Windows）排查。
3. **把 Redis 端口暴露到公网** → Redis 默认无密码（见 `requirepass` 配置），历史上大量 Redis 被入侵都源于"公网 + 无密码 + 默认端口"。本机开发无所谓，**任何上服务器的场合都必须设密码**（中段安全专题细讲）。
4. **容器删了数据就没了** → 不挂 `-v` 卷，`docker rm` 后所有键消失（见上文第二节）。

---

## 小结

- Windows 无官方原生 Redis：用 Docker（主推）或 WSL2
- `docker run -d --name my-redis -p 6379:6379 -v redis-data:/data redis:8.2` 一条命令起服务
- `redis-cli` 里 `PING` 得到 `PONG` 即验证连通
- 记住三个默认值：端口 6379、只绑本机、db0~db15

## 练习

1. 用 Docker 启动 `redis:8.2`，挂上数据卷，并用 `redis-cli` 完成 `PING`、`SET`、`GET`。
2. `docker stop my-redis` 后再 `docker start my-redis`，用 `GET hello` 检查数据还在（为什么还在？想想卷和 RDB 各扮演了什么角色）。
