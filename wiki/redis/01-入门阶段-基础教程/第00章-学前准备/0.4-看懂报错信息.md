# 看懂报错信息

## 一、通用排错顺序

遇到问题按这个顺序检查，能解决 90% 的入门期问题：

```
1. 服务活着吗？      → redis-cli PING
2. 连的是对的机器端口吗？→ 看提示符 127.0.0.1:6379 / 检查 -h -p
3. 选的是对的 db 吗？ → SELECT / DBSIZE
4. 键的类型用对了吗？ → TYPE 键名
5. 报错原文说了什么？  → 逐词读 (error) 后面的内容
```

第 4 步的 `TYPE` 是排错利器：绝大多数"命令结果不对"其实是**值的类型和你以为的不一样**（见下文 WRONGTYPE）。

## 二、入门阶段最常见的 8 类报错

### 1. `Connection refused`（连不上服务）

```
Could not connect to Redis at 127.0.0.1:6379: Connection refused
```

| 可能原因 | 检查方法 |
|----------|----------|
| 服务没启动 | Docker：`docker ps`；Linux：`systemctl status redis-server` |
| 端口没映射（Docker 忘写 `-p 6379:6379`） | `docker port 容器名` |
| 连错了主机 / 端口 | 看提示符；容器外连容器内 IP 是否可达 |

### 2. `(error) WRONGTYPE Operation against a key holding the wrong kind of value`

**入门期第一大报错。** 意思是：这个 key 存在，但它的值类型和你正在用的命令不匹配。

```
127.0.0.1:6379> LPUSH mykey a b c     # mykey 现在是 List
OK
127.0.0.1:6379> GET mykey             # GET 只能读 String
(error) WRONGTYPE Operation against a key holding the wrong kind of value
```

处理：`TYPE mykey` 查实际类型 → 要么改用对应类型的命令，要么 `DEL` 掉重建。

> 根因：**类型是"值"的属性，key 本身没有类型声明**（见 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.2-五种核心数据类型总览]]）。同一个 key 重新 `SET` 会直接覆盖成新类型——历史残留的旧 key 常常是"我明明存的字符串怎么变列表了"的元凶。

### 3. `(error) ERR unknown command ...`

命令拼错了（大小写不敏感，但拼写敏感），或当前版本没有这个命令。

```
(error) ERR unknown command 'ZADDSCORE', with args beginning with:
```

处理：`HELP 命令名` 核对拼写与签名；再核对命令的**引入版本**（本套文档对 `Redis 7.0+` 这类标注都会显式写出）。

### 4. `(error) ERR value is not an integer or out of range`

对非数字的值做算术命令：

```
127.0.0.1:6379> SET n abc
OK
127.0.0.1:6379> INCR n
(error) ERR value is not an integer or out of range
```

`INCR` / `HINCRBY` 等要求值是**能被解析为 64 位整数**的字符串（详见 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.3-String字符串]]）。注意 `"3.5"` 也不行——整数运算不接受小数（小数用 `INCRBYFLOAT`）。

### 5. `(error) ERR wrong number of arguments for 'xxx' command`

参数个数不对。最常见于**值里含空格却没加引号**（被拆成了多个参数），见 [[redis/01-入门阶段-基础教程/第00章-学前准备/0.3-redis-cli第一次连接]]。

### 6. `(error) NOAUTH Authentication required`

服务端设置了密码（`requirepass`），但当前连接没认证。

```
127.0.0.1:6379> AUTH 你的密码     # 认证后即可正常使用
OK
```

### 7. `(error) OOM command not allowed when used memory > 'maxmemory'`

内存超过上限且淘汰策略不允许继续写（默认策略 `noeviction` 的行为）。**内存上限 `maxmemory` 与淘汰策略属于中段专题**；入门期遇到它，先意识到"内存满了"，处理方向是删数据或调大上限。

### 8. `(error) MISCONF Redis is configured to save RDB snapshots...`

RDB 快照（持久化，中段内容）写盘失败时，默认配置会**拒绝写入**以提示你数据有丢失风险。入门期快速解法：确认磁盘没满。系统处理见中段持久化专题。

## 三、两类"不是报错但像报错"的输出

| 输出 | 实际含义 | 该做什么 |
|------|----------|----------|
| `(nil)` | 键 / 字段不存在 | 检查键名拼写、当前 db、键是否已过期 |
| `(empty array)` | 命令成功，结果为空列表 | 检查范围参数（如 `LRANGE k 0 -1` 的表是否为空） |

**键"莫名消失"的三大常规原因**（不是 bug）：

1. **过期了**：设了 TTL 到期自动删除（见 [[redis/01-入门阶段-基础教程/第02章-过期机制与通用Key命令/2.1-Key的过期机制]]）
2. **切错了 db**：`db0` 写的键到 `db1` 里当然找不到
3. **连错了实例**：提示符里的 host:port 对不对

---

## 四、排错用命令速查

| 命令 | 用途 |
|------|------|
| `PING` | 服务是否存活 |
| `TYPE 键` | 该键值的实际类型 |
| `TTL 键` | 键还剩几秒过期（`-1` 永不过期，`-2` 不存在） |
| `DBSIZE` | 当前 db 键数量 |
| `INFO memory` | 内存使用概况 |
| `CLIENT LIST` | 有哪些客户端连着 |
| `CONFIG GET 参数名` | 查配置项当前值 |

---

## 五、小结

- 排错顺序：PING → 连接目标 → db → TYPE → 读报错原文
- `WRONGTYPE` 是入门第一大错：先 `TYPE` 再动手
- `(nil)` / `(empty array)` 不是错误，是"没有"
- 键消失三常规原因：过期、切错 db、连错实例

## 练习

1. 故意触发一次 `WRONGTYPE`：`LPUSH k a` 后执行 `GET k`，再用 `TYPE k` 验证原因。
2. 故意触发一次 `value is not an integer`：`SET x hello` 后 `INCR x`。
3. `SETEX` 一个 2 秒过期的键，等 3 秒后 `GET`，观察 `(nil)`；再用 `TTL` 看一个过期键的返回（`-2`）。
