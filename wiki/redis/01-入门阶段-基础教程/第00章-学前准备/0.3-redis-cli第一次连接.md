# redis-cli 第一次连接

## 学习目标

读完本篇，你应当能够：

1. 进入 / 退出 `redis-cli` 交互模式，并知道提示符各段含义
2. 读懂 Redis 的五种**响应前缀**：`OK` / `(integer)` / `"(nil)"` / `(empty array)` / `(error)`
3. 正确处理命令里的引号与特殊字符，看懂 `redis-cli` 的帮助体系

## 一、进入与退出

```bash
redis-cli                      # 连接本机 127.0.0.1:6379
redis-cli -h 192.168.1.10      # 连接指定主机
redis-cli -p 6380              # 连接指定端口
redis-cli -h 主机 -p 端口 -a 密码   # 带密码（-a 明文传参，测试期可用）
```

进入后提示符变成：

```
127.0.0.1:6379>
```

提示符就是"当前连着谁"：主机 IP + 端口。退出输入 `quit` 或按 `Ctrl+D`。

> **非交互模式**（一次性执行单条命令，脚本里常用）：
> ```bash
> redis-cli SET foo bar
> redis-cli INCR counter
> ```

---

## 二、Redis 的响应有"类型前缀"

`redis-cli` 会给每种返回值加可读前缀，**看懂前缀是看懂输出的第一步**：

| 你看到的 | 类型 | 含义 |
|----------|------|------|
| `OK` | 简单字符串 | 命令成功（多见于 `SET`） |
| `PONG` | 简单字符串 | `PING` 的固定回复 |
| `(integer) 3` | 整数 | 命令返回了数字（如 `INCR`、`LLEN`、`EXISTS`） |
| `"(nil)"` | nil | **"这里没有东西"**——键不存在、字段不存在、取不到值 |
| `(empty array)` | 空数组 | 命令成功但结果列表为空（如 `LRANGE` 空表） |
| `(error) ERR ...` | 错误 | 命令执行失败，后面跟原因 |

`"(nil)"` 与空字符串是两回事：

```
127.0.0.1:6379> GET not-exist-key
(nil)                          ← 键不存在
127.0.0.1:6379> SET k ""
OK
127.0.0.1:6379> GET k
""                             ← 键存在，值是空字符串
```

## 三、命令与引号规则

Redis 命令格式统一为：

```
命令 参数1 参数2 ...
```

参数之间用**空格**分隔。含空格或特殊字符的参数要加**双引号**：

```
127.0.0.1:6379> SET greeting "hello world"
OK
127.0.0.1:6379> GET greeting
"hello world"
```

| 规则 | 示例 |
|------|------|
| 命令大小写不敏感（习惯全大写） | `set foo bar` 与 `SET foo bar` 等价 |
| 值是**字节序列**，不是文本 | 可以存二进制（图片、序列化数据），详见 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.1-Key与Value的世界观]] |
| 引号内保留空格 | `"hello world"` 是一个参数；不加引号会被拆成两个 |

> 引号是 **redis-cli 的语法**，不是 Redis 的：真正的服务端只接收"命令 + 参数列表"。这一区别在用 Python 客户端时会再次遇到——`r.set("greeting", "hello world")` 根本不需要引号处理。

## 四、内置帮助

```
127.0.0.1:6379> HELP                 # 帮助主题列表
127.0.0.1:6379> HELP SET             # SET 的完整签名与选项说明
127.0.0.1:6379> HELP @string         # 按组查看：@string @list @hash @set @zset ...
```

`HELP @组名` 是离线速查的好工具；官方完整命令文档在 <https://redis.io/docs/latest/commands/>。

---

## 五、几个"了解环境"的命令

| 命令 | 作用 | 说明 |
|------|------|------|
| `PING` | 探活 | 连通测试的标准动作 |
| `SELECT 1` | 切换到 db1 | 逻辑数据库编号 0~15，默认 db0；详见 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.1-Key与Value的世界观]] |
| `DBSIZE` | 当前 db 的键数量 | O(1)，可放心执行 |
| `INFO server` | 服务端信息摘要 | 版本、运行时长等；`INFO memory` 看内存（排查时常用） |
| `CLIENT LIST` | 当前连接的客户端列表 | 排查"谁占着连接"时用 |
| `CONFIG GET maxmemory` | 查配置项 | `CONFIG GET *` 列全部 |

## 六、陷阱

1. **把 `(nil)` 当错误。** 它只是"没有值"，`GET` 一个不存在的键返回 nil 是**正常行为**，程序里应把它分支处理（Python 里对应 `None`）。
2. **值含空格不加引号** → `SET greeting hello world` 会报参数数量错误，因为服务端收到了 3 个参数。
3. **`-a 密码` 会进 shell 历史。** 临时用可以，正式环境改用 `redis-cli` 交互内的 `AUTH` 或配置文件，避免密码留在 `.bash_history`。
4. **中文显示成 `\xe4\xbd\xa0\xe5\xa5\xbd`** → `redis-cli` 默认按字节显示非 ASCII。加 `--raw` 参数可按原样输出；本质原因是值是字节序列而非"文本"。

---

## 小结

- 提示符 = 当前连接的主机:端口；`quit` 退出
- 五种响应前缀，其中 `(nil)` 表示"没有"而不是"出错"
- 参数用空格分隔，含空格要加双引号；引号是 redis-cli 的语法
- `HELP 命令` / `HELP @组名` 随手可查

## 练习

1. 依次执行并解释每个输出：`SET t1 v1`、`GET t1`、`GET t2`、`DEL t1`、`EXISTS t1`。
2. 用 `SET` 存一个含空格的句子，观察不加引号 / 加引号的两种结果。
3. `HELP @list` 看一眼，不必记住，只体验"离线文档"的存在。
