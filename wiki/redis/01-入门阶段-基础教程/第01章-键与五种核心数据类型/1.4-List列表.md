# List 列表

## 学习目标

读完本篇，你应当能够：

1. 准确画出 List 的心智模型（双端序列），并按"哪端进、哪端出"区分队列与栈
2. 熟练使用 `LPUSH` / `RPUSH` / `LPOP` / `RPOP` / `LRANGE` / `LLEN` / `LTRIM`
3. 用 `BLPOP` / `BRPOP` 实现一个最简单的**阻塞队列**
4. 掌握下标（含负数）与 `LREM` 计数语义两个易错点

## 一、心智模型：一条两端都能进出的序列

```
       左端（头，下标 0）              右端（尾，下标 -1）
       ┌───┬───┬───┬───┬───┬───┐
       │ a │ b │ c │ d │ e │ f │
       └───┴───┴───┴───┴───┴───┘
下标:    0   1   2   3   4   5
负下标:  -6  -5  -4  -3  -2  -1
```

- **有序**：元素按你插入的顺序排
- **可重复**：同一个元素可以出现多次
- 两端插入/弹出都是 O(1)；**按值查找是 O(N)**（这是 List 与 Set 的分水岭）

| 组合 | 效果 |
|------|------|
| `RPUSH` 进 + `LPOP` 出 | **队列**（先进先出 FIFO） |
| `LPUSH` 进 + `LPOP` 出 | **栈**（后进先出 LIFO） |
| `LPUSH` 进 + `RPOP` 出 | 队列（另一方向） |

## 二、基础命令实操

```
127.0.0.1:6379> RPUSH tasks t1 t2 t3     # 从右端依次压入（一次可压多个）
(integer) 3
127.0.0.1:6379> LPUSH tasks t0           # 从左端压入
(integer) 4
127.0.0.1:6379> LRANGE tasks 0 -1        # 取全部：0 到倒数第 1
1) "t0"
2) "t1"
3) "t2"
4) "t3"
127.0.0.1:6379> LPOP tasks               # 左端弹出
"t0"
127.0.0.1:6379> LLEN tasks
(integer) 3
```

| 命令 | 作用 | 时间复杂度 |
|------|------|-----------|
| `LPUSH key v [v...]` | 左端压入（可多个） | O(压入个数) |
| `RPUSH key v [v...]` | 右端压入 | 同上 |
| `LPOP key [n]` / `RPOP key [n]` | 弹出左/右端 n 个（`n` 为 `Redis 6.2+`） | O(1) |
| `LRANGE key 起 止` | 取闭区间片段 | O(片段长度) |
| `LLEN key` | 长度 | O(1) |
| `LINDEX key i` | 取下标 i 的单个元素 | O(N)（慎用于长表） |
| `LSET key i v` | 改下标 i 的元素 | O(N) |
| `LREM key 数量 v` | 删除指定值的元素（见下） | O(N) |
| `LTRIM key 起 止` | **只保留**区间，其余删除 | O(N) |
| `LMOVE 源 目标 左/右 左/右` | 原子地从一个列表搬到另一个 | `Redis 6.2+` |

### 下标规则（与 Python 切片神似但不同）

- 闭区间 `[起, 止]`，**两端都包含**（Python 切片是左闭右开）
- 负数从尾部数：`-1` 是最后一个
- `0 -1` = 全部；`-3 -1` = 最后三个

### LREM 的计数语义（必背）

| 计数值 | 行为 |
|--------|------|
| 正数 n | 从**头到尾**找，删**前 n 个**等于 v 的元素 |
| 负数 -n | 从**尾到头**找，删前 n 个 |
| 0 | **删全部**等于 v 的元素 |

## 三、两个高频模式

### 模式 1：最新动态（LPUSH + LTRIM）

维护"最新的 100 条"：`LPUSH` 把新元素顶到头上，`LTRIM 0 99` 把 100 名以外的裁掉。两条命令保证列表**永远只有 100 条**：

```
127.0.0.1:6379> LPUSH feed:u1 post-1024
(integer) 101
127.0.0.1:6379> LTRIM feed:u1 0 99
OK
```

### 模式 2：最简单的任务队列（RPUSH + BLPOP）

```
# 生产者（任意客户端）
RPUSH queue:jobs "job-1"

# 消费者（另一个终端）
BLPOP queue:jobs 5        # 阻塞等待最多 5 秒
1) "queue:jobs"
2) "job-1"
```

`BLPOP` / `BRPOP`（B = Blocking，阻塞）的机制：

- 队列**有**元素 → 立即弹出，和 `LPOP` 一样
- 队列**空** → 挂起等待，**直到有新元素进来或超时**
- 超时时间 `0` 表示**无限等待**

为什么阻塞版比"轮询 `LPOP` + sleep"好：不空转浪费 CPU 与网络；新任务**一进来就被叫醒**，延迟最低。

> 队列进阶（消费确认、消费者组、消息不丢）是 **Stream** 的领域，中段内容。这个 List 队列是"至多一次"投递——消费者弹出后崩溃，这条消息就丢了。

## 四、机制层一瞥：List 在内存里怎么存

现代 Redis（7.0+）中 List 的底层编码是 **listpack**（紧凑连续内存块，小列表）；超出阈值后转为 **quicklist**（listpack 用链表串起来）。入门只需结论：**两端操作 O(1)，中段操作 O(N)**；细节属于中段内存优化专题。可用 `OBJECT ENCODING key` 观察。

---

## 五、陷阱

1. **`LRANGE 0 -1` 是全量拷贝**：百万级列表上执行会瞬间返回巨量数据、撑爆客户端。永远带具体的区间，或先 `LLEN` 看长度。
2. **列表弹空后自动消失**：最后一个元素被弹出后，键本身被删除（`EXISTS` → 0，`TYPE` → none）。这不是 bug，是设计——空容器不占键空间。
3. **`BLPOP` 超时 0 = 永久阻塞**：客户端会一直挂着。生产代码里的阻塞命令必须有超时 + 异常分支。
4. **`LPUSH a b c` 的顺序**：从左端依次压入 c、b、a？不——`LPUSH key a b c` 依次压 a、压 b、压 c，每个都顶到最左边，最终顺序是 `c b a`。批量压入后先 `LRANGE 0 -1` 确认一次再写代码。
5. **不要用 List 做成员判断**："在不在"是 Set 的职责（`SISMEMBER` O(1)）；List 按值查找是 O(N)。

---

## 小结

- List = 双端有序可重复序列；两端 O(1)，按值查找 O(N)
- 组合方向得队列或栈；`BLPOP` 做阻塞队列
- 下标闭区间、负数倒数；`LREM` 计数符号决定方向；`LTRIM` 保头裁尾
- 弹空即删键；`LRANGE 0 -1` 大列表勿用

## 练习

1. 用 `RPUSH` + `BLPOP` 在两个终端演示"生产者-消费者"，再把消费者超时设为 0 体会阻塞。
2. `LPUSH nums 1 2 3` 后 `LRANGE nums 0 -1`，验证实际顺序是 `3 2 1`。
3. `RPUSH x a b a c a`，分别执行 `LREM x 2 a` 与 `LREM x 0 a`，对比剩余元素。
