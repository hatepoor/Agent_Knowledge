# String 字符串

## 学习目标

读完本篇，你应当能够：

1. 熟练使用 `SET` 的常用选项（`EX` / `NX` / `XX` / `KEEPTTL`），并说出各自适用场景
2. 使用 `INCR` 家族做**原子**计数器，解释它为什么不需要加锁
3. 用 `MSET` / `MGET` 批量读写，减少网络往返
4. 识别 String 的三个经典陷阱

## 一、SET 与 GET：最基本的读写

```
SET key value [EX 秒 | PX 毫秒] [NX | XX] [KEEPTTL] [GET]
GET key
```

| 选项 | 含义 | 引入版本 |
|------|------|----------|
| `EX 秒` / `PX 毫秒` | 写入的同时设置过期时间 | 古老 |
| `NX` | **N**ot e**X**ists：只在键**不存在**时写入 | 古老 |
| `XX` | 只在键**已存在**时写入 | 古老 |
| `KEEPTTL` | 写入但**保留原有过期时间**（默认会被清掉！） | `Redis 6.0+` |
| `GET` | 写入并返回旧值（没有旧值返回 nil） | `Redis 6.2+` |

实操：

```
127.0.0.1:6379> SET session:1 "user-abc"
OK
127.0.0.1:6379> GET session:1
"user-abc"
127.0.0.1:6379> SET session:1 "new" NX          # 已存在 → 不执行
(nil)
127.0.0.1:6379> GET session:1
"user-abc"                                       # 原值未动
```

`SET ... NX` 是"**只在无人占用时占用**"的原子操作，也是**分布式锁**的底层原语（中段专题）。

> 历史说明：`SETNX` / `SETEX` / `PSETEX` 是旧式分体命令，官方已标记废弃，新代码一律用 `SET` 选项形式。

## 二、INCR 家族：原子计数器

| 命令 | 作用 |
|------|------|
| `INCR key` | +1 |
| `DECR key` | -1 |
| `INCRBY key n` | +n |
| `DECRBY key n` | -n |
| `INCRBYFLOAT key x` | +小数（浮点） |

```
127.0.0.1:6379> INCR rate:api:u1
(integer) 1
127.0.0.1:6379> INCR rate:api:u1
(integer) 2
127.0.0.1:6379> INCRBY rate:api:u1 100
(integer) 102
```

**注意：键不存在时会从 0 开始**——`INCR` 一个不存在的键，直接得到 1。这就是"计数器不需要预先初始化"的原因。

### 为什么 INCR 是原子的（机制层）

回顾 [[redis/01-入门阶段-基础教程/第00章-学前准备/0.1-Redis是什么]]：命令在单线程里逐条执行。因此"读出旧值 → 加一 → 写回"这三步在 `INCR` 内部**不会被任何其他命令插队**。

对比"先 `GET` 再 `SET`"的两步写法：两个客户端同时读到 5，各自写回 6，一次计数就丢了。**并发计数永远用 `INCR` 家族，永远不要 GET+SET。**

## 三、批量与片段操作

| 命令 | 作用 | 备注 |
|------|------|------|
| `MSET k1 v1 k2 v2 ...` | 批量写 | 原子：全部成功 |
| `MGET k1 k2 ...` | 批量读 | 不存在的键返回 `(nil)`，**位置对齐** |
| `APPEND key v` | 追加到末尾 | |
| `STRLEN key` | 字节长度 | 中文一个字 3 字节（UTF-8） |
| `GETRANGE key 起 止` | 取字节子串 | 闭区间；`0 -1` 表示全部 |
| `SETRANGE key 偏移 v` | 覆写指定偏移起的字节 | |
| `GETDEL key` | 取值并删除 | `Redis 6.2+` |

```
127.0.0.1:6379> MSET a:1 10 a:2 20 a:3 30
OK
127.0.0.1:6379> MGET a:1 a:2 missing a:3
1) "10"
2) "20"
3) (nil)          ← 位置对齐：第 3 个是 missing
4) "30"
```

**为什么批量重要（机制层）**：每条命令都要一次网络往返（本机 ~0.1ms，跨机房 ~几 ms）。读 100 个键，`GET`×100 = 100 次往返；`MGET` = 1 次。批量是 Redis 性能优化的第一课（更多见中段 pipeline 专题）。

## 四、String 的值到底是什么（机制层）

`SET k 123` 之后 `INCR k` 能用，说明 Redis 对 String 有**编码优化**：

| 值的样子 | 内部编码 | 后果 |
|----------|----------|------|
| 纯整数（≤ long 范围） | `int` | 直接按数字存，省内存、算术快 |
| 短字符串（≤ 44 字节） | `embstr` | 内存里一段连续分配 |
| 长字符串 | `raw` | 独立分配 |

入门阶段只需知道两点：① `INCR` 只对能解析成整数的值有效（否则报 `value is not an integer`）；② 编码细节是**中段内存优化**的内容。查看编码：`OBJECT ENCODING key`（好奇可用）。

## 五、陷阱

1. **`SET` 会清空 TTL。** 对带过期时间的键再 `SET` 新值，过期时间消失（键变永久）。要保留须写 `SET k v KEEPTTL`（`6.0+`）。这是缓存刷新场景的经典 bug，详见 [[redis/01-入门阶段-基础教程/第02章-过期机制与通用Key命令/2.1-Key的过期机制]]。
2. **`INCR` 遇到非整数值直接报错**（见 [[redis/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]]）；小数也不能用 `INCRBY`，要用 `INCRBYFLOAT`。
3. **`MGET` 结果与请求的键顺序对齐**，靠"第几个"定位而不是"哪个值"。程序里按下标配对。
4. **计数器也要设过期**：`rate:api:u1` 若不设 TTL，会永久累积——限流场景通常 `SET key 0 EX 60` + `INCR`，或 `INCR` 后首次为 1 时补 `EXPIRE`（原子写法：`SET rate 0 EX 60 NX` 先占位再 `INCR`）。

---

## 小结

- `SET` 的选项是原子复合操作：`EX`（带过期）、`NX`（不存在才写，锁的底座）、`KEEPTTL`（保留 TTL）
- `INCR` 家族 = 无锁原子计数；键不存在从 0 起
- `MSET` / `MGET` 把 N 次网络往返压成 1 次
- `SET` 覆盖 TTL 是第一大坑，记住 `KEEPTTL`
