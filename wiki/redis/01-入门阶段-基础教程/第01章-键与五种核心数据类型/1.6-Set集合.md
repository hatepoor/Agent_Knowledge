# Set 集合

## 学习目标

读完本篇，你应当能够：

1. 说出 Set 的三条铁律：无序、去重、成员判断 O(1)
2. 熟练使用 `SADD` / `SREM` / `SISMEMBER` / `SMEMBERS` / `SCARD`
3. 用集合三运算（交 / 并 / 差）解决"共同好友""独有标签"类问题
4. 区分 `SPOP` 与 `SRANDMEMBER`（删除 vs 不删除）

## 一、心智模型：一袋无序、不重复的元素

```
key: tags:article-1
   { "python", "redis", "cache", "nosql" }
```

三条铁律，决定了 Set 的全部用法：

| 铁律 | 含义 | 换来的能力 |
|------|------|-----------|
| **无序** | 没有第 1 个、第 2 个的说法 | ——（要顺序请用 List / Sorted Set） |
| **去重** | 同一元素只存在一份 | 重复添加自动忽略，天然去重器 |
| **哈希索引** | 元素像 Python `set` 一样哈希存放 | `SISMEMBER` 判断"在不在"是 **O(1)** |

与 List 的分界（复习 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.4-List列表]] 陷阱 5）：

| 你要的 | 选 |
|--------|-----|
| 保序、可重复、两端进出 | List |
| 去重、判断在不在、集合运算 | Set |

## 二、基础命令实操

```
127.0.0.1:6379> SADD tags:post-1 python redis cache
(integer) 3                  ← 返回"新加入"的元素个数
127.0.0.1:6379> SADD tags:post-1 redis
(integer) 0                  ← 已存在，忽略，不报错
127.0.0.1:6379> SISMEMBER tags:post-1 redis
(integer) 1
127.0.0.1:6379> SCARD tags:post-1
(integer) 3                  ← cardinality，基数 = 元素个数
127.0.0.1:6379> SMEMBERS tags:post-1
1) "python"
2) "redis"
3) "cache"
```

| 命令 | 作用 | 复杂度 |
|------|------|--------|
| `SADD key m [m...]` | 添加成员 | O(个数) |
| `SREM key m [m...]` | 删除成员 | O(个数) |
| `SISMEMBER key m` | 在不在（1/0） | **O(1)** |
| `SMISMEMBER key m [m...]` | 批量判断 | `Redis 6.2+` |
| `SCARD key` | 成员数量 | O(1) |
| `SMEMBERS key` | 全部成员 | O(N) |
| `SRANDMEMBER key [n]` | 随机取，**不删除** | O(n) |
| `SPOP key [n]` | 随机取并**删除**（抽奖用） | O(n) |
| `SINTERCARD key [key...]` | 只求交集的**数量**，不返回元素 | `Redis 7.0+` |

## 三、集合三运算：Set 的杀手锏

| 运算 | 命令 | 数学含义 |
|------|------|----------|
| 交集 | `SINTER k1 k2` | 既有 A 又有 B 的元素（**共同好友**） |
| 并集 | `SUNION k1 k2` | A 或 B 有的全部元素（**合并标签**） |
| 差集 | `SDIFF k1 k2` | 在 A 不在 B（**A 独有**） |

三者都有 `...STORE 目标key` 变体（如 `SINTERSTORE`）：结果直接写入目标集合而不返回给客户端。

```
127.0.0.1:6379> SADD follow:alice bob carol dave
127.0.0.1:6379> SADD follow:bob alice carol dave
127.0.0.1:6379> SINTER follow:alice follow:bob        # 共同关注
1) "carol"
2) "dave"
127.0.0.1:6379> SDIFF follow:alice follow:bob          # alice 关注而 bob 没关注
1) "bob"
127.0.0.1:6379> SINTERCARD follow:alice follow:bob     # 只要数量
(integer) 2
```

**复杂度警示**：三运算都是 O(N)（N 参与集合的总元素数）。大集合间做交并差会卡服务端，生产上大集合用 `SINTERCARD`（只数数）或分批方案，这是 `7.0+` 特性存在的意义。

## 四、两个高频模式

### 模式 1：去重计数（如"今天有多少独立访客"）

```
SADD uv:2026-09-29 user-a user-b user-a     # 重复自动忽略
SCARD uv:2026-09-29                         # 独立访客数
```

> 元素量级到千万、只要"大约多少"时，有更省内存的 HyperLogLog（中段内容）。

### 模式 2：抽奖

```
SADD lottery players...      # 候选人
SPOP lottery 3               # 随机抽 3 人，抽中即移除（不会重复中奖）
```

想"可重复抽"就用 `SRANDMEMBER lottery 3`（不删除）。

## 五、机制层一瞥

Set 有两种内部编码：整数集合 `intset`（全是整数且少量时，紧凑排序存储）与哈希表 `hashtable`（通用）。含义：**存一堆小整数时 Set 非常省内存**。`OBJECT ENCODING key` 可查。

## 六、陷阱

1. **`SMEMBERS` 是全量遍历**：百万成员的集合一次 `SMEMBERS`，网络传输直接打爆客户端。大集合只做 `SISMEMBER` / `SCARD`，要遍历用 `SSCAN`（见 [[redis/01-入门阶段-基础教程/第02章-过期机制与通用Key命令/2.2-通用Key命令与SCAN]]）。
2. **无序是刻意的**：依赖 `SMEMBERS` 返回顺序的代码是错的——同一集合两次 `SMEMBERS` 顺序可能不同。要顺序给元素加分数用 Sorted Set。
3. **`SPOP` 会删数据**：与 `SRANDMEMBER` 只差"是否移除"，但后果完全不同。抽奖后候选人没了通常是忘了这一点。
4. **集合运算不改变参与集合本身**（除非 `...STORE`）：`SINTER a b` 只是查询，a、b 不动。
5. **成员删空后键消失**：同 List / Hash 规则。

---

## 小结

- Set = 无序、去重、O(1) 成员判断；与 List 的分界是"顺序 vs 集合语义"
- 三运算：交（共同）/ 并（合并）/ 差（独有），大集合慎用，要数量用 `SINTERCARD`
- `SPOP` 删除、`SRANDMEMBER` 不删
- 大集合禁 `SMEMBERS` 全量
