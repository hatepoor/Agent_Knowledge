# SortedSet 有序集合

## 学习目标

读完本篇，你应当能够：

1. 说出 Sorted Set 的数据形态：成员唯一、分数可重复、**按分数自动排序**
2. 熟练使用 `ZADD` / `ZRANGE` / `ZSCORE` / `ZRANK` / `ZINCRBY` / `ZPOPMAX`
3. 实现一个完整排行榜（含"查我的名次""取 TopN""同分规则"）
4. 掌握"排名区间"与"分数区间"两种查询的区别——`ZRANGE` 的默认行为是最常踩的坑

## 一、心智模型：Set 的每个成员带一个分数

```
key: rank:game
   成员        分数(score)
   alice  →    350
   bob    →    500
   carol  →    500
   dave   →    120
（内部按分数升序排好：dave(120) < alice(350) < bob(500) = carol(500)）
```

| 规则 | 说明 |
|------|------|
| **成员唯一** | 同 Set 的去重规则；`ZADD` 已存在成员 = 改分数 |
| **分数可重复** | 多人可以同分 |
| **按分数排序** | 排序是**数据结构自带的**（跳表 + 哈希表），插入即排好，取区间 O(log N) |
| 分数是 64 位 double | 可用整数、小数、`+inf` / `-inf`（正/负无穷） |

同分时按**成员名的字典序**排列（成员当作字节序列比较）——排行榜的"同分先到先得"要自己加规则，见陷阱 4。

## 二、基础命令实操

```
127.0.0.1:6379> ZADD rank:game 350 alice 500 bob 500 carol 120 dave
(integer) 4                       ← 新建成员数
127.0.0.1:6379> ZSCORE rank:game alice
"350"
127.0.0.1:6379> ZRANGE rank:game 0 -1 WITHSCORES      # 按名次取（升序）
1) "dave"
2) "120"
3) "alice"
4) "350"
5) "bob"
6) "500"
7) "carol"
8) "500"
127.0.0.1:6379> ZREVRANGE rank:game 0 2 WITHSCORES    # 降序 Top 3
1) "bob"
2) "500"
3) "carol"
4) "500"
5) "alice"
6) "350"
127.0.0.1:6379> ZRANK rank:game alice                 # 名次（0 起，升序）
(integer) 1
127.0.0.1:6379> ZREVRANK rank:game alice              # 倒数名次（0 起，降序）
(integer) 2                        ← alice 是第 3 名
```

| 命令 | 作用 | 复杂度 |
|------|------|--------|
| `ZADD key 分数 成员 [分数 成员...]` | 加成员 / 改分数 | O(log N) |
| `ZSCORE key 成员` | 查分数 | O(1) |
| `ZCARD key` | 成员数 | O(1) |
| `ZRANK` / `ZREVRANK key 成员` | 名次（升/降序，0 起） | O(log N) |
| `ZRANGE key 起 止 [WITHSCORES]` | **按名次区间**取 | O(log N + 片段长) |
| `ZREVRANGE key 起 止` | 按名次倒序取 | 同上 |
| `ZRANGE key 最小 最大 BYSCORE [BYSCORE]` | **按分数区间**取（见下） | 同上 |
| `ZCOUNT key 最小 最大` | 分数区间内成员数 | O(log N) |
| `ZINCRBY key 增量 成员` | 分数原子增减 | O(log N) |
| `ZREM key 成员` | 删成员 | O(log N) |
| `ZPOPMIN` / `ZPOPMAX key [n]` | 弹出最低/最高分成员 | O(log N) |

### 同分排序演示

上面 `bob` 与 `carol` 同为 500，`ZREVRANGE` 输出 bob 在前——**同分按成员字典序**（"bob" < "carol"）。

## 三、`ZRANGE` 的两种区间：本篇最重要的区分

`Redis 6.2+` 统一了语法，`ZRANGE` 一个命令按参数切换语义：

| 写法 | 语义 | 例子 |
|------|------|------|
| `ZRANGE k 0 9` | **名次区间**：第 1 到第 10 名 | 取 TopN |
| `ZRANGE k 100 200 BYSCORE` | **分数区间**：分数 ∈ [100, 200] | "及格的所有人" |
| `ZRANGE k 100 (200 BYSCORE` | `(数字` = **开区间**（不含 200） | 分数 < 200 |
| `ZRANGE k +inf 500 BYSCORE REV` | 倒着取分数区间 | 分数 ≤ 500 的最高分们 |

```
127.0.0.1:6379> ZRANGE rank:game 300 +inf BYSCORE     # 分数 ≥ 300 的成员（升序）
1) "alice"
2) "bob"
3) "carol"
```

> 历史注：`ZRANGEBYSCORE` / `ZREVRANGEBYSCORE` 是旧写法，`6.2+` 起官方推荐改用上面的 `ZRANGE ... BYSCORE` 统一形式。两者目前都可用。

**默认（不带 BYSCORE）是按名次！** 想查"分数在 X 以上的"却写了 `ZRANGE k 0 -1`，得到的是整个榜单——这是本类型第一大坑。

## 四、完整实战：游戏排行榜

```
# 玩家得分事件（分数累加，原子）
ZINCRBY rank:game 50 alice

# 实时 Top 10（降序）
ZREVRANGE rank:game 0 9 WITHSCORES

# 查某玩家分数与名次
ZSCORE rank:game alice
ZREVRANK rank:game alice          # 返回 nil = 不在榜

# 发奖：取出前 3 名并清榜
ZPOPMAX rank:game 3

# 全体加 10% 活动（分数整体调整没有单命令，逐成员 ZINCRBY，或读出后重写）
```

另一个高频用法——**按时间索引**：分数存时间戳，就得到"某时间段内的记录"：

```
ZADD events 1759150800 "click:u1" 1759154400 "buy:u2"
ZRANGE events 1759150800 1759154400 BYSCORE    # 该时间窗内的事件
```

## 五、机制层一瞥

Sorted Set 同时维护两种结构：**跳表（skiplist）**——按分数有序，支撑 O(log N) 的插入与区间查询；**哈希表**——成员→分数，支撑 O(1) 的 `ZSCORE`。两者各干各的活，这就是"既能查名次又能查分数"都很快的原因。跳表原理属进阶内容。

---

## 六、陷阱

1. **`ZRANGE k 0 -1` 是名次全量，不是分数全量**——"我要查分数 ≥ 100 的"必须写 `BYSCORE`。
2. **`ZRANK` 从 0 开始**：返回 2 是第 3 名。给用户显示时要 +1。
3. **分数是 double**：`0.1 + 0.2` 类浮点误差同样存在；金额累加建议用整数（分）。
4. **同分排序是字典序，不是"先到达"**：要"同分先到先得"，惯用技巧是分数拼时间戳——如 `分数 * 10^13 + (MAX - 微秒时间戳)`（高分优先、同分时间早优先）。理解思想即可，用到时再推导。
5. **删除不存在成员返回 0，不报错**；`ZSCORE` 查不存在成员返回 `(nil)`，别与分数 0 混淆。

---

## 小结

- Sorted Set = 成员唯一 + 分数排序（跳表+哈希表双结构）
- `ZRANGE` 默认按**名次**；`BYSCORE` 才是按**分数**；`(n` 开区间；`+inf/-inf` 无穷
- `ZREVRANK`+1 得名次；`ZINCRBY` 原子改分；`ZPOPMAX` 取榜首清榜
- 分数是 double，金额用整数分

2. 构造两个同分成员，用 `ZREVRANGE` 验证字典序规则。
