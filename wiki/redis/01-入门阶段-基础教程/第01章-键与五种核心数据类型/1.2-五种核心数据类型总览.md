# 五种核心数据类型总览

## 学习目标

读完本篇，你应当能够：

1. 一句话描述每种类型的"数据形态"并各举一个典型场景
2. 面对"我要存 X"的需求，能选出合理的类型
3. 用 `TYPE` 命令确认任意 key 的实际类型

## 一、一张表看全五种类型

| 类型 | 数据形态（心智模型） | 典型场景 | 代表命令 |
|------|---------------------|----------|----------|
| **String** | 一个值（字符串/数字/序列化字节） | 缓存、计数器、分布式锁的值 | `SET` `GET` `INCR` |
| **List** | 双端可进出的**有序**元素序列（像双端队列） | 最新动态、任务队列、时间线 | `LPUSH` `RPUSH` `LPOP` `LRANGE` |
| **Hash** | 字段→值 的映射（像嵌套的小字典） | 对象：用户资料、会话数据 | `HSET` `HGET` `HGETALL` |
| **Set** | **无序**、**去重**的元素集合 | 标签、共同好友、抽奖、去重 | `SADD` `SISMEMBER` `SINTER` |
| **Sorted Set** (ZSet) | 成员→分数 的集合，**按分数自动排序**；成员唯一 | 排行榜、优先级队列、按时间索引 | `ZADD` `ZRANGE` `ZSCORE` |

用 Python 类型做类比（仅帮助理解，Redis 实现远比这精巧）：

| Redis 类型 | 近似的 Python 形态 |
|------------|-------------------|
| String | `str` / `int` / `bytes`（一个整体） |
| List | `collections.deque`（两端快进快出） |
| Hash | `dict`（一层，且值只能是"字符串"） |
| Set | `set` |
| Sorted Set | `dict` + 按 value 排序的索引（`member -> score`，能按 score 区间取） |

## 二、选型决策：按"你要对数据做什么"来选

类型选择不取决于"数据长什么样"，而取决于**"最频繁的操作是什么"**：

| 你的高频操作 | 该选 | 例子 |
|--------------|------|------|
| 整存整取一个值 | String | 缓存一段 JSON、一个计数器 |
| 只改对象的一个字段、只读一个字段 | Hash | 用户资料改昵称、会话续期 |
| 两端插入/弹出、按序消费 | List | 消息队列（生产者 `LPUSH`，消费者 `BRPOP`） |
| 判断"在不在"、去重、集合运算 | Set | "这个用户点过赞吗"、共同关注 |
| 按分数/时间排序取 TopN、按区间取 | Sorted Set | 排行榜 Top 10、"最近一小时的请求" |

**两个真实例子**（来自你的技术栈）：

1. **缓存 LLM 的 embedding**：整存整取 → String（key 为文本哈希，value 为序列化的向量字节）
2. **Agent 会话状态**：会话有多个字段（角色、轮次、摘要），常改单个字段 → Hash（key 为 `session:{id}`，field 为 `role` / `turns` ...）

## 三、验证类型的命令：TYPE

```
127.0.0.1:6379> SET s "hello"
OK
127.0.0.1:6379> TYPE s
string
127.0.0.1:6379> LPUSH l a b
(integer) 2
127.0.0.1:6379> TYPE l
list
```

`TYPE` 返回小写类型名：`string` / `list` / `hash` / `set` / `zset`。键不存在时返回 `none`。

**排错时先 `TYPE`**——`WRONGTYPE` 报错的唯一解法入口（见 [[redis/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]]）。

## 四、先知道有、入门不学

Redis 还有这些类型/能力，**属于中段及以后**，这里只报个名字免得你看到时恐慌：

| 名字 | 一句话 | 阶段 |
|------|--------|------|
| Bitmap（位图） | 把 String 当位数组用，海量布尔状态 | 中段 |
| HyperLogLog | 极小内存估算基数（约多少个不同元素） | 中段 |
| Stream | 更强的消息队列（消费者组、确认机制） | 中段 |
| GEO | 存坐标、算距离（基于 Sorted Set） | 中段 |
| JSON / Search / TimeSeries | 文档、全文搜索、时序（Redis 8.0+ 开源版内置，旧称 Redis Stack） | 中段 |

---

## 五、陷阱

1. **"存对象"别急着用 String + JSON。** 能用 String 存 JSON，但改一个字段要整取整存；字段级操作是 Hash 的主场。反过来，**只整存整取时别用 Hash**——徒增复杂度。
2. **Set 无序 ≠ List 无序**：Set 是"集合语义"（去重、成员判断 O(1)），List 是"序列语义"（保序、可重复）。判断"在不在"用 List `LRANGE` 全捞是常见误用。
3. **Sorted Set 的"有序"是按分数，不是按插入顺序**——要按插入顺序就用 List。
4. 混用同一 key 的类型会静默覆盖（见 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.1-Key与Value的世界观]] 陷阱节）。

---

## 小结

- 五种类型 = 五种"对数据的操作方式"：整体、字段、两端、成员、分数排序
- 选型看高频操作，不看数据外形
- `TYPE` 是排错第一反应
- Bitmap / HyperLogLog / Stream / JSON 等是中段内容
