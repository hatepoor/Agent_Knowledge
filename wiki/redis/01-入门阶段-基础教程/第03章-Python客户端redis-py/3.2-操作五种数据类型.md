## 一、返回类型对照（先背这张表）

redis-cli 里看到的前缀（[[redis/01-入门阶段-基础教程/第00章-学前准备/0.3-redis-cli第一次连接]]），在 Python 里就是对应的返回类型：

| redis-cli 显示 | redis-py 返回（decode=True） | 例子 |
|----------------|------------------------------|------|
| `OK` / `PONG` | `True` | `r.set(...)` → `True` |
| `(integer) 3` | `int` | `r.incr(k)` → `3` |
| `"(nil)"` | `None` | `r.get(不存在的键)` → `None` |
| 多行列表 | `list[str]` | `r.lrange(...)` |
| Hash 全量 | `dict[str, str]` | `r.hgetall(...)` |
| ZSet 区间 | `list`（元素是 `str` 或 `(成员, 分数)` 元组） | `r.zrange(k, 0, -1, withscores=True)` |

**编码注意**：`withscores=True` 时分数是 `float`（ZSet 分数本来就是 double，复习 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.7-SortedSet有序集合]] 陷阱 3）。

## 二、五种类型核心操作速写

### String

```python
r.set("cache:user:1", "张三", ex=300)          # SET ... EX 300
r.get("cache:user:1")                          # '张三' | None
r.set("lock:job", "owner-1", nx=True, ex=10)   # 抢锁：成功 True，被占 None
r.incr("rate:api:u1")                          # 1（不存在从 0 起）
r.incrby("rate:api:u1", 100)
r.mset({"a:1": "x", "a:2": "y"})
r.mget(["a:1", "a:2", "nope"])                 # ['x', 'y', None] ← 位置对齐
```

### List

```python
r.rpush("queue:jobs", "job-1", "job-2")        # 右端入队
r.lpop("queue:jobs")                           # 'job-1'
r.lrange("feed:u1", 0, 99)                     # 前 100 条
r.ltrim("feed:u1", 0, 99)                      # 只留前 100
r.llen("feed:u1")
r.blpop("queue:jobs", timeout=5)               # 阻塞 ≤5s：('queue:jobs', 'job-x') | None
```

`blpop` 超时返回 `None`——**一定要判空**，否则 `None[1]` 直接炸。

### Hash

```python
r.hset("session:abc", mapping={"user": "u1", "model": "deepseek-chat", "turns": 0})
r.hget("session:abc", "model")                 # 'deepseek-chat'
r.hgetall("session:abc")                       # {'user': 'u1', ...}
r.hincrby("session:abc", "turns", 1)           # 字段原子 +1 → 1
r.hdel("session:abc", "model")
r.expire("session:abc", 3600)                  # TTL 属于整个 key（复习 2.1）
```

`hset` 有两种参数形态：`r.hset(key, "field", "value")` 单字段；`mapping={...}` 批量。

### Set

```python
r.sadd("tags:post-1", "python", "redis")
r.sismember("tags:post-1", "redis")            # True / False
r.smembers("tags:post-1")                      # {'python', 'redis'} ← set 类型
r.scard("tags:post-1")                         # 2
r.sinter("follow:alice", "follow:bob")         # 交集 → set
r.sdiff("follow:alice", "follow:bob")          # 差集
r.spop("lottery", 3)                           # 随机抽 3 个并移除 → list
```

### Sorted Set

```python
r.zadd("rank:game", {"alice": 350, "bob": 500})
r.zincrby("rank:game", 50, "alice")            # 400.0 ← float
r.zrevrange("rank:game", 0, 9, withscores=True)  # [('bob', 500.0), ('alice', 400.0)]
r.zscore("rank:game", "alice")                 # 400.0 | None
r.zrevrank("rank:game", "alice")               # 1（0 起 → 第 2 名）
r.zrange("rank:game", 300, "+inf", byscore=True)  # 分数 ≥ 300（BYSCORE）
r.zpopmax("rank:game", 3)
```

## 三、pipeline：把 N 次往返压成 1 次

复习 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.3-String字符串]] 的结论：每条命令一次网络往返。**pipeline（管道）** 把一批命令攒起来、一次发出、一次收回所有结果：

```python
with r.pipeline() as pipe:
    pipe.set("k1", "v1")
    pipe.incr("counter")
    pipe.rpush("log", "batch-write")
    results = pipe.execute()        # [True, 1, 1] ← 顺序与入队一致

# 或函数式：
results = (r.pipeline()
           .set("k1", "v1")
           .incr("counter")
           .execute())
```

| 要点 | 说明 |
|------|------|
| 收益 | 纯网络层优化：N 次 RTT → 1 次 |
| **不是事务** | 默认 `transaction=False`：命令之间可能插入其他客户端的命令。要"打包且不被插队"需开启事务（`MULTI/EXEC`），属**中段**内容 |
| 适用 | 批量写、聚合读（如一次取 20 个键拼页面） |
| 限度 | 不是越多越好：攒几万条会撑爆缓冲区，几百一条为宜 |

`execute()` 的返回是**列表**，按入队顺序对应每条命令的结果——类型各异，按下标取用（对照第一节那张表）。

## 四、一个完整小案例：给 Agent 会话加缓存层

综合运用本篇与前面各章（Hash 存会话、String 存 LLM 响应缓存、pipeline 批量读）：

```python
import json
import redis

r = redis.Redis(decode_responses=True)

def save_session(sid: str, user: str, model: str):
    r.hset(f"session:{sid}", mapping={
        "user": user, "model": model, "turns": 0,
    })
    r.expire(f"session:{sid}", 3600)          # 会话 1 小时

def next_turn(sid: str) -> int:
    return r.hincrby(f"session:{sid}", "turns", 1)   # 原子轮次

def cache_llm_reply(prompt_hash: str, reply: dict):
    r.set(f"llm:{prompt_hash}", json.dumps(reply), ex=600)  # 回复缓存 10 分钟

def get_llm_reply(prompt_hash: str) -> dict | None:
    raw = r.get(f"llm:{prompt_hash}")
    return json.loads(raw) if raw is not None else None    # ★ nil → None → 判空
```

逐行对应已学知识：`mapping=` 批量写字段（Hash）、`expire` 作用于整个 key（[[redis/01-入门阶段-基础教程/第02章-过期机制与通用Key命令/2.1-Key的过期机制]]）、`hincrby` 字段原子计数、`get` 的 `None` 判空（[[redis/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]] 的 `(nil)`）。

## 五、陷阱

1. **拿返回值当布尔**：`r.get(k)` 返回空字符串 `""` 是"存在但为空"（真值），`None` 才是"不存在"。判断存在性用 `r.exists(k)`。
2. **`zincrby` / `zscore` 返回 float**：`400.0` 不是 `400`；比较与显示时留意。
3. **`blpop` 超时返回 None**：必须判空再取元素。
4. **`smembers` 返回 set、`hgetall` 返回 dict**：顺序都无意义（复习 Set 无序、Hash 字段无序），别按顺序下标。
5. **pipeline 默认非原子**：要不被插队需事务/`transaction=True`（中段）；把 pipeline 当"一批要么全成功要么全不执行"是错的。
6. **`decode_responses=True` 下存二进制**（pickle/png）会解码报错——二进制场景单独用一个 `decode_responses=False` 的客户端实例。

## 小结

- 命令即方法：五种类型的命令全部按"小写 + 关键字参数"映射，返回类型与前缀一一对应
- `None` / `float` / 顺序无关容器是三个最容易出 bug 的返回形态
- pipeline = 网络往返优化，默认非事务
- 入门阶段的终点：你能用 Redis 存缓存、会话、计数、队列、排行，并知道每种坑在哪
