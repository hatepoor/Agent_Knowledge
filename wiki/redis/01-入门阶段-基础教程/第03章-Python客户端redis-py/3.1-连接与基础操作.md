## 一、安装与版本基线（截至 2026-09）

```bash
pip install redis            # 或 pip install "redis[hiredis]" 获得更快的解析器
```

| 事实 | 内容 |
|------|------|
| 最新版 | **redis-py 8.1.0**（2026-07-30，MIT 协议） |
| Python 要求 | 3.10+（8.2.0 起支持 3.9+ 的旧环境已过时；当前主线 3.10+） |
| 服务端兼容 | 6.0+ 支持 Redis 7.2 至当前 8.x |
| `8.0` 起的重要默认值变化 | ① 线上协议默认 **RESP3**（服务端需 `Redis 6.0+`）；② 连接池默认上限 **100**；③ `socket_timeout` 默认 **5 秒**；④ 默认重试 **10 次**（指数退避） |

> 这些新默认值意味着：升级到 redis-py 8 后，"卡死的命令"最多 5 秒就会抛超时异常（老版本默认无限等待）——对生产是好事，但老代码里依赖"永不超时"的写法会开始报错。

## 二、第一个程序

```python
import redis

r = redis.Redis(
    host="localhost",
    port=6379,
    db=0,
    decode_responses=True,   # ★ 必设，见下文
)

print(r.ping())        # True
r.set("hello", "world", ex=60)
print(r.get("hello"))  # 'world'   （ex=60 对应 SET ... EX 60）
print(r.ttl("hello"))  # 58 左右
```

### `decode_responses=True`：入门期最值得记住的一个参数

Redis 的值是**字节序列**（复习 [[redis/01-入门阶段-基础教程/第01章-键与五种核心数据类型/1.1-Key与Value的世界观]]）。redis-py 默认原样返回 `bytes`：

```python
r = redis.Redis()                  # 忘了设 decode_responses
r.set("k", "你好")
r.get("k")                         # b'\xe4\xbd\xa0\xe5\xa5\xbd'  ← 字节串
r.get("k").decode("utf-8")         # '你好'  ← 每次都要手动 decode

r = redis.Redis(decode_responses=True)
r.get("k")                         # '你好'  ← 自动按 UTF-8 解码成 str
```

**规则**：处理文本数据的程序一律 `decode_responses=True`；只有当值是二进制（图片、pickle、序列化向量）时才用默认 `bytes` 模式，且此时**不要**设 True（会尝试把二进制按 UTF-8 解码而炸掉）。**整个项目内保持统一**。

## 三、方法名映射规则

> **redis-py 的方法名 = Redis 命令名转小写**，参数与命令选项同名（Python 关键字冲突时加下划线）。

| Redis 命令 | redis-py 方法 | 备注 |
|------------|---------------|------|
| `SET k v EX 60 NX` | `r.set("k", "v", ex=60, nx=True)` | 选项变关键字参数 |
| `GET k` | `r.get("k")` | |
| `DEL k` | `r.delete("k")` | **唯一大名鼎鼎的例外**：`del` 是 Python 关键字 |
| `EXPIRE k 60` | `r.expire("k", 60)` | |
| `INCR k` | `r.incr("k")` | |
| `EXISTS k` | `r.exists("k")` | 多键返回计数 |
| `SCAN 0 MATCH p*` | `r.scan(0, match="p*")` / `r.scan_iter("p*")` | `scan_iter` 是**生成器封装**，自动接力游标，日常用这个 |

命令行里会什么，Python 里就会什么——这是 redis-py 的设计哲学：它不发明抽象，只做命令的映射。忘了签名就查 [[redis/速查索引]] 或 `HELP 命令`。

`scan_iter`（把 [[redis/01-入门阶段-基础教程/第02章-过期机制与通用Key命令/2.2-通用Key命令与SCAN]] 的手动接力封装成 for 循环）：

```python
for key in r.scan_iter(match="user:*", count=500):
    print(key)
```

## 四、连接池（机制层）

**每个 `redis.Redis` 实例默认自带一个连接池**——你每次调用 `r.get(...)` 时，客户端从池里借一条连接，用完还回去，而不是每次新建 TCP 连接。

```python
# 让多个客户端实例共享一个池（Web 应用标准做法）
pool = redis.ConnectionPool(
    host="localhost", port=6379, db=0,
    decode_responses=True, max_connections=50,
)
r1 = redis.Redis(connection_pool=pool)
r2 = redis.Redis(connection_pool=pool)
```

| 要点 | 说明 |
|------|------|
| 为什么池必要 | TCP 三次握手 + 认证往返有成本；并发场景反复建连接会拖垮两端 |
| `max_connections` | `redis-py 8.0+` 默认 100；池满且无空闲连接时抛 `ConnectionError`（老版本默认无限建连） |
| `socket_timeout` | 单命令允许的最长等待，`8.0+` 默认 5 秒 |
| 连接 URL 写法 | `redis.from_url("redis://localhost:6379/0", decode_responses=True)`——配置文件/环境变量友好，`db 号`放在路径上 |

## 五、asyncio 风格（FastAPI / 异步 Agent 适用）

`redis.asyncio`（同包内，无需另装）：

```python
import asyncio
import redis.asyncio as redis

async def main():
    r = redis.from_url(
        "redis://localhost:6379/0",
        decode_responses=True,
    )
    await r.set("hello", "world", ex=60)
    print(await r.get("hello"))     # world
    await r.aclose()                # 关闭连接池（4.x+ 用 aclose；close 已废弃）

asyncio.run(main())
```

| 要点 | 说明 |
|------|------|
| 全部方法加 `await` | 连接、命令、关闭都是异步的 |
| 池的关闭 | FastAPI 里放在 lifespan 的 shutdown 阶段（与 [[fastapi/后台任务与长时间Agent作业]] 的生命周期管理同思路） |
| 同步 or 异步？ | FastAPI / asyncio 程序**必须**用 `redis.asyncio`，用同步客户端会阻塞事件循环 |

## 六、陷阱

1. **忘记 `decode_responses=True`**，然后到处 `b'...'`、两个"看起来一样"的字符串比较不相等——入门第一大坑。先想清楚值是文本还是二进制，再决定。
2. **在 asyncio 程序里用了同步 `redis.Redis`** → 每条命令卡住整个事件循环，全服务变慢。
3. **每次请求 new 一个 `Redis` 实例**（比如在 FastAPI 的每个 handler 里创建）：每次都新建连接池，池的意义归零。全局建一次，依赖注入使用。
4. **值直接 `int`/`dict` 传给 `set()`**：`r.set("k", 123)` 可以（数字会被转成字符串），但 `r.set("k", {"a": 1})` 报错——复杂对象要自己序列化（`json.dumps` / `pickle`），Redis 不知道什么是 dict。存结构化数据更推荐直接用 Hash 或 JSON 类型（中段）。
5. **redis-py 8 升级后"突然超时"**：默认 `socket_timeout=5s` 所致，定位慢命令而不是先调大超时。

---

## 小结

- `redis.Redis(decode_responses=True)` 是文本场景的标准开局；方法名 = 命令名小写（`DEL`→`delete` 唯一例外）
- 连接池默认自带；`8.0+` 默认 100 连接 / 5s 超时 / 重试 10 次
- 异步程序用 `redis.asyncio`，池在 lifespan 中统一创建与关闭
- `scan_iter` 是 SCAN 的生成器封装，日常遍历用它

## 练习

1. 分别用 `decode_responses=False/True` 连接，`set`/`get` 一个中文值，观察返回类型差异。
2. 用 `scan_iter` 清理 `test:*` 前缀的所有键（`r.delete(key)`）。
3. 写一个 FastAPI 最小应用：lifespan 里建 `redis.asyncio` 连接，一个接口读写一个计数器。
