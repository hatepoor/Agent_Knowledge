# Redis 学习路线图

> 本文回答三个问题：**现在在哪、下一步学什么、学到什么程度算过关。**
> 版本基线与组织结构见 [[redis/README]]。

---

## 一、总路线

```
【入门】会用：选对类型存取 + 接入 Python 项目          ← 已建成 ✅
   │
【中段】用对：数据不丢（持久化）、并发不崩（缓存模式）、规模可扩（高可用）
   │
【进阶】懂原理：单线程模型、RESP 协议、内部编码
```

| 阶段 | 状态 | 定位 | 组织方式 |
|------|------|------|----------|
| 入门 | ✅ 15 篇已建成 | 会用 | 顺序章节（[[redis/01-入门阶段-基础教程/00-章节目录]]） |
| 中段 | 🚧 规划中（8 个专题） | 用对 | 平行专题，按需取用 |
| 进阶 | 🚧 规划中（4 个专题） | 懂原理 | 深度专题 |

## 二、入门阶段（已建成）

**能力出口**：给定一个 Python 项目需求（缓存 / 会话 / 计数 / 队列 / 排行），能独立完成"选类型 → 写命令 → redis-py 接入 → 设过期 → 排错"。

**毕业自测清单**（每条都能不查资料回答/做到，即为过关）：

- [ ] 一句话讲清 Redis 与 PostgreSQL 的分工
- [ ] `SET` 的 `NX` / `EX` / `KEEPTTL` 各自解决什么问题
- [ ] `INCR` 为什么不需要锁；GET+SET 计数错在哪
- [ ] 五种类型各举一个场景；"字段级更新"选谁、"TopN"选谁、"判断在不在"选谁
- [ ] `TTL` 的 `-1` 与 `-2` 区别；`SET` 覆盖后 TTL 怎么了
- [ ] `KEYS` 为什么生产禁用；`SCAN` 的结束判据是什么
- [ ] redis-py 的 `decode_responses=True` 影响什么；`DEL` 对应的方法名
- [ ] pipeline 与事务的区别（答出"网络优化 vs 不被插队"即可）

## 三、中段阶段（规划：8 个专题）

按"先保证数据与正确性，再谈性能与规模"排序：

| # | 专题 | 核心问题 | 依赖 |
|---|------|----------|------|
| 1 | **持久化：RDB 与 AOF** | 重启后数据还在吗？两种机制怎么选、怎么混用（混合持久化） | 入门 |
| 2 | **发布订阅与 Stream** | 多个服务怎么实时收消息？Stream 的消费者组如何保证不丢 | 入门（List 队列） |
| 3 | **事务与 Lua 脚本** | 多条命令如何"不被插队"？`MULTI/EXEC` 的边界与 Lua 的原子性 | 入门（pipeline） |
| 4 | **管道与性能** | pipeline 深入、hiredis、批量设计、慢查询定位（`SLOWLOG`） | 入门 |
| 5 | **缓存三大问题与缓存模式** | 穿透 / 击穿 / 雪崩的成因与解法；旁路缓存（cache-aside）模式 | 入门（TTL） |
| 6 | **分布式锁** | `SET NX` 锁的缺陷、看门狗续期、Redlock 争议 | 专题 3 |
| 7 | **内存淘汰与 maxmemory** | 内存满了怎么办？8 种淘汰策略、大 key 治理 | 专题 5 |
| 8 | **高可用：主从 / 哨兵 / 集群** | 数据复制、故障转移、分片；集群为什么只有 db0 | 专题 1 |

**中段毕业标准**：能为一个真实服务设计完整的 Redis 使用方案（缓存策略 + 持久化配置 + 容量规划 + 故障预案），并说清每个决策的理由。

## 四、进阶阶段（规划：4 个专题）

| # | 专题 | 核心问题 |
|---|------|----------|
| 1 | **单线程模型与事件循环** | 为什么单线程反而快？6.0+ 的 IO 多线程改了什么 |
| 2 | **RESP 协议** | 客户端与服务端到底在说什么；RESP2 vs RESP3 |
| 3 | **内部编码** | listpack / quicklist / skiplist / intset：内存与速度的取舍 |
| 4 | **过期与淘汰的源码视角** | 定期删除的采样算法、LRU/LFU 的近似实现 |

**进阶毕业标准**：能读懂 Redis 相关的故障报告与性能分析，能评估"这个操作在服务端到底发生了什么"。

## 五、给你的 Agent 技术栈的建议路线

结合你当前的主线（LangChain/LangGraph 多智能体系统），建议的中段学习顺序：

1. **专题 5（缓存模式）+ 专题 1（持久化）先行** —— Agent 的 LLM 响应缓存、embedding 缓存、会话存储是马上能落地的
2. **专题 2（Stream）第二** —— Agent 间异步任务分发、事件流
3. **专题 6（分布式锁）、专题 8（高可用）最后** —— 多实例部署时才真正需要
