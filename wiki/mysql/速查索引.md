# MySQL 速查索引

> **本页定位：给语法骨架与命令清单，不给解释。** 函数的完整清单见 [[mysql/函数手册]]，名词含义见 [[mysql/术语与关键字手册]]。
> ⚠️ **SQL 方言差异**：本页全部是 MySQL 方言，与 PostgreSQL 差异处已标注。

---

## 一、客户端命令

| 命令 | 作用 |
|------|------|
| `mysql -u root -p` | 连上服务器（`-p` 会提示输入密码） |
| `mysql -h host -P 3306 -u user -p dbname` | 指定主机端口与库 |
| `mysql -u root -p -e "SELECT 1;"` | 执行单条命令后退出（脚本常用） |
| `mysql -u root -p --batch --raw < dump.sql` | 批量执行，恢复备份 |
| `mysqladmin -u root -p ping` | 探活，返回 `mysqld is alive` |
| `mysqladmin -u root -p shutdown` | 优雅关闭 |
| `mysqld_safe` | 带自动重启的启动包装 |
| `mysqld --defaults-file=/etc/my.cnf` | 按指定配置文件启动 |

⚠️ **`-p` 和密码之间不能有空格**（`-p123456` 可以，`-p 123456` 会被当成库名）。更安全的做法是 `-p` 交互输入或用 `MYSQL_PWD` 环境变量（仍会出现在进程环境里）。

## 二、常用 SQL 元命令（以 `\` 开头）

⚠️ **这些是客户端命令，不是 SQL，加分号是错的**（见 [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.2-一条SQL语句的组成|psql 元命令原理]]）。

| 命令 | 作用 |
|------|------|
| `\c dbname` | 切换数据库（等同 `USE dbname`） |
| `\G` | ⭐ 把结果显示成竖排表格，长结果集必备 |
| `\g` | 执行当前输入 |
| `\e` | 编辑当前输入后执行 |
| `\s` | 显示当前连接状态 |
| `\q` / `exit` | 退出 |
| `\p` | 打印当前输入 |
| `\i file.sql` | 执行 SQL 文件 |
| `\P` | 打印当前设置（含 `\G` 分隔） |
| `source file.sql` | 同 `\i` |

⭐ **`\G` 是 MySQL 排版利器**：`SELECT * FROM big_table\G` 竖排显示，字段多的表可读性大幅提升。

## 三、DDL 速查

```sql
-- 建库
CREATE DATABASE app CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE app DEFAULT CHARACTER SET utf8mb4;   -- 简写

-- 建表
CREATE TABLE users (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  name VARCHAR(64) NOT NULL DEFAULT '' COMMENT '姓名',
  email VARCHAR(255) NOT NULL COMMENT '邮箱',
  status TINYINT NOT NULL DEFAULT 0 COMMENT '状态',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_email (email),
  KEY idx_status_created (status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- 修改表
ALTER TABLE users ADD COLUMN phone VARCHAR(20) NULL AFTER email;
ALTER TABLE users MODIFY COLUMN name VARCHAR(128) NOT NULL;
ALTER TABLE users DROP COLUMN phone;
ALTER TABLE users ADD INDEX idx_name (name);
ALTER TABLE users RENAME TO users_new;

-- 删除
DROP TABLE IF EXISTS users;
TRUNCATE TABLE users;   -- 清空并重置自增，⚠️ 不可回滚
```

⚠️ **`TRUNCATE` vs `DELETE`**：`TRUNCATE` 更快且重置自增，但**不可回滚、不触发 DELETE 触发器、不支持 WHERE**。

⚠️ **字符集必须是 `utf8mb4`**：MySQL 的 `utf8` 实际是 utf8mb3，**存不了 emoji（4 字节字符）**。

## 四、DML 速查

```sql
-- 插入
INSERT INTO users (name, email) VALUES ('张三', 'a@b.com');
INSERT INTO users (name, email) VALUES ('李四','c@d.com'), ('王五','e@f.com');  -- 批量
INSERT INTO users (name, email) VALUES ('赵六','g@h.com')
  ON DUPLICATE KEY UPDATE name = VALUES(name);   -- 冲突则更新
INSERT IGNORE INTO users (name, email) VALUES ('钱七','i@j.com');  -- 冲突则忽略

-- 查询
SELECT * FROM users WHERE id = 1;
SELECT name, email FROM users WHERE status = 1 ORDER BY created_at DESC LIMIT 10;
SELECT * FROM users WHERE status = 1 LIMIT 10 OFFSET 20;   -- 跳过 20 取 10
SELECT name, COUNT(*) AS cnt FROM users GROUP BY name HAVING cnt > 1;
SELECT DISTINCT status FROM users;

-- 更新与删除
UPDATE users SET status = 2 WHERE id = 1;
DELETE FROM users WHERE id = 1;
DELETE FROM users WHERE created_at < '2020-01-01' LIMIT 5000;   -- ⚠️ 分批删
```

⚠️ **`ON DUPLICATE KEY UPDATE`** 是 MySQL/PG 都有的写法，但 **`VALUES(name)` 在 8.0.20+ 已弃用**，新写法是 `AS new ... new.name`：

```sql
INSERT INTO users (name, email) VALUES ('张三','a@b.com')
  AS new ON DUPLICATE KEY UPDATE name = new.name;
```

## 五、分页与限流

| 需求 | MySQL 写法 | 陷阱 |
|------|-----------|------|
| 跳到第 N 页 | `LIMIT (N-1)*M, M` | 深分页慢，见第六节 |
| 键集分页（推荐） | `WHERE id > last_id ORDER BY id LIMIT M` | ✅ 大表翻页首选 |
| 随机取一条 | `WHERE id >= (SELECT RAND() * MAX(id) FROM t) ORDER BY id LIMIT 1` | 别用 `ORDER BY RAND()` |

⭐ **键集分页是深分页的正解**：`LIMIT 1000000, 20` 要扫描 100 万行，键集分页只扫 20 行。

## 六、MySQL ↔ PostgreSQL 语法差异速查

⭐ **本页最重要的一张表。** 从 PG 迁过来或反过来时必看，详见 [[mysql/01-入门阶段-基础教程/第00章-学前准备/0.3-MySQL与PostgreSQL的差异]]。

| 需求 | MySQL | PostgreSQL |
|------|-------|-----------|
| 限制行数 | `LIMIT n` | `LIMIT n`（同） |
| 跳过前 N 行 | `LIMIT n, m`（跳过 n 取 m） | `OFFSET n LIMIT m` |
| 自增列 | `AUTO_INCREMENT` | `GENERATED ALWAYS AS IDENTITY` / `SERIAL` |
| 字符串 | `VARCHAR(n)` | `VARCHAR(n)` / `TEXT` |
| 真 UTF-8 | `utf8mb4` | `UTF8`（默认即真 UTF-8） |
| 标识符引用 | **反引号** `` `col` `` | **双引号** `"col"` |
| 区分大小写 | 表名 Linux 敏感 / Windows 不敏感 | 永远敏感，必须小写 |
| 数组 | ❌ 无原生数组 | `type[]` / `ARRAY[...]` |
| JSON | `JSON` 类型（二进制存储） | `json` / `jsonb`（拆两个变体） |
| 分页减偏移 | `LIMIT 10, 5` | `LIMIT 5 OFFSET 10` |
| 日期相减天数 | `DATEDIFF(d1, d2)` | `d1 - d2`（直接得 interval） |
| 布尔类型 | `TINYINT(1)` 或 `BOOLEAN` | 原生 `BOOLEAN` |
| 分组 | 宽松（`ONLY_FULL_GROUP_BY` 可关） | 严格 |
| `ILIKE` 大小写不敏感 LIKE | `LIKE`（默认就不敏感） | `ILIKE` |
| 导入导出 | `mysqldump` | `pg_dump` |
| 序列 | 无独立序列（自增） | 独立 `SEQUENCE` |

⚠️ **`LIMIT n, m` 的语义顺序和 PG 的 `LIMIT m OFFSET n` 相反**：`LIMIT 10, 5` 是「跳过 10，取 5」，不是「取 10，跳过 5」。

## 七、诊断命令

| 命令 | 作用 |
|------|------|
| `EXPLAIN SELECT ...;` | 查看执行计划 |
| `EXPLAIN ANALYZE SELECT ...;` | ⚠️ 8.0.18+，**实际执行**，写操作要小心 |
| `SHOW CREATE TABLE t;` | 看建表语句 |
| `SHOW INDEX FROM t;` | 看索引 |
| `SHOW TABLE STATUS LIKE 't'\G` | 表的引擎、行数、大小 |
| `SHOW PROCESSLIST;` | 当前连接与正在执行的语句 |
| `SHOW FULL PROCESSLIST;` | 显示完整语句 |
| `SHOW ENGINE INNODB STATUS\G` | InnoDB 内部状态（锁、事务、历史） |
| `SHOW ENGINE INNODB MUTEX;` | 互斥量竞争 |
| `SHOW BINARY LOGS;` | 列出 binlog 文件 |
| `SHOW MASTER STATUS;` / `SHOW BINARY LOG STATUS;` | 当前 binlog 位点 |
| `SHOW REPLICA STATUS\G` | ⚠️ 8.0.22+ 是 `REPLICA`，之前是 `SLAVE` |
| `SHOW GLOBAL STATUS LIKE 'Threads%';` | 连接与线程状态 |
| `SHOW VARIABLES LIKE 'innodb%';` | 查系统变量 |
| `SHOW WARNINGS;` | 看上一条语句的警告 |
| `ANALYZE TABLE t;` | 更新统计信息 |

⚠️ **`SHOW REPLICA STATUS` 的改名**：`SLAVE` 涉及历史用词，8.0.22 起改为 `REPLICA`。老文章里大量 `SHOW SLAVE STATUS` 已经过时。

## 八、关键配置变量速查

| 变量 | 建议/默认值 | 说明 |
|------|------------|------|
| `innodb_buffer_pool_size` | 物理内存 **50-70%** | ⚠️ 最重要的参数 |
| `innodb_redo_log_capacity` | 8.0.30+，默认 100MB | ⚠️ 旧版本要调两个 redo 参数 |
| `innodb_log_file_size` | 旧版本默认 48MB | 8.0.30+ 用上面的 capacity |
| `innodb_flush_log_at_trx_commit` | **1**（生产） | 1=每次提交刷盘 0=每秒 2=每秒且 OS 崩溃丢 1 秒 |
| `sync_binlog` | **1**（生产） | 1=每次提交同步 binlog |
| `max_connections` | 默认 151 | ⚠️ 太小会连接拒绝，太大会耗内存 |
| `thread_cache_size` | 默认 0（禁用） | 建议设 100-200 |
| `slow_query_log` | 1（开） | 慢日志开关 |
| `long_query_time` | 0.5~1（生产建议） | 默认 10 秒太宽松 |
| `sql_mode` | 含 `STRICT_TRANS_TABLES` | ⚠️ 生产必开严格模式 |
| `binlog_format` | ROW（8.0 默认） | ⚠️ STATEMENT 有主从不一致风险 |
| `character_set_server` | `utf8mb4` | ⚠️ 别用 utf8 |
| `default_time_zone` | `+00:00` 或 `+08:00` | 不要依赖服务器本地时区 |

## 九、备份与恢复命令

| 目的 | 命令 |
|------|------|
| 逻辑备份单库 | `mysqldump -u root -p --single-transaction dbname > db.sql` |
| 逻辑备份多库 | `mysqldump -u root -p --single-transaction --databases db1 db2 > dbs.sql` |
| 只备份结构 | `mysqldump -u root -p --no-data dbname > db_schema.sql` |
| 只备份数据 | `mysqldump -u root -p --no-create-info dbname > db_data.sql` |
| 逻辑恢复 | `mysql -u root -p dbname < db.sql` |
| 表级恢复 | `mysqldump -u root -p --where="id=5" dbname users > u5.sql` |
| 全量物理热备 | `xtrabackup --backup --target-dir=/backup` |
| 物理备份准备 | `xtrabackup --prepare --target-dir=/backup` |
| 物理恢复 | `xtrabackup --copy-back --target-dir=/backup` |
| 查看 binlog 内容 | `mysqlbinlog binlog.000001` |
| 按时间点恢复 | `mysqlbinlog --stop-datetime="2026-01-01 12:00:00" binlog.00000* \| mysql -u root -p` |

⭐ **`--single-transaction` 是 InnoDB 逻辑备份的关键参数**：用一致性快照，不锁表。⚠️ **对 MyISAM 无效**（会锁表）。

## 十、高频陷阱速记

| # | 陷阱 | 一句话 |
|---|------|--------|
| 1 | `utf8` 存不了 emoji | 必须用 `utf8mb4` |
| 2 | `LENGTH()` 是字节数 | 中文用 `CHAR_LENGTH()` |
| 3 | `CONCAT()` 遇 NULL 返 NULL | 用 `CONCAT_WS()` 或 `IFNULL()` |
| 4 | `GROUP_CONCAT` 默认截断 1024 字节 | 调 `group_concat_max_len` |
| 5 | `DAYOFWEEK` 的 1 是周日 | 业务周一用 `WEEKDAY` |
| 6 | MySQL 分钟格式符是 `%i` | 不是 `%M` |
| 7 | `LIMIT n, m` 是跳过 n 取 m | 和 PG 顺序相反 |
| 8 | 深分页 `LIMIT 1000000,20` 极慢 | 用键集分页 |
| 9 | `TRUNCATE` 不可回滚 | 且重置自增 |
| 10 | 长事务拖住 purge | 及时提交 |
| 11 | `innodb_flush_log_at_trx_commit=0` 会丢数据 | 生产必须 1 |
| 12 | `binlog_format=STATEMENT` 有主从不一致风险 | 用 ROW |
| 13 | 慢查询拖住 DDL（MDL 锁） | 先 kill 慢查询 |
| 14 | `SHOW SLAVE STATUS` 已过时 | 8.0.22+ 用 `SHOW REPLICA STATUS` |
| 15 | 大事务回滚代价巨大 | 分批提交 |
