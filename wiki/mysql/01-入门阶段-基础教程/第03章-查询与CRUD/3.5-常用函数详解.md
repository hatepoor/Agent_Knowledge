## 一、函数的「三要素」读法

⚠️ **看任何一个函数，先找这三样：**

```
语法（signature）→ 参数（parameters）→ 返回（return）
```

以 `SUBSTRING` 为例：

| 要素 | 内容 |
|------|------|
| **语法** | `SUBSTRING(str, pos[, length])` |
| **参数** | `str` 源字符串；`pos` 起始位置（**从 1 开始**）；`length` 可选，取多长 |
| **返回** | 截取出的子串 |

```sql
SELECT SUBSTRING('abcdef', 2, 3);   -- 'bcd'  （从第 2 位取 3 个）
SELECT SUBSTRING('abcdef', 4);      -- 'def'  （从第 4 位取到末尾）
```

⚠️ **两个通用注意点**：

1. **⚠️ 位置几乎都从 1 开始**，不是 0（和 Python 不同）
2. **⚠️ 越界不报错**：`SUBSTRING('abc', 10)` 返回空串 `''`

## 三、字符串函数 ⭐

### 3.1 拼接

#### `CONCAT(s1, s2, ...)`

| 项 | 内容 |
|---|---|
| **语法** | `CONCAT(str1, str2, ...)` |
| **参数** | 任意多个字符串 |
| **返回** | 拼接结果 |

```sql
SELECT CONCAT('张', '三');           -- '张三'
SELECT CONCAT('a', 'b', 'c', 'd');  -- 'abcd'
```

#### ⚠️⚠️ `CONCAT` 遇 NULL 返回 NULL

```sql
SELECT CONCAT('Hello, ', NULL);
-- ⚠️ NULL！不是 'Hello, '
```

**这是最高频的坑之一。** 业务场景：`CONCAT(first_name, ' ', last_name)`，只要有人没填 `last_name`，整个结果变 NULL。

#### ⭐ `CONCAT_WS(sep, s1, s2, ...)`

| 项 | 内容 |
|---|---|
| **语法** | `CONCAT_WS(separator, str1, str2, ...)` |
| **参数** | 第一个是分隔符，后面是待拼接字符串 |
| **返回** | 用分隔符拼接，⚠️ **自动跳过 NULL** |

```sql
SELECT CONCAT_WS(',', 'a', NULL, 'b');   -- 'a,b'   ⭐ NULL 被跳过
SELECT CONCAT_WS('-', '2026', '10', '13');  -- '2026-10-13'
```

⭐ **WS = With Separator。要拼接可能为空的字段，一律用 `CONCAT_WS`。**

### 3.2 截取与查找

| 函数 | 语法 | 典型用法 |
|------|------|---------|
| ⭐ `SUBSTRING(s, pos[, len])` | 截取 | `SUBSTRING('abcdef', 2, 3)` → `'bcd'` |
| `LEFT(s, n)` / `RIGHT(s, n)` | 取左/右 n 字符 | `LEFT('13800138000', 3)` → `'138'` |
| `LOCATE(sub, s)` | 找子串位置（0=没找到） | `LOCATE('cd', 'abcdef')` → `3` |
| `INSTR(s, sub)` | 同 `LOCATE`（参数顺序相反） | `INSTR('abcdef', 'cd')` → `3` |

⚠️ **`LOCATE(sub, str)` 和 `INSTR(str, sub)` 参数顺序相反**，极易搞混。

```sql
-- 典型用法：提取域名
SELECT SUBSTRING('user@example.com', LOCATE('@', 'user@example.com') + 1);
-- 'example.com'
```

### 3.3 替换与填充

| 函数 | 语法 | 典型用法 |
|------|------|---------|
| ⭐ `REPLACE(s, from, to)` | 替换**所有**出现 | `REPLACE('a-b-c', '-', '_')` → `'a_b_c'` |
| `TRIM(s)` | 去两端空格 | `TRIM('  ab  ')` → `'ab'` |
| `LTRIM` / `RTRIM` | 去左/右空格 | |
| ⭐ `LPAD(s, n, pad)` / `RPAD` | 补齐到 n 位 | `LPAD('7', 3, '0')` → `'007'` |
| `REPEAT(s, n)` | 重复 n 次 | `REPEAT('ab', 3)` → `'ababab'` |
| `REVERSE(s)` | 反转 | `REVERSE('abc')` → `'cba'` |

⭐ **`LPAD` 的典型场景**：订单号补零对齐、生成固定长度的编号。

```sql
-- 生成 8 位订单号
SELECT CONCAT('SO', LPAD(id, 6, '0')) FROM orders;
-- SO000123
```

### 3.4 长度与大小写 ⚠️

| 函数 | 返回 | ⚠️ 注意 |
|------|------|---------|
| ⚠️ **`LENGTH(s)`** | **字节数** | ⚠️ 中文 utf8mb4 下 1 字符 = 3 字节 |
| ⭐ **`CHAR_LENGTH(s)`** | ⭐ **字符数** | ⭐ 中文场景用这个 |
| `UPPER` / `LOWER` | 转大小写 | |

```sql
SELECT LENGTH('张三');         -- ⚠️ 6（3 字符 × 2 字节，utf8mb4 下是 3 字符 × 3 字节 = 9）
SELECT CHAR_LENGTH('张三');    -- ⭐ 2
```

⚠️⚠️ **`LENGTH('张三')` 在 utf8mb4 下是 9 不是 6。** 这个坑在「限制输入长度」时特别容易出事故：

```sql
-- ❌ 用 LENGTH 限制，中文只能输 1/3 的长度
WHERE LENGTH(input) <= 20

-- ✅ 用 CHAR_LENGTH
WHERE CHAR_LENGTH(input) <= 20
```

## 四、数值函数

| 函数 | 语法 | 返回 | 典型用法 |
|------|------|------|---------|
| ⭐ `ROUND(x, d)` | 四舍五入到 d 位 | 数值 | `ROUND(3.14159, 2)` → `3.14` |
| `CEIL(x)` / `CEILING(x)` | 向上取整 | 整数 | `CEIL(3.1)` → `4` |
| `FLOOR(x)` | 向下取整 | 整数 | `FLOOR(3.9)` → `3` |
| `TRUNCATE(x, d)` | ⚠️ 截断（不四舍五入） | 数值 | `TRUNCATE(3.99, 1)` → `3.9` |
| `ABS(x)` | 绝对值 | 数值 | `ABS(-5)` → `5` |
| `MOD(x, y)` | 取模 | 数值 | `MOD(10, 3)` → `1` |
| `GREATEST(a,b,...)` | 最大值 | 数值 | `GREATEST(3,7,2)` → `7` |
| `LEAST(a,b,...)` | 最小值 | 数值 | `LEAST(3,7,2)` → `2` |
| `POW(x,y)` / `POWER` | 幂 | 数值 | `POW(2,10)` → `1024` |
| `SQRT(x)` | 平方根 | 数值 | `SQRT(16)` → `4` |

⚠️ **`ROUND` vs `TRUNCATE`**：

```sql
SELECT ROUND(3.99, 1);       -- 4.0   （四舍五入）
SELECT TRUNCATE(3.99, 1);    -- 3.9   （直接截断）
```

⚠️⚠️ **`ROUND` 不能修浮点误差**：

```sql
-- 即使 ROUND 了，比较仍可能出问题
SELECT ROUND(0.1 + 0.2, 2) = 0.3;   -- ⚠️ 可能还是 FALSE
```

⭐ **金额从类型上就用 `DECIMAL`，不要指望 `ROUND` 救命。**（见 [[mysql/01-入门阶段-基础教程/第01章-环境与数据类型/1.2-数值类型]]）

## 五、日期时间函数 ⭐

### 5.1 加减与提取

| 函数 | 语法 | 典型用法 |
|------|------|---------|
| ⭐ `DATE_ADD(d, INTERVAL n unit)` | 加时间 | `DATE_ADD(NOW(), INTERVAL 7 DAY)` |
| `DATE_SUB(d, INTERVAL n unit)` | 减时间 | `DATE_SUB(NOW(), INTERVAL 30 DAY)` |
| `EXTRACT(unit FROM d)` | 提取部分 | `EXTRACT(YEAR FROM d)` |
| `YEAR/MONTH/DAY(d)` | 提取年月日 | |
| `HOUR/MINUTE/SECOND(t)` | 提取时分秒 | |
| `LAST_DAY(d)` | 当月最后一天 | `LAST_DAY('2026-02-05')` → `'2026-02-28'` |
| `UNIX_TIMESTAMP(d)` / `FROM_UNIXTIME(ts)` | 时间戳互转 | |

**`INTERVAL` 的单位**：`YEAR` `MONTH` `DAY` `HOUR` `MINUTE` `SECOND` `WEEK` `QUARTER`

```sql
-- 查最近 7 天的订单（⭐ 推荐写法，能用索引）
SELECT * FROM orders
WHERE created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY);

-- ❌ 不推荐（DATE() 包裹列会让索引失效）
SELECT * FROM orders WHERE DATE(created_at) >= DATE_SUB(CURDATE(), INTERVAL 7 DAY);
```

### 5.2 ⚠️ 算差值：`DATEDIFF` vs `TIMESTAMPDIFF`

| 函数 | 精度 | 参数顺序 |
|------|------|---------|
| `DATEDIFF(d1, d2)` | ⚠️ **只到天** | `d1 - d2` |
| ⭐ `TIMESTAMPDIFF(unit, d1, d2)` | ⭐ **到微秒** | `d2 - d1` |

```sql
-- DATEDIFF：抹掉时分秒
SELECT DATEDIFF('2026-10-02 01:00:00', '2026-10-01 23:00:00');
-- ⚠️ 1（实际只差 2 小时）

-- TIMESTAMPDIFF：精确
SELECT TIMESTAMPDIFF(HOUR, '2026-10-01 23:00:00', '2026-10-02 01:00:00');
-- ⭐ 2

SELECT TIMESTAMPDIFF(DAY, '2026-01-01', '2026-10-13');   -- 285
```

⚠️⚠️ **两个函数的参数顺序相反**，且 `DATEDIFF` 会「向上取整到天」。

### 5.3 ⚠️⚠️ `DATE_FORMAT` 的格式符

| 格式符 | 含义 | ⚠️ 常见错认 |
|--------|------|-----------|
| `%Y` / `%y` | 四位年 / 两位年 | |
| `%m` / `%c` | 两位月 / 不补零月 | |
| `%d` | 两位日 | |
| `%H` / `%h` | 24 小时 / 12 小时 | |
| ⚠️ **`%i`** | ⚠️ **分钟** | ⚠️⚠️ **很多人以为 `%M`** |
| ⚠️ **`%M`** | ⚠️ **英文月名**（October） | |
| `%S` / `%s` | 秒 | |
| `%p` | AM/PM | |

```sql
SELECT DATE_FORMAT(NOW(), '%Y-%m-%d %H:%i:%s');
-- 2026-10-14 13:37:00

-- ⚠️ 错误示范
SELECT DATE_FORMAT(NOW(), '%Y-%m-%d %H:%M:%S');
-- 2026-October-14 13:00:00   ← %M 变成了月名，%S 还是秒（碰巧对）
```

⚠️⚠️ **MySQL 的分钟是 `%i` 不是 `%M`。** ⭐ **对照 PostgreSQL**：PG 用 `TO_CHAR(ts, 'YYYY-MM-DD HH24:MI:SS')`——`YYYY` 才是年，`MI` 才是分钟。**跨库迁移时这里必错。**

📌 详见 [[mysql/01-入门阶段-基础教程/第01章-环境与数据类型/1.4-日期时间类型]]。

## 六、条件控制函数 ⭐

### 6.1 三个 NULL 处理函数

| 函数 | 语法 | 行为 |
|------|------|------|
| ⭐ `IFNULL(v, default)` | 两参数 | `v` 为 NULL 返回 `default` |
| ⭐ `COALESCE(v1, v2, ...)` | 多参数 | 返回**第一个非 NULL** |
| `NULLIF(v1, v2)` | 两参数 | 相等返回 NULL，否则返回 `v1` |

```sql
SELECT IFNULL(NULL, 0);              -- 0
SELECT COALESCE(NULL, NULL, 'x');    -- 'x'
SELECT NULLIF(5, 5);                 -- NULL
SELECT NULLIF(5, 3);                 -- 5
```

⚠️ **`IFNULL` 只支持两参数，`COALESCE` 支持任意多个。** ⭐ **跨库兼容用 `COALESCE`**（标准 SQL）。

### 6.2 典型用法

```sql
-- ① 空值显示为「未知」
SELECT name, IFNULL(phone, '未填写') FROM users;

-- ② 多级兜底
SELECT COALESCE(mobile, phone, email) AS contact FROM users;

-- ③ NULLIF 的巧妙用法：把 0 当 NULL 处理（避免除零）
SELECT total / NULLIF(cnt, 0) FROM stats;
-- ⚠️ cnt=0 时返回 NULL，而不是报错
```

### 6.3 `CASE` 表达式

```sql
-- 简单 CASE（等值匹配）
CASE status
  WHEN 'pending'  THEN '待付款'
  WHEN 'paid'     THEN '已付款'
  ELSE '其他'
END

-- 搜索 CASE（条件匹配）
CASE
  WHEN score >= 90 THEN 'A'
  WHEN score >= 80 THEN 'B'
  WHEN score >= 60 THEN 'C'
  ELSE 'F'
END
```

### 6.4 ⭐ `CASE` 做条件聚合（高频）

```sql
SELECT
  COUNT(*) AS total,
  SUM(CASE WHEN status = 'paid' THEN 1 ELSE 0 END) AS paid_cnt,
  SUM(CASE WHEN status = 'pending' THEN 1 ELSE 0 END) AS pending_cnt,
  ROUND(SUM(CASE WHEN status = 'paid' THEN amount ELSE 0 END), 2) AS paid_amount
FROM orders;
```

⭐ **一次扫描算出多个指标**，比多次 `COUNT` 快得多。

## 七、聚合函数 ⚠️

### 7.1 五个基础聚合

| 函数 | 作用 | ⚠️ 注意 |
|------|------|---------|
| `COUNT(*)` | 统计**所有行** | |
| ⚠️ `COUNT(col)` | 统计**非 NULL** 的行 | ⚠️ 不等于 `COUNT(*)` |
| `COUNT(DISTINCT col)` | 去重统计 | |
| `SUM(col)` / `AVG(col)` | 求和 / 均值 | ⚠️ **自动忽略 NULL** |
| `MIN(col)` / `MAX(col)` | 最小 / 最大 | |

⚠️⚠️ **`COUNT(col)` 和 `COUNT(*)` 的区别是高频坑**：

```sql
-- 表里 3 行，其中 1 行 name 是 NULL
SELECT COUNT(*), COUNT(name) FROM users;
-- ⚠️ 3, 2    ← 不一样！
```

### 7.2 ⚠️⚠️ `GROUP_CONCAT` 的 1024 字节截断

```sql
SELECT GROUP_CONCAT(name) FROM users;
-- ⚠️ 结果被静默截断到 1024 字节，不报错！
```

| 项 | 内容 |
|---|---|
| **语法** | `GROUP_CONCAT([DISTINCT] expr [ORDER BY ...] [SEPARATOR str])` |
| **参数** | `DISTINCT` 去重；`ORDER BY` 组内排序；`SEPARATOR` 分隔符（默认 `,`） |
| ⚠️ **默认上限** | ⚠️⚠️ **`group_concat_max_len` 默认 1024 字节** |

**解法**：

```sql
-- 会话级
SET SESSION group_concat_max_len = 1024000;

-- 全局（my.cnf）
[mysqld]
group_concat_max_len = 1024000
```

⚠️⚠️ **这是最隐蔽的 bug 之一**——数据量大时你会发现「少了很多人」，但没有任何报错。

### 7.3 `GROUP BY` 的严格模式

⚠️ **5.7.5 起默认开启 `ONLY_FULL_GROUP_BY`**，此时 SELECT 里的非聚合列必须出现在 `GROUP BY` 中：

```sql
-- ❌ 严格模式下报错
SELECT dept_id, name, COUNT(*) FROM employees GROUP BY dept_id;

-- ✅ 两种改法
SELECT dept_id, name, COUNT(*) FROM employees GROUP BY dept_id, name;
SELECT dept_id, MAX(name) AS name, COUNT(*) FROM employees GROUP BY dept_id;
```

## 九、查不到函数时的三步法 ⚠️

⚠️ **⚠️ 注意：`information_schema.ROUTINES` 只列「存储过程和存储函数」，不列内置函数！** 用 `SELECT CONCAT('a','b')` 试探比查 ROUTINES 更直接。

```
① 直接用，看报错
   SELECT CONCAT('a', 'b');
   -- 如果报 "FUNCTION shop.CONCAT does not exist" → 该版本没有
   -- 如果正常返回 → 存在

② 查 MySQL 官方文档按类别找（权威）
   -- 手册 → Functions and Operators

③ 换等价函数
   -- 例：MySQL 没有 STRING_AGG，用 GROUP_CONCAT
   --     MySQL 没有 IFNULL 的多参数版，用 COALESCE
```

⭐ **「换等价函数」时注意跨库差异**：

| 需求 | MySQL | PostgreSQL |
|------|-------|-----------|
| 组内字符串拼接 | `GROUP_CONCAT` | `string_agg` |
| 空值兜底 | `IFNULL` / `COALESCE` | `COALESCE` |
| 格式化日期 | `DATE_FORMAT(d, '%Y-%m-%d')` | `TO_CHAR(d, 'YYYY-MM-DD')` |
| 找子串 | `LOCATE` / `INSTR` | `POSITION` |
| 大小写不敏感 LIKE | `LIKE`（默认不敏感） | `ILIKE` |

| 6 | ⚠️ `COUNT(col)` 不等于 `COUNT(*)` | 要总行数用 `COUNT(*)` |
