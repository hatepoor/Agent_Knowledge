## 一、什么是数据类型

### 一句话定义

> **数据类型（data type）是「这一列允许存什么、占多少空间、能做什么运算」的规则声明。**

用建表语句来看最直观：

```sql
CREATE TABLE employees (
  id       BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT,   -- 整数
  name     VARCHAR(64)      NOT NULL,                  -- 字符串
  salary   DECIMAL(10,2)    NOT NULL DEFAULT 0,        -- 精确小数
  hired_at DATE             NOT NULL,                  -- 日期
  is_active BOOLEAN         NOT NULL DEFAULT 1         -- 布尔
);
```

⚠️ **每一列都必须有类型，没有「无类型列」这个概念。** 这和 Excel 不一样——Excel 里一格可以今天是数字、明天是文字，数据库不行。

### 数据库为什么必须有类型

三个理由，缺一不可：

| 理由 | 说明 | 没有会怎样 |
|------|------|-----------|
| ⭐ **① 决定占多少空间** | `TINYINT` 1 字节，`BIGINT` 8 字节 | ⚠️ 无法预估磁盘和内存 |
| ⭐ **② 决定能做什么运算** | 数字能加减，日期能算间隔，字符串能拼接 | ⚠️ `'abc' + 1` 该报错还是返回 1？ |
| ⭐ **③ 决定怎么校验** | 类型不匹配时拒绝或转换 | ⚠️ 脏数据直接进库 |

⚠️ **第 ② 点最容易被忽略。** 比如「手机号」——**如果用整数类型存，就无法保留前导 0**（`0755` 会变成 `755`），也**无法参与字符串拼接**（`'+86' + phone` 会变成算术加法）。

## 二、MySQL 怎么校验你写的数据 ⭐

⚠️ **这是本篇最重要的一节。** 不懂这个，后面所有「溢出会怎样」的讨论都看不明白。

### 三种不匹配的情况

```sql
CREATE TABLE t (
  age    TINYINT NOT NULL,
  name   VARCHAR(5) NOT NULL
);
```

| 情况 | 示例 | MySQL 的行为 |
|------|------|-------------|
| ⭐ **① 超出范围** | `INSERT INTO t (age) VALUES (200)` | ⚠️ **取决于 `sql_mode`**，见下 |
| ⭐ **② 超出长度** | `INSERT INTO t (name) VALUES ('张三丰 extra')` | ⚠️ **取决于 `sql_mode`** |
| ⭐ **③ 类型不相容** | `INSERT INTO t (age) VALUES ('abc')` | ⚠️ **取决于 `sql_mode`** |

### ⚠️ 两种后果（核心）

⚠️ **`sql_mode` 里有 `STRICT_TRANS_TABLES` 时**：

```
❌ 直接报错，插入失败
ERROR 1264 (22003): Out of range value for column 'age' at row 1
```

⚠️ **没有 `STRICT_TRANS_TABLES` 时（非严格模式）**：

```
⚠️ 静默截断 / 静默转换，插入「成功」
  200        → 127（TINYINT 上限）
  'abc'      → 0
  '张三丰 extra' → '张三丰'（前 5 个字符）
```

### ⭐ 为什么这件事极其重要

⚠️ **非严格模式下，你以为存了完整数据，实际只存了一部分，而且没有任何报错。**

```
场景：name 是 VARCHAR(5)，用户注册名「张三四五六七」
  ↓
非严格模式：存成「张三四五」，无报错
  ↓
三个月后用户投诉「我的名字怎么变短了」
  ↓
⚠️ 此时已经错了一万条数据，且无法从日志发现
```

⭐ **所以生产环境必须开严格模式**：

```sql
SET GLOBAL sql_mode = 'STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION';
```

📌 详见 [[mysql/01-入门阶段-基础教程/第00章-学前准备/0.2-MySQL架构与客户端]] 第五节的「静默截断」分析。

## 五、本篇的陷阱

1. **❌ 觉得「类型很简单，跳过本篇」。** ⚠️ **本篇第二节目「MySQL 怎么校验」是理解后面所有「溢出」「截断」的前提。**

3. **❌ 在非严格模式下学数据类型。** ⚠️ 你观察不到溢出行为（因为都被静默处理了）。**先开严格模式再学。**

## 小结

- **数据类型 = 「这一列允许存什么、占多少空间、能做什么运算」的规则声明**
- 数据库必须有类型的三个理由：**决定空间 / 决定运算 / 决定校验**
- ⭐ **MySQL 校验写入数据，失败有两种后果：严格模式报错、非严格模式静默截断**
- ⚠️ **「插入成功」不等于「数据对了」**——生产必须开 `STRICT_TRANS_TABLES`
- 本章 8 篇必须按顺序读，**1.1 的「存储范围总表」是地基**
