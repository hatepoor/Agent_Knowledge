# 数据库与 SQL 是什么

## 学习目标

读完本篇，你应当能够：

1. 说出数据库解决的四个问题
2. 说清「库 / 表 / 行 / 列」四个概念
3. 理解 SQL 是什么、为什么叫「声明式语言」
4. 分清客户端与服务器
5. 理解 SQL 的三条书写规则，并能预判自己的语法错误
6. 知道「MySQL 就是数据库吗」这个问题的答案

## 前置知识

| 前置 | 为什么需要 |
|------|-----------|
| 无 | 本篇是零基础起点，**不要求任何前置知识** |

## 一、数据库解决的四个问题

先说清楚「为什么要用数据库」。假设你要做一个员工信息表，用 Excel 存行不行？

**Excel 方案会在四个地方崩掉：**

| 问题 | 场景 | 后果 |
|------|------|------|
| **① 并发写冲突** | 两个员工同时更新自己的联系方式 | 后写的覆盖先写的，数据丢失 |
| **② 数据不一致** | 转岗操作要同时改「部门」和「工资表」两处 | 中途失败导致两处对不上 |
| **③ 权限控制** | 实习生不该看到全公司的薪资 | Excel 文件没法精确控制到「某些行某些列」 |
| **④ 查询效率** | 十万行里找「所有 2024 年入职且工资高于 2 万的」 | Excel 靠人工筛选，秒级变分钟 |

**数据库就是为解决这四件事而生的系统。** 它的核心能力是：

- 用**事务**保证多步操作要么全成要么全败（解决问题②）
- 用**锁与并发控制**让多人同时写不冲突（解决问题①）
- 用**权限体系**精确控制谁能看什么（解决问题③）
- 用**索引**让查找从「全表扫描」变成「直接定位」（解决问题④）

## 二、四个核心概念

### 库（Database / Schema）

**一个独立的逻辑空间**，里面装若干张互相关的表。

类比：一个仓库，里面有多个货架区（库），每个区放不同的货（表）。

```sql
CREATE DATABASE shop;   -- 建一个叫 shop 的库
USE shop;                -- 切到这个库
```

> ⚠️ **MySQL 与 PostgreSQL 的术语差异**：PostgreSQL 里 schema 和 database 基本同义，MySQL 里 `SCHEMA` **就是 `DATABASE` 的同义词**（`CREATE SCHEMA` 等价于 `CREATE DATABASE`）。这个坑见 [[mysql/01-入门阶段-基础教程/第00章-学前准备/0.3-MySQL与PostgreSQL的差异]]。

### 表（Table）

**同类数据的集合**，由行和列定义。

类比：一张 Excel 工作表。但数据库的表有三条额外约束：

| 约束 | 说明 |
|------|------|
| 表名唯一 | 同一个库里不能有两张同名表 |
| 每列有类型 | 数据库会校验类型，`VARCHAR` 列塞数字会报错或被转换 |
| 每行有唯一标识 | 通常是主键，否则无法精确指认某一行 |

### 行（Row）与列（Column）

| 概念 | 术语 | 说明 |
|------|------|------|
| 一行 | **记录 / record / tuple** | 一条完整的数据，比如「张三，25 岁，工程师」 |
| 一列 | **字段 / field / attribute** | 一个属性，比如「姓名」 |

⚠️ **MySQL 里行列的另一个叫法**：一个数据库表也叫「relation（关系）」，行叫「tuple（元组）」，列叫「attribute（属性）」。这是关系型数据库名字的来源（relational algebra 关系代数）。

## 三、SQL 是什么

**SQL = Structured Query Language，结构化查询语言。** 用它对数据库做四类操作：

| 操作类型 | 关键字 | 说明 |
|---------|--------|------|
| **DDL**（定义） | `CREATE` `ALTER` `DROP` `TRUNCATE` | 建库建表改结构 |
| **DML**（操作） | `INSERT` `SELECT` `UPDATE` `DELETE` | 增删改查 |
| **DCL**（控制） | `GRANT` `REVOKE` | 权限管理 |
| **TCL**（事务） | `COMMIT` `ROLLBACK` `START TRANSACTION` | 事务控制 |

### 关键理解：SQL 是「声明式」的

⚠️ **这是本篇最重要的一句话。** 新手最容易卡在这里。

```sql
-- 你写的（声明式）：说清楚「我要什么」
SELECT name, salary FROM employees WHERE dept = '技术部' AND salary > 20000;

-- 数据库做的（命令式）：怎么找到数据
-- 1. 打开 employees 表文件
-- 2. 找到所有 dept='技术部' 的行
-- 3. 过滤出 salary>20000 的
-- 4. 取出 name 和 salary 两列
-- 5. 排序 → 返回结果
```

| 对比 | 声明式（SQL） | 命令式（Python 代码） |
|------|-------------|-------------------|
| 你说什么 | 「我要什么结果」 | 「一步步怎么做」 |
| 谁优化 | **数据库优化器**决定怎么执行 | 你决定执行方式 |
| 换个硬件 | 同一段 SQL 可能就走索引了 | 代码不变，性能不变 |
| 学起来 | 简单，会描述需求就行 | 要懂执行机制 |

⭐ **这个设计的价值在于：优化器（optimizer）**是数据库最核心的组件之一。它根据数据量、索引分布、统计信息自动选执行计划。你写 `WHERE` 时不用管有没有索引——**优化器会替你决定**。详见 [[mysql/02-中段阶段-专题精讲/索引与查询优化/索引诊断与慢查询优化]]。

⚠️ **但优化器会猜错。** 猜错时它可能选一个很慢的执行计划，这时候就需要你用索引提示干预。详见 [[mysql/02-中段阶段-专题精讲/索引与查询优化/EXPLAIN解读]]。

## 四、客户端与服务器

这是新手最容易混淆的一层。

```
[你的程序 / 终端]
       │
       │ TCP 连接（默认端口 3306）
       ▼
[mysqld 服务器进程]        ← 真正存数据、执行 SQL
       │
       ▼
[磁盘上的数据文件 ibdata1 / app.ibd]
```

| 概念 | 说明 |
|------|------|
| **服务器（server）** | MySQL 的服务端程序 `mysqld`，负责存数据和执行 SQL |
| **客户端（client）** | 连上服务器的任意程序，可以是命令行 `mysql`、图形化工具、你的 Python 代码 |
| **端口（port）** | 网络上区分不同服务的编号。MySQL 默认 **3306** |

**类比**：服务器是餐厅的厨房，客户端是顾客。顾客（客户端）点菜（发 SQL），厨房（服务器）做菜（执行并返回结果）。**同一间厨房可以同时服务很多顾客**——这就是「多客户端」。

⚠️ **一个关键推论**：只要能连上 3306 端口并提供正确密码，任何程序都能操作数据库。**这意味着数据库必须放在安全的地方**，不能暴露在公网。详见 [[mysql/02-中段阶段-专题精讲/备份恢复与安全/备份体系与恢复演练]]。

## 五、SQL 的三条书写规则

⚠️ **这三条是新手 90% 语法错误的来源。**

### 规则一：分号结尾

```sql
SELECT name FROM employees;
SELECT * FROM users; SELECT * FROM orders;   -- 分号可以同行
SELECT * FROM a   -- 少了分号 → 客户端一直等
```

⚠️ 客户端会一直等分号（或 `\g`）才把语句发出去。**忘了加分号会表现为「敲回车没反应」。**

### 规则二：关键字大写不影响语义

```sql
select name from employees;   -- 合法
SELECT NAME FROM EMPLOYEES;   -- 也合法
```

⚠️ **但表名和列名的大小写在 MySQL 里受操作系统影响**：

| 环境 | 表名大小写 |
|------|-----------|
| Linux / Unix | **敏感**（`users` ≠ `Users`） |
| Windows | 不敏感 |

**所以规范要求：表名和列名统一用小写下划线风格**，比如 `user_orders`。这个规范能避免「本地能跑、Linux 上报表不存在」的经典事故。

### 规则三：字符串用单引号，标识符用反引号

| 类型 | 用什么 | 例 |
|------|--------|-----|
| 字符串值 | **单引号** `'...'` | `WHERE dept = '技术部'` |
| 数字 | 直接写 | `WHERE salary > 20000` |
| 标识符（表名/列名） | **反引号** `` ` `` | `` SELECT `order` FROM t `` |

⚠️ **为什么字符串必须用单引号？** 因为双引号在标准 SQL 里是标识符引号，而 MySQL 默认把它也当字符串（这叫 `ANSI_QUOTES` 关闭时的行为）。**依赖双引号当字符串，切换模式或迁到 PG 就会崩。**

⭐ **`order` 这类单词必须加反引号**：它是 SQL 保留字。常见保留字：`order`、`group`、`key`、`desc`、`range`、`table`、`select`、`from`、`default` 等。养成习惯：**所有标识符一律加反引号**，能省掉无数问题。

## 六、「MySQL 就是数据库吗」

⚠️ **这是个高频误解。** 准确的说法：

| 概念 | 是什么 | 例子 |
|------|--------|------|
| **数据库（Database）** | 一类软件（管理系统） | Oracle、PostgreSQL、MySQL、SQLite、MongoDB |
| **MySQL** | 数据库软件中的一个**具体产品** | Oracle 公司开发，GPLv2 |
| **mysqld** | MySQL 这个软件的**服务器进程名** | 你启动它，它才开始服务 |
| **MySQL Server** | MySQL 软件的正式名称 | 社区版叫 Community Server |

**再往下的层次：**

```
MySQL 软件
├── mysqld        ← 服务器进程（真正干活）
├── mysql         ← 命令行客户端
├── mysqladmin   ← 管理工具
├── mysqldump     ← 备份工具
├── mysqlbinlog   ← binlog 工具
└── mysqlsh       ← 官方 Shell
```

⚠️ **「装了 MySQL」这句话有歧义**：可能指装了客户端，也可能指装了服务器。判断依据是能不能连上——**服务端才提供数据，客户端只是发请求的**。

## 七、和 PostgreSQL 的关系

本知识库里 [[postgresql/README|PostgreSQL]] 是并列的另一条路线。快速定位：

| 维度 | MySQL | PostgreSQL |
|------|-------|-----------|
| 定位 | 互联网应用、LAMP、国产化替代 | 复杂查询、数据分析能力 |
| 许可证 | **GPLv2**（Community） | PostgreSQL License（更宽松） |
| 历史 | Oracle 主导 | 社区主导（BSD 式） |
| JSON | `JSON` 类型（二进制） | `json` + `jsonb` 两个变体 |
| MVCC 实现 | **undo log 式** | **追加式** |
| 数组类型 | ❌ 无 | ✅ 原生 |
| 严格程度 | 较宽松 | 严格 |

⚠️ **两者语法差异很大，不能照搬。** 完整的差异清单见 [[mysql/01-入门阶段-基础教程/第00章-学前准备/0.3-MySQL与PostgreSQL的差异]]，速查表见 [[mysql/速查索引]]。

## 八、陷阱

1. **❌ 以为 SQL 大小写无关。** 关键字可以，但**表名列名在 Linux 上大小写敏感**。
2. **❌ 字符串用双引号。** 用单引号；双引号是标识符。
3. **❌ 忘记加分号。** 客户端会一直等。
4. **❌ 用保留字做表名不加反引号。** 比如 `order`、`group`。
5. **❌ 把 3306 端口暴露到公网。** 数据库必须隔离。
6. **❌ 以为 MySQL 和 PostgreSQL 语法通用。** 迁移时必踩坑。
7. **❌ 以为「声明式」意味着不用关心性能。** 优化器会猜错，猜错时要靠索引干预。

## 小结

- 数据库解决四个问题：并发写、原子性、权限、查询效率
- 四个概念：库（schema）> 表 > 行（记录）> 列（字段）
- SQL 是**声明式**语言——你描述要什么，优化器决定怎么做
- 客户端发请求，服务器（`mysqld`）执行，默认端口 3306
- 三条书写规则：**分号结尾、表名列名小写、字符串单引号 + 标识符反引号**
- MySQL 是数据库软件的一种，mysqld 是它的服务器进程
