# 安装与连接

## 学习目标

读完本篇，你应当能够：

1. 用 Docker 快速起一个 MySQL 实例（本机 Windows 环境最省事）
2. 用原生安装包在 Linux/macOS 装 MySQL
3. 成功连上并跑通第一条语句
4. 说出 `sql_mode` 为什么要在初始化时就设好
5. 知道数据目录在哪、数据文件长什么样
6. 会用 `docker` 命令做日常管理

## 一、选哪种安装方式

| 方案 | 适合 | 优点 | 缺点 |
|------|------|------|------|
| **A. Docker** ⭐ | Windows 本机、快速试用、团队统一环境 | 30 秒起来，不污染系统、可随意重来 | 数据在卷里，重装要清 |
| **B. 原生安装包** | 生产服务器、要长期维护的实例 | 性能最优、系统服务托管 | 安装步骤多、卸载麻烦 |
| **C. 云托管** | 线上项目 | 免运维、自带备份 | 贵、学习成本在控制台 |

⭐ **对本机 Windows 开发环境，Docker 是最优选择**，且和你的 [[docker/README|Docker 知识库]] 正好衔接。理由：不用反复装卸、版本切换方便、和你其他项目的隔离性好。

## 二、方案 A：Docker（推荐）

### 启动实例

```bash
docker run -d \
  --name mysql9 \
  -e MYSQL_ROOT_PASSWORD=Root@123456 \
  -e MYSQL_DATABASE=app \
  -p 3306:3306 \
  -v mysql9_data:/var/lib/mysql \
  -e TZ=Asia/Shanghai \
  mysql:9.7
```

### 逐个参数解释

| 参数 | 作用 | ⚠️ 注意 |
|------|------|---------|
| `-d` | 后台运行 | |
| `--name mysql9` | 容器名 | 便于后续 `docker exec` / `docker stop` |
| `-e MYSQL_ROOT_PASSWORD` | ⚠️ **root 密码必填** | 8.0 起不填会直接启动失败 |
| `-e MYSQL_DATABASE=app` | 启动时自动建库 | 省一步 `CREATE DATABASE` |
| `-p 3306:3306` | 映射端口 | ⚠️ **只写 `127.0.0.1:3306:3306` 更安全** |
| `-v mysql9_data:/var/lib/mysql` | 数据卷 | ⚠️ **不加这个参数，容器删了数据就没了** |
| `-e TZ=Asia/Shanghai` | 时区 | 避免容器内时间显示异常 |
| `mysql:9.7` | 镜像版本 | ⚠️ **别用 `latest`**，8.0 和 9.7 行为有差异 |

⚠️ **四个必须记住的点：**

1. **数据卷是必须的。** 不加 `-v` 的话，`docker rm` 之后数据全部丢失。这是本节最重要的一个参数。

2. **端口绑定要限定本机。** `-p 3306:3306` 默认监听 `0.0.0.0`，**同网段的其他机器能连上你的数据库**。开发机写 `-p 127.0.0.1:3306:3306`。

3. **别用 `latest`。** MySQL 的 `latest` 现在指向 Innovation 版本，行为可能和你的预期不一致。**明确写版本号。**

4. **密码别写在命令行里。** 命令会进 shell 历史。用 `-e MYSQL_ROOT_PASSWORD`（不写值，Docker 会从交互读取）或 `--env-file`。

### 连接

```bash
# 进入容器用 mysql 客户端
docker exec -it mysql9 mysql -u root -p
# 看到 Enter password: 后输入 Root@123456
```

也可以直接在本机装个客户端（可选）：

```bash
mysql -h 127.0.0.1 -P 3306 -u root -p
```

### 跑通第一条语句

```sql
SELECT VERSION();          -- 确认版本
SELECT @@sql_mode;         -- 确认 sql_mode
SHOW DATABASES;            -- 应该能看到 app 和几个系统库
SELECT 1 + 1 AS result;    -- 最小验证
```

⚠️ **先查 `sql_mode`。** Docker 镜像默认可能不是最严格的组合，建议在配置里显式设成生产值（见第四节）。

### 日常管理命令

```bash
docker ps                        # 看容器状态
docker logs mysql9               # 看日志（排错第一步）
docker exec -it mysql9 mysql -u root -p   # 进客户端
docker stop mysql9               # 停止
docker start mysql9              # 启动
docker rm mysql9                 # 删容器（数据卷还在）
docker volume ls                 # 看数据卷
docker volume rm mysql9_data     # ⚠️ 删数据卷 = 删数据
docker restart mysql9            -- 重启
```

⚠️ **`docker rm mysql9` 删的是容器，数据卷 `mysql9_data` 还在**，重开一个同名容器数据还在。要彻底重来必须 `docker volume rm`。

### 生产配置挂载

⚠️ **开发够用，但生产要用配置文件控制参数**（比如 `sql_mode`、`innodb_buffer_pool_size`）：

```bash
docker run -d \
  --name mysql-prod \
  -e MYSQL_ROOT_PASSWORD='你的强密码' \
  -p 127.0.0.1:3306:3306 \
  -v mysql_data:/var/lib/mysql \
  -v /host/path/my.cnf:/etc/mysql/conf.d/custom.cnf:ro \
  mysql:9.7
```

`my.cnf` 示例：

```ini
[mysqld]
character-set-server = utf8mb4
collation-server     = utf8mb4_0900_ai_ci
default-time-zone    = '+08:00'
sql_mode = STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION
max_connections      = 500
innodb_buffer_pool_size = 2G

[client]
default-character-set = utf8mb4
```

> 📌 参数详解见 [[mysql/02-中段阶段-专题精讲/InnoDB存储引擎/专题概览]] 与 [[mysql/02-中段阶段-专题精讲/备份恢复与安全/备份体系与恢复演练]]。

## 三、方案 B：原生安装包

### Linux（以 Debian/Ubuntu 为例）

```bash
# 1. 官方源
wget https://dev.mysql.com/get/mysql-apt-config_0.8.33-1_all.deb
sudo dpkg -i mysql-apt-config_0.8.33-1_all.deb
# 交互式选择：Server -> mysql-innovation-community 或 mysql-9.7-lts-community

sudo apt update
sudo apt install mysql-server

# 2. 启动
sudo systemctl start mysql
sudo systemctl enable mysql      # 开机自启
sudo systemctl status mysql     # 看状态

# 3. 连接（Debian/Ubuntu 的 root 用 socket 认证，无需密码）
sudo mysql
```

⚠️ **发行版的坑**：`apt install mysql-server` 装的是**发行版仓库里的版本**，可能落后于官方。⚠️ **LTS 版本必须先配好官方源再装**，否则装到 Innovation 版本或老版本。

### macOS（Homebrew）

```bash
brew install mysql              # 装最新版（可能是 Innovation）
brew install mysql@8.4          # 装指定 LTS

brew services start mysql@8.4
mysql -u root -p
```

### Windows

下载 MSI 安装包，双击安装。⚠️ **安装过程里有一个关键选项：**

| 选项 | 说明 |
|------|------|
| Authentication Method | ⭐ 选 **Strong Password Encryption**（8.0 默认，MySQL 为 `caching_sha2_password`） |
| Windows Service | 勾选，注册为系统服务 |
| TCP Port | 默认 3306 |

配置文件路径：`C:\ProgramData\MySQL\MySQL Server 8.4\my.ini`

## 四、初始化后必做的四件事

⚠️ **装完之后别急着建表，先做这些。**

### 1. 设定 sql_mode（最重要）

```sql
-- 检查当前值
SELECT @@GLOBAL.sql_mode, @@SESSION.sql_mode;

-- 设为生产推荐值
SET GLOBAL sql_mode = 'STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION';

-- 写进配置永久生效
-- my.cnf 的 [mysqld] 段加：
-- sql_mode = STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION
```

📌 为什么这么重要：见 [[mysql/01-入门阶段-基础教程/第00章-学前准备/0.2-MySQL架构与客户端]] 第五节的「静默截断」分析。

### 2. 建应用账号（别用 root 连应用）

```sql
CREATE USER 'app'@'127.0.0.1' IDENTIFIED BY '强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON app.* TO 'app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

⚠️ **注意 `'app'@'127.0.0.1'` 的 host 部分**：写 `'app'@'%'` 表示任意主机都能连，⚠️ **这是生产事故的常见原因**。开发机只给本机，生产按需给具体网段。

### 3. 检查字符集

```sql
SHOW VARIABLES LIKE 'character_set%';
SHOW VARIABLES LIKE 'collation%';
```

⚠️ **不是 `utf8mb4` 就要改。** 存量表可能还是 latin1，见 [[mysql/01-入门阶段-基础教程/第01章-环境与数据类型/1.1-数据类型全景]]。

### 4. 确认数据目录和引擎

```sql
SHOW VARIABLES LIKE 'datadir';
SHOW VARIABLES LIKE 'default_storage_engine';
```

⚠️ `default_storage_engine` 必须是 `InnoDB`。如果是 `MyISAM`，你的表都会没有事务。

## 五、数据目录与文件结构

```
/var/lib/mysql/                    ← 数据目录（Docker 里对应数据卷）
├── ibdata1                        ← 表空间：数据、索引、undo（8.0 前是共享的）
├── app/
│   └── users.ibd                   ← ⭐ 8.0 起：每表一个独立表空间文件
├── ib_logfile0 / ib_logfile1      ← ⚠️ 8.0.30+ 默认改名为 #innodb_redo/
├── binlog.000001                  ← 二进制日志
├── mysql/
│   ├── user.ibd                   ← mysql 库（账号权限）
│   ├── innodb_index.ibd            ← InnoDB 字典
│   └── performance_schema/         ← 性能监控库
├── sys/                            ← 性能视图库
└── performance_schema/             ← 性能监控库
```

| 文件/目录 | 作用 | ⚠️ 风险 |
|----------|------|---------|
| `ibdata1` | 共享表空间 | ⚠️ 8.0 前它会不断增长且**不能单独收缩** |
| `xxx.ibd` | 单表表空间 | ⭐ 8.0 的改进，表可以独立回收空间 |
| `#innodb_redo/` | 重做日志 | ⚠️ **崩溃后不能删**，删了数据库起不来 |
| `binlog.*` | 变更日志 | ⚠️ 主从复制和 CDC 依赖它，**不能随便删** |
| `/var/lib/mysql` 整个目录 | 全部数据 | ⚠️ 备份这个目录必须停库或用 `FLUSH TABLES WITH READ LOCK` |

⚠️ **三个不能碰的目录/文件**：

1. **`#innodb_redo/`** — 删了数据库无法启动
2. **`binlog.*`** — 删了主从断链、CDC 断流
3. **`/var/lib/mysql` 直接 cp** — 不停库直接复制目录会得到**不一致的快照**（部分页已写、部分未写）

📌 正确的备份方式见 [[mysql/02-中段阶段-专题精讲/备份恢复与安全/备份体系与恢复演练]]，物理结构详解见 [[mysql/03-进阶阶段-深度剖析/00-剖析方法论]]。

> 📌 Docker 场景下数据卷挂载点就是 `/var/lib/mysql`，详见 [[docker/01-入门阶段-基础教程/第03章-数据卷与容器网络/3.1-数据卷与绑定挂载]]（那里提到 MySQL 官方镜像的数据路径**不是** `/var/lib/mysql/data`）。

## 六、Python 连接

| 驱动 | 用途 | 安装 |
|------|------|------|
| **PyMySQL** | ⭐ 纯 Python，最通用 | `pip install pymysql` |
| **mysqlclient** | C 扩展，性能略好 | `pip install mysqlclient` |
| **mysql-connector-python** | Oracle 官方 | `pip install mysql-connector-python` |
| **SQLAlchemy + PyMySQL** | ⭐ ORM 场景首选 | 见 [[sqlmodel/概述]] |

### PyMySQL 示例

```python
import pymysql

conn = pymysql.connect(
    host='127.0.0.1',
    port=3306,
    user='root',
    password='Root@123456',
    database='app',
    charset='utf8mb4',          # ⭐ 必须是 utf8mb4
    cursorclass=pymysql.cursors.DictCursor,   # 返回字典而不是元组
)
try:
    with conn.cursor() as cur:
        cur.execute("SELECT VERSION()")
        print(cur.fetchone())
finally:
    conn.close()
```

⚠️ **三个注意点：**

1. **必须指定 `charset='utf8mb4'`**，否则中文/emoji 出问题。
2. **⚠️ 生产一定要用连接池**，不要每次请求新建连接。见 [[mysql/02-中段阶段-专题精讲/工具与可观测性/工具链总览]]。
3. **⚠️ `autocommit=False` 是默认**，Python 侧如果不 commit，事务不会提交。

### SQLAlchemy（你的技术栈）

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

engine = create_engine(
    "mysql+pymysql://app:强密码@127.0.0.1:3306/app?charset=utf8mb4",
    pool_size=10,          # 连接池大小
    pool_recycle=3600,     # ⭐ 1 小时回收一次，避开 wait_timeout 断连
    pool_pre_ping=True,    # ⭐ 用前 ping 一下，防止拿到已断开的连接
    echo=False,            # 开发时设 True 打印 SQL
)
Session = sessionmaker(bind=engine)
```

⚠️ **`pool_pre_ping=True` 是生产必配项。** MySQL 默认 `wait_timeout=28800`（8 小时），空闲连接会被服务端断开，但客户端不知道。不开 pre_ping 就会遇到「偶发 `MySQL server has gone away`」。

📌 连接池详解见 [[sqlmodel/引擎与Session]]。

## 七、排查

| 症状 | 原因 | 解决 |
|------|------|------|
| `Can't connect to MySQL server on 'localhost'` | 服务没起 | `docker ps` / `systemctl status mysql` / 看日志 |
| `Access denied for user` | 密码错 / host 不匹配 | 确认账号的 host 部分 |
| `Unknown database 'app'` | 库没建 | `CREATE DATABASE app;` |
| `Public Key Retrieval is not allowed` | ⚠️ 8.0 默认 `caching_sha2_password`，老客户端不支持 | 客户端加 `allowPublicKeyRetrieval=true`，或改用 `mysql_native_password` |
| 中文写入报错 `Incorrect string value` | 字符集不是 utf8mb4 | 改库/表/连接三处字符集 |
| `Too many connections` | 连接数超 `max_connections` | 调大参数或用连接池 |
| 容器启动即退出 | 密码没给 / 数据卷权限问题 | `docker logs` 看具体原因 |
| `MySQL server has gone away` | 连接被服务端断开 | 开 `pool_pre_ping`，或调小 `wait_timeout` |

⚠️ **`Public Key Retrieval is not allowed` 是 8.0 升级后最常见的报错。** 原因：8.0 把默认认证插件改成了 `caching_sha2_password`，老客户端（如老的 mysql-connector、某些 JDBC 驱动）不认识。三个解法：

1. 客户端加参数 `allowPublicKeyRetrieval=true`（⚠️ 有安全前提：必须走 TLS 或本地回环）
2. 账号改用 `mysql_native_password`（⚠️ 该插件在 8.4 起默认关闭）
3. 升级客户端

📌 认证机制详解见 [[mysql/02-中段阶段-专题精讲/备份恢复与安全/备份体系与恢复演练]]。

## 八、陷阱

1. **❌ Docker 启动不加 `-v`。** 容器删了数据就没了。
2. **❌ 用 `mysql:latest`。** 行为不可控，必须写版本号。
3. **❌ 用 `-p 3306:3306` 暴露到公网。** 用 `-p 127.0.0.1:3306:3306`。
4. **❌ 应用用 root 连数据库。** 建专用账号并限制权限。
5. **❌ 不设 `sql_mode`。** 静默截断会造出一万条脏数据。
6. **❌ 不改 `character-set-server=utf8mb4`。** 中文和 emoji 会出问题。
7. **❌ 直接 cp `/var/lib/mysql` 目录做备份。** 快照不一致。
8. **❌ 忘记 `commit`。** Python 侧默认不开 autocommit。
9. **❌ 不配 `pool_pre_ping`。** 偶发 `server has gone away`。
10. **❌ 把密码写在命令行里。** 进 shell 历史。

## 小结

- **本机 Windows 推荐 Docker**：一条命令 30 秒起，不污染系统
- 启动参数四个要点：`-v` 数据卷必加、`-p` 限本机、写明版本号、设时区
- 初始化必做四件事：**`sql_mode` / 专用账号 / 字符集 / 确认 InnoDB**
- 数据目录 `/var/lib/mysql`：⚠️ `#innodb_redo/` 和 `binlog.*` 不能碰，不能直接 cp 目录
- Python：`charset='utf8mb4'` 必配；生产用连接池 + `pool_pre_ping`
- 8.0 起默认 `caching_sha2_password`，老客户端会报 `Public Key Retrieval is not allowed`
