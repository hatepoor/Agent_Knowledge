# 角色权限与账号管理

## 学习目标

读完本篇，你应当能够：

1. 掌握用户管理语句（建/改/删账号、设密码）
2. 掌握授权与回收授权语句
3. ⭐ **理解账号 host 部分的坑**（`localhost` vs `127.0.0.1` vs `%`）
4. 应用**最小权限原则**，为不同场景设计账号
5. 理解 8.0 默认的 `caching_sha2_password` 和它的兼容问题
6. 知道权限相关的报错怎么排查

## 一、账号的基本概念

### 账号的完整形态

> **`'用户名'@'主机'`**

⚠️ **⚠️ 这是本篇最重要的概念。** MySQL 的账号是「用户名 + 来源主机」的组合，**两个维度都要匹配才能连上。**

```sql
-- 这些是不同的账号！
'root'@'localhost'         -- 只能从本机 socket 连接
'root'@'127.0.0.1'        -- 只能从本机 TCP 连接
'root'@'%'                -- ⚠️ 任意主机
'root'@'192.168.1.%'      -- 192.168.1.x 网段
```

### 三种连接方式

| 连接方式 | 客户端写法 | 匹配哪个 host |
|---------|----------|--------------|
| **Socket** | `mysql -u root`（不写 host） | `'user'@'localhost'` |
| **TCP 本机** | `mysql -h 127.0.0.1 -u root` | ⚠️ `'user'@'127.0.0.1'` 或 `'user'@'%'` |
| **TCP 远程** | `mysql -h 10.0.0.5 -u root` | ⚠️ `'user'@'10.0.0.5'` 或 `'user'@'%'` |

⚠️ **⚠️ 关键坑：socket 连接和 TCP 连接的 host 匹配规则不同。**

```
mysql -u root                     → 匹配 'root'@'localhost'
mysql -h localhost -u root        → ⚠️ 走 TCP，匹配 'root'@'127.0.0.1' 或 'root'@'%'
mysql -h 127.0.0.1 -u root       → ⚠️ 走 TCP，匹配 'root'@'127.0.0.1' 或 'root'@'%'
```

⚠️ **同一个账号，`mysql -u root` 能连上但 `mysql -h 127.0.0.1 -u root` 连不上**——这就是「localhost 连接能通但程序连不上」的常见原因。

### 查看账号列表

```sql
SELECT user, host, plugin, account_locked, password_expired
FROM mysql.user;
```

⚠️ **不要用 `SELECT * FROM mysql.user`**——里面有密码哈希字段，会被打印到日志里。

## 二、用户管理

### 创建用户

```sql
-- 基本形式
CREATE USER 'app'@'127.0.0.1' IDENTIFIED BY '强密码';

-- 指定认证插件
CREATE USER 'app'@'%' IDENTIFIED WITH mysql_native_password BY '强密码';

-- ⚠️ MySQL 8.0 也可以一条语句建用户+授权
CREATE USER 'app'@'127.0.0.1' IDENTIFIED BY '强密码'
  GRANT SELECT, INSERT, UPDATE, DELETE ON app.* TO 'app'@'127.0.0.1';
```

⚠️ **`CREATE USER` 和 `GRANT` 的两种顺序**：

| 写法 | 含义 |
|------|------|
| `CREATE USER` + `GRANT`（分开） | ⭐ 传统方式 |
| `GRANT ... TO user`（不预先存在） | ⭐ 8.0 会自动创建用户 |

⚠️ **⚠️ 5.7 里 `GRANT` 会自动建用户但不带密码**，所以 8.0 推荐 `CREATE USER ... IDENTIFIED BY` 一步到位。

### 修改密码

```sql
-- 改自己的密码
ALTER USER USER() IDENTIFIED BY '新密码';

-- 改别人的密码（需要权限）
ALTER USER 'app'@'127.0.0.1' IDENTIFIED BY '新密码';

-- ⚠️ 8.0 弃用（旧写法）
SET PASSWORD FOR 'app'@'127.0.0.1' = PASSWORD('新密码');
SET PASSWORD = PASSWORD('新密码');
```

⚠️ **`PASSWORD()` 函数已废弃**，8.0 用 `ALTER USER`。

### 修改账号属性

```sql
-- 锁定 / 解锁
ALTER USER 'app'@'127.0.0.1' ACCOUNT LOCK;
ALTER USER 'app'@'127.0.0.1' ACCOUNT UNLOCK;

-- 设置密码有效期
ALTER USER 'app'@'127.0.0.1' PASSWORD EXPIRE INTERVAL 90 DAY;
ALTER USER 'app'@'127.0.0.1' PASSWORD NEVER EXPIRE;      -- 永不过期
ALTER USER 'app'@'127.0.0.1' PASSWORD HISTORY 5;         -- 不能复用最近 5 个

-- 限制资源使用
ALTER USER 'app'@'127.0.0.1'
  WITH MAX_USER_CONNECTIONS 10
       MAX_CONNECTIONS_PER_HOUR 100;

-- 重命名
ALTER USER 'app'@'127.0.0.1' RENAME TO 'app_v2'@'127.0.0.1';
```

⚠️ **`PASSWORD NEVER EXPIRE` 的安全考量**：永不过期方便但降低了安全性。⚠️ **生产建议设有效期**（如 90 天），配合密码管理策略；但对服务账号（程序用的）通常设不过期，否则要定期改配置。

### 删除用户

```sql
DROP USER 'app'@'127.0.0.1';

-- 8.0 也支持
DROP USER IF EXISTS 'app'@'127.0.0.1';
```

⚠️ **`DROP USER` 不可恢复。** 删之前先 `SHOW GRANTS` 记下权限。

## 三、权限体系

### 权限粒度

| 层级 | 语法 | 示例 |
|------|------|------|
| **全局** | `ON *.*` | 所有库所有表 |
| **库级** | `ON app.*` | app 库的所有表 |
| **表级** | `ON app.users` | 指定表 |
| **列级** | `ON app.users (col1, col2)` | ⭐ 只有部分权限支持列级 |

### 常用权限

| 权限 | 含义 |
|------|------|
| `SELECT` | 读数据 |
| `INSERT` | 插入 |
| `UPDATE` | 更新 |
| `DELETE` | 删除 |
| `CREATE` | 建表/建库 |
| `DROP` | 删表/删库 |
| `ALTER` | 改表结构 |
| `INDEX` | 建/删索引 |
| `REFERENCES` | 外键相关 |
| `ALL PRIVILEGES` | ⭐ 全部权限 |
| `GRANT OPTION` | ⭐ 可以再授权给别人（**危险**） |

### 授权与回收

```sql
-- 授权
GRANT SELECT, INSERT, UPDATE ON app.users TO 'app'@'127.0.0.1';
GRANT ALL PRIVILEGES ON app.* TO 'app_admin'@'127.0.0.1';
GRANT SELECT ON app.* TO 'readonly'@'%' WITH GRANT OPTION;

-- ⚠️ 8.0 推荐显式列出权限（❌ GRANT ALL 会包含 GRANT OPTION）
GRANT SELECT, INSERT ON app.* TO 'app2'@'%';

-- 回收（⚠️ 不会自动回收 GRANT OPTION）
REVOKE INSERT, UPDATE ON app.users FROM 'app'@'127.0.0.1';

-- 回收全部
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'app'@'127.0.0.1';

-- 改密码后让新密码生效
ALTER USER USER() IDENTIFIED BY '新密码';
```

⚠️ **⚠️ `GRANT ALL PRIVILEGES` 默认包含 `GRANT OPTION`**（即可以再授权）。8.0 起推荐显式列出需要的权限，避免这个隐患。

### 查看权限

```sql
-- 查自己的
SHOW GRANTS;
SHOW GRANTS FOR CURRENT_USER();

-- 查别人的（需要权限）
SHOW GRANTS FOR 'app'@'127.0.0.1';

-- 查某个用户能访问的库
SHOW DATABASES;

-- 查表级权限
SELECT * FROM information_schema.SCHEMA_PRIVILEGES WHERE GRANTEE LIKE '%app%';
SELECT * FROM information_schema.TABLE_PRIVILEGES WHERE GRANTEE LIKE '%app%';
```

⚠️ **`SHOW GRANTS` 是排查权限问题的第一手段。**

## 四、⚠️ 最小权限原则

### 原则

> **每个账号只授予它实际需要的权限。**

### 为什么重要

| 原因 | 说明 |
|------|------|
| **⚠️ 减少 SQL 注入的破坏面** | Web 应用注入漏洞，攻击者只能做应用账号能做的事 |
| **降低误操作影响** | 只读账号写坏了数据的概率 |
| **审计可追溯** | 不同账号对应不同的人/服务 |
| **满足合规要求** | 等保、ISO 27001 明确要求 |

⚠️ **⚠️ 反例**：给应用账号 root 权限，等于把整个数据库暴露在注入漏洞下。

### ⭐ 账号设计模板

```sql
-- ① 应用账号（只给业务库的读写，不给 DDL）
CREATE USER 'app_rw'@'10.0.1.%' IDENTIFIED BY '强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON app.* TO 'app_rw'@'10.0.1.%';
-- ⚠️ 没有 CREATE/DROP/ALTER → 注入也改不了表结构

-- ② 只读账号（报表、BI）
CREATE USER 'app_ro'@'10.0.1.%' IDENTIFIED BY '强密码';
GRANT SELECT ON app.* TO 'app_ro'@'10.0.1.%';

-- ③ 迁移账号（需要 DDL，仅在迁移时用）
CREATE USER 'migrate'@'10.0.1.%' IDENTIFIED BY '强密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER, INDEX,
      REFERENCES ON app.* TO 'migrate'@'10.0.1.%';

-- ④ 备份账号（只要读和锁）
CREATE USER 'backup'@'localhost' IDENTIFIED BY '强密码';
GRANT SELECT, LOCK TABLES, SHOW VIEW, RELOAD, REPLICATION CLIENT
      ON *.* TO 'backup'@'localhost';

-- ⑤ 监控账号（只要读状态）
CREATE USER 'monitor'@'%' IDENTIFIED BY '强密码';
GRANT PROCESS, REPLICATION CLIENT, SELECT ON *.* TO 'monitor'@'%';
```

⚠️ **注意每个账号的 host**：
- 应用账号给**具体网段**（如 `10.0.1.%`），⚠️ **不要给 `%`**
- 备份账号**只给 localhost**（备份通常是本机跑）
- 只读账号网段要收窄

### 按场景的权限矩阵

| 场景 | SELECT | INSERT | UPDATE | DELETE | CREATE/DROP/ALTER |
|------|:------:|:------:|:------:|:------:|:----------------:|
| Web 应用 | ✅ | ✅ | ✅ | ✅ | ❌ |
| 报表查询 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 数据迁移 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 备份 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 运维/DBA | ✅ | ✅ | ✅ | ✅ | ✅ |
| 监控 | ✅ | ❌ | ❌ | ❌ | ❌ |

### 列级权限

⚠️ **MySQL 只支持部分语句的列级权限**：

```sql
-- ✅ 支持：INSERT / UPDATE
GRANT SELECT (id, name, email) ON app.users TO 'limited'@'%';
GRANT UPDATE (name) ON app.users TO 'limited'@'%';

-- ⚠️ 不支持：SELECT（❌ 无法限制 SELECT 只能读某些列）
```

⚠️ **⚠️ 所以「让某账号不能看到 password 列」不能用列级权限实现。** 方案：
1. 建一个不包含该列的视图，授权视图
2. 应用层不 SELECT 该列

## 五、认证插件

### 8.0 的变化 ⚠️

| 插件 | 说明 | 8.0 状态 |
|------|------|---------|
| **`mysql_native_password`** | 老的认证方式，密码用 SHA1 派生 | ⚠️ **8.4 起默认禁用** |
| **`caching_sha2_password`** | ⭐ **8.0 默认**，更快更安全 | ✅ 推荐 |
| **`sha256_password`** | 更安全的旧插件 | 少用 |
| **LDAP / Kerberos** | 企业认证 | 商业版 |

### 查看和切换

```sql
-- 看当前账号用什么插件
SELECT user, host, plugin FROM mysql.user;

-- 切换
ALTER USER 'app'@'127.0.0.1' IDENTIFIED WITH caching_sha2_password BY '强密码';

-- ⚠️ 切回老的（不推荐）
ALTER USER 'app'@'127.0.0.1' IDENTIFIED WITH mysql_native_password BY '强密码';
```

### ⚠️ `Public Key Retrieval is not allowed`

⚠️ **这是 8.0 升级后最常见的客户端报错。**

**原因**：`caching_sha2_password` 需要 RSA 公钥加密密码传输。但服务端只通过 TLS 发送公钥，非 TLS 连接时客户端必须显式允许「从服务端获取公钥」，默认禁止。

**三个解法**：

```python
# 方案 1：客户端允许获取公钥（⚠️ 前提是走 TLS 或本地回环）
conn = pymysql.connect(
    ...,
    ssl={'ca': '/path/to/ca.pem'},     # ⭐ 最好配 TLS
)
# 或者在连接串加 allowPublicKeyRetrieval=true
```

```
mysql+pymysql://app:pwd@host/db?allowPublicKeyRetrieval=true&ssl_ca=/path/ca.pem
```

```java
// 方案 2：JDBC 加参数
jdbc:mysql://host:3306/db?allowPublicKeyRetrieval=true&useSSL=true
```

```bash
# 方案 3：服务端改回 native_password（⚠️ 不推荐，8.4 已禁用）
ALTER USER 'app'@'localhost' IDENTIFIED WITH mysql_native_password BY 'pwd';
-- ⚠️ 8.4/9.7 里需要先启动 mysql_native_password 插件
```

⚠️ **⚠️ `allowPublicKeyRetrieval=true` 的安全前提**：⚠️ **只在连接是加密的（TLS）或本地回环时开启**。否则中间人可以窃取密码。

⭐ **长期正解**：用 TLS 连接 + 保持 `caching_sha2_password`。

## 六、排查

| 症状 | 原因 | 排查 |
|------|------|------|
| `ERROR 1045 Access denied` | 密码错 / host 不匹配 | `SELECT user,host FROM mysql.user;` |
| ⚠️ 命令行能连，程序连不上 | socket vs TCP 的 host 差异 | 分别建 `'u'@'localhost'` 和 `'u'@'127.0.0.1'` |
| `ERROR 1142 command denied` | 权限不足 | `SHOW GRANTS FOR CURRENT_USER();` |
| ⚠️ `Public Key Retrieval is not allowed` | 认证插件兼容 | 见第五节 |
| ⚠️ `caching_sha2_password requires SSL` | 非 TLS 连接 | 配 TLS 或允许获取公钥 |
| `ERROR 1227 Access denied; you need SUPER` | 缺 SUPER 权限 | 改用需要的具体权限，或用 root |
| 账号存在但连不上 | `account_locked` | `SELECT account_locked FROM mysql.user;` |

### 排查流程

```sql
-- ① 账号存在吗？host 是什么？
SELECT user, host, plugin, account_locked, password_expired
FROM mysql.user WHERE user = 'app';

-- ② 当前用户是谁？（⚠️ USER() 和 CURRENT_USER() 语义不同）
SELECT USER(), CURRENT_USER();
-- USER()         = 'app@客户端IP'    ← 客户端传的，可伪造
-- CURRENT_USER() = 'app@localhost'   ← 实际认证的，⭐ 权限判断看这个

-- ③ 我有什么权限？
SHOW GRANTS FOR CURRENT_USER();

-- ④ 我能访问哪些库？
SHOW DATABASES;
```

⚠️ **`USER()` vs `CURRENT_USER()` 是本节的第二个重要坑**：

| 函数 | 返回 | 可否伪造 |
|------|------|---------|
| `USER()` | 客户端声称的身份 | ⚠️ **可以**（可改连接参数） |
| `CURRENT_USER()` | 实际认证通过的身份 | ❌ 不能 |

⚠️ **⚠️ 权限判断必须用 `CURRENT_USER()`**。用 `USER()` 写的判断可以被绕过。

### 重置 root 密码（忘密码时）

```bash
# 1. 停止服务
sudo systemctl stop mysql

# 2. 跳过权限检查启动
mysqld_safe --skip-grant-tables --skip-networking &

# 3. 无密码登录，修改密码
mysql -u root
mysql> FLUSH PRIVILEGES;          -- ⚠️ 必须先这句，否则 ALTER USER 报错
mysql> ALTER USER 'root'@'localhost' IDENTIFIED BY '新密码';
mysql> FLUSH PRIVILEGES;

# 4. 重启服务
sudo systemctl restart mysql
```

⚠️ **`FLUSH PRIVILEGES` 不能省**——跳过权限检查启动时，账号系统没加载，`ALTER USER` 会失败。

⚠️ **⚠️ 用 `--skip-networking` 更安全**，否则这期间数据库对网络开放且无密码。

📌 更多恢复场景见 [[mysql/02-中段阶段-专题精讲/备份恢复与安全/备份体系与恢复演练]]。

## 七、陷阱

1. **❌ 用 `'user'@'%'` 给应用账号。** ⚠️ 等于允许任意主机连接。
2. **❌ 忘了 host 部分的差异。** `'u'@'localhost'` ≠ `'u'@'127.0.0.1'`。
3. **❌ 给应用账号 `ALL PRIVILEGES`。** 注入漏洞的破坏面是整个库。
4. **❌ `GRANT ALL` 不显式排除 `GRANT OPTION`。** 账号能再授权。
5. **❌ 用 `USER()` 做权限判断。** 用 `CURRENT_USER()`。
6. **❌ 打印 `mysql.user` 的内容。** 含密码哈希。
7. **❌ `SET PASSWORD = PASSWORD(...)`。** 8.0 已废弃。
8. **⚠️ 不开 TLS 就用 `allowPublicKeyRetrieval=true`。** 密码可能被窃取。
9. **❌ 用 root 连接应用。** 至少建一个专用账号。

## 小结

- **账号 = `'用户'@'主机'`**，⚠️ **localhost（socket）和 127.0.0.1（TCP）是不同的账号**
- **`'user'@'%'` 是大坑**——应用账号应该给具体网段
- 权限粒度：全局 / 库 / 表 / 列（⚠️ 只有 INSERT/UPDATE 支持列级）
- ⭐ **最小权限原则**：应用账号只给 `SELECT,INSERT,UPDATE,DELETE`，不给 DDL
- ⭐ **`USER()` 可伪造，`CURRENT_USER()` 才是真身份**——权限判断用后者
- 8.0 默认 `caching_sha2_password`；⚠️ 老客户端报 `Public Key Retrieval is not allowed`
- `GRANT ALL PRIVILEGES` 默认含 `GRANT OPTION`，8.0 推荐显式列出权限
- 查权限第一手段：`SHOW GRANTS FOR CURRENT_USER();`
- 忘密码重置时，`--skip-networking` + `FLUSH PRIVILEGES` 是关键
