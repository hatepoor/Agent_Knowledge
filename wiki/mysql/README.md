# MySQL 学习知识库

> **MySQL 是 Oracle 旗下最广泛部署的开源关系型数据库**，采用 GPLv2 许可证，默认存储引擎 InnoDB。它与 PostgreSQL 是本知识库并列的两大关系型数据库路线，生态定位不同：MySQL 偏 LAMP/互联网应用与国产化替代，PostgreSQL 偏复杂查询与数据能力。
>

## 版本基线（2026-10-17 复核）

⚠️ **2026 年 MySQL 版本体系刚发生重大变化，网上大量资料已过时。** 三个必须知道的事实：

### 事实一：MySQL 8.0 已于 2026-04-30 彻底 EOL

| 项 | 内容 |
|---|------|
| 8.0 最后版本 | **8.0.46**（2026-04） |
| EOL 日期 | **2026-04-30** |
| 后果 | Oracle 不再为其发布安全补丁。新披露的 CVE 在 8.0 上**永远不会被修复** |
| 迁移目标 | **8.4 LTS**（不能直接跳到 9.x） |

⚠️ 8.0 曾是生产部署量最大的版本，这个 EOL 是自 5.7 退役以来最大的 MySQL 迁移事件。

### 事实二：9.7 是最后一个顺序版本号，之后改用日历版本号

| 版本 | 类型 | 时间 | 支持周期 |
|------|------|------|---------|
| **8.4 LTS** | LTS | GA 2024-04-30（最新 8.4.11，2026-07） | Premier 至 2029-04-30，Extended 至 **2032-04-30** |
| **9.7 LTS** | LTS | GA 2026-04-21（最新 9.7.2，2026-07） | Premier 至 2031-04，Extended 至 **2034-04** |
| **26.7.0** | Innovation | 2026-07-28 | **仅支持到下一个 Innovation 发布**（下个：26.10.0，计划 2026-10 下旬） |
| CSPU | 紧急安全补丁 | 按需 | ⚠️ 高危漏洞时才发布，版本号加第四位（如 `26.7.0.1`）；**不是**每季必有 |

**日历版本号规则**（YY.M.P）：
- `YY` = 两位年份（26 = 2026）
- `M` = 计划发布月份（7 = 7 月，10 月写 10，**不补零**）
- `P` = 补丁号。⚠️ **LTS 与 Innovation 的 P 位行为完全不同**（官方 CPU/CSPU 模型，2026-10 核实）：
  - **LTS**：P 随季度 CPU 递增（9.7.0 → 9.7.1 → 9.7.2），整个生命周期 YY.M 前缀冻结不变
  - **Innovation**：P **恒为 0**——跨季度直接换号（26.7.0 → 26.10.0），**不存在 26.7.1 这类「季内补丁号」**；季内紧急安全补丁走第四位 **CSPU**（如 `26.7.0.1`），按需发布
- **9.7 是最后一个顺序版本号**，所以不存在 9.8
- **版本号本身不决定类型**——LTS 和 Innovation 都可能是 26.x，成熟度是独立属性

⚠️ **看到 26.10.0 别以为是 26 个大版本**——它就是 2026 年 10 月的 Innovation 发布。

### 事实三：LTS 不能跳级

```
8.0(EOL) ──► 8.4 LTS ──► 9.7 LTS ──► 26.7 ──► 26.10 ──► 27.1 ──► … ──► 28.4 LTS
             │           │           └────── Innovation 线：每季度换号，仅活到下一季 ──────┘
             │           └── 支持至 2034-04；⭐ 进入日历谱系的唯一入口（8.4 不能直接升 26.x）
             └── 支持至 2032-04；原地升级要求 8.0.37+（8.0 已于 2026-04-30 EOL）

⚠️ 升级铁律：LTS 只能进入「紧随其后」的谱系，禁止跨谱系跳级
   完整路径：8.0 → 8.4 → 9.7 → 26.7 → 26.10 → … → 28.4 LTS（2028-04 GA）
```

⚠️ **「不能跨兼容谱系升级」是新规则。** Innovation 只能在同一谱系内升级；LTS 只能进入**紧随其后**的谱系，不能跳过。

### 事实四：2025-2026 治理风波（了解即可）

| 日期 | 事件 |
|------|------|
| 2025-09 | Oracle 裁撤大部分 MySQL 工程团队（约 50-70 名资深工程师） |
| 2026-02 | 社区峰会，约 200 人联署公开信要求基金会式治理 |
| 2026-05-27 | **OurSQL Foundation 成立**（Percona、PlanetScale、PingCAP、阿里等），Oracle **不是**成员 |
| 2026-06-25 | Oracle 发布社区治理模型，设咨询性技术委员会（AWS、Google Cloud、Oracle） |

**对使用者的实际影响**：短期不影响你的技术选型——8.4 和 9.7 都是 LTS，支持到 2032/2034。但如果你在评估「未来五年的长期归属」，这是一个需要知道的事实。

### 版本选择建议

| 场景 | 选什么 | 理由 |
|------|--------|------|
| **生产新项目** | **9.7 LTS** | 支持到 2034，功能比 8.4 新 |
| 生产但求稳、云厂商支持有限 | 8.4 LTS | 支持到 2032，生态工具最成熟 |
| 需要最新特性、能承担季度升级 | 26.x Innovation | **必须每季度升级**，否则失去支持 |
| 还在 8.0 | 立即规划迁 8.4 | 8.0 已无安全补丁 |

## 一句话技术画像

| 维度 | 特点 |
|------|------|
| 存储引擎 | **InnoDB**（默认）：B+ 树聚簇索引、MVCC、redo/undo、doublewrite |
| 事务 | ACID，四种隔离级别（RR 默认）+ MVCC |
| 索引 | B+ 树（聚簇 + 二级）、哈希、全文、空间 |
| 复制 | 异步 / 半同步复制、Group Replication、InnoDB Cluster |
| 默认端口 | **3306**（经典协议）、33060（X 协议）、33061（GR 常规端口） |
| 语言 | C++（含少量 C） |
| 许可 | Community Server 为 GPLv2，Enterprise Edition 商业许可 |
