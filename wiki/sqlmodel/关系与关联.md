# SQLModel 关系与关联

> SQLModel 用两个机制处理表间关系：`foreign_key`（数据库层外键约束）+ `Relationship`（Python 层对象导航）。复杂关系（多对多）需要第三个模型做关联表（Link 模型）。

## 一、一对多关系（Team → Hero）

### 模型定义

```python
from sqlmodel import SQLModel, Field, Relationship

class Team(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str = Field(index=True)
    headquarters: str
    # ① 一的那端：定义 heroes 列表
    heroes: list["Hero"] = Relationship(back_populates="team")

class Hero(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str = Field(index=True)
    secret_name: str
    age: int | None = Field(default=None, index=True)
    # ② 多的那端：外键 + 指向 Team 的关系属性
    team_id: int | None = Field(default=None, foreign_key="team.id")
    team: "Team | None" = Relationship(back_populates="heroes")
```

### 三个关键点

| 部分 | 作用 |
|------|------|
| `team_id: Field(foreign_key="team.id")` | **数据库层**：外键约束，`Hero` 表的 `team_id` 必须指向存在的 `team.id` |
| `heroes: list["Hero"] = Relationship(...)` | **Python 层**：Team 对象可直接访问其所有英雄 |
| `back_populates="..."` | **双向链接**：两个关系属性互相绑定，任何一端更新另一端自动同步 |

> `foreign_key` 是**必须的**（数据库约束）；`Relationship` 是**可选的**（纯 Python 导航便利层）。只想要约束不想要导航，可以只写 `team_id`。

### 使用

```python
with Session(engine) as session:
    # 创建关联数据
    team = Team(name="Z-Force", headquarters="Sister Margaret's Bar")
    hero = Hero(name="Deadpond", secret_name="Dive Wilson", team=team)
    #              ↑ 直接传 relationship 对象，SQLModel 自动填 team_id
    session.add(team)
    session.add(hero)
    session.commit()
    session.refresh(team)
    session.refresh(hero)

    # 正向导航：Hero → Team
    print(hero.team.name)          # Z-Force

    # 反向导航：Team → Hero 列表
    print(team.heroes)             # [Hero(name='Deadpond', ...)]
```

**数据流向**：`Hero(team=team)` → SQLModel 读取 `team.id` 填入 `hero.team_id` → 提交后数据库存外键 → 查询时 `hero.team` 自动回查。

## 二、多对多关系（Hero ↔ Power）

多对多需要 **Link 模型**（关联表）：

```python
class Hero(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str
    secret_name: str
    # 中间表模型
    powers: list["HeroPowerLink"] = Relationship(back_populates="hero")

class Power(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str
    heroes: list["HeroPowerLink"] = Relationship(back_populates="power")

# Link 模型：纯关联表，只有两个外键
class HeroPowerLink(SQLModel, table=True):
    hero_id: int | None = Field(default=None, foreign_key="hero.id", primary_key=True)
    power_id: int | None = Field(default=None, foreign_key="power.id", primary_key=True)
    # 复合主键 = (hero_id, power_id)，防止重复关联
```

### 访问多对多

```python
with Session(engine) as session:
    hero = session.exec(select(Hero).where(Hero.name == "Deadpond")).one()

    # 通过 Link 拿到该英雄的所有能力
    links = hero.powers          # [HeroPowerLink, ...]
    for link in links:
        print(link.power.name)   # 再导航到 Power

    # 添加关联
    power = Power(name="Super Jump")
    link = HeroPowerLink(hero=hero, power=power)
    session.add(power)
    session.add(link)
    session.commit()
```

**三种关系的选型**：

| 关系 | 数据库表示 | SQLModel 实现 |
|------|-----------|--------------|
| 一对多 | 多的表加外键 | `foreign_key` + 双向 `Relationship` |
| 多对多 | 中间关联表 | Link 模型 + 两端 `Relationship` |
| 一对一 | 任一端加唯一外键 | 一对多 + 关系属性类型改为单对象 |

## 三、关系属性参数

```python
class Team(SQLModel, table=True):
    ...
    heroes: list["Hero"] = Relationship(
        back_populates="team",        # 绑定的反向属性名
        cascade_delete=True,          # 删除 Team 时级联删除 Heroes（数据库级）
        sa_relationship_kwargs={
            "lazy": "selectin",       # 查询策略：selectin 预加载（避免 N+1）
            "order_by": "Hero.age",   # 列表排序
        },
    )
```

| 参数 | 作用 |
|------|------|
| `back_populates` | 绑定对面模型的关系属性名，保持双向同步 |
| `cascade_delete` | 删除父记录时自动删除子记录 |
| `sa_relationship_kwargs` | 透传 SQLAlchemy 原生参数（lazy/order_by/primaryjoin 等） |
| `sa_relationship` | 完全自定义 SQLAlchemy Relationship 对象 |

**N+1 问题**：默认懒加载（lazy="select"）时，查 100 个英雄再访问 `hero.team` 会触发 101 条 SQL（1 + 100）。用 `lazy="selectin"` 一次查完，降为 2 条。

## 四、常见误区

```python
# ❌ 只写 Relationship 不写 foreign_key
class Hero(SQLModel, table=True):
    team: "Team | None" = Relationship()   # 报错：找不到外键列

# ✅ foreign_key 是基础，Relationship 在其上导航
class Hero(SQLModel, table=True):
    team_id: int | None = Field(default=None, foreign_key="team.id")
    team: "Team | None" = Relationship()

# ❌ 双向 Relationship 忘了 back_populates
class Team(SQLModel, table=True):
    heroes: list["Hero"] = Relationship()   # 警告：未绑定，反向访问失效

# ✅ 两端互相指定
class Team(SQLModel, table=True):
    heroes: list["Hero"] = Relationship(back_populates="team")
class Hero(SQLModel, table=True):
    team: "Team | None" = Relationship(back_populates="heroes")

# ❌ 删除被引用的 Team，外键约束报错（默认 ON DELETE RESTRICT）
session.delete(team)
session.commit()   # IntegrityError: 外键约束

# ✅ 级联删除（需在 Relationship 声明 cascade_delete=True，且数据库表已创建）
```
