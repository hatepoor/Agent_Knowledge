## ⚠️ 开工前的两个假设

本篇及整个 `interview/` 目录基于以下假设写成。**如不符请告知，我按实际调整：**

| 假设 | 依据 |
|------|------|
| **① 三个项目都可用于简历** | 多智能体系统 / RAG 系统 / 个人知识库，均为 memory 记录的真实项目 |
| **② 目标岗位：Agent 工程为主，兼容后端** | 技能栈为 Python + LangChain/LangGraph + RAG + FastAPI + Docker + PostgreSQL + Redis |

⚠️ **如果实际是「纯后端岗」或「算法岗」，八股侧重点需要调整**——后者要补数学/模型/论文，本目录不覆盖。

---

## ⚠️ 一条硬约束：量化数据不编造

**项目经验篇里所有量化数据（QPS、数据量、耗时、准确率）一律留 `【待补充】` 占位符。**

原因：这些数字面试时会被追问细节（「这个 P99 是怎么测的」「样本量多少」），编造的数字撑不过三轮深挖。**宁可空着，不可造假。**

---

## 使用方式

⚠️ **本目录不是「读完」的，是「练出口」的。** 三遍法：

```
第一遍：通读，标出「看过但说不出口」的条目
第二遍：只看标出的条目，合上书复述，录音
第三遍：只练「高频追问」小节，练到不被问倒
```

**判断标准**：能脱稿讲清 + 接得住追问 = 会了。看懂了但说不出口 = 不会。

## 三种题型的不同打法

⚠️ **这是本目录最重要的方法论。三种题的准备方式完全不同：**

| 题型 | 考察什么 | 准备方式 | 常见错误 |
|------|---------|---------|---------|
| **八股题** | 记忆的准确度 | ⭐ **脱稿复述**，不是「看懂」 | 看懂了但说不出口 |
| **项目题** | 真实的深度 | ⭐ **STAR 重构 + 预判追问** | 只讲「做了什么」不讲「为什么」 |
| **设计题** | 权衡的意识 | ⭐ **先问清楚需求再设计** | 上来就画架构图 |
