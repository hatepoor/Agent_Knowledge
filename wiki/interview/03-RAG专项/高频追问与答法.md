# RAG 专项高频追问与答法

> **什么时候该读**：RAG 岗面试前最后一天。前三篇是知识点，这篇是弹药库。

---

## 一、RAG vs 微调（⭐ 第一高频）

### Q：RAG 和微调怎么选？

**及格**：RAG 便宜、可更新；微调改模型行为。
**加分**：⭐ **两者解决不同问题：**

| | RAG | 微调 |
|---|---|---|
| 解决 | ⭐ **「模型不知道」**（知识缺口） | ⭐ **「模型不会做」**（行为/格式/风格） |
| 更新知识 | ⭐ 改索引即可，分钟级 | 要重训，天/周级 |
| 成本 | 低 | 高（数据+算力） |
| 可解释 | ⭐ **能溯源** | ❌ 黑盒 |
| 幻觉 | ⭐ 降低（有据可依） | ⚠️ 可能更高 |

⭐ **一句话**：**知识问题用 RAG，行为问题用微调。** 实践中常先 RAG，不够再考虑微调。

⚠️ **追问「RAG 能完全消除幻觉吗？」**
→ ❌ 不能。RAG 降低幻觉，但模型仍可能「无视检索内容自己编」（faithfulness 低）。所以要评估。

## 二、检索细节

### Q：向量检索召回不理想，怎么排查？

**加分答案（按顺序）：**

```
① 看 recall：该检索到的是否完全没召回？
   ├─ 完全没召回 → 检查 embedding 模型是否适合该领域/语言
   │              （如中文用了英文优化的模型）
   └─ 部分召回 → 看是被什么挤掉的

② 看 top-k 是否太小：k=3 时第 4 个对的也白搭

③ 看分块：块是否切断语义？表格是否被打散？

④ 看是否缺精确匹配：SKU/型号/专有名词 → 加 BM25

⑤ 看 query 是否被正确理解：口语化/错别字/多义词 → 查询改写
```

### Q：Embedding 模型怎么选？

**加分答案（四个维度）：**

| 维度 | 考虑 |
|------|------|
| ⭐ **语言** | 中文场景选中英文均衡的（如 BGE 系列） |
| ⭐ **领域** | 法律/医疗等专业领域有专用模型 |
| **维度** | 影响存储和检索速度（384 vs 1024 vs 1536） |
| **上下文长度** | 长文档要用长上下文的模型 |

⚠️ **追问「换 embedding 模型要注意什么？」**
→ ⭐ **必须全量重建索引**（旧向量和新向量空间不兼容，混用等于随机）。⚠️ 这是最容易被忽略的坑。

### Q：top-k 怎么定？

**加分答案**：⭐ **k 是「召回数」和「上下文预算」的权衡，不是越大越好。**
- k 太小 → 漏召回
- ⚠️ **k 太大 → 上下文稀释 + 成本上升 + lost in the middle**
- 实践：**召回 50~100 → 重排到 5~10**（先粗后精）

## 三、生成侧

### Q：怎么降低幻觉？

**加分答案（四层）：**
1. ⭐ **检索质量**：recall/precision 是基础
2. ⭐ **prompt 约束**：明确「只基于给定内容回答，找不到就说不知道」
3. ⭐ **重排 + 裁剪**：只留最相关的，减少稀释
4. ⭐ **评估**：faithfulness 指标持续监控

⚠️ **追问「prompt 里写了『找不到就说不知道』，模型还是编怎么办？」**
→ ⭐ **因为模型有「必须回答」的压力。** 解法：① 明确允许说不知道；② 检索结果为空时走另一套 prompt（「知识库没有，请问是否…」）；③ 评估 faithfulness 持续监控。

### Q：怎么让 RAG 回答带引用？

**加分答案**：
```
① 每个 chunk 带来源元数据（文档名、页码/锚点）
② 检索返回时保留元数据
③ prompt 要求「引用时用 [来源N] 标注」
④ ⭐ 后处理校验：检查引用编号是否真的对应检索到的 chunk
```
⚠️ **「引用编号对不上」是常见 bug**——模型会编出不存在的引用编号，所以第 ④ 步校验是必需的。

## 四、场景设计题

### Q：「设计一个企业知识库 RAG」

**答题骨架（⭐ 七步）：**

```
1. 澄清需求：文档类型？规模？用户量？要不要写操作？权限要隔离吗？
2. 解析：按文档类型选解析器（docling 覆盖 PDF/DOCX/HTML）
3. 分块：结构感知为主，表格整块，代码按 AST
4. 索引：向量 + BM25 混合；⭐ 元数据（部门/权限/时间）用于过滤
5. 检索：查询改写 → 混合检索 → RRF 融合 → Cross-Encoder 重排
6. 生成：prompt 约束 + 溯源引用 + 引用编号校验
7. 评估：Golden Set + ragas 两层指标 + 在线监控
```

⭐ **第 1 步「澄清需求」和第 4 步「权限过滤」是最能加分的**：
- ⚠️ **权限过滤**：企业知识库必须按用户权限检索，否则「问出不该看的」是安全事故
- ⚠️ **元数据过滤**：比「全库检索再过滤」效率高得多

### Q：「RAG 效果不好，客户要求一周内提升，你怎么做？」

**答题骨架（⭐ 这是排序题，考优先级）：**

```
第一优先（见效最快）：
  ① 看评估数据定位是哪一层的问题——不评估就优化是瞎猜
  ② 如果是 faithfulness 低 → 重排 + 上下文裁剪（改动小，当天能上）

第二优先：
  ③ 如果是 recall 低 → 加分块调优 / 加 BM25 / 查询改写

第三优先（成本高）：
  ④ 换 embedding 模型（要全量重建索引）
  ⑤ 上 Agentic RAG（多跳/迭代检索）
```

⭐ **「先评估再优化」这个回答本身就是加分点**——它证明你有工程方法，不是乱试。

## 五、八股速答卡

| 问题 | 一句话答案 |
|------|-----------|
| RAG 解决什么？ | 知识截止、幻觉、私有数据 |
| 完整流程？ | 解析→清洗→分块→索引→检索→重排→生成 |
| RAG vs 微调？ | 知识问题用 RAG，行为问题用微调 |
| 为什么要混合检索？ | 向量弱在精确匹配，BM25 弱在语义 |
| RRF 为什么好？ | 分数不可比但排名可比，不用调权重 |
| top-k 怎么定？ | 召回 50~100 → 重排到 5~10 |
| 评估分几层？ | 检索层（recall/precision）+ 生成层（faithfulness） |
| 高 recall 低 faithfulness？ | 检索到了没用上，问题在上下文构建 |
| 怎么降幻觉？ | 检索质量 + prompt 约束 + 重排裁剪 + 评估监控 |
| 怎么加引用？ | 元数据 + prompt 要求 + ⚠️ 引用编号校验 |
| 换 embedding 模型？ | ⚠️ 必须全量重建索引 |
| 企业知识库特有点？ | ⚠️ 权限过滤 + 元数据过滤 |
