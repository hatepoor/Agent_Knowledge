# 数据库八股

> **什么时候该读**：面试前速成数据库部分。
> ⚠️ **本页只给「一句话答案 + 展开骨架」**，完整机制在 [[mysql/README]]、[[redis/README]]、[[postgresql/README]]。

## 一、MySQL 索引

### Q：B+ 树为什么适合做索引？

**一句话**：非叶子节点只存键 → 单节点能放更多键 → 树更矮 → **磁盘 IO 次数更少**；叶子节点串成链表 → **范围查询只需定位起点再顺序扫**。

**追问：为什么不用哈希索引做范围查询？**
→ 哈希把 `1~100` 映射成 8 个桶，存了 `1` 和 `100` 后查 `1~100` 无法定位——⚠️ **哈希无序，无法表达「区间」**。

📌 [[mysql/02-中段阶段-专题精讲/索引与查询优化/索引类型与选型]]

### Q：聚簇索引和二级索引的区别？

**一句话**：聚簇索引的**叶子存完整行**（InnoDB 只有一棵，默认主键）；二级索引叶子存**主键值**，查完整行要**回表**。

**追问：什么是回表？怎么避免？**
→ 二级索引找到主键 → 再查聚簇索引。避免：**覆盖索引**（把要查的列都放进索引）。

### Q：最左前缀原则？

**一句话**：联合索引 `(a,b,c)` 相当于 `a`、`(a,b)`、`(a,b,c)` 三个索引；⚠️ **跳过首列就用不上**。

**追问：`WHERE a>1 AND b=2` 能用到 b 吗？**
→ ❌ **用不上**。`a` 是范围查询，它之后的列无法再精确定位。

⚠️ **追问：`a` 是等值查询时呢？**
→ ✅ 能用上 `b`。这是「等值在前、范围在后」设计原则的依据。

### Q：什么是覆盖索引？

**一句话**：索引包含了查询需要的**全部列**，不需要回表。`EXPLAIN` 里表现为 **`Using index`**。

## 二、MySQL 事务与锁

### Q：四种隔离级别？

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|:----:|:----------:|:----:|
| RU | ❌ | ❌ | ❌ |
| RC | ✅ | ❌ | ❌ |
| **RR（默认）** | ✅ | ✅ | ⚠️ 基本防 |
| Serializable | ✅ | ✅ | ✅ |

### Q：MVCC 的实现原理？

**一句话**：每行有隐藏列 `DB_TRX_ID`（最后修改的事务 ID）和 `DB_ROLL_PTR`（指向 undo 版本链）；读操作顺着 `roll_ptr` 找**对自己可见的版本**。

**追问：ReadView 有哪四个字段？**
→ `m_ids`（活跃事务集合）、`min_trx_id`、`max_trx_id`（⚠️ **是「下一个要分配的 ID」不是「当前最大」**）、`creator_trx_id`。

**追问：可见性判定？**
→ ⭐ **自己改的可见；`< min` 可见；`>= max` 不可见；`[min,max)` 区间查 `m_ids`（在→不可见，不在→可见）。**

📌 [[mysql/03-进阶阶段-深度剖析/事务与锁内核/原理剖析-undo日志与MVCC]]

### Q：RR 和 RC 的唯一区别？

**一句话**：⭐ **ReadView 的创建时机**——RR 在**第一次快照读**时创建并复用，RC **每条 SELECT 都新建**。

⚠️ **这是最容易答错的题。** 答案是「ReadView 时机」不是「锁的粒度」。

### Q：什么是 Next-Key Lock？

**一句话**：**记录锁 + 前面的间隙锁**，区间形如 `(3, 5]`。RR 下用它防幻读。

**追问：间隙锁的代价？**
→ ⚠️ **锁的范围比实际需要的大得多**——「锁一行会阻塞邻近插入」。

📌 [[mysql/03-进阶阶段-深度剖析/事务与锁内核/原理剖析-锁体系与死锁]]

### Q：死锁怎么处理？

**一句话**：InnoDB 自动检测并回滚代价小的事务；**应用侧要捕获 1213 后退避重试**。

**追问：根治方案？**
→ ⭐ **所有事务按同一顺序访问表**（如按 ID 排序后遍历）。

## 三、MySQL 日志与复制

### Q：redo log 和 binlog 的区别？

| 维度 | redo log | binlog |
|------|---------|--------|
| 类型 | ⭐ **物理日志**（页级字节） | **逻辑日志**（SQL 或行变化） |
| 作用 | 崩溃恢复 | 复制 + PITR + CDC |
| 写入 | ⭐ **循环写**（写满覆盖） | **追加写** |
| 所属 | InnoDB 引擎层 | Server 层 |

**追问：为什么需要两阶段提交？**
→ 只写 redo → 主库有数据但从库没有；只写 binlog → 从库有但主库恢复不出来。⚠️ **所以：redo prepare → 写 binlog → redo commit。**

📌 [[mysql/03-进阶阶段-深度剖析/日志与复制内核/原理剖析-redo日志与WAL]]

### Q：为什么 binlog_format 默认是 ROW？

**一句话**：`STATEMENT` 下 `NOW()`/`UUID()`/`RAND()` 在主从执行时刻不同 → **结果不同 → 主从不一致**。

## 四、MySQL 优化

### Q：索引失效的场景？

⭐ **本质：函数/运算作用在「列」上。**

| 场景 | 例 |
|------|-----|
| 列上套函数 | `WHERE DATE(created_at) = ...` |
| 隐式类型转换 | ⚠️ `WHERE phone = 138...`（phone 是 VARCHAR） |
| 前导 % | `LIKE '%x'` |
| OR 的某列无索引 | `WHERE a=1 OR b=2`，b 无索引 |

### Q：深分页为什么慢？怎么优化？

**一句话**：`LIMIT 1000000, 20` 要**处理掉前 100 万行**。

**优化**：⭐ **键集分页** `WHERE id > 游标 ORDER BY id LIMIT 20` → 扫描量恒定。

⚠️ **追问：排序不唯一时怎么办？**
→ 必须加「打破平局」的列，用行值比较 `WHERE (created_at, id) < (?, ?)`。

📌 [[mysql/01-入门阶段-基础教程/第03章-查询与CRUD/3.3-ORDER-BY排序与分页]]

### Q：长事务有什么危害？

⭐ **四个：undo 膨胀、阻塞 purge 线程、锁阻塞、主从延迟。**

**追问：怎么排查？**
→ `information_schema.INNODB_TRX` + ⭐ **重点找 `command='Sleep'` 且在 `INNODB_TRX` 里的连接**（空闲但开着事务）。

## 五、Redis

### Q：Redis 为什么快？

**一句话**：数据在内存 + 单线程无锁（命令原子）+ IO 多路复用。

⚠️ **追问：单线程不是瓶颈吗？**
→ 瓶颈几乎从不在 CPU 计算；⚠️ **但慢命令（`KEYS *`）会霸占这唯一的线程**。

### Q：Redis 的持久化？

| | RDB | AOF |
|---|---|---|
| 内容 | 内存快照 | 命令日志 |
| 恢复速度 | 快 | 慢 |
| 数据丢失 | ⚠️ 分钟级 | 秒级（可配 always） |
| 文件大小 | 小 | 大 |

**追问：怎么选？**
→ 混合持久化（RDB 做全量 + AOF 做增量）。

### Q：缓存三大问题？

| 问题 | 解法 |
|------|------|
| **穿透**（查不存在的数据） | 布隆过滤器 / 缓存空值 |
| **击穿**（热点 key 过期） | 互斥锁 / 逻辑过期 |
| **雪崩**（大量同时过期） | TTL 加随机值 / 多级缓存 |

**追问：缓存和数据库怎么保证一致？**
→ ⭐ **Cache-Aside**（读：先缓存后库；写：先库后删缓存）。⚠️ 「先删缓存再写库」有并发不一致窗口。

📌 [[redis/02-中段阶段-生产实践/03-缓存三大问题与缓存模式]]

### Q：Redis 的分布式锁？

**一句话**：`SET key val NX PX ttl` + **唯一 token** + Lua 脚本保证「比对后删除」原子性。

**追问：为什么不能只用 `SETNX`？**
→ ① 没有过期时间会死锁；② 删锁时可能删掉别人的锁。

## 六、PostgreSQL（如被问到）

### Q：MySQL 和 PostgreSQL 的 MVCC 有什么不同？

**一句话**：⭐ **PG 是追加式**（新行写在表末尾，靠 VACUUM 回收）；**MySQL 是 undo 式**（老版本在 undo log，purge 线程清理）。

**追问：这导致什么行为差异？**
→ PG 的表会因 UPDATE 膨胀；MySQL 的 undo 表空间会因长事务膨胀。

### Q：PG 的 RR 会幻读吗？

**一句话**：⚠️ **会**。标准 SQL 的 RR 只保证「同一行读结果不变」。PG 用 **SSI（可串行化快照隔离）** 检测读写依赖来防，不加锁。

⚠️ **这是 MySQL 和 PG 的重大实现差异**，答错会显得只学过一边。
