## 一、GIL 与并发

### Q：什么是 GIL？

**一句话**：CPython 里同一时刻只有一个线程能执行 Python 字节码，所以多线程无法利用多核做 CPU 密集计算。

**展开骨架**：
| 点 | 内容 |
|---|---|
| 为什么有 | CPython 的内存管理不是线程安全的，GIL 是最简单的保护 |
| 影响 | ⚠️ **CPU 密集 → 多线程无效，甚至更慢**（切换开销） |
| 不受影响 | ⭐ **IO 密集 → 多线程有效**（等 IO 时释放 GIL） |
| 3.13 变化 | ⚠️ **free-threaded 构建（PEP 703）已实验性支持**，但生态兼容性仍在演进 |

**追问：那怎么利用多核？**
→ `multiprocessing`（多进程，各自有独立 GIL）；或 C 扩展/numpy 在底层释放 GIL。

📌 详解 [[python/concurrency/并发并行总览]]

### Q：GIL 和 asyncio 什么关系？

**一句话**：asyncio 是**单线程内**的协作式调度，GIL 对它没影响；它解决的是 IO 并发，不是并行。

⚠️ **高频错误**：「用了 asyncio 就能利用多核」——❌ 错。asyncio 依然是单核单线程。

## 二、装饰器与生成器

### Q：装饰器的原理？

**一句话**：装饰器是「接收函数、返回函数」的可调用对象，用 `@` 语法糖在原函数定义后立即替换它。

**展开骨架**：
| 点 | 内容 |
|---|---|
| 本质 | `@deco` 等价于 `f = deco(f)` |
| 保签名 | ⚠️ 必须 `functools.wraps`，否则 `__name__`/签名丢失 |
| 带参数 | 三层嵌套：`deco(args)` → 返回装饰器 → 装饰器包装函数 |
| 类装饰器 | 实现 `__call__` |

**追问：`functools.wraps` 做了什么？**
→ 复制 `__name__`/`__doc__`/`__module__`/`__qualname__`/`__wrapped__`，并同步 `__dict__`。

### Q：生成器和普通函数的区别？

**一句话**：生成器函数体含 `yield`，调用时**不执行函数体**，返回一个生成器对象，每次 `next()` 执行到下一个 `yield`。

**展开骨架**：
| 点 | 内容 |
|---|---|
| 惰性求值 | ⭐ 不预先算完，用一个算一个 → 省内存 |
| 状态保存 | 每次挂起时保存执行栈帧，恢复时继续 |
| 返回值 | ⚠️ `return` 的值会变成 `StopIteration.value` |
| 应用 | 流式处理、大文件读取、`itertools` 链 |

**追问：生成器怎么接收外部值？**
→ `yield` 表达式本身有返回值：`x = yield y`，配合 `gen.send(v)`。

## 三、内存与对象模型

### Q：Python 的垃圾回收？

**一句话**：**引用计数为主 + 分代 GC 兜底循环引用**。

| 点 | 内容 |
|---|---|
| 引用计数 | ⭐ 主机制，计数归零立即释放 |
| 无法处理 | ⚠️ **循环引用**（a.x = b; b.x = a） |
| 分代 GC | 三代（0/1/2），对象存活越久检查越少 |
| 触发 | 分配次数减去回收次数超过阈值 |
| `gc` 模块 | `gc.collect()` / `gc.disable()` / `gc.freeze()` |

⚠️ **追问「引用计数有什么问题」**——两个答案：① 循环引用；② **每次赋值都要改计数，有锁开销且非线程安全**（这是 CPython 用 GIL 的原因之一）。

### Q：`is` 和 `==` 的区别？

**一句话**：`is` 比**身份**（同一个对象，`id()` 相同），`==` 比**值**（调用 `__eq__`）。

**追问：小整数为什么 `is` 可能为 True？**
→ CPython 缓存了 `[-5, 256]` 的小整数。⚠️ **不要依赖这个行为**，值比较一律用 `==`。

## 四、深拷贝与浅拷贝

**一句话**：浅拷贝只复制容器本身（元素是同一引用）；深拷贝递归复制所有层级。

```python
import copy
b = copy.copy(a)       # 浅
c = copy.deepcopy(a)   # 深
```

⚠️ **追问：`copy.deepcopy` 对递归引用怎么处理？**
→ 用 `memo` 字典记录已拷贝对象，避免无限递归。

## 五、异常与上下文管理器

### Q：`with` 语句的原理？

**一句话**：调用对象的 `__enter__` / `__exit__`，无论是否异常都保证 `__exit__` 执行，用于资源释放。

**追问：`__exit__` 返回 True 会怎样？**
→ ⚠️ **吞掉异常**，不向外传播。这是 `contextlib.suppress` 的实现原理。

### Q：`try/except/else/finally` 执行顺序？

**一句话**：`try` 无异常 → `else` → `finally`；有异常 → 匹配的 `except` → `finally`。

⚠️ **高频坑**：`finally` 里的 `return` 会**覆盖** `try` 里的 `return`。

## 六、函数参数与作用域

### Q：`*args` 和 `**kwargs`？

**一句话**：`*args` 收集多余位置参数成 tuple，`**kwargs` 收集多余关键字参数成 dict。

⚠️ **追问：默认参数的坑**
```python
def f(x, acc=[]):      # ❌ 默认值只求值一次，跨调用共享！
    acc.append(x)
    return acc
```
→ 正确做法：默认用 `None`，函数体内 `if acc is None: acc = []`。

### Q：LEGB 规则？

**一句话**：变量查找顺序 **L**ocal → **E**nclosing → **G**lobal → **B**uilt-in。

⚠️ **追问：`nonlocal` vs `global`**
→ `nonlocal` 改**外层函数**（嵌套作用域）的变量；`global` 改**模块级**变量。

## 七、并发编程

### Q：线程 vs 进程 vs 协程？

| | 线程 | 进程 | 协程 |
|---|---|---|---|
| 内存 | 共享 | 独立 | 共享（单线程内） |
| 创建开销 | 中 | 大 | ⭐ 极小 |
| 适用 | IO 密集 | CPU 密集 | ⭐ **高并发 IO** |
| GIL 影响 | 有 | 无 | 无（单线程） |

**一句话选型**：CPU 密集用多进程，普通 IO 用线程，**上万并发连接用 asyncio**。

### Q：asyncio 的核心概念？

**一句话**：事件循环驱动协程，`await` 挂起时把控制权交还循环，去跑其他就绪任务。

| 概念 | 说明 |
|---|---|
| 事件循环 | ⭐ 单线程调度器 |
| `await` | 挂起点，遇到 IO 时让出 |
| `Task` | 被循环调度的协程包装 |
| ⚠️ 阻塞调用 | ⭐ **`time.sleep()` 会卡住整个循环**，要用 `await asyncio.sleep()` |
| 同步代码调 async | ⚠️ 用 `asyncio.run_coroutine_threadsafe()` |

## 八、数据类型与内置结构

### Q：dict 的查找为什么是 O(1)？

**一句话**：哈希表。key 经 `hash()` 得到槽位，冲突用开放寻址/扰动解决。

⚠️ **追问：为什么 dict 键必须可哈希？**
→ 可哈希 = 有 `__hash__` 且 `__hash__` 不变。list/dict 可变所以不可哈希。

### Q：list 和 tuple 的区别？

**一句话**：list 可变、tuple 不可变；tuple 可作 dict 键、可哈希；tuple 创建略快、内存略小。

## 九、常见追问的「坑点答案」

⚠️ **这些是「看似会但一深挖就露」的点：**

| 追问 | 正确答案 |
|------|---------|
| `len()` 调用了什么？ | `__len__`，且**返回值必须是 int 且 ≥ 0** |
| `bool([])` 是什么？ | `False`——空容器为假，调用 `__bool__` 或 `__len__` |
| `1 == 1.0` 为真，`1 is 1.0`？ | ❌ 不同类型，`is` 为 False |
| `sorted()` 和 `list.sort()`？ | 前者返回新 list，后者**原地修改返回 None** |
| 字符串可变吗？ | ❌ 不可变，`s[0]='a'` 报 TypeError |
| `__init__` 和 `__new__`？ | `__new__` 创建实例（先），`__init__` 初始化（后）；单例模式改 `__new__` |
