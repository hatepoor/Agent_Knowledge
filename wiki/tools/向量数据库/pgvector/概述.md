# pgvector

## 概述

pgvector 是 PostgreSQL 的向量搜索扩展。如果你的项目已经在用 PostgreSQL，pgvector 让你**不引入新组件**就能获得向量检索能力。

## 定位与适用场景

| 场景 | 是否适合 | 说明 |
|------|----------|------|
| 已有 PostgreSQL 的项目 | 非常适合 | 零新组件，直接用 |
| 向量 + 关系数据混合查询 | 非常适合 | SQL + 向量搜索，事务一致性有保障 |
| 中小规模（< 500 万向量） | 适合 | 性能足够，索引优化后表现好 |
| 大规模（> 500 万向量） | 一般 | 需要调优，不如专用向量库 |
| 没有 PostgreSQL | 不适合 | 为了 pgvector 单独装 PG 不值得 |
| 纯向量检索 | 不适合 | 用 Qdrant 或 Chroma 更专业 |

## 安装

```sql
-- PostgreSQL 12+ 支持
CREATE EXTENSION vector;
```

Docker 方式（自带 pgvector 的镜像）：

```bash
docker run -d --name pg-vector \
    -e POSTGRES_PASSWORD=123456 \
    -p 5432:5432 \
    pgvector/pgvector:pg16
```

## 基本使用

### 建表

```sql
-- 创建带向量列的表
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    content TEXT,
    source VARCHAR(255),
    embedding vector(768)  -- 768 维向量
);

-- 创建索引（推荐 HNSW）
CREATE INDEX ON documents
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);
```

### 插入数据

```sql
-- 直接插入（Python 生成向量后传入）
INSERT INTO documents (content, source, embedding)
VALUES ('LangChain 是 LLM 应用框架', 'wiki', '[0.023, -0.115, 0.087, ...]');

-- 或使用 psycopg2/SQLAlchemy
```

```python
import psycopg2
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings()
vector = embeddings.embed_query("LangChain 是什么？")

conn = psycopg2.connect("postgresql://user:pass@localhost/mydb")
cur = conn.cursor()

# 插入
cur.execute(
    "INSERT INTO documents (content, source, embedding) VALUES (%s, %s, %s::vector)",
    ("LangChain 是 LLM 应用框架", "wiki", str(vector))
)
conn.commit()
```

### 查询

```sql
-- 余弦相似度搜索（返回最相似的 5 条）
SELECT id, content, source,
       1 - (embedding <=> '[0.023, -0.115, ...]'::vector) AS similarity
FROM documents
ORDER BY embedding <=> '[0.023, -0.115, ...]'::vector
LIMIT 5;

-- 带过滤条件的向量搜索
SELECT id, content
FROM documents
WHERE source = 'wiki'
ORDER BY embedding <=> '[0.023, ...]'::vector
LIMIT 5;
```

距离操作符：

| 操作符 | 距离类型 | 说明 |
|--------|----------|------|
| `<->` | L2（欧氏） | 越小越相似 |
| `<#>` | 负内积 | 越小越相似（注意是负值） |
| `<=>` | 余弦距离 | 越小越相似 |

## 索引类型

```sql
-- HNSW（推荐，速度和精度最好）
CREATE INDEX ON docs USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);

-- IVFFlat（倒排文件，适合大规模）
CREATE INDEX ON docs USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);  -- 聚类数，建议 √(行数)
```

| 索引 | 速度 | 精度 | 适用 |
|------|------|------|------|
| HNSW | 最快 | 很高 | 首选，中小规模 |
| IVFFlat | 快 | 高 | 大规模（> 百万） |
| 无索引 | 最慢 | 100% | < 10 万，精度优先 |

## 与 LangChain 集成

```python
from langchain_postgres import PGVector
from langchain_openai import OpenAIEmbeddings

# 创建向量存储
vectorstore = PGVector(
    connection_string="postgresql://user:pass@localhost/mydb",
    embedding=OpenAIEmbeddings(),
    collection_name="my_docs",
)

# 添加文档
vectorstore.add_documents(docs)

# 检索
results = vectorstore.similarity_search("查询", k=5)

# 带过滤
results = vectorstore.similarity_search(
    "查询", k=5,
    filter={"source": "wiki"},
)
```

## 与专用向量库对比

| | pgvector | Chroma | Qdrant |
|---|---|---|---|
| 需要新组件 | 否（已有 PG） | 是（但很轻） | 是 |
| 事务支持 | 完整 ACID | 无 | 无 |
| SQL 混合查询 | 原生支持 | 不支持 | 不支持 |
| 向量搜索性能 | 好 | 好 | 最好 |
| 大规模扩展 | 需调优 | 不支持 | 支持 |
| 运维复杂度 | 低（已有 PG） | 极低 | 低 |

## 最佳实践

**批量插入**：用 `COPY` 或批量 `INSERT` 比逐条快几十倍。

**预热索引**：查询前 `SET hnsw.ef_search = 100;` 调整搜索精度。

**监控**：`EXPLAIN ANALYZE` 查看查询是否使用了向量索引。
