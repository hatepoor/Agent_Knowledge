# 向量数据库选型指南

## 什么是向量数据库

向量数据库是专门用于存储、索引和检索高维向量数据的系统。与传统数据库通过精确匹配查询不同，向量数据库通过**相似度**查询——找到与给定对象"最像"的那些东西。

核心工作流：文本/图片/音频 → Embedding 模型 → 高维向量 → 存入向量数据库 → 查询时计算相似度 → 返回最相似的结果。

## 选型决策树

```
你的项目处于什么阶段？
│
├─ 学习/原型验证
│   └─→ Chroma（三行代码跑起来）
│
├─ 已有 PostgreSQL 且数据量 < 500 万
│   └─→ pgvector（不引入新组件）
│
├─ 正式产品，中小规模（百万级以下）
│   ├─ 性能优先 → Qdrant（Rust 实现，单节点性能强）
│   ├─ 多模态 → Weaviate（原生支持图文）
│   └─ 最简部署 → Pinecone（全托管）
│
├─ 大规模生产（亿级向量、高并发、多租户）
│   ├─ 自建可控 → Milvus（需 K8s 运维能力）
│   └─ 不想运维 → Pinecone / Zilliz Cloud
│
└─ 纯研究/算法实验
    └─→ FAISS（可自定义索引算法，最灵活）
```

## 核心概念

### 相似度度量

| 方法 | 公式 | 范围 | 适用场景 |
|------|------|------|----------|
| 余弦相似度 | cos(A,B) = A·B / (‖A‖·‖B‖) | [-1, 1] | 文本语义搜索（首选） |
| 欧氏距离 | d = √Σ(ai - bi)² | [0, ∞) | 图像检索、坐标数据 |
| 内积 | A·B = Σ(ai × bi) | (-∞, ∞) | 推荐系统、归一化向量 |

选择原则：文本语义用余弦，图像特征用欧氏，已归一化的向量用内积（等价于余弦）。

### 索引算法

| 算法 | 原理 | 查询速度 | 精度 | 内存占用 |
|------|------|----------|------|----------|
| Flat（暴力搜索） | 逐一计算距离 | O(n) 最慢 | 100% 精确 | 最低 |
| IVF（倒排文件） | 先聚类再搜索子集 | 快 | 高（非精确） | 中 |
| HNSW（分层导航小世界图） | 多层图结构，跳表思想 | 最快 | 很高 | 高 |
| PQ（乘积量化） | 向量压缩后搜索 | 快 | 中 | 最低 |

HNSW 是当前最主流的选择，Chroma、Qdrant、Milvus 默认都用它。

## 与 Agent 的关系

向量数据库在 Agent 架构中有两个核心角色：

1. **RAG 系统的存储层**：文档切块 → 向量化 → 存入向量库 → 查询时检索相关上下文注入 LLM
2. **长期记忆的底层存储**：Agent 的记忆以向量形式存储，支持语义检索
