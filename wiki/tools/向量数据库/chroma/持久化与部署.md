# Chroma 持久化与部署

## 三种运行模式

Chroma 提供三种客户端：

| 模式 | 适用场景 | 数据位置 |
|------|----------|----------|
| Client（内存） | 实验、测试 | 内存，进程退出即丢失 |
| PersistentClient（持久化） | 开发、小规模生产 | 本地磁盘 |
| HttpClient（远程服务） | 生产环境、多进程共享 | 远程 Chroma 服务器 |

## 内存模式

```python
import chromadb

client = chromadb.Client()
collection = client.create_collection("test")
# 进程退出后数据全部丢失
```

适合：Jupyter 实验、单元测试、快速验证想法。

## 持久化模式

```python
client = chromadb.PersistentClient(path="./chroma_data")
collection = client.get_or_create_collection("docs")
collection.add(documents=["..."], ids=["1"])
# 数据保存到 ./chroma_data 目录，重启后仍在
```

### 数据目录结构

```
chroma_data/
├── chroma.sqlite3            # 元数据 + 文档文本（SQLite 数据库）
├── {collection_uuid}/        # HNSW 索引文件
│   ├── header.bin            # 索引头信息
│   ├── data_level0.bin       # 第 0 层图（最大）
│   ├── data_level1.bin       # 第 1 层图
│   └── length.bin            # 向量数量
└── ...
```

### 持久化注意事项

**不要手动移动或删除数据目录**。HNSW 索引文件是二进制格式，路径和 UUID 有内部关联。

**备份方式**：直接复制整个 `chroma_data` 目录即可。恢复时复制回来：

```python
import shutil

# 备份
shutil.copytree("./chroma_data", "./backup/chroma_data_20260726")

# 恢复
shutil.copytree("./backup/chroma_data_20260726", "./chroma_data")
```

**磁盘占用估算**：

| 向量维度 | 1 万条 | 10 万条 | 50 万条 |
|----------|--------|---------|---------|
| 384（MiniLM） | ~30 MB | ~300 MB | ~1.5 GB |
| 768（BGE） | ~60 MB | ~600 MB | ~3 GB |
| 1536（OpenAI） | ~120 MB | ~1.2 GB | ~6 GB |

## Client-Server 模式

当需要多进程访问同一个向量库、或者需要通过网络访问时，使用 Client-Server 模式：

### 启动服务器

```bash
# 方式 1：命令行启动
chroma run --path ./chroma_data --host 0.0.0.0 --port 8000

# 方式 2：Python 启动
import chromadb
from chromadb.config import Settings

server = chromadb.HttpServer(
    host="0.0.0.0",
    port=8000,
    settings=Settings(
        chroma_db_impl="duckdb+parquet",
        persist_directory="./chroma_data",
    ),
)
server.start()
```

### 客户端连接

```python
import chromadb

client = chromadb.HttpClient(host="localhost", port=8000)
collection = client.get_or_create_collection("docs")
# API 和嵌入式模式完全一致
```

### Docker 部署

```yaml
# docker-compose.yml
version: '3.9'
services:
  chroma:
    image: chromadb/chroma:latest
    ports:
      - "8000:8000"
    volumes:
      - ./chroma_data:/chroma/chroma
    environment:
      - IS_PERSISTENT=TRUE
      - ANONYMIZED_TELEMETRY=FALSE
```

```bash
docker-compose up -d
```

## 生产环境配置

### HNSW 参数调优

```python
collection = client.create_collection(
    name="production_docs",
    metadata={
        "hnsw:space": "cosine",
        "hnsw:M": 32,                  # 生产环境适当调高
        "hnsw:construction_ef": 200,    # 构建质量更高
        "hnsw:search_ef": 50,           # 查询精度更高
    }
)
```

### 批量写入优化

大量数据写入时，批量操作比逐条写入快几十倍：

```python
# 不推荐：逐条写入
for doc in documents:
    collection.add(documents=[doc], ids=[doc_id])

# 推荐：批量写入（每批 1000-5000 条）
batch_size = 1000
for i in range(0, len(documents), batch_size):
    batch = documents[i:i+batch_size]
    batch_ids = [f"doc_{j}" for j in range(i, i+len(batch))]
    collection.add(documents=batch, ids=batch_ids)
```

### 错误处理

```python
import chromadb
from chromadb.errors import UniqueConstraintError

client = chromadb.PersistentClient(path="./chroma_data")
collection = client.get_or_create_collection("docs")

try:
    collection.add(documents=["..."], ids=["existing_id"])
except UniqueConstraintError:
    print("ID 已存在，使用 update 代替")
    collection.update(ids=["existing_id"], documents=["..."])
```

## 数据迁移

### 从 Chroma 迁移到其他向量库

```python
# 1. 导出所有数据
all_data = collection.get()
# all_data = {"ids": [...], "documents": [...], "metadatas": [...], "embeddings": [...]}

# 2. 导入到新的向量库（以 pgvector 为例）
from langchain_postgres import PGVector

pg_store = PGVector(
    connection_string="postgresql://...",
    embedding=embeddings,
)
# 逐个添加
for doc, meta, id_ in zip(all_data["documents"], all_data["metadatas"], all_data["ids"]):
    pg_store.add_texts(texts=[doc], metadatas=[meta], ids=[id_])
```

### Chroma 版本升级

Chroma 在 0.4.x → 0.5.x → 0.6.x 之间有不兼容变更。升级前：

1. 备份数据目录
2. 查看 [Chroma 迁移指南](https://docs.trychroma.com/docs/deployment/migration)
3. 使用 `chromadb` 提供的迁移工具

## 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `database is locked` | SQLite 并发写入冲突 | 使用 Client-Server 模式或单线程写入 |
| 查询越来越慢 | HNSW 索引碎片化 | 重建 collection（导出→删除→重新导入） |
| 内存占用过高 | HNSW 索引全在内存 | 减小 `hnsw:M`，或迁移到 Qdrant |
| `Collection not found` | 使用了 `get_collection` 但 collection 不存在 | 改用 `get_or_create_collection` |
