# 上下文工程（Context Engineering）

## 定义
上下文工程是系统化设计和优化传递给 AI Agent 的上下文信息的技术实践。目标是让 Agent 在有限的上下文窗口内获得最有效的信息，提升任务执行的准确性、效率和可靠性。

Agent 的行为完全取决于接收到的上下文——系统提示、工具描述、历史对话和外部检索信息。上下文工程的核心问题：**在这轮调用中，Agent 最需要知道什么？**

> 上下文工程不是一次性的提示词编写，而是贯穿 Agent 全生命周期的持续优化过程。

## 核心要素（五层结构）

| 层次 | 内容 | 特点 |
|------|------|------|
| 系统提示 | 角色定义、行为规则、输出格式 | 每次携带，相对稳定 |
| 工具定义 | 工具名称、参数、功能描述 | 占用大量token，需精简 |
| 历史记录 | 对话和工具调用记录 | 持续增长，需截断/摘要 |
| 检索上下文 | 从知识库/代码库检索的内容 | 按需注入，需相关性排序 |
| 用户输入 | 当前指令或问题 | 不可控，可通过澄清优化 |

## 核心实践

### 1. 上下文预算管理
将窗口视为有限"预算"，合理分配：
- 系统提示 ~10%
- 工具定义 ~20%
- 检索上下文 ~25%
- 历史记录 ~30%
- 用户输入 ~5-10%
- 预留缓冲 ~5%

### 2. 系统提示工程化
- 分层组织（Markdown标题分隔）
- 正面表述（告诉应该怎么做，而非不怎么做）
- 提供示例（few-shot比长篇描述更高效）
- 优先级明确（规则冲突时的优先级）
- 去除冗余（定期审查精简）

### 3. 工具描述优化
- 工具精简：移除无关工具定义（减少30-50%上下文）
- 描述精炼：每个工具一句话说明用途和参数
- 参数约束：明确使用场景和限制
- 分组注册：按任务阶段动态注册不同工具集

### 4. 历史记录压缩策略

| 策略 | 方法 | 适用场景 |
|------|------|----------|
| 滑动窗口 | 保留最近N轮完整记录 | 短对话、实时交互 |
| 阶梯摘要 | 每轮做增量摘要 | 长对话、客服 |
| 分层摘要 | 近期完整、远期摘要 | 文档生成、复杂任务 |
| 关键轮标记 | 标记重要轮次，其余丢弃 | 调试、分步执行 |

### 5. 检索上下文质量控制
- 查询改写：让Agent先改写查询再检索
- 相关性过滤：设置阈值，不足时主动提示
- 来源标注：附上路径和更新时间
- 长度裁剪：按段落截取最相关片段

## 常见模式
- **渐进式披露**：根据执行阶段逐步注入信息，避免干扰
- **上下文压缩链**：链式调用拆分步骤，每步只保留关键中间结果
- **上下文水印**：在关键位置放标记，监控和诊断Agent行为

## AI 工程演进路线
提示词工程（怎么问）→ 上下文工程（给什么信息）→ Harness工程（怎么组织能力）→ Loop工程（怎么持续创造结果）
