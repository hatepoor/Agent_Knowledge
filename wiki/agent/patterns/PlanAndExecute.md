# Plan-and-Execute（规划先行 · 执行在后）

## 定义
把「想清楚」和「去做」解耦成两阶段：**先由 Planner 生成一份完整计划，再由 Executor 按计划逐步执行**。源自 Anthropic 工作流思想（先确定步骤、再逐段执行），也是 [[Agent模式总览]] 六种架构中「规划 + 执行」的直接体现。

```
复杂目标
  └─► Planner（规划者）：拆解为子任务清单
        └─► Executor（执行者）：1.抓取网页 2.提取数据 3.生成报告
              └─► 汇总 → 最终交付
```

## 两种变体（关键决策）
| 变体 | 行为 | 适用 |
|------|------|------|
| **静态规划** | 一次性生成全部计划，线性执行，中途不回头 | 步骤确定、可提前完整列举 |
| **动态规划** | 每步执行后重新评估、必要时修正后续计划 | 步骤会随中间结果变化 |

## 与 ReAct 的本质区别
| 维度 | ReAct | Plan-and-Execute |
|------|-------|------------------|
| 思考时机 | 边想边做（逐 Thought→Action） | 先想完再做（计划先行） |
| 上下文 | 所有历史挤在同一上下文，长任务易超载 | 每步子任务独立上下文，上下文干净 |
| 长任务 | 疲软、易偏航 | 极其适合长线复杂任务 |
| 应对突变 | 灵活但易迷失目标 | 计划出错时不够灵活（可用动态规划缓解） |
| 人工审查 | 难在中间插入 | 可先审查计划再执行 |

## 优点 / 局限
| 优点 | 局限 |
|------|------|
| 长任务友好，上下文不膨胀 | 初始计划可能不准（依赖第一步质量） |
| 推理与执行职责分离、可审计 | 两阶段增加一次延迟 |
| 计划可人工审查/调整 | 纯静态下无法应对未预见变化 |
| 适合提前规划排期式任务 | 需要额外的「计划生成」能力与成本 |

## 最适合的场景
- 长链路、多步骤、可清晰拆解的复杂任务（研究报告、数据处理流水线、MVP 开发）
- 需要先出方案/排期再动手、便于人工把关的任务（典型：Claude Code 的 Plan Mode）
- 上下文预算紧张、希望隔离各子任务上下文的任务

## 及各模式衔接
- 常与 [[Reflection]] 组合：计划由 Critic 审查不合格则重新规划。
- 任务不可预测、需实时决策时，优先选 [[ReAct]]。
- 若同时存在多个可并行分支的搜索类问题，考虑 [[ToT]] 或 [[MultiAgent协作]]。
