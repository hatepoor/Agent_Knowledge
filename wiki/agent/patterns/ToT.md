# ToT 树状思维（Tree of Thoughts）

## 定义
把推理从 CoT 的**单条线性路径**扩展为**树状多路径**：在每个思考节点分叉出多个候选「步骤」，用评估挑选有希望的分支继续，必要时**回溯**重选。模仿人类「设想多种方案→评估→择优→出错回溯」的方式，适合搜索/组合类难题。源自 Anselmi et al.《Tree of Thoughts》(2023)。

```
                  问题
            ┌───────┼───────┐
        想法A1   想法A2   想法A3
         │         │  ✗回溯
   想法B1/ B2  想法B3
         \    /
       最优路径 → 最终方案
```
（每个节点可评估；死胡同分支被剪除，可回到上一节点另选）

## 四项组成
1. **思维分解**：把问题拆成可评估的中间想法（thought）。
2. **思维生成器**：每步生成若干候选想法（采样示意 or 建议他者）。
3. **状态评估器**：给候选打分/分类，决定哪些分支值得继续。
4. **搜索算法**：BFS/DFS 等，配合回溯在树上寻找最优路径。

## 与其他模式的区别
- **vs [[CoT]]**：CoT 一条思路走到底；ToT 多分支 + 评估 + 回溯，更擅长探索，但 token 开销大得多。
- **vs [[ReAct]]**：ReAct 靠外部工具反馈推进；ToT 主要靠内部评估探索多条假设，可再结合工具。
- **vs [[Reflection]]**：Reflection 一条解反复精修；ToT 分叉多条解并择优/回溯。

## 优点 / 局限
| 优点 | 局限 |
|------|------|
| 有效处理组合爆炸、多解选优问题 | 分支多 → token 与延迟成本高 |
| 支持回溯，可绕过局部最优 | 需设计评估器，实现成本高 |
| 对规划/谜题/数学证明提升显著 | 简单问题用它是过度设计 |
| 探索与利用可权衡 | 状态空间大时需要剪枝策略 |

## 最适合的场景
- 组合规划、谜题、数学证明、创意搜索
- 存在多个可行分支、需要「试错与比较」的问题
- 已有明确「中间状态可评估」的问题（否则评估器无从下手）
