# Reflexion（反思内省 · 记忆复用）

## 定义
在 [[Reflection]]（自我反思）的基础上，增加一条关键能力：**把失败原因与改进经验写进「记忆」，在重试时读取复用**。让智能体不是每次从零重做，而是「吃一堑长一智」，跨轮次积累教训。源自 Shinn et al.《Reflexion》(2023)。

```
执行(Act) → 得到结果 → 反思(Reflect)：记录失败与教训
    ▲                           │
    └──── 读取「经验记忆」重试 ◄─┘（写入长期记忆）
          （迭代直到成功或达到上限）
```

## 三个核心组件
1. **Actor**：执行任务（常基于 ReAct）。
2. **Evaluator**：判断成败/质量（自评或外部检查）。
3. **Self-Reflection（自我反思）**：失败后生成「为什么会失败 + 下次怎么做」的文本，写入**记忆存储**（会话内或长期）。
4. **记忆检索**：下次尝试开始时，读取相关经验作为指导，而非白板起跳。

## 与 Reflection 的关键区别
| 维度 | Reflection | Reflexion |
|------|------------|-----------|
| 反思是否留存 | ❌ 每轮从零重做 | ✅ 写进记忆跨轮复用 |
| 重试起点 | 无历史 | 带着先前教训 |
| 适用进程 | 单轮精修 | 多轮/多次尝试的学习 |
| 成本 | 每次重新推理 | 首轮多写摘要，后续少走弯路 |

## 优点 / 局限
| 优点 | 局限 |
|------|------|
| 在试错型任务上持续改进（如代码修复、答题） | 多轮 + 记忆存储，延迟/成本较高 |
| 可跨会话/跨任务积累经验 | 记忆质量依赖反思质量，泛化到新任务有限 |
| 比纯 Reflection 收敛更快 | 需设计记忆存储与检索机制 |
| 尤其适合「反馈明确、可判定成败」的任务 | 长尾任务易陷入重复失败 |

## 最适合的场景
- 需要**反复尝试、从失败中学习**的任务：编程调试、评测题、复杂的工具调用链
- 外部反馈可判定成败（测试通过与否、环境报错）的场景
- 希望同一套经验复用到后续相似任务的场景
