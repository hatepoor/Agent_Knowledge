# CoT 思维链（Chain-of-Thought）

## 定义
思维链指在**不调用外部工具**的前提下，让模型把推理过程显式地「一步步写出来」再作答，而不是直接给答案。本质是把隐式推理变成可解释、可校验的中间步骤。

## 三种触发方式
1. **Few-shot 示例**：在提示词里给 1~3 个「分步解答」示例，模型模仿该格式。
2. **指令式（Zero-shot CoT）**：直接要求「Let's think step by step / 请一步一步推理」，无需示例。
3. **框架内置**：部分模型（o1/o3、Claude 等）在训练时已内化类似能力，无需显式 prompt。

## 核心循环
```
问题
  └─► Step 1: ...（中间推理）
        └─► Step 2: ...（中间推理）
              └─► ... → 最终答案
```
注意：这是**单条线性路径**，且通常不与环境交互。

## 与其他模式的区别
- **vs [[ReAct]]**：CoT 只在模型内部推理、不调工具（「闭着眼想」）；ReAct 打开了工具交互（「睁着眼做」）。
- **vs [[ToT]]**：CoT 是单条路径；ToT 分叉成多棵树并回溯选择。
- **vs [[PlanAndExecute]]**：CoT 是解释过程；Plan-and-Execute 的「计划」面向需执行的动作而非推理步。

## 优点 / 局限
| 优点 | 局限 |
|------|------|
| 显著提升数学/逻辑/常识推理准确率 | 长链易累积错误（一步错步步错） |
| 零工具、零额外依赖、成本低 | 推理不存在「外部反馈」来纠偏 |
| 过程可读，便于排查 | 对需联网检索的事实性问题无能为力 |
| 可作为其它模式的「推理底座」 | 分支/备选方案有限 |

## 最适合的场景
- 数学计算、逻辑推理、代码逻辑推演、常识/concept 问题
- 无需实时信息、仅靠模型内部知识即可回答的问题
- 作为 [[ReAct]]、[[PlanAndExecute]] 等以工具为中心范式的**底层推理增强**
