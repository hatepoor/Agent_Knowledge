# Agentic RL 正在重新定义 AI 的下限

> 原文：Agentic RL 正在重新定义 AI 的下限
> 作者：喔家ArchiSelf
> 发布时间：2026年6月28日
> 来源：ima「AI Agent」知识库

## 核心观点

Agentic RL（智能体强化学习）正在让 AI 学会的第二件事，名叫"行动"——它能感知需求、拆解任务、调用工具、发现错误、自我反思并调整策略。

## 根本认知：RLHF 不是 Agentic RL#

| 对比维度 | 传统 PBRFT（RLHF / DPO） | Agentic RL |
|----------|-----------------------------|--------------|
| 状态空间 | 单一提示 {s₀}，任务立即结束 | 动态状态流 sₜ ∈ S_agent，任务时长远大于 1 |
| 动作空间 | 纯文本序列 | 文本 ∪ 工具调用 ∪ API 请求 |
| 状态转移 | 确定性终止 | 动态转移函数 P(sₜ₊₁ \| sₜ, aₜ) |
| 奖励结构 | 单一标量 r(a) | 步骤级密集奖励 + 稀疏终局奖励 |
| 优化目标 | E[r(a)] | E[Σ γᵗ R(sₜ, aₜ)][[ |

**关键洞见**：信用分配（Credit Assignment）——在多轮交互中判断哪些中间步骤对最终结果有贡献——正是 Agentic RL 区别于传统方法的最本质特征。

## 八大工程原则#

### 第一层：系统架构设计#

**原则一：模块化设计（Modular Design）**

Agentic RL 训练系统的工程架构核心思想是解耦。标准异步训练流水线包含四个阶段：
1. 以较高温度参数采样生成响应
2. 异步汇聚多处理器结果
3. 执行 Actor 训练，将模型响应与真实标签对比计算奖励
4. 计算优势值，若所有优势均为零则提前终止

**架构范式**：
- **并行架构（Parallel）**：智能体同时与多个环境实例交互，效率最高。
- **序列架构（Sequential）**：交互按顺序执行，更适用于需要严格状态依赖的任务。

**代表框架**：
- **HybridFlow（verl）**：3D-HybridEngine 在训练和生成阶段对 Actor 模型进行高效重新分片，实现零内存冗余。
- **Forge（MiniMax）**：原生支持数十万 Agent 脚手架和环境交互、200K 上下文长度，实现每天百万级样本吞吐。
- **AgentGym-RL（复旦 & 字节）**：模块化解耦的统一 RL 框架，支持 27 种以上多样化任务评测。

### 第二层：训练信号设计#

**原则二：趋势路径的结构（Trajectory Structure）**

Agentic RL 处理的是 Trajectory——一个完整的闭环循环：用户提出问题 → 智能体执行动作并调用工具 → 环境返回反馈 → 智能体基于反馈做出下一步决策。

**趋势结构的三个关键特征**：
1. 多步序贯决策：单趋势包含多个时间步的状态转移。
2. 部分可观测性：智能体无法获取环境的完整状态。
3. 稀疏延迟奖励：最终奖励往往在趋势末端才被赋予。

**原则三：智能体掩码（Agent Mask）**

单纯的 RL 训练容易导致奖励黑客（Reward Hacking）或策略坍塌（Policy Collapse）。解决方案是将强化学习与监督微调以加权方式融合：

E_CHO = RL + α ⋅ SFT

其中 α 控制 SFT 损失在整体目标函数中的贡献比例。

**原则四：过程奖励（Process Rewards）**

| 奖励类型 | 英文全称 | 特点 | 适用场景 |
|----------|----------|------|----------|
| 结果奖励 | Outcome Reward Model (ORM) | 仅对最终结果打分，实现简单 | 答案明确可验证的任务（如数学、代码） |
| 过程奖励 | Process Reward Model (PRM) | 对中间步骤逐一评估，提供密集信号 | 长链路推理任务（如多步规划） |

### 第三层：算法优化技巧#

**原则五：优势归一化（Advantage Normalization）**

在传统的 PPO 算法中，优势函数基于全局批次计算。但在 Agentic RL 场景下，这种方法会带来严重问题：不同任务（环境）的难度差异巨大，简单任务的 Advantage 信号可能被困难任务的数值彻底"淹没"。

**ERPO（Environment-level Relative Policy Optimization）算法**：在同一环境内部进行组内归一化。

**原则六：可扩展的阶段采样（Scalable Rollouts）**

生成阶段（Rollout）和训练节点的负载极不平衡。业界主要采取两种架构应对：
1. **分离式架构（Disaggregated）**：生成与训练在物理上分离，各自独占 GPU 资源。
2. **共置架构（Colocated）**：生成与训练共享同一 GPU 集群，通过异步调度实现资源复用。

**原则七：稳定性与探索（Stability & Exploration）**

多轮 Agentic RL 训练面临"回声陷阱"（Echo Trap）：智能体过度拟合局部奖励推理模式。

为缓解这一问题，学界提出了多种策略，统称为 StarPO-S（稳定变体）：
1. 基于方差的趋势过滤：在训练前筛除低质量趋势。
2. 评估器基线化（Critic Baselining）：通过基线减少方差。
3. 解耦裁剪（Decoupled Clipping）：分离不同组件的裁剪范围。

### 第四层：训练策略#

**原则八：任务课程（Task Curriculum）**

渐进式缩放交互框架的设计理念源于课程学习（Curriculum Learning）。

**典型的课程设计包含三个层次**：
- **较短视野 h₁**：训练基础技能任务，交互步数有限，成功概率高。
- **中等视野 h₂**：进一步探索任务，增加交互复杂度。
- **较长视野 h₃**：解决复杂任务，需要长程规划和多步推理。

## 关键算法：PPO 与 GRPO 的战场#

### PPO：经典但昂贵的"全功能选手"#

**四个模型**：
1. 策略模型（Policy）：正在训练的核心模型。
2. 参考模型（Reference）：用于 KL 散度约束。
3. 奖励模型（Reward Model）：给模型生成的回答打分。
4. 价值模型（Critic）：预测当前状态下未来能获得多少累计奖励。

**主要优势**：通用性强，可以处理各种复杂任务场景。

**主要劣势**：显存开销巨大——Critic 模型与策略模型同样大。

### GRPO：DeepSeek 带来的"省显存革命"#

**工作流程只需四步**：
1. 一对多生成：对同一个输入问题，让策略模型一次性生成多个回答。
2. 直接打分：将这些回答送入奖励模型，给出每个回答的实际分数。
3. 计算群体统计量：算出这组回答分数的均值和标准差。
4. 相对归一化：将每个回答的分数与组内均值对比，得到相对优势值。

**主要优势**：大幅降低显存需求。

**主要劣势**：在长程智能体任务中存在明显短板——长短不一的子趋势难以形成可比较的样本组。

### 最新动态：GLM-5.2 放弃 GRPO，回归 PPO#

智谱在长程强化学习阶段放弃了 GRPO，回归了基于价值网络的 PPO。核心原因在于：GLM-5.2 瞄准的长程智能体任务（多轮工具调用、子任务拆解、跨轮反馈）的执行阶段长短不一，GRPO 要求样本组内长度一致才能公平比较，这一前提在长程 Agent 场景下无法满足。

| 应用领域 | 典型任务 | 代表工作 |
|----------|----------|----------|
| 搜索与研究智能体 | Deep Research、多步检索 | Search-R1 |
| 代码智能体 | SWE-bench 代码修复 | KAT-Coder-V2、DeepSWE |
| 数学推理 | GSM8K、MATH | DeepSeek-R1、QwenLong-L1 |
| GUI 智能体 | 网页浏览、桌面操作 | CRAFT-GUI、OSWorld |

**主流工具链**：
- **verl（字节跳动）**：开源框架，支持 PPO、GRPO、REINFORCE++ 等多种算法。
- **Agent Lightning（微软）**：将 Agent 执行建模为 MDP。
- **Forge（MiniMax）**：原生大规模 Agent RL 系统。
- **OpenManus-RL（Ulab-UIUC / MetaGPT）**：集成了 verl 框架。

## 挑战与展望#

1. **训练不稳定性**：多轮交互容易引发梯度爆炸、奖励坍缩等"训练崩溃"现象。
2. **信用分配困难**：独立研究者 Chenchen Zhang 在 2026 年 4 月发布的综述系统梳理了 2024-2026 年初的 47 种信用分配方法。
3. **系统效率瓶颈**：真实环境中的 Rollout 成本高昂，异步训练框架仍需持续优化。
4. **泛化能力验证**：在特定环境训练的智能体能否迁移到全新场景，仍需更多实证。
