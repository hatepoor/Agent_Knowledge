# Agentic RL 算法对比：PPO vs GRPO

## 概述

在 Agentic RL（智能体强化学习）领域，PPO（Proximal Policy Optimization）和 GRPO（Group Relative Policy Optimization）是两种主流的强化学习算法。它们在内存效率、训练稳定性和适用场景上存在显著差异。

## PPO（Proximal Policy Optimization）

### 核心机制

PPO 是一种经典的强化学习算法，使用 Critic 模型（价值网络）来评估状态价值。

**四个核心模型**：
1. **策略模型（Policy）**：正在训练的核心模型
2. **参考模型（Reference）**：用于 KL 散度约束，防止策略偏离过快
3. **奖励模型（Reward Model）**：给模型生成的回答打分
4. **价值模型（Critic）**：预测当前状态下未来能获得多少累计奖励

### 优势

- **通用性强**：可以处理各种复杂任务场景
- **训练稳定**：Critic 模型提供准确的价值估计，训练过程更可控
- **适合长程任务**：能够有效处理长短不一的子轨迹（sub-trajectory）

### 劣势

- **显存开销巨大**：Critic 模型与策略模型同样大，显存需求翻倍
- **训练成本高**：四个模型同时运行，计算和存储开销大

### 适用场景

- 长程智能体任务（多轮工具调用、子任务拆解、跨轮反馈）
- 需要稳定训练的大规模 Agentic RL 系统
- 智谱 GLM-5.2 在长程强化学习阶段放弃 GRPO，回归 PPO

## GRPO（Group Relative Policy Optimization）

### 核心机制

GRPO 是 DeepSeek 提出的显存优化方案，通过群体相对策略优化消除对 Critic 模型的需求。

**工作流程（四步）**：
1. **一对多生成**：对同一个输入问题，让策略模型一次性生成多个回答
2. **直接打分**：将这些回答送入奖励模型，给出每个回答的实际分数
3. **计算群体统计量**：算出这组回答分数的均值和标准差
4. **相对归一化**：将每个回答的分数与组内均值对比，得到相对优势值

### 优势

- **显存需求大幅降低**：无需 Critic 模型，显存需求减半
- **训练速度更快**：减少了模型数量和计算开销
- **实现简单**：基于群体统计的归一化易于实现

### 劣势

- **长程任务表现差**：长短不一的子轨迹难以形成可比较的样本组
- **样本组要求严格**：要求样本组内长度一致才能公平比较，这一前提在长程 Agent 场景下无法满足
- **训练稳定性较差**：缺乏 Critic 的价值估计，训练过程可能不稳定

### 适用场景

- 短程、固定长度的任务（如单轮问答、短文本生成）
- 显存受限的训练环境
- DeepSeek-R1 等模型的训练

## 详细对比

| 对比维度 | PPO | GRPO |
|---------|-----|------|
| **模型数量** | 4个（Policy、Reference、Reward、Critic） | 3个（Policy、Reference、Reward） |
| **显存需求** | 高（Critic 与 Policy 同样大） | 低（无需 Critic） |
| **训练稳定性** | 高（价值网络提供稳定信号） | 中（缺乏价值估计） |
| **长程任务** | 适合（处理变长轨迹） | 不适合（要求固定长度） |
| **训练速度** | 慢 | 快 |
| **计算开销** | 高 | 中 |
| **适用任务** | 复杂 Agent 任务、长程规划 | 短程任务、显存受限场景 |

## 行业动态

### GLM-5.2 放弃 GRPO，回归 PPO

智谱在长程强化学习阶段放弃了 GRPO，回归了基于价值网络的 PPO。核心原因在于：

- GLM-5.2 瞄准的长程智能体任务（多轮工具调用、子任务拆解、跨轮反馈）的执行阶段长短不一
- GRPO 要求样本组内长度一致才能公平比较，这一前提在长程 Agent 场景下无法满足
- PPO 的 Critic 模型能够有效处理变长轨迹，提供更稳定的训练信号

### DeepSeek-R1 使用 GRPO

DeepSeek-R1 使用 GRPO 进行训练，主要考虑：

- 显存效率：降低训练成本
- 任务特性：R1 主要面向推理任务，轨迹长度相对固定
- 工程优化：通过工程手段缓解 GRPO 的训练稳定性问题

## 算法选择建议

### 选择 PPO 的场景

1. **长程 Agent 任务**：需要多轮工具调用、子任务拆解
2. **生产环境部署**：需要稳定的训练过程和可靠的性能
3. **资源充足**：显存和计算资源充足，可以承担四个模型的开销
4. **复杂环境交互**：环境反馈延迟、奖励稀疏的场景

### 选择 GRPO 的场景

1. **显存受限**：训练资源有限，需要降低显存需求
2. **短程任务**：任务长度相对固定，可以组成长度一致的样本组
3. **快速迭代**：需要快速实验和原型验证
4. **推理任务**：主要面向文本生成、问答等短程推理任务
