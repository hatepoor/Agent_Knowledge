# 异常处理

> Python 使用 `try/except/else/finally` 语句来处理运行时错误（异常）。合理的异常处理能让程序更健壮。

## 基本语法

```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("除零错误！")
```

## 完整结构

```python
try:
    # 可能出错的代码
    f = open("data.txt", "r")
    data = f.read()
except FileNotFoundError as e:
    # 捕获特定异常
    print(f"文件未找到: {e}")
except (ValueError, TypeError) as e:
    # 捕获多种异常
    print(f"值或类型错误: {e}")
except Exception as e:
    # 捕获所有常规异常（兜底）
    print(f"未知错误: {e}")
else:
    # try 中没有异常时执行
    print("读取成功")
finally:
    # 无论是否异常都会执行（常用于清理资源）
    f.close()
```

## 执行流程

```
try 块
  ├── 无异常 → else 块 → finally 块
  └── 有异常 → 匹配的 except 块 → finally 块
```

| 块 | 何时执行 |
|----|---------|
| `try` | 总是执行 |
| `except` | try 中发生匹配的异常时 |
| `else` | try 中**没有**异常时 |
| `finally` | **总是**执行（无论有无异常） |

## 常见内置异常

| 异常 | 触发场景 |
|------|---------|
| `ValueError` | 值不合适，如 `int("abc")` |
| `TypeError` | 类型错误，如 `"a" + 1` |
| `KeyError` | 字典键不存在 |
| `IndexError` | 列表索引越界 |
| `AttributeError` | 对象没有该属性 |
| `FileNotFoundError` | 文件不存在 |
| `ImportError` / `ModuleNotFoundError` | 导入失败 |
| `ZeroDivisionError` | 除以零 |
| `NameError` | 变量名未定义 |
| `IOError` / `OSError` | I/O 操作失败 |
| `StopIteration` | 迭代器耗尽 |
| `RuntimeError` | 通用运行时错误 |
| `RecursionError` | 递归深度超限 |

## 抛出异常

```python
# raise 主动抛出异常
def set_age(age):
    if age < 0:
        raise ValueError("年龄不能为负数")
    if not isinstance(age, int):
        raise TypeError("年龄必须是整数")
    return age

# 重新抛出当前异常
try:
    do_something()
except Exception as e:
    log_error(e)
    raise    # 重新抛出同一个异常
```

## assert 断言语句

> `assert` = 断言语句，用于在代码中"声明"某个条件必须为真。条件为真则程序正常继续；条件为假则立即抛出 `AssertionError` 终止程序。本质是**开发期调试工具**。

### 语法

```python
assert 条件
assert 条件, "失败时的提示信息"
```

```python
x = 10
assert x > 0               # 条件为真 → 什么都不发生，继续执行
assert x > 100, "x 必须大于 100"   # 条件为假 → 抛 AssertionError("x 必须大于 100")
```

### 执行流程

```
执行到 assert 条件
    │
    ├── 条件为 True  → 空操作，继续下一行
    │
    └── 条件为 False → 抛 AssertionError("提示信息") → 程序终止（未捕获时）
```

### 等价写法

```python
assert x > 0, "x 必须为正数"

# 完全等价于
if not x > 0:
    raise AssertionError("x 必须为正数")
```

### 三个典型使用场景

```python
# 1. 防御性编程——检查函数前置条件
def divide(a, b):
    assert b != 0, "除数不能为 0"
    return a / b

# 2. 检查后置条件——验证计算结果在合理范围
def calculate_discount(price, rate):
    result = price * (1 - rate)
    assert 0 <= result <= price, "折扣计算异常：结果超出合理范围"
    return result

# 3. 开发期调试——检查"不可能发生"的分支
def get_user_role(user):
    if user.is_admin:
        return "admin"
    elif user.is_member:
        return "member"
    else:
        assert False, f"未知用户类型: {user}"  # 走到这里说明逻辑有 bug
```

### ⚠️ 关键坑：`-O` 模式下断言被禁用

Python 优化模式运行（`python -O`）时，**所有 assert 语句会被直接删除，不执行**：

```python
# demo.py
def check(n):
    assert n > 0, "n 必须为正"
    return n * 2

check(-1)   # 普通模式：AssertionError
            # -O 模式：返回 -2！断言被跳过，参数错误静默通过
```

| | `assert` | `if + raise` / `raise ValueError` |
|---|---|---|
| `-O` 模式下 | **被删除，不执行** | 始终执行 |
| 用途 | 开发期调试、内部不变量检查 | 生产环境的正式输入校验 |
| 面向对象 | 开发者自己（"我的代码不该这样"） | 用户/外部调用方（"输入不合法"） |

> **经验规则**：面向用户的输入校验必须用 `if + raise ValueError`；`assert` 只用来检查"自己代码内部的状态"，且要接受它在生产优化模式下可能不生效。

### 其他注意点

```python
# 1. 断言失败抛的是 AssertionError，不是 ValueError
# 2. 提示信息不是惰性求值——即使条件为真也会先求值
assert x > 0, expensive_log()   # expensive_log() 无条件执行（浪费）
# 3. 不要用 assert 做安全检查（-O 模式下跳过，后果严重）
assert user.is_admin, "无权访问"   # ❌ 危险！
```

### Agent 项目中的实战用法

```python
def web_search_tool(query: str, max_results: int):
    # 外部输入 → raise（用户可能传错）
    if not query or len(query) > 500:
        raise ValueError("查询内容不能为空且不超过 500 字")
    # 内部配置 → assert（代码写死的值，不该错）
    assert 1 <= max_results <= 20, "max_results 配置超出范围"
    ...
```

## 自定义异常

```python
class AppError(Exception):
    """应用基础异常"""
    pass

class ValidationError(AppError):
    """数据校验异常"""
    def __init__(self, field, message):
        self.field = field
        self.message = message
        super().__init__(f"字段 '{field}': {message}")

class NotFoundError(AppError):
    """资源未找到"""
    pass

# 使用
try:
    raise ValidationError("email", "格式不正确")
except ValidationError as e:
    print(e)            # 字段 'email': 格式不正确
    print(e.field)      # email
    print(e.message)    # 格式不正确
```

## 异常链（Exception Chaining）

```python
try:
    result = config["db"]["password"]
except KeyError as e:
    raise RuntimeError("数据库配置缺失") from e
    # 保留原始异常信息，Traceback 中会显示原因
```

## 最佳实践

1. **精确捕获**：避免裸 `except:`，应指定具体异常类型
2. **不要吞掉异常**：`except: pass` 是最危险的模式
3. **finally 用于清理**：文件关闭、锁释放、连接断开
4. **用 `with` 替代手动清理**：上下文管理器更安全
5. **自定义异常继承自合适的基类**：便于分组捕获

```python
# 好的做法
try:
    data = json.loads(raw)
except json.JSONDecodeError as e:
    logger.error(f"JSON 解析失败: {e}")
    raise ConfigError("配置文件格式错误") from e

# 不好的做法
try:
    data = json.loads(raw)
except:          # 太宽泛，会吞掉 KeyboardInterrupt 等
    pass         # 吞掉异常，完全无法调试
```
