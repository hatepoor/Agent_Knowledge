# 选型决策树

> 根据任务类型和场景，快速做出正确的并发模型选择。

## 决策树

```
你的任务是什么类型？
│
├─ I/O 密集型（网络/文件/DB）
│  ├─ 并发连接数 < 100？
│  │  └─ → threading 或 ThreadPoolExecutor
│  ├─ 并发连接数 100-1000？
│  │  └─ → ThreadPoolExecutor（控制并发数）
│  └─ 并发连接数 > 1000？
│     └─ → asyncio
│
├─ CPU 密集型（计算/处理）
│  ├─ 数据量小，任务可独立？
│  │  └─ → ProcessPoolExecutor
│  ├─ 数据量大，需要共享内存？
│  │  └─ → multiprocessing + shared_memory
│  └─ 可以用 NumPy/专用库？
│     └─ → 使用专用库（内部已释放 GIL）
│
└─ 混合型（I/O + CPU）
   ├─ I/O 和 CPU 阶段分离？
   │  └─ → asyncio + run_in_executor(ProcessPool)
   └─ I/O 和 CPU 交错？
      └─ → ThreadPoolExecutor + ProcessPoolExecutor
```

## 常见选型错误

### 错误 1：CPU 密集型用 threading

```python
# ❌ 多线程在 GIL 下不会加速 CPU 任务
threads = [threading.Thread(target=heavy_compute) for _ in range(4)]

# ✅ 使用多进程
with Pool(4) as p:
    p.map(heavy_compute, data)
```

### 错误 2：少量 I/O 用 asyncio

```python
# ❌ 过度工程化：5 个请求用 asyncio
async def fetch(url): ...

# ✅ 简单方案
with ThreadPoolExecutor(5) as pool:
    results = list(pool.map(fetch, urls))
```

### 错误 3：进程池中传递大对象

```python
# ❌ 每次调用都序列化 800MB 数据
pool.map(process, [big_array] * 4)

# ✅ 使用共享内存
from multiprocessing import shared_memory
```
