# 性能基准对比

> 通过 I/O 密集型和 CPU 密集型的量化实验，直观展示三种模型的性能差异。

## I/O 密集型基准

100 个 1 秒延迟的 HTTP 请求：

```
串行:           ~100s    (线性叠加)
threading:      ~5s      (受限于线程数和 GIL 切换)
multiprocessing:~5s      (进程开销 + I/O)
asyncio:        ~1s      (最优：单线程高并发)
```

## CPU 密集型基准

8 核机器上计算 `sum(i*i for i in range(10_000_000))` × 8 次：

```
串行:            8.21s
threading:      8.15s  (加速: 1.01x ← GIL 限制)
multiprocessing: 1.15s  (加速: 7.14x ← 接近 8 核线性加速)
```

## 适用场景矩阵

### I/O 密集型

| 场景 | 并发规模 | 推荐 | 理由 |
|------|----------|------|------|
| 少量 HTTP 请求 | <100 | threading | 简单直接 |
| 批量 API 调用 | 100-1000 | ThreadPoolExecutor | 池化管理 |
| 超高并发 API | >1000 | asyncio | 单线程高并发 |
| WebSocket 服务 | >1000 | asyncio | 长连接管理 |

### CPU 密集型

| 场景 | 数据规模 | 推荐 | 理由 |
|------|----------|------|------|
| 数值计算 | 中 | multiprocessing.Pool | 绕过 GIL |
| 机器学习 | 大 | 专用库（CUDA/NumPy） | 底层释放 GIL |
| 大矩阵运算 | 大 | NumPy/MKL | C 扩展自动并行 |

### 混合型

| 场景 | 推荐 | 理由 |
|------|------|------|
| 下载+处理 | ThreadPool + ProcessPool | 各取所长 |
| 爬虫+解析 | asyncio + run_in_executor | 异步 I/O + 同步解析 |
