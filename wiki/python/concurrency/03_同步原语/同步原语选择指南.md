# 同步原语选择指南

> 六种同步原语的对比与选择决策树。

## 总览对比

| 原语 | 核心作用 | 典型场景 |
|------|----------|----------|
| `Lock` | 互斥访问临界区 | 保护共享变量 |
| `RLock` | 可重入的互斥锁 | 同一线程内多次获取锁 |
| `Semaphore` | 限制并发访问数量 | 连接池、资源池 |
| `Event` | 线程间信号通知 | 启动/停止信号 |
| `Condition` | 等待条件满足后唤醒 | 生产者-消费者 |
| `Barrier` | 线程同步到汇合点 | 多线程分阶段并行 |

## 选择决策树

```
需要保护共享资源？
├─ 是 → 需要锁
│  ├─ 同一线程内需要重入？ → RLock
│  └─ 不需要重入？ → Lock
├─ 需要限制并发数？ → Semaphore / BoundedSemaphore
├─ 需要等待/发出信号？
│  ├─ 简单开关信号 → Event
│  └─ 条件满足后唤醒 → Condition
└─ 需要多线程同步到汇合点？ → Barrier
```

## 性能对比

```python
# 不同同步原语的大致开销（纳秒级，仅供参考）
# 单次 acquire+release 的开销

# Lock:          ~50 ns   最轻量
# RLock:         ~100 ns  额外的计数器开销
# Semaphore:     ~80 ns   类似 Lock
# Event:         ~100 ns  包含内部 Lock
# Condition:     ~150 ns  最重（wait 时释放+重新获取锁）
# Barrier:       ~200 ns  需要协调多个线程
```
