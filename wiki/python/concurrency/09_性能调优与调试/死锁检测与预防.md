# 死锁检测与预防

> 死锁是并发编程中最危险的陷阱。本页讲解死锁条件、预防策略和检测方法。

## 死锁的四个必要条件

```
1. 互斥 (Mutual Exclusion)：资源同一时刻只能被一个线程持有
2. 持有并等待 (Hold and Wait)：持有资源的同时等待其他资源
3. 不可抢占 (No Preemption)：资源不能被强制剥夺
4. 循环等待 (Circular Wait)：线程间形成等待环
```

## 经典死锁示例

```python
import threading
import time

lock_a = threading.Lock()
lock_b = threading.Lock()

def thread1():
    with lock_a:
        print("Thread 1: 持有 A，等待 B")
        time.sleep(0.1)
        with lock_b:  # 死锁！
            print("Thread 1: 获取 A 和 B")

def thread2():
    with lock_b:
        print("Thread 2: 持有 B，等待 A")
        time.sleep(0.1)
        with lock_a:  # 死锁！
            print("Thread 2: 获取 B 和 A")

t1 = threading.Thread(target=thread1)
t2 = threading.Thread(target=thread2)
t1.start(); t2.start()
t1.join(timeout=3); t2.join(timeout=3)
if t1.is_alive():
    print("死锁！线程仍在运行")
```

## 预防策略

### 1. 锁排序

```python
# 规则：始终按固定顺序获取锁（A → B）
def thread1():
    with lock_a:      # 先 A
        with lock_b:  # 后 B
            pass

def thread2():
    with lock_a:      # 先 A（不是先 B！）
        with lock_b:  # 后 B
            pass
```

### 2. 锁超时

```python
def thread1():
    acquired_a = lock_a.acquire(timeout=1)
    if not acquired_a:
        print("获取 A 超时，放弃")
        return

    acquired_b = lock_b.acquire(timeout=1)
    if not acquired_b:
        lock_a.release()
        return

    try:
        pass
    finally:
        lock_b.release()
        lock_a.release()
```

### 3. 使用 RLock

```python
# 同一线程多次获取同一把锁用 RLock
lock = threading.RLock()
```

## 死锁检测

```python
import threading
import sys
import traceback

def dump_threads():
    """打印所有活跃线程的调用栈"""
    print(f"\n=== 活跃线程: {threading.active_count()} ===")
    for thread in threading.enumerate():
        print(f"\n--- {thread.name} (ident={thread.ident}) ---")
        frame = sys._current_frames().get(thread.ident)
        if frame:
            traceback.print_stack(frame)
```
