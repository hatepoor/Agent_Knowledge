# 常见性能陷阱

> 并发编程中最常见的性能陷阱及其解决方案。

## 陷阱 1：线程数过多

```python
# ❌ 1000 个 URL 用 1000 个线程
with ThreadPoolExecutor(max_workers=1000) as ex:
    list(ex.map(requests.get, urls))

# ✅ 控制并发数
with ThreadPoolExecutor(max_workers=20) as ex:
    list(ex.map(requests.get, urls))
```

## 陷阱 2：进程间传递大数据

```python
# ❌ 每次调用都 pickle 序列化 800MB
pool.map(process, [big_array] * 4)

# ✅ 使用共享内存
from multiprocessing import shared_memory
shm = shared_memory.SharedMemory(create=True, size=big_array.nbytes)
```

## 陷阱 3：锁粒度过大

```python
# ❌ 整个循环加锁
def process_large_batch(items):
    with lock:
        for item in items:  # 10 万次循环都在锁内
            results.append(item * 2)

# ✅ 只锁共享操作
def process_large_batch_v2(items):
    local_results = []
    for item in items:  # 无锁计算
        local_results.append(item * 2)
    with lock:  # 只锁结果合并
        results.extend(local_results)
```

## 陷阱 4：忽略 pickle 限制

```python
# ❌ 不可 pickle 的对象传给子进程
lock = threading.Lock()  # 不可 pickle
p = Process(target=worker, args=(lock,))  # TypeError

# ✅ 使用 multiprocessing 的同步原语
from multiprocessing import Lock
lock = Lock()  # 可 pickle
```

## 陷阱 5：阻塞事件循环

```python
# ❌ CPU 密集操作阻塞 asyncio 事件循环
async def bad_handler(request):
    result = heavy_computation()  # 阻塞 2 秒
    time.sleep(2)

# ✅ 放到线程/进程池中
async def good_handler(request):
    loop = asyncio.get_event_loop()
    result = await loop.run_in_executor(None, heavy_computation)
    await asyncio.sleep(2)
```

## GIL 竞争检测

```python
import threading
import time

def cpu_burn(duration):
    end = time.perf_counter() + duration
    while time.perf_counter() < end:
        pass

# 单线程基线
start = time.perf_counter()
cpu_burn(1.0)
single = time.perf_counter() - start

# 4 线程
threads = [threading.Thread(target=cpu_burn, args=(1.0,)) for _ in range(4)]
start = time.perf_counter()
for t in threads: t.start()
for t in threads: t.join()
multi = time.perf_counter() - start

ratio = multi / single
if ratio > 3.5:
    print("⚠ GIL 竞争严重！考虑 multiprocessing")
```
