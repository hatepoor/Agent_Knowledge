# 竞态条件详解

> 竞态条件是多步操作之间被其他线程插入导致的错误。本页通过经典案例深入讲解。

## 经典案例：counter += 1

```python
import threading

counter = 0

def unsafe_increment():
    global counter
    for _ in range(100000):
        counter += 1  # 非原子操作！

threads = [threading.Thread(target=unsafe_increment) for _ in range(5)]
for t in threads: t.start()
for t in threads: t.join()
print(f"期望: 500000, 实际: {counter}")
# 输出可能是 387421
```

`counter += 1` 编译为多条字节码：
```python
import dis
dis.dis(compile("counter += 1", "<stdin>", "exec"))
# 1. LOAD_GLOBAL   counter    ← 读取
# 2. LOAD_CONST    1          ← 加载 1
# 3. BINARY_ADD               ← 相加
# 4. STORE_GLOBAL  counter    ← 写回
# GIL 可能在这些步骤之间释放！
```

## 经典案例：check-then-act

```python
balance = 100

def withdraw(amount):
    global balance
    if balance >= amount:        # 步骤 1: 检查余额
        # GIL 可能在这里释放！
        balance -= amount        # 步骤 2: 扣款
        return amount
    else:
        return "余额不足"

# 两个线程同时取款 100：
# 线程 A: 检查 100 >= 100 ✓
#          ← GIL 切换到线程 B
# 线程 B: 检查 100 >= 100 ✓  ← 还没扣款，所以还是 100
# 线程 B: 扣款 100，余额 = 0
# 线程 A: 扣款 100，余额 = -100  ← 透支了！
```

## 解决方案

```python
import threading

balance = 100
lock = threading.Lock()

def safe_withdraw(amount):
    global balance
    with lock:  # 加锁保证检查和扣款的原子性
        if balance >= amount:
            balance -= amount
            return amount
        else:
            return "余额不足"
```

## 常见竞态场景

| 场景 | 描述 | 解决方案 |
|------|------|----------|
| 计数器自增 | `counter += 1` 非原子 | Lock/RLock |
| 检查后操作 | check-then-act 之间被中断 | Lock |
| 懒初始化 | 单例模式双重检查 | 双重检查锁定 |
| 读写竞争 | 读旧值后写新值 | Lock 或不可变对象 |
