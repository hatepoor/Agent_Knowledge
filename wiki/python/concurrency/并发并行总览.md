## 核心速览

### 并发 vs 并行

```
并发 (Concurrency)
  多个任务交替执行，同一时刻可能只执行一个
  强调"同时处理"——不一定"同时执行"
  适用：I/O 密集（网络请求、文件读写）

并行 (Parallelism)
  多个任务真正同时执行，需要多核 CPU
  强调"同时执行"——物理上的同时
  适用：CPU 密集（数值计算、图像处理）
```

### 三种并发模型对比

| 维度 | threading | multiprocessing | asyncio |
|------|-----------|----------------|---------|
| 执行单元 | 线程（用户态） | 进程（独立内存空间） | 协程（单线程内） |
| GIL 限制 | 受限 | 不受限 | 不适用 |
| 适用场景 | I/O 密集型 | CPU 密集型 | 超高并发 I/O |
| 内存开销 | 低（共享进程内存） | 高（独立内存空间） | 最低 |
| 通信成本 | 低（直接共享变量） | 高（IPC：Queue/Pipe） | 无需通信 |
| 启动成本 | ~0.01ms | ~10-100ms | ~0.001ms |
| 数据安全 | 需同步原语 | 天然隔离 | 单线程无竞争 |
| Python 3.13+ | 可选 no-GIL | 不受影响 | 不受影响 |

### 速选决策树

```
你的任务是？
├─ I/O 密集（网络/文件/数据库）
│  ├─ 连接数 < 1000 → threading 或 concurrent.futures.ThreadPoolExecutor
│  ├─ 连接数 > 1000 → asyncio
│  └─ 需要兼容同步库 → threading
├─ CPU 密集（计算/图像/数值）
│  ├─ 数据量小 → multiprocessing.Pool
│  ├─ 数据量大，可分片 → multiprocessing + 共享内存
│  └─ 需要 GPU → 专用库（CUDA/torch.multiprocessing）
└─ 混合型
   └─ concurrent.futures（同时使用线程池+进程池）
```

### GIL 对并发的影响

```
有 GIL 的 Python（默认，3.12 及以下）：
  ┌─────────────────────────────────────┐
  │           Python 进程                │
  │  ┌──────┐  ┌──────┐  ┌──────┐      │
  │  │线程 1│  │线程 2│  │线程 3│      │
  │  └──┬───┘  └──┬───┘  └──┬───┘      │
  │     │         │         │           │
  │     └─────────┼─────────┘           │
  │               ▼                     │
  │        ┌─────────────┐              │
  │        │  GIL (互斥锁) │             │
  │        └──────┬──────┘              │
  │               ▼                     │
  │        ┌─────────────┐              │
  │        │  单个 CPU 核心 │             │
  │        └─────────────┘              │
  └─────────────────────────────────────┘
  → 多线程无法真正并行执行 Python 字节码
  → I/O 操作会释放 GIL，所以 I/O 密集场景仍受益

Python 3.13+ 自由线程（PEP 703，实验性）：
  → GIL 可禁用（--disable-gil 编译选项）
  → 多线程可真正并行执行
  → 详见 [[python/concurrency/01_GIL/GIL历史与PEP703]]
```
