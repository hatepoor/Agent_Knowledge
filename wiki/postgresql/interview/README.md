# PostgreSQL 面试题库

> **本目录的定位：把 PostgreSQL 的知识点变成「面试能说出口的答案」。**
>
> 与 `interview/01-八股基础/数据库八股.md`（跨数据库通用题）的分工：**那一篇讲 MySQL/PG 通用概念，本目录只讲 PG 特有机制与深挖题。**
> 逐题格式统一为「先问题、后答案」，**每篇不超过 10 题，且同篇只讲一个主题**。

---

## 一、版本口径（2026-10）

| 项 | 说明 |
|---|---|
| 版本基线 | **PostgreSQL 18.x**（18.0 于 2025-09 GA，当前稳定线 18.6） |
| 上一个稳定大版本 | 17.x |
| EOL 提醒 | **PG 14 于 2026-11-12 停止维护**，面试举例不要再说「我们生产用 14」 |
| 18 的关键变化 | 异步 I/O（AIO）、`uuidv7()` 内置函数、虚拟生成列、OAuth 2.0 认证、`EXPLAIN` 可读性改进 |
| 答题建议 | 机制题不依赖版本；提到新特性时明确说「18 才有」，避免把新特性当成通用能力 |

⚠️ **不要背具体默认参数值**（如 `shared_buffers` 默认 128MB）。这些随版本和发行版变，说「按内存比例调、默认偏保守」更稳。

## 三、使用方式

```
第一遍：只看问题，口述答案，卡住做标记
第二遍：读答案，重点看「追问」和「对比表」
第三遍：把 PG 与 MySQL 的差异点单独背一遍（面试官最爱问这个）
```

**判断标准**：能用「机制 → 现象 → 调优手段」三段式讲完一题，才算过。

⚠️ **筛选原则**：

1. **只收机制题、选型题、排查题**，不收「某个参数叫什么」的记忆题；
2. **PG 与 MySQL 的差异点优先收**，这是 PG 面试的区分度所在；
3. **AI 应用相关单列一篇**（pgvector / 向量检索 / Checkpointer），这是当前岗位的真实需求。

## 六、答题总原则

| 原则 | 说明 |
|------|------|
| **先说结论，再说机制** | 「PG 用 MVCC，读不阻塞写」比先讲一堆结构更抓人 |
| **机制 → 现象 → 手段** | 每个答案都落到「所以线上会出现什么、怎么处理」 |
| **主动对比 MySQL** | 面试官问 PG，往往是想听差异；能对比说明真用过 |
| **区分版本** | 「PG 12 之后 CTE 默认内联」这类话，比笼统说「PG 优化好」可信 |
| **不编数字** | 参数、阈值记不准就说「量级」或「按比例」，别报精确值 |
