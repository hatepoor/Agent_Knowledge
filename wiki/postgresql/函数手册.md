# PostgreSQL 函数手册

> **这份文件存在的唯一目的:您永远不会因为"不认识某个函数"而卡住。**
>
> 本套文档中出现的**每一个函数**都收录在此。遇到不认识的名字,先在这里查——不需要往回翻任何章节。
>
> 使用方式:直接按 `Ctrl+F` / `Cmd+F` 搜索函数名。
>
> **如果卡住的是"关键字"而不是"函数"**(例如 `CONSTRAINT`、`RETURNING`、`relation`),请查 [[postgresql/术语与关键字手册]]。

## 怎么读这张表

| 列 | 含义 |
|----|------|
| **作用** | 一句话说明它做什么 |
| **示例 / 返回值** | 能直接对照的结果 |
| **详解位置** | 该函数的完整讲解在哪一章(带链接) |

**标注说明**:`⭐` = 入门阶段必须掌握;`PG14+` / `PG15+` / `PG18+` = 需要的最低版本,低版本用不了。

**查不到怎么办**:见本页最后一节「查不到函数时的四步法」。

## 二、聚合函数 ⭐

| 函数 | 作用 | 示例 / 返回值 | 详解位置 |
|------|------|---------------|----------|

| `avg(x)` | 平均(**分母是非 NULL 行数**) | `avg(score)` | 同上 |

| `array_agg(x)` | 聚合成数组(**含 NULL**) | `array_agg(id)` → `{1,2,3}` | 同上 |

| `power(a, b)` | a 的 b 次方 | `power(2, 10)` → `1024` | 同上 |
| `sqrt(x)` | 平方根 | `sqrt(16)` → `4` | 同上 |

| `generate_series(起点, 终点 [, 步长])` | **不是数值函数,是表函数**:生成一行序列 | `generate_series(1, 3)` → `1,2,3` | [[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.3-日期时间类型]] |

**`width_bucket` 详解**(原先缺失,现补齐)

```sql
-- 签名:width_bucket(operand, low, high, count) → integer
-- 把 [low, high) 均分成 count 个等宽区间,返回 operand 落在第几个桶
-- 桶号从 1 开始;低于 low 返回 0,高于等于 high 返回 count + 1

SELECT width_bucket(5, 0, 10, 5);    -- 3
-- 区间宽 = (10-0)/5 = 2,分桶为:
--   [0,2) → 1    [2,4) → 2    [4,6) → 3    [6,8) → 4    [8,10] → 5
--   5 落在 [4,6) → 第 3 桶

SELECT width_bucket(-1, 0, 10, 5);   -- 0   低于下界
SELECT width_bucket(99, 0, 10, 5);   -- 6   高于等于上界(5+1)
```

**典型用途:做等宽直方图**

```sql
SELECT width_bucket(amount, 0, 1000, 10) AS bucket,
       count(*)                            AS cnt,
       min(amount)                         AS lo,
       max(amount)                         AS hi
FROM orders
GROUP BY 1 ORDER BY 1;
```

> **同类但不同用途的函数别混淆**:
> - `width_bucket` —— 按**数值等宽**分桶(直方图)
> - `date_bin`(PG14+)—— 按**时间等宽**分桶(时间序列)
> - `ntile(n)` —— 按**行数**均分成 n 份(每桶行数相近,但桶的取值宽度不等)

**`date_bin` 详解**(原先只有行尾注释,现补齐)

```sql
-- 签名:date_bin(stride interval, source timestamp, origin timestamp) → timestamp
-- 从 origin 起,按 stride 划分时间桶,返回 source 所属桶的起点

SELECT date_bin(interval '15 min', timestamp '2026-09-19 10:37:42',
                timestamp '2000-01-01');
-- 2026-09-19 10:30:00    ← 归到所在 15 分钟区间(10:30~10:45)的起点

-- 典型用途:按 15 分钟统计单量(比 date_trunc 更灵活,能对齐任意起点)
SELECT date_bin(interval '15 min', created_at, timestamp '2026-01-01') AS bucket,
       count(*) AS orders
FROM orders
GROUP BY 1 ORDER BY 1;
```

**与 `date_trunc` 的差异**:`date_trunc` 只能按日历单位(年/月/日/时),且从自然边界起算;`date_bin` 可任意步长(如 7 分钟)并自定义起点。

| 需求 | 用哪个 |
|------|--------|
| 按自然日/月/年 | `date_trunc` |
| 按 15 分钟 / 7 天 / 自定义起点 | `date_bin` |
| 按数值区间分桶 | `width_bucket` |

| 运算符 `@>` `<@` `&&` `\|\|` `=` | 包含 / 被包含 / 有交集 / 拼接 / 逐元素相等 | `'{a,b}' @> '{a}'` → `true` | [[postgresql/02-中段阶段-专题精讲/数组范围与枚举/专题概览]] |
| `= ANY(数组)` | 某值等于数组中任一元素 | `'a' = ANY(ARRAY['a','b'])` → `true` | [[postgresql/01-入门阶段-基础教程/第05章-查询核心/5.1-WHERE与运算符]] |
| `<> ALL(数组)` | 某值不等于数组中所有元素 | | 同上 |

> **`@>` 与 `= ANY` 的区别**(最易混):`tags @> ARRAY['a']` 是"tags 包含 a";`'a' = ANY(tags)` 是"数组里存在 a"。单元素时间等价,多元素时 `@>` 要求**全部包含**。

### 咨询锁(advisory lock)

**不是锁表,是锁"你自己约定的一个编号"**。常用于分布式任务互斥、定时任务防重、外部资源串行化。

| 函数 | 作用 |
|------|------|
| `pg_advisory_lock(key)` | 获取**会话级**咨询锁,**阻塞等待**直到拿到 |
| `pg_try_advisory_lock(key)` | 同上但**不等待**,立即返回成功/失败(布尔) |
| `pg_advisory_unlock(key)` | 释放会话级咨询锁 |
| `pg_advisory_xact_lock(key)` | 获取**事务级**咨询锁,事务结束自动释放(更安全,不会忘释放) |
| `pg_try_advisory_xact_lock(key)` | 同上,不等待 |

```sql
-- key 可以是单个 bigint,也可以是两个 int:(类目, 对象)
SELECT pg_try_advisory_lock(42);          -- true 表示拿到锁
SELECT pg_advisory_unlock(42);
```

> **该用哪个**:优先 `pg_advisory_xact_lock`。会话级锁若忘了 `unlock`,会一直持有到连接断开。

## 十四、查不到函数时的四步法

如果某个函数在上表里没有,按顺序做这四步——**不需要问任何人**:

### 第 1 步:在 psql 里查签名与说明

```sql
\df width_bucket
-- 输出:Schema | Name | Result data type | Argument data types | Type
-- 会列出所有重载版本与参数类型

\df+ width_bucket
-- 额外显示:Owner、Security、Volatility、Description
```

查**操作符**(如 `@>` `&&`)对应的实现:

```sql
SELECT oprname, oprleft::regtype, oprright::regtype, oprresult::regtype
FROM pg_operator WHERE oprname = '@>';
```

### 第 2 步:查 SQL 语法帮助

```sql
\h CREATE TABLE        -- 语法帮助,psql 内置
\h SELECT
\h UPDATE
```

### 第 3 步:直接试出来

```sql
-- 对纯函数,试一个输入就知道返回值语义
SELECT width_bucket(5, 0, 10, 5);      -- 输出 3
SELECT lower_inc('[1,5)'::int4range);  -- 输出 true

-- 对表函数,看它返回几行几列
SELECT * FROM generate_series(1, 3);
SELECT * FROM unnest(ARRAY['a','b']) AS t(x);
```

### 第 4 步:查官方文档

| 想查 | 地址 |
|------|------|
| 函数与操作符总表 | https://www.postgresql.org/docs/current/functions.html |
| SQL 命令语法 | https://www.postgresql.org/docs/current/sql-commands.html |
| 系统视图与目录 | https://www.postgresql.org/docs/current/catalogs.html |
| 版本新特性 | https://www.postgresql.org/docs/current/release.html |

> **最可靠的技巧**:在上表或官方文档中搜到函数名后,**用 `\df+ 函数名` 确认参数类型再调用**。绝大多数"函数报错"其实是参数类型或顺序不匹配,而不是函数不存在。

## 十五、阅读本套文档的约定

1. **不假设您认识任何函数。** 代码块中出现陌生函数时,先查本手册;查不到用第十四节四步法。
2. **代码块可直接执行。** 入门阶段的所有 SQL 都可粘贴到 psql 运行。表中未创建时,先执行同章节前面的 `CREATE TABLE`。
3. **看到 `-- 中文注释` 就是解释**,注释紧跟函数用途;若某行注释过短,以本手册为准。
4. **发现"用了但没讲"的函数,直接指出。** 这类缺口是本套文档明确要避免的缺陷,发现即修复。
