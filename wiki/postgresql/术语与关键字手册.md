> **这份文件存在的唯一目的:您永远不会因为"不认识某个词"而卡住。**

| 列 | 含义 |

## 二、连接(JOIN)类关键字 ⭐

| 关键字 | 一句话解释 |
|--------|-----------|
| `JOIN` / `INNER JOIN` 🔒 | 内连接:只保留两边都匹配上的行 |
| `LEFT JOIN` / `LEFT OUTER JOIN` 🔒 | 左连接:保留左表全部行,右表没有匹配时填 NULL |
| `RIGHT JOIN` 🔒 | 右连接:保留右表全部行 |
| `FULL JOIN` / `FULL OUTER JOIN` 🔒 | 全连接:两边都保留 |
| `CROSS JOIN` 🔒 | 交叉连接:左表每行 × 右表每行(笛卡尔积) |
| `ON` 🔒 | 指定连接条件:`ON a.id = b.a_id` |
| `USING (列)` 🔒 | 连接条件是"同名同值"时的简写 |
| `NATURAL JOIN` 🔒 | 自动按所有同名列连接(**不推荐,易出意外**) |
| `自连接` | 不是关键字,指同一张表和自己 JOIN(如"员工表找上级") |

> 全部见 [[postgresql/01-入门阶段-基础教程/第05章-查询核心/5.4-多表连接JOIN]]。

## 五、约束类关键字 ⭐

| 关键字 | 一句话解释 |
|--------|-----------|
| `CONSTRAINT 名字` 🔒 | 给约束起个名字(便于以后精确修改/删除)。**强烈建议显式命名** |
| `PRIMARY KEY` 🔒 | 主键:唯一 + 非空,一行一个"身份证号" |
| `UNIQUE` 🔒 | 唯一:这一列(或这几列)的值不能重复 |
| `NOT NULL` 🔒 | 必填:不能为空 |
| `CHECK (...)` 🔒 | 自定义规则:`CHECK (price >= 0)` |
| `FOREIGN KEY` / `REFERENCES` 🔒 | 外键:这一列的值必须存在于另一张表的某行 |
| `ON DELETE` / `ON UPDATE` 🔒 | 被引用的行被删/改时怎么办。后接动作见下 |
| `CASCADE` 🔒 | 连带删除/更新子行 |
| `RESTRICT` 🔒 | 立即拒绝操作 |
| `NO ACTION` 🔒 | 拒绝,但可推迟到语句/事务结束时检查 |
| `SET NULL` / `SET DEFAULT` 🔒 | 把子行的外键列置为 NULL / 默认值 |
| `EXCLUDE USING gist (...)` 🔒 | 排他约束:保证任意两行不满足指定关系(如"时间区间不重叠") |
| `NOT VALID` 🔒 | 加约束但先不校验存量数据(大表加约束的提速手段) |
| `VALIDATE CONSTRAINT` 🔒 | 补做那份校验 |
| `DEFERRABLE INITIALLY DEFERRED` 🔒 | 把检查推迟到事务提交时 |
| `UNIQUE NULLS NOT DISTINCT` 🔒 | 让唯一约束把多个 NULL 也视为重复(PG15+) |
| `REPLICA IDENTITY` 🔒 | 逻辑复制时用什么标识"改的是哪一行" |
| `MATCHED` 🔒 | `MERGE` 语句里表示"与已有行匹配上了"(`WHEN MATCHED`) |
| `CONSTRAINTS` 🔒 | "约束"的复数形式,出现在 `\d` 的输出标题和部分语句里 |
| `ALL TABLES IN SCHEMA 模式名` 🔒 | 授权时的批量写法:对该模式下**所有表**一次性授权 |
| `SEQUENCE` / `SEQUENCES` 🔒 | 序列对象。授权时要写成 `ON SEQUENCES`,否则自增列无法使用 |

> 全部见 [[postgresql/01-入门阶段-基础教程/第03章-建表与约束/3.2-约束体系与数据完整性]]。

## 六、事务类关键字 ⭐

| 关键字 | 一句话解释 |
|--------|-----------|
| `BEGIN` / `START TRANSACTION` 🔒 | 开始一个事务:**从这里到 COMMIT 之间的所有操作是一个整体** |
| `COMMIT` 🔒 | 提交:确认这一组操作生效 |
| `ROLLBACK` 🔒 | 回滚:撤销这一组操作,像什么都没发生 |
| `SAVEPOINT 名字` 🔒 | 在事务内设一个存档点,可以只回滚到它 |
| `ROLLBACK TO SAVEPOINT 名字` 🔒 | 回滚到某个存档点(之前的操作保留) |
| `RELEASE SAVEPOINT` 🔒 | 释放存档点 |
| `SET TRANSACTION` 🔒 | 设置事务属性(如隔离级别) |
| `ISOLATION LEVEL` 🔒 | 隔离级别:并发事务之间能互相看到多少 |
| `READ COMMITTED` 🔒 | 隔离级别之一:每条语句看到最新已提交数据(**PostgreSQL 默认**) |
| `REPEATABLE READ` 🔒 | 隔离级别:整个事务看到同一个快照 |
| `SERIALIZABLE` 🔒 | 隔离级别:最高的,等价于串行执行;冲突时会报错要求重试 |
| `READ ONLY` 🔒 | 只读事务,不允许写入 |
| `SET LOCAL` 🔒 | 只在当前**事务**内生效的设置 |
| `AUTOCOMMIT` | psql 客户端概念:每条语句自动提交(默认开着) |
| `READ WRITE` / `READ ONLY` 🔒 | 事务是"可写"还是"只读" |
| `PREPARE 名字(参数) AS ...` 🔒 | 预编译一条语句,之后可以带参数反复执行 |
| `EXECUTE 名字(参数)` 🔒 | 执行前面 `PREPARE` 好的语句 |
| `PREPARED` 🔒 | "两阶段提交"相关:如 `max_prepared_transactions`。**入门阶段用不到** |
| `SERIALIZABLE` 相关:`40001` | 可串行化冲突的**错误码**,应用捕获到它应重试整个事务 |

> 全部见 [[postgresql/01-入门阶段-基础教程/第06章-事务与权限入门/6.1-事务基础]]。

| **autovacuum** 🐘 | 自动的 VACUUM,后台默默进行 | 进阶 |

| **HOT update** 🐘 | 更新时如果能不走索引维护,会更快(一种优化) | 进阶 |

| **fork** 🐘 | 一个表对应的几种文件(main / fsm / vm / init) | 进阶 |
| **OID** 🐘 | 对象标识号,数据库内部给每个对象发的编号 | 进阶(看系统表时) |

| **逻辑复制 / 物理复制** 🐘 | 两种复制方式:传行级变更 vs 传物理日志 | 中段 |

## 十三、系统列(每张表都偷偷有的列)🐘

**每一张表都自带这些列,不用定义就能查**。入门阶段可以先不看,看到 `xmin`/`ctid` 时回来查。

| 系统列 | 含义 |
|--------|------|
| `tableoid` | 这一行属于哪张表(分区表里用来区分来自哪个分区) |
| `xmin` | **创建**这一行版本的事务号 |
| `xmax` | **删除/更新掉**这一行版本的事务号;`0` 表示这一行仍然有效 |
| `cmin` / `cmax` | 同一事务内的命令序号 |
| `ctid` | 这一行版本在物理文件中的位置,形如 `(0,1)` = 第 0 页第 1 个槽位 |

|------|-----------|
| `shared_buffers` | 数据库自己用的内存缓存大小 |
| `work_mem` | **每个**排序/哈希操作可用的内存;**是"每操作"不是"每连接"** |
| `maintenance_work_mem` | VACUUM、建索引这类维护操作可用的内存 |
| `effective_cache_size` | **不是分配内存**,只是告诉规划器"系统大概能缓存多少" |
| `max_connections` | 最大连接数。太高反而降低性能,高并发要用连接池 |
| `wal_level` | 日志详细程度:`minimal` / `replica`(默认) / `logical` |
| `max_wal_size` | 日志累积到多少触发检查点 |
| `checkpoint_timeout` | 检查点最长间隔时间 |
| `synchronous_commit` | 提交时是否强制等日志落盘。改 `off` 更快但有丢数据窗口 |
| `random_page_cost` | 规划器认为"随机读一页"的相对代价。**SSD 上应调低** |
| `seq_page_cost` | 顺序读一页的代价(基准值 1.0) |
| `default_statistics_target` | 统计信息采样精度 |
| `autovacuum` | 是否开启自动清理(默认开,**不要关**) |
| `autovacuum_vacuum_scale_factor` | 死行占比到多少触发自动清理 |
| `log_min_duration_statement` | 超过多少毫秒的语句记进日志 |
| `track_io_timing` | 是否采集 IO 耗时(`on` 后 `EXPLAIN BUFFERS` 才有耗时) |
| `search_path` | 没写模式名时的查找顺序 |
| `timezone` | 会话时区 |
| `statement_timeout` | 单条语句超时时间 |
| `idle_in_transaction_session_timeout` | 空闲事务超时后自动断开(**强烈建议设置**) |
| `io_method` 🐘 | (PG18+) 异步 IO 方式:`sync` / `worker`(默认) / `io_uring` |
| `password_encryption` | 密码加密方式,应为 `scram-sha-256` |

## 十六、报错信息里的常见词

看懂这些词,报错就懂一半。

| 词 | 含义 |
|----|------|
| `ERROR` / `FATAL` / `WARNING` / `NOTICE` / `HINT` / `DETAIL` | 错误 / 致命错误 / 警告 / 提示 / 建议 / 详情 |
| `syntax error` | 语法错误——拼写或标点有问题 |
| `does not exist` / `unknown` | 找不到这个对象或名字 |
| `relation` | 表 / 索引 / 视图这类对象的统称 |
| `constraint violation` | 违反了某条约束 |
| `not-null constraint` | 必填列没给值 |
| `unique constraint` / `duplicate key` | 唯一约束冲突,值重复了 |
| `foreign key constraint` | 外键约束:引用的行不存在,或正在被引用 |
| `check constraint` | CHECK 规则不满足 |
| `invalid input syntax for type X` | 值的格式和类型 X 不匹配 |
| `permission denied` | 没有权限 |
| `must appear in the GROUP BY clause` | 分组查询里带了没分组的列 |
| `ambiguous` | 有歧义:同名列来自多张表,必须写清是哪张表的 |
| `canceling statement due to ...` | 语句被取消(超时或人工取消) |
| `could not serialize access` | 可串行化冲突,需**重试整个事务**(SQLSTATE 40001) |
| `deadlock detected` | 死锁:互相等对方持有的锁 |
| `out of range` | 数值超出该类型范围 |
| `unterminated` | 引号或括号没配対 |

全文排查方法见 [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]]。

## 十七、命名约定(强烈建议遵守)

| 对象 | 约定 | 例子 |
|------|------|------|
| 表名 | 复数、小写、下划线分词 | `users`、`order_items` |
| 列名 | 小写、下划线分词 | `created_at`、`user_id` |
| 主键列 | 统一叫 `id` | `id` |
| 外键列 | `被引用表单数_id` | `user_id` |
| 约束名 | `表名_列名_类型缩写` | `users_email_uk`、`orders_user_fk` |
| 索引名 | `表名_列名_idx` | `orders_created_idx` |
| 关键字 | **全大写** | `SELECT`、`WHERE` |
| 本地变量/临时名 | 小写 | `total` |

**核心原则:标识符一律小写 + 下划线**,这样永远不需要双引号,也不会因为大小写踩坑。

```
               -- 这是 psql 元命令吗?全部列出来
```

```sql
-- 这是关键字吗?查保留字清单
SELECT word, catcode, catdesc FROM pg_get_keywords()
WHERE word = 'user';

SELECT name, setting, short_desc FROM pg_settings
```
