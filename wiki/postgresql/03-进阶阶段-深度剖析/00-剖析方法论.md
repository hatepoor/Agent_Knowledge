# 进阶阶段 · 剖析方法论

> ⚠️ **阅读门槛提醒**:本阶段讲的是数据库**内部实现**(页结构、事务号、日志、锁)。这里会出现大量你在入门阶段没见过的名词——`xmin`、`ctid`、`pd_lsn`、`LSN`、`relkind`、`opclass`……
>
> **这些名词在本阶段会被逐个解释**,但前提是你已经**能独立写业务 SQL**。
> **如果你还没学完入门阶段(第 00–06 章),读到这里看不懂是正常的,请先回到入门阶段。**
> 遇到不认识的名词可以查 [[postgresql/术语与关键字手册]],函数查 [[postgresql/函数手册]]。

> **组织范式:分层剖析式。** 本阶段与中段阶段的根本差异在于:**中段按"问题域"组织,进阶按"内核模块"组织**。
>
> 这样做的理由是:一个"UPDATE 变慢了"的现象,可能同时牵涉**页结构、MVCC、索引、WAL** 四个层次。按问题域切分会割裂因果链;按内核模块切分,才能逐层下钻、定位真正的瓶颈。

## 一、统一文档模板

本阶段每篇文档遵循固定六段结构。这不是形式,而是**保证"从现象到根因"的推理链完整**。

| 段落 | 回答的问题 | 为什么需要 |
|------|-----------|-----------|
| **① 现象** | 什么样的可观测症状会让人来查这一层? | 建立"何时该读这篇"的索引 |
| **② 机制** | 内核是怎么实现的? | 解释"为什么是这个行为" |
| **③ 数据结构** | 关键结构体/页面布局/磁盘格式长什么样 | 把抽象机制落到可验证的实体 |
| **④ 源码路径** | 相关代码在哪个文件、哪个函数 | 让"继续深挖"有明确入口 |
| **⑤ 实验验证** | 用一条 SQL / 一个扩展把机制**看见** | 把知识变成可复现的观察 |
| **⑥ 生产启示** | 这个机制导致哪些运维与调优结论 | 回到工程价值 |

> **关键原则**:每篇都必须有**可执行的验证手段**。只看描述会形成"以为懂了"的错觉;"看见"了字段值变化,才算真的理解。

## 二、九个内核模块与依赖关系

```
        ┌──────────────────────────────────────────────────┐
        │  进程与内存架构  ← 一切的地基,先读这一层         │
        └───────────────┬──────────────────────────────────┘
                        │
        ┌───────────────▼──────────────┐
        │  存储引擎与页结构             │
        │  (堆表 / 页 / TOAST / 行版本) │
        └───────────────┬──────────────┘
                        │
        ┌───────────────▼──────────────┐   ┌─────────────────┐
        │  事务与 MVCC 内核             │◄──┤  并发控制与锁    │
        │  (快照 / 可见性 / 事务状态)   │   │  (锁管理器/SSI)  │
        └───────┬───────────────┬──────┘   └─────────────────┘
                │               │
        ┌───────▼──────┐  ┌─────▼──────────┐
        │  索引内核     │  │  查询优化器     │
        │  (BTree/GIN)  │  │  (代价/统计)    │
        └───────────────┘  └────────────────┘
                │               │
        ┌───────▼───────────────▼──────┐
        │  WAL 与崩溃恢复               │
        │  (WAL / Checkpoint / 恢复)    │
        └───────────────┬──────────────┘
                        │
        ┌───────────────▼──────────────┐
        │  复制与高可用内核             │
        │  (流复制 / 逻辑解码)          │
        └───────────────┬──────────────┘
                        │
        ┌───────────────▼──────────────┐
        │  扩展与内核开发               │
        │  (扩展框架 / FDW / Hook)      │
        └──────────────────────────────┘
```

**推荐顺序**:进程与内存 → 存储引擎 → MVCC → 索引 / 优化器 → WAL → 锁 → 复制 → 扩展。
但从**排障**角度,顺序应反过来:**先看现象在哪一层**(性能 → 索引/优化器 → 存储行版本;并发 → 锁/MVCC;持久性 → WAL/复制)。

## 四、必备工具箱

**内置观测能力**

| 工具 | 用途 |
|------|------|
| `pageinspect` 扩展 | 直接读页的二进制内容(页头、行指针、元组头) |
| `pgstattuple` / `pgstatindex` | 表的死元组比例、索引结构统计 |
| `pg_buffercache` | 看共享缓冲区里有哪些页 |
| `pg_freespacemap` | 看页的空闲空间分布 |
| `pg_visibility` | 看可见性映射(VM)内容 |
| `pg_walinspect` / `pg_waldump` | 查看 WAL 记录内容 |
| `pg_prewarm` | 预热缓存 |
| `amcheck` | 校验索引结构完整性 |
| `pg_controldata` | 读控制文件(检查点位置、WAL 状态) |
| `pg_ctl` / `pg_resetwal` | 实例级操作 |

## 五、源码阅读方法

1. **从结构体定义入手**,而不是从函数实现。结构体决定了机制的可能性空间。
   - 页头:`src/include/storage/bufpage.h`
   - 元组头:`src/include/access/htup_details.h`
   - 快照:`src/include/utils/snapshot.h`
   - B-tree 页:`src/include/access/nbtree.h`
2. **顺着一个具体操作追调用链**,例如 `INSERT` → `heap_insert` → `RelationGetBufferForTuple` → `PageAddItem`。
3. **用 `pageinspect` 把结构体字段与磁盘字节对应起来** —— 这是本阶段最有价值的练习。
4. 术语对照:文档中的 `tuple` = 行版本,`relation` = 表/索引,`fork` = 数据文件的分支(main/fsm/vm/init)。

## 六、学习纪律

- **不要试图一次读完源码**。按模块逐层推进,每层都要有实验支撑。
- **每篇至少做一次实验**。看到 `pd_lsn` 变化、看到 `xmin`/`xmax` 的值、看到 `ctid` 移动 —— 这些具体的数字比任何描述都有说服力。
- **遇到与自己认知冲突的地方,以实验为准**。版本差异很大,旧文章经常过时。
