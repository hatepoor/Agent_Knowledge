# 实验验证 · 物理布局观测

> 本篇是一套**完整可执行的实验脚本集**,把前两篇的机制"看见"。建议在一个**可随时销毁**的 Docker 实例上逐步执行。
> 所有实验都遵循同一模式:**构造数据 → 观测结构 → 改变操作 → 再观测 → 对比解释**。

## 实验准备

```sql
-- 环境:PostgreSQL 16/17/18 均可
CREATE EXTENSION IF NOT EXISTS pageinspect;
CREATE EXTENSION IF NOT EXISTS pgstattuple;
CREATE EXTENSION IF NOT EXISTS pg_buffercache;
CREATE EXTENSION IF NOT EXISTS pg_visibility;
CREATE EXTENSION IF NOT EXISTS amcheck;

SHOW block_size;        -- 应为 8192
SHOW server_version;
```

**辅助视图(建议先建好,后续反复使用)**

```sql
-- 页头摘要
CREATE OR REPLACE VIEW v_page_header AS
SELECT
    (SELECT count(*) FROM generate_series(1,1)) AS _,
    h.*
FROM page_header(get_raw_page('orders', 0)) h;

-- 更通用:用函数封装
CREATE OR REPLACE FUNCTION show_page_head(p_table regclass, p_blk int DEFAULT 0)
RETURNS TABLE(lsn pg_lsn, lower_i int, upper_i int, free_space int, pagesize int)
LANGUAGE sql AS $$
    SELECT (h).lsn, (h).lower, (h).upper, (h).upper - (h).lower, (h).pagesize
    FROM (SELECT page_header(get_raw_page(p_table, p_blk)) AS h) s;
$$;

SELECT * FROM show_page_head('pg_class', 0);
```

## 实验一:页头字段与空闲空间的动态变化

**目标**:直接看到 `pd_lower` 上升、`pd_upper` 下降、空闲空间收缩。

```sql
DROP TABLE IF EXISTS exp1;
CREATE TABLE exp1 (id int, v text);
INSERT INTO exp1 VALUES (1, 'a');

SELECT * FROM show_page_head('exp1', 0);
-- 记录:lower ≈ 28~32,upper ≈ 8160,free_space ≈ 8130

-- 连续插入,观察变化
DO $$
BEGIN
    FOR i IN 2..200 LOOP
        INSERT INTO exp1 VALUES (i, 'v' || i);
    END LOOP;
END $$;

SELECT * FROM show_page_head('exp1', 0);
-- lower 增大(行指针多了),upper 减小(元组数据多了),free_space 显著减小

-- 看每页的元组分布
SELECT count(*) AS tuples_in_pages, count(DISTINCT blkno) AS pages_used
FROM (
    SELECT blkno, lp FROM generate_series(0, 100) AS blkno,
         LATERAL heap_page_items(get_raw_page('exp1', blkno)) AS t(lp)
) s;
```

**结论**:空闲空间是 `upper - lower`,在页内部管理,**不归还 OS**。

## 实验二:行指针与元组头(ItemIdData / HeapTupleHeader)

**目标**:把索引引用的"槽位"与元组头字段对应起来。

```sql
DROP TABLE IF EXISTS exp2;
CREATE TABLE exp2 (id int, v text);
INSERT INTO exp2 VALUES (1, 'a'), (2, 'b');

SELECT
    lp,                          -- 槽位号(即 ctid 的第二部分)
    lp_off,                      -- 元组在页内偏移
    lp_flags,                    -- 0=UNUSED 1=NORMAL 2=REDIRECT 3=DEAD
    lp_len,                      -- 元组长度
    t_xmin, t_xmax,              -- 创建/失效事务
    t_ctid,                      -- 指向最新版本
    t_infomask,
    t_data                       -- 原始字节
FROM heap_page_items(get_raw_page('exp2', 0));
```

**验证 ctid 与槽位的对应**:

```sql
SELECT ctid, xmin, xmax, * FROM exp2;
-- ctid 形如 (0,1)、(0,2) —— 第 0 页的第 1、2 个槽位
-- 与上面 heap_page_items 的 lp 字段一一对应
```

## 实验三:UPDATE 产生的版本链

**目标**:看到"标记旧版本 + 追加新版本",并观察 HOT 更新。

```sql
DROP TABLE IF EXISTS exp3;
CREATE TABLE exp3 (id int PRIMARY KEY, v text);
INSERT INTO exp3 VALUES (1, 'a');

-- 更新一个"未被索引的列"(v) → 应触发 HOT 更新
UPDATE exp3 SET v = 'b' WHERE id = 1;
UPDATE exp3 SET v = 'c' WHERE id = 1;

-- 看页内所有版本
SELECT lp, lp_off, lp_flags, lp_len, t_xmin, t_xmax, t_ctid
FROM heap_page_items(get_raw_page('exp3', 0))
ORDER BY lp;
```

**预期**:出现 3 个元组条目。

| 版本 | 特征 |
|------|------|
| 第 1 个 | `t_xmax` = 第 2 个事务的 xid(已被标记失效) |
| 第 2 个 | `t_xmax` = 第 3 个事务的 xid |
| 第 3 个 | `t_xmax = 0`(当前有效版本) |

`t_ctid` 指向上一个版本 → 形成**版本链**。

**验证 HOT 更新**:

```sql
-- 对比:更新"被索引的列"(id 是主键)
DROP TABLE IF EXISTS exp3b;
CREATE TABLE exp3b (id int PRIMARY KEY, v text);
INSERT INTO exp3b VALUES (1, 'a');
UPDATE exp3b SET id = 1, v = 'b' WHERE id = 1;   -- 只改 v → HOT

SELECT n_tup_upd, n_tup_hot_upd
FROM pg_stat_user_tables WHERE relname = 'exp3b';
-- hot_pct 应为 100%(只改未索引列)

UPDATE exp3b SET id = 2 WHERE id = 1;            -- 改索引列 → 非 HOT
SELECT n_tup_upd, n_tup_hot_upd FROM pg_stat_user_tables WHERE relname = 'exp3b';
-- hot_upd 未增加
```

## 实验四:验证可见性——xmin/xmax 与 VACUUM

**目标**:看到死元组从"存在"到"被回收"。

```sql
DROP TABLE IF EXISTS exp4;
CREATE TABLE exp4 (id int, v text);
INSERT INTO exp4 SELECT g, 'v' || g FROM generate_series(1, 1000) g;
VACUUM ANALYZE;

SELECT pg_size_pretty(pg_relation_size('exp4')) AS size_before,
       n_live_tup, n_dead_tup
FROM pg_stat_user_tables WHERE relname = 'exp4';

-- 全表更新两次
UPDATE exp4 SET v = v || '!';
UPDATE exp4 SET v = v || '!';

SELECT pg_size_pretty(pg_relation_size('exp4')) AS size_after_update,
       n_live_tup, n_dead_tup
FROM pg_stat_user_tables WHERE relname = 'exp4';
-- size 明显变大,n_dead_tup ≈ 2000

-- 用 pgstattuple 精确定量
SELECT * FROM pgstattuple('exp4');
-- 关注 dead_tuple_count / dead_tuple_percent / free_percent

-- VACUUM 后
VACUUM exp4;
SELECT pg_size_pretty(pg_relation_size('exp4')) AS size_after_vacuum,
       n_dead_tup FROM pg_stat_user_tables WHERE relname = 'exp4';
-- n_dead_tup 降为 0,但 size 不变!(空间仅标记为可复用)

-- VACUUM FULL 后
VACUUM FULL exp4;
SELECT pg_size_pretty(pg_relation_size('exp4')) AS size_after_full;
-- 这次文件真正缩小
```

**这是理解"膨胀"与"VACUUM vs VACUUM FULL"最直接的实验。**

## 实验五:可见性映射(VM)与 Index Only Scan

**目标**:看到"干净 VM"让仅索引扫描免回表。

```sql
DROP TABLE IF EXISTS exp5;
CREATE TABLE exp5 (id int, v text);
INSERT INTO exp5 SELECT g, repeat('x', 50) FROM generate_series(1, 100000) g;
CREATE INDEX exp5_id_idx ON exp5 (id);
ANALYZE exp5;

-- 未 VACUUM:VM 全为 0
SELECT count(*) FILTER (WHERE all_visible) AS all_visible_pages,
       count(*) AS total_pages
FROM pg_visibility_map('exp5');

-- 查询:注意 Heap Fetches
EXPLAIN (ANALYZE, BUFFERS) SELECT id FROM exp5 WHERE id < 100;
-- "Heap Fetches: 99"  ← 仍需回表确认可见性

VACUUM exp5;

SELECT count(*) FILTER (WHERE all_visible) AS all_visible_pages,
       count(*) AS total_pages
FROM pg_visibility_map('exp5');
-- 大部分页变为 all_visible

EXPLAIN (ANALYZE, BUFFERS) SELECT id FROM exp5 WHERE id < 100;
-- "Heap Fetches: 0"  ← 免回表!真正走了 Index Only Scan
```

**结论**:`VACUUM` 不只是回收空间,还通过 VM 让仅索引扫描真正生效。

## 实验六:TOAST 的空间归属

**目标**:看到"主表小、TOAST 表大"。

```sql
DROP TABLE IF EXISTS exp6;
CREATE TABLE exp6 (id int, body text);

-- 小数据
INSERT INTO exp6 SELECT g, repeat('y', 500) FROM generate_series(1, 500);
VACUUM ANALYZE;
SELECT pg_size_pretty(pg_relation_size('exp6'))        AS main,
       pg_size_pretty(pg_relation_size((SELECT reltoastrelid FROM pg_class WHERE relname='exp6'))) AS toast,
       pg_size_pretty(pg_total_relation_size('exp6'))  AS total;

-- 大数据
DELETE FROM exp6;
INSERT INTO exp6 SELECT g, repeat('y', 50000) FROM generate_series(1, 500);
VACUUM ANALYZE;
SELECT pg_size_pretty(pg_relation_size('exp6'))        AS main,
       pg_size_pretty(pg_relation_size((SELECT reltoastrelid FROM pg_class WHERE relname='exp6'))) AS toast,
       pg_size_pretty(pg_total_relation_size('exp6'))  AS total;
-- main 几乎不变,toast 巨大
```

**验证外置后的元组长度**:

```sql
SELECT lp, lp_len FROM heap_page_items(get_raw_page('exp6', 0)) LIMIT 3;
-- lp_len 很小,尽管 body 有 50000 字节
```

## 实验七:共享缓冲区观测

**目标**:看到哪些表被缓存、热度如何。

```sql
-- 先清缓存(重启实例)
-- docker restart pg18

SELECT count(*) FILTER (WHERE relname IS NOT NULL) AS used_buffers,
       count(*) FILTER (WHERE relname IS NULL)     AS free_buffers
FROM pg_buffercache b
LEFT JOIN pg_class c ON b.relfilenode = pg_relation_filenode(c.oid);

-- 全表扫描一个大表
SELECT count(*) FROM exp5;

-- 再看缓存分布
SELECT c.relname, count(*) AS buffers,
       pg_size_pretty(count(*)::bigint * 8192) AS cached,
       round(avg(b.usagecount),2) AS avg_usage
FROM pg_buffercache b
JOIN pg_class c ON b.relfilenode = pg_relation_filenode(c.oid)
WHERE b.reldatabase = (SELECT oid FROM pg_database WHERE datname = current_database())
GROUP BY 1 ORDER BY buffers DESC LIMIT 5;
```

**观察 `usagecount`**:反复访问的页计数升高(上限 5),是"时钟扫描"的体现。

## 实验八:索引结构校验(amcheck)

```sql
-- 校验 B-tree 索引的完整性
SELECT bt_index_check('exp5_id_idx'::regclass);
-- 无输出即通过

-- 更严格:同时校验与堆表的一致性(PG12+)
SELECT bt_index_parent_check('exp5_id_idx'::regclass, heapallindexed => true, rootdescend => true);

-- 索引体积统计
SELECT * FROM pgstatindex('exp5_id_idx');
-- 关注:level(树高)、leaf_pages、internal_pages、avg_leaf_density、root_blkno
```

## 实验九:表膨胀的量化与修复

```sql
-- 造一个膨胀表
DROP TABLE IF EXISTS exp9;
CREATE TABLE exp9 AS SELECT g AS id, repeat('p', 200) AS pad FROM generate_series(1, 300000) g;
CREATE INDEX exp9_id_idx ON exp9 (id);
VACUUM ANALYZE;

SELECT pg_size_pretty(pg_total_relation_size('exp9')) AS before_size,
       (SELECT pg_size_pretty(pg_relation_size('exp9_id_idx'))) AS idx_size;

-- 大量更新(制造死元组 + 索引膨胀)
UPDATE exp9 SET pad = pad || '!' WHERE id % 2 = 0;
UPDATE exp9 SET pad = pad || '!' WHERE id % 2 = 0;

SELECT pg_size_pretty(pg_total_relation_size('exp9')) AS after_update_size,
       (SELECT pg_size_pretty(pg_relation_size('exp9_id_idx'))) AS idx_size;

SELECT * FROM pgstattuple('exp9');
SELECT * FROM pgstatindex('exp9_id_idx');
-- 关注 avg_leaf_density 下降(索引页稀疏化)

-- 修复
VACUUM exp9;                              -- 元组空间可复用,但文件不变
REINDEX INDEX exp9_id_idx;                -- 索引重建,密度恢复
VACUUM FULL exp9;                         -- 表重写
SELECT pg_size_pretty(pg_total_relation_size('exp9')) AS after_repair;
```

## 实验十:观察 hint bits 让只读查询也产生脏页

```sql
SELECT pg_current_wal_lsn() AS lsn0 \gset

-- 第一次读(会设置 hint bits,产生脏页)
SELECT sum(id) FROM exp9;

SELECT pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), :'lsn0')::bigint) AS wal_from_select;
```

> 若结果非 0(或有脏页出现),说明只读查询通过设置 hint bits 修改了页。这是"只读查询也可能写 WAL"的直接证据(设置了 hint bits 需要写入 WAL,以保证崩溃后重放一致)。

## 观测速查表

| 想观测 | 用什么 |
|--------|--------|
| 页头字段 | `page_header(get_raw_page(t, blk))` |
| 元组头/行指针 | `heap_page_items(get_raw_page(t, blk))` |
| 表的死元组比例 | `pgstattuple('t')` |
| 索引结构统计 | `pgstatindex('idx')` |
| 索引完整性 | `bt_index_check('idx')` / `bt_index_parent_check` |
| VM 内容 | `pg_visibility_map('t')` |
| FSM 内容 | `pg_freespacemap` 扩展 |
| 缓冲区内容 | `pg_buffercache` |
| 页空位分布 | `pg_freespace('t')` |
| 表各 fork 大小 | `pg_relation_size(t, 'main'/'fsm'/'vm')` |
| 表文件路径 | `pg_relation_filepath('t')` |
| WAL 内容 | `pg_walinspect` / `pg_waldump` |
