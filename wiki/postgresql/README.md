# PostgreSQL 学习知识库

> 本目录是一套**按学习路径三阶段组织**的 PostgreSQL 学习资料。三个阶段采用**三种不同**的文件组织范式,分别服务于「建立基本盘」「横向打通能力面」「纵向理解内核」三类学习目标。

## 〇、从这里开始(零基础请先读这一段)

**本套文档的定位:带你从零基础学到"能独立写业务 SQL"。**

**不假设你认识任何名词、任何关键字、任何函数。** 遇到不认识的东西时,按下表找到对应入口——**不要硬啃,也不要以为自己漏学了什么**。

| 你遇到的情况 | 去哪里查 |
|--------------|----------|
| 完全没接触过数据库,不知道从哪开始 | [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.1-数据库与SQL是什么]] |
| 不认识某个**名词或关键字**(如 `CONSTRAINT`、`relation`、`xmin`、`oid`) | [[postgresql/术语与关键字手册]] |
| 不认识某个**函数**(如 `width_bucket`、`jsonb_path_query`) | [[postgresql/函数手册]] |
| 看不懂**报错信息** | [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]] |
| 某页读不下去 | 先看该页开头的「本篇读法」提示;再检查该页「前置知识」列的几篇是否读过 |

**三条阅读原则**

1. **零基础从第 00 章开始,按章节序号推进。** 入门阶段的知识是**线性依赖**的——先懂数据类型才能建表,先有表才能增删改查。跳读一定会卡。
2. **每页开头的「前置知识」是必读清单**,不是参考建议。读不懂某页,绝大多数情况是前置没读。
3. **读不懂不一定是你的问题。** 如果你发现有名词、关键字、函数被"用了却没讲",这是本套文档明确要避免的缺陷——**请直接指出,会立即补齐**。

**关于难度**:本套文档有三个阶段,难度差别很大。

| 阶段 | 面向 | 看不懂时怎么办 |
|------|------|----------------|
| 入门 | 零基础 → 能写业务 SQL | 应从第 00 章顺序读 |
| 中段 | 已有基础 → 会选型、会调优 | 属于平行专题,可只挑需要的看 |
| 进阶 | 面向内核原理(存储、事务、索引机制) | **入门没学完不要看进阶**,看不懂是正常的 |

> **重要**:进阶阶段的内容(如 `xmin`、页结构、WAL、MVCC 的实现)是为"已经能写 SQL、想理解原理"的人准备的。**如果你现在看不懂它们,说明你还没到那个阶段,而不是内容有问题。**

## 三、为什么三个阶段要"换一种组织方式"

这不是形式主义,而是因为三类知识的结构本身不同:

1. **入门知识是线性的**——数据类型讲完才能讲建表,建表讲完才能讲 CRUD。所以用**带序号的章节**强化学科顺序。
2. **中段知识是网状的**——窗口函数和 JSON 没有先后依赖,它们各自回答"某类需求该用什么工具"。所以用**平行专题**,每篇自包含,可跳读。
3. **进阶知识是分层递归的**——一个"UPDATE 变慢了"的现象,可能同时牵涉页结构、MVCC、索引、WAL 四层。所以按**内核模块分层**,每篇都从"现象"下沉到"机制",再回到生产。

## 四、如何使用

1. **零基础:从第 00 章开始** —— [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.1-数据库与SQL是什么]]。第 00 章不要求任何前置知识,只解决"能连上、能敲语句、能看懂报错"。
2. **先读** [[postgresql/学习路线图]] —— 确定自己当前所处阶段与下一目标。
3. **按阶段推进** —— 入门阶段**必须按章节顺序**;中段阶段按需抽取;进阶阶段按"遇到的现象"倒查。
4. **卡住时查三处** —— 不认识**名词/关键字**查 [[postgresql/术语与关键字手册]];不认识**函数**查 [[postgresql/函数手册]];看不懂**报错**查 [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]]。
5. **动手优先** —— 每篇末的练习/实验都要在真实实例上跑一遍。仅阅读无法形成能力。
