# 0.3 动手:跑通你的第一条语句

## 学习目标

读完并跟着做完这一篇,你应该能:

- 拥有一个可以随便折腾、随时删掉重来的 PostgreSQL 实例
- 用 `psql` 连上它、执行 SQL、看结果、退出
- 独立走完"建库 → 建表 → 插数据 → 查 → 改 → 删"全流程

**这一篇是纯动手的。请打开终端跟着敲,不要只读。**

## 前置知识

## 一、先拿到一个实例(1 分钟)

如果你已经装好 PostgreSQL,可以跳过这一步,直接看第三节。

**推荐用 Docker**,因为最省事,而且**搞坏了删掉重建只要一条命令**——学习阶段这一点非常重要。

打开终端,执行:

```bash
docker run -d --name pglearn \
  -e POSTGRES_PASSWORD=learn123 \
  -p 5432:5432 \
  -v pglearn_data:/var/lib/postgresql/data \
  postgres:18
```

这一行做四件事:

| 参数 | 含义 |
|------|------|
| `--name pglearn` | 给容器起名叫 `pglearn`,后面用它来操作 |
| `-e POSTGRES_PASSWORD=learn123` | 设置超级用户的密码为 `learn123`(**这只是学习用的弱密码**) |
| `-p 5432:5432` | 把容器的 5432 端口映射到你本机的 5432 端口 |
| `-v pglearn_data:/...` | 数据存到名为 `pglearn_data` 的卷里,容器删除数据还在 |

> **这是学习实例,里面不要放任何真实数据。** 密码也请只用在这类一次性环境里。

**验证是否起来了**:

```bash
docker ps                      # 应该看到名为 pglearn 的容器在运行
docker exec pglearn pg_isready # 输出 "accepting connections" 表示就绪
```

**随时删掉重来**(练习搞乱了就执行这两条,再重新 `docker run`):

```bash
docker rm -f pglearn && docker volume rm pglearn_data
```

## 二、连上去

```bash
docker exec -it pglearn psql -U postgres -d postgres
```

拆解这行命令:

| 部分 | 含义 |
|------|------|
| `docker exec -it pglearn` | 进入名为 pglearn 的容器,并分配一个可交互的终端 |
| `psql` | 启动 psql 这个客户端程序 |
| `-U postgres` | 以 `postgres` 这个**角色(用户)** 身份连接 |
| `-d postgres` | 连到名为 `postgres` 的**数据库**(默认就有的一个库) |

连上后你会看到提示符:

```
postgres=#
```

它的含义是:`数据库名=#`,`#` 表示当前是超级用户(普通用户会显示 `>`)。

## 三、第一条语句

在提示符后输入下面这行,**注意结尾的分号**,然后回车:

```sql
SELECT 1;
```

你会看到:

```
 ?column?
----------
        1
(1 row)
```

解读这个输出:

| 部分 | 含义 |
|------|------|
| `?column?` | 这一列没有名字,所以数据库给了个占位名 |
| `1` | 结果值 |
| `(1 row)` | 返回了 1 行 |

**`SELECT` 是最简单的验证手段**:它不需要任何表,可以用来测试"连接是否正常""某个表达式算出来是什么""某个函数怎么用"。

多试几个:

```sql
SELECT 1 + 1;                    -- 算术
SELECT '你好' AS 问候;            -- AS 给结果列起个名字(中文也可以,但不推荐)
SELECT now();                     -- 当前时间
SELECT version();                 -- 数据库版本
```

## 四、完整走一遍:建库 → 建表 → 增删改查

下面每一步都请真实执行。

### 第 1 步:建一个自己的数据库

```sql
CREATE DATABASE learn;
```

**数据库(database)** 是表的容器,一个项目通常用一个库。

查看现在有哪些库:

```
\l
```

> **注意 `\l` 没有分号**。反斜杠开头的是 **psql 元命令**(客户端功能,不是 SQL),它**不需要分号**。这是它和 SQL 语句的重要区别。

### 第 2 步:切换到自己建的库

```sql
\c learn
```

提示符变成 `learn=#`,表示你现在在 `learn` 库里操作。

> **为什么必须切换**:表是建在某个库里的。不切库,表会建在 `postgres` 库里,后面容易找不着。

### 第 3 步:建一张表

```sql
CREATE TABLE users (
    id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email      text NOT NULL,
    name       text,
    vip        boolean NOT NULL DEFAULT false,
    created_at timestamptz NOT NULL DEFAULT now()
);
```

先不用理解每个词。这一句的作用是:**建一张叫 `users` 的表,它有 5 列**,分别规定:

| 列名 | 存什么 | 那一串修饰词的粗略含义 |
|------|--------|----------------------|
| `id` | 整数 | 自动生成序号,并作为行的唯一标识 |
| `email` | 文本 | 必填(不能为空) |
| `name` | 文本 | 可填可不填 |
| `vip` | 真/假 | 必填,不写时默认 `false` |
| `created_at` | 时间点 | 必填,不写时默认取当前时间 |

> **`CREATE TABLE` 的完整语法、以及上面每个修饰词的确切含义,在第 3 章逐个讲。** 这里你先能跑通就行——**看不懂就照着敲,不要卡住**。

**看看表建出来了吗**:

```
\dt
```

输出里应该出现 `public | users`。

**看看表的详细结构**:

```
\d users
```

这条命令会列出列名、类型、以及 `id` 上自动建好的主键。**`\d 表名` 是你以后最常用的命令之一**,记不住某张表有哪些列时就查它。

### 第 4 步:插入数据

```sql
INSERT INTO users (email, name, vip) VALUES
    ('ann@example.com',  '安妮', true),
    ('ben@example.com',  '本',   false),
    ('cara@example.com', '卡拉', false);
```

注意我们**没有提供 `id` 和 `created_at`**——因为它们的默认值会自动填。

确认插进去了:

```sql
SELECT * FROM users;
```

`*` 表示"所有列"。你应该看到 3 行。

### 第 5 步:查询

```sql
-- 只看部分列,并且只看 VIP
SELECT email, name
FROM users
WHERE vip = true;

-- 加个条件:名字叫"本"的那行
SELECT * FROM users WHERE name = '本';
```

`WHERE` 后面写的是**筛选条件**,只有满足条件的行才会被返回。

### 第 6 步:修改

```sql
UPDATE users SET vip = true WHERE name = '本';
```

**这条语句的含义是**:在 `users` 表里,找到 `name` 等于"本"的行,把它的 `vip` 改成 `true`。

再查一次确认:

```sql
SELECT email, name, vip FROM users;
```

> **⚠️ 极其重要:`UPDATE` 后面如果忘了写 `WHERE`,会把整张表的每一行都改掉。**
> `UPDATE users SET vip = true;` —— 一个字的差别,3 行全变 VIP。养成习惯:**先写 `WHERE`,再回头补 `SET`**。

### 第 7 步:删除

```sql
DELETE FROM users WHERE name = '卡拉';
```

同样,**忘了 `WHERE` 就是清空整张表**。

确认:

```sql
SELECT count(*) FROM users;   -- 应该返回 2
```

### 第 8 步:退出

```
\q
```

## 五、卡住时怎么办

| 情况 | 现象 | 怎么办 |
|------|------|--------|
| 忘了写分号 | 提示符从 `=#` 变成 `-#` | 补一个 `;` 回车 |
| 敲错了想取消 | 语句还没结束 | 敲 `\r` 回车(清空当前输入) |
| 想不起来有什么表 | | 敲 `\dt` |
| 想不起来表有哪些列 | | 敲 `\d 表名` |
| 想看能敲哪些反斜杠命令 | | 敲 `\?` |
| 想看 SQL 语法帮助 | | 敲 `\h SELECT` |
| 屏幕上一堆字想清屏 | | 敲 `\! clear` 或直接滚屏 |

**报错信息看不懂**:见 [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]]。

## 小结

- 学习环境用 Docker,一行命令拉起,**删掉重建一条命令**。
- 连上:`docker exec -it pglearn psql -U postgres -d postgres`。
- `SELECT 1;` 是最简单的连通性测试。
- **SQL 语句要分号结尾;`\` 开头的 psql 元命令不要分号。**
- 全流程:`CREATE DATABASE` → `\c` → `CREATE TABLE` → `INSERT` → `SELECT` → `UPDATE` → `DELETE`。
- **`UPDATE` / `DELETE` 忘写 `WHERE` 会波及全表。**
- `\dt` 看表清单,`\d 表名` 看表结构,`\q` 退出。

## 练习

1. 完整走一遍上面的流程。走完后再执行 `\d users`,说出 `id` 列上有哪些修饰词。
2. 故意执行 `SELECT * FROM users`(去掉分号),观察提示符;再补分号。
3. 建一张自己的表(比如 `books`,含书名、作者、出版年三列),插入 3 行,查出所有 2020 年后出版的书。
4. **危险练习**:先执行 `SELECT count(*) FROM users;` 记下数量,再执行不带 `WHERE` 的 `UPDATE users SET vip = true;`,然后 `SELECT count(*) FROM users WHERE vip = true;`。理解 `WHERE` 的作用后,用 `docker rm -f pglearn && docker volume rm pglearn_data` 把环境删掉重来。
