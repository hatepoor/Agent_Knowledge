# 0.1 数据库与 SQL 是什么

## 学习目标

读完这一篇,你应该能回答:

- 数据库比"把数据存成文件"好在哪
- 数据库、表、行、列、字段 这几个词分别指什么
- SQL 是什么,它能做哪几件事
- 什么是"客户端"和"服务端",psql 扮演什么角色

**本篇不需要任何前置知识。**

## 一、为什么不直接把数据存进文件

假设你要做一个记账程序,把账目存进一个文本文件。很快会遇到四个问题:

| 问题 | 说明 |
|------|------|
| **两个人同时写会坏** | A 和 B 同时往文件追加,可能互相覆盖。这叫**并发问题** |
| **查得慢** | 想找"上个月餐饮花了多少",得把整个文件读一遍自己算 |
| **改到一半断电会坏** | 一笔转账只写了"扣款"还没写"入账",数据就不一致了 |
| **谁都能看** | 文件没有权限分层,销售不该看到工资表 |

**数据库(database)** 就是专门解决这四个问题的软件。它把数据管起来,负责:多人同时安全读写、快速查询、断电不丢不乱、按人分配权限。

**PostgreSQL** 是数据库软件中的一种(和 MySQL、Oracle、SQL Server 同类)。本套文档只讲它。

## 二、数据是怎么组织的:库 → 表 → 行 → 列

这是最基础也最必须搞清的一层结构。用"记账"举例:

```
实例 (PostgreSQL 服务,跑在某个端口上)
 │
 └── 数据库 learn                    ← 一个项目 / 一个应用用一个库
      │
      ├── 表 users                    ← 一张表 = 一类东西(这里的"东西"是人)
      │    ┌────────┬──────────────┬────────┬──────────────┐
      │    │ id     │ email        │ name   │ created_at   │  ← 列(字段):表头
      │    ├────────┼──────────────┼────────┼──────────────┤
      │    │ 1      │ a@example.com│ 安妮   │ 2026-09-20   │  ← 行(记录):一条数据
      │    │ 2      │ b@example.com│ 本     │ 2026-09-20   │
      │    └────────┴──────────────┴────────┴──────────────┘
      │
      └── 表 orders                   ← 另一张表 = 另一类东西(订单)
```

| 名词 | 也叫 | 是什么 | 类比 |
|------|------|--------|------|
| **实例** | server | 一个跑起来的 PostgreSQL 服务 | 一栋楼 |
| **数据库** | database | 一批表的集合,通常一个应用一个 | 一个房间 |
| **表** | table | 一类数据的容器,有固定列 | 一张 Excel 工作表 |
| **列** | column / **字段** / field | 表的一竖列,规定"存什么类型的数据" | Excel 的表头 |
| **行** | row / **记录** / record | 表的一横条,是一个具体对象的数据 | Excel 的一行 |
| **值** | value | 某行某列交叉处的具体内容 | Excel 的一个单元格 |

> **注意"字段"和"列"是同一个东西**:你在很多中文资料里会看到"字段",它和"列"完全等价,英文都叫 column。本套文档两个词都会用,看到时不必纠结。

**为什么要有"表"这个概念**:因为同类数据有相同的结构。所有用户都有邮箱和名字,所以可以放在一张表里,用列预先规定"这里只能放字符串""这里只能放时间"。

## 三、SQL 是什么

**SQL** 全称 **Structured Query Language**,中文叫"结构化查询语言"。它是你**命令数据库做事**的语言。

两个关键认知:

### 认知一:SQL 不是编程语言,而是"指令单"

写 Python 时你要描述"怎么一步步做"。写 SQL 时你只描述"我要什么",具体怎么找由数据库自己决定。

```sql
-- 你只说:我要 users 表里所有 VIP 用户的邮箱
SELECT email FROM users WHERE vip = true;
```

你没有说"从第一行开始扫、比较 vip 列、收集 email"。**数据库会自己决定怎么执行最快**。这叫**声明式(declarative)**——这是 SQL 最重要的性格,也是它和普通编程语言最大的区别。

### 认知二:SQL 只管四件事

不管多复杂的 SQL,归根结底就是四类动作,简称 **CRUD**:

| 动作 | 英文 | SQL 命令 | 例子 |
|------|------|----------|------|
| **增** | Create | `INSERT` | 新增一个用户 |
| **查** | Read | `SELECT` | 查所有 VIP 用户 |
| **改** | Update | `UPDATE` | 把某用户标记为 VIP |
| **删** | Delete | `DELETE` | 删除某用户 |

另外还有一类动作是"定义表本身的结构"(建表、改表结构),它不属于操作数据,而属于操作"容器":

| 动作 | 命令 |
|------|------|
| 建表 | `CREATE TABLE` |
| 改表结构 | `ALTER TABLE` |
| 删表 | `DROP TABLE` |

> 这几类命令有专门的缩写名称(`DDL`/`DML` 等),这些缩写不是必须先背的。讲到的章节会现场解释,另可见 [[postgresql/术语与关键字手册]]。

## 四、客户端与服务端:psql 是什么

PostgreSQL 是**服务端软件**——它在后台一直跑着,等着别人来提问。你用的**不是**它本身,而是一个**客户端**去连它。

```
   你的电脑                                
   ┌──────────────────────────┐
   │  客户端(psql / 图形工具 / 你的程序)  │
   └────────────┬─────────────┘
                │  网络连接(默认端口 5432)
                ▼
   ┌──────────────────────────┐
   │  PostgreSQL 服务端        │  ← 一直在后台运行
   │  (负责存储数据、执行 SQL)  │
   └──────────────────────────┘
```

| 名词 | 是什么 | 举例 |
|------|--------|------|
| **服务端** | 后台常驻的数据库程序,真正持有数据 | `postgres` 服务;Docker 容器 |
| **客户端** | 你用来"连上并下命令"的工具 | **`psql`**(命令行)、pgAdmin(图形界面)、你的应用代码 |
| **连接** | 客户端与服务端之间的一条会话 | 一个客户端进程对应服务端一个进程 |

**`psql`** 是 PostgreSQL 官方的命令行客户端。它没有按钮和菜单,你在里面直接敲 SQL 语句。第 0.3 篇会带你用它跑通第一条语句。

> **为什么先学 psql 而不是图形工具**:因为 psql 的命令在任何服务器上都能用(服务器通常没有图形界面),而且它给出的报错信息最完整,对学习最有利。

## 五、三条必须现在记住的书写规则

### 规则一:一条语句以分号结尾

```sql
SELECT 1;
```

**分号是"这句话说完了"的信号。** 在 psql 里忘了写分号,你会看到提示符从 `learn=#` 变成 `learn-#`——它在等你把话说完,并没有报错。补上分号回车即可。

### 规则二:SQL 关键字不区分大小写,但字符串区分

```sql
SELECT email FROM users;   -- 完全可以
select email from users;   -- 也完全可以,作用完全相同
SELECT email FROM users WHERE name = 'Ann';   -- 'Ann' 和 'ann' 不同!
```

**约定**(不是强制,但请照做,否则代码没法和别人交流):

| 内容 | 写法 | 例子 |
|------|------|------|
| **关键字**(数据库预留的词) | **全大写** | `SELECT`、`FROM`、`WHERE`、`CREATE` |
| **标识符**(你自己起的名字) | 全小写,多个词用下划线 | `user_id`、`created_at` |
| **字符串内容** | 单引号,原样保留 | `'Ann'`、`'2026-09-20'` |

> **什么是"关键字"**:`SELECT`、`FROM`、`TABLE` 这类词是数据库**自己留着用的**,有固定含义,你不能拿它当表名或列名。完整的清单见 [[postgresql/术语与关键字手册]]。

### 规则三:注释用两个减号或斜杠星

```sql
-- 这是单行注释,两个减号后面的内容数据库会忽略

/*
   这是多行注释
   可以写好几行
*/
```

注释是写给人看的。本套文档的代码块里大量使用 `--` 注释来逐行解释,这些注释**可以连同 SQL 一起复制粘贴执行**,数据库会自动忽略它们。

## 小结

- 数据库解决四个问题:并发、查询速度、崩溃一致性、权限。
- 结构层次:**实例 → 数据库 → 表 → 行 / 列**;「字段」=「列」。
- SQL 是**声明式**语言:你只说"要什么",不说"怎么做"。
- SQL 的四件事:**增(INSERT)、查(SELECT)、改(UPDATE)、删(DELETE)**。
- PostgreSQL 是服务端;`psql` 是官方命令行客户端。
- 三条书写规则:分号结尾、关键字大写(约定)、注释用 `--`。
