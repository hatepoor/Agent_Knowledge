# 0.5 学前名词与学习地图

## 这一篇怎么用

**读完前四篇之后、正式开始第 1 章之前,读这一篇。**

它做两件事:

1. 把后面会反复出现、但你不可能提前知道的**核心名词**列出来,每个给一句话解释和"详解在哪"。
2. 说明**为什么是这个学习顺序**,以及每一章要解决什么问题。

## 一、核心名词(第一批,约 20 个)

### 结构类

| 名词 | 一句话解释 | 详解 |
|------|-----------|------|
| **实例 / 服务端** | 一个跑起来的 PostgreSQL 服务,负责存数据、执行 SQL | [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.1-数据库与SQL是什么]] |
| **客户端** | 你用来连上数据库的工具,比如 `psql` | 同上 |
| **数据库** | 一批表的容器,通常一个应用用一个 | 同上 |
| **表** | 一类数据的容器,有固定的若干列 | 同上 |
| **行 / 记录** | 表里的一条数据 | 同上 |
| **列 / 字段** | 表的一竖列,规定这一格存什么类型 | 同上 |
| **模式 / schema** | 库内部的命名空间,用来把表分组;默认有一个 `public` | [[postgresql/01-入门阶段-基础教程/第03章-建表与约束/3.1-DDL建表与列定义]] |
| **序列** | 一个"专门用来发号"的计数器,自增列背后就是它 | [[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.1-数值类型]] |

### 语法类

| 名词 | 一句话解释 | 详解 |
|------|-----------|------|
| **关键字** | 数据库预留、有固定含义的词,如 `SELECT`、`WHERE` | [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.2-一条SQL语句的组成]] |
| **标识符** | 你自己起的名字:表名、列名 | 同上 |
| **字面量** | 直接写出来的具体值:`'Ann'`、`42`、`true` | 同上 |
| **运算符** | 表示运算或比较的符号:`=`、`>`、`+`、`AND` | 同上 |
| **表达式** | 能算出一个值的写法,如 `price * 2`、`upper(name)` | [[postgresql/01-入门阶段-基础教程/第04章-基础操作CRUD/4.2-SELECT基础查询]] |
| **别名 / AS** | 给结果列或表临时起个名字 | 同上 |
| **语句** | 一条完整的 SQL,以分号结尾 | [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.2-一条SQL语句的组成]] |

### 数据完整性类

| 名词 | 一句话解释 | 详解 |
|------|-----------|------|
| **类型** | 规定一列只能放哪类值:整数、文本、时间…… | [[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.1-数值类型]] |
| **约束** | 数据库强制执行的规则,如"这一列不能为空" | [[postgresql/01-入门阶段-基础教程/第03章-建表与约束/3.2-约束体系与数据完整性]] |
| **主键** | 能唯一标识每一行的那一列(或几列) | 同上 |
| **外键** | 指向另一张表某一行的"引用",用来保证引用关系有效 | 同上 |
| **默认值** | 不写这一列时自动填入的值 | [[postgresql/01-入门阶段-基础教程/第03章-建表与约束/3.1-DDL建表与列定义]] |
| **NULL** | 表示"这个值不知道 / 不适用",**不是 0 也不是空字符串** | [[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.6-NULL语义与类型转换]] |

### 查询类

| 名词 | 一句话解释 | 详解 |
|------|-----------|------|
| **筛选 / WHERE** | 只保留满足条件的行 | [[postgresql/01-入门阶段-基础教程/第05章-查询核心/5.1-WHERE与运算符]] |
| **排序 / ORDER BY** | 指定结果按什么顺序排列 | [[postgresql/01-入门阶段-基础教程/第05章-查询核心/5.2-ORDER-BY与分页]] |
| **聚合** | 把多行合并成一个值,如求和、计数 | [[postgresql/01-入门阶段-基础教程/第05章-查询核心/5.3-聚合函数与GROUP-BY]] |
| **分组 / GROUP BY** | 先按某列把行分组,再对每组算聚合 | 同上 |
| **连接 / JOIN** | 把两张表按某个对应关系拼到一起查 | [[postgresql/01-入门阶段-基础教程/第05章-查询核心/5.4-多表连接JOIN]] |

### 事务与性能类(**先知道有这回事即可,不必现在懂**)

| 名词 | 一句话解释 | 详解 |
|------|-----------|------|
| **事务** | 一组"要么全成功、要么全不做"的操作 | [[postgresql/01-入门阶段-基础教程/第06章-事务与权限入门/6.1-事务基础]] |
| **索引** | 为了加快查询而额外维护的"目录"。像书的索引,不是必须但有它更快 | [[postgresql/02-中段阶段-专题精讲/索引实战应用/专题概览]] |
| **MVCC** | PostgreSQL 内部让"读和写互不阻塞"的机制 | [[postgresql/03-进阶阶段-深度剖析/事务与MVCC内核/原理剖析-MVCC与快照隔离]] |
| **TOAST** | PostgreSQL 把超大字段单独存到别处的机制 | [[postgresql/03-进阶阶段-深度剖析/存储引擎与页结构/原理剖析-TOAST与行版本]] |
| **VACUUM** | 清理删除/更新后残留空间的维护动作 | [[postgresql/01-入门阶段-基础教程/第04章-基础操作CRUD/4.3-UPDATE与DELETE]] |

> **一句话原则**:**`MVCC`、`TOAST`、`VACUUM`、`索引` 这四个词,在你学完入门阶段之前不需要真正理解。** 看到时知道"这是更后面的内容"就行。入门阶段的正文里如果出现它们,一定是在告诉你"这个以后会讲"。

## 二、学习地图:为什么是这个顺序

入门阶段的学习顺序不是随意的,它是一条**依赖链**——每一步都用得上上一步:

```
0. 学前准备    ← 你现在在这里:知道库表行列、会敲语句、看得懂报错
      │
      ▼
1. 环境与初识   有个能随便折腾的实例,会用 psql 下单、看结构
      │
      ▼
2. 数据类型    知道每列该存什么类型(整数?文本?时间?)   ← 建表的前提
      │
      ▼
3. 建表与约束   把结构定义出来,并把业务规则写进数据库     ← 有表才能存数据
      │
      ▼
4. 基础操作    往表里增、删、改、查                      ← 有了表,开始操作数据
      │
      ▼
5. 查询核心    筛选、排序、聚合、多表连接                ← 从"取出来"到"算出来"
      │
      ▼
6. 事务与权限  多步操作要一致,不同人要有不同权限
```

**每条依赖的理由**

| 顺序 | 为什么不能颠倒 |
|------|----------------|
| 2 → 3 | 建表时必须为每列指定类型,不懂类型就没法建表 |
| 3 → 4 | 没有表,增删改查无从谈起 |
| 4 → 5 | 先会"取出来",才能学"怎么算、怎么拼" |
| 5 → 6 | 事务保证的正是"多条增删改查要么全做要么全不做" |

> **建议顺序学完,不要跳。** 中段和进阶阶段的知识是平行/分层的,可以按需跳读;但入门阶段是线性的,跳了会卡。

## 三、每章学完你能做什么

| 章节 | 学完能做到 | 自测方式 |
|------|-----------|----------|
| 第 0 章 | 连上数据库、执行语句、看懂报错 | 独立走完 0.3 的完整流程 |
| 第 1 章 | 拉起实例、用 psql 浏览库与表 | 不用查资料,说出查看表结构的命令 |
| 第 2 章 | 为每个字段选对类型 | 给出 10 个业务字段,说出各自该用什么类型 |
| 第 3 章 | 独立设计一张表并加上必要约束 | 从零写出一个"订单表"的建表语句 |
| 第 4 章 | 增删改查一次写对,会幂等写入 | 写出"存在则更新、不存在则插入"的语句 |
| 第 5 章 | 写多表关联的统计查询 | 写出"每个用户的订单数与总金额,按金额降序" |
| 第 6 章 | 控制事务边界、授最小权限 | 用事务保证一次转账的两步都成功或都取消 |

**目标定位**:走完入门阶段,你应当能**独立完成后端开发里绝大多数数据库工作**。索引优化、执行计划、复制备份等属于后续阶段。

## 四、看不懂的时候怎么办(三个入口)

本套文档为"看不懂"这件事准备了三个固定的查询入口。**任何时候卡住,先查这三处,不要硬啃。**

| 入口 | 解决什么 | 怎么用 |
|------|----------|--------|
| [[postgresql/术语与关键字手册]] | **不认识的名词、关键字、系统列名** | 按 Ctrl+F 搜那个词 |
| [[postgresql/函数手册]] | **不认识的函数** | 按 Ctrl+F 搜函数名 |
| [[postgresql/01-入门阶段-基础教程/第00章-学前准备/0.4-看懂报错信息]] | **看不懂报错** | 按报错关键词对号入座 |

还有一条兜底:**在 psql 里直接问数据库本身**。

```
\d 表名        -- 这张表有哪些列、什么类型、什么约束
\dt            -- 有哪些表
\df 函数名      -- 这个函数的参数是什么
\h SELECT      -- 这个命令的语法帮助
\?             -- 所有反斜杠命令的清单
```

## 五、给零基础的三条建议

1. **不要试图"读懂每一个词"再往下走。** 入门阶段允许你"暂时不理解,先照着敲通"。第 3.1 篇的建表语句里有六个修饰词,第一次见不需要全懂——**先跑起来,再回头理解**,比卡在原地有效得多。
2. **每个代码块都真的执行一遍。** 数据库是"手上的知识",不是"读会的知识"。看懂 `WHERE` 的定义,和亲手体验"忘写 `WHERE` 把全表改了",学习效果差一个数量级。
3. **报错时先别急着删环境。** 报错信息本身就是最好的教材(见 0.4)。
