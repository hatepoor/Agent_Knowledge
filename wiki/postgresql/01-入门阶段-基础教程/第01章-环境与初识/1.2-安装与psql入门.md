# 1.2 安装与 psql 入门

## 学习目标

- 用 Docker 在 1 分钟内拉起一个可随时重建的实例
- 掌握 psql 的连接方式与高频元命令
- 知道配置文件在哪、连接串怎么写

## 前置知识

[[postgresql/01-入门阶段-基础教程/第01章-环境与初识/1.1-PostgreSQL概览与版本演进]]

## 正文

### 一、用 Docker 拉实例(推荐)

学习环境最重要的是**可重建**。一条命令即可:

```bash
docker run -d --name pg18 \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=learn \
  -p 5432:5432 \
  -v pg18data:/var/lib/postgresql/data \
  postgres:18

# 进入 psql
docker exec -it pg18 psql -U postgres -d learn
```

**重建实例**(练习搞脏了数据时):

```bash
docker rm -f pg18 && docker volume rm pg18data
# 再执行一次上面的 run 命令
```

常用运维命令:

| 命令 | 作用 |
|------|------|
| `docker exec -it pg18 psql -U postgres -d learn` | 进交互式 psql |
| `docker exec pg18 pg_isready` | 探活 |
| `docker logs pg18` | 看启动日志(排查启动失败必看) |
| `docker exec -it pg18 bash` | 进入容器(看数据文件、配置) |

**Windows 原生安装**:官方 Windows 安装包会同时装 `pgAdmin`(图形界面)与 `psql`;也可用 `winget install PostgreSQL.PostgreSQL.18`。学习阶段建议 Docker,因为"删库重来"成本最低。

### 二、连接方式

```bash
# 基础形式
psql -h localhost -p 5432 -U postgres -d learn

# 连接串(URI 形式,应用配置里最常见)
psql "postgresql://postgres:postgres@localhost:5432/learn?sslmode=disable"

# 仅本地 socket 连接(容器内)
psql -U postgres
```

**URI 连接串结构**

```
postgresql://<user>:<password>@<host>:<port>/<dbname>?<param>=<value>
```

常见参数:`sslmode`(disable/require/verify-full)、`application_name`(排查时能标识来源)、`connect_timeout`、`options`(如 `-c statement_timeout=5000`)。

> **实践建议**:应用连接串里一定设 `application_name`,这样 `pg_stat_activity` 里能直接看出是哪个服务占着连接。

### 三、psql 高频元命令

元命令以反斜杠开头,是 psql 客户端功能(非 SQL)。

**结构探索**

```
\conninfo          -- 当前连接信息
\l                 -- 数据库列表
\c learn           -- 切换数据库
\dn                -- schema 列表
\dt                -- 表列表
\dt public.*       -- 指定 schema 的表
\d  users          -- 表结构(列/类型/索引/约束/外键)
\d+ users          -- 附加:存储参数、注释、大小
\di                -- 索引列表
\dv \dm \df       -- 视图 / 物化视图 / 函数
\du \dg            -- 角色 / 组
\dp users          -- 权限
```

**执行与调试**

```
\timing            -- 打开每条 SQL 的耗时
\x                 -- 扩展显示(一列一行,宽表友好)
\e                 -- 打开编辑器写多行 SQL
\i schema.sql      -- 执行文件
\o out.txt         -- 结果输出到文件
\watch 2           -- 每 2 秒重跑上一条(观察统计变化)
\set ON_ERROR_STOP on  -- 出错即停(脚本模式必备)
\h CREATE TABLE    -- SQL 语法帮助
\q                 -- 退出
```

**导入导出**

```
\copy users TO 'users.csv' WITH (FORMAT csv, HEADER)      -- 客户端侧导出
\copy users FROM 'users.csv' WITH (FORMAT csv, HEADER)    -- 客户端侧导入
```

> `\copy` 与 `COPY` 的区别:`COPY` 是**服务端**执行,要求文件在**服务端**文件系统上且需超级用户/`pg_read_server_files` 权限;`\copy` 由 **psql 客户端**读写本地文件,权限要求低,日常导入导出用 `\copy`。

### 四、配置文件与数据目录

| 文件 | 作用 |
|------|------|
| `postgresql.conf` | 主配置(内存、WAL、日志、规划器……) |
| `pg_hba.conf` | 客户端认证规则(**谁 从哪 用哪种方式 连哪个库**) |
| `pg_ident.conf` | 认证时的用户名映射 |
| `PG_VERSION` | 数据目录的版本标记 |

定位数据目录与配置文件:

```sql
SHOW data_directory;  -- 数据目录
SHOW config_file;     -- postgresql.conf 路径
SHOW hba_file;        -- pg_hba.conf 路径
```

容器里看配置:

```bash
docker exec -it pg18 bash -lc 'ls /var/lib/postgresql/data && cat /var/lib/postgresql/data/postgresql.conf | head -50'
```

> **PG12 起**:`recovery.conf` 被废弃,改为通过 `standby.signal` / `recovery.signal` 触发恢复模式,相关参数移入 `postgresql.conf`。PG18 明确弃用 `recovery.conf` 文件。

### 五、运行期改参数

```sql
-- 会话级(只影响当前连接)
SET work_mem = '128MB';

-- 事务级
SET LOCAL statement_timeout = '30s';

-- 实例级持久化(写入 postgresql.auto.conf,需重启的会提示)
ALTER SYSTEM SET max_connections = 200;

-- 查看
SHOW work_mem;
SELECT * FROM pg_settings WHERE name = 'work_mem';
```

优先级:`postgresql.conf` < `postgresql.auto.conf`(`ALTER SYSTEM` 写入) < 命令行参数 < 会话 `SET`。

## 小结

- 学习环境用 Docker,把"重建实例"变成一条命令。
- 连接串写 `application_name`;日常探索靠 `\d` 系列,调试靠 `\timing` / `\x` / `\watch`。
- `\copy` 走客户端,`COPY` 走服务端。
- 三个配置文件:`postgresql.conf`(行为)、`pg_hba.conf`(认证)、`pg_ident.conf`(映射)。
- 改参数分三层:会话 `SET` / 事务 `SET LOCAL` / 实例 `ALTER SYSTEM`。

## 练习

1. 用 Docker 拉起实例,创建 `learn` 库,导出 `\l` 输出。
2. 执行 `SHOW data_directory` 与 `SHOW config_file`,并进入容器确认这两个路径真实存在。
3. 用 `\d+` 查看 `pg_class` 的列,数一数它有多少列(体会系统目录的规模)。
4. 建一个最简表,用 `\copy` 导出一份 CSV,删除表,再用 `\copy` 导入回来。
