# 5.1 WHERE 与运算符

## 学习目标

- 掌握比较、逻辑、模糊匹配、集合、存在性五类运算符
- 理解 `LIKE` 与索引的关系,知道何时该用 `pg_trgm`
- 会写 `EXISTS` / `IN` / `ANY` 并知道它们的取舍

## 前置知识

## 正文

### 一、比较运算符

```sql
=  <>  !=  <  >  <=  >=
```

```sql
SELECT * FROM orders WHERE amount >= 100 AND status <> 'canceled';
```

**`BETWEEN` 是闭区间(含两端)**

```sql
-- 这两个写法等价
SELECT * FROM orders WHERE created_at BETWEEN '2026-01-01' AND '2026-01-31 23:59:59';
```

> **实践警告**:对带时间的列用 `BETWEEN '2026-01-01' AND '2026-01-31'` 会**漏掉 1 月 31 日当天**的时间部分(因为上界是当天 00:00:00)。时间范围一律用**半开区间**:
>
> ```sql
> WHERE created_at >= '2026-01-01' AND created_at < '2026-02-01'
> ```

### 二、逻辑运算符与优先级

```sql
AND  OR  NOT
```

**优先级:`NOT` > `AND` > `OR`。** 因此:

```sql
-- ⚠️ 与直觉不符:实际是 a AND b, OR c
WHERE a AND b OR c

-- ✅ 显式加括号,永不依赖优先级记忆
WHERE (a AND b) OR c
```

**三值逻辑提醒**:`WHERE` 只保留 `true`,`NULL` 与 `false` 都被过滤(见 2.6)。

### 三、模糊匹配

```sql
-- LIKE:区分大小写  ILIKE:不区分大小写
SELECT * FROM users WHERE name LIKE 'A%';      -- 前缀
SELECT * FROM users WHERE name LIKE '%ann%';   -- 任意位置
SELECT * FROM users WHERE name LIKE '_nn';     -- 单字符通配
SELECT * FROM users WHERE name ILIKE 'a%';

-- 转义通配符
SELECT * FROM t WHERE code LIKE '100\%' ESCAPE '\';
SELECT * FROM t WHERE code LIKE '100\%';       -- 默认转义符是反斜杠
```

**`LIKE` 与索引的关键规则**

| 模式 | 能否用 B-tree 索引 |
|------|-------------------|
| `'abc%'`(前缀,无 `_` 起始) | ✅ 可以——**前提是排序规则为 `C`** |
| `'%abc'`、`'%abc%'` | ❌ 不能用 B-tree |

**为什么前缀匹配还依赖 `C` 排序规则?** B-tree 索引按排序规则建立顺序。只有 `C` 排序规则(纯字节序)下,"同前缀"才对应"索引中的连续区间"。使用 ICU/libc 排序规则时,`LIKE 'abc%'` 无法被转成索引区间扫描。

**三种解决方案**

```sql
-- 方案 1:把列/索引指定为 C 排序规则
CREATE INDEX users_name_c_idx ON users (name COLLATE "C");
CREATE INDEX users_name_pat_idx ON users (name text_pattern_ops);   -- 变长版

-- 方案 2:pg_trgm + GIN/GiST 索引(支持任意位置模糊)
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX users_name_trgm_idx ON users USING gin (name gin_trgm_ops);
SELECT * FROM users WHERE name ILIKE '%ann%';   -- 现在可用索引
SELECT similarity(name, 'ann'), name <-> 'ann' AS dist FROM users ORDER BY dist LIMIT 5;

-- 方案 3:正则表达式(见下)
```

**`SIMILAR TO` 与 POSIX 正则**

```sql
-- SIMILAR TO:SQL 标准,介于 LIKE 与正则之间
SELECT * FROM t WHERE code SIMILAR TO '[A-Z]{3}[0-9]{4}';

-- POSIX 正则:~ 区分大小写,~* 不区分,!~ / !~* 取反
SELECT 'abc123' ~ '^[a-z]+\d+$';        -- true
SELECT 'ABC' ~* '^abc$';                -- true
SELECT regexp_replace('a1b2c3', '\d', '#', 'g');
SELECT (regexp_matches('a1b2', '\d', 'g'))[1];
```

> **性能提示**:正则与 `ILIKE '%x%'` 都是**逐行求值**,无法通过普通索引加速。数据量大时必须用 `pg_trgm` 索引或把可检索信息抽成结构化列(如把品牌、型号拆列)。

### 四、集合与存在性

```sql
-- IN(等价于 = ANY)
SELECT * FROM orders WHERE status IN ('paid','done');
SELECT * FROM orders WHERE status = ANY(ARRAY['paid','done']);

-- NOT IN 的陷阱:列表中含 NULL 会导致结果为空集!
SELECT * FROM t WHERE x NOT IN (1, 2, NULL);   -- 永远返回 0 行
-- 原因:x <> 1 AND x <> 2 AND x <> NULL → 最后一个恒为 NULL → 整体不为 true

-- 修正
SELECT * FROM t WHERE x NOT IN (1, 2);
SELECT * FROM t WHERE x IS DISTINCT FROM ALL (ARRAY[1,2,NULL]);

-- EXISTS / NOT EXISTS(子查询相关)
SELECT u.* FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id AND o.amount > 1000);
```

**`IN` vs `EXISTS` 的选择**

| 场景 | 推荐 | 理由 |
|------|------|------|
| 小常量列表 | `IN` | 可读性好,规划器会转成 `= ANY` |
| 子查询结果大 | `EXISTS` | 半连接语义,可短路,通常更快 |
| 子查询结果小 | `IN` | 规划器可能物化后哈希,也可 |
| 需要"取反" | `NOT EXISTS` | 避免 `NOT IN` 的 NULL 陷阱 |

> 现代 PostgreSQL 优化器对 `IN (子查询)` 与 `EXISTS` 常会**自动改写**,两者计划可能相同。**可读性优先**,`EXISTS` 更明确表达"存在性",也天然规避 NULL 问题。

### 五、`ANY` / `ALL` / `SOME`

```sql
SELECT 5 = ANY(ARRAY[1,5,9]);       -- true   (等价 IN)
SELECT 5 <> ALL(ARRAY[1,5,9]);      -- false  (等价 NOT IN)
SELECT 5 > ANY(ARRAY[1,5,9]);       -- true
SELECT 5 > ALL(ARRAY[1,5,9]);       -- false
SELECT 5 > SOME(ARRAY[1,2]);        -- true   (SOME 是 ANY 的同义词)
```

配合 `generate_series` 做区间判定:

```sql
SELECT * FROM t WHERE id = ANY(generate_series(1, 100));
```

### 六、其他实用谓词

```sql
-- 判空
WHERE col IS NULL / IS NOT NULL
WHERE col IS DISTINCT FROM other      -- NULL 可比较的不等

-- 布尔列
WHERE NOT flag                        -- 等价 flag = false
WHERE flag IS TRUE                    -- 与 flag = true 在 NULL 下不同!

-- 空数组/空 JSONB
WHERE tags = '{}'::text[]
WHERE ext = '{}'::jsonb

-- 类型判定
WHERE pg_typeof(x) = 'integer'::regtype

-- 行值比较(注意 NULL 行为)
WHERE (a, b) > (1, 2)                 -- 字典序比较
```

**`flag = false` 与 `flag IS FALSE` 的差异**

```sql
-- flag = false 会排除 NULL 行
-- flag IS FALSE 也一样(都不匹配 NULL)
-- 但 flag IS NOT TRUE 会包含 NULL 行!
SELECT * FROM t WHERE flag IS NOT TRUE;   -- 返回 false 与 NULL 的行
```

## 小结

- 时间范围一律用半开区间,避免 `BETWEEN` 漏掉末端当天。
- `AND` 优先级高于 `OR`,永远显式加括号。
- `LIKE 'abc%'` 走索引需要 `C` 排序规则或 `text_pattern_ops`;任意位置模糊需 `pg_trgm`。
- `NOT IN` 遇 NULL 会返回空集,用 `NOT EXISTS` 或 `IS DISTINCT FROM ALL` 规避。
- `flag = false` 与 `flag IS NOT TRUE` 在 NULL 行上行为不同。
