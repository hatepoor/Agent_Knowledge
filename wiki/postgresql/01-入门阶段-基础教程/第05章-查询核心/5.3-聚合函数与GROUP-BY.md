# 5.3 聚合函数与 GROUP BY

## 学习目标

- 掌握常用聚合函数及其对 NULL 的处理
- 分清 `WHERE` 与 `HAVING` 的执行时机
- 会用 `FILTER`、`ROLLUP`、`GROUPING SETS` 做多维统计

## 前置知识

## 正文

### 一、常用聚合函数

| 函数 | 说明 | 对 NULL |
|------|------|---------|
| `count(*)` | 行数 | 计所有行 |
| `count(col)` | 非 NULL 计数 | 忽略 NULL |
| `count(DISTINCT col)` | 去重计数 | 忽略 NULL |
| `sum` / `avg` | 求和 / 平均 | 忽略 NULL |
| `min` / `max` | 最小 / 最大 | 忽略 NULL |
| `array_agg` | 聚合为数组 | **包含 NULL** |
| `string_agg(col, sep)` | 聚合为字符串 | 忽略 NULL |
| `bool_and` / `bool_or` | 逻辑与 / 或 | 忽略 NULL |
| `jsonb_agg` / `jsonb_object_agg` | 聚合为 JSONB | **包含 NULL** |
| `percentile_cont(0.5) WITHIN GROUP (ORDER BY x)` | 连续百分位(中位数) | |
| `mode() WITHIN GROUP (ORDER BY x)` | 众数 | |
| `stddev` / `variance` | 标准差 / 方差 | |

```sql
SELECT
    count(*)                        AS rows,
    count(status)                   AS non_null_status,
    count(DISTINCT user_id)         AS users,
    sum(amount)                     AS total,
    round(avg(amount), 2)           AS avg_amount,
    min(created_at), max(created_at),
    array_agg(id ORDER BY created_at DESC)      AS ids_desc,
    string_agg(DISTINCT status, ',' ORDER BY status) AS statuses,
    percentile_cont(0.5) WITHIN GROUP (ORDER BY amount) AS median
FROM orders;
```

> **`array_agg` / `jsonb_agg` 包含 NULL**,与 `string_agg` 不同。若不需要 NULL,先过滤或用 `FILTER`。

**`avg` 的陷阱再强调一遍**:`avg(x)` 的分母是"非 NULL 行数"。业务上若"缺数据应计为 0",必须 `avg(coalesce(x, 0))`。

### 二、`GROUP BY`

```sql
SELECT status, count(*) AS cnt, sum(amount) AS total
FROM orders
GROUP BY status
ORDER BY total DESC;

-- 多列分组
SELECT user_id, status, count(*)
FROM orders
GROUP BY user_id, status;
```

**规则:SELECT 列表中的非聚合列必须出现在 `GROUP BY` 中。**

```sql
-- ❌ 报错:column "orders.created_at" must appear in the GROUP BY clause
SELECT user_id, created_at, count(*) FROM orders GROUP BY user_id;

-- ✅ 用聚合把它"收"成单值
SELECT user_id, min(created_at) AS first_order, count(*) FROM orders GROUP BY user_id;

-- ✅ 或函数依赖(PostgreSQL 支持按主键分组后取其他列)
SELECT u.id, u.email, count(o.id)
FROM users u LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.id;      -- 因为 id 是主键,email 函数依赖于 id,合法
```

**按表达式 / 序号分组**

```sql
SELECT date_trunc('month', created_at) AS mon, count(*) FROM orders GROUP BY 1 ORDER BY 1;
SELECT lower(status), count(*) FROM orders GROUP BY lower(status);
```

> 生产代码建议写完整表达式而非序号 `1`,避免列顺序调整后语义漂移。

### 三、`WHERE` vs `HAVING`

| 子句 | 执行时机 | 作用对象 | 能否用聚合 |
|------|----------|----------|-----------|
| `WHERE` | 分组**之前** | 原始行 | ❌ |
| `HAVING` | 分组**之后** | 分组结果 | ✅ |

```sql
SELECT user_id, count(*) AS cnt, sum(amount) AS total
FROM orders
WHERE status <> 'canceled'          -- 先过滤行:排除取消单
GROUP BY user_id
HAVING count(*) >= 5                -- 再过滤组:只看下单 ≥5 次的用户
   AND sum(amount) > 1000
ORDER BY total DESC;
```

**性能原则**:能放在 `WHERE` 的条件不要放在 `HAVING`。`WHERE` 先减少行数,`HAVING` 之后才过滤意味着"白算了一堆组"。

```sql
-- ⚠️ 低效:所有行都参与分组,分完再丢掉大部分组
SELECT user_id, count(*) FROM orders GROUP BY user_id HAVING max(status) <> 'canceled';

-- ✅ 若无语义差异,提前过滤
SELECT user_id, count(*) FROM orders WHERE status <> 'canceled' GROUP BY user_id;
```

### 四、`FILTER`:条件聚合

`FILTER` 是"带条件的聚合",等价于 `CASE`,但更清晰。

```sql
SELECT
    count(*)                                        AS all_cnt,
    count(*) FILTER (WHERE status = 'paid')          AS paid_cnt,
    count(*) FILTER (WHERE status = 'done')          AS done_cnt,
    sum(amount) FILTER (WHERE status = 'paid')       AS paid_amount,
    avg(amount) FILTER (WHERE amount > 100)          AS avg_big
FROM orders;
```

**等价 `CASE` 写法**(可移植性更好):

```sql
SELECT count(CASE WHEN status = 'paid' THEN 1 END) AS paid_cnt,
       sum(CASE WHEN status = 'paid' THEN amount ELSE 0 END) AS paid_amount
FROM orders;
```

| 写法 | 可读性 | 可移植性 |
|------|--------|----------|
| `FILTER` | 更好 | PostgreSQL / SQL 标准,MySQL 不支持 |
| `CASE` | 稍差 | 全平台 |

**行转列(枢轴)标准做法**

```sql
SELECT
    date_trunc('day', created_at)::date AS d,
    count(*) FILTER (WHERE status = 'paid') AS paid,
    count(*) FILTER (WHERE status = 'done') AS done,
    count(*) FILTER (WHERE status = 'canceled') AS canceled
FROM orders
GROUP BY 1 ORDER BY 1;
```

若需要**动态列**(状态值来自数据而非硬编码),SQL 无法直接做到,需 `crosstab`(tablefunc 扩展)或应用层拼接 SQL。

### 五、多维聚合:`ROLLUP` / `CUBE` / `GROUPING SETS`

一次查询产出多个粒度的汇总(等价于多次 `UNION ALL` 但只扫一遍表)。

```sql
-- ROLLUP:层级汇总(如 年 → 月 → 总计)
SELECT
    extract(year  FROM created_at) AS y,
    extract(month FROM created_at) AS m,
    sum(amount) AS total
FROM orders
GROUP BY ROLLUP (1, 2)
ORDER BY 1 NULLS LAST, 2 NULLS LAST;

-- CUBE:所有组合(2^n 个分组集)
SELECT status, user_id, count(*) FROM orders GROUP BY CUBE (status, user_id);

-- GROUPING SETS:精确指定要哪些分组集
SELECT status, date_trunc('month', created_at) AS mon, count(*)
FROM orders
GROUP BY GROUPING SETS (
    (status),
    (mon),
    (status, mon),
    ()                       -- 总计
)
ORDER BY 1 NULLS LAST, 2 NULLS LAST;
```

**区分"总计行"与"真实 NULL"**:用 `GROUPING()` 函数。

```sql
SELECT
    status,
    grouping(status) AS is_total_row,
    sum(amount)
FROM orders
GROUP BY ROLLUP (status);
```

`grouping(col)` 返回 1 表示该列在这一行是**汇总产生的占位**(不是数据里的 NULL)。

### 六、`string_agg` 的顺序与去重

```sql
-- 顺序必须写在 WITHIN 或聚合内部的 ORDER BY
SELECT user_id, string_agg(status, ' > ' ORDER BY created_at) FROM orders GROUP BY user_id;

-- 去重 + 排序
SELECT string_agg(DISTINCT status, ',' ORDER BY status) FROM orders;
```

> **注意**:`string_agg(DISTINCT x ORDER BY y)` —— 若 `DISTINCT` 用 `x` 而 `ORDER BY` 用 `y`,`y` 必须也在聚合参数里,否则报错。

## 小结

- 聚合忽略 NULL 的规则对 `avg`/`sum` 影响最大,业务语义要先想清楚。
- `WHERE` 在分组前过滤行,`HAVING` 在分组后过滤组;**能下推到 `WHERE` 的不要留在 `HAVING`**。
- `FILTER` 是条件聚合的清晰写法;`CASE` 版本可移植。
- `ROLLUP`/`CUBE`/`GROUPING SETS` 一次扫描产出多维汇总,用 `grouping()` 区分占位 NULL。
- 动态透视列 SQL 做不到,需扩展或应用层处理。

## 练习

1. 用 `count(*) FILTER` 与 `count(CASE WHEN ...)` 写出等价的按状态行转列统计,并比较执行计划。
2. 用 `ROLLUP` 输出"年/月/总计"三级汇总,并用 `grouping()` 标记总计行。
3. 构造一个"`WHERE` 与 `HAVING` 可互换但性能不同"的查询,用 `EXPLAIN ANALYZE` 证明差异。
4. 用 `percentile_cont(0.5)` 求订单金额中位数,并与 `avg` 结果对比,解释差异的业务含义。
