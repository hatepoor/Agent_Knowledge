# 4.2 SELECT 基础查询

## 学习目标

- 掌握 SELECT 的书写与执行顺序
- 会用别名、`DISTINCT`、`DISTINCT ON`、`CASE`、`COALESCE`
- 理解为什么 `SELECT *` 在生产代码中是问题

## 正文

### 一、SELECT 的书写顺序与执行顺序

**书写顺序**(你写 SQL 的顺序):

```
SELECT → FROM → JOIN → WHERE → GROUP BY → HAVING → WINDOW → ORDER BY → LIMIT/OFFSET
```

**逻辑执行顺序**(数据库实际处理顺序):

```
FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT(含窗口函数) → DISTINCT → ORDER BY → LIMIT
```

这个差异解释了大量"为什么不能在 WHERE 里用别名"的问题:

```sql
-- ❌ 报错:WHERE 早于 SELECT,别名还不存在
SELECT amount * 2 AS double_amount FROM orders WHERE double_amount > 100;

-- ✅ 修正一:重复表达式
SELECT amount * 2 AS double_amount FROM orders WHERE amount * 2 > 100;

-- ✅ 修正二:子查询/CTE 包一层
SELECT * FROM (SELECT amount * 2 AS double_amount FROM orders) t WHERE double_amount > 100;

-- 注意:ORDER BY 在 SELECT 之后,所以可以用别名
SELECT amount * 2 AS d FROM orders ORDER BY d;
```

### 二、列表达式与别名

```sql
SELECT
    id,
    email,
    upper(name)          AS name_upper,       -- AS 可省略,但强烈建议写
    amount * 1.06        AS amount_with_tax,
    amount::text         AS amount_text,
    coalesce(ext->>'vip', 'n/a') AS vip_flag
FROM users;

-- 别名含特殊字符/关键字时加双引号
SELECT 1 AS "total count", 2 AS "select";
```

**`SELECT *` 的问题**

| 问题 | 说明 |
|------|------|
| 传输浪费 | 宽表带出 TOAST 字段,网络与内存成本高 |
| 脆弱 | 加列后应用映射错位(尤其位置映射的 ORM/驱动) |
| 阻碍索引优化 | 无法利用仅索引扫描(Index Only Scan)的覆盖能力 |
| 语义不清 | 读者不知道真正用了哪些列 |

**结论**:探索时用 `SELECT *`,**进入代码的 SQL 一律显式列名**。唯一合理例外是 `EXISTS (SELECT 1 ...)` 与 CTE 内部临时使用。

### 三、`DISTINCT` 与 `DISTINCT ON`

```sql
-- 去重(对所有选定列)
SELECT DISTINCT status FROM orders;
SELECT DISTINCT user_id, status FROM orders;   -- 组合去重

-- DISTINCT ON:按指定列去重,并保留每组"排序第一条"
-- 用途:取每个用户最新的一笔订单
SELECT DISTINCT ON (user_id) user_id, id, created_at, amount
FROM orders
ORDER BY user_id, created_at DESC;
```

**`DISTINCT ON` 的硬性规则**:`ORDER BY` 的**最左列必须与 `DISTINCT ON` 的列一致**,否则结果不确定(会报错)。

| 方案 | 可读性 | 性能 | 备注 |
|------|--------|------|------|
| `DISTINCT ON` | 好(PG 特有,较简洁) | 好 | 需索引 `(user_id, created_at DESC)` 才高效 |
| 窗口函数 `row_number()` | 稍繁 | 好 | 标准 SQL,可移植 |
| 相关子查询 `LATERAL` | 中 | 有索引时最好 | 见 5.4 |

### 四、CASE 表达式

```sql
-- 简单形式
SELECT CASE status
         WHEN 'paid' THEN '已支付'
         WHEN 'done' THEN '已完成'
         ELSE '其他'
       END AS status_cn
FROM orders;

-- 搜索形式(更灵活,可写条件)
SELECT CASE
         WHEN amount >= 1000 THEN '大额'
         WHEN amount >= 100  THEN '中额'
         ELSE '小额'
       END AS bucket
FROM orders;

-- 与聚合配合:行转列(枢轴)
SELECT
    count(*) FILTER (WHERE status = 'paid') AS paid_cnt,
    count(*) FILTER (WHERE status = 'done') AS done_cnt,
    sum(CASE WHEN status = 'paid' THEN amount ELSE 0 END) AS paid_amount
FROM orders;
```

> **`CASE` 从上到下短路求值**,第一个匹配的分支生效。所以条件顺序影响结果。

### 五、常用标量表达式

```sql
-- 空值处理
SELECT coalesce(ext->>'channel', 'unknown'), nullif(qty, 0) FROM ...;

-- 类型与判空
SELECT pg_typeof(amount), id IS NULL FROM ...;

-- 数值
SELECT round(amount, 1), ceil(amount), floor(amount), abs(-3), power(2,10);

-- 字符串(见 2.2)
SELECT concat_ws('-', a, b), substring(name from 1 for 3) FROM ...;

-- 时间(见 2.3)
SELECT date_trunc('day', created_at), now() - created_at AS age FROM ...;

-- 数组
SELECT tags[1], cardinality(tags), array_to_string(tags, '/') FROM products;

-- JSONB
SELECT ext->>'channel', ext#>>'{trace,id}' FROM ...;

-- 条件函数
SELECT greatest(a, b, c), least(a, b, c) FROM ...;

-- 类型转换
SELECT '123'::integer, CAST(now() AS date);
```

### 六、`VALUES` 作为常量表

```sql
SELECT * FROM (VALUES
    (1, 'low'),
    (2, 'mid'),
    (3, 'high')
) AS levels(level, label);

-- 与应用层枚举映射表连接
SELECT o.id, l.label
FROM orders o
JOIN (VALUES ('paid','已支付'), ('done','已完成')) AS l(status, label)
  ON o.status = l.status;
```

### 七、LIMIT 与 OFFSET 初步

```sql
SELECT * FROM orders ORDER BY created_at DESC LIMIT 10;
SELECT * FROM orders ORDER BY created_at DESC LIMIT 10 OFFSET 20;
```

`ORDER BY` 不唯一时,`LIMIT` 结果**不确定**。分页必须让排序键唯一(通常补 `, id`),细节见 [[postgresql/01-入门阶段-基础教程/第05章-查询核心/5.2-ORDER-BY与分页]]。

## 小结

- 逻辑执行顺序是 `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`,这解释了别名可用范围。
- 进代码的 SQL 不用 `SELECT *`。
- `DISTINCT ON` 是 PostgreSQL 取"每组第一条"的简洁写法,但 `ORDER BY` 最左列必须匹配。
- `CASE` 短路求值;`FILTER` 与 `CASE` 配合可实现条件聚合与行转列。
- `ORDER BY` 不唯一时 `LIMIT` 结果不确定。

## 练习

1. 用 `DISTINCT ON` 取每个用户最近一笔订单,并用窗口函数写等价版本,比较执行计划。
2. 用 `CASE` + `count(*) FILTER` 把订单表按状态做行转列统计。
3. 故意在 `WHERE` 中引用 `SELECT` 的别名,记录报错信息,再给两种修正写法。
4. 用 `VALUES` 构造一张状态映射表,与订单表连接输出中文状态。
