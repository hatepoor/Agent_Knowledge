# 3.1 DDL 建表与列定义

## 正文

> **本篇怎么读**:本篇会逐个词讲清楚一条 `CREATE TABLE` 语句。你会看到 `CONSTRAINT`、`REFERENCES`、`NOT NULL`、`GENERATED ALWAYS AS IDENTITY` 等一串修饰词——**每个都会解释**。遇到不认识的关键字也可以随时查 [[postgresql/术语与关键字手册]]。
>
> 本篇第一节先讲"模式(schema)",这是组织表的方式。如果觉得抽象,**可以先跳到第二节看完整的建表语句**,再回头理解模式。

### 一、Schema 与搜索路径

Schema 是数据库内的**命名空间**。默认有 `public`。

```sql
CREATE SCHEMA app;
CREATE SCHEMA audit AUTHORIZATION app_user;   -- 指定属主

-- 对象限定名
CREATE TABLE app.users (...);

-- 搜索路径:未限定名按顺序查找
SHOW search_path;                    -- "$user", public
SET search_path = app, public;       -- 会话级
ALTER ROLE app_user SET search_path = app, public;   -- 角色级(推荐)
```

**生产建议**:业务表放独立 schema(如 `app`),不污染 `public`。这样便于权限集中管理,也避免第三方扩展建表造成命名冲突。

### 二、一个完整的生产级建表语句

```sql
CREATE TABLE app.orders (
    -- 主键:IDENTITY + bigint
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,

    -- 外键:显式命名约束,便于后续 ALTER
    user_id         bigint NOT NULL
                    CONSTRAINT orders_user_fk REFERENCES app.users(id) ON DELETE RESTRICT,

    -- 业务编码:唯一
    order_no        text NOT NULL
                    CONSTRAINT orders_no_uk UNIQUE,

    -- 枚举值用 CHECK(便于演进,优于 enum)
    status          text NOT NULL DEFAULT 'pending'
                    CONSTRAINT orders_status_ck
                    CHECK (status IN ('pending','paid','shipped','done','canceled')),

    -- 金额:精确小数,非负
    amount          numeric(12,2) NOT NULL
                    CONSTRAINT orders_amount_ck CHECK (amount >= 0),

    -- 生成列:金额的税额(读取时计算)
    tax             numeric(12,2)
                    GENERATED ALWAYS AS (round(amount * 0.06, 2)) VIRTUAL,

    -- 半结构化扩展字段
    ext             jsonb NOT NULL DEFAULT '{}'::jsonb,

    -- 时间戳:统一 timestamptz + now()
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),

    -- 表级约束(涉及多列时)
    CONSTRAINT orders_paid_amount_ck CHECK (status <> 'paid' OR amount > 0)
);

COMMENT ON TABLE  app.orders      IS '订单主表';
COMMENT ON COLUMN app.orders.ext  IS '业务扩展字段,JSONB';
```

**几个值得记住的点**

| 写法 | 理由 |
|------|------|
| `bigint` 主键 | 避免增长后溢出 |
| `GENERATED ALWAYS AS IDENTITY` | 优于 `serial` |
| **显式命名约束** | 报错信息可读,`ALTER TABLE ... DROP CONSTRAINT <名>` 可控 |
| `timestamptz` + `now()` | 统一时间语义与默认值 |
| `NOT NULL` 尽量加 | NULL 会污染逻辑(见 2.6) |
| `jsonb` 而非 `json` | 可索引 |
| `COMMENT ON` | 让 `\d+` 直接显示说明,降低交接成本 |

### 三、生成列(GENERATED COLUMN)

```sql
CREATE TABLE t_gen (
    price  numeric(10,2) NOT NULL,
    qty    integer NOT NULL,
    -- 存储式:写入时计算并落盘
    total_stored numeric(12,2) GENERATED ALWAYS AS (price * qty) STORED,
    -- 虚拟式:读取时计算,不占存储(PG18 起为默认)
    total_virt   numeric(12,2) GENERATED ALWAYS AS (price * qty) VIRTUAL
);
```

| 维度 | `STORED` | `VIRTUAL` |
|------|----------|-----------|
| 计算时机 | 写入时 | 读取时 |
| 占存储 | ✅ | ❌ |
| 可建索引 | ✅ | ❌(表达式索引可替代) |
| 版本 | PG12+ | **PG18 起为默认** |
| 表达式要求 | 必须 immutable | 必须 immutable |

> **PG18 兼容性提示**:同一 `CREATE TABLE` 里若未显式写 `STORED`/`VIRTUAL`,现在默认创建 **VIRTUAL** 生成列。从 PG17 及更早迁移时,若依赖生成列被落盘(例如给它建了索引),升级会失败或行为改变,必须显式写 `STORED`。这是升级前必须检查的一项。

生成列**不能**引用其他生成列,也不能用 volatile 函数(如 `now()`)。

```sql
-- ❌ 报错:generation expression is not immutable
ts timestamptz GENERATED ALWAYS AS (now()) STORED
```
需要"自动更新时间"时应使用触发器,而非生成列。

### 四、默认值

```sql
id         bigint GENERATED ALWAYS AS IDENTITY,   -- 序列默认值
status     text     NOT NULL DEFAULT 'pending',
created_at timestamptz NOT NULL DEFAULT now(),
ext        jsonb    NOT NULL DEFAULT '{}'::jsonb,
tags       text[]   NOT NULL DEFAULT '{}'::text[],
uid        uuid     NOT NULL DEFAULT uuidv7(),      -- PG18+
seq        integer  NOT NULL DEFAULT nextval('my_seq')
```

> **`DEFAULT` 只对"未提供该列"生效**;显式插入 `NULL` 会存 NULL(除非列是 `NOT NULL`,此时报错)。

序列 vs 生成列 vs 默认值的区别:P**G17 起支持 `GENERATED ALWAYS AS IDENTITY` 与 `DEFAULT nextval()` 的差异主要在权限与依赖管理上**。日常优先 IDENTITY。

### 五、`CREATE TABLE ... AS` / `LIKE` / 临时表

```sql
-- 备份表结构 + 数据(不继承约束与索引!)
CREATE TABLE orders_bak AS SELECT * FROM app.orders;

-- 只复制结构
CREATE TABLE orders_empty AS SELECT * FROM app.orders WHERE false;

-- 复制结构并继承约束/索引/默认值
CREATE TABLE orders_copy (LIKE app.orders INCLUDING ALL);

-- 含数据
CREATE TABLE orders_copy2 (LIKE app.orders INCLUDING ALL);
INSERT INTO orders_copy2 SELECT * FROM app.orders;

-- 临时表(会话结束自动删除)
CREATE TEMP TABLE tmp_ids (id bigint);
```

| 方式 | 约束 | 索引 | 默认值 | 生成列 |
|------|------|------|--------|--------|
| `CREATE TABLE AS` | ❌ | ❌ | ❌ | ❌ |
| `CREATE TABLE (LIKE t)` | ❌(除 NOT NULL) | ❌ | ❌ | ❌ |
| `CREATE TABLE (LIKE t INCLUDING ALL)` | ✅ | ✅ | ✅ | ✅ |

### 六、`ALTER TABLE` 安全演进

```sql
-- 加列:PG11+ 带常量默认值不再重写整表(快)
ALTER TABLE app.orders ADD COLUMN note text NOT NULL DEFAULT '';

-- 加约束
ALTER TABLE app.orders ADD CONSTRAINT orders_note_len_ck CHECK (length(note) <= 500);

-- 改类型:能否避免重写取决于转换是否"二进制兼容"
ALTER TABLE app.orders ALTER COLUMN amount TYPE numeric(14,2);
ALTER TABLE app.orders ALTER COLUMN amount TYPE text USING amount::text;   -- 需 USING

-- 重命名
ALTER TABLE app.orders RENAME COLUMN note TO remark;

-- 设/删默认值
ALTER TABLE app.orders ALTER COLUMN status SET DEFAULT 'new';
ALTER TABLE app.orders ALTER COLUMN status DROP DEFAULT;

-- 加/删 NOT NULL
ALTER TABLE app.orders ALTER COLUMN ext SET NOT NULL;
ALTER TABLE app.orders ALTER COLUMN ext DROP NOT NULL;
```

**大表加列/加约束的在线化技巧**

```sql
-- 1) 加约束先 NOT VALID,再后台 VALIDATE(避免长时间持锁阻塞写入)
ALTER TABLE app.orders ADD CONSTRAINT orders_x_ck CHECK (amount < 1e9) NOT VALID;
ALTER TABLE app.orders VALIDATE CONSTRAINT orders_x_ck;   -- 只取弱锁

-- 2) 建索引加 CONCURRENTLY(见中段专题)

-- 3) 加列 + 设默认值分两步(极老版本兼容用)
ALTER TABLE t ADD COLUMN c integer;
ALTER TABLE t ALTER COLUMN c SET DEFAULT 0;
UPDATE t SET c = 0 WHERE c IS NULL;   -- 分批做,避免长事务
```

**破坏性操作**(必须确认):

```sql
ALTER TABLE app.orders DROP COLUMN remark;         -- 立即不可逆
DROP TABLE app.orders;                             -- 立即
DROP TABLE IF EXISTS app.orders CASCADE;           -- 连带依赖对象
TRUNCATE app.orders RESTART IDENTITY CASCADE;      -- 清空(比 DELETE 快)
```

> **学习环境的救命习惯**:做 DDL 前先 `BEGIN;`,确认无误再 `COMMIT;`。PostgreSQL 的 **DDL 是事务性的**——这是它与 MySQL 的重要差异,`ROLLBACK` 能把 `DROP TABLE` 也撤销。

## 小结

- 用独立 schema 组织业务表;约束显式命名。
- 主键 `bigint` + `IDENTITY`;时间用 `timestamptz` + `now()`;扩展字段用 `jsonb`。
- 生成列分 `STORED`(落盘可索引)与 `VIRTUAL`(PG18 起默认,读取时算);表达式必须 immutable。
- `CREATE TABLE AS` 不继承约束索引,要继承用 `LIKE ... INCLUDING ALL`。
- DDL 可回滚;大表变更用 `NOT VALID` + `VALIDATE` 与 `CONCURRENTLY` 降低锁影响。

## 练习

1. 写出一个包含主键、外键、唯一、CHECK、生成列、注释的完整建表语句。
2. 分别用 `CREATE TABLE AS` 与 `LIKE ... INCLUDING ALL` 复制同一张表,用 `\d` 对比两者的约束与索引差异。
3. 在事务内执行 `DROP TABLE` 后 `ROLLBACK`,验证表仍然存在,并解释这体现了什么特性。
4. 给一张已有一亿行的表加一个 CHECK 约束,用 `NOT VALID` + `VALIDATE` 两步完成,并用 `pg_locks` 观察锁级别。
