# 2.6 NULL 语义与类型转换

## 学习目标

- 彻底理解 `NULL` 的"未知"语义与三值逻辑
- 掌握 `IS NULL` / `IS DISTINCT FROM` / `COALESCE` / `NULLIF` 的正确用法
- 分清隐式、显式、赋值三种类型转换及其风险

## 正文

### 一、NULL 是"未知",不是"空"

这是理解一切 NULL 行为的总纲。`NULL` 表示**值未知/不适用**,而不是"零"或"空字符串"。

```sql
SELECT NULL = NULL;      -- NULL   ← 不是 true!两个未知值无法断定相等
SELECT NULL <> NULL;     -- NULL
SELECT NULL + 1;         -- NULL   ← 传播性:任何含 NULL 的运算结果为 NULL
SELECT 'a' || NULL;      -- NULL
SELECT NULL AND false;   -- false  ← 短路例外
SELECT NULL AND true;    -- NULL
```

**三值逻辑真值表**

| AND | true | false | NULL |
|-----|------|-------|------|
| **true** | true | false | NULL |
| **false** | false | false | false |
| **NULL** | NULL | false | NULL |

| OR | true | false | NULL |
|----|------|-------|------|
| **true** | true | true | true |
| **false** | true | false | NULL |
| **NULL** | true | NULL | NULL |

> `NOT NULL` 仍为 `NULL`。

### 二、最经典的坑:`WHERE` 只接受 true

`WHERE` 子句只保留**条件为 `true`** 的行。`false` 与 `NULL` 都被过滤掉。

```sql
CREATE TABLE t (id int, val int);
INSERT INTO t VALUES (1, 10), (2, NULL), (3, 30);

SELECT * FROM t WHERE val > 20;          -- 只有 id=3
SELECT * FROM t WHERE val <= 20;         -- 只有 id=1  ← id=2 两条都不出现!
SELECT * FROM t WHERE val <> 20;         -- 只有 id=1,3
SELECT count(*) FROM t WHERE val <> 20;  -- 2
SELECT count(val), count(*) FROM t;      -- 2, 3
```

**结论**:`x > 20` 与 `NOT (x <= 20)` **不等价** —— 有 NULL 时两者都漏掉该行。做"补集"查询时务必显式处理 NULL:

```sql
SELECT * FROM t WHERE val <= 20 OR val IS NULL;
SELECT * FROM t WHERE coalesce(val, 0) <= 20;
```

### 三、判断与替换函数

```sql
-- 判空
SELECT val IS NULL, val IS NOT NULL FROM t;

-- IS DISTINCT FROM:把 NULL 当作一个可比较的"值"
SELECT NULL IS DISTINCT FROM NULL;     -- false
SELECT 1    IS DISTINCT FROM NULL;     -- true
SELECT NULL IS NOT DISTINCT FROM NULL; -- true

-- 对比:处理"两列是否不同"时,= 会漏掉 NULL 情况,IS DISTINCT FROM 不会
SELECT * FROM t WHERE val IS DISTINCT FROM 20;   -- 返回 id=1,2,3(全中)

-- 替换
SELECT coalesce(val, 0) FROM t;                       -- NULL → 0
SELECT nullif(val, 0) FROM t;                         -- 等于 0 时返回 NULL
SELECT coalesce(a, b, c, 'default') FROM ...;         -- 取第一个非 NULL

-- 条件式
SELECT CASE WHEN val IS NULL THEN '未知' WHEN val > 20 THEN '大' ELSE '小' END FROM t;
```

**`NULLIF` 的经典用途:防除零**

```sql
SELECT sum(amount) / nullif(count(*), 0) FROM orders;   -- 无行时返回 NULL 而非报错
```

### 四、NULL 与聚合、排序、唯一约束

**聚合**:所有聚合函数(除 `count(*)`)都**忽略 NULL**。

```sql
SELECT count(*), count(val), sum(val), avg(val), max(val) FROM t;
-- 3, 2, 40, 20, 30   ← count(*) 数行数,其余只算非 NULL 行
```

> **由此产生的高频业务 Bug**:"平均分"用 `avg(score)` 时,缺考(NULL)的学生**不计入分母**,得到的"平均分"偏高。若业务要求缺考按 0 算,必须 `avg(coalesce(score, 0))`。

**排序**:默认 `NULL` 视为**最大**(升序排在最后)。

```sql
SELECT val FROM t ORDER BY val;                    -- 10, 30, NULL
SELECT val FROM t ORDER BY val NULLS FIRST;        -- NULL, 10, 30
SELECT val FROM t ORDER BY val DESC NULLS LAST;    -- 30, 10, NULL
```

**唯一约束**:`UNIQUE` 允许多个 NULL,因为 `NULL ≠ NULL`。

```sql
CREATE TABLE u (email text UNIQUE);
INSERT INTO u VALUES (NULL), (NULL), (NULL);   -- ✅ 全部成功
```

**PG15+ 新增 `NULLS NOT DISTINCT`**:

```sql
CREATE TABLE u2 (email text UNIQUE NULLS NOT DISTINCT);
INSERT INTO u2 VALUES (NULL);   -- 第一次成功
INSERT INTO u2 VALUES (NULL);   -- ERROR: duplicate key  ← NULL 之间也判重
```

> 该特性在"唯一键可空"的业务里非常实用(如"软删除 + 唯一编码")。

**GROUP BY / DISTINCT**:NULL 会被视为**同一个分组**(与 `=` 的语义不同,这是特例)。

```sql
SELECT val, count(*) FROM t GROUP BY val;   -- NULL 自成一组
SELECT DISTINCT val FROM t;                 -- 含一个 NULL
```

### 五、类型转换

PostgreSQL 的转换分三类:

| 类型 | 例子 | 特点 |
|------|------|------|
| **隐式**(implicit) | `int` → `bigint`、`int` → `numeric` | 系统自动,安全 |
| **赋值**(assignment) | `text` → `varchar`、`numeric` → `int` | 存入列时自动,可能丢精度/报错 |
| **显式**(explicit) | `x::type`、`CAST(x AS type)` | 由你负责 |

```sql
-- 显式转换的两种写法(等价)
SELECT '42'::integer, CAST('42' AS integer);
SELECT now()::date, now()::text, '3.14'::numeric;

-- 赋值转换:可能失败
CREATE TABLE c (n integer);
INSERT INTO c VALUES ('abc');   -- ERROR: invalid input syntax for type integer

-- 数值截断 vs 四舍五入(赋值转换是四舍五入,显式整型转换是四舍五入)
SELECT 3.7::numeric(2,0);   -- 4
SELECT 3.7::integer;        -- 4
SELECT round(3.7)::numeric; -- 4
SELECT trunc(3.7)::numeric; -- 3
```

**为什么隐式转换会害人**

```sql
-- 1) 列与条件类型不一致 → 索引可能无法使用
CREATE TABLE p (id bigint PRIMARY KEY, code text);
CREATE INDEX ON p (code);
SELECT * FROM p WHERE code = 12345;     -- 12345 是 int,需转换为 text
                                        -- 若转换函数不是 immutable,索引可能被跳过
SELECT * FROM p WHERE code = '12345';   -- ✅ 类型一致,索引可用

-- 2) 字面量类型推断的意外
SELECT 1 + 1.0;             -- 2.0 (numeric)
SELECT 1 / 2;               -- 0   ← 整数除法
SELECT 1 / 2.0;             -- 0.5
SELECT '1' + 1;             -- 2,因为 '1' 被推断为 unknown → integer

-- 3) unknown 类型的传播
SELECT '2026-09-19' < '2026-10-01';   -- unknown 之间比较,按文本;建议显式 ::date
```

> **实践规则**:比较、连接、聚合时,**保证操作数类型一致**。宁可多写一次 `::type`,也不要依赖隐式转换——尤其是在有索引的列上。

## 小结

- `NULL` = 未知;`NULL = NULL` 得 `NULL`;NULL 参与运算会传播。
- `WHERE` 只保留 `true`,`false` 与 `NULL` 都被过滤 —— `x > n` 与 `NOT (x <= n)` 不等价。
- 判断用 `IS NULL`,`比较两值是否不同` 用 `IS DISTINCT FROM`;替换用 `coalesce`,`防除零` 用 `nullif`。
- 聚合忽略 NULL,排序默认 NULL 最大,`UNIQUE` 默认允许多个 NULL(PG15+ 可用 `NULLS NOT DISTINCT` 改变)。
- 类型转换优先显式;有索引的列上尤其要避免隐式转换导致索引失效。

## 练习

1. 建表插入 `NULL`,分别验证 `count(*)` / `count(val)` / `avg(val)` 的差异,并解释 `avg` 在业务统计上的风险。
2. 用 `IS DISTINCT FROM` 改写一个"两列不等"的查询,对比用 `<>` 时的结果差异。
3. 造一个"有索引但查询没走索引"的例子:让条件里的字面量类型与列类型不一致,用 `EXPLAIN` 证明索引未被使用。
4. 若使用 PG15+,对比 `UNIQUE` 与 `UNIQUE NULLS NOT DISTINCT` 在多次插入 NULL 时的行为。
