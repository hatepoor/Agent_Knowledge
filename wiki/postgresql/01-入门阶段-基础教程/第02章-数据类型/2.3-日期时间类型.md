# 2.3 日期时间类型

## 学习目标

- 彻底分清 `timestamp` 与 `timestamptz`,并形成"默认用 timestamptz"的肌肉记忆
- 掌握 `interval` 的运算与常用单位
- 会做时区转换、日期截断与区间重叠判断

## 前置知识

[[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.2-字符与二进制类型]]

## 正文

### 一、类型全景

| 类型 | 存储 | 语义 | 推荐 |
|------|------|------|------|
| `date` | 4 字节 | 日期(无时间) | 生日、账期 |
| `time` | 8 字节 | 一天内时间(无日期、无时区) | 营业时间 |
| `timetz` | 12 字节 | 时间 + 时区偏移 | ❌ 语义含糊,少用 |
| `timestamp` | 8 字节 | 日期时间,**无时区** | 仅限"墙上时间"场景 |
| `timestamptz` | 8 字节 | 日期时间,**内部存 UTC 瞬时** | ✅ **默认选它** |
| `interval` | 16 字节 | 时间间隔 | 时长、账龄 |
| `tsrange` / `tstzrange` | — | 时间区间 | 排期、预订 |

### 二、`timestamp` vs `timestamptz`:核心机制

这是本节最重要的一段。

**`timestamptz` 并不存储时区**,它做的是:

1. **写入时**:把你的输入按**当前会话的 `TimeZone`** 解释,转换成 UTC 瞬时,存下来(8 字节,就是一个绝对时刻)。
2. **读出时**:把这个 UTC 瞬时按**当前会话的 `TimeZone`** 渲染成字符串。

也就是说:`timestamptz` 存的是"**什么时候发生的**",显示随会话时区变化;`timestamp` 存的是"**钟表上显示了几点**",与时区无关。

```sql
SET TimeZone = 'Asia/Shanghai';
CREATE TABLE t_ts (a timestamp, b timestamptz);
INSERT INTO t_ts VALUES ('2026-09-19 12:00:00', '2026-09-19 12:00:00');

SELECT * FROM t_ts;
--  a: 2026-09-19 12:00:00        b: 2026-09-19 12:00:00+08

SET TimeZone = 'UTC';
SELECT * FROM t_ts;
--  a: 2026-09-19 12:00:00        ← 不变(墙上时间)
--  b: 2026-09-19 04:00:00+00     ← 变了(同一绝对时刻的 UTC 表示)
```

**选型判定**:

| 问题 | 选择 |
|------|------|
| 这个时刻在全世界指的是同一个瞬间吗?(订单时间、日志时间、操作时间) | `timestamptz` |
| 这个时刻只是"表盘读数",不该随时区漂移吗?(营业时间 9:00、航班起飞 08:00 当地时间) | `timestamp` |

**结论:99% 的业务时间字段用 `timestamptz`。** 唯一的例外是"跨时区也应该保持同一个钟面数字"的场景。

> 常见反模式:库里存 `timestamp`,应用层再"假装"它是某个时区的时间。一旦部署时区变化或跨区域查询,数据就失去意义。**不要这么做。**

### 三、interval:时间间隔

```sql
SELECT interval '1 day', interval '2 hours 30 minutes', interval '1 year 2 months';

-- 字面量写法
SELECT '3 days'::interval, '1-2'::interval /* 1年2月 */, '01:30:00'::interval;

-- 运算
SELECT now() + interval '7 days';
SELECT now() - interval '1 month';
SELECT date '2026-09-19' - date '2026-09-01';        -- 18(整数,天)
SELECT timestamp '2026-09-19' - timestamp '2026-09-01 06:00';  -- interval '18 days'
SELECT interval '1 day' * 3, interval '6 hours' / 2;
```

**关键概念:`interval` 有两类组成部分**

| 组成 | 含义 | 是否依赖具体日期 |
|------|------|------------------|
| 月(months) | 月/年 | ✅ 依赖(`1 month` 在 1 月与 2 月天数不同) |
| 日(days) | 日 | ✅ 依赖夏令时 |
| 微秒(microseconds) | 时分秒 | ❌ 绝对时长 |

因此需要 `justify_*` 系列函数把"过多的日"折算成"月"、把"过多的小时"折算成"日":

```sql
-- 签名:接受一个 interval,返回规范化后的 interval
SELECT justify_interval(interval '35 days');   -- 1 mon 5 days  (30 天折成 1 月)
SELECT justify_interval(interval '30 hours');  -- 1 day 6 hours (24 小时折成 1 天)
SELECT justify_days(interval '35 days');       -- 1 mon 5 days  (只折算"日"这一层)
SELECT justify_hours(interval '30 hours');     -- 1 day 6 hours (只折算"小时"这一层)
```

| 函数 | 折算范围 |
|------|----------|
| `justify_days(i)` | 只把"日"折算成"月"(按 30 天 = 1 月) |
| `justify_hours(i)` | 只把"小时"折算成"日"(按 24 小时 = 1 天) |
| `justify_interval(i)` | **同时做以上两步**,最常用 |

> **为什么需要它**:`interval '35 days'` 与 `interval '1 mon 5 days'` 在 PostgreSQL 里是**两个不同的值**(因为月的天数不固定),但人读起来都觉得是"一个多月"。`justify_*` 的作用就是让输出符合人的阅读习惯。**它只影响显示与比较,不改变实际时长。**

> **实践警告**:用 `now() - interval '1 month'` 做"一个月前"的分界线,在跨月时结果天数不一致。时间范围查询优先用 `date_trunc`,见下文。

### 四、常用函数与格式化

```sql
-- 当前时间
SELECT now(), current_timestamp, current_date, current_time, localtime;
SELECT clock_timestamp();   -- 随语句执行变化(now() 是事务开始时刻)

-- 截断(时间范围查询的核心工具)
SELECT date_trunc('day',  now());
SELECT date_trunc('month', now());
SELECT date_trunc('hour', now());
SELECT date_trunc('week', now());   -- 周一为一周起点

-- 抽取字段
SELECT extract(year FROM now()), extract(month FROM now()), extract(dow FROM now()); -- dow: 0=周日
SELECT date_part('hour', now());
SELECT to_char(now(), 'YYYY-MM-DD HH24:MI:SS');
SELECT to_char(now(), 'YYYY"年"MM"月"DD"日"');

-- 解析
SELECT to_date('2026-09-19', 'YYYY-MM-DD');
SELECT to_timestamp('2026-09-19 12:00', 'YYYY-MM-DD HH24:MI');
SELECT to_timestamp(1758268800);   -- Unix 秒

-- 时区转换
SELECT now() AT TIME ZONE 'UTC';
SELECT now() AT TIME ZONE 'America/New_York';
SELECT timezone('Asia/Shanghai', now());

-- 生成序列
SELECT generate_series('2026-09-01'::date, '2026-09-10', interval '1 day');

-- 时间差与构造
SELECT age(timestamp '2026-09-19', timestamp '2005-02-07');  -- 21 years 7 mons 12 days
SELECT make_date(2026, 9, 19);        -- 由 年/月/日 构造 date → 2026-09-19
SELECT make_interval(days => 10);     -- 由命名参数构造 interval → 10 days
```

> `make_interval(days => 10)` 里的 `=>` 是 **命名参数**写法:可以只给需要的那一项,其余默认 0。等价的可写 `make_interval(years => 1, days => 10)`。

**时间分桶:`date_bin`(PG14+)**

把时间轴按**固定步长**切成等长的桶,用于时间序列统计。

```sql
-- 签名:date_bin(步长 interval, 待归桶的时间, 起点) → 该桶的起点时间
SELECT date_bin(interval '15 min',
                timestamp '2026-09-19 10:37:42',
                timestamp '2000-01-01');
-- 2026-09-19 10:30:00   ← 10:37:42 属于 10:30~10:45 这个桶,返回桶起点

-- 典型用途:每 15 分钟统计单量
SELECT date_bin(interval '15 min', created_at, timestamp '2026-01-01') AS bucket,
       count(*) AS orders
FROM orders
GROUP BY 1
ORDER BY 1;
```

**与 `date_trunc` 的区别**:`date_trunc` 只能按日历单位(年/月/日/时/分)截断,且必然从自然边界起算;`date_bin` 可以指定**任意步长**(如 7 分钟、3 小时)和**任意起点**。

| 需求 | 该用哪个 |
|------|----------|
| 按自然日 / 月 / 年 / 小时 统计 | `date_trunc` |
| 按 15 分钟 / 7 天 等非自然步长 | `date_bin` |
| 按数值区间分桶(金额、年龄) | `width_bucket`,见 [[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.1-数值类型]] |
| 按行数均分(前后 25% 排名) | `ntile`,见 [[postgresql/02-中段阶段-专题精讲/窗口函数/语法与函数速查]] |

**时间范围查询的正确写法**

```sql
-- ✅ 推荐:半开区间,可用索引(索引内逐条比较)
WHERE created_at >= date_trunc('month', now())
  AND created_at <  date_trunc('month', now()) + interval '1 month'

-- ⚠️ 避免:对列做函数运算会导致普通索引失效
WHERE date_trunc('month', created_at) = date_trunc('month', now())
```

`date_trunc(列)` 属于**表达式索引**可以救的场景,见 [[postgresql/02-中段阶段-专题精讲/索引实战应用/索引类型选型与设计]]。

### 五、区间类型与时序约束

```sql
CREATE TABLE bookings (
    room  text,
    stay  tstzrange,
    EXCLUDE USING gist (room WITH =, stay WITH &&)   -- 同房间时间不得重叠
);

INSERT INTO bookings VALUES ('A', tstzrange(now(), now() + interval '2 hours'));
```

**PostgreSQL 18 新增**:基于范围的主键 / 唯一 / 外键**时序约束**,可直接对范围表达约束语义,简化排期类建模。

## 小结

- `timestamptz` 存 UTC 瞬时,显示随会话时区;`timestamp` 存钟面读数。**默认用 `timestamptz`。**
- `interval` 中"月/日"成分依赖具体日期,做分界线时优先 `date_trunc` 而非 `interval '1 month'`。
- `now()` 是事务开始时刻,`clock_timestamp()` 才是当前时刻。
- 时间范围查询用"半开区间 + 列不加函数",才能吃到索引。
