# 2.7 网络类型:inet / cidr / macaddr

## 学习目标

- 分清 `inet`、`cidr`、`macaddr` 三种类型各自适合什么
- 理解 `inet` 的中心语义:**地址 + 可选掩码**,以及为何用 `inet` 而非 `text` 存 IP
- 掌握包含(containment)等网络运算与索引方式
- 识别网络类型最典型的坑:V4/V6 混用、host 位、MA-C 地址归一化

## 前置知识

[[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.6-NULL语义与类型转换]]、[[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.1-数值类型]]

> 本类是**内置类型**,不属于任何扩展(无需 `CREATE EXTENSION`),出厂自带。

## 正文

### 一、三种类型与定位

| 类型 | 存储 | 语义 | 典型用途 |
|------|------|------|----------|
| `inet` | IPv4/IPv6 地址 + 可选掩码 | **一个主机地址**(可选带子网) | 记录客户端 IP、访问来源 |
| `cidr` | IPv4/IPv6 **网络**块 | 一个网络(掩码必填,host 位必须为 0) | 白名单网段、防火墙规则、归属判断 |
| `macaddr` | 6 字节 MAC | 物理网卡地址 | 设备标识、网络审计 |
| `macaddr8`(PG10+) | 8 字节(含 EUI-64) | 64 位 MAC | 兼容 IPv6 的 MAC |

**一句话选型**:存"某个具体 IP"用 `inet`;存"一段地址范围/网段"用 `cidr`;存网卡地址用 `macaddr`。三者都是**校验过的强类型**,能拒绝非法输入。

```sql
CREATE TABLE access_log (
    id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    client_ip inet    NOT NULL,
    req_path  text
);

INSERT INTO access_log (client_ip) VALUES ('192.168.1.5');         -- ✅ 接受
INSERT INTO access_log (client_ip) VALUES ('10.0.0.1/24');          -- ✅ 带掩码
INSERT INTO access_log (client_ip) VALUES ('999.1.1.1');            -- ❌ ERROR: invalid byte octet
```

### 二、为什么用 `inet` 而不是 `text`

这是最常见的问题。几条硬理由:

| 维度 | `text` 存 IP | `inet` |
|------|-------------|--------|
| 输入校验 | ❌ `'999.1.1.1'` 照收 | ✅ 非法地址直接报错 |
| 包含判断(是否属于某网段) | ❌ 需手写字符串/位运算 | ✅ 原生 `<<` 操作符 |
| 排序 | 字典序(错误) | ✅ 数值序 |
| 归一化 | ❌ 手写 | ✅ 自动:前导零去掉、IPv6 压缩 |
| 索引 | B-tree(无法按网段检索) | B-tree + GiST + SP-GiST |

```sql
-- text 的字典序是错的:'10.1.1.1' 会排在 '9.9.9.9' 之前
-- inet 按数值序,结果符合直觉
SELECT '9.9.9.9'::inet > '10.1.1.1'::inet;   -- t
```

> **经验**:IP 一律用 `inet`。等到要用 `WHERE ip <<= '10.0.0.0/8'` 判断内网时,再想把 `text` 迁过去就很痛苦了。

### 三、输入与归一化

`inet` / `cidr` 输入均接受 IPv4、IPv6,可带 `<掩码长度>`(:ex: `/24`)。PostgreSQL 会把值**规范化为标准形式**:IPv4 每段在 **1–999(不带前导零)**;IPv6 用 `::` 压缩;IPv4 地址在 IPv6 中可写为 IPv4-mapped 形式。

```sql
SELECT '192.168.001.005'::inet;       -- 192.168.1.5   (去掉前导零)
SELECT '192.168.1.5/255.255.255.0'::inet;  -- 192.168.1.5/24 (子网掩码自动转 CIDR 长度)
SELECT '::ffff:192.168.1.5/24'::inet;  -- ::ffff:192.168.1.5/24 (IPv4-mapped IPv6)
```

**`cidr` 的严格要求**:host 位(掩码右侧的位)**必须全为 0**,否则报错——因为它代表的是"网段"而非"某个地址"。

```sql
SELECT '192.168.1.0/24'::cidr;    -- ✅ 192.168.1.0/24
SELECT '192.168.1.5/24'::cidr;    -- ERROR: invalid cidr value (host bits should not be set)
```

而 `inet` 允许 host 位非 0,并且在做**包含判断时忽略 host 位**(`network()` 会截断)。

> **差异本质**:`inet` 关注"这个地址落在哪个网段里";`cidr` 本身就是"网段"。需要"判断归属"用 `inet` + `<<`;需要表达"一段合法网段"用 `cidr`。

### 四、常用函数

| 函数 | 作用 | 例子 |
|------|------|------|
| `host(inet)` | 去掉掩码,只取地址 | `host('192.168.1.5/24')` → `192.168.1.5` |
| `network(inet)` | 取网络部分 | `network('192.168.1.5/24')` → `192.168.1.0/24` |
| `broadcast(inet)` | 广播地址 | `broadcast('192.168.1.5/24')` → `192.168.1.255` |
| `netmask(inet)` / `hostmask()` | 掩码 / 反掩码 | `netmask('192.168.1.5/24')` → `255.255.255.0` |
| `masklen(inet)` | 掩码长度 | `masklen('192.168.1.5/24')` → `24` |
| `family(inet)` | 地址族:4 或 6 | `family('::1')` → 6 |
| `abbrev()` / `text()` | 展示 / 转换 | `abbrev('192.168.1.5/24')` → `192.168.1.5/24` |
| `set_masklen(inet,int)` | 改掩码长度后返回新 inet | `set_masklen('10.0.0.5'::inet, 8)` |
| `trunc(inet)` | 置零 host 位(当网络用) | `trunc('192.168.1.5/24'::inet)` → `192.168.1.0/24` |

```sql
SELECT host('192.168.1.5/24'),
       network('192.168.1.5/24'),
       broadcast('192.168.1.0/24'),
       masklen('192.168.1.5/24'),
       family('::1');
-- 192.168.1.5 | 192.168.1.0/24 | 192.168.1.255 | 24 | 6
```

### 五、包含与比较运算

网络类型最值钱的能力是**包含判断**——判断某个 IP 是否属于某个网段。

| 操作符 | 含义 |
|--------|------|
| `<<` | 地址(或网段)**被包含于**某网段 |
| `>>` | 地址**包含**某网段(反向) |
| `<<=` | 被包含**或相等** |
| `>>=` | 包含**或相等** |
| `&&` | 两个网段**有重叠**(任一地址相同即真) |
| `=` | 地址与掩码完全相同 |
| `+` / `-` | 把某个 8 位整数加到地址各段 / 相减 |
| `&` / `\|` / `~` | 逐位 AND / OR / NOT |

```sql
-- 经典用法:判断内网 / 白名单
SELECT '192.168.1.5'::inet << '192.168.1.0/24'::inet;   -- t
SELECT '10.0.0.9'::inet  << '10.0.0.0/8'::inet;          -- t
SELECT '8.8.8.8'::inet   << '10.0.0.0/8'::inet;          -- f

-- <<= 与 << 的区别:边界相等
SELECT '192.168.1.0/24'::inet <<  '192.168.1.0/24'::inet;   -- f
SELECT '192.168.1.0/24'::inet <<= '192.168.1.0/24'::inet;   -- t

-- 网段重叠
SELECT '192.168.1.0/25'::inet && '192.168.1.128/25'::inet;  -- f(各占一半,不重叠)
SELECT '192.168.1.0/24'::inet && '192.168.1.0/25'::inet;    -- t

-- host 位在包含判断中被忽略(inet 只看 network 那部分)
SELECT '192.168.1.200'::inet << '192.168.1.0/24'::inet;     -- t
```

> **关键认知**:对 `inet` 做 `<<` 时,比较的是它的**网络部分**,与 `host()` 里填的具体主机号无关。这就是为什么"存具体 IP + 判归属"可以一步到位。

**不同地址族(V4/V6)的比较**:`family()` 不同时,比较/包含结果如何?

```sql
-- 比较:PG 规定 IPv4 排在 IPv6 之前(数值上更小),可比较不报错
SELECT '192.168.1.1'::inet < '::1'::inet;    -- t

-- 包含:不同族的网段互不包含(结果是 f,而非报错)
SELECT '::1'::inet << '0.0.0.0/0'::inet;     -- f
SELECT '::/0'::inet << '0.0.0.0/0'::inet;    -- f
```

> V4 与 V6 **不能互相归属判断**。想要"V4 中的 `10/8`"之类规则同时涵盖映射地址,需显式用 IPv4-mapped 形式或应用层拆分,别指望 `<<` 跨族。

### 六、索引

网络类型支持三种索引,按需选择:

| 索引方法 | 支持的查询 | 适用 |
|----------|-----------|------|
| **B-tree** | 排序、`=`、范围 | 按 IP 精确/区间过滤、排序 |
| **GiST** / **SP-GiST** | `<<` `>>` `<<=` `>>=` `&&` | **按网段归属查询**(最常用) |
| GIN(仅配合 `inet_ops`) | 其他场景较少 | 一般不用于网络类型 |

```sql
-- 按网段归属查询必须配 GiST 或 SP-GiST(否则全表扫 + 逐行算)
CREATE INDEX ON access_log USING gist (client_ip inet_ops);

-- 之后"某网段内有谁 / 集体是否落入白名单"走索引
EXPLAIN SELECT * FROM access_log
WHERE client_ip <<= '10.0.0.0/8';          -- Bitmap Index Scan on ... (gist)

-- 若只要等值/排序,普通 B-tree 即可
CREATE INDEX ON access_log (client_ip);
```

> 规划器会根据查询选择。**混合场景可建两个**:GiST(归属)+ B-tree(等值排序),代价只是写放大翻倍。

### 七、macaddr 与 macaddr8

```sql
CREATE TABLE devices (
    id   bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    mac  macaddr NOT NULL
);

INSERT INTO devices (mac) VALUES ('08:00:2b:01:02:03');   -- ✅
INSERT INTO devices (mac) VALUES ('08-00-2b-01-02-03');    -- ✅ 连字符也被接受
INSERT INTO devices (mac) VALUES ('08:00:11:22:33:44:55:66'); -- ❌ 6 字节写 8 组报错
```

**特点与陷阱**

- 归一化:输出统一为**小写、冒号分隔**的规范形式(`08:00:2b:01:02:03`),不受输入写法影响。
- **匹配时忽略位 0 的组播/单播位**:MAC 比较忽略地址的"第 8 位"(2 的 7 次方位)与"第 6 位"…… 即 `08:00:2b...` 与 `09:00:2b...` 可能被判相等,因为这几位无关紧要。
- `macaddr8` 用 64 位,可表示 EUI-64(常由 MAC-48 加 FFFE 扩展而成)。
- 若要精确字符串匹配(如按"厂商 OUI"过滤),可用 `substr(mac::text,1,8)` 或直接对 `text` 化后的前缀做判断。

```sql
-- 常见误用预警:若业务里"必须严格区分两个 MAC",注意上述忽略位的语义
SELECT '08:00:2b:01:02:03'::macaddr = '09:00:2b:01:02:03'::macaddr;
-- 可能返回 t(取决于具体实现是否忽略特定位),详见官方文档
```

## 小结

- `inet` = 地址(+ 可选掩码),是最常用的 IP 类型;`cidr` = 网段(host 位必须为 0);`macaddr` = 网卡地址。
- 存 IP **用 `inet` 而非 `text`**:自带校验、数值排序、`<<` 归属判断、归一化。
- 归属判断用 `<<`/`<<=`,**必须建 GiST 或 SP-GiST 索引**,否则全表扫。
- `inet` 的 host 位在包含判断中会被忽略;V4/V6 **不能跨族**判断归属。
- `macaddr` 输出归一化,且比较会忽略特定位——需精确匹配要注意。

## 练习

1. 建一张 `access_log`(含 `client_ip inet`),插入 `'10.0.0.7'`、`'192.168.1.200'`、`'::1'`,分别用 `<<=` 判断三者是否属于 `10.0.0.0/8`。
2. 给 `client_ip` 建一个 GiST 索引,用 `EXPLAIN` 验证 `WHERE client_ip <<= '10.0.0.0/8'` 走索引;再对比不带索引时的 `Seq Scan`。
3. 尝试 `SELECT '192.168.001.005'::inet` 与 `SELECT '192.168.1.5/255.255.255.0'::inet`,确认其归一化输出。
4. 用 `macaddr` 插入 `'08-00-2b-01-02-03'`,观察输出;再验证 `08:00:2b:01:02:03` 与 `09:00:2b:01:02:03` 是否判等(理解忽略位语义)。
