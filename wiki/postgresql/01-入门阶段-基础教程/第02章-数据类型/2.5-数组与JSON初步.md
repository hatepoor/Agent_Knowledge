## 正文

### 一、数组

PostgreSQL 的数组是**类型的一部分**,任何基础类型都可用 `[]` 变长数组。

```sql
CREATE TABLE products (
    id   bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name text NOT NULL,
    tags text[] NOT NULL DEFAULT '{}'          -- 或 ARRAY[]::text[]
);

-- 插入
INSERT INTO products (name, tags) VALUES
  ('键盘',   ARRAY['数码','外设']),
  ('咖啡豆', '{食品,饮品}'),                   -- 字符串字面量形式
  ('鼠标',   ARRAY['数码','外设','热销']);
```

**下标从 1 开始**,这是与多数编程语言的第一处差异:

```sql
SELECT tags[1], tags[1:2] FROM products;   -- 切片用 [下界:上界]
SELECT array_length(tags, 1), cardinality(tags) FROM products;
```

**运算符**

| 运算符 | 含义 | 示例 |
|--------|------|------|
| `@>` | 包含(左含右) | `'{a,b,c}'::text[] @> '{a}'::text[]` → `true` |
| `<@` | 被包含 | `'{a}'::text[] <@ '{a,b,c}'::text[]` → `true` |
| `&&` | 数组有交集 | `'{a,b}'::text[] && '{b,c}'::text[]` → `true` |
| `\|\|` | 拼接 | `'{a}'::text[] \|\| '{b}'::text[]` → `{a,b}` |
| `=` | 逐元素相等且维度一致 | 注意:顺序敏感 |

```sql
-- 查询:包含某标签
SELECT * FROM products WHERE tags @> ARRAY['数码'];

-- = ANY(数组):某值等于数组中"任一"元素 → 结果是布尔
SELECT * FROM products WHERE '数码' = ANY(tags);
-- <> ALL(数组):某值不等于数组中"所有"元素(即"不包含")→ 结果是布尔
SELECT * FROM products WHERE '热销' <> ALL(tags);

-- unnest:表函数。把数组展开成多行(数组有几个元素就产生几行)
SELECT id, unnest(tags) AS tag FROM products;

-- array_agg:聚合函数。把多行的某个值收集成一个数组
SELECT array_agg(name ORDER BY name) FROM products;
--              ↑ ORDER BY 写在函数内部,决定数组元素的顺序;不写则顺序不确定

-- array_append / array_remove:追加一个元素 / 移除"所有"等于该值的元素
SELECT array_append(tags, '新') FROM products;
SELECT array_remove(tags, '数码') FROM products;

-- array_position:元素"首次"出现的下标(从 1 开始);元素不存在时返回 NULL
-- array_positions:元素"所有"出现的下标,返回一个数组
SELECT array_position(tags, '外设')  AS 首次出现位置,
       array_positions(tags, '外设') AS 全部出现位置
FROM products;
```

> **`@>` 与 `= ANY` 的区别(最容易混淆的一处)**
>
> | 写法 | 语义 | 多元素时 |
> |------|------|----------|
> | `tags @> ARRAY['a','b']` | tags 是否**同时包含** a 和 b | 要求**全部**包含 |
> | `'a' = ANY(tags)` | 数组里**是否存在**元素等于 a | 只能匹配**单个值**(要"或"就写 `tags && ARRAY['a','b']`) |
>
> 单元素查找时两者结果相同,但**思考方向相反**:`@>` 是"容器包含元素",`= ANY` 是"元素在容器里"。多元素场景下绝不可互换。完整对比如 [[postgresql/02-中段阶段-专题精讲/数组范围与枚举/专题概览]]。

**数组 vs 规范化子表**

| 维度 | 数组列 | 子表(1:N) |
|------|--------|-----------|
| 查询 | 简单,`@>` 一个条件搞定 | 需 JOIN |
| 可索引 | ✅ GIN 索引支持 `@>`/`&&` | ✅ 普通 B-tree |
| 元数据 | ❌ 元素无法携带额外字段 | ✅ 可有列 |
| 更新粒度 | 整列更新 | 单行更新 |
| 统计/约束 | 弱 | 强(外键、检查约束) |

**选型判据**:标签、分类、固定数量的小集合 → 数组;需要"每个元素带属性"(如订单行有数量、单价)→ 子表。

数组的 GIN 索引见 [[postgresql/02-中段阶段-专题精讲/索引实战应用/索引类型选型与设计]]。

### 二、复合类型(composite)

把若干字段组合成一个**自定义类型**,可以直接用作列类型。

```sql
CREATE TYPE address AS (
    city    text,
    street  text,
    zip     text
);

CREATE TABLE customers (
    id   bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name text,
    addr address
);

INSERT INTO customers (name, addr) VALUES ('Ann', ROW('北京','中山路1号','100000'));

-- 访问字段:需要括号包裹
SELECT (addr).city, (addr).zip FROM customers;
SELECT name FROM customers WHERE (addr).city = '北京';
```

> **注意点**:复合类型字段的 NULL 语义可以整体为 NULL。`(addr).city` 的括号**不能省略**,否则解析器会把 `addr` 当成表名。

**表也可以当类型用**:

```sql
SELECT ROW(u.*)::users FROM users u LIMIT 1;   -- 行类型
```

嵌套复合类型在实战中**较少使用**——多数情况下用 JSONB 更灵活,或用子表更规范。它的价值主要在:函数返回多列、游标、以及需要严格列约束的"值对象"。

### 三、域(domain):给基础类型加约束

域 = 基础类型 + 约束 + 默认值,是**可复用的类型别名**。

```sql
CREATE DOMAIN email AS text
    CHECK (VALUE ~ '^[^@\s]+@[^@\s]+\.[^@\s]+$');

CREATE DOMAIN positive_amount AS numeric(12,2)
    CHECK (VALUE > 0);

CREATE TABLE accounts (
    id      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    contact email,
    balance positive_amount
);

INSERT INTO accounts (contact, balance) VALUES ('bad-email', 10);  -- ERROR: violates check constraint
```

**域 vs CHECK 约束**

| 维度 | 域 | 列级 CHECK |
|------|-----|-----------|
| 复用 | ✅ 多处复用同一规则 | ❌ 每列各写一遍 |
| 修改 | 改一处,所有列生效(但仍需校验存量) | 需逐列修改 |
| 类型显示 | 显示为域名(工具需解析) | 显示为基础类型 |
| 适用 | 跨表统一的值域(邮箱、金额、百分比) | 单表特化规则 |

> **域的实际收益**:除了复用,域还能在**函数参数**上做类型级约束,这是列约束做不到的。

### 四、JSON 与 JSONB 初步

| 类型 | 存储 | 保留格式 | 支持索引 | 重复键 | 键顺序 |
|------|------|----------|----------|--------|--------|
| `json` | 原始文本 | ✅ 空格/换行/键序原样 | ❌ | 保留 | 保留 |
| `jsonb` | 二进制解析 | ❌ 规范化 | ✅ GIN | 后写覆盖前写 | 不保留 |

```sql
CREATE TABLE events (
    id      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    payload jsonb NOT NULL,
    raw     json
);

INSERT INTO events (payload, raw)
VALUES ('{"b":1,"a":2,"a":3}', '{"b":1,"a":2,"a":3}');

SELECT payload FROM events;   -- {"a": 3, "b": 1}   ← 去重、键排序
SELECT raw     FROM events;   -- {"b":1,"a":2,"a":3} ← 原样
```

**初学阶段的结论**:除"必须原样保留文本"(如审计原文、签名校验)外,**一律用 `jsonb`**。理由:支持索引、支持操作符、写入时即校验合法性。

```sql
SELECT payload->'a'      FROM events;   -- jsonb 值(带引号)
SELECT payload->>'a'     FROM events;   -- text 值
SELECT payload#>>'{x,y}' FROM events;   -- 路径取值转 text
SELECT jsonb_typeof(payload) FROM events;
```

操作符、函数、索引与 SQL/JSON 路径语法见 [[postgresql/02-中段阶段-专题精讲/JSON与JSONB/专题概览]]。

> **PG14+ 下标写法**:可直接用 `payload['a']` 与 `payload['items'][0]` 取值,可读性优于 `->`/`->>` 链。

## 小结

- 数组是类型的一部分,下标从 1 开始;`@>` 适合"包含"查询,`= ANY(...)` 适合"存在"查询。
- 复合类型适合严格的值对象,但实战中更常用 JSONB 或子表。
- 域 = 可复用的带约束类型,适合跨表统一的值域。
- `jsonb` 是默认选择,`json` 只用于保留原始文本。
