# 2.1 数值类型

## 学习目标

- 分清整数、精确小数、浮点、自增四类数值的适用场景
- 记住 `numeric` 与 `double precision` 的正确选择边界
- 掌握自增列的正确写法(`IDENTITY` 优于 `serial`)

## 前置知识

## 正文

### 一、类型全景

| 类型 | 存储 | 范围 / 精度 | 用途 |
|------|------|-------------|------|
| `smallint` (int2) | 2 字节 | -32768 ~ 32767 | 小范围枚举计数 |
| `integer` (int4) | 4 字节 | -2.1e9 ~ 2.1e9 | **默认整数选择** |
| `bigint` (int8) | 8 字节 | -9.2e18 ~ 9.2e18 | 主键、计数、时间戳整数 |
| `numeric(p,s)` / `decimal` | 变长 | 精确,支持任意精度 | **金额、需精确的小数** |
| `real` (float4) | 4 字节 | 约 6 位十进制有效数字 | 科学计算、近似值 |
| `double precision` (float8) | 8 字节 | 约 15 位十进制有效数字 | 科学计算 |
| `money` | 8 字节 | 依赖 `lc_monetary` 区域 | **不推荐**(区域相关,行为不直观) |

### 二、整数:该选哪个

```sql
CREATE TABLE t_int (
    a smallint,
    b integer,
    c bigint
);
```

**选择原则**

1. 不确定就用 `integer`。
2. **主键用 `bigint`**:业务量增长后 `integer` 溢出是灾难性事故,`bigint` 的额外 4 字节不值得省。
3. `smallint` 只在字段语义天然很小时用(如 `priority smallint`)。

整数运算溢出会**直接报错**,而不是静默回绕——这是好事:

```sql
SELECT 32767::smallint + 1;   -- ERROR: smallint out of range
```

**取整与整除**

```sql
SELECT 7 / 2;          -- 3    整数除法,丢弃小数(不是 3.5!)
SELECT 7 % 2;          -- 1    取余
SELECT 7::numeric / 2; -- 3.5  转 numeric 后才是真实除法
SELECT div(7, 2);      -- 3    整除的函数写法,等价于 7 / 2
SELECT mod(7, 2);      -- 1    取余的函数写法,等价于 7 % 2
```

> **高频坑**:`SELECT sum(x)/count(*)` 在整数列上会做整数除法。要平均值必须显式转 `numeric` 或 `::float8`。

**取整函数**

```sql
SELECT round(3.7);        -- 4    四舍五入
SELECT round(3.14159, 2); -- 3.14 保留 2 位小数
SELECT trunc(3.7);        -- 3    直接截断(不四舍五入)
SELECT ceil(3.2);         -- 4    向上取整(也可写 ceiling)
SELECT floor(3.8);        -- 3    向下取整
SELECT abs(-5);           -- 5    绝对值
```

> **注意 `round` 与 `trunc` 的差别**:两者在正数上结果不同(`round(3.7)=4`,`trunc(3.7)=3`)。做金额计算时先明确业务要的是"四舍五入"还是"截断"。

### 三、数值分桶:`width_bucket`

这是一个**独立于取整/整除**的能力:把连续的数值映射到**若干个等宽区间(桶)** 上。做直方图、数值分段统计时必须用它。

```sql
-- 签名:width_bucket(要分桶的值, 区间下界, 区间上界, 桶数量) → 桶号(从 1 开始)
-- 规则:把 [下界, 上界) 等分成 n 份,返回值落在第几个桶
--       值 < 下界     → 返回 0
--       值 >= 上界    → 返回 n + 1

SELECT width_bucket(5, 0, 10, 5);   -- 3
```

上例的分桶过程(区间宽 = (10 − 0) ÷ 5 = 2):

| 桶号 | 区间 |
|------|------|
| 1 | `[0, 2)` |
| 2 | `[2, 4)` |
| 3 | `[4, 6)` ← 5 落在这里 |
| 4 | `[6, 8)` |
| 5 | `[8, 10]` |

边界情况:

```sql
SELECT width_bucket(-1, 0, 10, 5);   -- 0   低于下界
SELECT width_bucket(99, 0, 10, 5);   -- 6   高于等于上界(桶数 + 1)
```

**典型用途:等宽直方图**

```sql
-- 把订单金额按 10 档统计分布
SELECT width_bucket(amount, 0, 1000, 10) AS bucket,
       count(*)                          AS orders,
       min(amount)                       AS 区间最小,
       max(amount)                       AS 区间最大
FROM orders
GROUP BY 1
ORDER BY 1;
```

> **三个"分桶"函数不要混淆**(它们的分桶依据不同):
>
> | 函数 | 分桶依据 | 桶的大小 |
> |------|----------|----------|
> | `width_bucket` | **数值范围** | 各桶**数值宽度相等** |
> | `date_bin`(PG14+) | **时间范围** | 各桶**时长相等** |
> | `ntile(n)`(窗口函数) | **行数** | 各桶**行数相近**,但数值宽度不等 |
>
> `date_bin` 见 [[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.3-日期时间类型]],`ntile` 见 [[postgresql/02-中段阶段-专题精讲/窗口函数/语法与函数速查]]。

**其他常用数值函数**

```sql
SELECT power(2, 10);   -- 1024  幂运算
SELECT sqrt(16);       -- 4     平方根
SELECT random();       -- 0.735...  [0,1) 之间的随机浮点
SELECT greatest(1, 9, 3);  -- 9   取最大值(忽略 NULL)
SELECT least(1, 9, 3);     -- 1   取最小值
```

### 四、numeric 与 float:核心取舍

这是数值类型中最重要的一次选择。

```sql
-- numeric:精确十进制,金额必用
SELECT 0.1::numeric + 0.2::numeric = 0.3::numeric;   -- true

-- double precision:IEEE 754 二进制浮点,存在表示误差
SELECT 0.1::float8 + 0.2::float8 = 0.3::float8;      -- false
SELECT 0.1::float8 + 0.2::float8;                    -- 0.30000000000000004
```

**取舍表**

| 维度 | `numeric` | `double precision` |
|------|-----------|--------------------|
| 精度 | 精确 | 近似(IEEE 754) |
| 运算速度 | 慢(软件实现) | 快(硬件浮点) |
| 存储 | 变长,精度越高越大 | 固定 8 字节 |
| 适用 | 金额、税率、需对账的数 | 科学计算、统计、坐标 |

`numeric` 的精度声明是 `numeric(precision, scale)`:总位数、小数位数。

```sql
CREATE TABLE prices (
    amount numeric(12, 2)   -- 最多 12 位有效数字,其中 2 位小数 → 最大 9999999999.99
);

INSERT INTO prices VALUES (1.005);   -- 存入 1.01(四舍五入到 scale)
SELECT 1.2345::numeric(6,2);         -- 1.23
```

特殊值:

```sql
SELECT 'NaN'::numeric, 'Infinity'::double precision, '-Infinity'::double precision;
```

`NaN` 在 `numeric` 中可用,且 `NaN = NaN` 为 `true`(与 float 标准不同,PostgreSQL 按"大于一切"排序)。

### 五、自增列:用 IDENTITY,不要用 serial

`serial` / `bigserial` 是**历史写法**,它实际是三件事的组合:建序列 + 设默认值 + 建立依赖。它有三个问题:序列归属不清晰、权限继承复杂、`pg_dump` 恢复时易踩坑。

**推荐写法(PG10+ 标准 SQL)**:

```sql
CREATE TABLE users (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    ...
);

-- 允许手工插入(使用序列默认值)
CREATE TABLE logs (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
);
```

| 写法 | 行为 |
|------|------|
| `GENERATED ALWAYS AS IDENTITY` | 默认拒绝手工赋值,需 `OVERRIDING SYSTEM VALUE` 才能插入指定值(**推荐**) |
| `GENERATED BY DEFAULT AS IDENTITY` | 允许手工赋值(数据迁移时方便) |
| `serial` / `bigserial` | 旧写法,仅用于兼容既有代码 |

手工覆盖 `ALWAYS` 列:

```sql
INSERT INTO users (id, email, name)
OVERRIDING SYSTEM VALUE VALUES (100, 'a@b.c', 'Ann');
```

序列操作:

```sql
SELECT currval('users_id_seq');            -- 当前值(需本会话先 nextval)
SELECT nextval('users_id_seq');            -- 推进并返回
SELECT setval('users_id_seq', 1000, true); -- 重置
```

> **IDENTITY 列对应的序列名**:`<table>_<column>_seq`,可用 `pg_get_serial_sequence('users','id')` 查询。

### 六、位运算与其他

```sql
SELECT 5 & 3, 5 | 3, 5 # 3, ~5;      -- 与、或、异或、取反
SELECT 1 << 3, 16 >> 2;              -- 位移
SELECT bit_length(5), octet_length(5);
```

PG18 新增单字节 XOR 与 NAND 位运算符。若需**固定长度位串**,用 `bit(n)` / `bit varying(n)` 类型,而非整数位运算。

## 小结

- 整数:默认 `integer`,主键用 `bigint`,`smallint` 只用于语义天然小的字段。
- 精度:`numeric` 精确但慢,用于金额;`double precision` 快但近似,用于科学计算。**金额永远不要用 float。**
- 自增:用 `GENERATED ALWAYS AS IDENTITY`,不要再用 `serial`。
- 整数除法会丢小数,求平均值务必显式转型。
