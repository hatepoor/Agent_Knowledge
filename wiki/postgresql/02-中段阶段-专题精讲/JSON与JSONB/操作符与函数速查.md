# JSON / JSONB · 操作符与函数速查

## 一、操作符总表

| 操作符 | 左 | 右 | 返回 | 示例 |
|--------|----|----|------|------|
| `->` | jsonb | int / text | jsonb | `'{"a":1}'::jsonb -> 'a'` → `1` |
| `->>` | jsonb | int / text | text | `'{"a":1}'::jsonb ->> 'a'` → `'1'` |
| `#>` | jsonb | text[] | jsonb | `'{"a":{"b":2}}'::jsonb #> '{a,b}'` → `2` |
| `#>>` | jsonb | text[] | text | 同上 → `'2'` |
| `@>` | jsonb | jsonb | bool | `'{"a":1,"b":2}' @> '{"a":1}'` → `t` |
| `<@` | jsonb | jsonb | bool | 反向包含 |
| `?` | jsonb | text | bool | `'{"a":1}' ? 'a'` → `t` |
| `?\|\|` 写作 `?\|` | jsonb | text[] | bool | `?\| array['a','z']` |
| `?&` | jsonb | text[] | bool | `?& array['a','b']` |
| `-\|` 写作 `-` | jsonb | text / int | jsonb | 删除键 / 删除数组下标 |
| `-\|\|` 写作 `#-` | jsonb | text[] | jsonb | 按路径删除 |
| `\|\|` | jsonb | jsonb | jsonb | 浅合并 / 数组拼接 |

> **`-` 的两种语义**:右侧是文本 → 删键;右侧是整数 → 删数组元素(负数从右往左)。

```sql
SELECT '{"a":1,"b":2}'::jsonb - 'a';               -- {"b": 2}
SELECT '[1,2,3]'::jsonb - 1;                       -- [1, 3]
SELECT '[1,2,3]'::jsonb - -1;                      -- [1, 2]
SELECT '{"a":{"b":2,"c":3}}'::jsonb #- '{a,b}';    -- {"a": {"c": 3}}
```

## 二、构造与转换

| 函数 | 作用 |
|------|------|
| `to_json(anyelement)` / `to_jsonb(...)` | 任意值 → json / jsonb |
| `json_build_object(k1,v1,...)` / `jsonb_build_object(...)` | 构造对象 |
| `json_build_array(...)` / `jsonb_build_array(...)` | 构造数组 |
| `json_object(keys text[], values text[])` / `jsonb_object(...)` | 由两个数组构造对象 |
| `json_agg(x)` / `jsonb_agg(x)` | 聚合为数组 |
| `json_object_agg(k, v)` / `jsonb_object_agg(k, v)` | 聚合为对象 |
| `row_to_json(row)` / `to_jsonb(row)` | 行 → json |
| `jsonb_populate_record(t, j)` | jsonb → 某个行类型 |
| `jsonb_populate_recordset(t, j)` | jsonb 数组 → 行集合 |
| `jsonb_to_record(j)` / `jsonb_to_recordset(j)` | jsonb → 记录(**推荐**) |
| `json_typeof(j)` / `jsonb_typeof(j)` | 类型名 |
| `json_array_length(j)` / `jsonb_array_length(j)` | 数组长度 |
| `json_strip_nulls(j)` / `jsonb_strip_nulls(j)` | 删除值为 NULL 的键 |
| `jsonb_pretty(j)` | 美化输出(调试用) |

```sql
SELECT jsonb_build_object('a', 1, 'b', 'x');
SELECT jsonb_agg(jsonb_build_object('id', id, 'amt', total)) FROM orders;
SELECT jsonb_pretty(to_jsonb(ROW(1,'a')));
SELECT jsonb_populate_record(NULL::users, '{"email":"a@b.c","name":"A"}');
```

## 三、展开函数

| 函数 | 作用 |
|------|------|
| `jsonb_each(j)` | → `(key, value jsonb)` 多行 |
| `jsonb_each_text(j)` | → `(key, value text)` |
| `jsonb_object_keys(j)` | → 键多行 |
| `jsonb_array_elements(j)` | 数组 → 元素(jsonb) |
| `jsonb_array_elements_text(j)` | 数组 → 元素(text) |
| `json_to_record(j)` / `jsonb_to_record(j)` | 按列定义展开一行 |
| `jsonb_to_recordset(j)` | 按列定义展开多行 |

```sql
-- 展开对象
SELECT id, k, v FROM events, jsonb_each_text(payload) AS x(k, v);

-- 展开数组
SELECT id, e->>'sku' AS sku, (e->>'qty')::int AS qty
FROM orders o, jsonb_array_elements(o.payload->'items') AS e;

-- 展开为强类型列(推荐,替代逐个 -> 取值)
SELECT id, r.sku, r.qty, r.price
FROM orders o,
     jsonb_to_recordset(o.payload->'items') AS r(sku text, qty int, price numeric);
```

> **`jsonb_to_record` 系列的价值**:一次性把 JSONB 展开成**带类型的列**,避免写一堆 `(x->>'a')::int`,并且能与 JOIN/GROUP BY 自然配合。

## 四、修改函数

| 函数 | 作用 |
|------|------|
| `jsonb_set(target, path, new, [create_if_missing])` | 设置路径的值 |
| `jsonb_insert(target, path, new, [insert_after])` | 在数组位置插入 |
| `jsonb_pretty` | 美化 |
| `jsonb || jsonb` | 浅合并 |

```sql
-- 设置(路径存在)
SELECT jsonb_set('{"a":{"b":1}}', '{a,b}', '2');
-- {"a": {"b": 2}}

-- 创建缺失路径需要 create_if_missing=true(默认 true)
SELECT jsonb_set('{"a":{}}', '{a,b}', '2', true);

-- 数组插入:默认插到指定下标之前
SELECT jsonb_insert('{"i":[1,3]}', '{i,1}', '2');
-- {"i": [1, 2, 3]}

-- 浅合并:同名顶层键被右侧覆盖
SELECT '{"a":1,"b":2}'::jsonb || '{"b":9,"c":3}'::jsonb;
-- {"a": 1, "b": 9, "c": 3}
```

**深合并需要自己实现**(原生 `||` 是浅合并):

```sql
-- 简化的递归深合并(PG14+ 可用 plpgsql 或应用层实现)
CREATE OR REPLACE FUNCTION jsonb_deep_merge(a jsonb, b jsonb)
RETURNS jsonb LANGUAGE sql IMMUTABLE AS $$
  SELECT CASE
    WHEN jsonb_typeof(a) <> 'object' OR jsonb_typeof(b) <> 'object' THEN b
    ELSE (
      SELECT jsonb_object_agg(k, v)
      FROM (
        SELECT k, jsonb_deep_merge(
                 coalesce(a->k, 'null'::jsonb), coalesce(b->k, 'null'::jsonb)) AS v
        FROM (SELECT DISTINCT k FROM (
                SELECT jsonb_object_keys(a) AS k
                UNION SELECT jsonb_object_keys(b)) u) ks
      ) s
    )
  END
$$;
```

## 五、SQL/JSON 路径表达式速查

```sql
-- 基本
jsonb_path_query(j, '$.a.b')
jsonb_path_query(j, '$.items[0]')
jsonb_path_query(j, '$.items[*].name')
jsonb_path_query(j, '$.*')                 -- 对象所有值
jsonb_path_query(j, '$..name')             -- 递归
jsonb_path_query(j, '$.items[1 to 3]')     -- 切片

-- 过滤
jsonb_path_query(j, '$.items[*] ? (@.qty > 2)')
jsonb_path_query(j, '$.items[*] ? (@.qty > $min)', '{"min":2}')
jsonb_path_query(j, '$.items[*] ? (@.name starts with "A")')
jsonb_path_query(j, '$.items[*] ? (@.name like_regex "^A" flag "i")')

-- 存在性 / 首值 / 数组
jsonb_path_exists(j, '$.items[*] ? (@.qty > 10)')
jsonb_path_query_first(j, '$.items[0]')
jsonb_path_query_array(j, '$.items[*].qty')

-- 严格与宽松
jsonb_path_query(j, 'strict $.a')     -- 缺失则报错
jsonb_path_query(j, 'lax $.a')        -- 缺失返回空(默认)

-- 谓词与逻辑
'? (@.a && @.b)'        -- 与
'? (@.a || @.b)'        -- 或
'? (!(@.a))'            -- 非
'? (@.qty > 1 && @.sku != null)'
```

**`jsonb_path_match`**(返回布尔,路径需为单一谓词):

```sql
SELECT jsonb_path_match(payload, 'exists($.items[*] ? (@.qty > 5))');
```

## 六、可用的索引与对应查询写法

| 查询写法 | 需要的索引 |
|----------|-----------|
| `payload @> '{"a":1}'` | `GIN (payload)` 或 `GIN (payload jsonb_path_ops)` |
| `payload ? 'a'` | `GIN (payload)`(默认 `jsonb_ops`) |
| `payload->>'a' = '1'` | `BTREE ((payload->>'a'))` |
| `(payload->>'n')::int > 5` | `BTREE (((payload->>'n')::int))` |
| `jsonb_path_exists(...)` | `GIN (payload)`(部分谓词可命中) |

## 七、性能注意

```sql
-- 1) 避免在 JOIN/GROUP 里反复取值,先展开为强类型列
SELECT * FROM (
    SELECT id, jsonb_to_record(payload) AS r(...)  FROM events
) x;

-- 2) 表达式索引必须与查询表达式完全一致
CREATE INDEX ON events ((payload->>'city'));
SELECT * FROM events WHERE payload->>'city' = 'BJ';         -- ✅
SELECT * FROM events WHERE (payload->>'city') = 'BJ';        -- ✅ 括号等价
SELECT * FROM events WHERE payload @> '{"city":"BJ"}';       -- ❌ 不走该索引

-- 3) 统计信息不足会误估行数
CREATE STATISTICS events_city_stat ON (payload->>'city') FROM events;
ANALYZE events;

-- 4) 键数量过多时 GIN 索引可能变得很大
SELECT pg_size_pretty(pg_relation_size('events_payload_gin'));
```
