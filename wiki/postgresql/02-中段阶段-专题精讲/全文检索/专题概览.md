# 全文检索 · 专题概览

## 专题定位

PostgreSQL 内置全文检索(FTS),能力介于 `LIKE` 与专用搜索引擎(Elasticsearch)之间。

**何时该翻这个专题**

- 站内搜索、文档检索、日志关键词
- `LIKE '%x%'` 太慢且不支持词法
- 需要"相关性排序"

**能力边界**

| 能做 | 不能做 |
|------|--------|
| 词法切分、词干还原、停用词 | 中文分词(需扩展) |
| 布尔检索(AND/OR/NOT/短语) | 复杂相关性调优(如 BM25 细粒度) |
| 高亮、排名 | 分布式检索 |
| GIN 索引加速 | 拼写纠错(需 pg_trgm 辅助) |

**结论**:数据量在千万级以下、检索需求不复杂时,PostgreSQL 内置 FTS 足够,不必引入 ES。需要中文分词时加 `zhparser` 或 `pg_jieba`。

## 一、两个核心类型

| 类型 | 含义 |
|------|------|
| `tsvector` | 文档的**词元集合**(已切分、归一化,含位置信息) |
| `tsquery` | 查询条件的**词元表达式**(支持 `&` `\|` `!` `<->`) |

```sql
SELECT to_tsvector('english', 'The cats are running quickly');
-- 'cat':3 'quick':5 'run':4        ← 停用词 the/are 被去掉,做了词干还原

SELECT to_tsquery('english', 'cat & run');
SELECT plainto_tsquery('english', 'cat run');        -- 自动 AND
SELECT phraseto_tsquery('english', 'cat run');       -- 短语
SELECT websearch_to_tsquery('english', 'cat -dog "run fast"');  -- 类搜索引擎语法
```

**匹配操作符 `@@`**

```sql
SELECT to_tsvector('english', 'the cat is running') @@ to_tsquery('english', 'run');
-- t
```

## 二、配置(configuration)

配置决定"如何分词、哪些算停用词、如何还原词干"。

```sql
\dF            -- 列出所有文本搜索配置
\dF+ english   -- 查看 english 配置的解析器与词典链
SHOW default_text_search_config;
```

| 配置 | 说明 |
|------|------|
| `simple` | 只小写化,不做词干还原,不分语言 —— **中文/未知语言的兜底** |
| `english` / `chinese`(若安装) | 语言特定 |
| `pg_catalog.english` | 内置 |

```sql
-- 会话/实例级默认配置
SET default_text_search_config = 'english';
ALTER SYSTEM SET default_text_search_config = 'chinese';
```

**语言器/词典**

```sql
-- 查看词典
\dFd
-- 查看某个词典的内容
SELECT * FROM ts_lexize('english_stem', 'running');   -- {run}
SELECT * FROM ts_lexize('simple', 'Running');         -- {running}
```

## 三、中文处理

**PostgreSQL 内置配置对中文无效**(无空格切割)。

| 方案 | 说明 |
|------|------|
| `simple` 配置 + `pg_trgm` | 不分词,用三元组做子串模糊匹配,**最简单可行** |
| `zhparser` 扩展 | 基于 SCWS 的中文分词,支持自定义词典 |
| `pg_jieba` 扩展 | 基于结巴分词 |
| 应用层预分词后写入 `tsvector` 列 | 灵活,与应用分词器一致 |

**推荐方案 A:pg_trgm 模糊匹配**

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE TABLE articles (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, title text, body text);
CREATE INDEX articles_title_trgm ON articles USING gin (title gin_trgm_ops);

-- 支持任意位置匹配,走索引
SELECT id, title, similarity(title, '数据库原理') AS sim
FROM articles
WHERE title % '数据库原理'          -- % 为相似度阈值操作符
ORDER BY sim DESC
LIMIT 10;

-- 设置阈值
SHOW pg_trgm.similarity_threshold;      -- 默认 0.3
SET pg_trgm.similarity_threshold = 0.2;
```

**推荐方案 B:zhparser**

```sql
CREATE EXTENSION zhparser;
CREATE TEXT SEARCH CONFIGURATION chinese (PARSER = zhparser);
ALTER TEXT SEARCH CONFIGURATION chinese ADD MAPPING FOR n,v,a,i,e,l WITH simple;

SELECT to_tsvector('chinese', 'PostgreSQL 是一个强大的开源数据库');
-- 'postgresql':1 '一个':3 '强大':5 '开源':6 '数据库':7
```

**推荐方案 C:应用层预分词 + 存 tsvector**

```sql
-- 应用侧用结巴/IK 分词后拼成 tsvector 字面量写入
CREATE TABLE docs (
    id       bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    body     text,
    body_tsv tsvector
);
CREATE INDEX docs_tsv_gin ON docs USING gin (body_tsv);

UPDATE docs SET body_tsv = to_tsvector('simple', body);   -- 若已预分词则为拼好的字符串
SELECT * FROM docs WHERE body_tsv @@ to_tsquery('simple', '数据库 & 索引');
```

**结论**:中文场景,**`pg_trgm`(简单可靠)**或 **`zhparser`(真分词)**。前者适合"模糊找一下",后者适合"真做检索"。

## 四、建索引

```sql
-- 方式一:表达式索引(不新增列)
CREATE INDEX docs_body_fts ON docs USING gin (to_tsvector('english', body));

-- 查询必须用同一配置
SELECT * FROM docs WHERE to_tsvector('english', body) @@ to_tsquery('english', 'db');

-- 方式二:生成列(PG12+ 推荐,避免重复计算)★
ALTER TABLE docs ADD COLUMN body_tsv tsvector
    GENERATED ALWAYS AS (to_tsvector('english', body)) STORED;
CREATE INDEX docs_body_tsv_gin ON docs USING gin (body_tsv);

SELECT * FROM docs WHERE body_tsv @@ to_tsquery('english', 'db');
```

> **重要**:`to_tsvector` 的第二个参数(配置名)必须**显式写出且与索引一致**。因为 `to_tsvector(text)`(两参版本)是 immutable 的,而带配置名参数的版本也是 immutable;但若依赖 `default_text_search_config`,则**不是 immutable**,无法建索引。
>
> **实践规则:索引与查询都必须写死配置名。**

GIN vs GiST:

| | GIN | GiST |
|--|-----|------|
| 查询速度 | 快 | 较慢 |
| 更新速度 | 慢 | 快 |
| 体积 | 大 | 小 |
| 选择 | **推荐 GIN** | 写入极密集时考虑 |

## 五、排名与高亮

```sql
-- 相关性排名
SELECT id, title,
       ts_rank(body_tsv, q) AS rank,
       ts_rank_cd(body_tsv, q) AS rank_cd   -- 考虑距离
FROM docs, to_tsquery('english', 'database & index') q
WHERE body_tsv @@ q
ORDER BY rank DESC
LIMIT 20;

-- 权重:标题权重高于正文(PG 支持 A/B/C/D 四级)
UPDATE docs SET body_tsv =
    setweight(to_tsvector('english', coalesce(title,'')), 'A') ||
    setweight(to_tsvector('english', coalesce(body ,'')), 'B');

-- 按权重排序
SELECT ts_rank('{0.1, 0.2, 0.4, 1.0}', body_tsv, q) FROM docs, to_tsquery(...) q;

-- 高亮
SELECT ts_headline('english', body, to_tsquery('english', 'database'),
                   'StartSel=<b>, StopSel=</b>, MaxWords=30')
FROM docs WHERE body_tsv @@ to_tsquery('english', 'database');
```

> **`ts_rank` 的权重数组**默认是 `{0.1, 0.2, 0.4, 1.0}`,分别对应 D/C/B/A。可通过第四参数覆盖。

## 六、查询语法

```sql
-- 布尔
to_tsquery('english', 'database & index')
to_tsquery('english', 'database | index')
to_tsquery('english', 'database & !index')
to_tsquery('english', 'database <-> index')       -- 相邻(短语)
to_tsquery('english', 'database <2> index')       -- 相隔 2 个词
to_tsquery('english', 'data:*')                   -- 前缀匹配

-- 从用户原始输入安全构造(推荐 websearch_to_tsquery)
SELECT websearch_to_tsquery('english', 'postgres -mysql "full text"');
-- 'postgres' & !'mysql' & 'full' <-> 'text'

-- 用户输入含特殊符号时避免拼错,用 plainto_tsquery(自动 AND,自动转义)
SELECT plainto_tsquery('english', 'C++ & Java');
```

> **不要用字符串拼接构造 `to_tsquery`** —— 用户输入里的 `&` `|` `!` `(` 会导致语法错误或语义错误。用 `plainto_tsquery` 或 `websearch_to_tsquery`。

## 七、常见陷阱

| 陷阱 | 说明 | 修正 |
|------|------|------|
| 配置名不一致 | 索引用 `english`,查询用 `simple` → 索引无法用 | 两处写死同一配置 |
| 依赖 `default_text_search_config` | 该表达式非 immutable,无法建索引 | 显式传配置名 |
| 中文用 `english` 配置 | 整句被当作一个词 | 用 `simple` + `pg_trgm` 或 zhparser |
| 用 `to_tsquery` 接用户输入 | 特殊字符导致语法错误 | 用 `plainto_tsquery` / `websearch_to_tsquery` |
| 生成列未写 `STORED` | PG18 起默认 VIRTUAL,不能建索引 | 显式 `STORED` |
| 停用词导致查不到 | `the`、`a` 等被丢弃 | 换 `simple` 配置或自定义停用词 |
| 更新原文未同步 `tsv` | 生成列自动同步;手工列需触发器 | 用生成列或触发器 |

## 八、pg_trgm 补充

```sql
CREATE EXTENSION pg_trgm;

-- 相似度
SELECT similarity('postgres', 'postgrs');            -- 0.5x
SELECT word_similarity('pg', 'postgres');            -- 局部相似
SELECT 'postgres' <-> 'postgrs';                     -- 距离

-- 索引类型
CREATE INDEX ON t USING gin (col gin_trgm_ops);      -- 支持 LIKE/ILIKE/相似度
CREATE INDEX ON t USING gist (col gist_trgm_ops);    -- 支持 KNN 排序 <->

-- 用 KNN 排序(需 GiST)
SELECT * FROM t ORDER BY col <-> 'postgres' LIMIT 5;

-- 加速 LIKE '%x%'
SET pg_trgm.similarity_threshold = 0.1;
SELECT * FROM t WHERE col LIKE '%postgre%';
```

**GIN `gin_trgm_ops` 的额外价值**:能让 `LIKE '%abc%'` 与 `ILIKE` **走索引**,这是 B-tree 做不到的(回顾 [[postgresql/01-入门阶段-基础教程/第05章-查询核心/5.1-WHERE与运算符]])。
