# 扩展生态 · 专题概览

## 专题定位

PostgreSQL 的护城河不是内核本身,而是**扩展机制**:向量检索、地理空间、时序、分布式、图查询,都以扩展形式"长"进数据库。

**这意味着**:学会一套 SQL,能力边界由"装了哪些扩展"决定,而不是换数据库。

## 一、扩展机制基础

```sql
-- 查看可安装的扩展
SELECT name, default_version, installed_version, comment
FROM pg_available_extensions ORDER BY name;

-- 安装
CREATE EXTENSION pg_stat_statements;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION postgis VERSION '3.4';
CREATE EXTENSION pgvector SCHEMA public CASCADE;

-- 查看已装
\dx
SELECT * FROM pg_extension;

-- 升级扩展版本
ALTER EXTENSION pg_trgm UPDATE TO '1.6';

-- 卸载
DROP EXTENSION pg_trgm;

-- 查看扩展包含的对象
\dx+ pg_trgm
```

**扩展的三个组成部分**

| 文件 | 作用 |
|------|------|
| `<name>.control` | 元数据:默认版本、是否需要预加载、依赖 |
| `<name>--<ver>.sql` | 安装脚本(创建函数、类型、操作符) |
| `<name>.so` | 共享库(含 C 函数) |

```sql
-- 查看控制文件信息
SELECT * FROM pg_available_extension_versions WHERE name = 'pg_stat_statements';
```

**两类扩展**

| 类型 | 说明 | 例子 |
|------|------|------|
| 纯 SQL/PLpgSQL | 只建函数与类型,无需预加载 | `pg_trgm`、`hstore`(部分) |
| 需要预加载 | 需在 `shared_preload_libraries` 中声明并**重启** | `pg_stat_statements`、`pg_cron`、`auto_explain`、`pg_stat_kcache` |

```ini
# postgresql.conf
shared_preload_libraries = 'pg_stat_statements,auto_explain,pg_cron'
```

> **必须重启才能生效**。这是"装了扩展但函数报错"的最常见原因。

## 二、必备扩展

### pg_stat_statements(性能诊断第一工具)

```ini
shared_preload_libraries = 'pg_stat_statements'
pg_stat_statements.max = 10000
pg_stat_statements.track = all
pg_stat_statements.track_utility = off
```

```sql
CREATE EXTENSION pg_stat_statements;

-- 按总耗时排序
SELECT round(total_exec_time::numeric,1) AS total_ms, calls,
       round(mean_exec_time::numeric,2) AS mean_ms,
       round(100*total_exec_time/sum(total_exec_time) OVER (),1) AS pct,
       left(query, 70) AS q
FROM pg_stat_statements ORDER BY total_exec_time DESC LIMIT 10;

-- 按平均耗时
SELECT calls, round(mean_exec_time::numeric,2) AS mean_ms, left(query,70)
FROM pg_stat_statements ORDER BY mean_exec_time DESC LIMIT 10;

-- 按 I/O 量
SELECT shared_blks_read + shared_blks_hit AS blks, left(query,70)
FROM pg_stat_statements ORDER BY blks DESC LIMIT 10;

-- 重置
SELECT pg_stat_statements_reset();
```

**要看的四个维度**

| 维度 | 字段 | 意义 |
|------|------|------|
| 总耗时 | `total_exec_time` | 优化收益最大的目标 |
| 调用次数 | `calls` | 高频查询(即使单次快) |
| 平均耗时 | `mean_exec_time` | 单次慢的查询 |
| I/O | `shared_blks_*` | 缓存未命中 |

> **`shared_blks_hit` / `shared_blks_read` 可用于计算缓存命中率**,并识别"读得太多的查询"。配合 `track_io_timing = on` 还能看到真实 I/O 时间。

### auto_explain

```ini
shared_preload_libraries = 'auto_explain'
auto_explain.log_min_duration = '1s'
auto_explain.log_analyze = on
auto_explain.log_buffers = on
auto_explain.log_verbose = on
auto_explain.log_nested_statements = on
auto_explain.sample_rate = 1.0
```

自动把慢查询的**执行计划**写进日志 —— 生产上抓偶发慢查询的利器。

### pg_trgm(模糊匹配)

```sql
CREATE EXTENSION pg_trgm;
CREATE INDEX ON users USING gin (name gin_trgm_ops);
SELECT * FROM users WHERE name ILIKE '%ann%';         -- 走索引
SELECT similarity(name,'ann'), name <-> 'ann' FROM users ORDER BY 2 LIMIT 5;
```

### pgcrypto(加密与摘要)

```sql
CREATE EXTENSION pgcrypto;

SELECT digest('abc','sha256'), encode(digest('abc','sha256'),'hex');
SELECT crypt('password', gen_salt('bf', 12));                 -- bcrypt
SELECT crypt('password', stored_hash) = stored_hash;           -- 校验
SELECT gen_random_uuid();                                      -- UUID v4(PG13+ 内置)
SELECT pgp_sym_encrypt('data','key'), pgp_sym_decrypt(...);
```

> **注意**:PG18 修复了一个 `pgcrypto` 问题——对 OpenSSL 已禁用的算法会**静默地以明文加解密**。升级到 18.6 后应检查是否使用了此类算法。

### hstore / citext / uuid-ossp

```sql
CREATE EXTENSION hstore;      -- 单层键值对(现多用 jsonb 替代)
CREATE EXTENSION citext;      -- 大小写不敏感文本类型
CREATE EXTENSION "uuid-ossp"; -- uuid_generate_v4() 等(现多用内置 gen_random_uuid / uuidv7)
```

> **趋势**:`hstore` 让位于 `jsonb`;`citext` 需谨慎(排序规则相关),更推荐用「`lower(col)` 表达式索引 + `CITEXT` 语义在应用处理」或 `COLLATE` 方案;`uuid-ossp` 让位于内置 `gen_random_uuid()` 与 PG18 的 `uuidv7()`。

## 三、AI / 向量:pgvector

**用途**:向量相似度检索 —— RAG、语义搜索、推荐、去重。

```sql
CREATE EXTENSION vector;

CREATE TABLE items (
    id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    content   text,
    embedding vector(1536)          -- 维度需与模型一致
);

-- 插入向量
INSERT INTO items (content, embedding) VALUES ('文档1', '[0.1, 0.2, ...]'::vector);

-- 相似度检索
SELECT id, content, embedding <-> '[0.1,0.2,...]'::vector AS distance
FROM items ORDER BY distance LIMIT 10;

-- 距离操作符
-- <->  L2 欧氏距离
-- <#>  负内积
-- <=>  余弦距离
```

**索引(必须建,否则全表扫描)**

```sql
-- HNSW(推荐,查询快,构建慢)
CREATE INDEX ON items USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);

-- IVFFlat(构建快,需先有数据)
CREATE INDEX ON items USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);

-- 查询时调搜索范围(精度/速度权衡)
SET hnsw.ef_search = 100;
SET ivfflat.probes = 10;
```

| 索引 | 构建 | 查询 | 内存 | 推荐 |
|------|------|------|------|------|
| HNSW | 慢 | 快 | 大 | ✅ 首选 |
| IVFFlat | 快 | 中 | 中 | 数据量大且需快速构建时 |
| 无索引 | — | 全表扫描 | — | 仅小数据量 |

**RAG 组合模式**

```sql
-- 向量 + 全文/JSONB 混合检索(先过滤再算距离)
SELECT id, content, embedding <=> $1 AS dist
FROM items
WHERE metadata @> '{"source":"wiki"}'      -- JSONB 预过滤(GIN 索引)
ORDER BY dist LIMIT 10;
```

> **实践要点**:`vector` 有维度上限(默认 16000);高维向量可考虑半精度(`halfvec`)或二值化(`bit`)以省空间。批量写入时先插数据后建索引,比边插边维护快得多。

## 四、地理空间:PostGIS

```sql
CREATE EXTENSION postgis;

CREATE TABLE places (
    id   bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name text,
    geom geometry(Point, 4326)         -- WGS84
);

CREATE INDEX places_geom_gix ON places USING gist (geom);

-- 插入(经度在前)
INSERT INTO places (name, geom) VALUES ('某点', ST_SetSRID(ST_MakePoint(116.4, 39.9), 4326));

-- 距离查询(米)
SELECT name, ST_Distance(geom::geography, ST_MakePoint(116.4,39.9)::geography) AS m
FROM places ORDER BY 2 LIMIT 10;

-- 包含关系
SELECT * FROM places WHERE ST_Within(geom, ST_MakeEnvelope(116,39,117,40,4326));

-- 距离范围(KNN,走 GiST)
SELECT * FROM places WHERE ST_DWithin(geom::geography, ST_MakePoint(116.4,39.9)::geography, 5000);
```

| 类型 | 说明 |
|------|------|
| `geometry` | 平面几何,坐标单位由 SRID 决定 |
| `geography` | 球面几何,单位是米,适合长距离 |

**性能要点**:`ST_DWithin` 比 `ST_Distance(...) < x` 快得多(前者可用索引做包围盒过滤,后者必须逐行算)。

## 五、定时任务:pg_cron

```ini
shared_preload_libraries = 'pg_cron'
cron.database_name = 'postgres'
```

```sql
CREATE EXTENSION pg_cron;

SELECT cron.schedule('nightly-vacuum', '0 3 * * *', $$VACUUM ANALYZE$$);
SELECT cron.schedule('refresh-mv', '*/15 * * * *', $$REFRESH MATERIALIZED VIEW CONCURRENTLY mv_daily_sales$$);
SELECT * FROM cron.job;
SELECT cron.unschedule('nightly-vacuum');

-- 历史
SELECT * FROM cron.job_run_details ORDER BY start_time DESC LIMIT 20;
```

> 替代方案:外部调度(cron / Airflow / Kubernetes CronJob)+ `psql -c`。**只在"任务就是库内 SQL"时才用 pg_cron**,避免把业务编排塞进数据库。

## 六、跨库访问:FDW

**外部数据包装器(Foreign Data Wrapper)** 让 PostgreSQL 把外部数据源当作本地表查询。

```sql
CREATE EXTENSION postgres_fdw;

-- 1) 定义服务器
CREATE SERVER remote_srv FOREIGN DATA WRAPPER postgres_fdw
    OPTIONS (host 'remote', port '5432', dbname 'other');

-- 2) 用户映射
CREATE USER MAPPING FOR app_user SERVER remote_srv
    OPTIONS (user 'remote_user', password '...');

-- 3) 外部表
CREATE FOREIGN TABLE remote_orders (
    id bigint, user_id bigint, total numeric(12,2)
) SERVER remote_srv OPTIONS (schema_name 'app', table_name 'orders');

-- 4) 像本地表一样查询(条件会下推到远端)
SELECT count(*) FROM remote_orders WHERE user_id = 1;
```

| FDW | 数据源 |
|-----|--------|
| `postgres_fdw` | 其他 PostgreSQL |
| `file_fdw` | CSV / 文本文件 |
| `oracle_fdw` / `mysql_fdw` | 异构数据库 |
| `sqlite_fdw` | SQLite |
| `mongo_fdw` | MongoDB |
| `parquet_s3_fdw` | 对象存储上的 Parquet |

**关键性能点:条件下推**

```sql
EXPLAIN (VERBOSE) SELECT * FROM remote_orders WHERE user_id = 1;
-- 关注 "Remote SQL: SELECT ... WHERE (user_id = 1)"
-- 只有下推了,过滤才在远端完成,而不是全量拉到本地再过滤
```

```sql
-- 提高下推能力(代价估算更准,但可能出错需回退)
ALTER SERVER remote_srv OPTIONS (ADD extensions 'postgis');
SET enable_...;
```

> **PG18 改进**:`postgres_fdw` 会把事务的 `READ ONLY` / `DEFERRABLE` 状态传递给远端会话,因此只读事务**不能再修改**经由 `postgres_fdw` 的行。若依赖该行为需注意。

## 七、扩展选型速查

| 需求 | 扩展 | 是否需预加载 |
|------|------|--------------|
| 性能诊断 | `pg_stat_statements` | ✅ |
| 自动记录慢计划 | `auto_explain` | ✅ |
| 模糊匹配 | `pg_trgm` | ❌ |
| 加密/摘要 | `pgcrypto` | ❌ |
| 向量检索 | `pgvector` | ❌ |
| 地理空间 | `PostGIS` | ❌ |
| 库内定时 | `pg_cron` | ✅ |
| 跨库查询 | `postgres_fdw` | ❌ |
| CSV 当作表 | `file_fdw` | ❌ |
| 中文分词 | `zhparser` / `pg_jieba` | ❌ |
| 增量物化视图 | `pg_ivm` | ✅(部分) |
| 在线重建表 | `pg_repack` | ❌ |
| 自动分区管理 | `pg_partman` | ✅(部分) |
| 时序数据 | `TimescaleDB` | ✅ |
| 分布式 | `Citus` | ✅ |
| 连接池 | `pgbouncer`(独立进程,非扩展) | — |

```sql
-- 统计扩展使用情况
SELECT extname, extversion FROM pg_extension ORDER BY extname;
-- 检查预加载配置
SHOW shared_preload_libraries;
```

## 八、注意事项

| 事项 | 说明 |
|------|------|
| 预加载需重启 | 只 `CREATE EXTENSION` 不够,函数会报"未加载" |
| 版本对齐 | 扩展版本需与 PG 大版本匹配(升级 PG 后需升级扩展) |
| 升级 PG 时 | 需在新版中安装相同扩展版本,`pg_upgrade` 会检查 |
| 权限 | `CREATE EXTENSION` 通常需超级用户(除非是"可信扩展") |
| **可信扩展** | 标记为 trusted 的扩展可由有 `CREATE` 权限的普通用户安装(如 `pg_trgm`、`hstore`) |
| 安全 | C 语言扩展可访问内核,只装可信来源 |
| 扩展 vs 应用逻辑 | 优先"库内 SQL 能解决";扩展是能力扩展,不是架构替代 |

```sql
-- 查看哪些扩展是可信的
SELECT name, trusted FROM pg_available_extensions WHERE trusted;
```
