# 窗口函数 · 专题概览

## 专题定位

窗口函数解决的问题是:**在保留明细行的同时,计算"与该行相关的聚合"**。

`GROUP BY` 会把多行压成一行;窗口函数**不减少行数**,而是在每行旁边追加一列计算结果。

```sql
-- GROUP BY:3 个用户 → 3 行
SELECT user_id, sum(amount) FROM orders GROUP BY user_id;

-- 窗口函数:20 万行仍是 20 万行,每行多出该用户的总额
SELECT id, user_id, amount,
       sum(amount) OVER (PARTITION BY user_id) AS user_total
FROM orders;
```

**何时该翻这个专题**

- 需要排名、序号
- 需要"截止当前的累计值"(running total)
- 需要移动平均、同比环比
- 需要"取每组前 N 条"
- 需要"与上一行/下一行比较"

## 核心概念:`OVER` 子句的三个组成部分

```sql
函数名(...) OVER (
    PARTITION BY 分组列      -- 可选:把行分成若干组,窗口计算在组内独立进行
    ORDER BY    排序列       -- 可选:决定组内的顺序
    frame_clause             -- 可选:决定当前行能看到组内的哪些行
)
```

| 部分 | 作用 | 省略时 |
|------|------|--------|
| `PARTITION BY` | 划分窗口,类似 `GROUP BY` 但不折叠 | 全部行是一个窗口 |
| `ORDER BY` | 组内排序,决定累计方向 | 组内无序(整组一个结果) |
| frame | 决定"当前行的可见范围" | 有 `ORDER BY` 时为 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`;无 `ORDER BY` 时为整组 |

**frame 是窗口函数最容易出错的部分**,因为它**默认值依赖是否存在 `ORDER BY`**:

```sql
-- 有 ORDER BY:默认 frame 是"从组头到当前行" → 累计
SELECT id, sum(amount) OVER (PARTITION BY user_id ORDER BY created_at) AS running_total
FROM orders;

-- 无 ORDER BY:默认 frame 是整组 → 总额(每行都相同)
SELECT id, sum(amount) OVER (PARTITION BY user_id) AS user_total
FROM orders;
```

> **重要**:很多人以为"`ORDER BY` 只影响顺序",实际上它还**改变了 frame 默认值**,从而改变结果。这是窗口函数的第一大认知陷阱。

## 函数分类速览

| 类别 | 函数 | 需要 `ORDER BY`? |
|------|------|------------------|
| 排名 | `row_number()` `rank()` `dense_rank()` `percent_rank()` `cume_dist()` `ntile(n)` | ✅ 通常需要 |
| 偏移 | `lag()` `lead()` `first_value()` `last_value()` `nth_value()` | ✅ |
| 聚合 | `sum` `avg` `count` `min` `max` `array_agg` `string_agg` | 可选(决定是否累计) |
| 统计 | `stddev` `variance` `corr` `regr_*` | 可选 |

## 执行顺序中的位置

窗口函数在**`HAVING` 之后、`DISTINCT` / `ORDER BY` 之前**求值:

```
FROM → WHERE → GROUP BY → HAVING → WINDOW(窗口函数) → SELECT → DISTINCT → ORDER BY → LIMIT
```

两个直接结论:

1. **窗口函数不能出现在 `WHERE` 里**(`WHERE` 更早)。
2. **但可以出现在 `ORDER BY` 里**(`ORDER BY` 更晚)。

```sql
-- ❌ 报错:window functions are not allowed in WHERE
SELECT * FROM orders WHERE row_number() OVER (ORDER BY id) = 1;

-- ✅ 用子查询/CTE 包一层
SELECT * FROM (
    SELECT *, row_number() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
    FROM orders
) t WHERE rn = 1;

-- ✅ 可以直接在 ORDER BY 用
SELECT id, row_number() OVER (ORDER BY amount DESC) FROM orders ORDER BY 1;
```

## 命名窗口:避免重复书写

```sql
SELECT
    id, user_id, created_at,
    sum(amount)   OVER w AS running_total,
    avg(amount)   OVER w AS running_avg,
    count(*)      OVER w AS running_cnt,
    row_number()  OVER w AS seq
FROM orders
WINDOW w AS (PARTITION BY user_id ORDER BY created_at)
ORDER BY user_id, created_at;
```

`WINDOW` 子句适合多个函数共用同一窗口定义。也可在 `OVER` 中"基于命名窗口再加工":

```sql
SELECT sum(amount) OVER (w ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
FROM orders
WINDOW w AS (PARTITION BY user_id ORDER BY created_at);
```

## 与 `GROUP BY` 的对比

| 维度 | `GROUP BY` | 窗口函数 |
|------|-----------|----------|
| 输出行数 | 分组数 | 与原表一致 |
| 能否保留明细 | ❌ | ✅ |
| 能否嵌套聚合 | 需子查询 | 需子查询(同层不能嵌套) |
| 典型用途 | 报表汇总 | 排名、累计、组内比较 |
| 性能 | 通常更省内存 | 需排序,可能多一次扫描 |

**性能提醒**:窗口函数会对每个分区**排序**,大表上代价显著。若能用 `GROUP BY` + `JOIN` 达到同样效果,往往更快。窗口函数的不可替代价值在"排名""偏移""累计"这三类**需要看到邻近行**的场景。
