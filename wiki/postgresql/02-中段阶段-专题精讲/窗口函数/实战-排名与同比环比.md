# 窗口函数 · 实战:排名、累计与同比环比

> 12 个可直接改为业务用的写法。所有示例基于订单表的 `(user_id, status, total, created_at, channel)`。

## 一、组内 TopN(最常用)

**取每个用户金额最大的 3 笔订单**

```sql
SELECT * FROM (
    SELECT id, user_id, total, created_at,
           row_number() OVER (PARTITION BY user_id ORDER BY total DESC) AS rn
    FROM orders
) t
WHERE rn <= 3
ORDER BY user_id, rn;
```

**并列也要保留**:用 `rank()`,可能出现超过 3 条。

```sql
... dense_rank() OVER (PARTITION BY user_id ORDER BY total DESC) AS rk ...
WHERE rk <= 3
```

**选哪个**

| 需求 | 函数 |
|------|------|
| 严格取 3 条 | `row_number()` |
| 并列共享名次,可能多于 3 条 | `rank()` |
| 名次不跳号 | `dense_rank()` |

> **性能要点**:入参查询最好带 `WHERE created_at > ...` 缩小范围,并为 `(user_id, total DESC)` 建索引以减少排序开销。

## 二、取每组最新一条

```sql
-- 窗口函数版
SELECT * FROM (
    SELECT *, row_number() OVER (PARTITION BY user_id ORDER BY created_at DESC, id DESC) AS rn
    FROM orders
) t WHERE rn = 1;

-- DISTINCT ON 版(通常更快)
SELECT DISTINCT ON (user_id) *
FROM orders ORDER BY user_id, created_at DESC, id DESC;

-- LATERAL 版(组数多、每组只取 1 条时有索引最快)
SELECT u.id, t.*
FROM users u
LEFT JOIN LATERAL (
    SELECT * FROM orders o WHERE o.user_id = u.id ORDER BY o.created_at DESC LIMIT 1
) t ON true;
```

## 三、累计值(running total)

```sql
SELECT user_id, created_at, total,
       sum(total) OVER (PARTITION BY user_id ORDER BY created_at
                        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM orders
ORDER BY user_id, created_at;
```

**全局累计(不分区)**:

```sql
SELECT created_at, total,
       sum(total) OVER (ORDER BY created_at ROWS UNBOUNDED PRECEDING) AS global_running
FROM orders;
```

**注意**:同一时间戳多行时,`ROWS` 与 `RANGE`(默认)结果不同。要"严格逐行累加"必须显式 `ROWS`。

## 四、移动平均(滑动窗口)

```sql
-- 最近 7 笔订单的移动平均
SELECT id, created_at, total,
       round(avg(total) OVER (ORDER BY created_at
             ROWS BETWEEN 6 PRECEDING AND CURRENT ROW), 2) AS ma7
FROM orders;

-- 基于时间的 7 天窗口(含 peer 行)
SELECT id, created_at, total,
       round(avg(total) OVER (ORDER BY created_at
             RANGE BETWEEN interval '7 days' PRECEDING AND CURRENT ROW), 2) AS ma7d
FROM orders;
```

**移动平均前几行只有部分数据**是正常现象(窗口未满)。若业务要求"窗口不足时不算",加计数判断:

```sql
SELECT * FROM (
    SELECT id, created_at, total,
           count(*) OVER w AS cnt,
           avg(total) OVER w AS ma7
    FROM orders
    WINDOW w AS (ORDER BY created_at ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)
) t WHERE cnt = 7;
```

## 五、环比(与上一期比较)

```sql
-- 按月汇总 → 计算环比增长率
WITH monthly AS (
    SELECT date_trunc('month', created_at)::date AS mon,
           sum(total) AS amt
    FROM orders
    GROUP BY 1
)
SELECT mon, amt,
       lag(amt) OVER (ORDER BY mon) AS prev_amt,
       round((amt - lag(amt) OVER (ORDER BY mon))
             / nullif(lag(amt) OVER (ORDER BY mon), 0) * 100, 2) AS mom_pct
FROM monthly
ORDER BY mon;
```

> `nullif(..., 0)` 必不可少 —— 否则上一期为 0 时会除零报错。

**用命名窗口简化**

```sql
WITH monthly AS (...)
SELECT mon, amt,
       lag(amt) OVER w   AS prev_amt,
       lead(amt) OVER w  AS next_amt,
       lag(amt, 12) OVER w AS same_month_last_year
FROM monthly
WINDOW w AS (ORDER BY mon)
ORDER BY mon;
```

## 六、同比(与去年同期比较)

```sql
WITH monthly AS (
    SELECT date_trunc('month', created_at)::date AS mon, sum(total) AS amt
    FROM orders GROUP BY 1
)
SELECT mon, amt,
       lag(amt, 12) OVER (ORDER BY mon) AS yoy_amt,
       round((amt - lag(amt, 12) OVER (ORDER BY mon))
             / nullif(lag(amt, 12) OVER (ORDER BY mon), 0) * 100, 2) AS yoy_pct
FROM monthly
ORDER BY mon;
```

**要求**:数据必须**月份连续**。若有缺月,`lag(amt, 12)` 会错位。保险做法是先补全月份骨架再连接:

```sql
WITH months AS (
    SELECT generate_series(
        date_trunc('month', min(created_at)),
        date_trunc('month', max(created_at)),
        interval '1 month'
    )::date AS mon FROM orders
),
agg AS (
    SELECT date_trunc('month', created_at)::date AS mon, sum(total) AS amt
    FROM orders GROUP BY 1
),
joined AS (
    SELECT m.mon, coalesce(a.amt, 0) AS amt
    FROM months m LEFT JOIN agg a USING (mon)
)
SELECT mon, amt,
       lag(amt, 12) OVER (ORDER BY mon) AS yoy_amt
FROM joined ORDER BY mon;
```

## 七、占比与构成

```sql
SELECT status, sum(total) AS amt,
       round(sum(total) * 100.0 / sum(sum(total)) OVER (), 2) AS pct_of_total
FROM orders
GROUP BY status
ORDER BY amt DESC;
```

**注意** `sum(sum(total)) OVER ()`:内层 `sum` 是聚合(把组压成一行),外层 `sum ... OVER ()` 是窗口(对聚合结果再求总和)。这是"聚合后再开窗"的标准写法。

**分区内占比(各渠道内各状态的占比)**:

```sql
SELECT channel, status, sum(total) AS amt,
       round(sum(total) * 100.0 / sum(sum(total)) OVER (PARTITION BY channel), 2) AS pct_in_channel
FROM orders
GROUP BY channel, status
ORDER BY channel, amt DESC;
```

## 八、按分组取分位数 / 中位数

```sql
SELECT user_id,
       percentile_cont(0.5) WITHIN GROUP (ORDER BY total) AS median,
       count(*) AS cnt
FROM orders
GROUP BY user_id;
```

若要在明细行上打标"是否高于本用户中位数":

```sql
SELECT id, user_id, total,
       total > avg(total) OVER (PARTITION BY user_id) AS above_avg,
       total > percentile_cont(0.5) WITHIN GROUP (ORDER BY total)
               OVER (PARTITION BY user_id) AS above_median   -- ⚠️ 该写法不合法
FROM orders;
```

> **注意**:有序集聚合(`percentile_cont ... WITHIN GROUP`)不能直接当窗口函数用。需要先子查询算出中位数,再 JOIN 回来。

```sql
WITH med AS (
    SELECT user_id, percentile_cont(0.5) WITHIN GROUP (ORDER BY total) AS m
    FROM orders GROUP BY user_id
)
SELECT o.id, o.user_id, o.total, o.total > med.m AS above_median
FROM orders o JOIN med USING (user_id);
```

## 九、用户行为序列:首次/末次/间隔

```sql
SELECT user_id, id, created_at,
       first_value(created_at) OVER w AS first_order_at,
       last_value(created_at)  OVER (w ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS last_order_at,
       created_at - lag(created_at) OVER w AS gap_since_prev
FROM orders
WINDOW w AS (PARTITION BY user_id ORDER BY created_at)
ORDER BY user_id, created_at;
```

**计算留存/回访间隔**可直接在结果上过滤 `gap_since_prev > interval '30 days'`。

## 十、连续登录/连续达标(streak)

经典问题:找出连续 N 天有行为的记录。技巧是**用 `id - 行号` 构造"连续性分组键"**。

```sql
WITH days AS (
    SELECT DISTINCT created_at::date AS d FROM orders
),
marked AS (
    SELECT d,
           d - (row_number() OVER (ORDER BY d))::int AS grp   -- 连续日期的 grp 相同
    FROM days
)
SELECT min(d) AS streak_start, max(d) AS streak_end,
       count(*) AS streak_len
FROM marked
GROUP BY grp
HAVING count(*) >= 3
ORDER BY streak_start;
```

**原理**:对连续递增的日期,`日期 - 行号` 是一个常量;一旦日期断档,该值就跳变。所以同一 `grp` 内就是连续区间。这是窗口函数最优雅的应用之一。

## 十一、累积百分比(帕累托分析)

```sql
SELECT channel, amt,
       round(sum(amt) OVER (ORDER BY amt DESC ROWS UNBOUNDED PRECEDING)
             / sum(amt) OVER () * 100, 2) AS cum_pct
FROM (
    SELECT channel, sum(total) AS amt FROM orders GROUP BY channel
) t
ORDER BY amt DESC;
```

用于回答"前几个渠道贡献了 80% 的销售额"。

## 十二、当前行与组内其他行比较

```sql
-- 该订单金额占同用户总额的比例
SELECT id, user_id, total,
       round(total * 100.0 / nullif(sum(total) OVER (PARTITION BY user_id), 0), 2) AS pct
FROM orders;

-- 与同用户的平均值的差
SELECT id, user_id, total,
       total - round(avg(total) OVER (PARTITION BY user_id), 2) AS diff_from_avg
FROM orders;

-- 排名第几(便于报表展示)
SELECT id, user_id, total,
       rank() OVER (PARTITION BY user_id ORDER BY total DESC) AS rk_in_user
FROM orders;
```

## 常见陷阱汇总

| 陷阱 | 说明 | 修正 |
|------|------|------|
| 默认 frame 变化 | 加 `ORDER BY` 后聚合变"累计" | 显式写 frame |
| `last_value` 返回当前行 | 默认 frame 到当前行 | 显式 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING` |
| 在 `WHERE` 用窗口函数 | 执行顺序不允许 | 子查询/CTE 包一层 |
| `ORDER BY` 不唯一导致排名不稳定 | 同值行的 `row_number` 随机 | 补唯一列,如 `, id` |
| `percentile_cont` 当窗口用 | 有序集聚合不可开窗 | 先聚合再 JOIN |
| 排序落盘 | 大表窗口排序超出 `work_mem` | 调大 `work_mem` 或缩小范围 |
