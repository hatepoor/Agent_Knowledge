# 窗口函数 · 语法与函数速查

## 一、完整语法

```sql
function_name([expression, ...])
    [FILTER (WHERE condition)]
OVER (
    [PARTITION BY expression [, ...]]
    [ORDER BY expression [ASC|DESC] [NULLS {FIRST|LAST}] [, ...]]
    [frame_clause]
)

-- 命名窗口
SELECT ... WINDOW w AS (PARTITION BY ... ORDER BY ...)
```

## 二、frame 语法(核心)

```
{ ROWS | RANGE | GROUPS } BETWEEN frame_start AND frame_end
frame_start / frame_end ∈ {
    UNBOUNDED PRECEDING
    N PRECEDING
    CURRENT ROW
    N FOLLOWING
    UNBOUNDED FOLLOWING
}
-- 简写:只写 frame_start 时,end 默认为 CURRENT ROW
ROWS UNBOUNDED PRECEDING     ≡  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

### 三种模式的区别

| 模式 | 计数依据 | 说明 |
|------|----------|------|
| `ROWS` | 物理行数 | 最直观,"前 3 行就是前 3 行" |
| `RANGE` | **排序值** | 与当前行排序值之差在范围内;**必须只有一个排序键**;`N` 需为数值 |
| `GROUPS` | **同级组数**(PG11+) | 以 `ORDER BY` 值的"peer 组"为计数单位 |

```sql
-- ROWS:严格 3 行
sum(amount) OVER (ORDER BY created_at ROWS BETWEEN 3 PRECEDING AND CURRENT ROW)

-- RANGE:时间窗口(与当前行相差不超过 7 天)
sum(amount) OVER (ORDER BY created_at RANGE BETWEEN interval '7 days' PRECEDING AND CURRENT ROW)

-- GROUPS:按排序值的不同取值分组计数
sum(amount) OVER (ORDER BY status GROUPS BETWEEN 1 PRECEDING AND CURRENT ROW)
```

> **`RANGE` 的坑**:`RANGE BETWEEN N PRECEDING AND CURRENT ROW` 中,若 `ORDER BY` 有重复值,所有"peer 行"都会被纳入当前行,结果可能与 `ROWS` 不同。有重复排序值时优先用 `ROWS`。

### EXCLUDE 子句(PG11+)

```
EXCLUDE CURRENT ROW       -- 排除当前行
EXCLUDE GROUP             -- 排除当前行的所有 peer
EXCLUDE TIES              -- 排除 peer,但保留当前行
EXCLUDE NO OTHERS         -- 默认,不排除
```

```sql
-- 累计但不含自己(用于"与其他人比较")
SELECT id, sum(amount) OVER (ORDER BY id ROWS UNBOUNDED PRECEDING EXCLUDE CURRENT ROW)
FROM orders;
```

## 三、默认 frame(必须记住)

| `OVER` 内容 | 默认 frame | 效果 |
|-------------|-----------|------|
| `OVER ()` | 整组 | 全表聚合,每行相同 |
| `OVER (PARTITION BY x)` | 整个分区 | 分区聚合,分区内每行相同 |
| `OVER (ORDER BY x)` | `RANGE UNBOUNDED PRECEDING AND CURRENT ROW` | **累计**(含 peer) |

```sql
-- 演示差异
SELECT id, amount,
       sum(amount) OVER ()                                    AS total_all,
       sum(amount) OVER (ORDER BY id)                          AS running_含peer,
       sum(amount) OVER (ORDER BY id ROWS UNBOUNDED PRECEDING) AS running_行级
FROM orders;
```

## 四、排名函数

| 函数 | 说明 | 示例(值 10,20,20,30) |
|------|------|----------------------|
| `row_number()` | 唯一序号,无并列 | 1, 2, 3, 4 |
| `rank()` | 并列同名,跳号 | 1, 2, 2, 4 |
| `dense_rank()` | 并列同名,不跳号 | 1, 2, 2, 3 |
| `percent_rank()` | `(rank-1)/(n-1)` | 0, 0.33, 0.33, 1 |
| `cume_dist()` | 小于等于当前值的行数占比 | 0.25, 0.75, 0.75, 1 |
| `ntile(n)` | 分 n 桶,返回桶号 | 1,2,3,4(4 行 4 桶) |

```sql
SELECT id, amount,
       row_number()  OVER (ORDER BY amount DESC) AS rn,
       rank()        OVER (ORDER BY amount DESC) AS rk,
       dense_rank()  OVER (ORDER BY amount DESC) AS drk,
       percent_rank()OVER (ORDER BY amount DESC) AS prk,
       cume_dist()   OVER (ORDER BY amount DESC) AS cd,
       ntile(4)      OVER (ORDER BY amount DESC) AS quartile
FROM orders;
```

> `ntile` 在行数不能被 n 整除时,前面的桶会多一行。分布不均,不适合做"等分位数"的严格场景(那种场景用 `percentile_cont`)。

## 五、偏移函数

| 函数 | 说明 |
|------|------|
| `lag(expr [, offset [, default]])` | 组内往前第 offset 行(默认 1) |
| `lead(expr [, offset [, default]])` | 组内往后第 offset 行 |
| `first_value(expr)` | frame 内第一行 |
| `last_value(expr)` | frame 内最后一行(**受 frame 影响!**) |
| `nth_value(expr, n)` | frame 内第 n 行 |

```sql
SELECT id, created_at, amount,
       lag(amount)  OVER (ORDER BY created_at)                       AS prev_amount,
       lead(amount) OVER (ORDER BY created_at)                       AS next_amount,
       lag(amount, 2, 0) OVER (ORDER BY created_at)                  AS amount_2_ago,
       first_value(amount) OVER (ORDER BY created_at)                 AS first_amount,
       last_value(amount)  OVER (ORDER BY created_at
            ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS last_amount
FROM orders;
```

> **`last_value` 的头号陷阱**:默认 frame 是"到当前行",所以 `last_value(x) OVER (ORDER BY y)` 返回的是**当前行自己**(因为 frame 最后一帧就是当前行)。要取整组最后一个值,必须显式写 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`。

## 六、聚合函数作窗口函数

几乎所有聚合函数都能当窗口函数用:

```sql
SELECT id, user_id, amount,
       sum(amount)         OVER w AS running_sum,
       avg(amount)         OVER w AS running_avg,
       count(*)            OVER w AS running_cnt,
       max(amount)         OVER w AS running_max,
       min(amount)         OVER w AS running_min,
       array_agg(id)       OVER w AS ids_so_far,
       string_agg(status, ',') OVER w AS statuses_so_far,
       count(*) FILTER (WHERE status = 'paid') OVER w AS paid_cnt_so_far
FROM orders
WINDOW w AS (PARTITION BY user_id ORDER BY created_at
             ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW);
```

`FILTER` 可与窗口函数组合(如上)。

## 七、统计类窗口函数

```sql
SELECT id,
       stddev(amount)  OVER (PARTITION BY user_id) AS sd,
       variance(amount) OVER (PARTITION BY user_id) AS var,
       corr(amount, id::numeric)   OVER (PARTITION BY user_id) AS correlation,
       regr_slope(amount, id::numeric) OVER (PARTITION BY user_id) AS slope
FROM orders;
```

## 八、`EXCLUDE` 与去重的组合(查找重复)

```sql
-- 找出同一用户同一时间重复下单的记录(保留最早 id)
SELECT * FROM (
    SELECT *, row_number() OVER (PARTITION BY user_id, created_at ORDER BY id) AS rn
    FROM orders
) t WHERE rn > 1;

-- 删除重复,保留每组最小 id
DELETE FROM orders o
USING (
    SELECT id, row_number() OVER (PARTITION BY user_id, created_at ORDER BY id) AS rn
    FROM orders
) d
WHERE o.id = d.id AND d.rn > 1;
```

## 九、性能注意事项

| 事项 | 说明 |
|------|------|
| 需要排序 | 每个分区的 `ORDER BY` 需排序,大表上会 `Sort` 且可能落盘(`work_mem` 超限 → 临时文件) |
| 分区数多 | 分区多且分区内数据多时内存压力大 |
| 索引利用 | 若 `ORDER BY` 与索引同序,可免排序;`PARTITION BY` 最好是有序前缀 |
| 与 `DISTINCT` 组合 | `DISTINCT` 在窗口计算**之后**,无法靠它减少窗口计算量 |
| 多次不同窗口 | 每个不同 `PARTITION BY/ORDER BY` 组合都要额外排序,尽量复用 |
| 最优化替代 | "取每组第一条"若可接受,`DISTINCT ON` 通常比 `row_number()` + 子查询更快(少一次排序复算) |

```sql
-- 观察窗口排序是否落盘
EXPLAIN (ANALYZE, BUFFERS)
SELECT user_id, sum(amount) OVER (PARTITION BY user_id ORDER BY created_at) FROM orders;
-- 关注 Sort 节点的 "Sort Method: external merge Disk: xxxkB"
SET work_mem = '256MB';   -- 调大后重试,磁盘排序可能消失
```
