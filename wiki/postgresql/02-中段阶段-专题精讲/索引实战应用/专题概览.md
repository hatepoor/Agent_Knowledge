# 索引实战应用 · 专题概览

## 专题定位

索引是 PostgreSQL 性能的第一杠杆,也是**最容易滥用**的机制。本专题回答三个问题:

1. **该建什么索引**(类型选型)
2. **为什么没走索引**(诊断)
3. **索引本身的开销有多大**(取舍)

**何时该翻这个专题**

- 查询变慢,需要判断是否缺索引
- 准备加索引,但不清楚该用什么类型
- 发现建了索引却没被使用
- 需要评估"这个索引值不值得留"

## 一、索引的本质与代价

索引是**额外的数据结构**,用**写放大**换**读加速**。

| 索引带来的收益 | 索引付出的代价 |
|----------------|----------------|
| 减少扫描的数据量 | 每写一行要维护所有索引 |
| 支持排序免排序 | 占用磁盘空间 |
| 支持唯一性约束 | 增加 VACUUM 负担 |
| 支持连接加速 | 规划器候选计划变多(规划变慢) |

**核心原则**:索引应该服务于**真实的、高频的、选择性的查询**。凭空推测的索引是纯负债。

```sql
-- 评估索引是否被使用 ★必会
SELECT
    relname,
    indexrelname,
    idx_scan,                    -- 被使用次数
    pg_size_pretty(pg_relation_size(indexrelid)) AS size
FROM pg_stat_user_indexes
ORDER BY idx_scan, pg_relation_size(indexrelid) DESC;

-- 找出"从未被使用且体积不小"的索引 → 候选删除对象
SELECT relname, indexrelname, idx_scan,
       pg_size_pretty(pg_relation_size(indexrelid)) AS size
FROM pg_stat_user_indexes
WHERE idx_scan = 0
  AND indexrelid NOT IN (SELECT conindid FROM pg_constraint WHERE contype IN ('p','u','x'))
ORDER BY pg_relation_size(indexrelid) DESC;
```

> **注意**:`idx_scan = 0` 不等于无用。唯一约束索引、被外键依赖的索引即使不用于查询也不能删。上面的 SQL 已排除主键/唯一/排他约束索引。另外统计在重启后可能复位,应长期观察。

## 二、六种索引方法一览

| 方法 | 结构 | 支持 | 典型用途 |
|------|------|------|----------|
| **B-tree** | 平衡多路树 | `= < > <= >= BETWEEN IN LIKE 'x%'` 排序 | **默认选择**,90% 场景 |
| **Hash** | 哈希表 | 仅 `=` | 等值且键很长时略优于 B-tree |
| **GIN** | 倒排索引 | `@>` `<@` `&&` `?` 数组/JSONB/全文 | 多值列、JSONB、全文检索 |
| **GiST** | 平衡树(可扩展) | `&&` `<@` `@>` `<<` 等 | 几何、范围、排他约束 |
| **SP-GiST** | 空间分区树 | 前缀、四叉树、k-d | 点数据、IP 范围、非平衡结构 |
| **BRIN** | 块范围摘要 | `= < >` | 超大表且**物理有序**(时间序列) |

**B-tree 的默认地位**:能解决问题时优先 B-tree。理由是它支持排序、支持范围、体积可控、规划器代价估算最准。

## 三、索引类型与查询的匹配速查

| 查询形态 | 索引 |
|----------|------|
| `col = ?` | B-tree(唯一时最佳) |
| `col > ? AND col < ?` | B-tree |
| `ORDER BY col LIMIT n` | B-tree(同序) |
| `a = ? AND b = ?` | B-tree(多列,顺序有讲究) |
| `a = ? ORDER BY b` | B-tree `(a, b)` |
| `col LIKE 'abc%'` | B-tree + `text_pattern_ops`(或 `C` collation) |
| `col ILIKE '%abc%'` / 模糊 | GIN + `pg_trgm` |
| `tags @> ARRAY['x']` | GIN |
| `jsonb @> '{...}'` | GIN |
| `tsvector @@ tsquery` | GIN(或 GiST) |
| `range && range` | GiST |
| `点/几何包含` | GiST / SP-GiST |
| `ip << inet` | GiST / SP-GiST |
| 超大表 + 时间范围 | BRIN |
| `WHERE flag AND col = ?`(flag 选择性低) | 部分索引 |
| `lower(col) = ?` | 表达式索引 |
| 只读少数列 | 覆盖索引(`INCLUDE`) |

## 五、必须记住的三条

1. **索引列上做运算/函数 → 普通索引失效**。需要时用表达式索引。
2. **隐式类型转换会让索引失效**(见 [[postgresql/01-入门阶段-基础教程/第02章-数据类型/2.6-NULL语义与类型转换]])。
3. **多列索引的列顺序决定可复用范围**(最左前缀),不是随便排的。
