> 一句话定位：`DoclingDocument` 只是中间表示，真正产出价值的是在它之上的五类下游处理——导出、分块、抽取、可视化、剖析。

## 核心结论

Docling 的解析管线（`backend` + `pipeline`）把任意格式收敛成统一的 `DoclingDocument`。但 `DoclingDocument` 本身不是交付物，它是一棵带 `prov`（来源坐标）的节点树。要进入检索、问答、知识库，必须再做一层"下游处理"。这一层集中在 `docling_core/transforms/`（`serializer/`、`chunker/`、`visualizer/`、`profiler/`）以及 `docling/document_extractor.py`。

五类能力解决五个不同的问题：

- **serializer（导出）**：把 `DoclingDocument` 树压平成一段文本/HTML/JSON，供人读、供模型读、或供下游系统迁移。
- **chunker（分块）**：沿文档结构切出语义完整、token 可控的 `DocChunk`，直接对接 embedding 与检索。
- **extractor（抽取）**：用 VLM 按模板从文档里抽取结构化字段（发票、简历等），产出 `ExtractionResult`。
- **visualizer（可视化）**：把解析结果画回原页图像上——这是人工核对解析质量最直观的手段，比读文本输出强得多。
- **profiler（剖析）**：`doc_profiler` 对文档做统计画像，用于质量监控与流水线调优。

其中 **serializer 与 chunker 是 RAG 链路的主干**，visualizer 是调试利器，extractor 是结构化数据捕获的捷径，profiler 偏运维。下文逐层展开，并把"可视化怎么用"作为本页亮点写透。

## 机制与原理

### 五类下游能力总表

| 类别 | 主入口（源码核实） | 输入 | 输出 | 解决什么问题 |
| --- | --- | --- | --- | --- |
| 导出 serializer | `docling_core/transforms/serializer/` | `DoclingDocument` | `SerializationResult(text, spans)` | 把树变成可消费的一维文本/HTML/JSON |
| 分块 chunker | `docling_core/transforms/chunker/` | `DoclingDocument` | `Iterator[DocChunk]` | 切出语义块，控制 token 预算，准备检索 |
| 抽取 extractor | `docling.document_extractor.DocumentExtractor` | 文件路径/流 | `ExtractionResult` | 按模板抽取结构化字段 |
| 可视化 visualizer | `docling_core/transforms/visualizer/` | `DoclingDocument`（需页图像） | `dict[page_no, PIL.Image]` | 人工核对布局/阅读顺序质量 |
| 剖析 profiler | `docling_core/transforms/profiler/doc_profiler.py` | `DoclingDocument` | 统计画像 | 文档质量监控、流水线调优 |

共同底座：所有 serializer 都实现 `BaseDocSerializer`（`serializer/base.py`），所有 chunker 都实现 `BaseChunker`（`chunker/base.py`）。这意味着**你自己写的导出器/分块器只要继承对应基类，就能无缝替换官方实现**。

### 导出（serializer）：可导出哪些格式

`DoclingDocument` 通过 `DocSerializer`（`serializer/common.py`，一个具体装配类）把树遍历后交给各类 item serializer（文本、表格、图片、键值、表单、列表、内联、兜底）拼装。每个格式对应一个 `*DocSerializer` 子类（源码核实的可用列表）：

| 序列化器类 | 模块 | 适用场景 |
| --- | --- | --- |
| `MarkdownDocSerializer` | `markdown.py` | 给人看、给 Markdown 渲染器、给多数 LLM 上下文 |
| `HTMLDocSerializer` | `html.py` | 网页/前端展示，保留结构样式 |
| `DocTagsDocSerializer` | `doctags.py` | 给模型——紧凑 token 序列（`<doctag>` 标记），用于训练/推理 |
| `DocLangDocSerializer` | `doclang.py` | DocLang 结构化令牌语言，便于程序化消费 |
| `AzureDocSerializer` | `azure.py` | 兼容 Azure Document Intelligence 的 JSON，便于从 Azure DI 迁移 |
| `LaTeXDocSerializer` | `latex.py` | 学术排版场景 |
| `PlainTextDocSerializer` | `plain_text.py` | 纯文本基线、简单比对 |
| `MsExcelMarkdownDocSerializer` | `markdown_excel.py` | Excel 单元格的 Markdown 导出 |
| `WebVTTDocSerializer` | `webvtt.py` | 视频字幕（WebVTT） |

注意 `SerializationResult` 同时返回 `text` 与 `spans`：`spans` 是 `[Span(item=DocItem)]`，记录文本片段回溯到了哪些 `DocItem`。这对"检索命中后定位回原文"非常关键，不要只取 `.text` 丢掉 `.spans`。

### 分块（chunker）：组件族与 HybridChunker 四步

`chunker/__init__.py` 导出的分块器族：

| 分块器 | 模块 | 切分逻辑 |
| --- | --- | --- |
| `HierarchicalChunker` | `hierarchical_chunker.py` | 纯按文档层级（标题结构）切，不感知 token |
| `HybridChunker` | `hybrid_chunker.py` | 结构切 + token 预算 + 语义兜底，最常用 |
| `PageChunker` | `page_chunker.py` | 整页一个块 |
| `LineBasedTokenChunker` | `line_chunker.py` | 按行 + token 预算切（Hybrid 内部复用） |
| 代码分块族 | `code_chunking/` | tree-sitter 按语法切代码（`_language_code_chunkers.py` 约 60 KB） |

两类 **Expander**（不改变块的切分，而是把块"回溯放大"到更完整的上下文）：

- `TreeChunkExpander`：沿文档树向上回溯到 body 的直接子节点（顶层项），把整段顶层项原文并入块。
- `PageChunkExpander`：扩到整页，依赖 `prov.page_no`——**DOCX 不可用**（DOCX 的 prov 是空列表，实测）。

#### HybridChunker 的四步流程（源码核实，务必准确）

`HybridChunker.chunk()` 主方法依次做四件事：

1. **`_inner_chunker.chunk()`** → 调用 `HierarchicalChunker`（`_inner_chunker` 是 `cached_property`，见 `hybrid_chunker.py:127`），先按文档标题结构切成若干 `DocChunk`。
2. **`_split_by_doc_items()`** → 对上一步的每个块，沿 `meta.doc_items` 做滑动窗口，把元素逐个累加，直到 contextualize 后的 token 数超过 `max_tokens` 为止。
3. **`_split_using_plain_text()`** → 若单个元素（如一张超长表格）仍超预算，**交给 `semchunk` 按语义边界切**——**不是递归字符切分**（网上普遍说错，源码 `segment()` 在 `else` 分支调用 `semchunk.chunkerify`）。表格且开启 `repeat_table_header` 时走 `LineBasedTokenChunker` 按行切并重复表头。
4. **`_merge_chunks_with_matching_metadata()`** → 合并**同一标题链**（`headings` 相同）下的相邻碎块，只要合并后不超 `max_tokens`。

默认值（源码核实，`hybrid_chunker.py:73-78`）：`repeat_table_header=True`、`merge_peers=True`、`omit_header_on_overflow=False`、`always_emit_headings=False`。

**关键预算语义**：`max_tokens` 是属性，代理到 `tokenizer.get_max_tokens()`（`hybrid_chunker.py:121`）。源码里 `available_length = max_tokens - other_len`，其中 `other_len` 是标题与 caption 的 token 数（`_split_using_plain_text`）。**所以 `max_tokens` 是"含标题链的总预算"，不是纯正文预算**——设置 512 是指整块（含 headings）上限 512 token。

#### contextualize()：内置上下文增强

`BaseChunker.contextualize(chunk)`（`chunker/base.py:82`）是给 embedding 用的文本构造器：它把 `chunk.meta` 中**未被排除**的字段 JSON 化，与 `chunk.text` 用换行拼接。旧名 `serialize()` 已 deprecated。

`DocMeta` 的排除清单（`doc_chunk.py:58`）：

```python
excluded_embed: ClassVar[list[str]] = [
    _KEY_SCHEMA_NAME,   # schema_name
    _KEY_VERSION,       # version
    _KEY_DOC_ITEMS,     # doc_items
    _KEY_ORIGIN,        # origin
]
excluded_llm:  ClassVar[list[str]] = [schema_name, version, doc_items, origin]
```

`headings` 不在排除列表里——**`headings` 会被保留进 embedding 文本**，这正是"块带标题链上下文"的实现机制。`DocMeta` 字段为 `schema_name / version / doc_items / headings / captions(已 deprecated) / origin`，**没有显式 `parent_id`**，父子关系靠 `headings` + `doc_items` 表达（`TreeChunkExpander` 也是沿 `self_ref`/`parent` 回溯，而非读 parent_id）。

#### TreeChunkExpander 做父级回溯

`chunk_expander.py:24` 的 `_get_top_containing_items` 从块内每个元素的 `self_ref` 沿 `parent.resolve(doc)` 一路向上，直到父节点是 `doc.body` 的直接子节点（顶层项），再按 `doc.body.children` 的原始阅读顺序序列化——保证扩出来的内容语义完整且顺序正确：

```python
# chunk_expander.py:42 节选——向上回溯到 body 的直接子节点
top_item = RefItem(cref=item).resolve(doc)
while top_item.parent != doc.body.get_ref():
    top_item = top_item.parent.resolve(doc)
items[top_item.self_ref] = top_item
# 再按 doc.body.children 阅读顺序输出
doc_body_refs = [ref.cref for ref in doc.body.children]
```

### 抽取（extractor）：ExtractionFormatOption 的作用

`docling/document_extractor.py:52` 的 `ExtractionFormatOption` 继承 `BaseFormatOption`，比普通转换多一个 `pipeline_cls: Type[BaseExtractionPipeline]` 字段——它把"用哪条抽取管线"绑定到某格式上。`DocumentExtractor` 用它按格式选择 VLM 抽取管线（默认 `ExtractionVlmPipeline` + `ImageDocumentBackend`/`ThreadedDoclingParseDocumentBackend`）。这套能力对应 `extract-core` extra。它和 `DocumentConverter` 是两套入口：转换产出 `DoclingDocument`，抽取产出 `ExtractionResult`（按模板如发票/简历的结构化字段）。

### 可视化（visualizer）：调试解析质量的利器

`visualizer/base.py` 定义 `BaseVisualizer.get_visualization(*, doc) -> dict[int | None, Image]`。两个实现：

- `LayoutVisualizer`（`layout_visualizer.py`）：在**原页图像**上画每个 `DocItem` 的包围框 + 标签名 + 置信度（按 `DocItemLabel.get_color` 上色）。
- `ReadingOrderVisualizer`（`reading_order_visualizer.py`）：在原页图像上画**阅读顺序箭头**——红箭头是外层阅读顺序，蓝箭头是图片内部的阅读顺序（图片内嵌元素单独成链）。

二者可链式叠加：`ReadingOrderVisualizer(base_visualizer=LayoutVisualizer())` 先画布局框再叠箭头。它们在 `get_visualization` 里要求 `doc.pages[page_no].image.pil_image` 存在（即转换时必须开启 `generate_page_images=True`），且元素要有 `prov`（bbox）——否则抛 `RuntimeError("Cannot visualize document without images")`。

## 实操

### 导出四种典型格式

```python
from docling.document_converter import DocumentConverter
from docling_core.transforms.serializer.markdown import MarkdownDocSerializer
from docling_core.transforms.serializer.doctags import DocTagsDocSerializer
from docling_core.transforms.serializer.azure import AzureDocSerializer

conv = DocumentConverter()
result = conv.convert("report.pdf")

md = MarkdownDocSerializer(doc=result.document).serialize().text      # 给人看
tags = DocTagsDocSerializer(doc=result.document).serialize().text    # 给模型
az = AzureDocSerializer(doc=result.document).serialize().text        # 迁移到 Azure DI
```

### 用 HybridChunker 分块并构造 embedding 文本

```python
from docling_core.transforms.chunker import HybridChunker

chunker = HybridChunker(max_tokens=512)  # tokenizer 默认 all-MiniLM-L6-v2
chunks = list(chunker.chunk(result.document))
for c in chunks:
    embed_text = chunker.contextualize(c)   # 含 headings 的上下文文本
    refs = [s.item.self_ref for s in c.meta.doc_items]  # 回溯原文
```

### 用 TreeChunkExpander 做父级回溯

```python
from docling_core.transforms.chunker import HybridChunker
from docling_core.transforms.chunker.chunk_expander import TreeChunkExpander
from docling_core.transforms.serializer.markdown import MarkdownDocSerializer

chunker = HybridChunker()
expander = TreeChunkExpander()
serializer = MarkdownDocSerializer(doc=result.document)

for chunk in chunker.chunk(result.document):
    expanded = expander.expand(chunk, result.document, serializer)
    # expanded.text 已是完整顶层 item 的内容，适合做"块→父级段落"召回
```

### 用可视化人工核对解析质量（本页亮点）

```python
from docling.document_converter import DocumentConverter
from docling_core.transforms.visualizer.layout_visualizer import LayoutVisualizer
from docling_core.transforms.visualizer.reading_order_visualizer import ReadingOrderVisualizer

conv = DocumentConverter()
# 必须开启页图像，否则可视化会报 "without images"
result = conv.convert("report.pdf")

vis = ReadingOrderVisualizer(base_visualizer=LayoutVisualizer())
images = vis.get_visualization(doc=result.document)  # {page_no: PIL.Image}
for page_no, img in images.items():
    img.save(f"page_{page_no}.png")
```

拿到 PNG 后重点看三件事：① 标题/段落/表格框是否套准（布局框偏移说明 `prov` 不准）；② 红色箭头是否按你预期的阅读顺序走（乱序说明阅读顺序模型有误）；③ 表格是否被误判成文本块（框标签直接显示 `TABLE` 等）。这些肉眼一眼能看出的问题，靠 diff 文本输出要花十倍时间。

### 用 DocumentExtractor 按模板抽取

```python
from docling.document_extractor import DocumentExtractor
from docling.datamodel.document import ExtractionTemplateType

extractor = DocumentExtractor()
res = extractor.extract(
    source="invoice.pdf",
    template=ExtractionTemplateType.INVOICE,
)
print(res.data)  # 结构化字段，而非 DoclingDocument
```

## 陷阱与边界

- **HybridChunker 默认偷偷拉 HuggingFace**：`get_default_tokenizer()` 直接 `HuggingFaceTokenizer.from_pretrained("sentence-transformers/all-MiniLM-L6-v2")`。即使你只写 `HybridChunker(max_tokens=512)`，**没有显式传 `tokenizer=` 就会触发 HF 下载**。国内环境用镜像 `HF_ENDPOINT=https://hf-mirror.com`，或换 `OpenAITokenizer`（`docling_core/transforms/chunker/tokenizer/openai.py`，依赖 tiktoken），或自定义 `BaseTokenizer`（`tokenizer/base.py`，需实现 `count_tokens`/`get_max_tokens`/`get_tokenizer`）。要完全避开 HF，必须显式 `tokenizer=<你的实例>` 传进去。
- **`max_tokens` 是含标题的总预算**：设 512 不代表正文 512，标题链 token 也占额度；超长表格的 `available_length = max_tokens - other_len` 可能变成负数，源码会 warning 并丢弃 headings/captions 再切。
- **`captions` 已 deprecated**：新代码用 `headings`；序列化时 `captions` 仍可能出现在结构里，别依赖它。
- **可视化需要页图像 + prov**：PDF 须 `generate_page_images=True`；**DOCX 既无页图像、prov 又为空**，两套可视化都跑不了——这不是代码 bug，是后端能力边界（见 `[[docling/09_已知陷阱与边界|Docling 已知陷阱]]`）。
- **Expander 的 DOCX 限制**：`PageChunkExpander` 依赖 `prov.page_no`，DOCX prov 为空 → 无法扩到整页；`TreeChunkExpander` 不依赖 prov，但 DOCX 仍可用。
- **不要只取 `.text` 丢 `.spans`**：检索命中后想定位回原文，靠的是 `SerializationResult.spans` 里的 `DocItem` 引用。
