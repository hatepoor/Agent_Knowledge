# Docling 知识库

> 本库是围绕 IBM Research 发起、现属 LF AI & Data 基金会的开源文档解析框架 **Docling** 构建的个人知识库，目标是把"复杂文档如何变成结构化、可检索、可溯源的 AI 数据"这件事讲透——从为什么用、怎么用，到内部怎么工作、怎么扩展。

## 核心结论

- Docling 把 34 种输入格式统一收敛为一份 **DoclingDocument** 文档模型，下游无论导出 Markdown、结构化 JSON、做分块（chunking）还是抽取表格/图片，都只对接这一个模型。
- 它不是给人看的排版工具，而是**面向 AI 数据准备**的解析层：输出带层级、带坐标、带阅读顺序的结构，专为 RAG、微调、知识图谱等下游服务。
- 可以**完全离线、自托管**，MIT 许可，数据不出本地——这是它在合规场景里相对 LlamaParse / Azure DI 等云服务的关键卖点。
- 代价是依赖较重：含 ML 模型的 extras 会拉入 torch；但**纯 Office / HTML / Markdown 场景不需要任何模型**，走无模型的 SimplePipeline。

## 安装形态提醒

2.129.0 起，PyPI 上的 `docling` 只是元包（wheel 5.2 kB），真正实现在 `docling-slim`。按需安装：纯轻量解析用 `docling-slim`，要全部 ML 能力再加对应 extras（如 `[torch]`）。详见 [[docling/08_格式支持与依赖管理|格式支持与依赖管理]]。

## 如何阅读本库

- 内部链接均为 Obsidian wikilink，路径从 `wiki/` 下一级（`docling/...`）开始，不带 `.md` 后缀，例如 `[[docling/01_定位与适用场景|定位与适用场景]]`。
- 每个内容页统一结构：`> 一句话定位` → `## 核心结论` → `## 机制与原理` → `## 实操` → `## 陷阱与边界` → `## 相关导航`。
- 凡标注 `（待核实）` 的内容，表示该事实未在本轮源码核实范围内，使用前请二次确认。

## 与知识库其他部分的关系

Docling 在本知识库里定位为 **RAG 解析层**的工具：它负责把 PDF / Word / 图片 / 表格等多源文档变成结构化语料，喂给检索与生成链路。关于它在整个多源接入中的位置，见 [[rag/01_多源数据接入/文档解析_PDF_Word_图片与表格|解析总览]]。
