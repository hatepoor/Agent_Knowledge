> 一句话定位：Docling 的每一层都可替换——扩展点比使用点多。backend、pipeline、serializer、chunker、expander、模型规格，全都能换。

## 核心结论

Docling 的设计哲学是"约定优于配置，但一切皆可覆写"。解析管线的四个核心抽象——`AbstractDocumentBackend`、`BasePipeline`、`DocumentConverter` 的 `FormatOption`、以及下游的 `BaseDocSerializer` / `BaseChunker` / `BaseChunkExpander`——全部是带抽象方法的基类。你不需要 fork 源码，只要在 `DocumentConverter(format_options={...})` 里塞入自己的 `FormatOption`，就能把自定义实现挂进官方流水线。

高层认知：

- **扩展是"组合"而非"修改"**：官方 `WordFormatOption` 只是把 `pipeline_cls=SimplePipeline` 和 `backend=MsWordDocumentBackend` 绑在一起（`document_converter.py:149`）。你照猫画虎即可。
- **声明式 vs 分页式**是 backend 的两条主线：能直接读文本/XML 的格式走 `DeclarativeDocumentBackend`（无需识别模型），扫描件/PDF 走 `PaginatedDocumentBackend`（逐页识别）。
- **换模型通常不改代码**：模型规格集中在 `stage_model_specs.py` / `layout_model_specs.py` / `vlm_model_specs.py` / `asr_model_specs.py`，通过 `pipeline_options` 指向不同预设即可。

## 机制与原理

### 扩展点全景表

| 扩展目标 | 基类（源码核实） | 需要实现什么 | 典型场景 |
| --- | --- | --- | --- |
| 新格式（文本/XML 类） | `DeclarativeDocumentBackend`（`backend/abstract_backend.py:69`） | `__init__、is_valid、supports_pagination、supported_formats、convert` | 自研 XML、数据库导出、内部格式 |
| 新格式（分页型） | `PaginatedDocumentBackend`（同上:57） | 上述 + `page_count` | 新扫描格式、新分页容器 |
| 新管线 | `BasePipeline` / `ConvertPipeline` / `PaginatedPipeline`（`pipeline/base_pipeline.py`） | `_build_document、_determine_status、get_default_options、is_backend_supported`；分页式再加 `initialize_page` | 自定义识别阶段编排 |
| 新导出格式 | `BaseDocSerializer`（`serializer/base.py:207`） | `serialize、serialize_bold/italic/...、get_parts、post_process` 等 | 自定义下游文本格式 |
| 新分块策略 | `BaseChunker`（`chunker/base.py:62`） | `chunk`（抽象） | 领域特化切分 |
| 新上下文扩展 | `BaseChunkExpander`（`chunker/base.py:114`） | `expand` | 父级回溯、页级回溯之外的新扩增 |
| 换模型 | 通过 `pipeline_options` 指定模型规格 | 选预设 / 改 `repo_id`、引擎 | 换 layout/table/OCR/VLM/ASR 模型 |

### 抽象方法清单（务必实现，否则运行期才报错）

**`AbstractDocumentBackend`**（`abstract_backend.py:22`）的抽象成员：

- `__init__(self, in_doc, path_or_stream, options=None)`
- `is_valid(self) -> bool`
- `supports_pagination(cls) -> bool`（classmethod）
- `supported_formats(cls) -> set[InputFormat]`（classmethod）

`PaginatedDocumentBackend` 额外抽象：`page_count(self) -> int`。`DeclarativeDocumentBackend` 额外抽象：`convert(self) -> DoclingDocument`（并覆写 `__init__`，把 `options` 默认成 `DeclarativeBackendOptions`）。

**`BasePipeline`**（`base_pipeline.py:57`）的抽象成员：

- `_build_document(self, conv_res) -> ConversionResult`
- `_determine_status(self, conv_res) -> ConversionStatus`
- `get_default_options(cls) -> PipelineOptions`（classmethod）
- `is_backend_supported(cls, backend) -> bool`（classmethod）

`PaginatedPipeline` 额外抽象：`initialize_page(self, conv_res, page) -> Page`。非抽象但常被覆写的有 `_assemble_document`、`_enrich_document`、`_unload`——`execute()` 主流程（`base_pipeline.py:76`）会依次调用 `_build_document → _assemble_document → _enrich_document → _determine_status`。

### 接入方式：把自定义实现挂进 DocumentConverter

`DocumentConverter` 接受 `format_options: dict[InputFormat, FormatOption]`。`FormatOption`（`document_converter.py:116`）有四个关键字段（源码核实）：

```python
class FormatOption(BaseFormatOption):
    pipeline_cls: Type[BasePipeline]          # 用哪条管线
    backend_options: Optional[BackendOptions] = None
    # 继承自 BaseFormatOption:
    #   backend: Type[AbstractDocumentBackend]
    #   pipeline_options: PipelineOptions | None
```

**三种接入姿势**：

1. **整个替换**：写一个新的 `FormatOption` 子类，把 `pipeline_cls` 和 `backend` 都换成自己的。
2. **只换 backend**：继承现成的 `WordFormatOption`，覆写 `backend = MyBackend`，`pipeline_cls` 保留 `SimplePipeline`。
3. **只换模型/选项**：保留官方 `FormatOption`，只传 `pipeline_options=MyPdfPipelineOptions(...)`。

### 换模型而不改代码

模型规格集中在四个模块（均位于 `docling/datamodel/`）：

- `stage_model_specs.py`：阶段模型预设（`StageModelPreset`、`VlmModelSpec`、`EngineModelConfig`），统一描述"某模型在某引擎下的 repo_id / revision / dtype"。
- `layout_model_specs.py`：版面检测模型预设。
- `vlm_model_specs.py`：VLM 预设，如 `GRANITEDOCLING_TRANSFORMERS`、`GRANITEDOCLING_VLLM`、`GRANITEDOCLING_MLX`、`GRANITEDOCLING_VLLM_API`、`GRANITEDOCLING_OLLAMA`（`vlm_model_specs.py:26` 起）。它们本质是 `InlineVlmOptions`（本地加载）或 `ApiVlmOptions`（远程端点）的实例。
- `asr_model_specs.py`：语音识别模型预设。

切换推理后端靠 pip extra 与引擎字段：

- 本地 Transformer/MLX/VLLM：`docling`（默认）或对应 extra。
- **ONNX Runtime**：装 `docling[models-onnxruntime]`，再把模型规格的引擎指向 ONNX Runtime。
- **远程推理**：装 `docling[models-remote]`，设 `enable_remote_services=True` 或用 `ApiVlmOptions` 指向自建/云端点。

典型用法：把 `PdfPipelineOptions` 里的 `layout_model` / `table_model` / `ocr_options` / `vlm_model_spec` 换成上述预设之一即可，无需动管线代码。

### 图片描述的三条实现路径（且只在 PDF 管线可用）

PDF 管线的 `PdfPipelineOptions` 提供 `do_picture_description`（开关）、`picture_description_options`（默认预设 `smolvlm`），以及三条实现路径的选项类（`document_converter`/pipeline_options 中定义）：

1. **内置 VLM**：`models-vlm-inline` extra，本地加载小模型（如 smolvlm）直接描述图片。
2. **API 方式**：`PictureDescriptionApiOptions`——**OpenAI 兼容的 chat completions 端点，可指向任意兼容服务**，字段含 `url / headers / params / timeout / concurrency / prompt`。这意味着你能把图片描述打到自建 vLLM、云厂商或本地 LM Studio。
3. **远程推理**：`models-remote` / `enable_remote_services`，把描述任务卸载到远程推理服务。

**必须注明**：这些定义都在 `PdfPipelineOptions` 里，而 DOCX 走 `SimplePipeline`（`WordFormatOption.pipeline_cls = SimplePipeline`），**DOCX 用不了内置图片描述**。要描述 DOCX 里的图，必须自己遍历 `PictureItem` 调 VLM（见 `[[docling/09_已知陷阱与边界|Docling 已知陷阱]]` 的 DOCX 实测结论）。

### 服务化扩展：docling-serve 与 service_client 的分工

- **docling-serve**：把转换/抽取能力暴露为 HTTP 服务，背后是 FastAPI + 可选的批处理/队列。适合**集中式 GPU、需要水平扩展、多语言客户端、与编排系统解耦**的场景。
- **service_client**：Python 客户端，把远程 docling-serve 当成本地 `DocumentConverter` 一样调用，接口对齐。

**什么场景该走服务而不是本地调用**：① 团队没有本地 GPU，想集中调度显存；② 需要并发处理大量文档、做队列与限速；③ 多个服务/语言都要用同一套解析能力；④ 想把重模型与业务进程隔离。反之，轻量脚本、单机一次性处理，本地 `DocumentConverter` 更直接。

## 实操

### 自定义一个 DeclarativeDocumentBackend 并注册进 FormatOption

下面示意如何为一个内部 XML 格式写后端并挂进转换器（示意即可，不要求完整可运行）：

```python
from io import BytesIO
from pathlib import Path
from typing import Optional, Union

from docling.backend.abstract_backend import DeclarativeDocumentBackend
from docling.datamodel.base_models import InputFormat
from docling_core.types.doc import DoclingDocument, DocItemLabel

class MyXmlBackend(DeclarativeDocumentBackend):
    def __init__(self, in_doc, path_or_stream, options=None):
        super().__init__(in_doc, path_or_stream, options)

    @classmethod
    def supports_pagination(cls) -> bool:
        return False                       # 声明式：非分页

    @classmethod
    def supported_formats(cls) -> set[InputFormat]:
        return {InputFormat.XML_DOCLANG}   # 换成你的 InputFormat

    def is_valid(self) -> bool:
        return True

    def convert(self) -> DoclingDocument:  # 唯一的核心抽象：产出 DoclingDocument
        doc = DoclingDocument(name=self.file.name)
        # 读 self.path_or_stream，按 XML 构造节点树……
        doc.add_text(label=DocItemLabel.TEXT, text="从 XML 解析出的正文")
        return doc
```

注册（声明式后端无需识别管线，配 `SimplePipeline` 即可）：

```python
from docling.document_converter import DocumentConverter, FormatOption
from docling.datamodel.base_models import InputFormat
from docling.pipeline.simple_pipeline import SimplePipeline

class MyXmlFormatOption(FormatOption):
    pipeline_cls = SimplePipeline     # 声明式后端不需 layout/table 识别
    backend = MyXmlBackend

conv = DocumentConverter(
    format_options={InputFormat.XML_DOCLANG: MyXmlFormatOption}
)
result = conv.convert("sample.dclg.xml")
```

### 自定义 serializer（新导出格式）

继承 `BaseDocSerializer`，至少实现 `serialize`、`get_parts`、`post_process`、`serialize_meta` 等抽象方法，并分别提供文本/表格/图片的 item serializer（`BaseTextSerializer` 等）。装配进 `DocSerializer` 时把各 item serializer 作为字段传入。注意：**自定义 serializer 时务必处理表格与图片元素**，否则 `TableItem`/`PictureItem` 会落到 `BaseFallbackSerializer` 而丢失结构（陷阱一节详述）。

### 换图片描述到自建 OpenAI 兼容端点

```python
from docling.datamodel.pipeline_options import PictureDescriptionApiOptions

opts.picture_description_options = PictureDescriptionApiOptions(
    url="http://localhost:8000/v1/chat/completions",
    prompt="用中文描述这张图。",
    params={"model": "my-vlm", "max_tokens": 256},
)
```

## 陷阱与边界

- **扩展 backend 忘记实现抽象方法 → 运行期才报错**：`DeclarativeDocumentBackend` 要求 `__init__/is_valid/supports_pagination/supported_formats/convert` 全实现，pydantic/ABC 只在实例化时校验，IDE 不一定提示。写完先 `conv.convert` 跑一个最小样例，别等上线才发现。
- **自定义 serializer 未处理表格与图片**：`DocSerializer.serialize`（`serializer/common.py:408`）对 `TableItem`/`PictureItem` 走各自的 item serializer，没覆写就退化成 fallback 文本，结构信息（单元格、坐标）全丢。
- **换模型后未重新验证输出格式**：`vlm_model_specs` 里不同预设的 `response_format`（如 DOCTAGS vs 纯文本）不同，换模型后 DocTags 导出可能变样；务必重新跑一遍导出与分块回归。
- **DOCX 无法用内置图片描述**：`WordFormatOption` 的 `pipeline_cls = SimplePipeline`，`PdfPipelineOptions` 里的 `do_picture_description` 对 DOCX 无效。需要图描述就自己遍历 `PictureItem` 调 VLM。
- **声明式后端不能配 PaginatedPipeline**：`PaginatedPipeline._build_document`（`base_pipeline.py:287`）会检查 backend 是否为 `PaginatedDocumentBackend`，否则直接 `RuntimeError`。声明式格式请配 `SimplePipeline` 或自定义非分页管线。
- **`FormatOption` 会自动补默认 `pipeline_options`**：`set_optional_field_default`（`document_converter.py:125`）在 `pipeline_options=None` 时调用 `pipeline_cls.get_default_options()`——自定义 `pipeline_cls` 必须实现 `get_default_options`，否则这里崩。
