# TypeScript 面试题库

> **本目录的定位：把 TypeScript 的知识点变成「面试能说出口的答案」。**
>
> 与教程正文（[[typescript/README|TypeScript 知识库]]）的分工：**教程讲「机制是什么、为什么这样设计」，本目录讲「面试官问什么、怎么答、追问到哪一层」。**
> 逐题格式统一为「先问题、后答案、再追问」，**每篇不超过 10 题，且同篇只讲一个主题**。

---

## 一、版本口径（2026-10-22 核实）

| 项 | 说明 |
|---|---|
| **TypeScript** | ⭐ **7.0**（2026-07-08 GA，**Go 原生编译器**）；**6.0**（2026-03-23）是最后一个纯 JS 实现版本；5.x 为维护线 |
| Node.js | **20+**（22/24 LTS 推荐） |
| LangChain.js | **v1**（`langchain` 1.5.x）；入口 `createAgent` / `tool` / `createMiddleware` |
| LangGraph.js | **v1**（`@langchain/langgraph` 1.4.x）；状态定义用 `StateSchema`（Zod） |
| 答题建议 | 机制题不依赖版本；⚠️ **提到 TS 6/7 的变化时必须带版本号**，这是区分「读过文档」和「跟踪过版本」的分水岭 |

⚠️ **三个必须记住的版本坑**（答错会被追问）：

1. **TS 6.0 改了默认值**：`strict: true`、`module: esnext`、`target: es2025`、`types: []`——⚠️ **`types: []` 意味着 `@types/node` 不再自动引入**，症状是满屏「Cannot find name 'process'」；
2. **TS 6.0 废弃了** `target: es5`、`moduleResolution: node/node10`、AMD/UMD、`baseUrl` 作为查找根——⚠️ **TS 7.0 会把它们变成硬错误**；
3. ⭐ **TS 7.0 不提供 compiler API**——`typescript-eslint` 等直接 import TS API 的工具需暂时留在 6.0。

⚠️ **不要背具体默认参数值**（如 G1 的堆占比、线程池推荐核心数）。说「按压测调、按 IO/CPU 密集区分」更稳。

## 三、使用方式

```
第一遍：只看问题，口述答案，卡住做标记
第二遍：读答案，重点看「追问」——面试真正考的是追问层
第三遍：把「TS vs Java」「TS vs Python」两张对比表单独背一遍（面试官最爱问这个）
```

**判断标准**：每题能用「**结论 → 机制 → 边界/代价**」三段式讲完，才算过。
只会背结论不背机制，面试官一个追问就会露底。

**时间安排建议**：40 题按主题拆成 4 轮，每轮 1 小时（40 分钟过题 + 20 分钟查漏）。

## 四、题目来源与筛选口径

参考（2026-10 核对）：

| 来源 | 用途 |
|------|------|
| 牛客网 / 掘金 / 面试鸭 | 真实提问顺序与追问深度 |
| TypeScript Handbook | **事实核对基准**，与社区文章冲突时以官方为准 |
| TypeScript 6.0 / 7.0 Release Notes | 版本差异题的唯一权威来源 |
| LangChain.js v1 官方文档 + npm 包源码 | Agent/LangGraph 相关题的 API 基准 |
| MDN Web Docs | 运行时语义的基准（Promise、模块、事件循环） |

⚠️ **筛选原则**：

1. **只收机制题、选型题、迁移题**，不收「某个类型叫什么」的记忆题；
2. **必带追问**——一道没有追问的题说明还没挖到面试的深度；
3. **版本敏感题必须标版本**，不标版本的答案在面试里等于错答案；
4. ⭐ **TS 与 Java 的对比题优先级最高**——「TS 和 Java 泛型有什么不同」「TS 为什么是结构化类型」这类问题在后端面试中出现频率极高。

## 六、答题总原则

| 原则 | 说明 |
|------|------|
| **先说结论，再说机制** | 「TS 的类型在编译后被完全擦除，运行时是纯 JS」比先讲历史更抓人 |
| **机制 → 现象 → 手段** | 每个答案都落到「所以会出现什么、怎么定位、怎么修」 |
| **主动给边界和代价** | 「用 `unknown` 而不是 `any`——代价是每次用都要先收窄」——只讲优点会被追问击穿 |
| **区分版本** | 「TS 6.0 起 `strict` 默认开启，5.x 还要手写」比笼统说「TS 很严格」可信得多 |
| ⭐ **TS vs Java 要能秒答** | 泛型擦除、结构化 vs 名义类型、`any` 逃逸、编译目标——这四条是高频 |
| **不编数字** | 参数、阈值记不准就说「量级」或「按压测调」，别报精确值 |
| **诚实说边界** | 不知道就说「这块我只用过 API，机制没深挖」——比硬编强，面试官反而会给台阶 |
