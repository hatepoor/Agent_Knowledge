## ⭐ 为什么 TypeScript 与 LangChain.js 是「天生一对」

| 维度 | 说明 |
|------|------|
| **Zod 一套 schema 两用** | ⭐ 同一份 schema **既是运行时校验器，又是静态类型来源**（`z.infer`）——这是 TS 侧相对 Python Pydantic 的核心优势 |
| **端到端类型贯通** | 工具参数 → Agent 输入 → 结构化输出，全链路无 `any` 逃逸 |
| **`StateSchema` 天然契合泛型** | `typeof State.State` / `typeof State.Update` 直接推导节点签名，reducer 的类型也带得动 |
| **同构部署** | 前端、Node 服务端、边缘运行时一套代码 |
| **测试友好** | `fakeModel()` + Zod schema → **Agent 行为可以完全离线测**，不烧 token |

⚠️ **但要诚实**：**Python 版生态更全**。LangGraph 的新特性与第三方 checkpointer 后端总是 Python 先出，TS 侧跟进。本专题第 1 篇与第 6 篇专门讲这个取舍。

## 七条通用纪律

1. **⚠️ 版本必须显式 pin。** `langchain` / `@langchain/core` / `@langchain/openai` 三者 peer 约束不同步就会装出一堆 peer 警告——用 lockfile 锁死；
2. **⚠️ 旧教程的 API 大多失效。** `createOpenAIFunctionsAgent`、`AgentExecutor`、`langchain/chains` 在 v1 已移除或迁移到 `@langchain/classic`——**照抄旧代码必然导入失败**；
3. **⚠️ 不要预先 `.bindTools()`。** v1 的 `createAgent` 内部会绑定，预绑定会抛 `MultipleToolsBoundError`；
4. **⚠️ 工具的 `description` 是模型的决策依据。** 写得笼统，模型就不调它——**这不是代码问题，是描述问题**；
5. **⚠️ 状态通道的默认 reducer 是覆盖。** 并行节点写同一通道必须显式给 reducer，否则数据丢失（并行场景会直接抛 `InvalidUpdateError`）；
6. **⚠️ 生产环境必须用 SQLite/Postgres 检查点后端。** 内存版进程重启即丢状态；而 checkpointer 写入在热路径上，无状态短请求是纯开销；
7. **⚠️ `interrupt()` 靠抛异常实现暂停。** 被 `try/catch` 吞掉，审批流程会**静默失效**——这是最难排查的一类 bug。
