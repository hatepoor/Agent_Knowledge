## 中段阶段的五条通用原则

1. **⚠️ 类型检查和转译是两件事。** `tsc` 先查类型再转译；`esbuild`/`tsx` **只转译不查类型**——⭐ **CI 里必须单独跑 `tsc --noEmit`**，否则类型错误会漏到线上；
2. **⚠️ `strict` 是类型系统的地基。** 关掉 `strictNullChecks` 等于关掉一半的 TS 价值——**新项目一律开**；
3. **⚠️ ESM 与 CJS 的互操作是 bug 温床。** 相对导入**必须带扩展名**、默认导入是否需要 `esModuleInterop`、`exports` 条件导出怎么配——三个点任意一个配错都是运行时才炸；
4. **⚠️ Node 是单线程的。** CPU 密集任务会**卡死整个事件循环**（不只是变慢）；解法是 `worker_threads` 或独立进程；
5. **⚠️ `Promise.all` 是并发而非并行安全的兜底。** 一个失败就整体失败，且**其余请求不会被取消**——需要部分失败容忍就用 `allSettled`，需要限制并发就得自己实现并发池。

## 版本纪律

6. **⚠️ TS 6.0 改了默认值，`types: []` 是最容易踩的一个。** 用 `@types/node` 的项目升级后会满屏 `Cannot find name 'process'`，需显式写 `"types": ["node"]`；
7. **⚠️ TS 7.0 会把 6.0 的废弃项变成硬错误。** 迁移前把 `target: es5`、`moduleResolution: node`、`baseUrl` 清理干净，别用 `"ignoreDeprecations"` 掩盖。
