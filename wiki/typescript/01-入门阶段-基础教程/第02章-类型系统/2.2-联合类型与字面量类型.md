# 联合类型与字面量类型

> **什么时候该读**：你在设计一个"可能是 A 也可能是 B"的数据结构（接口返回成功还是失败、命令参数、状态码），想知道联合类型怎么写、为什么访问属性会报错，以及**判别联合（discriminated union）**这个 TS 最实用的模式怎么用。
> **阅读门槛**：读完 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.1-类型推断与注解]]。本篇会用到的 `as const`、`satisfies`、上下文类型都在 2.1 讲过；`switch` 收窄的完整机制在 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.4-类型收窄与类型守卫]]。

## 学习目标

读完本篇，你应当能够：

1. 写出联合类型 `string | number`，并说明它表示什么
2. 用**字面量类型** `"success" | "error"` 把取值锁死在一组固定值上
3. 解释联合类型上的**属性访问限制**（为什么 `a.toFixed()` 会报错），并说出正确的处理方式
4. ⭐ 用**判别联合（discriminated union）**建模"多种形态"，并说清 switch 为什么能自动收窄
5. ⭐ 用 `as const` + 字面量类型写出「常量表」，并解释它与 `enum` 的差别
6. ⭐ 解释 TS 的 `enum` 为什么**会生成运行时代码**，以及**用联合字面量替代 `enum`** 的做法与取舍
7. 说清 `const enum` 的问题（跨文件编译、`isolatedModules`）
8. 用联合类型写出「多态参数」——一个函数同时接受多种类型

## 一、联合类型 `|`：类型层面的"或"

### 是什么

**联合类型（union type）** 用 `|` 连接多个类型，表示**这个值是其中任意一个**：

```ts
let value: string | number;

value = "hello";   // ✅
value = 42;        // ✅
value = true;      // ⚠️ 报错：Type 'boolean' is not assignable to type 'string | number'
```

它等价于"这个值**至少**符合其中一个类型"，而不是"同时符合"。

### 与 Python 的差异

```python
from typing import Union
value: Union[str, int] = "hello"
```

| 维度 | TypeScript | Python |
|------|-----------|--------|
| 写法 | `string \| number` | `Union[str, int]`（3.10+ 可写 `str \| int`） |
| 运行时检查 | ❌ 类型被擦除，运行时不做任何事 | ❌ 同上 |
| 静态检查 | ✅ `tsc` 检查 | ✅ mypy / pyright 检查 |
| 收窄 | ✅ 自动（见第四节） | ❌ 无自动收窄，需 `isinstance` 手写 |

⭐ **重要区别**：TS 的联合类型是**编译器**直接理解的结构，`switch`/`if` 能自动收窄（2.4 详讲）；Python 的 `Union` 只是给静态检查器看的，运行时**完全不存在**。

### 联合类型的"成员都有"性质

联合类型是**可交换的**：`string | number` 和 `number | string` 完全等价。

## 二、字面量类型：把值锁死

### 是什么

**字面量类型（literal type）** 表示"**这个值只能是这一个具体值**"，而不是它的基础类型。

```ts
let status: "success" | "error";   // 只能是这两个字符串之一

status = "success";   // ✅
status = "error";     // ✅
status = "pending";   // ⚠️ 报错：Type '"pending"' is not assignable to type '"success" | "error"'
```

不只是字符串，数字和布尔也可以：

```ts
type Code = 200 | 404 | 500;
type Flag = true | false;
```

### ⚠️ 为什么 `let` 和 `const` 的推断结果不同

```ts
const a = "success";   // a: "success"  ← 字面量类型（const 不可重新赋值，可以安全保留精确值）
let b = "success";     // b: string    ← 拓宽成基础类型（let 之后可能被改成别的字符串）
```

这个现象叫**字面量拓宽（literal widening）**：字面量类型在**可变**位置会被拓宽成它的基础类型。

```ts
let b = "success";
b = "error";   // ✅ 合法，因为 b 的类型是 string
```

```ts
let c: "success" | "error" = "success";
c = "error";   // ✅ 合法，联合类型本来就允许
```

### ⭐ 联合字面量类型 + `as const` 的组合用法

这是 TS 里做**常量表**的标准写法：

```ts
const STATUS = {
  PENDING: "pending",
  SUCCESS: "success",
  ERROR: "error",
} as const;

type Status = (typeof STATUS)[keyof typeof STATUS];
// 等价于 type Status = "pending" | "success" | "error"
```

⭐ **逐层拆解这句话的意思**：

| 片段 | 含义 |
|------|------|
| `as const` | 把每个值冻结成字面量类型，并加上 `readonly` |
| `typeof STATUS` | 取 `STATUS` 这个**值**的类型（详见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.3-泛型与类型约束]]） |
| `(typeof STATUS)[keyof typeof STATUS]` | 取这个对象**所有键对应的值的类型**（索引访问类型 + `keyof` 组合） |
| 结果 | `"pending" \| "success" \| "error"` |

然后可以直接用作函数参数类型：

```ts
const STATUS = {
  PENDING: "pending",
  SUCCESS: "success",
  ERROR: "error",
} as const;

type Status = (typeof STATUS)[keyof typeof STATUS];

function handle(status: Status) {
  if (status === STATUS.SUCCESS) {
    console.log("成功");
  }
}
```

⭐ **更简洁的等价写法**（`as const` + `satisfies` 组合，`satisfies` 是 TS 4.9 引入的）：

```ts
const STATUS = {
  PENDING: "pending",
  SUCCESS: "success",
  ERROR: "error",
} as const satisfies Record<string, string>;

type Status = (typeof STATUS)[keyof typeof STATUS];
```

用 `satisfies Record<string, string>` 的好处：既保证所有值都是字符串（防止有人手滑写成数字），又保留了精确的字面量类型（见 2.1 第六节）。

### 用 `satisfies` 保证键名不拼错、成员不遗漏

```ts
type StatusKey = "PENDING" | "SUCCESS" | "ERROR";

const STATUS = {
  PENDING: "pending",
  SUCCESS: "success",
  ERROR: "error",
} as const satisfies Record<StatusKey, string>;

// ⭐ Record<StatusKey, string> 做两件事：
// ① 强制这三个键**全部必须出现**（少一个就报错）
// ② 键名拼错立刻报错（写错 "PENDING" 成 "PENDDING" 会被拦下）
```

## 三、联合类型的属性访问限制

### 问题：只有共有属性才能访问

联合类型上的属性访问，**必须存在于所有成员中**：

```ts
declare let value: string | number;

value.toFixed();     // ⚠️ 报错：Property 'toFixed' does not exist on type 'string | number'
value.length;        // ⚠️ 报错：'length' does not exist on type 'number'
value.toString();    // ✅ 所有类型都有 toString（继承自 Object）
```

> 小技巧：示例里用 `declare let value: ...` 而不是 `let value: ...`——`declare` 表示"这个变量由外部提供，我只用它做类型演示"，编译器就不会再报"变量在使用前未被赋值"这种与主题无关的噪音。

**为什么**：联合类型可能**任一时刻**是 `string` 或是 `number`。如果允许调用 `toFixed()`，那当它是字符串时就崩了。编译器必须假设"最坏情况"。

### 三种处理方式

**方式一：先收窄（推荐）**——见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.4-类型收窄与类型守卫]]：

```ts
declare let value: string | number;

if (typeof value === "string") {
  value.length;      // ✅ 块内 value 已被收窄为 string
} else {
  value.toFixed();   // ✅ 块内已收窄为 number
}
```

**方式二：所有成员都有的属性**——直接访问：

```ts
declare let value: string | number;
value.toString();    // ✅
```

**方式三：用 `in` 收窄**——适合对象联合：

```ts
type Cat = { meow: () => void };
type Dog = { bark: () => void };
type Pet = Cat | Dog;

function speak(pet: Pet) {
  if ("meow" in pet) {
    pet.meow();     // ✅ 已收窄为 Cat
  } else {
    pet.bark();     // ✅ 已收窄为 Dog
  }
}
```

⭐ **`in` 的关键作用**：它能区分"这个属性**存在于**哪个成员"。如果两个成员都有 `name` 属性，`in` 就无法区分了——这正是下一节**判别联合**要解决的问题。

## 四、⭐ 判别联合（discriminated union）：TS 最实用的模式之一

### 什么是判别联合

**判别联合（discriminated union，也叫可辨识联合）** 是一种联合类型，其中每个成员都有一个**共同的、取值互不重叠的字面量字段**——这个字段叫**判别器（discriminator）**。

编译器看到判别器，就能确定当前是哪个成员，从而**自动收窄**（automatic narrowing）整个对象。

### 完整例子

```ts
// 每个成员都有 kind 字段，取值互不重叠
type Result =
  | { kind: "success"; data: string; code: number }
  | { kind: "error"; message: string; retryable: boolean }
  | { kind: "loading"; progress: number };

function render(result: Result) {
  switch (result.kind) {
    case "success":
      // ✅ result 自动收窄为 { kind: "success"; data: string; code: number }
      console.log(result.data, result.code);
      break;
    case "error":
      // ✅ 自动收窄为 error 成员
      console.log(result.message, result.retryable);
      break;
    case "loading":
      console.log(result.progress);   // ✅ 只有 progress 可访问
      break;
  }
}
```

⭐ **对比一下没有判别器会怎样**：

```ts
// ❌ 普通联合：data / message / progress 分属不同成员
type Result2 =
  | { data: string }
  | { message: string }
  | { progress: number };

function render2(result: Result2) {
  console.log(result.data);   // ⚠️ 报错：'data' does not exist on type 'Result2'
}
```

**判别器把"哪些成员"的信息编码进了一个可比较的字面量字段**，于是编译器能顺着它做控制流分析。

### 为什么这比"可选属性"好

另一种常见做法是**所有字段都可选**：

```ts
// ❌ 可选属性方案
type Result3 = {
  data?: string;
  message?: string;
  progress?: number;
};
```

对比结果：

| 维度 | 可选属性方案 | ⭐ 判别联合方案 |
|------|-------------|---------------|
| 字段访问 | 每个字段都要判空：`if (r.data !== undefined)` | 判别器一判断，整个对象就定了 |
| 非法状态 | ❌ 能构造出"三个字段都没有"的对象 | ✅ **不可能**——必须有一个 `kind` |
| 编译器收窄 | 只能收窄单个字段 | ⭐ **收窄整个对象** |
| 新增分支 | 所有 `if` 都要重新检查 | 只改联合定义 + switch 加 `case`（编译器会提示漏了） |

⭐ **一句话**：判别联合让"**不可能的状态无法被表示**"（impossible states unrepresentable），这是类型系统最有价值的用法之一。

### 判别联合 + `never` = 穷尽检查

完整的"新增类型成员时自动报错"效果，要配合 `never`：

```ts
type Result =
  | { kind: "success"; data: string }
  | { kind: "error"; message: string };

function assertNever(x: never): never {
  throw new Error("未处理的类型: " + x);
}

function render(result: Result) {
  switch (result.kind) {
    case "success":
      console.log(result.data);
      break;
    case "error":
      console.log(result.message);
      break;
    default:
      // ✅ 编译器证明这里 result 只能是 never
      assertNever(result);
  }
}
```

⭐ **机制**：当 `switch` 的所有 `case` 都覆盖了联合类型后，`default` 分支里的 `result` 类型就是 `never`（**穷尽性证明**）。如果以后给联合类型加了第三个成员 `"pending"`，这一行会**立刻报错**，提醒你补一个 `case`。

`never` 与断言函数的完整机制见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.4-类型收窄与类型守卫]]。

### 判别联合的适用范围

判别器不一定是字符串字面量，任何**可比较**的字段都行：

```ts
// 数字判别器
type Shape =
  | { kind: 1; radius: number }
  | { kind: 2; width: number; height: number };

// 布尔判别器
type ApiResponse =
  | { ok: true; value: string }
  | { ok: false; error: Error };
```

⚠️ **前提**：判别器字段的类型必须是**字面量类型**（或至少是"单位类型"的封闭集合）。如果写成 `kind: string`，编译器就没法收窄了。

## 五、⭐ `enum` 的取舍

### TS 的 `enum` 会生成运行时代码

⭐ **这是最关键的一点**：TypeScript 的 `enum` **不是纯类型**，它是**运行时代码**。

```ts
enum Direction {
  Up,      // 0
  Down,    // 1
  Left,    // 2
}
```

编译成 JavaScript 后：

```js
var Direction;
(function (Direction) {
    Direction[Direction["Up"] = 0] = "Up";
    Direction[Direction["Down"] = 1] = "Down";
    Direction[Direction["Left"] = 2] = "Left";
})(Direction || (Direction = {}));
```

也就是说：**运行时会真的存在一个 `Direction` 对象**，`Direction.Up` 是一次真实的属性访问。这带来几个后果：

1. **产物体积变大**——多出一整个对象；
2. **无法被 `const` 优化掉**——因为它有运行时存在性；
3. **有"反向映射"**——`Direction[0]` 居然等于 `"Up"`（因为 `Direction["Up"] = 0` 这一步建立了数字到字符串的反向索引）。

```ts
enum Direction { Up, Down }
console.log(Direction[0]);   // "Up" ← 反向映射（Python 的 enum 没有这个）
```

⭐ **这就是 `enum` 在现代 TS 项目里常被诟病的原因**：它是"TypeScript 的历史遗留特性"，与其他语言（Java、Rust、Go）的枚举都不一样。

### ⭐ 对比：联合字面量替代 `enum`

**方案 A：传统 `enum`**（生成运行时代码，有反向映射）：

```ts
enum Direction {
  Up = "UP",
  Down = "DOWN",
}
```

**方案 B：纯联合字面量类型**（零运行时代码，但没有"命名"体验）：

```ts
type Direction = "UP" | "DOWN";

function move(d: Direction) { /* ... */ }
move("UP");   // ✅ 只能用字面量，不能写 Direction.Up
```

**方案 C：常量对象 + `as const`**（保留"命名"体验，零运行时代码）：

```ts
const Direction = {
  Up: "UP",
  Down: "DOWN",
} as const;

type Direction = (typeof Direction)[keyof typeof Direction];

function move(d: Direction) { /* ... */ }

move(Direction.Up);   // ✅ 体验和 enum 几乎一样
```

> ⚠️ 注意方案 C 里 `const Direction` 和 `type Direction` **同名是合法的**——TypeScript 的**值**和**类型**分属两个命名空间（`namespace`），`const` 占值空间，`type` 占类型空间。但 `enum Direction` **两个空间都占**，所以它不能和同名的 `type`/`const` 共存。

| 维度 | `enum` | ⭐ 联合字面量 / `as const` 常量对象 |
|------|--------|----------------------------------|
| 运行时产物 | ⚠️ **生成 JS 对象** | ✅ 完全没有 |
| 反向映射 | ✅ 有（`Direction[0] === "Up"`） | ❌ 无（这是优点，不是缺点） |
| 类型系统地位 | 独立类型，**不与字面量类型互通** | 就是普通联合类型，**与字符串字面量完全兼容** |
| 跨枚举比较 | ❌ 不同 enum 之间不能直接比 | ✅ 自由比较 |
| 与 `satisfies` 配合 | 一般 | ✅ 天然契合 |
| 需要 `import` 才能用 | ✅ 是（enum 是值） | ✅ `as const` 对象也是值，同样要 import |

### ⭐ `enum` 与字面量类型不能互通（重要陷阱）

```ts
enum Direction { Up = "UP" }
type Direction2 = "UP";

declare const a: Direction;
declare const b: Direction2;

a === b;   // ⚠️ 报错：This comparison appears to be unintentional because the types 'Direction' and 'Direction2' have no overlap
```

⭐ **原因**：`enum` 的成员类型是"**名义类型**"（nominal type）——`Direction.Up` 是一种**独特的**类型，不是 `string`。而 `"UP"` 是字符串字面量类型。两者虽然运行时值一样，编译器认为它们**没有交集**。

这是 `enum` 最大的隐性成本：**它把一个普通的字符串/数字变成了一个"新类型"，从此和外界不互通**。

### 什么时候仍然该用 `enum`

不要盲目排斥。`enum` 仍有适用场景：

| 场景 | 为什么 |
|------|--------|
| 需要**运行时**的对象（如传给库、挂在 `window` 上） | 联合字面量是纯类型，运行时不存在任何东西 |
| 需要**反向映射** | `enum` 独有 |
| 需要**数值自增**且依赖运行时计算 | `as const` 做不到自动编号 |
| 与**非 TS 语言**（Java、C#）交互 | 对方用数值枚举，编译产物要对齐 |

⭐ **默认建议**：**新项目优先用 `as const` 常量对象 + 联合类型**；只有确实需要运行时产物时才用 `enum`。

### ⚠️ `const enum` 的问题

**`const enum`**（常量枚举）声明的是"编译期内联、不生成运行时对象"的枚举：

```ts
const enum Direction {
  Up = 0,
  Down = 1,
}

const d = Direction.Up;   // 编译后直接变成 0
```

编译产物（实测 `tsc --target es2015`）：

```js
const d = 0 /* Direction.Up */;   // 没有任何 Direction 对象
```

⭐ **它解决的问题**：既保留 `enum` 的写法，又不生成运行时对象。

⚠️ **但它有两个硬伤**：

**硬伤一：跨文件编译会坏**

`const enum` 的内联依赖编译器**看到别的文件里的声明**。当项目用 **按文件独立转译**的构建工具（Vite、esbuild、swc、Babel）时，构建工具不认识 `const enum` 这套语义：

```ts
// a.ts
export const enum Level { Low = 1, High = 2 }
```

```ts
// b.ts
import { Level } from "./a";
const x = Level.Low;   // ⚠️ 构建工具逐文件转译时可能报错或行为不一致
```

**硬伤二：`isolatedModules` 下访问"环境 const 枚举"会报错**

开启 `isolatedModules: true`（现代构建工具的默认做法）时，**从 `.d.ts` 里访问 `declare const enum`** 会直接报错：

```ts
// 某个第三方库发布的 types.d.ts
export declare const enum Level { Low = 1, High = 2 }
```

```ts
// 你的代码（some-lib 是上面那个库）
import { Level } from "some-lib";
console.log(Level.Low);   // ⚠️ 报错 TS2748：Cannot access ambient const enums when 'isolatedModules' is enabled
```

⚠️ 注意区分：**你自己 `.ts` 文件里写的普通 `const enum` 在 `isolatedModules` 下不报错**（实测 TS 5.8 与 7.0 均如此）；真正报错的是**从类型声明文件（`.d.ts`）里访问"环境 const 枚举"**——因为单文件转译根本看不到那个声明。

⭐ **结论**：`const enum` 是"看起来很美、用起来很痛"的特性——跨文件内联和 `isolatedModules` 这两件事加起来，足以让现代工具链下的它变得不可预测。**现代 TS 项目里基本不要用**。

### ⚠️ `as const` 与 `enum` 混用的坑

```ts
enum Status { Active = "active" }

// ❌ 坑 1：想用字面量类型，但 enum 的成员不是字面量类型
type S1 = "active";              // 字符串字面量类型
type S2 = Status.Active;         // enum 成员类型 —— 和 S1 不互通
const v: S1 = Status.Active;     // ⚠️ 报错：Type 'Status.Active' is not assignable to type '"active"'
```

**坑 2：`as const` 对 enum 成员无效**

```ts
enum Status { Active = "active" }

const s = { status: Status.Active } as const;
// s.status 的类型是 Status.Active（enum 成员类型），不是 "active"
```

**坑 3：想用 enum 又想用 `satisfies`，两边不兼容**

```ts
enum Status { Active = "active" }

// 混用时，satisfies 的目标类型必须是 enum 本身
const s = { status: Status.Active } satisfies { status: Status };   // ✅ 这样才行
```

⭐ **最佳实践**：**不要混用**。要么全用 `enum`，要么全用 `as const` + 联合字面量。混用时你会同时遇到"名义类型不互通"和"字面量信息丢失"两个问题。

## 六、联合类型在函数参数上的应用（多态参数）

### 基础：接受多种类型

```ts
function formatId(id: string | number): string {
  return `ID-${id}`;
}

formatId(42);        // ✅
formatId("abc");     // ✅
```

### 进阶：返回类型也跟着变

如果希望"传 `string` 就返回 `string` 类型，传 `number` 就返回 `number` 类型"，普通联合类型做不到——因为返回类型不能依赖参数类型。

这需要**泛型 + 条件类型**（详见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.3-泛型与类型约束]]）：

```ts
function parse<T extends string | number>(input: T): T {
  // 返回类型跟着输入走
  return input;
}

const s = parse("abc");   // s: string
const n = parse(42);      // n: number
```

### 更常见的用法：`Array<string | number>` 做混合数组

```ts
const mixed: (string | number)[] = [1, "a", 2, "b"];
```

⚠️ 注意写法：`string | number[]` 是**错的**（它表示「**要么是一个 string，要么是一个 number 数组**」），必须加括号写成 `(string | number)[]`。

```ts
// ❌ 这里的类型是 "string 或 number 数组"，不是混合数组
const wrong: string | number[] = [1, 2];        // ✅ 碰巧合法：这是一个 number[]
const alsoWrong: string | number[] = "hello";   // ✅ 碰巧合法：这是一个 string
const mixedWrong: string | number[] = [1, "a"]; // ⚠️ 报错：混合数组两个分支都不匹配

// ✅ 混合数组必须加括号
const right: (string | number)[] = [1, "a"];    // ✅ 这是混合数组
```

## 七、联合类型与 `switch` 的配合

### 完整的判别联合处理流程

```ts
type NetworkState =
  | { status: "idle" }
  | { status: "loading"; progress: number }
  | { status: "success"; data: string[] }
  | { status: "error"; code: number; message: string };

function describe(state: NetworkState): string {
  switch (state.status) {
    case "idle":
      return "空闲中";
    case "loading":
      return `加载中 ${state.progress}%`;        // ✅ 只有 loading 有 progress
    case "success":
      return `成功，共 ${state.data.length} 条`;  // ✅ 只有 success 有 data
    case "error":
      return `错误 ${state.code}: ${state.message}`;  // ✅ 只有 error 有 code
    default: {
      // 编译器在这里证明 state 是 never —— 如果上面漏了 case，这里会报错
      const exhaustive: never = state;
      return exhaustive;
    }
  }
}
```

⭐ **`default` 分支里的 `const exhaustive: never = state;` 是 TS 的标准惯用法**——它的作用是"**穷尽性证明**"：编译器会检查 `state` 在此处是否真的可以是 `never`。如果将来给 `NetworkState` 加一个新成员而没加 `case`，这一行立刻编译报错。

### 用 `if` 也能收窄

```ts
type NetworkState =
  | { status: "idle" }
  | { status: "loading"; progress: number }
  | { status: "success"; data: string[] }
  | { status: "error"; code: number; message: string };

function describe2(state: NetworkState): string {
  if (state.status === "loading") {
    return `${state.progress}%`;   // ✅ 已收窄
  }
  if (state.status === "error") {
    return `${state.code}`;         // ✅ 已收窄
  }
  // 此时 state 是 idle | success 的联合
  return "其他";
}
```

⭐ `switch` 的优势是**更容易做穷尽性检查**（`default` + `never`），`if` 链则更灵活。

## 陷阱

1. **⚠️ 以为 `enum` 是纯类型**——TS 的 `enum` **会生成运行时代码**（一个真实的 JS 对象），产物变大、有"反向映射"（`Direction[0] === "Up"`）；新项目优先用 `as const` 常量对象 + 联合字面量类型；
2. **⚠️ 以为 `enum` 成员就是字面量类型**——`enum` 是**名义类型**，`Direction.Up` 和 `"UP"` 是**没有交集**的两个类型，互相赋值/比较会报错；
3. **⚠️ 用 `const enum`**——它在跨文件独立转译（Vite/esbuild/swc）时语义不成立；在 `isolatedModules: true` 下**从 `.d.ts` 访问"环境 const 枚举"**会直接报错（TS2748）；现代项目不要用；
4. **⚠️ 混用 `as const` 与 `enum`**——`as const` 不会把 enum 成员变成字符串字面量类型，两套体系不互通；**要么全 enum，要么全 `as const`**；
5. **⚠️ 在联合类型上直接访问非共有属性**——`value.toFixed()`（`value: string | number`）会报错，因为编译器必须假设最坏情况；先 `typeof` 收窄；
6. **⚠️ 写 `string | number[]` 想表达混合数组**——这是"string **或** number 数组"，混合数组必须写 `(string | number)[]`；
7. **⚠️ 用 `let` 声明再指望保留字面量类型**——`let s = "ok"` 推断为 `string`，字面量类型会被拓宽；要精确请用 `const` 或 `as const`；
8. **⚠️ 以为 `as const` 出来的对象的键名受联合类型约束**——`as const` **不做任何校验**，要校验键名必须配 `satisfies Record<Status, string>`；
9. **⚠️ 判别器字段写成 `string` 而不是字面量联合**——`kind: string` 无法收窄，判别联合就失效了；
10. **⚠️ 忘了 `switch` 会漏分支**——加了新的联合成员却不加 `case`，编译器不会自动报错；用 `default` + `never` 断言来强制检查；
11. **⚠️ 用 `in` 收窄时两个成员都有该属性**——`in` 无法区分，此时必须换成**字面量判别器**（第四节的做法）。

## 小结

- **联合类型** `A | B` 表示"是其中之一"；`string | number[]` ≠ 混合数组，混合数组要写 `(string | number)[]`
- **字面量类型** 把值锁死成 `"success"`、`200` 这样的具体值；`let` 会拓宽、`const` 不会
- ⭐ **联合字面量 + `as const`**：`(typeof OBJ)[keyof typeof OBJ]` 是提取"常量表所有取值"的标准写法，常与 `satisfies Record<Status, string>` 搭配
- ⭐ **判别联合**是 TS 最实用的模式：用共同字面量字段做判别器，switch/if 能**自动收窄整个对象**，并且让非法状态无法被表示；比"全部字段可选"强得多
- ⭐ **穷尽性检查**：`default` 分支里写 `const exhaustive: never = state;`，新增联合成员时编译器会立刻报错
- 联合类型的属性访问**只允许共有成员**；用 `typeof` / `in` / 判别器收窄后再访问
- ⭐ **`enum` 会生成运行时代码**（真实的 JS 对象 + 反向映射），且是**名义类型**、不与字面量类型互通；新项目优先用 `as const` 常量对象 + 联合类型
- ⭐ **`const enum` 在按文件独立转译下会坏，在 `isolatedModules: true` 下访问 `.d.ts` 里的"环境 const 枚举"会报 TS2748**，现代项目避免使用
- 联合类型做函数参数可以实现"多态参数"；需要"返回类型跟随参数"则要上泛型 + 条件类型
