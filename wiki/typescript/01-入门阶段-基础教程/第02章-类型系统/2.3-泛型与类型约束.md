# 泛型与类型约束

> **什么时候该读**：你写了一个只对 `string` 有意义的函数，现在想让它同时支持 `number`；或者你在封装一个 API 库，想让调用者的类型信息能"流"到返回值里；又或者你看到 `T extends U ? X : Y` 这种看不懂的代码。
> **阅读门槛**：读完 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.2-联合类型与字面量类型]]。本篇的"类型运算符"部分（`keyof`、`typeof`、索引访问）是后续「类型体操」的门票，[[typescript/interview/02-泛型与类型体操]] 会考得更细。

## 学习目标

读完本篇，你应当能够：

1. 写泛型函数、泛型类、泛型接口，并说清泛型相比 `any` 的优势
2. 用 `extends` 约束泛型类型参数（`T extends { id: string }`），包括多个约束（`T extends A & B`）
3. 用 `keyof` 取出对象的键联合类型
4. 用 `typeof`（**类型位置**的 `typeof`）取出某个值的类型
5. 用索引访问类型 `T[K]` 取出属性类型，并和 `keyof` 组合出"取属性类型"的通用工具
6. ⭐ 写条件类型 `T extends U ? X : Y`，并解释**分布式条件类型**的分发规则
7. ⭐ 写映射类型 `{ [K in keyof T]: ... }`，并知道它会**移除 `readonly` 与可选性**
8. 用泛型默认值 `<T = unknown>`（TypeScript 2.3+）

## 一、泛型是什么

### 问题：既要通用，又要保留类型信息

假设你要写一个 `first` 函数，取数组的第一个元素：

```ts
// ❌ 方案一：any —— 丢失所有类型信息
function firstAny(arr: any[]): any {
  return arr[0];
}
const n = firstAny([1, 2, 3]);
n.toFixed();   // ✅ 编译通过 —— 但如果 n 其实是字符串呢？运行时炸
```

```ts
// ❌ 方案二：具体类型 —— 不通用
function firstString(arr: string[]): string | undefined {
  return arr[0];
}
```

**泛型（generics）** 就是第三种方案：**用一个"类型占位符"代替具体类型，让调用者来填，同时把填进去的类型信息保留下来**。

```ts
// ✅ 泛型
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const n = first([1, 2, 3]);    // n: number | undefined
n?.toFixed();                  // ✅ 编译器知道 n 是 number

const s = first(["a", "b"]);   // s: string | undefined
s?.toUpperCase();              // ✅ 编译器知道 s 是 string
```

⭐ **泛型的本质**：`first` 只有一份实现，但调用时 `T` 会被**分别**替换成 `number` 和 `string`。这叫**泛型实例化**。

### 与 Python 的差异

```python
from typing import TypeVar, Sequence

T = TypeVar("T")

def first(arr: Sequence[T]) -> T | None:
    return arr[0] if arr else None
```

| 维度 | TypeScript | Python |
|------|-----------|--------|
| 语法 | `<T>` 放在名字后面 | `TypeVar("T")` + `Generic[T]` 基类（3.12+ 可用 `class Box[T]` 新语法） |
| 运行时 | ❌ 泛型被擦除 | ❌ 同样擦除（`Generic[T]` 只是元类技巧） |
| 约束 | `<T extends X>` | `TypeVar("T", bound=X)` 或 `TypeVar("T", int, str)` |
| 默认值 | `<T = unknown>` | `TypeVar("T", default=int)`（3.13+） |
| 推导时机 | 调用时 | 调用时 |

⭐ **最大差异**：TS 的泛型**在类型层面可以任意复杂**（条件类型、映射类型、模板字面量），而 Python 的泛型基本只做"参数化"。TS 的泛型是**类型编程**的语言，Python 的泛型更接近"带类型的容器"。

## 二、泛型函数、泛型类、泛型接口

### 泛型函数

```ts
function identity<T>(value: T): T {
  return value;
}

const s = identity("hello");   // s: string
const n = identity(42);        // n: number
```

⭐ **多个类型参数**：

```ts
function pair<A, B>(a: A, b: B): [A, B] {
  return [a, b];
}

const p = pair("x", 1);   // p: [string, number]
```

### 泛型接口

```ts
interface Box<T> {
  value: T;
  get(): T;
  set(v: T): void;
}

const numBox: Box<number> = {
  value: 1,
  get() { return this.value; },
  set(v) { this.value = v; },
};
```

### 泛型类

```ts
class Stack<T> {
  private items: T[] = [];

  push(item: T): void { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
  peek(): T | undefined { return this.items[this.items.length - 1]; }
  get size(): number { return this.items.length; }
}

const s = new Stack<string>();
s.push("a");
s.peek();   // string | undefined
```

⭐ **泛型类的一个限制**：类型参数**只在类的定义处声明一次**，不能在使用时"部分具体化"：

```ts
class Pair<A, B> { /* ... */ }

type StringPair = Pair<string, string>;   // ✅ 必须两个都写
// type PartialPair = Pair<string>;        // ❌ 报错：泛型类型要求 2 个类型参数
```

⭐ **默认值可以解决这个问题**（见第七节）。

## 三、⭐ `extends` 约束

### 什么是约束

泛型如果不加限制，`T` 可以是任何东西（包括 `number`、`string`、`null`）。但很多时候我们**需要 T 至少具备某些能力**——比如必须有个 `id` 字段。**`extends` 约束**就是给 `T` 划一条底线。

```ts
// T 必须是一个"有 id 字段"的对象
function getId<T extends { id: string }>(item: T): string {
  return item.id;
}

getId({ id: "a", name: "x" });   // ✅
getId({ name: "x" });             // ⚠️ 报错：缺少 id 属性
getId("just a string");          // ⚠️ 报错：string 不满足约束
```

⭐ **关键理解**：约束**不是**"把 T 变成 `{id: string}`"，而是"**T 至少得是 `{id: string}` 的子类型**"。所以在函数体内部，`item` 仍然拥有 `T` 的完整类型——如果 `T` 额外有 `name` 字段，你在里面照样能访问。

```ts
function getId<T extends { id: string }>(item: T): string {
  return item.id;
  // item.name 在这里会报错 —— 因为 T 的约束只保证有 id，
  // 不能假设有 name
}
```

### 多个约束：`T extends A & B`

用 `&`（交叉类型，intersection）组合：

```ts
interface HasId { id: string }
interface HasName { name: string }

function describe<T extends HasId & HasName>(item: T): string {
  return `${item.id}: ${item.name}`;   // ✅ 两个属性都能访问
}

describe({ id: "1", name: "a" });   // ✅
describe({ id: "1" });              // ⚠️ 报错：缺少 name
```

### 用接口作为约束（更清晰）

约束写成内联对象类型也行，但**用接口更可读**：

```ts
// ✅ 内联
function inline<T extends { id: string; name: string }>(x: T) { }
```

```ts
// ✅ 接口
interface Entity { id: string; name: string }
function withInterface<T extends Entity>(x: T) {}
```

### ⚠️ 约束不是运行时检查

⭐ **`extends` 只在编译期检查**，编译后完全没有对应的 JavaScript 代码：

```ts
function getId<T extends { id: string }>(item: T): string {
  return item.id;
}
```

编译后（类型全被擦除）：

```js
function getId(item) {
  return item.id;
}
```

所以**运行时传入一个没有 `id` 的对象，照样能调用**，只是 `item.id` 会得到 `undefined`。约束是"**编译期的契约**"，不是运行时校验。

## 四、⭐ `keyof` 运算符

### 是什么

**`keyof`** 取一个类型的**所有键名**，结果是一个**字面量类型的联合**：

```ts
interface Person {
  name: string;
  age: number;
  email: string;
}

type PersonKeys = keyof Person;
// 等价于：type PersonKeys = "name" | "age" | "email";
```

### 它最直接的用途：限制属性名

```ts
interface Person {
  name: string;
  age: number;
  email: string;
}

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];   // ✅ 编译器知道 obj[key] 是合法的
}

const p: Person = { name: "a", age: 1, email: "e" };
getProperty(p, "name");   // ✅ 返回类型是 string
getProperty(p, "age");    // ✅ 返回类型是 number
getProperty(p, "nope");   // ⚠️ 报错：'"nope"' 不能赋给 '"name" | "age" | "email"'
```

⭐ 注意 `K extends keyof T` 这个约束的威力：`K` 只能是 `T` 真实拥有的键，所以 `obj[key]` 一定合法。

### `keyof` 的几种变体

```ts
type Person = { name: string; age: number };

// 1. 联合类型的 keyof：取交集
type A = { a: string; b: number };
type B = { b: string; c: boolean };
type Common = keyof (A | B);   // "b" —— 只有共有属性

// 2. 交集类型的 keyof：取并集
type All = keyof (A & B);       // "a" | "b" | "c"

// 3. keyof 数组
type ArrKeys = keyof string[];  // number | "length" | "push" | ... （数组方法全在里面）
```

### `keyof` 与 `typeof` 组合（取常量对象的键）

```ts
const ACTIONS = {
  ADD: "add",
  REMOVE: "remove",
} as const;

type ActionKey = keyof typeof ACTIONS;      // "ADD" | "REMOVE"
type ActionValue = (typeof ACTIONS)[ActionKey];   // "add" | "remove"
```

⭐ `(typeof ACTIONS)[ActionKey]` 这一招叫**索引访问类型**，见第六节。

## 五、⭐ `typeof`（类型位置）

### 两种 `typeof`，别搞混

| 写法 | 位置 | 含义 |
|------|------|------|
| `typeof x` | **值**位置（写在表达式里） | 运行时运算符，返回字符串 `"string"` / `"number"` 等 |
| `typeof x` | **类型**位置（写在类型注解里） | 取 `x` 这个**值的类型**，编译后完全擦除 |

```ts
const config = { host: "localhost", port: 8080 };

// 值位置：运行时得到 "object"
console.log(typeof config);

// 类型位置：得到 { host: string; port: number }
type Config = typeof config;
```

### 类型位置 `typeof` 的用法

```ts
const config = { host: "localhost", port: 8080 };

type Config = typeof config;   // { host: string; port: number }

function setup(c: Config) { /* ... */ }
setup(config);   // ✅
```

### ⚠️ `typeof` 在类型位置只能用于**值**，不能用于类型

```ts
type Person = { name: string };

// ❌ 报错：'Person' only refers to a type, but is being used as a value here
type Wrong = typeof Person;
```

⭐ **记忆口诀**：类型位置的 `typeof` 后面跟着的必须是**一个变量名/常量名**（一个值），不是类型名。

### `typeof` + `as const` 的标准组合

```ts
const routes = {
  home: "/",
  about: "/about",
} as const;

type RoutePath = (typeof routes)[keyof typeof routes];
// "/" | "/about"  ← 精确字面量
```

## 六、⭐ 索引访问类型 `T[K]`

### 是什么

**索引访问类型（indexed access type）** 语法是 `T[K]`，表示"**类型 `T` 的属性 `K` 的类型**"。

```ts
interface Person {
  name: string;
  age: number;
}

type NameType = Person["name"];   // string
type AgeType = Person["age"];      // number
```

### 与 `keyof` 组合 = 取属性类型的通用工具

```ts
interface Person {
  name: string;
  age: number;
  email: string;
}

// 取"所有属性值的类型"的联合
type ValueOf<T> = T[keyof T];

type PersonValues = ValueOf<Person>;   // string | number
```

⭐ **这正是 2.2 讲的那个 `(typeof STATUS)[keyof typeof STATUS]` 背后的原理**——`ValueOf<T>` 就是那个手写出来的通用版本。

### 泛型函数里最实用的组合：取出所有属性值

`T[keyof T]` 是**类型位置**的写法。想在**函数体**里真的拿到"所有属性的值"，得换成运行时 API：

```ts
// ✅ 正确写法：用 Object.values 拿到所有值，再断言成联合类型
function getValues<T extends object>(obj: T): Array<T[keyof T]> {
  return Object.values(obj) as Array<T[keyof T]>;
}

const person = { name: "a", age: 1, email: "e" };
const values = getValues(person);
// values 的类型是 Array<string | number>
```

⚠️ **这里有一个必须知道的语法边界**：

```ts
// ❌ 语法错误：`keyof` 只能出现在**类型位置**，不能出现在表达式位置
function bad<T>(obj: T): T[keyof T] {
  return obj[keyof T];   // ⚠️ 报错 TS1005: ']' expected
}
```

⭐ **`keyof` 是纯类型运算符**，它只存在于编译期，**在 JavaScript 表达式里没有对应的运行时语法**。所以：

- `type X = keyof T;` ✅ 合法（类型位置）
- `obj[keyof T]` ❌ **语法错误**（表达式位置）
- `obj[key as keyof T]` ✅ 合法（`keyof` 在 `as` 的**右侧**，仍然是类型位置）

```ts
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];   // ✅ key 是一个**值**，它的类型是 K extends keyof T
}
```

⭐ **记忆点**：`keyof` 出现在**类型标注的右侧**永远是合法的；出现在**表达式的方括号里**一定是语法错误。

### 数组与元组的索引访问

```ts
type Items = string[];
type FirstItem = Items[0];      // string

type Pair = [string, number];
type P0 = Pair[0];              // string
type P1 = Pair[1];              // number
type AllPair = Pair[number];    // string | number
```

## 七、⭐ 条件类型

### 是什么

**条件类型（conditional type）** 语法是 `T extends U ? X : Y`：

> 如果 `T` 可以赋值给 `U`（即 `T` 是 `U` 的子类型），结果就是 `X`；否则是 `Y`。

```ts
type IsString<T> = T extends string ? "是字符串" : "不是字符串";

type A = IsString<string>;    // "是字符串"
type B = IsString<number>;    // "不是字符串"
```

### 实战：把联合类型"过滤"掉某个成员

```ts
type Status = "pending" | "success" | "error";

// 手写 Exclude：把 "error" 从联合里去掉
type ExcludeError<T> = T extends "error" ? never : T;

type Result = ExcludeError<Status>;
// "pending" | "success"
```

⭐ **为什么能工作**：`never` 在联合类型里会被**吸收**（`"pending" | never` 等于 `"pending"`）。

### ⭐ 分布式条件类型（distributive conditional type）

⭐ **这是条件类型最反直觉、也最重要的性质**。

**规则**：当条件类型左侧是一个**裸类型参数**（bare type parameter，写成 `T extends ...` 而不是 `[T] extends ...`）时，TypeScript 会**把联合类型拆开，逐个分发处理，再把结果合并**。

```ts
type ExcludeError<T> = T extends "error" ? never : T;

type Result = ExcludeError<"pending" | "success" | "error">;
// 等价于：ExcludeError<"pending"> | ExcludeError<"success"> | ExcludeError<"error">
//        =  "pending"      | "success"              | never
//        =  "pending" | "success"
```

⭐ **换句话说**：`ExcludeError<"pending" | "success" | "error">` 里的 `T` 不是被当成"一个整体"，而是被拆成三个独立分支分别代入。

**分发带来的一个经典"意外"**：

```ts
type ToArray<T> = T extends any ? T[] : never;

type R = ToArray<string | number>;
// 分发后：string[] | number[]
// 而**不是** (string | number)[]
```

⚠️ **注意**：如果 `T` 不是裸类型参数（用 `[T] extends ...` 方括号包起来），**就不会分发**：

```ts
type ToArrayNonDistributive<T> = [T] extends [any] ? T[] : never;
type R2 = ToArrayNonDistributive<string | number>;
// (string | number)[]
```

⭐ **标准库里的 `Exclude`、`Extract`、`Omit`、`NonNullable` 全都是分布式的**——这就是为什么 `Exclude<Status, "error">` 能直接用。

### 条件类型 + `infer`（从类型里"提取"信息）

`infer` 关键字让你在条件类型的真分支里**声明一个新的类型变量**，用来捕获匹配到的部分：

```ts
type ElementOf<T> = T extends (infer E)[] ? E : never;

type E1 = ElementOf<string[]>;   // string
type E2 = ElementOf<(string | number)[]>;   // string | number
```

⭐ `infer` 的完整用法属于"类型体操"专题，见 [[typescript/interview/02-泛型与类型体操]]。

## 八、⭐ 映射类型

### 是什么

**映射类型（mapped type）** 语法是 `{ [K in keyof T]: ... }`，表示"**对 `T` 的每一个键，做同样的事**"。

```ts
interface Person {
  name: string;
  age: number;
  email: string;
}

// 把所有属性类型都变成 string
type AllStrings = {
  [K in keyof Person]: string;
};
// 等价于：{ name: string; age: string; email: string }
```

### 最常用的三个内置映射类型

```ts
interface Person {
  name: string;
  age: number;
}

// 1. Partial：所有属性变可选
type P1 = Partial<Person>;
// { name?: string; age?: number }

// 2. Required：所有属性变必填
type P2 = Required<{ name?: string; age?: number }>;
// { name: string; age: number }

// 3. Pick：挑几个属性
type P3 = Pick<Person, "name" | "age">;
// { name: string; age: number }

// 4. Omit：排除几个属性
type P4 = Omit<Person, "email">;
// { name: string; age: number }

// 5. Readonly：所有属性变只读
type P5 = Readonly<Person>;
// { readonly name: string; readonly age: number }
```

### ⭐⚠️ 陷阱：映射类型会移除 `readonly` 与可选性

⭐ **这是本节最重要的一个坑**，新手几乎都会踩。

**规则**：写 `{ [K in keyof T]: X }` 时，**`T` 上的 `readonly` 修饰符和 `?` 可选性修饰符不会被自动复制到结果里**。

```ts
interface Config {
  readonly host: string;   // 只读
  port?: number;           // 可选
}

type Bad = { [K in keyof Config]: Config[K] };
// 结果：{ host: string; port: number }
// ⚠️ readonly 没了！port 变成必填了！
```

**解法：用修饰符增删前缀**

| 修饰符 | 作用 |
|--------|------|
| `+readonly` | **加上**只读（保留原属性） |
| `-readonly` | **去掉**只读（可变属性） |
| `+?` | **加上**可选 |
| `-?` | **去掉**可选（变必填） |

```ts
// ✅ 保留 readonly
type KeepReadonly<T> = { readonly [K in keyof T]: T[K] };

// ✅ 去掉 readonly（做"可变副本"时用）
type Mutable<T> = { -readonly [K in keyof T]: T[K] };

// ✅ 保留可选性
type KeepOptional<T> = { [K in keyof T]?: T[K] };
```

⭐ **记忆法**：**`+` 表示加，`-` 表示减**。默认情况下映射结果是"**中性的**"——既不 readonly 也不可选。

### 实战例子：把只读对象转成可变对象

```ts
interface ReadonlyUser {
  readonly id: string;
  readonly name: string;
}

type MutableUser = { -readonly [K in keyof ReadonlyUser]: ReadonlyUser[K] };

const u: MutableUser = { id: "1", name: "a" };
u.name = "b";   // ✅ 可以改了
```

### 映射类型 + 键重命名（`as` 子句，TypeScript 4.1+）

```ts
interface Person {
  name: string;
  age: number;
}

// 把 name 改成 firstName
type Renamed = {
  [K in keyof Person as K extends "name" ? "firstName" : K]: Person[K];
};
// { firstName: string; age: number }
```

⭐ 条件类型可以配合 `as` 子句，实现"**基于键的条件映射**"。

### 映射类型处理数组的特殊行为

```ts
type Boxed<T> = { [K in keyof T]: T[K] };

type Arr = Boxed<string[]>;   // string[] —— ✅ 数组映射回数组，不是对象
```

TypeScript 对数组和元组有特殊处理：映射数组类型会得到数组类型，映射元组会得到元组。

## 九、泛型默认值 `<T = unknown>`

### 语法与版本

```ts
interface Box<T = unknown> {
  value: T;
}

const b: Box = { value: 42 };   // ✅ T 默认是 unknown
```

⭐ **`unknown` 作为默认值是官方推荐**：它比 `any` 安全（不能直接当 `string` 用），又不至于让使用者纠结。

> **版本说明**：泛型默认值是 **TypeScript 2.3** 引入的特性。

### 什么时候用默认值

**场景一：部分类型参数需要默认**

```ts
class Pair<A, B = string> {
  constructor(public first: A, public second: B) {}
}

const p1 = new Pair<number>(1, "x");   // ✅ B 用默认的 string
const p2 = new Pair<number, number>(1, 2);
```

⭐ **注意规则**：有默认值的类型参数必须放在**没有默认值的后面**（否则无法省略前面的）。

```ts
class Bad<A = string, B> { }   // ⚠️ 报错：Required type parameters may not follow optional type parameters
```

**场景二：库作者给"不知道用啥"的类型参数一个安全兜底**

```ts
function parse<T = unknown>(input: string): T {
  return JSON.parse(input) as T;
}
```

**场景三：允许"部分具体化"**

```ts
class Box<T = unknown> { }
class IntBox extends Box<number> { }
```

### ⚠️ 默认值只在"无法推断"时生效

```ts
function f<T = string>(x: T): T { return x; }

const r1 = f("a");    // T 推断为 string（不是靠默认值）
const r2 = f(42);     // T 推断为 number —— ⚠️ 默认值不生效！
```

⭐ **推断优先于默认值**。默认值只在**编译器完全无法推断**时才用得上（比如参数里根本没出现 `T`）。

## 陷阱

1. **⚠️ 以为 `extends` 约束是运行时检查**——`extends` **只存在于编译期**，编译后的 JS 里完全没有它；运行时传入不满足约束的对象照样能调用，只是属性会是 `undefined`；
2. **⚠️ 在泛型函数体里访问"约束之外"的属性**——`T extends { id: string }` **只保证有 `id`**，不代表有 `name`；要访问更多属性就把它们都写进约束；
3. **⚠️ 以为泛型能替代 `any`**——泛型保留了**具体**类型信息，`any` 把信息全扔了；能用泛型就别用 `any`；
4. **⚠️ 映射类型丢失 `readonly` 和可选性**——`{ [K in keyof T]: T[K] }` **不复制** `readonly` 和 `?`；要用 `+readonly` / `-readonly` / `+?` / `-?` 显式控制；
5. **⚠️ 忘了条件类型会"分发"**——`T extends U ? X : Y` 中 `T` 是裸类型参数时会**把联合类型拆开逐个处理**；不想分发就用 `[T] extends [U] ? X : Y`；
6. **⚠️ 在类型位置对类型名用 `typeof`**——`typeof Person`（`Person` 是 interface）会报错；类型位置的 `typeof` 后面必须跟**值**；
7. **⚠️ 以为泛型参数可以从返回值"反推"**——TypeScript 的推断**只从参数向返回值流**，不能"调用后才知道结果类型"；需要的话要用 `ReturnType<typeof fn>`（但那也只是取出已有函数类型的返回类型，不是真的推断）；
8. **⚠️ 多个类型参数时漏写一部分**——`Pair<string>` 会报错（需要 2 个），要么全写，要么给后面的参数**默认值**；
9. **⚠️ 以为泛型默认值会覆盖推断**——推断优先；只有无法推断时才用默认值；
10. **⚠️ 在表达式位置写 `keyof`**——`obj[keyof T]` 是**语法错误**（TS1005），不是类型不匹配；`keyof` 只能出现在类型位置（`type X = keyof T`、`obj[key as keyof T]`）；要在函数体里取"所有属性的值"请用 `Object.values(obj) as Array<T[keyof T]>`；
11. **⚠️ 以为 `keyof T` 在 `T` 是数组时只有 `number`**——`keyof string[]` 还包含 `"length"`、`"push"` 等所有数组方法名。

## 小结

- **泛型**用类型占位符替代具体类型，**保留**调用者的类型信息；泛型函数、泛型接口、泛型类三种形态
- ⭐ **`extends` 约束**给类型参数划底线（`T extends { id: string }`）；多个约束用 `&`（`T extends A & B`）；**约束只在编译期，不是运行时检查**
- ⭐ **`keyof`** 取类型的键联合（`keyof Person` → `"name" | "age"`）；`keyof T` 常与 `K extends keyof T` 搭配做属性访问
- ⭐ **类型位置的 `typeof`** 取值的类型（后面必须是**值**不是类型）；与 `as const` 组合是提取常量表的标准写法
- ⭐ **索引访问类型 `T[K]`** 取属性类型；`T[keyof T]` = 所有属性值类型的联合（标准库 `ValueOf<T>` 的原理）
- ⭐ **条件类型** `T extends U ? X : Y`；**裸类型参数会分发**（联合类型被拆开逐个处理），`[T] extends [U]` 可关闭分发；`infer` 用于提取类型信息
- ⭐ **映射类型** `{ [K in keyof T]: ... }` 对每个键做同样的事；⚠️ **默认不复制 `readonly` 与 `?`**，需要用 `+readonly` / `-readonly` / `+?` / `-?` 显式控制
- **泛型默认值** `<T = unknown>`（TS 2.3+）用于部分参数可省略的场景；**推断优先于默认值**

## 练习

1. 写一个泛型函数 `getProperty<T, K extends keyof T>(obj: T, key: K): T[K]`，并用它取出对象的所有属性值组成一个新对象（提示：`Object.entries` + 断言）。
2. 写一个 `Partial<T>` 的手写版本（不要用内置的），并验证它对可选属性和必填属性的处理是否一致。
3. 写一个 `Mutable<T>`，把一个全是 `readonly` 的接口变成可修改的版本；写一个 `ReadonlyDeep<T>` 试试递归处理嵌套对象。
4. 手写实现以下标准库类型（不要直接用内置的）：`Exclude<T, U>`、`Extract<T, U>`、`NonNullable<T>`、`ReturnType<T>`、`Parameters<T>`。
5. 用条件类型写一个 `DeepReadonly<T>`：对象属性的值也递归变只读。验证它对数组、函数、`Date` 这些内置类型的表现（提示：需要判断"这个类型是不是对象/函数"）。
6. 写一个泛型类 `Repository<T extends { id: string }>`，提供 `save`、`findById`、`findAll` 方法；然后写一个泛型默认值版本 `Repository<T = unknown>`，观察约束在什么时候才生效。
7. ⭐ 验证条件类型的**分发**：`type ToArray<T> = T extends any ? T[] : never` 与 `type ToArray2<T> = [T] extends [any] ? T[] : never`，分别作用在 `string | number` 上，用 `tsc --noEmit` 看报错或用类型显示工具观察差异。
8. 进阶：用映射类型 + 条件类型 + `as` 子句，实现一个 `Getters<T>` 类型：把 `{ name: string; age: number }` 变成 `{ getName(): string; getAge(): number }`。
