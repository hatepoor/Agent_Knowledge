# 函数与参数

> **什么时候该读**：写第一个 TS 函数时开始纠结「箭头函数和 `function` 有什么区别」「`this` 到底指向谁」「Python 的 `*args` 在 TS 里怎么写」「函数重载怎么写」。
> **阅读门槛**：会写 `const` / `let` 和基本的类型注解（见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.1-变量与基本类型]]）。

## 学习目标

读完本篇，你应当能够：

1. 写出**函数声明**、**函数表达式**、**箭头函数**三种形式，并说出它们在提升（hoisting）和 `this` 上的差异
2. 给参数和返回值加上类型注解，并判断什么时候该显式写、什么时候让编译器推断
3. 使用**默认参数**和**剩余参数**（`...rest`），并说明剩余参数对应 Python 的 `*args`
4. ⭐ 写出**函数类型**（如 `(a: number, b: string) => void`），把函数当值传递
5. ⭐ 解释普通函数与箭头函数的 **`this` 绑定差异**，并判断一段代码运行时 `this` 指向谁
6. 使用**可选参数** `?`，并用 TS 的**重载签名 + 实现签名**写法实现重载
7. 看懂泛型函数的基本形态 `<T>`，知道它解决什么问题
8. 在 `map` / `filter` 回调和事件处理器中正确选用箭头函数

## 一、三种函数写法

### 1.1 函数声明（Function Declaration）

**函数声明**用 `function` 关键字开头，函数名写在 `function` 后面：

```ts
function add(a: number, b: number): number {
  return a + b;
}

console.log(add(1, 2));   // 3
```

⭐ 关键特性：**会被提升（hoisted）**。所谓提升，是指编译器在处理代码时会把函数声明「提前」，因此你可以**先调用、后声明**：

```ts
console.log(add(1, 2));   // ✅ 3 —— 声明在下面也能调
function add(a: number, b: number): number {
  return a + b;
}
```

这和 Python 的顺序要求不同（Python 必须先 `def` 再调用），也和 JS 里的 `const f = function(){}` 不同（那是赋值，赋值没有提升效果）。

### 1.2 函数表达式（Function Expression）

**函数表达式**是把一个函数当作**值**赋给变量：

```ts
const add = function (a: number, b: number): number {
  return a + b;
};

console.log(add(1, 2));   // 3
```

⭐ 关键特性：**没有提升**。必须在赋值之后才能调用：

```ts
// console.log(add(1, 2));   // ❌ 运行时 ReferenceError
const add = function (a: number, b: number): number { return a + b; };
```

⚠️ 注意匿名函数表达式在报错信息里不好定位，所以实践上会**给它一个名字**（命名函数表达式）：

```ts
const factorial = function fact(n: number): number {
  return n <= 1 ? 1 : n * fact(n - 1);   // 可以用 fact 自己递归
};
```

### 1.3 箭头函数（Arrow Function）

**箭头函数**用 `=>`（读作「箭头」）连接参数列表和函数体，是 TS/JS 里最常用的简写：

```ts
const add = (a: number, b: number): number => {
  return a + b;
};

// 单个表达式可以省略大括号和 return
const double = (x: number): number => x * 2;

// 单参数可以省略括号
const square = (x: number): number => x * x;

// 无参数需要空括号
const now = (): string => "2026-10-22";
```

### 1.4 三者对比

| 维度 | 函数声明 `function f() {}` | 函数表达式 `const f = function() {}` | 箭头函数 `const f = () => {}` |
|------|------|------|------|
| 是否提升 | ✅ 提升，可先调用 | ❌ 不提升 | ❌ 不提升 |
| 是否有自己的 `this` | ✅ 有（见第五节） | ✅ 有 | ❌ **没有**，捕获外层 `this` |
| 能否用 `arguments` | ✅ 能 | ✅ 能 | ❌ 不能 |
| 能否用 `new` 调用（构造函数） | ✅ 能 | ✅ 能 | ❌ **不能** |
| 有没有 `prototype` 属性 | ✅ 有 | ✅ 有 | ❌ 没有 |
| 是否有 `.name` 属性 | ✅ 有 | ❌ 匿名时没有 | ✅ 有（从变量名推断） |
| 典型用途 | 顶层工具函数、递归 | 需要覆盖已有函数名时 | 回调、事件处理器、`map`/`filter` |

```ts
// 箭头函数不能当构造函数
const Bad = (x: number) => { console.log(x); };
// new Bad(1);    // ❌ 编译报错 TS7009；绕过后运行时 TypeError: Bad is not a constructor

// 函数声明可以
function Good(this: { x: number }, x: number) { this.x = x; }
const g = new Good(1);   // ✅
console.log(g.x);         // 1
```

⚠️ **选型经验**：

- **默认用箭头函数**——更短，且回调里没有 `this` 烦恼；
- 需要**提升**或需要 `new`（构造函数）时用**函数声明**；
- 需要**覆盖**一个已经存在的函数名时用**函数表达式**。

## 二、参数与返回值的类型注解

```ts
function greet(name: string, age: number): string {
  return `你好，${name}，你今年 ${age} 岁`;
}
```

### 2.1 返回值注解与 `void`

**没有返回值**的函数用 `void` 标注：

```ts
function logInfo(msg: string): void {
  console.log(msg);
}

const result = logInfo("hi");   // result 的类型是 void
```

⚠️ `void` 标注的函数里不能 `return` 一个值：

```ts
function bad(): void {
  // return 1;    // ❌ 编译报错
  return;        // ✅ 可以（提前退出）
}
```

### 2.2 上下文推断：什么时候可以不写

TS 会在某些场景下**推断**参数和返回值类型。关键在于**有没有上下文类型**：

```ts
// ✅ 有上下文：作为 map 的回调，n 的类型由 Array<number> 推出
const nums = [1, 2, 3];
const doubled = nums.map((n) => n * 2);   // n 推断为 number

// ❌ 无上下文：TS 不知道 x 是什么，报 TS7006 隐式 any
// const double = (x) => x * 2;
```

⭐ **规则**：

| 场景 | 建议 |
|------|------|
| 参数**有上下文类型**（比如作为回调传给已知签名的函数） | ✅ 可以不写，TS 会推断 |
| 参数**没有上下文**（独立定义的函数） | ⚠️ 必须写，否则报隐式 `any`（TS7006） |
| **返回值** | ⚠️ 建议显式写，除非函数极短且意图一目了然 |
| 导出的函数、类的公有方法 | ✅ 一定显式写（见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.1-类型推断与注解]]） |

```ts
// 有上下文：map 的回调参数类型由 Array<number> 决定
const nums = [1, 2, 3];
const doubled = nums.map((n) => n * 2);   // n 推断为 number ✅

// 无上下文：必须注解
// const half = (n) => n / 2;              // ❌ 编译报错 TS7006：隐式 any
const half2 = (n: number): number => n / 2;   // ✅
```

⚠️ **「长函数建议显式写返回值类型」**：返回值类型写出来，等于把「这个函数对外承诺了什么」固定下来；将来改内部实现时，编译器会帮你检查有没有破坏承诺。

⚠️ 还有一种情况返回类型**必须**显式写——**递归函数**和**返回自身类型**的函数，否则 TS 推断不出来（报「隐式 any 递归引用」错误）。

## 三、默认参数与剩余参数

### 3.1 默认参数

```ts
function greet(name: string, greeting: string = "你好"): string {
  return `${greeting}，${name}`;
}

console.log(greet("Ada"));           // 你好，Ada
console.log(greet("Ada", "早安"));   // 早安，Ada
```

⚠️ **带默认值的参数后面不能跟必填参数**：

```ts
function bad(a: number = 1, b: number): void {}   // ❌ 编译报错：必填参数不能跟在可选参数后
```

⭐ **和 Python 的关键差异**——**默认参数什么时候求值**：

| | 求值时机 | 后果 |
|---|---------|------|
| **TypeScript / JavaScript** | **每次调用时**求值 | 每次调用都拿到一个新对象，安全 |
| **Python** | **函数定义时**求值一次 | 那个对象被所有调用共享——经典的「可变默认参数陷阱」 |

```ts
function pushItem(item: string, list: string[] = []): void {
  list.push(item);
  console.log(list);
}
pushItem("a");   // ["a"]
pushItem("b");   // ["a","b"]  ✅ 每次调用都是新的 []
```

```python
def push_item(item, lst=[]):      # ⚠️ lst 在定义时只创建了一次
    lst.append(item)
    print(lst)

push_item("a")   # ['a']
push_item("b")   # ['a', 'b']  ⚠️ 上次的 'a' 还在
```

⭐ TS/JavaScript 没有这个坑，因为默认参数是**调用时**新建的。

### 3.2 剩余参数 `...rest`

**剩余参数（rest parameter）**用 `...` 把「数量不定」的多余参数收集成一个**数组**：

```ts
function sum(...nums: number[]): number {
  return nums.reduce((acc, n) => acc + n, 0);
}

console.log(sum(1, 2, 3));        // 6
console.log(sum());               // 0
console.log(sum(1, 2, 3, 4, 5)); // 15
```

对应 Python 的 `*args`：

```python
def sum(*nums):
    return sum(nums)
```

⚠️ 规则：

- 剩余参数**必须放最后**，且一个函数**最多一个**；
- 它的类型**一定是数组**（哪怕只有一个参数进来时也是长度 1 的数组）；
- 不能在调用时直接传一个数组进去（得用展开运算符，见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.3-对象与数组]]）：

```ts
function sum(...nums: number[]): number {
  return nums.reduce((acc, n) => acc + n, 0);
}

const nums = [1, 2, 3];
// sum(nums);          // ❌ 编译报错 TS2345：number[] 不能赋给 number
sum(...nums);          // ✅ 展开成 sum(1, 2, 3)
```

## 四、⭐ 函数类型：函数是一等公民

**函数类型（function type）**是「一个函数长什么样」的**类型标注**。写法是「参数列表 => 返回值」：

```ts
type Formatter = (value: number) => string;

const format: Formatter = (v) => `$${v}`;
console.log(format(5));   // "$5"
```

也可以直接写在参数位置：

```ts
// 参数类型是「接收两个参数、什么都不返回（void）」的函数
function runTask(name: string, task: (a: number, b: string) => void): void {
  console.log(`执行 ${name}`);
  task(1, "x");
}

runTask("任务A", (a, b) => { console.log(a, b); });
```

### 4.1 为什么这很重要

TS 里**函数是值**（一等公民），可以：

1. **赋给变量**（函数表达式、箭头函数）；
2. **作为参数传递**（回调）；
3. **作为返回值返回**（高阶函数）；
4. **放进数组/对象里**（函数集合）；
5. **用 `typeof` 取类型**（`typeof myFunc` 得到它的函数类型）。

```ts
// 高阶函数：返回一个函数
function makeAdder(n: number): (x: number) => number {
  return (x) => x + n;
}

const add5 = makeAdder(5);
console.log(add5(10));   // 15
```

### 4.2 三个相关写法别搞混

| 写法 | 含义 |
|------|------|
| `(a: number) => string` | **函数类型**（一个类型的写法） |
| `type F = (a: number) => string` | 给函数类型起个名字（**类型别名**） |
| `const f: (a: number) => string = ...` | 用函数类型给变量做注解 |
| `function f(a: number): string` | 函数声明 + 返回值注解 |

⚠️ **别用大写 `Function` 类型**：它几乎等于「任何函数」，会丢掉全部类型信息。永远写具体的函数类型。

## 五、⭐ `this` 的绑定差异

⭐ **这是本章面试最高频的机制点。先给结论**：

> **普通函数**（`function` 写法和普通函数表达式）**有自己独立的 `this`**，它的值由**调用方式**决定。
> **箭头函数没有自己的 `this`**，它使用**定义时**所在作用域的 `this`（词法作用域 / 静态绑定）。

### 5.1 普通函数：`this` 由调用方式决定

**`this`** 指向「当前这个函数被调用时的接收者对象」。

```ts
const user = {
  name: "Ada",
  greet() {
    console.log(this.name);       // this === user
  },
};

user.greet();                       // "Ada" —— 以 user 为接收者调用
```

⚠️ 一旦**脱离**这个对象调用，`this` 就变了：

```ts
const user = {
  name: "Ada",
  greet() {
    console.log(this.name);
  },
};

const greet = user.greet;   // 只是把函数取出来，接收者丢了
greet();                    // ⚠️ 运行时 this 是 undefined，这行会抛 TypeError
```

⭐ **TS 怎么知道 `this` 是谁？** 它用「**上下文类型推断**」：在 `user.greet()` 这种写法里，TS 从调用点反推出 `this` 是 `user` 的类型，所以 `this.name` 是 `string`，编译通过。

但一旦 `this` 的接收者**推不出来**（比如把方法取出来单独调用、或写成独立函数），TS 就报 **TS2683：`'this' implicitly has type 'any'`**。这时候要显式标注 `this` 的类型——写法是在参数列表最前面加一个 **`this` 参数**（它只是类型标注，不会真的传参）：

```ts
function standalone(this: unknown) {
  console.log(this);        // ✅ 有标注，不再报 TS2683
}

// function bad() {
//   console.log(this);      // ❌ 编译报错 TS2683：'this' implicitly has type 'any'
// }
```

对象字面量里的方法也可以这样标注：

```ts
const user = {
  name: "Ada",
  greet(this: { name: string }) {
    console.log(this.name);
  },
};
```

四种常见调用方式对应的 `this`：

| 调用方式 | `this` 是什么 |
|---------|--------------|
| `obj.method()` | `obj` |
| `fn()`（独立调用） | `undefined`（严格模式）/ 全局对象（非严格） |
| `fn.call(x)` / `fn.apply(x)` | `x` |
| `new Fn()` | 新建的实例 |

### 5.2 箭头函数：没有自己的 `this`

```ts
const user = {
  name: "Ada",
  greet: () => {
    // ⚠️ 箭头函数里没有自己的 this
    console.log(this);      // 这里的 this 来自定义处的外层作用域
  },
};
```

⚠️ 在模块顶层（ESM）里，顶层 `this` 是 `undefined`，所以上面的 `this` 是 `undefined`。这就是**为什么事件处理器、类回调里几乎总是用箭头函数**——它们不需要「动态 this」，只需要「记住当时那个对象」。

### 5.3 典型场景对比

```ts
class Counter {
  count = 0;

  // 箭头函数作为类属性：this 在定义时就绑定到了这个实例
  startArrow = () => {
    this.count++;
    console.log("箭头:", this.count);   // ✅ this 是实例
  };

  // 普通方法：this 取决于调用方式
  startNormal() {
    // ⚠️ 普通函数里的 this 不跟随词法作用域
    setTimeout(function (this: unknown) {
      console.log("普通:", this);   // this 是 undefined
    }, 100);
  }
}
```

⚠️ 上面 `startNormal` 里的 `this` 是 `undefined`——如果直接写 `this.count`，运行时就会抛 `Cannot read properties of undefined`。**修法**：要么把 `function` 换成箭头函数，要么用 `bind`：

```ts
class Counter {
  count = 0;

  startNormal() {
    setTimeout(function (this: Counter) {
      console.log("普通:", this.count);   // ✅ 绑定到实例
    }.bind(this), 100);
  }
}
```

### 5.4 一张速查表

| 特性 | 普通函数 | 箭头函数 |
|------|---------|---------|
| 有自己的 `this` | ✅ | ❌ |
| `this` 的来源 | **调用方式**（运行时决定） | **定义位置**（写代码时决定） |
| 能改 `this`（`call`/`apply`/`bind`） | ✅ | ❌ |
| 有 `arguments` | ✅ | ❌ |
| 能 `new` | ✅ | ❌ |
| 适合场景 | 对象方法、需要动态 `this`、构造函数 | 回调、事件处理器、类属性回调 |

⭐ **一句话记住**：**箭头函数「没有自己，只记得外面那个」**。

## 六、可选参数与函数重载

### 6.1 可选参数 `?`

在参数类型后加 `?` 表示「可以不传」：

```ts
function greet(name: string, greeting?: string): string {
  return `${greeting ?? "你好"}，${name}`;
}

console.log(greet("Ada"));           // 你好，Ada
console.log(greet("Ada", "早安"));   // 早安，Ada
```

⚠️ **语义精确**：可选参数的值类型实际是 `string | undefined`，所以**必须在使用前处理 `undefined`**（用 `??`、默认值、或条件判断）。

⚠️ 可选参数**必须排在必填参数后面**。

⚠️ 可选参数和默认参数**不要混用**做同一件事：

```ts
function f(a?: string, b: string = "x") {}   // 能写，但语义混乱
```

### 6.2 函数重载（TS 的写法）

⚠️ **TS 的重载和 Java 完全不同**：Java 靠「参数列表不同」在同一类里定义多个同名方法，由编译器按实参挑选；**TS 不靠类型系统实现多态重载**，而是靠「**重载签名 + 实现签名**」：

```ts
// ① 重载签名（overload signature）：只写签名，没有实现，告诉编译器「有这个形状」
function parse(input: string): string;
function parse(input: number): number;
function parse(input: boolean): { value: boolean };

// ② 实现签名（implementation signature）：真正干活的，只写一个，参数用联合类型
function parse(input: string | number | boolean): string | number | { value: boolean } {
  if (typeof input === "string") return input.trim();
  if (typeof input === "number") return input * 2;
  return { value: input };
}

console.log(parse("  hi  "));   // "hi"    —— 走第 ① 个签名
console.log(parse(21));         // 42      —— 走第 ② 个签名
console.log(parse(true));       // { value: true } —— 走第 ③ 个签名
```

规则与要点：

| 规则 | 说明 |
|------|------|
| **顺序** | 所有重载签名必须**连续**写在最前面，实现签名在**最后**且**只有一个** |
| **实现签名不对外暴露** | 调用方只能看到重载签名；实现签名的参数类型必须**兼容**所有重载 |
| **调用时按顺序匹配** | 编译器从上往下找第一个匹配的签名 |
| **⚠️ 拿不到实现签名** | 不能 `parse.call(...)` 之类地绕开重载去调实现 |

⚠️ **常见错误**：忘了写实现签名前的重载签名，直接写一个联合类型参数——那就不是重载了，返回值类型会被**合并**成联合类型，调用方拿到的类型精度全丢：

```ts
// ❌ 不是重载：返回值类型是 string | number
function parse(input: string | number): string | number {
  return typeof input === "string" ? input.trim() : input * 2;
}
const r = parse("x");
// console.log(r.length);   // ❌ 编译报错 TS2339：r 可能是 number，number 上没有 length
```

```ts
// ✅ 用重载签名，r 的类型就是 string
function parse(input: string): string;
function parse(input: number): number;
function parse(input: string | number): string | number {
  return typeof input === "string" ? input.trim() : input * 2;
}
const r = parse("x");
console.log(r.length);   // ✅
```

⭐ **什么时候用重载**：同一个名字在不同入参下返回**不同类型**时。重载的本质是「给同一个名字提供多个精确的类型视图」。

## 七、泛型函数基础（预告第 02 章）

**泛型（generics）**让你在写一个函数时，把「类型本身」当作参数来处理：

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}

console.log(first([1, 2, 3]));        // 1    —— T 推断为 number
console.log(first(["a", "b"]));        // "a"  —— T 推断为 string
console.log(first<number>([1, 2, 3])); // 1    —— 也可以手动指定 T
```

⭐ 为什么需要它：没有泛型时，你要么把类型写死（`first(items: number[])`），要么用 `any`（丢掉类型检查）。泛型让你**写一次、适用于任意类型、同时保留精确类型**。

⚠️ 注意 `first([])` 会让 T 推断为 `never`，返回值类型变成 `never | undefined`——这属于「空数组无法推断」的老问题，解法是显式指定 `first<number>([])`。

泛型的约束、`<T extends X>`、`keyof`、`typeof` 等完整内容见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.3-泛型与类型约束]]。

## 八、箭头函数的常见用途

### 8.1 作为 `map` / `filter` 回调

```ts
const nums = [1, 2, 3, 4, 5];

const doubled = nums.map((n) => n * 2);         // [2, 4, 6, 8, 10]
const evens = nums.filter((n) => n % 2 === 0);   // [2, 4]
const total = nums.reduce((acc, n) => acc + n, 0); // 15
```

箭头函数在回调里的优势是**短**，而且回调通常**不需要自己的 `this`**，所以 `this` 绑定规则不构成干扰。

### 8.2 作为事件处理器

```ts
class Button {
  private onClick: () => void;

  constructor(handler: () => void) {
    this.onClick = handler;
  }

  click(): void {
    this.onClick();
  }
}

// 用箭头函数包裹，回调里的 this 稳定指向实例
const btn = new Button(() => {
  console.log("被点击了");
});
btn.click();
```

⚠️ 在 DOM 事件里，浏览器会把 `this` 设为触发事件的元素，所以事件处理函数里如果想拿到组件自己的状态，**通常要用箭头函数包一层**。

## 九、与 Python 的对照

| 场景 | Python | TypeScript |
|------|--------|-----------|
| 函数定义 | `def f(a, b):` | `function f(a, b) {}` |
| 简写形式 | `lambda x: x * 2` | `(x) => x * 2` |
| 隐式返回 | 无（总是要 `return`） | 单表达式箭头函数可省略 `return` |
| 类型注解 | `def f(a: int) -> str:` | `function f(a: number): string {}` |
| 缺参数 | 编译/运行时报 `TypeError` | TS 编译期报错；运行时是 `undefined` |
| 额外参数 | 报错 | ⚠️ TS 报错（调用方多传参数也是编译错误） |
| `*args` | `def f(*args)` | `function f(...args: T[])` |
| `**kwargs` | `def f(**kw)` | 用对象参数 + 索引签名近似（见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.3-对象与数组]] 的「索引签名」一节） |
| `self` | **显式**第一个参数 | **隐式**的 `this` |
| 关键字参数 | ✅ `f(a=1)` | ❌ 用对象参数代替 |
| 默认参数求值 | ⚠️ **定义时**求值一次 | ✅ **调用时**求值 |
| 闭包 | ✅ 捕获外层变量 | ✅ 箭头函数捕获外层 `this`；普通函数不捕获 |
| 函数是一等公民 | ✅ | ✅ |
| 函数重载 | ❌ 不支持 | ✅ **重载签名 + 实现签名** |

```python
# Python：self 显式
class Counter:
    def __init__(self):
        self.count = 0

    def inc(self):
        self.count += 1
```

```ts
// TS：this 隐式
class Counter {
  count = 0;

  inc(): void {
    this.count += 1;
  }
}
```

⭐ **闭包行为对照**：Python 的嵌套函数天然捕获外层变量；TS 里**普通函数不捕获 `this`**（`this` 是动态的），**箭头函数捕获**。想要「记住外层 `this`」的效果，在 TS 里就用箭头函数。

⚠️ **注意**：Python 里 `lambda` 不绑定 `this`（Python 根本没有 `this`），而 TS 的箭头函数绑定 `this`。这是两边最容易混淆的一点——**TS 箭头函数 ≈ Python 的 `lambda` + 闭包 + 固定 this**，比 Python 的 `lambda` 多了一层 `this` 语义。

## 陷阱

1. **⚠️ 以为函数表达式也能提升**——`const f = function(){}` 是赋值，**不提升**，声明前调用会 `ReferenceError`；
2. **⚠️ 用箭头函数当构造函数**——`new (() => {})` 抛 `TypeError`；箭头函数也没有 `prototype` 和 `arguments`；
3. **⚠️ 在箭头函数里指望 `this` 是那个对象**——箭头函数**没有自己的 `this`**，拿到的是定义处的外层 `this`（模块顶层通常是 `undefined`）；
4. **⚠️ 把普通函数的 `this` 当成「词法作用域」**——普通函数的 `this` 由**调用方式**决定：`const g = obj.method; g()` 会丢 `this`；
5. **⚠️ 忘了 TS 的 `this` 参数标注**——方法里用 `this` 需要写 `this: SomeType`（或依赖类上下文的推断），否则编译报错；
6. **⚠️ 把 TS 重载写成「一个联合参数」**——那不是重载，返回值会退化成联合类型，精度全丢；重载必须是「多签名 + 单实现」；
7. **⚠️ 重载签名后面不跟实现签名**——编译器报「函数实现缺失或声明后紧跟其他语句」；
8. **⚠️ 以为默认参数和 Python 一样在定义时求值**——TS 是**每次调用时**求值，没有 Python 的「可变默认参数陷阱」；
9. **⚠️ 可选参数后跟必填参数**——编译报错；可选参数必须最后；
10. **⚠️ 剩余参数位置放错**——`...rest` 必须最后、只能有一个；
11. **⚠️ 忘了上下文推断会失效**——独立定义的 `(x) => x * 2` 报隐式 `any` 错误；
12. **⚠️ 用大写 `Function` 类型**——它等于「任何函数」，丢掉全部类型信息；
13. **⚠️ 在回调里用普通 `function` 却指望 `this` 指向外层**——普通函数的 `this` 是动态的，用箭头函数或 `bind`。

## 小结

- **三种写法**：函数声明（**提升**）/ 函数表达式（不提升）/ 箭头函数（不提升、无 `this`）
- **默认用箭头函数**；需要提升或 `new` 用函数声明；需要覆盖同名函数用函数表达式
- **注解**：返回值建议显式写（尤其导出函数、递归函数必须有）；有上下文的回调参数可省略
- **默认参数**每次调用时求值（无 Python 的可变默认参数陷阱）；**剩余参数** `...rest: T[]` 对应 `*args`，必须放最后
- ⭐ **函数是一等公民**：**函数类型** `(a: number) => string` 可用来标注变量、参数、返回值；⚠️ 别用大写 `Function`
- ⭐ **`this`**：普通函数**由调用方式决定**；箭头函数**没有自己的 `this`**，捕获定义处的外层 `this`；普通函数不捕获 `this`，箭头函数才捕获
- **可选参数** `?` 必须最后，用之前要处理 `undefined`；**重载**用「重载签名 + 实现签名」，⚠️ 与 Java 的实现机制不同
- **泛型** `<T>` 让函数对任意类型通用且保留精确类型（详见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.3-泛型与类型约束]]）
- **箭头函数**最适合：`map`/`filter` 回调、事件处理器、类属性回调
