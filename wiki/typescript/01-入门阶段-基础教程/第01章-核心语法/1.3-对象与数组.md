# 对象与数组

> **什么时候该读**：开始写第一个「有结构的业务对象」——用户、商品、配置；或者遇到「为什么改了一个对象的字段，另一个对象也变了」「为什么 `obj["key"]` 报错」「`for...in` 和 `for...of` 到底差在哪」。
> **阅读门槛**：会写 `const` / `let` 和对象字面量（见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.1-变量与基本类型]]）、会写函数与箭头函数（见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.2-函数与参数]]）。

## 学习目标

读完本篇，你应当能够：

1. 写出带类型注解的对象字面量，并用**可选属性** `?` 和**只读属性** `readonly` 精确描述形状
2. ⭐ 使用**索引签名** `[key: string]: T` 描述「键不确定」的对象，并知道它带来的访问约束
3. 区分数组的两种写法 `T[]` 与 `Array<T>`，并使用**元组类型** `[string, number]`
4. ⭐ 使用**解构**（数组解构、对象解构、重命名、默认值、剩余元素）和**展开运算符** `...`
5. ⭐ 讲清**引用语义**：赋值共享引用、`{...obj}` 是浅拷贝、`structuredClone` 是深拷贝、`Object.assign` 的局限
6. 熟练使用 `Object.keys`/`values`/`entries` 与数组的 `map`/`filter`/`reduce`/`find`/`flatMap`
7. ⚠️ 分清 `for...in`（遍历字符串键）和 `for...of`（遍历值），并避免由此产生的 bug

## 一、对象字面量与类型注解

**对象字面量（object literal）**是「用 `{}` 直接写出一个对象」的写法：

```ts
const user = {
  name: "Ada",
  age: 36,
  isActive: true,
};

console.log(user.name);   // "Ada"
```

### 1.1 给对象加类型注解

```ts
type User = {
  name: string;
  age: number;
  isActive: boolean;
};

const user: User = {
  name: "Ada",
  age: 36,
  isActive: true,
};
```

⚠️ **注解是「精确匹配」**——少写一个属性、多写一个属性、类型对不上，全部编译报错：

```ts
type User = {
  name: string;
  age: number;
  isActive: boolean;
};

// 多写一个属性
const user: User = {
  name: "Ada",
  age: 36,
  isActive: true,
  // role: "admin",     // ❌ 编译报错 TS2353：对象字面量不能有未知属性
};

// 少写一个属性
const u2: User = {
  name: "Bob",
  age: 28,
  // isActive: true,    // ❌ 编译报错 TS2739：缺少属性 isActive
};
```

⭐ 这就是 TS 相对 Python 字典的一大优势：**Python 的 `dict` 不检查结构，写错 key 要到运行时才发现；TS 的对象类型在编译期就锁住了形状。**

### 1.2 `interface` 也可以（预告 1.4 节）

同样的形状也可以用**接口（interface）**声明：

```ts
interface User {
  name: string;
  age: number;
  isActive: boolean;
}

const user: User = { name: "Ada", age: 36, isActive: true };
```

⭐ **`type` 别名 vs `interface`** 的区别见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.4-类与接口]]。日常写对象形状两者都能用，团队约定哪个就用哪个。

### 1.3 可选属性 `?`

**可选属性（optional property）**用 `?` 标记，表示「这个键可能不存在」：

```ts
type User = {
  name: string;
  nickname?: string;      // 可选：可能是 string，也可能是 undefined
};

const u1: User = { name: "Ada" };             // ✅ 不写 nickname 也行
const u2: User = { name: "Bob", nickname: "bobby" };   // ✅
```

⚠️ 读取可选属性时，类型是 `string | undefined`，**必须处理 undefined**：

```ts
type User = {
  name: string;
  nickname?: string;
};

const u: User = { name: "Ada" };
// console.log(u.nickname.length);          // ❌ 编译报错 TS18048：可能为 undefined
console.log(u.nickname?.length);             // ✅ undefined
console.log((u.nickname ?? "").length);       // ✅ 兜底
```

⚠️ **可选 ≠ 可为 null**：`nickname?: string` 表示「键可能不存在或值为 undefined」，但**不包括 `null`**。要允许 `null` 得写 `nickname?: string | null`。

## 二、只读属性 `readonly`

**只读属性（readonly property）**在类型层面禁止重新赋值：

```ts
type Config = {
  readonly version: string;
  readonly timeout: number;
};

const config: Config = { version: "1.0.0", timeout: 3000 };
// config.timeout = 5000;   // ❌ 编译报错 TS2540：不能给只读属性赋值
```

⚠️ **`readonly` 是编译期约束**，运行时照样能改（和 `private` 一样，见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.4-类与接口]] 的「访问修饰符」一节）。它的意义是「告诉编译器别让人改」。

⭐ **对象字面量整体也可以冻结**：用 `as const`（见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.1-变量与基本类型]] 第 6.4 节）：

```ts
const config = {
  version: "1.0.0",
  timeout: 3000,
} as const;
// config.timeout = 5000;   // ❌ 编译报错
```

## 三、⭐ 索引签名 `[key: string]: T`

**索引签名（index signature）**用来描述「对象的键名不确定，但值的类型固定」的场景——相当于 Python 的 `dict[str, int]`。

```ts
type UserScores = {
  [key: string]: number;      // 任意字符串键，值都是 number
};

const scores: UserScores = { alice: 90, bob: 85 };
scores["carol"] = 88;         // ✅ 合法
console.log(scores.alice);    // 90
```

### 3.1 ⚠️ 不能用 `obj["key"]` 访问「未声明索引签名」的对象

这是一个高频编译错误。**原因**：对象类型默认只允许访问**明确声明过的属性**，用字符串字面量下标访问未声明的键，TS 认为这是非法访问（类型不安全）：

```ts
type User = { name: string; age: number };
const user: User = { name: "Ada", age: 36 };

console.log(user.name);      // ✅ 点号访问声明过的属性
// console.log(user["name"]); // ❌ 编译报错 TS7053：元素隐式具有 "any" 类型
```

⚠️ 注意报错信息是「隐式 any」而不是「属性不存在」——因为 TS 允许用 `noImplicitAny: false` 放宽这条限制，TS 6.0 起 `strict` 默认开启，所以这条检查默认生效。

### 3.2 三种访问方式的适用场景

| 方式 | 写法 | 什么时候用 |
|------|------|-----------|
| **点号** | `obj.name` | ✅ 首选：键名确定且已声明 |
| **方括号** | `obj["name"]` | 键名是**变量**时必须用这个：`obj[key]` |
| **索引签名** | `obj[someString]` | 对象声明了 `[key: string]: T` 时可用 |

```ts
type UserScores = {
  [key: string]: number;
};

const scores: UserScores = { alice: 90 };
const key = "alice";
console.log(scores[key]);      // ✅ 方括号 + 变量
```

⚠️ **动态键访问的统一写法**：

```ts
function getProp(obj: Record<string, unknown>, key: string): unknown {
  return obj[key];   // ✅ Record<string, unknown> 自带索引签名
}
```

⭐ `Record<K, V>` 是 TS 内置的**工具类型**，等价于 `{ [key in K]: V }`，是描述「字典」的常用手段。

### 3.3 索引签名的代价

⚠️ 声明了索引签名后，**所有属性都必须符合索引值的类型**：

```ts
type Dict = {
  [key: string]: number;
  name: string;      // ❌ 编译报错 TS2411：name 的类型 string 不能赋给索引签名声明的 number
};
```

⚠️ 这就是为什么实践中更常用**交叉类型**或 `Record`：

```ts
type UserMeta = {
  id: number;
  [key: string]: unknown;   // ✅ 用 unknown 兜底，允许其他任意键
};
```

## 四、数组与元组

### 4.1 两种数组写法

```ts
const nums1: number[] = [1, 2, 3];        // ✅ 简写
const nums2: Array<number> = [1, 2, 3];   // ✅ 通用写法
```

| 写法 | 优点 | 缺点 |
|------|------|------|
| `T[]` | 简洁、读起来像数学 | 复杂类型时要套一层括号：`(string | number)[]` |
| `Array<T>` | 复杂类型时更清楚：`Array<string \| number>` | 稍啰嗦 |

⚠️ **不能用 `Array<number[]>` 表示二维数组**——那表示「元素是 `number[]` 的数组」……实际上 `Array<number[]>` 确实是二维数组，但更常见的错误是写成 `Array<number>` 却想表示二维。要二维数组写 `number[][]`。

⚠️ **联合类型数组必须加括号**：

```ts
const mixed: (string | number)[] = [1, "a"];   // ✅
// const mixed2: string | number[] = [1, "a"];  // ❌ 这是联合类型，不是数组
```

### 4.2 元组类型

**元组（tuple）**是「长度固定、每个位置类型不同」的数组：

```ts
type Point = [number, number];              // x, y
const p: Point = [3, 4];
console.log(p[0]);   // 3

type UserEntry = [string, number];          // 名字, 年龄
const entry: UserEntry = ["Ada", 36];
```

⭐ 元组还支持**具名元素**和**可选元素**：

```ts
type Result = {
  status: "ok" | "error";
  data: [value: string, timestamp: number];   // 具名元组
};

type MaybePair = [string, number?];          // 第二个可选
```

⚠️ 元组**长度必须匹配**：`const p: Point = [3, 4, 5]` 编译报错（除非用剩余元素语法 `...rest: number[]`）。

⚠️ 解构元组时，TS 能推断出每个元素的类型：

```ts
type Point = [number, number];
const p: Point = [3, 4];
const [x, y] = p;    // ✅ x: number, y: number
```

## 五、⭐ 解构与展开运算符

### 5.1 数组解构

**解构（destructuring）**把数组或对象的元素「拆开」成独立变量：

```ts
const nums = [1, 2, 3, 4, 5];

const [a, b] = nums;              // a = 1, b = 2
const [first, , third] = nums;    // ⭐ 空位跳过：first = 1, third = 3
const [head, ...tail] = nums;     // ⭐ 剩余元素：head = 1, tail = [2,3,4,5]
```

⚠️ 解构数组时，**位置必须对上**——`const [a, b] = nums` 取的是**前两个**，不是「第一个和最后一个」。

### 5.2 对象解构

```ts
const user = {
  name: "Ada",
  age: 36,
  city: "London",
};

// 基本形式
const { name, age } = user;             // name = "Ada", age = 36

// ⭐ 重命名（用冒号）
const { name: userName, age: userAge } = user;   // userName = "Ada", userAge = 36

// ⭐ 剩余元素
const { name: n3, ...rest } = user;     // rest = { age: 36, city: "London" }
```

⭐ **默认值（用等号）**：属性不存在或值为 `undefined` 时用默认值顶上：

```ts
type PartialUser = { name: string; age?: number };
const user2: PartialUser = { name: "Bob" };   // 注意：没有 age
const { name: n4, age: a4 = 18 } = user2;      // ✅ a4 = 18，默认值生效
```

⚠️ **注意**：同一段代码里不能重复声明同名变量（那会报 TS2451「重复声明」），所以上面用了不同的名字。真实代码里如果确实需要多组解构，把它们**分到不同的作用域**（比如不同的函数或 `{ }` 块）里就行。

⚠️ **默认值的判定条件是 `undefined`，不是「不存在」**：

```ts
const { v = 10 } = { v: undefined };   // v = 10  ✅ undefined 会触发默认值
const { w = 10 } = { w: null };        // ⚠️ w = null，不会触发默认值（null 不是 undefined）
```

### 5.3 解构用于函数参数（最实用的场景）

```ts
type User = { name: string; age?: number };   // age 写成可选，才能省略

function greet({ name, age = 18 }: User): string {
  return `你好，${name}，${age} 岁`;
}

console.log(greet({ name: "Ada", age: 36 }));   // 你好，Ada，36 岁
console.log(greet({ name: "Bob" }));            // 你好，Bob，18 岁
```

⭐ 这个写法避免了「一堆位置参数传错顺序」的问题，是 TS 项目里最推荐的参数传递风格。

⚠️ **注意配合的细节**：解构里的 `age = 18` 只影响**函数体内的取值**，并不会让调用方也能省略这个属性——所以**类型里也要把 `age` 写成可选**（`age?: number`），两边才能对上。

### 5.4 展开运算符 `...`

**展开运算符（spread operator）**在**字面量**或**函数调用**里把一个可迭代对象「摊开」：

```ts
// 数组展开
const a = [1, 2];
const b = [...a, 3, 4];      // [1, 2, 3, 4]

// 对象展开
const base = { app: "demo", version: "1.0" };
const prod = { ...base, version: "2.0" };   // { app: "demo", version: "2.0" } —— 后面的覆盖前面的

// 函数调用展开
const nums = [1, 2, 3];
console.log(Math.max(...nums));   // 3
```

⚠️ **对象展开的顺序规则**：后面的属性**覆盖**前面的，但**不会删除**。想「去掉某个键」得用解构 + `...rest`：

```ts
const user = { name: "Ada", password: "secret", age: 36 };
const { password, ...safeUser } = user;   // 取出 password，剩下的存进 safeUser
console.log(safeUser);                     // { name: "Ada", age: 36 }
```

## 六、⭐ 引用语义与拷贝

⭐ **这是本库读者（Python 背景）最需要建立心智模型的一节。**

> **JavaScript / TypeScript 的对象和数组是「引用类型（reference type）」。赋值传的是「引用」，不是「内容」。**

### 6.1 赋值共享引用

```ts
const original = { count: 1, nested: { value: 10 } };
const alias = original;      // alias 和 original 指向「同一个对象」

alias.count = 99;
console.log(original.count);   // 99  ⚠️ 改的是同一个对象
```

```python
# Python 行为完全一样
original = {"count": 1}
alias = original
alias["count"] = 99
print(original["count"])   # 99
```

⭐ 但和 **Python 重新赋值** 的差别在这里：

```ts
const a = { x: 1 };
const b = a;
// b = { x: 2 };               // ⚠️ 编译报错 TS2588：const 不能重新赋值

let c = { x: 1 };
let d = c;
d = { x: 2 };                 // ✅ 只是让 d 指向新对象
console.log(c.x);             // 1 —— c 还指着原来的对象（Python 行为一致）
```

### 6.2 `{...obj}` 是浅拷贝

**浅拷贝（shallow copy）**只复制**第一层**的属性值；属性值如果还是对象，**复制过去的还是同一个引用**：

```ts
const original = { count: 1, nested: { value: 10 } };
const copy = { ...original };      // 浅拷贝

copy.count = 99;                   // ✅ 改的是 copy 自己的第一层属性
console.log(original.count);       // 1  —— 第一层独立了

copy.nested.value = 200;           // ⚠️ 改的是「共享的那个」nested 对象
console.log(original.nested.value); // 200 —— 第二层还是共享的！
```

⭐ **一句话记住**：浅拷贝 = 「新的外壳 + 旧的零件」。

### 6.3 深拷贝：`structuredClone`

**深拷贝（deep copy）**递归复制所有层级，得到完全独立的对象：

```ts
const original = { count: 1, nested: { value: 10 }, list: [1, 2] };
const deep = structuredClone(original);   // ✅ 深拷贝（Node.js 17+ / 现代浏览器原生 API）

deep.nested.value = 200;
console.log(original.nested.value);   // 10  ✅ 完全独立
```

⚠️ `structuredClone` 的限制：

- **不能克隆函数**（会抛 `DataCloneError`）；
- **不能克隆 DOM 节点**；
- **不保留原型**（类的实例会被变成普通对象）；
- Node.js 需要 **17+**（本库推荐 Node.js 22/24 LTS，见 [[typescript/01-入门阶段-基础教程/第00章-学前准备/0.2-环境搭建与第一个程序]]）。

### 6.4 `Object.assign` 的局限

```ts
const original = { count: 1, nested: { value: 10 } };
const copy = Object.assign({}, original);   // 也是浅拷贝！
```

⚠️ `Object.assign(target, source)` 的语义是「把 `source` 的**可枚举自有属性**拷贝到 `target` 上并返回 `target`」，它**修改并返回第一个参数**，而不是创建新对象：

```ts
const target = { a: 1 };
const result = Object.assign(target, { b: 2 });
console.log(result === target);   // true —— 是同一个对象
```

⚠️ 另一个坑：`Object.assign` 走的是「属性写入」语义（JS 规范里的内部方法 `Set`），**会触发 setter**；而 `{...obj}` 是**创建新属性**，不会触发 getter/setter 的副作用行为。这个差异在有 getter/setter 的对象上很明显。

### 6.5 拷贝方式对照

| 方式 | 层级 | 保留原型 | 克隆函数 | 说明 |
|------|------|---------|---------|------|
| `obj` 赋值 | 无拷贝 | ✅ | — | 完全共享 |
| `{...obj}` | 浅 | ❌ | — | 展开只复制自有可枚举属性 |
| `Object.assign({}, obj)` | 浅 | ❌ | ✅ | ⚠️ 修改 target |
| `structuredClone(obj)` | 深 | ❌ | ❌ | 原生 API，Node 17+ |
| `JSON.parse(JSON.stringify(obj))` | 深 | ❌ | ❌ | ⚠️ 丢 `undefined`/`Date`/`Map`，见下 |

⚠️ **JSON 序列化深拷贝的老写法问题**：

```ts
const o = { d: new Date(), u: undefined, fn: () => {}, n: null };
const c = JSON.parse(JSON.stringify(o));
console.log(c.d);    // ⚠️ 变成字符串 "2026-10-22..."
console.log(c.u);    // ⚠️ 键直接消失了
console.log(c.fn);   // ⚠️ 变成 undefined
```

⭐ 现代项目里**优先用 `structuredClone`**。

## 七、常用方法

### 7.1 对象的三种枚举方式

```ts
const user = { name: "Ada", age: 36, city: "London" };

Object.keys(user);     // ["name", "age", "city"]  —— string[]
Object.values(user);   // ["Ada", 36, "London"]   —— (string | number)[]
Object.entries(user);  // [["name","Ada"], ["age",36], ["city","London"]]  —— [string, T][]
```

⭐ 三个方法返回的都是**自有可枚举**属性（不含原型链上的），且顺序稳定。

### 7.2 数组的遍历与转换

```ts
const nums = [1, 2, 3, 4, 5];

nums.map((n) => n * 2);          // [2,4,6,8,10]  —— 映射，长度不变
nums.filter((n) => n % 2 === 0);  // [2,4]         —— 过滤，可能变短
nums.reduce((acc, n) => acc + n, 0);   // 15      —— 归约成一个值
nums.find((n) => n > 3);          // 4            —— 找第一个匹配的
nums.findIndex((n) => n > 3);     // 3            —— 找第一个匹配的索引
nums.some((n) => n > 4);          // true         —— 有任意一个满足吗
nums.every((n) => n > 0);         // true         —— 全部满足吗
nums.flatMap((n) => [n, n * 10]); // [1,10,2,20,...] —— 映射后摊平一层
```

| 方法 | Python 对照 |
|------|------------|
| `map(fn, list)` | ⚠️ Python 的 `map` 返回**迭代器**，要 `list(map(...))`；TS 的 `map` 直接返回**新数组** |
| `filter(fn, list)` | ✅ 行为一致，TS 直接返回数组 |
| `reduce` | `functools.reduce`（TS 内置，无需导入） |
| `find` / `findIndex` | `next((x for x in l if cond), None)` |
| `flatMap` | 需 `itertools.chain.from_iterable` 或列表推导式 |

⚠️ Python 的列表推导式 `[f(x) for x in xs]` 在 TS 里**没有直接对应语法**，最接近的是 `map` + `filter`，或用 `flatMap` 组合。

### 7.3 `includes` vs `indexOf`

```ts
const nums = [1, 2, 3];

nums.includes(2);      // true  —— 布尔
nums.indexOf(2);       // 1     —— 索引，找不到是 -1
```

⚠️ 两个关键差异：

1. **返回值不同**：一个布尔、一个索引（`-1` 表示没有）；
2. **对 `NaN` 的处理不同**：

```ts
const arr = [NaN];
console.log(arr.includes(NaN));   // ✅ true
console.log(arr.indexOf(NaN));    // ⚠️ -1 —— 永远找不到！
```

原因：`indexOf` 用严格相等（`===`）比较，而 `NaN !== NaN`（见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.1-变量与基本类型]]）。

⭐ **结论**：判断「有没有」用 `includes`；要「在哪」用 `indexOf`；⚠️ 但 `indexOf` 找 `-1` 时要记得 `=== -1`，不能写 `if (index)`。

```ts
const nums = [1, 2, 3];
const i = nums.indexOf(99);        // -1

if (i) {
  console.log("⚠️ 错！-1 也是真值，这里会错误地进入分支");
}
if (i !== -1) {
  console.log("✅ 只有真的找到时才进入");
}
```

## 八、⚠️ `for...in` vs `for...of`

⭐ **写错就是 bug**，因为两者遍历的东西完全不同。

### 8.1 `for...in`：遍历键

```ts
const user = { name: "Ada", age: 36 };

for (const key in user) {
  console.log(key);            // "name", "age"  —— 键名（字符串）
}
```

⚠️ **三个坑**：

1. 遍历的是**字符串键**（不是数字索引）；
2. **包含原型链上可枚举的属性**（`for...of` 不会）；
3. 遍历数组时拿到的是**字符串下标**：

```ts
const nums = [10, 20, 30];
for (const key in nums) {
  console.log(key, typeof key);   // "0" string, "1" string, "2" string ⚠️
}
```

### 8.2 `for...of`：遍历值

```ts
const nums = [10, 20, 30];
for (const value of nums) {
  console.log(value);          // 10, 20, 30 —— 值（number）
}

const user = { name: "Ada", age: 36 };
// for (const v of user) { }    // ❌ 运行时 TypeError: user is not iterable
```

⚠️ `for...of` 要求对象是**可迭代的（iterable）**：数组、字符串、`Set`、`Map`、生成器都可以，普通对象不行。

### 8.3 对照表

| | `for...in` | `for...of` |
|---|------------|-----------|
| 遍历什么 | **键**（字符串） | **值** |
| 适用对象 | 对象、数组 | 可迭代对象（数组、字符串、Set、Map） |
| 原型链属性 | ⚠️ **会遍历到** | 不会 |
| 数组下标类型 | `string` | `number`（值） |
| 能否 `break`/`continue` | ✅ 能 | ✅ 能 |

### 8.4 安全写法

```ts
const nums = [10, 20, 30];
const user = { name: "Ada", age: 36 };

// ⭐ 遍历数组用 for...of（拿到值）
for (const n of nums) {
  console.log(n);          // 10, 20, 30
}

// ⭐ 遍历对象的键用 Object.keys + for...of
for (const key of Object.keys(user)) {
  console.log(key);        // "name", "age"
}

// ⭐ 遍历对象用 for...in 时加 hasOwnProperty 保护，避开原型链上的属性
for (const key in user) {
  if (Object.prototype.hasOwnProperty.call(user, key)) {
    console.log(key);      // "name", "age"
  }
}
```

⚠️ **注意一个坑**：`Object.keys(user)` 返回的键类型是 `string`，所以 `user[key]` 会报 TS7053（用字符串下标访问一个没有索引签名的对象）。想同时拿到键和值，**用 `Object.entries` 更省事**：

```ts
const user = { name: "Ada", age: 36 };
for (const [key, value] of Object.entries(user)) {
  console.log(key, value);   // "name" "Ada"，"age" 36
}
```

## 九、与 Python 的对照

| 场景 | Python | TypeScript |
|------|--------|-----------|
| 字面量 | `{"name": "Ada"}` | `{ name: "Ada" }` |
| 「有结构的对象」 | 一般用 `dict`（不检查结构）或 `dataclass` / `NamedTuple`（有结构） | 用 `type` / `interface`（**编译期检查结构**） |
| 可选字段 | `dict` 里直接不写这个 key | `name?: string`（读取时类型含 `undefined`） |
| 动态字典 | `dict[str, int]` | `{ [key: string]: number }` 或 `Record<string, number>` |
| 列表 | `[1, 2, 3]`（`list[int]`） | `number[]` |
| 元组 | `(1, "a")`（长度固定） | `[number, string]` |
| 解构 | `a, b = nums` / `k, v = d.items()` | `const [a, b] = nums` / `const { k } = obj` |
| 列表推导式 | `[f(x) for x in xs]` | ⚠️ 无直接对应，用 `map` / `filter` |
| 拷贝 | `copy.copy(x)`（浅）/ `copy.deepcopy(x)`（深） | `{...x}`（浅）/ `structuredClone(x)`（深） |
| 浅拷贝陷阱 | ⚠️ `copy.copy` 只复制一层 | ⚠️ `{...x}` 同样只复制一层 |
| 字典遍历 | `for k, v in d.items()` | `Object.entries(d)` + `for...of` |
| `get` 带默认值 | `d.get(k, default)` | `obj[k] ?? default` |
| 键是否存在 | `k in d` | `k in obj` 或 `Object.hasOwn(obj, k)` |

⚠️ **最容易照搬踩坑的两点**：

1. **Python 的 `dict` 极其灵活**（任何 key、随时加键），TS 的对象类型是**封闭的**——多写一个属性就编译报错。要动态加键就得声明索引签名；
2. **Python 的 `copy.deepcopy` 有现成 API**，TS 里原生只有 `structuredClone`（Node 17+），没有「深拷贝」的一等方法论。

## 陷阱

1. **⚠️ 用 `obj["key"]` 访问未声明索引签名的属性**——编译报错（元素隐式具有 `any` 类型）；键名已知用点号，键名是变量才用方括号；
2. **⚠️ 以为 `{...obj}` 是深拷贝**——只有第一层独立，嵌套对象仍共享引用；
3. **⚠️ 以为 `Object.assign({}, obj)` 是深拷贝**——也是浅拷贝，而且它**修改并返回第一个参数**；
4. **⚠️ 用 `JSON.parse(JSON.stringify())` 做深拷贝**——`Date` 变字符串、`undefined` 的键消失、函数丢失；现代代码用 `structuredClone`；
5. **⚠️ `structuredClone` 克隆含函数或类的实例**——函数抛 `DataCloneError`，类实例丢原型；
6. **⚠️ `for...in` 遍历数组**——拿到的是**字符串**下标，且会遍历到原型链上的属性；
7. **⚠️ `for...of` 遍历普通对象**——运行时 `TypeError: not iterable`；
8. **⚠️ 混淆 `includes` 和 `indexOf`**——一个返回布尔一个返回索引；`indexOf` 永远找不到 `NaN`；⚠️ `if (index)` 的写法在 `-1` 时会误判；
9. **⚠️ 解构默认值对 `null` 不生效**——默认值只在值为 `undefined` 时触发；
10. **⚠️ 解构数组时误以为能跳着取**——`[a, b]` 取的是**前两个**，不是首尾；
11. **⚠️ 索引签名类型和具体属性冲突**——`[key: string]: number` 之后不能再加 `name: string`；用 `unknown` 兜底；
12. **⚠️ 可选属性 ≠ 可为 null**——`name?: string` 不含 `null`，要写 `name?: string | null`；
13. **⚠️ 对象展开不会删除旧属性**——`{...base, version: "2.0"}` 里 `version` 是被覆盖，不是被移除；
14. **⚠️ `readonly` 以为运行时也拦得住**——它只是编译期约束，运行时随便改。

## 小结

- **对象字面量** `{ key: value }`；类型注解用 `type` 或 `interface`，**注解是精确匹配**
- **可选属性** `?`（类型含 `undefined`，用前要处理）；**只读属性** `readonly`（编译期约束）
- ⭐ **索引签名** `[key: string]: T` 描述动态字典；⚠️ 未声明索引签名的对象**不能**用 `obj["key"]` 访问；`Record<K, V>` 是常用替代
- **数组**：`T[]` 或 `Array<T>`；**元组** `[string, number]` 长度固定、位置异型
- ⭐ **解构**：数组按位置、对象按键名，支持**重命名** `:`、**默认值** `=`、**剩余** `...`；⚠️ 默认值只在 `undefined` 时生效
- ⭐ **展开** `...`：数组摊平、对象合并（后者覆盖前者、**不删除**）
- ⭐ **引用语义**：赋值共享引用；`{...obj}` / `Object.assign` 是**浅拷贝**；`structuredClone` 是**深拷贝**（Node 17+，不能克隆函数）
- **对象方法**：`Object.keys`/`values`/`entries`；**数组方法**：`map`/`filter`/`reduce`/`find`/`flatMap`
- ⚠️ **`includes` 返回布尔、`indexOf` 返回索引**（找不到 `-1`，且永远找不到 `NaN`）
- ⚠️ **`for...in` 遍历键（含原型链、字符串类型）、`for...of` 遍历值（要求可迭代）**——写错就是 bug
