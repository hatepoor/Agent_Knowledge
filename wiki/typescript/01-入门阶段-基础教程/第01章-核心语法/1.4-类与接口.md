# 类与接口

> **什么时候该读**：开始用 TypeScript 组织业务代码——需要复用一类东西的行为（类）、需要描述「一个东西必须有什么」（接口）、或者面试被问「TS 的 `private` 能挡住外部访问吗」「接口和抽象类该选哪个」。
> **阅读门槛**：会写对象字面量、类型注解、箭头函数（见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.3-对象与数组]]、[[typescript/01-入门阶段-基础教程/第01章-核心语法/1.2-函数与参数]]）。

## 学习目标

读完本篇，你应当能够：

1. 声明一个 `class`，写构造函数，并解释为什么 **TS 的属性必须先声明再初始化**
2. 说出 `public` / `private` / `protected` / `readonly` 的可见范围，并 ⚠️ 讲清 `private` 只是**编译期**约束
3. 使用 `extends` 继承、`implements` 实现接口、`override` 标记重写、`abstract` 声明抽象类与抽象方法
4. ⭐ 写出**接口**（方法签名、属性、可选成员、接口继承），并说明它与类的职责分工
5. ⭐ 用自己的话解释**结构化类型（structural typing）**：TS 只看形状不看名字，并说出它带来的「意外兼容」
6. 说清 `type` 别名与 `interface` 的区别（声明合并 vs 联合/条件类型）
7. ⚠️ 判断一个场景该用「类实现接口」还是「继承抽象类」

## 一、`class` 声明与构造函数

**类（class）**是「一类东西的模板」，同时也是 TS 里的一个**类型**。

```ts
class User {
  name: string;              // 属性声明
  age: number;

  constructor(name: string, age: number) {
    this.name = name;        // 用 this 给属性赋值
    this.age = age;
  }

  greet(): string {          // 方法
    return `你好，我是${this.name}`;
  }
}

const u = new User("Ada", 36);
console.log(u.name);     // "Ada"
console.log(u.greet());   // "你好，我是Ada"
```

### 1.1 ⚠️ TS 的属性必须「声明 + 初始化」

**这是 TS 和 Python 差别最大的地方之一。**

Python 里，实例属性在 `__init__` 里 `self.x = ...` 一赋值就自动存在了。TS **不会自动推断类的属性**——你必须在类体里**显式声明**属性名和类型：

```ts
class User {
  name: string;          // ✅ 声明了

  constructor(name: string) {
    this.name = name;
  }
}

// class Bad {
//   constructor(name: string) {
//     this.name = name;   // ❌ 编译报错：属性 'name' 不存在于类型 'Bad' 上
//   }
// }
```

⚠️ 更重要的是**初始化检查**：TS 6.0 起 `strict` 默认开启，其中的 `strictPropertyInitialization`（严格属性初始化）要求**每个属性在构造函数结束时都必须有值**：

```ts
class User {
  name: string;              // ⚠️ 编译报错 TS2564：属性 'name' 没有确定初始化
  age: number | undefined;   // ✅ 显式声明可能为 undefined

  constructor() {
    // 忘了 this.name = ...
  }
}
```

⭐ **三种合法的写法**：

```ts
class User {
  // ① 声明时直接给默认值
  name: string = "匿名";
  age = 0;

  // ② 声明类型，包含 undefined
  nickname: string | undefined;

  // ③ 用构造函数参数属性（parameter property）一步到位
  constructor(
    public email: string,
    private token: string,
    readonly createdAt: Date = new Date(),
  ) {
    this.nickname = undefined;
  }
}
```

⭐ **构造函数参数属性（parameter property）**是 TS 独有的语法糖：在构造函数参数前加访问修饰符，TS 会**自动生成对应的属性声明并赋值**。这是 TS 里最常用的类写法。

```ts
class Point {
  // 不用写属性声明，也不用写 this.x = x
  constructor(public x: number, public y: number) {}
}

const p = new Point(1, 2);
console.log(p.x);   // 1
```

### 1.2 `this` 在类里指向实例

```ts
class Counter {
  count = 0;

  inc(): void {
    this.count += 1;   // this === 当前实例
  }
}

const c = new Counter();
c.inc();
console.log(c.count);   // 1
```

⚠️ 箭头函数作为类属性时，`this` 在**定义时**就绑定到实例（见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.2-函数与参数]] 第五节）：

```ts
class Timer {
  seconds = 0;

  // 箭头函数属性：this 固定为实例 ✅
  tick = (): void => {
    this.seconds += 1;
  };

  // 普通方法：this 由调用方式决定
  tickNormal(): void {
    setTimeout(() => {
      // 如果写成 setTimeout(function () { this.seconds += 1 }, 100)，this 会是 undefined ⚠️
    }, 100);
  }
}
```

## 二、访问修饰符

**访问修饰符（access modifier）**控制成员在类外能不能被访问：

| 修饰符 | 类内 | 子类内 | 类外 | 说明 |
|--------|------|--------|------|------|
| `public` | ✅ | ✅ | ✅ | **默认值**，不写就是 public |
| `private` | ✅ | ❌ | ❌ | 只能在**本类**内部访问 |
| `protected` | ✅ | ✅ | ❌ | 本类和**子类**可以访问 |
| `readonly` | — | — | — | 与上面三个**正交**：只读修饰 |

```ts
class Account {
  public owner: string;        // 公开
  private balance: number;      // 私有
  protected createdAt: Date;    // 受保护
  readonly currency: string;    // 只读

  constructor(owner: string, initial: number) {
    this.owner = owner;
    this.balance = initial;
    this.createdAt = new Date();
    this.currency = "CNY";
  }

  deposit(amount: number): void {
    this.balance += amount;    // ✅ 类内可以改 private
  }

  getBalance(): number {
    return this.balance;
  }
}

const acc = new Account("Ada", 100);
console.log(acc.owner);        // ✅ "Ada"
console.log(acc.currency);     // ✅ "CNY"
// console.log(acc.balance);   // ❌ 编译报错：属性 'balance' 是私有的
// acc.currency = "USD";       // ❌ 编译报错：不能给只读属性赋值
```

### 2.1 ⚠️ `private` 只是编译期约束

⭐ **这是本页最重要的机制点之一。**

TS 编译成 JavaScript 后，`private` **完全消失**——它只是给编译器看的一张「通行证检查表」：

```ts
class Account {
  private balance: number = 100;
}

const acc = new Account();
// acc.balance = 999;        // ❌ TS 编译报错
```

编译产物（`tsc` 输出的 JS）：

```js
class Account {
  constructor() {
    this.balance = 100;   // 修饰符没了，就是个普通属性
  }
}
const acc = new Account();
// acc.balance = 999;     // 在纯 JS 里这么写，完全合法
```

⚠️ 也就是说：**绕过 TS 编译器**（写 `.js` 文件、用 `any` 断言、用 `as any` 强转、或从 `Object` 层面访问），`private` 就形同虚设。

| | Python 的私有 | Java 的私有 | TS 的 `private` |
|---|--------------|------------|----------------|
| 机制 | **命名约定** `_name` / `__name` | **字节码级**强制（`private` 字段 + 反射限制） | **编译期**检查 |
| 能否绕过 | ✅ 随便访问（只是「约定别碰」） | ⚠️ 靠反射/Unsafe 能绕过，但普通代码不行 | ✅ 绕开编译器就能改 |
| 报错时机 | ❌ 从不报错 | ❌ 不报错（编译通过） | ✅ **编译期**报错 |
| 真正的运行时私有 | ❌（`__name` 只是改名） | ✅ `private` 字段 | ✅ `#name`（见下） |

### 2.2 `#` 私有字段：真正的运行时私有

TypeScript 3.8+ 支持 ECMAScript 的 **`#` 私有字段**，它在**运行时**真正不可访问：

```ts
class Account {
  #balance: number = 100;      // ✅ 真正的私有

  getBalance(): number {
    return this.#balance;
  }
}

const acc = new Account();
console.log(acc.getBalance());   // ✅ 100
// console.log(acc.#balance);   // ❌ 编译报错
// acc["#balance"] = 999;       // ⚠️ 运行时也访问不到（真的被藏起来了）
```

⭐ **实践建议**：库的公开 API 用 `private`（表达意图、配合 `readonly`），真正需要防篡改的敏感数据用 `#`。

## 三、继承与实现

### 3.1 `extends`：继承

```ts
class Animal {
  constructor(public name: string) {}

  speak(): string {
    return "...";
  }
}

class Dog extends Animal {
  constructor(name: string, public breed: string) {
    super(name);        // ⚠️ 必须调用父类构造函数
  }

  override speak(): string {   // ⚠️ TS 4.3+ 建议写 override
    return "汪！";
  }
}

const d = new Dog("旺财", "柴犬");
console.log(d.name);     // ✅ 继承来的属性
console.log(d.speak());  // "汪！"
```

⚠️ **子类构造函数里必须先调 `super()`**，否则运行时报错（`this` 还没初始化就用 `this`）。

⚠️ **`override` 关键字**（TS 4.3+）：写上它，编译器会检查「你真的重写了吗」。**写错了（比如父类根本没有这个方法）会报错**——这能挡住一类低级 bug：

```ts
class Animal {
  constructor(public name: string) {}

  speak(): string {
    return "...";
  }
}

class Cat extends Animal {
  override bark(): string {   // ❌ 编译报错 TS4113：父类没有 bark，override 无从谈起
    return "喵";
  }
}
```

⚠️ 父类方法是 `private` 时，子类不能 `override` 它（私有成员不参与继承的可见性）。

### 3.2 `implements`：实现接口

**`implements`** 表示「这个类承诺满足某个接口描述的结构」：

```ts
interface Printable {
  print(): string;
}

class Article implements Printable {
  print(): string {
    return "文章内容";
  }
}

console.log(new Article().print());   // "文章内容"
```

⚠️ `implements` **不产生任何运行时代码**——它纯粹是一句「我保证我满足这个形状」的**编译期检查**。类里必须真的实现接口要求的所有成员，否则编译报错。

⚠️ `implements` 可以一次实现多个接口：`class Foo implements A, B {}`。

### 3.3 `abstract`：抽象类与抽象方法

**抽象类（abstract class）**是不能被 `new` 出来实例化的类，它的作用是「提供共同的实现 + 规定子类必须做什么」：

```ts
abstract class Shape {
  // 抽象方法：只有签名，没有实现，子类必须实现
  abstract area(): number;

  // 普通方法：所有子类共享的实现
  describe(): string {
    return `面积是 ${this.area()}`;
  }
}

class Circle extends Shape {
  constructor(private radius: number) {
    super();
  }

  area(): number {
    return Math.PI * this.radius ** 2;
  }
}

const c = new Circle(2);
console.log(c.describe());   // "面积是 12.566370614359172"
// new Shape();             // ❌ 编译报错：不能实例化抽象类
```

⚠️ 抽象类**可以有抽象方法，也可以有具体方法**——这是它和接口最大的差别（接口**一律不能有实现**，见本页「四、⭐ 接口 `interface`」一节）。

## 四、⭐ 接口 `interface`

**接口（interface）**描述「一个值必须长什么样」，**不能包含实现**。

```ts
interface User {
  id: number;              // 属性
  name: string;
  email?: string;          // 可选属性
  readonly createdAt: Date;  // 只读属性
  greet(): string;         // 方法签名
  send?(msg: string): void;  // 可选方法
}

const u: User = {
  id: 1,
  name: "Ada",
  createdAt: new Date(),
  greet() { return `hi ${this.name}`; },
};
```

### 4.1 接口只能声明，不能实现

⚠️ **没有任何例外**——接口成员**一律只能省略实现**：

```ts
interface Bad {
  greet(): string {
    return "hi";      // ❌ 编译报错 TS1005：接口成员必须省略实现
  }
}
```

⚠️ **Java 读者注意**：Java 8 起接口可以有 `default` 方法（带实现），**TypeScript 完全没有这个概念**——`default` 在 TS 里只跟 `export default` 有关，不是接口成员的修饰符。写出来直接是语法错误：

```ts
interface JavaStyle {
  default greet(): void;    // ❌ 编译报错 TS1005：TypeScript 接口不支持 default 方法
}
```

⭐ **想给「接口」提供默认行为怎么办？** 有两条正规路径：

```ts
// 路径一：用抽象类——它既有接口的「约定」作用，又能提供实现
abstract class Greeter {
  abstract name: string;
  greet(): string {          // ✅ 具体方法，有实现
    return `hi ${this.name}`;
  }
}

// 路径二：用「可选方法 + 运行时判断」
interface OptionalGreeter {
  name: string;
  greet?(): string;          // ✅ 可选方法（不是带实现）
}

const g: OptionalGreeter = { name: "Ada" };
console.log(g.greet?.());     // ✅ 用 ?. 调用，方法不存在时返回 undefined
```

### 4.2 接口继承

```ts
interface Base {
  id: number;
}

interface Timestamped {
  createdAt: Date;
}

interface Entity extends Base, Timestamped {
  name: string;
}

const e: Entity = { id: 1, createdAt: new Date(), name: "x" };
```

⭐ 接口继承的**成员类型必须兼容**（子类接口的属性类型要是父接口的**子类型**，这叫**协变**，covariance）。

### 4.3 一个值可以同时满足多个接口

```ts
interface Flyable {
  fly(): void;
}
interface Swimmable {
  swim(): void;
}

class Duck implements Flyable, Swimmable {
  fly(): void { console.log("飞"); }
  swim(): void { console.log("游"); }
}
```

### 4.4 ⚠️ `type` 别名 vs `interface`

两者都能描述对象形状，但有实质区别：

| 维度 | `interface` | `type` |
|------|------------|--------|
| **声明合并** | ✅ 可以，同名接口会自动合并 | ❌ 不行，同名 `type` 报重复定义 |
| **联合类型** | ❌ 不能写 `A \| B` | ✅ 可以 |
| **交叉类型** | ❌ 不能写 `A & B` | ✅ 可以 |
| **条件类型 / 映射类型** | ❌ 不能 | ✅ 可以 |
| **基础类型别名** | ❌ 不能（`interface` 只能描述对象/类） | ✅ `type N = number \| string` |
| **错误信息** | 更友好（会提示「还有哪些属性没实现」） | 较差 |
| **扩展** | `interface X extends Y {}` | `type X = Y & { ... }` |

⭐ **声明合并（declaration merging）**是 `interface` 独有的能力，也是它在「第三方库类型扩展」场景里的杀手锏：

```ts
interface Window {
  myCustomProp: string;
}

// 之后在别的文件里再写一次同名 interface，两处会合并
interface Window {
  anotherProp: number;
}
```

⚠️ 实践建议：**描述对象/类的形状用 `interface`**；**需要联合、交叉、条件类型时用 `type`**。很多团队规定「能用 `interface` 就别用 `type`」，但 TS 官方现在的建议正相反——**能用 `type` 就用 `type`**（因为 `interface` 的能力正在向 `type` 靠拢）。团队统一比选哪个更重要。

## 五、⭐ 结构化类型（Structural Typing）

⭐ **这是 TS 类型系统最核心、也最容易被 Python 读者误解的机制。**

> **TS 是结构化类型系统：它判断两个类型是否兼容，只看「形状」（有哪些成员、成员类型对不对），完全不看「名字」。**

```ts
interface Point {
  x: number;
  y: number;
}

function draw(p: Point): void {
  console.log(p.x, p.y);
}

// 传一个「长得一样」的对象，完全合法
draw({ x: 1, y: 2 });        // ✅
// 甚至传一个名字完全不同的类型
const somethingElse = { x: 1, y: 2, extra: "多一个字段也不影响" };
draw(somethingElse);        // ✅ 多余属性被允许（因为不是字面量直接传参）
```

⭐ 这就是「**鸭子类型（duck typing）**」被提升为**类型系统的一等规则**——「如果它走起路来像鸭子、叫起来像鸭子，那它就是鸭子」。Python 的鸭子类型是**运行时**约定，TS 的结构化类型是**编译期**规则。

### 5.1 ⚠️ 由此带来的「意外兼容」

因为不看名义，**两个毫不相关的类型只要形状相同就会互相兼容**：

```ts
interface UserProfile {
  id: number;
  name: string;
}

// 业务上完全不同的另一个接口
interface ProductId {
  id: number;
  name: string;
}

function deleteUser(u: UserProfile): void {
  console.log("删除用户", u);
}

const pid: ProductId = { id: 1, name: "SKU-001" };
deleteUser(pid);   // ⚠️ 编译通过！TS 认为 ProductId 满足 UserProfile
```

⚠️ **风险**：一个本该只接受「用户」的函数，误传了「产品」对象，编译器**不会报错**，bug 会溜到运行时。

⭐ **解决办法**：

1. **给类型加「私有品牌成员」**，让两个形状相同但名义不同的类型不再兼容：

```ts
interface UserProfile {
  readonly __brand: "UserProfile";   // 唯一的品牌标记
  id: number;
  name: string;
}

interface ProductId {
  readonly __brand: "ProductId";
  id: number;
  name: string;
}

// ⚠️ 现在会报错：__brand 的字面量类型不匹配
// deleteUser(pid);
```

2. **用类的 `private` 成员**做「名义化」——因为两个类的 `private` 成员**来源不同就不兼容**（TS 特有的「名义类型」逃生舱）：

```ts
class RealUser {
  private brand!: void;    // ⚠️ private 成员让类型带上名义
  id = 1;
  name = "Ada";
}
```

3. **用泛型约束**（见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.3-泛型与类型约束]]）表达更精确的关系。

### 5.2 结构化类型的优点

别只看到缺点——结构化类型是 TS 相比 Java/C# 最大的优势之一：

```ts
// 不用继承、不用 implements，只要形状对就能传
function print(value: { toString(): string }): void {
  console.log(value.toString());
}

print("hello");              // ✅ string 有 toString
print(42);                   // ✅ number 有 toString
print({ toString: () => "custom" });  // ✅ 自定义对象
```

⭐ **这就是为什么 TS 里很少需要 `implements`**——只要形状对，直接传就行。`implements` 的价值在于**表达意图**（「这个类**承诺**要实现这个契约」）和**在类内部强制补齐成员**。

## 六、⚠️ 类实现接口 vs 继承抽象类

这两个经常被问「该选哪个」。先给决策表：

| 维度 | `class Foo implements Bar` | `class Foo extends Bar`（Bar 是抽象类） |
|------|---------------------------|-------------------------------------|
| 能否提供**默认实现**给子类 | ❌ 接口一律不能有实现 | ✅ 抽象类可以有具体方法，子类直接继承 |
| 能否有**构造函数 / 实例状态** | ❌ 接口完全不涉及实现 | ✅ 抽象类可以有 |
| 能否被 `new` | — | ❌ 抽象类不能实例化 |
| 能否**多重继承** | ✅ 可以 `implements A, B` | ❌ 一个类只能继承一个类 |
| 关系语义 | 「**能**做某事」（能力/契约） | 「**是**某种东西」（is-a 血缘关系） |
| TS 的运行时影响 | ❌ 无（纯编译期） | ✅ 有真实的原型链继承 |

⭐ **决策口诀**：

- **「是-a」的血缘关系 + 需要共享实现和状态** → **继承抽象类**；
- **「能-do」的能力契约，或需要同时实现多个** → **实现接口**。

```ts
// ✅ 场景一：血缘关系 + 共享实现 → 抽象类
abstract class BaseEntity {
  constructor(public id: string, public createdAt: Date = new Date()) {}

  toJSON(): string {
    return JSON.stringify({ id: this.id, createdAt: this.createdAt });
  }
}

class User extends BaseEntity {
  constructor(id: string, public name: string) {
    super(id);          // 复用父类构造逻辑
  }
}

// ✅ 场景二：能力契约 → 接口
interface Serializable {
  serialize(): string;
}

interface Loggable {
  log(): void;
}

class AuditLog implements Serializable, Loggable {
  serialize(): string { return "audit"; }
  log(): void { console.log("logged"); }
}
```

⚠️ **常见错误**：为了「复用几行代码」就把一堆逻辑塞进抽象类，结果所有子类被迫继承一条它并不需要的关系链。**能力用接口，共性实现才用抽象类。**

## 七、与 Python 的对照

| 场景 | Python | TypeScript |
|------|--------|-----------|
| 类定义 | `class User:` | `class User {` |
| 构造函数 | `def __init__(self, name):` | `constructor(name: string) {}` 或参数属性 |
| 第一个参数 | ⚠️ **显式** `self` | ⚠️ **隐式** `this`，不写在参数列表 |
| 实例属性 | 在 `__init__` 里赋值即存在 | ⚠️ **必须先声明**，且构造函数结束时必须有值 |
| 方法 | 普通函数 `def greet(self):` | `greet(): void {}` |
| 继承 | `class Dog(Animal):` | `class Dog extends Animal {}` |
| 多继承 | ✅ 可以（`class C(A, B)`） | ❌ 类只能继承一个类（但可实现多个接口） |
| 抽象类 | `abc.ABC` + `@abstractmethod` | `abstract class` + `abstract` 方法 |
| 抽象方法 | 装饰器 `@abstractmethod` | `abstract area(): number;` |
| 接口 | ❌ 无（用 `Protocol` / `ABC` 近似） | ✅ `interface` |
| 私有 | 约定 `__name`（**可绕过**） | ⚠️ `private`（编译期）/ `#name`（运行时） |
| 只读 | 约定 `_name` + 手动检查 | ✅ `readonly`（编译期） |
| 重写标记 | 无 | ✅ `override` 关键字 |
| 类型兼容判定 | **鸭子类型**（运行时） | ⭐ **结构化类型**（编译期） |
| 「私有成员让类型带上名义」 | ❌ 没有这种机制 | ✅ 类的 `private` 成员 → 名义类型 |

⚠️ **如果你还写过 Java**：Java 的接口可以有 `default` 方法（带实现）、可以有静态方法和常量，TS 的接口**一律只有声明**；Java 的 `private` 是字节码级强制，TS 的 `private` 只是编译期约束。

### 7.1 同一个类，两种语言

```python
class User:
    def __init__(self, name: str, age: int):
        self.name = name          # 属性自动存在
        self.age = age

    def greet(self) -> str:
        return f"你好，我是{self.name}"
```

```ts
class User {
  // ⚠️ 必须声明属性
  name: string;
  age: number;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }

  greet(): string {
    return `你好，我是${this.name}`;
  }
}
```

### 7.2 ⭐ 结构化类型 vs 鸭子类型

Python 的鸭子类型是**运行时**的：

```python
def draw(p):
    p.x, p.y          # 不检查，传错就运行时 AttributeError

draw({"x": 1, "y": 2})   # ⚠️ 运行时报 AttributeError
```

TS 的结构化类型是**编译期**的：

```ts
interface Point { x: number; y: number; }
function draw(p: Point): void { console.log(p.x, p.y); }

draw({ x: 1, y: 2 });      // ✅ 编译期就检查形状
draw({ x: 1 } as any);      // ⚠️ 硬绕过才会到运行时才炸
```

⭐ **本质相同，差别在时机**：两者都是「只看行为不看名义」，但 TS 把这个检查**提前到了编译期**。

## 陷阱

1. **⚠️ 忘了声明类的属性**——`this.name = name` 报「属性不存在于类型上」；构造函数参数属性（`constructor(public name: string)`）可以一步到位；
2. **⚠️ 忘了初始化属性**——`strictPropertyInitialization` 报错；要么给默认值，要么写 `| undefined`；
3. **⚠️ 以为 `private` 能挡住运行时访问**——它**编译后完全消失**，绕开 TS 就能改；真要防篡改用 `#`；
4. **⚠️ 以为 Python 的 `_name` 约定在 TS 里也管用**——TS 里写 `_name` 只是普通名字，**编译器不拦**；要拦就写 `private`；
5. **⚠️ 子类构造函数忘了 `super()`**——运行时 `ReferenceError`（`this` 未初始化）；
6. **⚠️ 在抽象类里 `new`**——编译报错；抽象方法必须在子类实现；
7. **⚠️ 以为接口可以有实现**——接口成员**一律只能省略实现**；要默认行为请用抽象类或可选方法 + `?.`；
8. **⚠️ 以为 `implements` 会产生运行时代码**——它纯编译期，JS 产物里看不到；
9. **⚠️ 结构化类型导致「意外兼容」**——两个不相关的类型形状相同就会互相接受；用品牌字面量或类的 `private` 成员做名义化隔离；
10. **⚠️ 多继承写 `extends A, B`**——类只能继承一个类；多能力要用 `implements A, B`；
11. **⚠️ `override` 写错方法名**——编译器会报错（这正是它的价值）；父类 `private` 方法不能 `override`；
12. **⚠️ 用 `type` 和 `interface` 互相替代**——`type` 不能声明合并、`interface` 不能写联合类型；需要联合/交叉/条件类型就得用 `type`；
13. **⚠️ 以为 TS 的 `private` 像 Java 那样是字节码级**——Java 的 `private` 字段是真正的运行时限制，TS 的不是；
14. **⚠️ 在类里用普通函数做回调并指望 `this` 是实例**——普通函数的 `this` 由调用方式决定，用箭头函数。

## 小结

- **类**：`class` + 构造函数 + 属性 + 方法；⚠️ **属性必须先声明再初始化**（`strictPropertyInitialization`）
- **参数属性**：`constructor(public x: number)` 自动生成属性声明并赋值，是最常用写法
- **访问修饰符**：`public`（默认）/ `private`（仅本类）/ `protected`（本类 + 子类）/ `readonly`（只读，与前三者正交）
- ⚠️ **`private` 只是编译期约束**，编译产物里完全消失；真私有用 `#name`
- **`extends`** 继承（子类必须 `super()`，用 `override` 标记重写）；**`implements`** 实现接口（纯编译期检查，可多个）；**`abstract`** 抽象类与抽象方法
- ⭐ **接口**：只声明不实现；可继承、可选成员、可多个实现；
- ⭐ **结构化类型**：只看形状不看名义，「鸭子类型」被提升为编译期规则；⚠️ 带来「意外兼容」，可用品牌字面量或 `private` 成员做名义化
- **`type` vs `interface`**：`interface` 能声明合并；`type` 能写联合/交叉/条件类型
- ⚠️ **决策**：血缘 + 共享实现 → 抽象类；能力契约 / 多重能力 → 接口
