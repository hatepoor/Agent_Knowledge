## 一、声明变量：`const` / `let` / `var`

**变量（variable）**是一个名字指向某个值。三种声明关键字的差别，正是 TypeScript 反复强调「作用域」与「可变性」的地方。

```ts
// const：绑定不可重新赋值（但对象的内部内容仍可改）
const PI = 3.14159;
// PI = 3;          // ❌ 编译报错：Cannot assign to 'PI' because it is a constant.

// let：绑定可以重新赋值，作用域限于所在代码块
let score = 0;
score = 10;            // ✅ 可以
score = score + 5;     // ✅ 可以

// var：老式写法，能重新赋值，作用域是整个函数
var legacy = "hello";
legacy = "world";      // ✅ 可以
```

三者的核心差异：

| 维度 | `const` | `let` | `var` |
|------|---------|-------|-------|
| 能否重新赋值 | ❌ 不能 | ✅ 能 | ✅ 能 |
| 作用域 | **块级**（`{}` 内） | **块级**（`{}` 内） | ⚠️ **函数级**（函数内任意位置都可见） |
| 声明前访问 | ⚠️ 报错（TDZ，见第五节） | ⚠️ 报错（TDZ） | ✅ 得到 `undefined`（提升，见下） |
| 能否作为 `for` 循环变量 | ✅（每轮独立绑定） | ✅（每轮独立绑定） | ❌ 所有轮次共用一个变量 |
| 现状 | **默认首选** | 需要重新赋值时用 | **不要新写** |

### 1.1 ⚠️ `var` 的第一个坑：函数作用域

**作用域（scope）**指「一个名字在哪些代码位置可以被访问到」。`var` 只认**函数**边界，不认 `{}` 边界：

```ts
function demo() {
  if (true) {
    var leaked = "我其实在函数外也能看到";
    let scoped = "我只在这个块里可见";
  }
  console.log(leaked);   // ✅ 能打印——var 泄漏到了函数作用域
  // console.log(scoped); // ❌ 编译报错：scoped 不在这里
}
```

⚠️ 这不是「更方便」，而是**污染**：同名的 `var` 在不同分支里会互相覆盖，而 `let` 每次进入 `{}` 都是一个独立的新变量。

### 1.2 ⚠️ `var` 的第二个坑：循环里共用一个变量

```ts
// var：三个回调拿到的是同一个变量，全是 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}

// let：每轮循环 i 都是独立绑定，输出 0 1 2
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

### 1.3 提升（hoisting）

**提升**指「变量声明在编译时会被移到作用域顶部」。`var` 的声明会被提升并初始化为 `undefined`；`let` / `const` 的声明虽然也提升，但**不初始化**（这就是 TDZ，见第五节）。

⭐ **有意思的是：TypeScript 在编译期就把这两种「提前访问」都拦下来了**，根本不用等运行时：

```ts
console.log(a);   // ❌ 编译报错 TS2454：变量 'a' 在赋值前就被使用了
var a = 1;

console.log(b);   // ❌ 编译报错 TS2448：块级变量 'b' 在声明前就被使用了
let b = 1;
```

⚠️ 也就是说，**「运行时 `var` 给 `undefined`、`let` 抛 `ReferenceError`」这条规律，在 TS 里是「你根本写不出这种代码」的状态**——编译器先一步挡住了。下面的运行时规律仍然要知道，因为你迟早要读别人写的 JS 代码，或者在 `as any` 之后遇到它。

⭐ **实践结论**：新代码一律用 `const`，确实需要重新赋值才用 `let`。`var` 只在读老代码时才需要认识。

## 二、8 种基本类型

TypeScript 的类型分两大类：**基本类型**（primitive type，也叫基础类型）和**对象类型**（object type，包括数组、函数、类实例等，见 [[typescript/01-入门阶段-基础教程/第01章-核心语法/1.3-对象与数组]]）。

8 种基本类型：

| 类型 | 是什么 | 示例 | Python 对应 |
|------|--------|------|-----------|
| `string` | 字符串（文本） | `"hi"`、`'hi'`、`` `hi` `` | `str` |
| `number` | ⚠️ **整数和浮点数共用** | `25`、`3.14` | ⚠️ 无单一对应（Python 有 `int`/`float` 之分） |
| `boolean` | 布尔真值 | `true` / `false` | `bool` |
| `null` | ⚠️ 程序员**显式**置空 | `null` | `None`（部分像） |
| `undefined` | ⚠️ **未赋值 / 不存在** | `undefined` | 无直接对应 |
| `symbol` | **唯一标识符** | `Symbol("id")` | 无（功能接近 Python 的 `id()` 对象） |
| `bigint` | **任意精度大整数** | `9007199254740993n` | `int`（超出 64 位时） |
| `void` | **无返回值**的标记 | `function f(): void {}` | 无返回值（Python 用隐式 `None`） |

### 2.1 ⚠️ `number` 一个类型装下所有数字

TS 里 **没有 `int` 和 `float` 的区分**。`25`、`25.0`、`3.14` 全都是 `number`，底层统一用 IEEE 754 双精度浮点数（和 Python 的 `float` 一样）。所以：

```ts
let a: number = 25;      // ✅
let b: number = 3.14;    // ✅
let c: number = 25.0;    // ✅ 也合法，但 c 的类型就是 number，没有"整数类型"信息

// ⚠️ 不存在这些写法（Python 读者最容易照搬）
// let d: int = 25;      // ❌ 编译报错：找不到名称 'int'
// let e: float = 1.5;   // ❌ 编译报错：找不到名称 'float'
```

**后果**：TS 没法区分「这个数字本来是整数」，所以 `arr.push(1.5)` 到一个 `number[]` 里不会被拦。要表达「必须是整数」，得用逻辑约束（运行时 `Number.isInteger` 检查）或 `bigint`。

### 2.2 `string` 的三种引号

```ts
const a = "双引号";
const b = '单引号';
const c = `模板字符串`;       // 反引号，可以嵌入 ${} 插值
const name = "Ada";
const greeting = `你好，${name}！`;   // 插值：你好，Ada！
```

⚠️ 模板字符串里的 `${}` 只在**反引号**里有效，用双引号写 `"${name}"` 会得到字面量字符串 `${name}`。

### 2.3 `symbol`：唯一标识

**符号（symbol）**是一个**保证唯一**的原始值，用作对象属性键时不会和别的键撞名：

```ts
const id = Symbol("id");
const obj = { [id]: 1, name: "Ada" };
console.log(obj[id]);   // 1
console.log(Object.keys(obj)); // ["name"]——symbol 键不参与字符串键枚举
```

日常写业务代码很少直接用 `symbol`，它是库作者做「私有属性」和「唯一标签」时的工具。

### 2.4 `bigint`：超出安全整数范围时用

JavaScript 的 `number` 只能精确表示到 `2^53 - 1`（约 9 千万亿）：

```ts
console.log(Number.MAX_SAFE_INTEGER);  // 9007199254740991
console.log(9007199254740993);          // ⚠️ 已经是 9007199254740992，精度丢了

const big = 9007199254740993n;         // ✅ bigint：精确
console.log(big.toString());            // "9007199254740993"
```

⚠️ `bigint` 和 `number` **不能混算**：`big + 1` 编译报错（`1` 是 `number`），必须写 `big + 1n`。也别把普通数字加上 `n` 当成习惯——`bigint` 主要用于 ID、时间戳这类必须精确的场景。

### 2.5 `void`：没有返回值

**`void`** 不表示「空值」，它专门用来标注「这个函数不返回任何东西」：

```ts
function logMessage(msg: string): void {
  console.log(msg);
  // 不能写 return 值;
}

const n = logMessage("hi");   // n 的类型是 void
```

⚠️ 注意区分：`void` 是**类型**（函数返回类型），`undefined` 是**值**（一个具体的原始值）。

## 三、类型注解：把类型写在代码里

**类型注解（type annotation）**是在声明处显式写出变量类型，用冒号加类型名：

```ts
let age: number = 25;              // 注解 + 初始化
let name: string;                   // 只有注解，没有初始值
let nickname: string | undefined;   // 联合类型：字符串 或 undefined（详见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.2-联合类型与字面量类型]]）
```

### 3.1 ⚠️ 注解写错，编译期就报错

这是 TS 相对于 Python 最大的日常差异。Python 是**运行时**才检查类型，TS 是在**编译/类型检查阶段**就拦下：

```ts
let age: number = 25;
age = "二十五";     // ❌ 编译报错：Type 'string' is not assignable to type 'number'
```

Python 对照：

```python
age = 25
age = "二十五"     # ✅ 运行不报错（除非某处显式检查），运行时才可能炸
```

### 3.2 注解 vs 推断

不写注解时，TS 会**推断（inference）**类型：

```ts
let age = 25;          // age 被推断为 number
let name = "Ada";      // name 被推断为 string（不是字面量 "Ada"）
```

⭐ **实践建议**：**局部变量**（函数内部的临时值）让编译器推断即可，写注解是冗余；**导出给他人使用的变量、类的属性、函数签名**才写注解——这些地方显式写出来，调用方才知道自己拿到了什么。更多策略见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.1-类型推断与注解]]。

## 四、⭐ `undefined` vs `null` vs `NaN`

这三个是新手最容易混的。**先给结论**：

| | `undefined` | `null` | `NaN` |
|---|-------------|--------|-------|
| 含义 | **不存在 / 没赋值** | **程序员主动置空** | **数值运算失败的结果** |
| 谁产生的 | 引擎自动 | 你手动写 `null` | 引擎自动（`0/0` 等） |
| `typeof` 结果 | `"undefined"` | `"object"` ⚠️ | `"number"` ⚠️ |
| 怎么产生 | 声明未赋值、缺参数、查不存在的属性 | `let x = null` | `Number("abc")`、`0/0` |

### 4.1 `undefined`：不存在

```ts
function noArgs() {}
noArgs();                        // 参数没传 → undefined

// ⚠️ 声明了类型但没赋值：TS 会报 TS2454（赋值前被使用）
let notAssigned: string;
// console.log(notAssigned);      // ❌ 编译报错；绕过后运行时是 undefined
```

⚠️ **属性不存在会返回 `undefined`，但 TS 会先在编译期拦下来**：

```ts
const obj = { name: "Ada" };
// console.log(obj.age);         // ❌ 编译报错 TS2339：类型 '{ name: string; }' 上不存在属性 'age'
```

⭐ 这是 TS 相比 Python 的一个重要差别：Python 里 `obj.age`（`obj` 是普通对象）会抛 `AttributeError`；而 TS **在编译期就告诉你「这个属性不存在」**。

那怎么合法地表达「我预期这个属性可能不存在」？两种写法：

```ts
// 写法一：显式声明可选属性
type User = { name: string; age?: number };
const u: User = { name: "Ada" };
console.log(u.age);              // ✅ 类型是 number | undefined，运行时就是 undefined

// 写法二：索引签名（见 1.3 的「索引签名」一节）
type Dict = { [key: string]: number };
const d: Dict = {};
console.log(d.anything);         // ✅ 类型是 number，运行时是 undefined
```

⚠️ 在 TS 里，如果开启了 `strict`（TS 6.0 起 `strict: true` 是默认值），「可能为 `undefined`」会被类型系统标出来，必须处理。这正是 TS 相比 Python 的价值所在。

### 4.2 `null`：程序员显式清空

```ts
let currentUser: string | null = "Ada";   // 现在有用户
currentUser = null;                        // 用户登出了，显式清空
```

`null` 的语义是「**我知道这里本来该有值，但现在故意没有**」。这在「数据还没加载完」「请求失败了」这类场景里表达意图很清楚。

⚠️ `typeof null === "object"` 是 JavaScript 的一个**历史 bug**（早期用 `null` 表示「无对象」，被错误实现），TS 也保留了这个行为。判断空值要用 `x === null`，不要用 `typeof x === "object"`。

### 4.3 `NaN`：运算失败的结果

**`NaN`** 是「Not a Number」，它是 `number` 类型的一个特殊值，表示「这次数值运算没得到有效数字」：

```ts
console.log(Number("abc"));   // NaN
console.log(0 / 0);           // NaN
console.log(Number("12"));    // 12
console.log(Infinity);        // Infinity（另一个特殊值）

// ⚠️ NaN 参与任何运算结果还是 NaN
console.log(NaN + 1);         // NaN
```

### 4.4 ⭐ 为什么 `NaN !== NaN`

这是**必须记住**的一条：

```ts
console.log(NaN === NaN);       // ❌ 编译报错 TS2845：这个条件永远为 false
                                //    （运行时结果确实是 false）
console.log(Number.isNaN(NaN)); // ✅ true
```

⭐ **TS 编译器自己就知道 `NaN === NaN` 恒为 `false`**——所以它直接把这个条件标记成一个错误（TS2845），提醒你「这里写错了」。

**原因**：`NaN` 表示「我不知道这个数字是什么」，那么两个「不知道」比较起来，**结果也是不知道**——而不是「它们相等」。这和浮点数的其他边界情况（`0.1 + 0.2 !== 0.3`）是不同的机制，但结果一样：**不能用 `===` 判断 NaN**。

⭐ **判断 NaN 的正确方式**：

```ts
const x = Number("abc");

Number.isNaN(x);     // ✅ 推荐：只对真正的 NaN 返回 true，不做类型转换
// x !== x           // ⚠️ 能用但不直观
// isNaN("abc")      // ⚠️ 全局 isNaN 会先转换类型，"abc" 也会返回 true
```

## 五、⭐ 作用域与 TDZ（暂时性死区）

**块级作用域（block scope）**指：变量只在声明它的那对 `{}` 内可见。

```ts
{
  let inner = "只在块内";
}   // 到这里 inner 就被销毁了
// console.log(inner);  // ❌ 编译报错
```

### 5.1 TDZ：声明前访问会报错

**暂时性死区（Temporal Dead Zone，TDZ）** 是 `let` / `const` 特有的机制：在**声明语句执行到之前**的这段时间里，变量已经「存在」（作用域已建立）但**还不能被读取**。

```ts
console.log(x);   // ❌ 编译报错 TS2448：块级变量 'x' 在声明前就被使用了
                  //    （如果绕过 TS，运行时抛 ReferenceError）
let x = 1;
```

对比 `var`：

```ts
console.log(y);   // ❌ 编译报错 TS2454：变量 'y' 在赋值前就被使用了
                  //    （如果绕过 TS，运行时输出 undefined）
var y = 1;
```

⭐ **注意**：TypeScript 的**控制流分析**（control flow analysis）会把「赋值前使用」当成错误直接拦下，所以上面两段在 `.ts` 文件里根本编译不过。TDZ 的运行时行为通常出现在**纯 JS 代码**或**绕过了类型检查**的场景里。

### 5.2 为什么会这样

回到提升机制。TS/JS 在**编译期**把整个函数体的变量声明扫描一遍并做提升，区别只在于**提升时是否初始化**：

| | 声明是否提升 | 提升时是否初始化 | 声明前访问的运行时结果 |
|---|---|---|---|
| `var` | ✅ | ✅ 初始化为 `undefined` | `undefined` |
| `let` / `const` | ✅ | ❌ 不初始化（留空 = TDZ） | ⚠️ `ReferenceError` |

⭐ **一句话记住 TDZ**：`let`/`const` 的「声明前」不是「值为 undefined」，而是「**还不许碰**」。

⚠️ 一个连带陷阱：`typeof` 在 TDZ 里也会抛错，而不只是「不报错」：

```ts
console.log(typeof z);   // ❌ 编译报错 TS2448（绕过后运行时抛 ReferenceError，而不是 "undefined"）
let z = 1;
```

这和 Python 的 `NameError` 是同一类问题，只是 TS 把它做成了编译期就能被静态分析出来的规则。

### 5.3 作用域层级

TypeScript 的作用域从外到内：

```text
全局作用域（global scope）      ← 模块顶层
 └─ 模块作用域（module scope）  ← 一个 .ts 文件就是一个模块
     └─ 函数作用域（function scope）
         └─ 块级作用域（block scope）  ← { } 内部
```

⚠️ 关键区别：`var` 只在**函数**层就被拦住了（函数作用域），`let`/`const` 一直到**块**层才被拦住。所以 `if`、`for`、`while` 的 `{}` 对 `let`/`const` 有效，对 `var` 无效。

## 六、运算符里的几个坑

### 6.1 ⚠️ `+` 的字符串拼接陷阱

`+` 有两个身份：**数值加法** 和 **字符串拼接**。只要两边**有一个是字符串**，它就变成拼接。

```ts
console.log(1 + 1);      // 2   （number）
console.log("1" + 1);    // "11"（string）⚠️ 不是 2
console.log(1 + "1");    // "11"（string）⚠️ 不是 2
console.log("1" + "1");  // "11"（string）
```

⚠️ 这是从 Python 抄代码时最容易中招的一处：Python 里 `"1" + 1` 会直接抛 `TypeError`，而 TS 会**静默**给你一个字符串 `"11"`，bug 要等到后面用到才算术时才炸。

**解法：显式转换。**

```ts
console.log(Number("1") + 1);          // 2
console.log(parseInt("1", 10) + 1);     // 2
console.log(String(1) + 1);             // "11"（明确想要拼接时）
```

⭐ **口诀**：拼接前先想清楚「我要的是字符串还是数字」，别依赖 `+` 自己决定。

### 6.2 `??`（空值合并）vs `||`（逻辑或）

两个都返回「左边不满足条件时的替代值」，但**判定条件不同**：

```ts
const n = 0;
const s = "";

console.log(n || "默认值");   // "默认值" ⚠️ 0 是「假值」，被当成没有值
console.log(n ?? "默认值");   // 0       ✅ ?? 只认 null 和 undefined

console.log(s || "默认值");   // "默认值"
console.log(s ?? "默认值");   // ""      ✅ 空字符串是有意义的值，?? 保留了它
```

| 运算符 | 触发条件 | 典型场景 |
|--------|---------|---------|
| `\|\|` | **所有假值**：`false`、`0`、`""`、`null`、`undefined`、`NaN`、`0n` | 「有值就用它，没值就用默认」——但要小心 `0` |
| `??` | 只看 `null` 和 `undefined` | 「可能为空」的兜底，**更安全** |

⭐ **默认优先用 `??`**：它只在真的「没有值」时才兜底，不会误伤 `0`、`""`、`false` 这些有效值。

### 6.3 可选链 `?.`

**可选链（optional chaining）**让「可能不存在」的属性访问在途中为 `undefined` 时**安全短路**，直接返回 `undefined`，而不是抛错。

```ts
type User = { profile?: { name?: string; address?: { city?: string } } };
const user: User = {};

// 直接访问 user.profile.address.city → 运行时抛错
console.log(user.profile?.address?.city);   // ✅ undefined，一路短路
console.log(user.profile?.name?.toUpperCase()); // ✅ undefined（后面不再调用）
```

⚠️ **注意语义差别**：`a?.b.c` 只在 `a` 这一段做了保护，`.c` 仍然可能抛错。要**每一级**都安全就得每一级都写 `?.`。

⚠️ `?.` 与 `??` 常配对使用：`obj?.deep?.value ?? "兜底"`。

### 6.4 `as const`：字面量收窄（预告第 02 章）

**字面量类型（literal type）**是指「类型就是某个具体值」，比如 `"dark"` 而不是 `string`。

`as const` 是**类型断言**（assertion，告诉编译器「相信我，这是这个类型」）的一种特殊形式，它把对象的属性从宽类型收窄成字面量类型，并且把所有属性变成 `readonly`：

```ts
const config = {
  mode: "dark",
  retries: 3,
} as const;

// config.mode = "light";   // ❌ 编译报错 TS2540：不能给只读属性赋值
```

```ts
// 不加 as const 时
const plain = { mode: "dark", retries: 3 };
plain.mode = "light";    // ✅ 合法
plain.mode;              // 类型是 string（任何字符串都合法）

// 加 as const 后
const strict = { mode: "dark", retries: 3 } as const;
strict.mode;             // 类型是 "dark"（只能取这一个值）
// strict.mode = "light"; // ❌ 编译报错 TS2540
```

⭐ 典型用途：配置对象、路由表、动作名常量——希望「写错值」在编译期就被抓住。字面量类型与联合类型的完整玩法见 [[typescript/01-入门阶段-基础教程/第02章-类型系统/2.2-联合类型与字面量类型]]。

## 七、与 Python 的对照

| 场景 | Python | TypeScript |
|------|--------|-----------|
| 声明常量 | 约定用大写 `PI = 3.14`（**运行时仍可改**） | `const PI = 3.14`（**编译期禁止改**） |
| 声明可变变量 | `x = 1`（无关键字） | `let x = 1` |
| 类型注解 | `x: int = 1`（**可选**，运行时忽略） | `let x: number = 1`（**写错就编译报错**） |
| 整数 / 浮点 | `int` / `float` **是两个类型** | ⚠️ 只有 `number` 一个 |
| 字符串类型 | `str` | `string` |
| 空值 | `None`（唯一） | ⚠️ `null`（显式）+ `undefined`（不存在）两个 |
| 未定义名字 | 抛 `NameError` | `let`/`const` 抛 `ReferenceError`；`var` 给 `undefined` |
| 类型检查时机 | **运行时** | **编译期**（`tsc` / 编辑器实时） |
| 数值溢出 | 任意精度 `int` | ⚠️ `number` 仅 53 位精确；超范围用 `bigint` |
| 字符串不变性 | 不可变 | 不可变（都是新变量） |
| 变量赋值语义 | 名字绑定到对象（引用绑定） | 名字绑定到值（`const`/`let` 绑定不可变） |

```python
# Python：整数自动任意精度
x = 9007199254740993      # ✅ 精确
```

```ts
// TS：number 只有 53 位精度，要精确得用 bigint
const x = 9007199254740993;    // ⚠️ 已被舍入
const y = 9007199254740993n;   // ✅ bigint，精确
```

⚠️ **最容易照搬踩坑的三点**（详见 [[typescript/01-入门阶段-基础教程/第00章-学前准备/0.3-TypeScript与Python的差异]]）：

1. Python 里 `None` 走天下，TS 里要区分「主动置空（`null`）」和「本来就没有（`undefined`）」；
2. Python 的 `int` / `float` 之分在 TS 里不存在，别写 `int`；
3. Python 的类型错误在运行时才暴露，TS 在写的时候就报——**不要因为「我 Python 里这么写能跑」就以为 TS 也能过**。

## 陷阱

1. **⚠️ 以为 `const` 意味着「内容也不能改」**——`const` 只禁止**重新赋值**，对象/数组的内部内容照样能改（`const arr = [1]; arr.push(2)` 合法）；
2. **⚠️ 用 `var` 写新代码**——函数作用域会泄漏、循环里会共用变量、还有提升的坑，一律用 `const` / `let`；
3. **⚠️ 以为存在 `int` / `float` 类型**——只有 `number` 一个，写 `let x: int` 直接编译报错；
4. **⚠️ 注解与初始值对不上**——`let age: number = "25"` 编译报错；TS 是编译期检查，不是运行时；
5. **⚠️ 用 `===` 判断 `NaN`**——`NaN === NaN` 是 `false`，必须用 `Number.isNaN(x)`；
6. **⚠️ 把 `undefined` 和 `null` 当同一个东西**——`undefined` 是「不存在」，`null` 是「主动置空」；⚠️ 且 `typeof null === "object"`（历史 bug，判断空值别用 `typeof`）；
7. **⚠️ 在 `let`/`const` 声明前访问变量**——抛 `ReferenceError`（TDZ），不是 `undefined`；`typeof` 也一样会抛；
8. **⚠️ 以为 `||` 和 `??` 等价**——`0 || "x"` 得到 `"x"`，`0 ?? "x"` 得到 `0`；默认用 `??`；
9. **⚠️ 写 `"1" + 1` 以为得到 2**——得到字符串 `"11"`，Python 里这会直接抛 `TypeError`，TS 静默出错更难查；
10. **⚠️ 可选链只保护一级**——`a?.b.c` 中 `.c` 仍可能抛错，每一级都要写 `?.`；
11. **⚠️ 用 `bigint` 和 `number` 混算**——`big + 1` 编译报错，必须写 `1n`；
12. **⚠️ 在模板字符串里用双引号写 `${}`**——双引号里不插值，要用反引号。

## 小结

- **声明**：默认 `const`，需要重新赋值用 `let`，**不要新写 `var`**（函数作用域 + 提升 + 循环共用变量）
- **作用域**：TS 有全局 / 模块 / 函数 / 块级四层；`let`/`const` 是块级，`var` 是函数级
- **TDZ**：`let`/`const` 声明前访问抛 `ReferenceError`；`var` 提升后是 `undefined`
- **8 种基本类型**：`string` / `number` / `boolean` / `null` / `undefined` / `symbol` / `bigint` / `void`
- ⚠️ **只有 `number`**，没有 `int` / `float`；精度只到 2^53-1，超出用 `bigint`
- **注解**：`let age: number = 25`，写错**编译期**报错；局部变量让编译器推断更清爽
- ⭐ **`undefined`（不存在）/ `null`（主动置空）/ `NaN`（运算失败）** 三者语义完全不同；`NaN !== NaN`，判断用 `Number.isNaN`
- **运算符**：`+` 遇字符串变拼接（静默坑）；`??` 只兜 `null`/`undefined`，比 `||` 安全；`?.` 逐级短路
- **`as const`**：把属性收窄成字面量类型并置为只读，配置对象的好搭档
