# 依赖注入（Depends）

`Depends` 是 FastAPI 最强大的机制——把**可复用的逻辑**（认证、数据库连接、参数校验）抽取为独立函数，FastAPI 自动"注入"到路由中。

## 一、核心概念

### 1.1 不用 Depends 的问题

```python
# 两个路由都要 q/skip/limit，重复写三遍
@app.get("/items/")
async def read_items(q: str | None = None, skip: int = 0, limit: int = 10):
    return {"q": q, "skip": skip, "limit": limit}

@app.get("/users/")
async def read_users(q: str | None = None, skip: int = 0, limit: int = 10):
    return {"q": q, "skip": skip, "limit": limit}

@app.get("/orders/")
async def read_orders(q: str | None = None, skip: int = 0, limit: int = 10):
    return {"q": q, "skip": skip, "limit": limit}
```

### 1.2 用 Depends 解决

```python
from fastapi import Depends

# 第1步：定义依赖函数（普通 async/def 函数）
async def common_params(q: str | None = None, skip: int = 0, limit: int = 10):
    return {"q": q, "skip": skip, "limit": limit}
    # 返回值 → 自动注入到路由函数的参数

# 第2步：用 Depends 声明依赖
@app.get("/items/")
async def read_items(commons: dict = Depends(common_params)):
    # commons 就是 common_params 的返回值
    return commons

@app.get("/users/")
async def read_users(commons: dict = Depends(common_params)):
    return commons
```

### 1.3 执行流程

```
请求到达 → FastAPI 路由匹配
    ↓
扫描函数参数，发现 Depends(common_params)
    ↓
执行 common_params(q=..., skip=0, limit=10)
    ↓
返回值 {"q": ..., "skip": 0, "limit": 10}
    ↓
注入到路由函数：read_items(commons={"q": ..., "skip": 0, "limit": 10})
    ↓
路由函数执行
```

## 二、依赖链（Depends 嵌套）

```python
# 依赖 B 可以依赖 A
async def get_db():
    db = await connect_db()
    try:
        yield db     # yield 表示资源需要清理
    finally:
        await db.close()

async def get_user(db=Depends(get_db), user_id: int = ...):
    return await db.fetch_user(user_id)

# 路由依赖链：get_db → get_user → read_user
@app.get("/users/{user_id}")
async def read_user(user=Depends(get_user)):
    return user
```

## 三、在 Agent API 中的应用

### 3.1 提取 thread_id（核心用法）

```python
from fastapi import Depends, Header

# 从请求头提取 thread_id → 注入为 RunnableConfig
async def get_agent_config(
    thread_id: str = Header(default="default"),
    auth_token: str = Header(default=""),
):
    return {
        "configurable": {"thread_id": thread_id},
        "auth_token": auth_token,
    }

@app.post("/chat")
async def chat(
    req: ChatRequest,
    config: dict = Depends(get_agent_config),  # 注入配置
):
    result = await agent.ainvoke(
        {"messages": [HumanMessage(content=req.message)]},
        config=config,
    )
    return {"reply": result["messages"][-1].content}
```

### 3.2 从依赖获取 Agent 实例（单例）

```python
from functools import lru_cache

@lru_cache                  # 多次调用只创建一次
def get_agent():
    llm = ChatDeepSeek(model="deepseek-v4-flash", temperature=1.0)
    return create_agent(model=llm, tools=[...])

@app.post("/chat")
async def chat(
    req: ChatRequest,
    agent=Depends(get_agent),  # 注入单例 Agent
):
    ...
```

### 3.3 复合依赖链

```python
# 依赖链：settings → llm → agent → route
@lru_cache
def get_settings():
    return Settings()

def get_llm(settings=Depends(get_settings)):
    return ChatDeepSeek(
        model=settings.model_name,
        api_key=settings.api_key,
    )

def get_agent(llm=Depends(get_llm)):
    return create_agent(model=llm, tools=[web_search, calculator])

@app.post("/chat")
async def chat(req: ChatRequest, agent=Depends(get_agent)):
    ...
```

## 四、与 LangChain 中间件概念对比

| LangChain 中间件 | FastAPI Depends | 异同 |
|-----------------|-----------------|------|
| 钩子拦截 | 依赖函数 | 都是"横切关注点" |
| 在 Agent 调用前后插入 | 在请求处理前插入 | 时机不同：Agent 内 vs HTTP 层 |
| `before_model(state, runtime)` | `depends(request, header)` | 参数来源不同 |
| 可修改 state | 可注入配置 | 状态管理方式不同 |

> **详见**：[[langchain/middleware/中间件概述]] — LangChain 中间件系统

## 五、最佳实践

1. **用 `@lru_cache` 缓存资源型依赖**（数据库连接、LLM 客户端）
2. **依赖链保持 2-3 层以内**，避免过度嵌套
3. **`yield` 用于需要清理的资源**（DB 连接、文件句柄）
4. **依赖函数遵循单一职责**——Auth 依赖只做认证，DB 依赖只管连接
