# 边（Edge）详解

边定义了 LangGraph 图中**节点之间的执行顺序和路由逻辑**。LangGraph 支持普通边（固定连接）和条件边（动态路由），让你可以构建从简单管道到复杂 Agent 的各种工作流。

## 核心概念

### 边的本质

边回答一个问题：**"这个节点执行完后，接下来执行谁？"**

- **普通边**：固定的下一个节点
- **条件边**：根据状态动态选择下一个节点
- **入口边**：从 `START` 到第一个节点
- **出口**：节点执行完后结束图（返回 `END`）

## 普通边（Normal Edge）

普通边定义固定的执行顺序。

### 语法

```python
builder.add_edge(from_node, to_node)
```

### 参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `from_node` | `str` 或 `START` | 起始节点 |
| `to_node` | `str` 或 `END` | 目标节点 |

### 示例

```python
from langgraph.graph import StateGraph, START, END

builder = StateGraph(State)

# 入口边：从 START 到第一个节点
builder.add_edge(START, "node_a")

# 节点间边：固定顺序
builder.add_edge("node_a", "node_b")
builder.add_edge("node_b", "node_c")

# 出口边：从最后一个节点到 END
builder.add_edge("node_c", END)
```

### 执行流程

```
START → node_a → node_b → node_c → END
```

## 条件边（Conditional Edge）

条件边根据状态**动态选择**下一个节点。

### 语法

```python
builder.add_conditional_edges(from_node, route_function, path_map=None)
```

### 参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `from_node` | `str` | 起始节点 |
| `route_function` | `Callable` | 路由函数，接收状态，返回下一个节点名 |
| `path_map` | `dict`，可选 | 节点名映射（可选） |

### 路由函数签名

```python
def route_function(state: State) -> str:
    """
    路由函数
    - 接收当前状态
    - 返回下一个节点的名称（字符串）
    """
    if condition:
        return "node_a"
    else:
        return "node_b"
```

### 示例一：简单条件路由

```python
from typing import Literal

def should_continue(state: State) -> Literal["tools", "end"]:
    """判断是否继续调用工具"""
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "tools"
    return "end"

builder.add_conditional_edges("agent", should_continue)
```

### 示例二：多分支路由

```python
from typing import Literal

def route_by_category(state: State) -> Literal["tech", "finance", "general"]:
    """根据内容分类路由"""
    content = state["content"]
    
    if "AI" in content or "编程" in content:
        return "tech"
    elif "股票" in content or "投资" in content:
        return "finance"
    else:
        return "general"

builder.add_conditional_edges("classifier", route_by_category)
```

### 示例三：循环路由

```python
def should_retry(state: State) -> Literal["retry", "end"]:
    """判断是否重试"""
    if state["retry_count"] < 3 and not state["success"]:
        return "retry"
    return "end"

builder.add_conditional_edges("process", should_retry)
builder.add_edge("retry", "process")  # 形成循环
```

## 入口与出口

### START 常量

`START` 是虚拟节点，表示图的入口：

```python
from langgraph.graph import START

# 必须有一条从 START 到第一个节点的边
builder.add_edge(START, "first_node")
```

### END 常量

`END` 是虚拟节点，表示图的出口：

```python
from langgraph.graph import END

# 方式一：添加边到 END
builder.add_edge("last_node", END)

# 方式二：路由函数返回 END
def route(state) -> Literal["next_node", END]:
    if should_stop:
        return END
    return "next_node"
```

### 特殊字符串 `"__end__"`

`"__end__"` 等价于 `END`：

```python
def route(state) -> str:
    if done:
        return "__end__"  # 等价于 END
    return "next_node"
```

## Fan-out / Fan-in 模式

### Fan-out（扇出）

一个节点执行后，多个节点**并行**执行：

```python
# 节点 A 执行后，B 和 C 并行执行
builder.add_edge(START, "A")
builder.add_edge("A", "B")  # A → B
builder.add_edge("A", "C")  # A → C（与 B 并行）
builder.add_edge("B", "D")
builder.add_edge("C", "D")
builder.add_edge("D", END)
```

执行流程：
```
     ┌→ B ─┐
A ───┤     ├──→ D
     └→ C ─┘
```

### Fan-in（扇入）

多个节点执行完后，汇聚到一个节点：

```python
# B 和 C 都执行完后，才执行 D
builder.add_edge("B", "D")
builder.add_edge("C", "D")
```

LangGraph 会自动等待所有前置节点完成。

## 完整示例：复杂路由

```python
"""
完整示例：展示各种边的用法
"""
from typing import TypedDict, Literal
from langgraph.graph import StateGraph, START, END

# 定义状态
class State(TypedDict):
    input_text: str
    category: str
    processed: bool
    result: str
    retry_count: int

# 定义节点
def classify(state: State) -> dict:
    """分类节点"""
    text = state["input_text"]
    if "bug" in text.lower():
        category = "bug_report"
    elif "feature" in text.lower():
        category = "feature_request"
    else:
        category = "general"
    return {"category": category}

def handle_bug(state: State) -> dict:
    """处理 bug 报告"""
    return {"result": f"Bug 报告已记录: {state['input_text'][:50]}"}

def handle_feature(state: State) -> dict:
    """处理功能请求"""
    return {"result": f"功能请求已记录: {state['input_text'][:50]}"}

def handle_general(state: State) -> dict:
    """处理一般请求"""
    return {"result": f"一般请求已处理: {state['input_text'][:50]}"}

def validate_result(state: State) -> dict:
    """验证结果"""
    # 简单验证：结果不为空
    is_valid = bool(state.get("result"))
    return {"processed": is_valid}

def retry_handler(state: State) -> dict:
    """重试处理"""
    return {"retry_count": state["retry_count"] + 1}

# 路由函数
def route_by_category(state: State) -> Literal["bug", "feature", "general"]:
    """根据分类路由"""
    category = state["category"]
    if category == "bug_report":
        return "bug"
    elif category == "feature_request":
        return "feature"
    else:
        return "general"

def should_retry(state: State) -> Literal["retry", "end"]:
    """判断是否重试"""
    if not state["processed"] and state["retry_count"] < 3:
        return "retry"
    return "end"

# 构建图
builder = StateGraph(State)

# 添加节点
builder.add_node("classify", classify)
builder.add_node("bug", handle_bug)
builder.add_node("feature", handle_feature)
builder.add_node("general", handle_general)
builder.add_node("validate", validate_result)
builder.add_node("retry", retry_handler)

# 添加边
# 入口
builder.add_edge(START, "classify")

# 条件边：根据分类路由
builder.add_conditional_edges("classify", route_by_category)

# 所有处理节点汇聚到验证
builder.add_edge("bug", "validate")
builder.add_edge("feature", "validate")
builder.add_edge("general", "validate")

# 条件边：根据验证结果决定是否重试
builder.add_conditional_edges("validate", should_retry)

# 重试循环
builder.add_edge("retry", "classify")

# 出口
# 注意：当 should_retry 返回 "end" 时，图结束

# 编译
graph = builder.compile()

# 执行
result = graph.invoke({
    "input_text": "我发现了一个 bug，程序在运行时崩溃了",
    "retry_count": 0
})

print(f"分类: {result['category']}")
print(f"结果: {result['result']}")
print(f"已处理: {result['processed']}")
print(f"重试次数: {result['retry_count']}")
```

## 路由函数模式

### 模式一：返回字符串

```python
def simple_route(state: State) -> str:
    """简单路由：返回节点名"""
    if condition:
        return "node_a"
    return "node_b"
```

### 模式二：使用 Literal 类型提示

```python
from typing import Literal

def typed_route(state: State) -> Literal["a", "b", "c"]:
    """类型安全的路由"""
    if state["x"] > 10:
        return "a"
    elif state["x"] > 5:
        return "b"
    else:
        return "c"
```

### 模式三：返回 END

```python
from langgraph.graph import END

def route_or_end(state: State) -> str:
    """路由或结束"""
    if state["done"]:
        return END
    return "next_node"
```

### 模式四：Fan-out 路由（返回列表）

```python
def fanout_route(state: State) -> list[str]:
    """扇出路由：返回多个节点名（并行执行）"""
    return ["node_a", "node_b", "node_c"]

builder.add_conditional_edges("splitter", fanout_route)
```

## 常见错误

### 错误一：忘记添加入口边

```python
# 错误：没有从 START 到第一个节点的边
builder.add_node("A", node_a)
builder.add_edge("A", "B")
# 图无法执行，因为没有入口

# 正确
builder.add_edge(START, "A")
```

### 错误二：路由函数返回不存在的节点

```python
# 错误：返回了未添加到图的节点
def bad_route(state):
    return "non_existent_node"

# 正确：只返回已添加的节点名
def good_route(state):
    return "existing_node"
```

### 错误三：死循环

```python
# 错误：无限循环
def infinite_loop(state):
    return "next"  # 总是返回 next

builder.add_edge("next", "next")  # 自循环，没有退出条件

# 正确：有退出条件的循环
def bounded_loop(state):
    if state["count"][[ < 10:
        return "next"
    return END
```

## 最佳实践

1. **使用类型提示**：路由函数使用 `Literal` 类型提示，提高代码可读性
2. **保持简单**：路由逻辑应该简单明了，复杂逻辑放到节点中
3. **避免深层嵌套**：条件不要太复杂，必要时拆分为多个路由函数
4. **测试路由逻辑**：单独测试路由函数，确保覆盖所有分支
5. **文档化**：为路由函数添加注释，说明每个分支的含义
