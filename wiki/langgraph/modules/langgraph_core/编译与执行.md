# 编译与执行

编译与执行是 LangGraph 工作流的最后阶段。`compile()` 方法将图定义转换为可执行对象，然后可以通过 `invoke()`、`stream()` 等方法执行图。

## 编译（compile）

### 语法

```python
builder.compile(checkpointer=None, interrupt_before=None, interrupt_after=None)
```

### 参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `checkpointer` | `BaseCheckpointSaver`，可选 | 状态持久化器 |
| `interrupt_before` | `list[str]`，可选 | 在这些节点执行前中断 |
| `interrupt_after` | `list[str]`，可选 | 在这些节点执行后中断 |

### 返回值

返回 `CompiledStateGraph` 对象，提供以下执行方法：
- `invoke()`：同步执行到完成
- `stream()`：同步流式执行
- `astream()`：异步流式执行
- `batch()`：批量执行

### 示例

```python
from langgraph.graph import StateGraph
from langgraph.checkpoint.memory import MemorySaver

builder = StateGraph(State)
# ... 添加节点和边 ...

# 方式一：基础编译
graph = builder.compile()

# 方式二：带持久化
checkpointer = MemorySaver()
graph = builder.compile(checkpointer=checkpointer)

# 方式三：带中断（人机协作）
graph = builder.compile(
    checkpointer=checkpointer,
    interrupt_before=["sensitive_action"],
    interrupt_after=["log_action"]
)
```

## 执行方法

### invoke()：同步执行到完成

`invoke()` 运行整个图直到完成，返回最终状态。

#### 语法

```python
graph.invoke(inputs, config=None)
```

#### 参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `inputs` | `dict` | 初始输入状态 |
| `config` | `RunnableConfig`，可选 | 运行时配置 |

#### 示例

```python
# 基础调用
result = graph.invoke({
    "messages": [("user", "你好")]
})

# 带配置调用
config = {
    "configurable": {
        "thread_id": "user-123",
        "user_id": "user-456"
    }
}
result = graph.invoke(
    {"messages": [("user", "你好")]},
    config=config
)

# 访问结果
print(result["messages"][-1].content)
```

### stream()：同步流式执行

`stream()` 逐步执行图，每一步都产出中间结果。

#### 语法

```python
graph.stream(inputs, config=None, stream_mode="values")
```

#### 参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `inputs` | `dict` | — | 初始输入状态 |
| `config` | `RunnableConfig` | `None` | 运行时配置 |
| `stream_mode` | `str` | `"values"` | 流式模式 |

#### 流式模式（stream_mode）

| 模式           | 说明             | 输出内容    |
| ------------ | -------------- | ------- |
| `"values"`   | 每步输出完整状态       | 完整状态字典  |
| `"updates"`  | 每步输出状态增量       | 只有变化的字段 |
| `"messages"` | 流式输出 LLM token | 实时生成的文本 |

#### 示例

```python
# 模式一：values（完整状态）
for state in graph.stream(inputs, stream_mode="values"):
    print(f"当前状态: {state}")

# 模式二：updates（状态增量）
for step in graph.stream(inputs, stream_mode="updates"):
    for node_name, update in step.items():
        print(f"节点 {node_name} 的更新: {update}")

# 模式三：messages（LLM token 流）
for chunk in graph.stream(inputs, stream_mode="messages"):
    # chunk 是 LLM 生成的 token
    print(chunk.content, end="", flush=True)
```

### astream()：异步流式执行

`astream()` 是 `stream()` 的异步版本。

#### 示例

```python
import asyncio

async def main():
    async for step in graph.astream(inputs, stream_mode="updates"):
        print(step)

asyncio.run(main())
```

### batch()：批量执行

`batch()` 同时执行多个输入。

#### 示例

```python
inputs_list = [
    {"messages": [("user", "问题1")]},
    {"messages": [("user", "问题2")]},
    {"messages": [("user", "问题3")]},
]

results = graph.batch(inputs_list)

for result in results:
    print(result["messages"][-1].content)
```

## 配置（Config）

### RunnableConfig

配置对象用于传递运行时参数：

```python
config = {
    "configurable": {
        "thread_id": "conversation-123",  # 对话 ID（用于持久化）
        "user_id": "user-456",            # 用户 ID
        "custom_param": "value"           # 自定义参数
    },
    "tags": ["production", "v2"],         # 标签（用于追踪）
    "metadata": {"source": "web"}         # 元数据
}
```

### thread_id 的作用

`thread_id` 是持久化的关键：

```python
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()
graph = builder.compile(checkpointer=checkpointer)

# 第一次调用
config = {"configurable": {"thread_id": "conv-001"}}
result1 = graph.invoke(
    {"messages": [("user", "我叫小明")]},
    config=config
)

# 第二次调用（使用相同的 thread_id，会恢复之前的状态）
result2 = graph.invoke(
    {"messages": [("user", "我叫什么名字？")]},
    config=config
)
# LLM 会记住用户叫"小明"
```

## 完整示例：各种执行方式

```python
"""
完整示例：展示编译和执行的多种方式
"""
from typing import TypedDict
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.checkpoint.memory import MemorySaver
from langchain_openai import ChatOpenAI

# 初始化 LLM
model = ChatOpenAI(model="gpt-4o-mini", temperature=0.7)

# 定义节点
def chatbot(state: MessagesState) -> dict:
    """聊天机器人节点"""
    response = model.invoke(state["messages"])
    return {"messages": [response]}

# 构建图
builder = StateGraph(MessagesState)
builder.add_node("chatbot", chatbot)
builder.add_edge(START, "chatbot")
builder.add_edge("chatbot", END)

# 编译（带持久化）
checkpointer = MemorySaver()
graph = builder.compile(checkpointer=checkpointer)

# ============================================
# 执行方式一：invoke（同步执行到完成）
# ============================================
print("=== invoke() ===")
config = {"configurable": {"thread_id": "test-001"}}
result = graph.invoke(
    {"messages": [("user", "你好！")]},
    config=config
)
print(f"最终回复: {result['messages'][-1].content}")

# ============================================
# 执行方式二：stream（流式执行，updates 模式）
# ============================================
print("\n=== stream(updates) ===")
inputs = {"messages": [("user", "介绍一下 LangGraph")]}
config = {"configurable": {"thread_id": "test-002"}}

for step in graph.stream(inputs, config=config, stream_mode="updates"):
    for node_name, update in step.items():
        print(f"节点: {node_name}")
        if "messages" in update:
            for msg in update["messages"]:
                print(f"  消息: {msg.content[:100]}...")

# ============================================
# 执行方式三：stream（流式执行，values 模式）
# ============================================
print("\n=== stream(values) ===")
config = {"configurable": {"thread_id": "test-003"}}

for state in graph.stream(
    {"messages": [("user", "什么是 AI？")]},
    config=config,
    stream_mode="values"
):
    print(f"当前消息数: {len(state['messages'])}")

# ============================================
# 执行方式四：多轮对话（利用持久化）
# ============================================
print("\n=== 多轮对话 ===")
config = {"configurable": {"thread_id": "conv-100"}}

# 第一轮
result1 = graph.invoke(
    {"messages": [("user", "我叫张三")]},
    config=config
)
print(f"第一轮回复: {result1['messages'][-1].content}")

# 第二轮（会记住之前的对话）
result2 = graph.invoke(
    {"messages": [("user", "我叫什么名字？")]},
    config=config
)
print(f"第二轮回复: {result2['messages'][-1].content}")
# 应该包含"张三"

# ============================================
# 执行方式五：batch（批量执行）
# ============================================
print("\n=== batch() ===")
inputs_list = [
    {"messages": [("user", "问题1")]},
    {"messages": [("user", "问题2")]},
]
configs = [
    {"configurable": {"thread_id": f"batch-{i}"}}
    for i in range(len(inputs_list))
]

results = graph.batch(inputs_list, config=configs)
for i, result in enumerate(results):
    print(f"批量结果 {i+1}: {result['messages'][-1].content[:50]}...")
```

## 状态管理

### 获取当前状态

使用 `get_state()` 查看当前状态（需要 checkpointer）：

```python
# 获取当前状态
state = graph.get_state(config)
print(f"当前状态: {state.values}")
print(f"下一个节点: {state.next}")

# 获取特定线程的状态
state = graph.get_state({"configurable": {"thread_id": "conv-001"}})
```

### 更新状态

使用 `update_state()` 手动修改状态：

```python
# 更新状态
graph.update_state(
    config,
    {"messages": [("user", "强制更新的消息")]},
    as_node="chatbot"  # 假装是 chatbot 节点更新的
)
```

### 时间旅行

LangGraph 支持回溯到历史状态：

```python
# 获取历史状态列表
history = list(graph.get_state_history(config))

# 回溯到之前的状态
old_state = history[-2]  # 倒数第二个状态
graph.update_state(config, old_state.values, as_node="__root__")
```

## 错误处理

### 节点错误

如果节点抛出异常，图会停止执行：

```python
def failing_node(state: State) -> dict:
    """会失败的节点"""
    raise ValueError("出错了！")

# 解决方案：在节点内部捕获异常
def robust_node(state: State) -> dict:
    try:
        risky_operation()
        return {"result": "success"}
    except Exception as e:
        return {"result": "error", "error_msg": str(e)}
```

### 重试策略

为节点配置重试策略：

```python
from langgraph.graph import StateGraph

builder = StateGraph(State)

# 为节点添加重试策略
builder.add_node(
    "flaky_task",
    flaky_function,
    retry={
        "max_attempts": 3,
        "retry_on": (ConnectionError, TimeoutError),
        "backoff_factor": 2
    }
)
```

## 性能优化

### 1. 使用异步节点

对于 I/O 密集型操作，使用异步节点：

```python
async def async_node(state: State) -> dict:
    result = await async_api_call()
    return {"result": result}
```

### 2. 并行执行

使用 fan-out 并行执行独立节点：

```python
# A 执行后，B 和 C 并行执行
builder.add_edge("A", "B")
builder.add_edge("A", "C")
```

### 3. 流式输出

使用 `stream_mode="messages"` 实时输出 LLM 生成的内容：

```python
for chunk in graph.stream(inputs, stream_mode="messages"):
    print(chunk.content, end="", flush=True)
```

## recursion_limit 与无限循环防护

### 什么是 recursion_limit

`recursion_limit` 是 LangGraph 的一个运行时配置参数，用于限制图中**节点执行的总次数**。它的默认值是 **25**，意味着一次 `invoke()` 或 `stream()` 调用中，最多允许 25 个节点执行。

这个限制的核心目的是**防止无限循环**。当你的图中包含循环（cycle）——例如条件边让执行回到之前的节点——如果条件永远不满足退出条件，图就会无限执行下去。`recursion_limit` 就是这种场景的安全阀。

```
节点 A → 条件边 → 节点 B → 条件边 → 节点 A → 条件边 → 节点 B → ...（无限循环）
                                                    ↑
                                          recursion_limit 在此处强制停止
```

### 为什么需要 recursion_limit

考虑以下场景：

```python
from langgraph.graph import StateGraph, START, END
from typing import TypedDict

class State(TypedDict):
    count: int
    result: str

def process(state: State) -> dict:
    # 假设这个节点有 bug，永远返回 "continue"
    return {"result": f"processed {state['count']}"}

def should_continue(state: State) -> str:
    # Bug：条件永远为 True
    return "continue"  # 永远不会返回 "stop"

builder = StateGraph(State)
builder.add_node("process", process)
builder.add_edge(START, "process")
builder.add_conditional_edges("process", should_continue, {
    "continue": "process",  # 回到自身 → 形成循环
    "stop": END
})

graph = builder.compile()

# 没有 recursion_limit 的话，这个图会永远执行下去
# 但有了默认的 recursion_limit=25，它会在 25 次节点执行后停止
```

### 如何设置 recursion_limit

通过 `config` 参数传递 `recursion_limit`：

```python
# 方式一：在 invoke/stream 时设置
result = graph.invoke(
    {"count": 0, "result": ""},
    config={"recursion_limit": 10}  # 最多 10 次节点执行
)

# 方式二：在 stream 时设置
for chunk in graph.stream(
    {"count": 0, "result": ""},
    config={"recursion_limit": 50}
):
    print(chunk)

# 方式三：与其他 config 一起使用
config = {
    "recursion_limit": 30,
    "configurable": {
        "thread_id": "conv-001"
    }
}
result = graph.invoke({"count": 0, "result": ""}, config=config)
```

### 检测 GraphRecursionError

当节点执行次数超过 `recursion_limit` 时，LangGraph 会抛出 `GraphRecursionError`：

```python
from langgraph.errors import GraphRecursionError

try:
    result = graph.invoke(
        {"count": 0, "result": ""},
        config={"recursion_limit": 10}
    )
except GraphRecursionError as e:
    print(f"达到递归限制！节点执行次数已超过上限。")
    print(f"错误详情: {e}")
    # 可以选择：
    # 1. 增大 recursion_limit 重试
    # 2. 返回部分结果
    # 3. 通知用户
except Exception as e:
    print(f"其他错误: {e}")
```

### 实际示例：带防护的循环图

```python
from langgraph.graph import StateGraph, START, END
from langgraph.errors import GraphRecursionError
from typing import TypedDict

class AgentState(TypedDict):
    messages: list
    iteration: int
    max_iterations: int

def agent_node(state: AgentState) -> dict:
    """Agent 节点：执行工具调用或生成回答"""
    iteration = state["iteration"]
    print(f"[Agent] 第 {iteration} 次迭代")
    # 模拟 Agent 逻辑
    return {
        "messages": state["messages"] + [f"Agent 思考 ({iteration})"],
        "iteration": iteration + 1
    }

def tool_node(state: AgentState) -> dict:
    """工具节点：执行工具"""
    print(f"[Tool] 执行工具")
    return {"messages": state["messages"] + ["Tool 结果"]}

def should_continue(state: AgentState) -> str:
    """判断是否继续"""
    if state["iteration"] >= state["max_iterations"]:
        return "stop"
    return "continue"

# 构建图
builder = StateGraph(AgentState)
builder.add_node("agent", agent_node)
builder.add_node("tool", tool_node)
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", should_continue, {
    "continue": "tool",
    "stop": END
})
builder.add_edge("tool", "agent")
graph = builder.compile()

# 安全执行
def safe_invoke(graph, inputs, recursion_limit=25):
    """带防护的执行函数"""
    try:
        return graph.invoke(inputs, config={"recursion_limit": recursion_limit})
    except GraphRecursionError:
        print(f"警告：达到 recursion_limit ({recursion_limit})，强制停止")
        # 返回最后一次成功获取的状态（如果使用了 checkpointer）
        return None

# 使用
result = safe_invoke(
    graph,
    {"messages": [], "iteration": 0, "max_iterations": 5},
    recursion_limit=20  # 留出足够的余量
)
```

### 不同图类型的推荐值

| 图类型 | 推荐 recursion_limit | 说明 |
|--------|---------------------|------|
| 线性图（无循环） | 25（默认） | 节点数通常远小于 25 |
| 简单循环（如重试） | 10-15 | 重试 3 次 ≈ 每次循环 2-3 个节点 × 3 次 |
| Agent 图（工具调用循环） | 30-50 | Agent 可能需要多次工具调用 |
| 复杂多 Agent 系统 | 50-100 | 多个 Agent 之间可能多次交互 |
| 批处理/ETL 管道 | 根据节点数调整 | 设为 `节点数 × 1.5` 左右 |

### 最佳实践

1. **始终设置合理的 recursion_limit**：即使是线性图，也建议显式设置，避免意外循环。

2. **在节点中内置退出条件**：不要仅依赖 `recursion_limit` 作为唯一的循环防护。

```python
def agent_node(state: AgentState) -> dict:
    # 内置退出条件
    if state["iteration"] >= 10:
        return {"messages": [("assistant", "达到最大迭代次数，强制结束")]}
    # 正常逻辑...
```

3. **配合 checkpointer 使用**：当触发 `GraphRecursionError` 时，如果有 checkpointer，你可以通过 `get_state()` 获取最后保存的状态，了解图停在了哪里。

4. **调试时降低 recursion_limit**：开发阶段可以设置为 5 或 10，快速发现意外的循环。

```python
# 调试模式
result = graph.invoke(inputs, config={"recursion_limit": 5})
```

5. **记录循环次数**：在状态中维护一个计数器，方便追踪和调试。

```python
class State(TypedDict):
    step_count: int  # 记录执行步数

def any_node(state: State) -> dict:
    print(f"当前步数: {state['step_count']}")
    return {"step_count": state["step_count"] + 1}
```
