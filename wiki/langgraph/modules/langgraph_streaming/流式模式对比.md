# 流式模式对比

LangGraph 提供三种流式模式，每种模式针对不同的使用场景进行了优化。理解它们的区别对于构建高效的应用至关重要。

## 1. Values 模式

### 工作原理

`stream_mode="values"` 在每个节点执行完成后返回**完整的状态快照**。这意味着每次你收到的 chunk 都包含图的当前完整状态。

### 代码示例

```python
from langgraph.graph import StateGraph, START, END
from typing import Annotated
from typing_extensions import TypedDict

class State(TypedDict):
    count: int
    message: str

def node_a(state: State):
    return {"count": state["count"] + 1, "message": "Node A executed"}

def node_b(state: State):
    return {"count": state["count"] * 2, "message": "Node B executed"}

# 构建图
graph = StateGraph(State)
graph.add_node("node_a", node_a)
graph.add_node("node_b", node_b)
graph.add_edge(START, "node_a")
graph.add_edge("node_a", "node_b")
graph.add_edge("node_b", END)

app = graph.compile()

# 使用 values 模式
for chunk in app.stream({"count": 0, "message": ""}, stream_mode="values"):
    print(chunk)
    # 输出示例：
    # {'count': 1, 'message': 'Node A executed'}
    # {'count': 2, 'message': 'Node B executed'}
```

### 特点

- **完整性**：每次输出都是完整状态
- **简单性**：不需要追踪增量变化
- **调试友好**：可以轻松查看任何时刻的完整状态
- **数据量大**：如果状态很大，每次传输的数据量也大

### 适用场景

- 状态相对较小
- 需要完整状态快照
- 调试和开发阶段
- 状态审计和监控

## 2. Updates 模式

### 工作原理

`stream_mode="updates"` 只返回**每个节点的输出**（增量更新），而不是完整状态。你需要自己将这些更新应用到状态中。

### 代码示例

```python
# 使用 updates 模式
for chunk in app.stream({"count": 0, "message": ""}, stream_mode="updates"):
    # chunk 是一个字典，键是节点名，值是该节点的输出
    for node_name, node_output in chunk.items():
        print(f"节点 {node_name} 输出: {node_output}")
    
    # 输出示例：
    # 节点 node_a 输出: {'count': 1, 'message': 'Node A executed'}
    # 节点 node_b 输出: {'count': 2, 'message': 'Node B executed'}
```

### 特点

- **增量性**：只传输变化的部分
- **高效性**：网络传输量更小
- **需要追踪**：需要自己维护状态
- **灵活性**：可以选择性地应用更新

### 适用场景

- 状态很大，但每次变化很小
- 只需要知道节点做了什么
- 网络带宽有限
- 日志记录和审计

### 实际应用示例

```python
# 跟踪状态变化
current_state = {"count": 0, "message": ""}

for chunk in app.stream(current_state, stream_mode="updates"):
    for node_name, node_output in chunk.items():
        print(f"执行节点: {node_name}")
        print(f"输出: {node_output}")
        # 可以选择性地更新状态
        current_state.update(node_output)
```

## 3. Messages 模式

### 工作原理

`stream_mode="messages"` 提供**逐 token 的流式输出**，特别适合 LLM 节点。它让你能够实时显示 LLM 生成的文本，实现打字机效果。

### 代码示例

```python
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI
from typing import Annotated
from typing_extensions import TypedDict

class State(TypedDict):
    messages: Annotated[list, add_messages]

# 创建 LLM
llm = ChatOpenAI(model="gpt-4")

def chatbot(state: State):
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

# 构建图
graph = StateGraph(State)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)

app = graph.compile()

# 使用 messages 模式
for chunk in app.stream({"messages": [("user", "讲一个故事")]}, stream_mode="messages"):
    # chunk[0] 是消息内容
    # chunk[1] 是元数据
    if chunk[0].content:
        print(chunk[0].content, end="", flush=True)
```

### 特点

- **实时性**：Token 级别的实时输出
- **用户体验**：可以实现打字机效果
- **细粒度**：最细粒度的流式输出
- **LLM 专用**：主要针对 LLM 节点优化

### 适用场景

- 实时显示 LLM 生成的文本
- 打字机效果
- 流式响应给前端
- 长文本生成

### 高级用法

```python
# 处理消息元数据
for chunk in app.stream({"messages": []}, stream_mode="messages"):
    message_chunk, metadata = chunk
    
    # 显示消息内容
    if message_chunk.content:
        print(message_chunk.content, end="")
    
    # 使用元数据
    if metadata:
        print(f" [来自节点: {metadata.get('langgraph_node', 'unknown')}]")
```

## 完整对比表

| 特性 | Values | Updates | Messages |
|------|--------|---------|----------|
| **输出粒度** | 节点级（完整状态） | 节点级（增量） | Token 级 |
| **数据量** | 最大 | 中等 | 最小 |
| **实时性** | 节点完成后 | 节点完成后 | 实时 |
| **需要状态追踪** | 否 | 是 | 否 |
| **网络开销** | 高 | 中 | 低 |
| **适用节点类型** | 所有节点 | 所有节点 | 主要是 LLM |
| **调试友好度** | 高 | 中 | 低 |
| **用户体验** | 一般 | 一般 | 优秀 |

## 选择指南

### 使用 Values 模式当：

- 状态较小，完整快照不会造成性能问题
- 需要完整状态进行调试
- 不想自己追踪状态变化
- 构建监控或审计系统

```python
# 调试场景
for chunk in app.stream(inputs, stream_mode="values"):
    # 可以轻松查看任何时刻的完整状态
    assert "messages" in chunk
    assert "count" in chunk
```

### 使用 Updates 模式当：

- 状态很大，但每次变化很小
- 网络带宽有限
- 只需要知道节点做了什么
- 构建日志系统

```python
# 日志场景
for chunk in app.stream(inputs, stream_mode="updates"):
    for node_name, output in chunk.items():
        logger.info(f"节点 {node_name} 完成: {output}")
```

### 使用 Messages 模式当：

- 需要实时显示 LLM 生成的文本
- 构建聊天界面
- 实现打字机效果
- 处理长文本生成

```python
# 聊天界面场景
for chunk in app.stream(inputs, stream_mode="messages"):
    if chunk[0].content:
        # 实时发送到前端
        websocket.send(chunk[0].content)
```

## 多模式组合使用

你可以同时使用多种流式模式来获取不同层次的信息：

```python
# 同时使用 values 和 messages 模式
for chunk in app.stream(
    {"messages": [("user", "Hello")]}, 
    stream_mode=["values", "messages"]
):
    # chunk 是一个元组: (mode, data)
    mode, data = chunk
    
    if mode == "values":
        print(f"完整状态: {data}")
    elif mode == "messages":
        print(f"Token: {data[0].content}")
```

## 性能考虑

### 内存使用

- **Values**：每次都需要创建完整状态副本，内存使用最高
- **Updates**：只传输变化部分，内存使用中等
- **Messages**：只传输单个 token，内存使用最低

### 网络传输

- **Values**：每次传输完整状态，网络开销最大
- **Updates**：只传输增量，网络开销中等
- **Messages**：只传输 token，网络开销最小

### CPU 使用

- **Values**：需要复制完整状态，CPU 开销较高
- **Updates**：需要计算增量，CPU 开销中等
- **Messages**：只处理单个 token，CPU 开销最低
