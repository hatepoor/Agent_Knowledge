# 流式处理概述

LangGraph 提供了强大的流式处理功能，允许你逐步获取图执行的输出，而不是等待整个执行完成。这对于构建实时交互应用、显示进度指示器或逐步处理大型输出非常有用。

## 核心概念

流式处理让你能够在图执行过程中实时获取中间结果，主要优势包括：

- **实时反馈**：用户可以看到处理进度，而不是面对空白等待
- **渐进式处理**：可以在输出生成的同时开始处理
- **更好的用户体验**：减少感知延迟，提供即时响应
- **资源优化**：不需要等待所有节点完成才开始处理

### 流式处理的基本原理

LangGraph 的流式处理基于 Python 的生成器（generator）机制。当调用 `stream()` 方法时，图不会一次性执行完毕，而是每完成一个有意义的步骤就 `yield` 一个数据块（chunk）。这意味着：

1. 图引擎执行第一个节点
2. 节点完成后，将结果通过 `yield` 产出
3. 图引擎继续执行下一个节点
4. 重复直到图执行完毕

```python
# 同步流式
for chunk in graph.stream(inputs, stream_mode="values"):
    # 每个 chunk 都是一个数据块
    process(chunk)

# 异步流式
async for chunk in graph.astream(inputs, stream_mode="values"):
    await process(chunk)
```

## stream_mode 参数详解

`stream_mode` 是流式处理的核心参数，决定了每次 `yield` 产出什么内容。它可以是：

- **字符串**：单一模式，如 `"values"`
- **字符串列表**：多模式组合，如 `["values", "updates"]`

```python
# 单一模式
for chunk in graph.stream(inputs, stream_mode="values"):
    ...

# 多模式组合 — chunk 格式变为 (mode, data) 元组
for mode, chunk in graph.stream(inputs, stream_mode=["values", "updates"]):
    if mode == "values":
        print(f"完整状态: {chunk}")
    elif mode == "updates":
        print(f"增量更新: {chunk}")
```

> **注意**：当传入列表时，每个 chunk 的格式会变为 `(stream_mode, data)` 元组。当传入字符串时，chunk 直接是数据本身。

## 三种流式模式

LangGraph 提供了三种不同的流式模式，适用于不同的场景：

### 1. Values 模式

`stream_mode="values"` 在每个节点执行后返回**完整的状态快照**。这是默认模式。

```python
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_openai import ChatOpenAI
from typing import Annotated
from typing_extensions import TypedDict

class State(TypedDict):
    messages: Annotated[list, add_messages]
    context: str
    answer: str

# 构建一个多节点图
def retrieve(state: State) -> dict:
    """检索节点：根据用户问题检索相关上下文"""
    query = state["messages"][-1].content
    # 模拟检索
    return {"context": f"关于 '{query}' 的检索结果"}

def generate(state: State) -> dict:
    """生成节点：基于上下文生成回答"""
    context = state.get("context", "")
    # 模拟生成
    return {"messages": [("assistant", f"基于上下文生成的回答: {context}")]}

graph = StateGraph(State)
graph.add_node("retrieve", retrieve)
graph.add_node("generate", generate)
graph.add_edge(START, "retrieve")
graph.add_edge("retrieve", "generate")
graph.add_edge("generate", END)
app = graph.compile()

# 使用 values 模式流式处理
for chunk in app.stream({"messages": [("user", "LangGraph 是什么?")]}, stream_mode="values"):
    # chunk 包含完整的状态快照
    print(f"--- 当前完整状态 ---")
    print(f"  消息数: {len(chunk['messages'][[)}")
    print(f"  上下文: {chunk.get('context', '无')}")
    print(f"  回答: {chunk.get('answer', '无')}")
```

**输出示例**：
```
--- 当前完整状态 ---
  消息数: 1
  上下文: 无
  回答: 无
--- 当前完整状态 ---
  消息数: 1
  上下文: 关于 'LangGraph 是什么?' 的检索结果
  回答: 无
--- 当前完整状态 ---
  消息数: 2
  上下文: 关于 'LangGraph 是什么?' 的检索结果
  回答: 无
```

> **特点**：每次产出都包含**所有字段**，即使某些字段没有变化。适合需要完整状态视图的场景。

**适用场景**：
- 需要跟踪完整状态变化
- 调试和监控
- 状态审计
- 前端需要完整状态来渲染 UI

**详细文档**：[[langgraph/modules/langgraph_streaming/流式模式对比|流式模式对比]]

### 2. Updates 模式

`stream_mode="updates"` 只返回每个节点的**输出（增量更新）**，而不是完整状态。

```python
# 使用 updates 模式流式处理
for chunk in app.stream(
    {"messages": [("user", "LangGraph 是什么?")]},
    stream_mode="updates"
):
    # chunk 是一个字典，key 是节点名，value 是该节点的输出
    for node_name, node_output in chunk.items():
        print(f"节点 '{node_name}' 的输出:")
        for key, value in node_output.items():
            print(f"  {key}: {value}")
```

**输出示例**：
```
节点 'retrieve' 的输出:
  context: 关于 'LangGraph 是什么?' 的检索结果
节点 'generate' 的输出:
  messages: [AIMessage(content='基于上下文生成的回答: ...')][[
```

> **特点**：只包含当前节点修改的字段，数据量更小。适合只关心"发生了什么变化"的场景。

**适用场景**：
- 只需要知道每个节点做了什么
- 减少网络传输（前端只需处理增量）
- 日志记录
- 构建执行追踪（trace）

**详细文档**：[[langgraph/modules/langgraph_streaming/流式模式对比|流式模式对比]]

### 3. Messages 模式

`stream_mode="messages"` 提供**逐 token 的流式输出**，特别适合 LLM 节点。这是唯一能在 LLM 生成过程中实时看到每个 token 的模式。

```python
from langgraph.graph import MessagesState, START, END, StateGraph
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o-mini", temperature=0.7)

def chatbot(state: MessagesState) -> dict:
    response = model.invoke(state["messages"])
    return {"messages": [response]}

graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)
app = graph.compile()

# 使用 messages 模式流式处理
for chunk in app.stream(
    {"messages": [("user", "用 100 字介绍 LangGraph")][[},
    stream_mode="messages"
):
    # chunk 是一个元组: (message_chunk, metadata)
    msg_chunk, metadata = chunk
    # msg_chunk 可能是 AIMessageChunk 或 HumanMessage 等
    if hasattr(msg_chunk, "content") and msg_chunk.content:
        print(msg_chunk.content, end="", flush=True)
    # metadata 包含节点名、语言模型名等信息
    if metadata:
        langgraph_node = metadata.get("langgraph_node", "unknown")
```

**输出示例**（逐 token 打印）：
```
LangGraph是一个用于构建有状态的、支持多轮对话的AI Agent框架...
```

> **特点**：Token 级别的实时输出，延迟最低。但只适用于包含 LLM 调用的节点。

**适用场景**：
- 实时显示 LLM 生成的文本（打字机效果）
- 流式响应给前端
- 需要最低延迟的场景

**详细文档**：[[langgraph/modules/langgraph_streaming/流式模式对比|流式模式对比]]

## 何时使用哪种模式

选择正确的流式模式取决于你的具体需求。以下是决策指南：

### 决策流程图

```
你需要实时显示 LLM 生成的文本吗？
├── 是 → 使用 "messages" 模式
│        （打字机效果、聊天界面）
│
└── 否 → 你需要跟踪每个节点做了什么吗？
         ├── 是 → 使用 "updates" 模式
         │        （日志、追踪、增量更新前端）
         │
         └── 否 → 使用 "values" 模式
                  （调试、完整状态监控）
```

### 场景对照表

| 场景 | 推荐模式 | 原因 |
|------|----------|------|
| 聊天界面实时显示回复 | `messages` | Token 级延迟，用户体验最佳 |
| 前端进度条/状态指示器 | `updates` | 只需知道哪个节点完成了 |
| 调试图执行流程 | `values` | 可以看到每步的完整状态 |
| 构建 LangSmith 风格的追踪 | `updates` | 节点级别的输入/输出记录 |
| 状态审计/合规检查 | `values` | 完整状态快照，不遗漏任何字段 |
| 同时需要实时文本 + 节点进度 | `["messages", "updates"]` | 多模式组合 |
| SSE (Server-Sent Events) 推送 | `messages` 或 `updates` | 取决于前端需要什么粒度 |

### 模式选择注意事项

1. **`messages` 模式只对有 LLM 调用的节点有效**：如果节点不涉及 LLM 调用（如纯函数、数据库查询），`messages` 模式不会产生任何输出。

2. **`values` 模式数据量最大**：每个节点执行后都输出完整状态，如果状态很大（如包含大量消息历史），网络传输开销会显著增加。

3. **`updates` 模式最灵活**：你可以从增量更新中重建完整状态，同时保持较低的数据传输量。

## 多模式组合

你可以同时使用多种流式模式，在一次执行中获取不同粒度的信息。

### 基本用法

```python
# 同时使用 values 和 updates 模式
for chunk in app.stream(
    {"messages": [("user", "你好")]},
    stream_mode=["values", "updates"]
):
    # chunk 是 (mode, data) 元组
    mode, data = chunk
    if mode == "values":
        print(f"[完整状态] 消息数: {len(data['messages'])}")
    elif mode == "updates":
        for node_name, output in data.items():
            print(f"[增量] 节点 {node_name}: {output}")
```

### 组合 messages + updates

这是构建实时聊天界面最常用的组合：

```python
for mode, chunk in app.stream(
    {"messages": [("user", "详细介绍 LangGraph 的核心概念")]},
    stream_mode=["messages", "updates"]
):
    if mode == "messages":
        msg, metadata = chunk
        if hasattr(msg, "content") and msg.content:
            # 实时输出 LLM 生成的文本
            print(msg.content, end="", flush=True)
    elif mode == "updates":
        for node_name, output in chunk.items():
            # 记录节点执行信息
            print(f"\n[节点完成] {node_name}")
```

### 组合所有三种模式

```python
for mode, chunk in app.stream(
    {"messages": [("user", "你好")]},
    stream_mode=["values", "updates", "messages"]
):
    if mode == "values":
        print(f"[VALUES] 完整状态快照")
    elif mode == "updates":
        print(f"[UPDATES] 节点增量")
    elif mode == "messages":
        msg, meta = chunk
        if hasattr(msg, "content") and msg.content:
            print(f"[MESSAGES] Token: {msg.content}")
```

> **注意**：多模式组合时，产出的顺序是按执行时间排列的。一个节点执行期间，`messages` 的 chunk 会穿插在该节点的 `updates` chunk 之间。

## 异步流式处理

LangGraph 完整支持异步流式处理，适合与 FastAPI、Starlette 等异步 Web 框架集成：

```python
import asyncio

async def main():
    # 异步 values 模式
    async for chunk in app.astream({"messages": []}, stream_mode="values"):
        print(chunk)

asyncio.run(main())
```

### 与 FastAPI 集成

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import json

app = FastAPI()

@app.post("/chat")
async def chat(message: str):
    async def event_generator():
        async for mode, chunk in graph.astream(
            {"messages": [("user", message)]},
            stream_mode=["messages", "updates"][[
        ):
            if mode == "messages":
                msg, metadata = chunk
                if hasattr(msg, "content") and msg.content:
                    yield f"data: {json.dumps({'type': 'token', 'content': msg.content})}\n\n"
            elif mode == "updates":
                yield f"data: {json.dumps({'type': 'node_done', 'data': chunk})}\n\n"
        yield f"data: {json.dumps({'type': 'done'})}\n\n"

    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

## 流式处理中的错误处理

流式处理过程中可能发生错误，需要妥善处理：

### 基本错误捕获

```python
try:
    for chunk in app.stream(
        {"messages": [("user", "你好")]},
        stream_mode="updates"
    ):
        for node_name, output in chunk.items():
            print(f"节点 {node_name}: {output}")
except Exception as e:
    print(f"流式处理出错: {e}")
    # 已经产出的 chunk 仍然有效
```

### 在节点内部处理错误

推荐在节点内部捕获异常，避免中断整个流式过程：

```python
def fragile_node(state: State) -> dict:
    try:
        result = risky_api_call(state["query"])
        return {"result": result}
    except Exception as e:
        # 将错误信息写入状态，而不是抛出异常
        return {"result": None, "error": str(e)}
```

### 流式处理的超时控制

```python
import signal

def timeout_handler(signum, frame):
    raise TimeoutError("流式处理超时")

# 设置 30 秒超时
signal.signal(signal.SIGALRM, timeout_handler)
signal.alarm(30)

try:
    for chunk in app.stream(inputs, stream_mode="updates"):
        process(chunk)
except TimeoutError:
    print("处理超时，部分结果可能已丢失")
finally:
    signal.alarm(0)  # 取消定时器
```

### 处理 LLM 流式错误

使用 `messages` 模式时，LLM 可能在生成过程中出错：

```python
collected_content = []

try:
    for chunk in app.stream(inputs, stream_mode="messages"):
        msg, metadata = chunk
        if hasattr(msg, "content") and msg.content:
            collected_content.append(msg.content)
            print(msg.content, end="", flush=True)
except Exception as e:
    # 已经收到的 token 仍然可用
    partial_result = "".join(collected_content)
    print(f"\n生成中断，已收到部分内容: {partial_result[:100]}...")
    print(f"错误: {e}")
```

## 完整实战示例：流式聊天机器人

下面是一个完整的实战示例，展示如何构建一个支持流式输出的聊天机器人：

```python
"""
完整示例：流式聊天机器人
支持实时输出、进度显示、错误处理
"""
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_openai import ChatOpenAI

# ============================================
# 1. 定义状态
# ============================================
class ChatState(TypedDict):
    messages: Annotated[list, add_messages]
    retrieved_context: str

# ============================================
# 2. 初始化组件
# ============================================
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.7, streaming=True)

# ============================================
# 3. 定义节点
# ============================================
def retrieve(state: ChatState) -> dict:
    """检索节点：模拟 RAG 检索"""
    last_message = state["messages"][-1]
    query = last_message.content
    # 实际项目中这里会调用向量数据库
    context = f"检索到关于 '{query}' 的相关信息"
    return {"retrieved_context": context}

def respond(state: ChatState) -> dict:
    """响应节点：基于检索结果生成回答"""
    context = state.get("retrieved_context", "")
    messages = state["messages"]
    # 将上下文注入系统消息
    system_msg = f"基于以下上下文回答用户问题：\n{context}"
    response = llm.invoke([("system", system_msg)] + messages)
    return {"messages": [response]}

# ============================================
# 4. 构建并编译图
# ============================================
builder = StateGraph(ChatState)
builder.add_node("retrieve", retrieve)
builder.add_node("respond", respond)
builder.add_edge(START, "retrieve")
builder.add_edge("retrieve", "respond")
builder.add_edge("respond", END)
graph = builder.compile()

# ============================================
# 5. 流式执行
# ============================================
def chat_stream(user_input: str):
    """流式聊天函数"""
    inputs = {"messages": [("user", user_input)]}

    print(f"\n用户: {user_input}")
    print("助手: ", end="", flush=True)

    for mode, chunk in graph.stream(
        inputs,
        stream_mode=["messages", "updates"]
    ):
        if mode == "messages":
            msg, metadata = chunk
            if hasattr(msg, "content") and msg.content:
                print(msg.content, end="", flush=True)
        elif mode == "updates":
            for node_name, output in chunk.items():
                if node_name == "retrieve":
                    print(f"\n  [已检索上下文][[", flush=True)

    print()  # 换行

# 运行
chat_stream("LangGraph 的核心概念有哪些？")
```

## 模式对比

| 特性 | Values | Updates | Messages |
|------|--------|---------|----------|
| 输出内容 | 完整状态快照 | 节点输出增量 | 单个 token |
| 数据量 | 最大 | 中等 | 最小 |
| 实时性 | 节点级 | 节点级 | Token 级 |
| 适用场景 | 状态跟踪 | 日志记录 | 实时显示 |
| 性能开销 | 较高 | 中等 | 较低 |
| 需要 LLM 节点 | 否 | 否 | 是（才有意义） |
| chunk 格式 | 状态字典 | `{node_name: output}` | `(msg, metadata)` |
