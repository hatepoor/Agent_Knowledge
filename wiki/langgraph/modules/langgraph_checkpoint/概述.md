# 持久化（Checkpointing）概述

## 什么是持久化

LangGraph 的**持久化（Checkpointing）** 机制允许在每个节点执行后自动保存图的完整状态快照。这些快照称为**检查点（Checkpoint）**，存储在外部存储中。

持久化使得 LangGraph 图从"一次性执行"变为"可恢复、可回溯、可多轮交互"的有状态应用。

```
无持久化：输入 → [图执行] → 输出 → 结束（状态丢失）
有持久化：输入 → [节点A] → 💾保存 → [节点B] → 💾保存 → 输出 → 状态保留
```

---

## 持久化能做什么

| 功能 | 说明 |
|------|------|
| **多轮对话** | 同一个 `thread_id` 下的多次调用共享消息历史 |
| **断点恢复** | 节点执行失败后，从上一个检查点恢复，无需重头开始 |
| **时间旅行** | 查看任意历史步骤的状态，甚至从历史状态重新执行 |
| **人工介入** | 在特定节点暂停，等待人工审批后继续 |
| **流式输出** | 配合 `stream` 方法实时获取中间状态 |

---

## 核心概念

### Checkpointer（检查点器）

Checkpointer 是负责存储和检索检查点的组件。LangGraph 提供多种实现：

| 类 | 存储后端 | 适用场景 |
|----|----------|----------|
| `InMemorySaver` | 内存字典 | 开发、测试、原型 |
| `PostgresSaver` | PostgreSQL | 生产环境（推荐） |
| `SqliteSaver` | SQLite 文件 | 轻量级持久化 |

详见各子页面：
- [[langgraph/modules/langgraph_checkpoint/InMemorySaver|InMemorySaver 详解]]
- [[langgraph/modules/langgraph_checkpoint/PostgresSaver|PostgresSaver 详解]]
- [[langgraph/modules/langgraph_checkpoint/SqliteSaver|SqliteSaver 详解]]

### thread_id（线程ID）

`thread_id` 是隔离不同对话/会话的标识符。

- **相同的 `thread_id`**：共享同一条状态历史链（多轮对话）
- **不同的 `thread_id`**：完全独立的状态（不同对话互不干扰）

```python
# 配置 thread_id
config = {"configurable": {"thread_id": "user-123-session-1"}}

# 同一 thread_id 的调用会共享历史
app.invoke(input1, config)  # 第一轮对话
app.invoke(input2, config)  # 第二轮对话（能看到第一轮的上下文）

# 不同 thread_id 完全隔离
config2 = {"configurable": {"thread_id": "user-456-session-1"}}
app.invoke(input3, config2)  # 独立对话，看不到之前的历史
```

详见 → [[langgraph/modules/langgraph_checkpoint/thread_id与会话管理|thread_id 与会话管理]]

## 基本用法

### 编译时传入 Checkpointer

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.checkpoint.memory import MemorySaver

# 定义图
graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot_node)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)

# 创建 Checkpointer
checkpointer = MemorySaver()

# 编译时传入 checkpointer
app = graph.compile(checkpointer=checkpointer)

# 调用时传入 thread_id
config = {"configurable": {"thread_id": "my-session"}}
result = app.invoke(
    {"messages": [("user", "你好")]},
    config=config
)
```

### 多轮对话示例

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.checkpoint.memory import MemorySaver
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini")

def chatbot(state: MessagesState) -> dict:
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

# 构建并编译图
graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)

checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)

# 配置
config = {"configurable": {"thread_id": "conversation-1"}}

# 第一轮对话
result1 = app.invoke(
    {"messages": [("user", "我叫小明")]},
    config=config
)
print(result1["messages"][-1].content)
# → "你好小明！..."

# 第二轮对话（LLM 记得第一轮的内容）
result2 = app.invoke(
    {"messages": [("user", "我叫什么名字？")]},
    config=config
)
print(result2["messages"][-1].content)
# → "你叫小明。"  ← 记住了！
```

## 检查点存储结构

每个 Checkpointer 存储的数据包含：

```
检查点存储
├── thread_id: "conversation-1"
│   ├── checkpoint_1 (节点A执行后)
│   │   ├── 状态快照
│   │   ├── 元数据（时间戳、节点名等）
│   │   └── 父检查点ID
│   ├── checkpoint_2 (节点B执行后)
│   │   ├── 状态快照
│   │   ├── 元数据
│   │   └── 父检查点ID → checkpoint_1
│   └── checkpoint_3 (节点C执行后)
│       └── ...
├── thread_id: "conversation-2"
│   └── ...
└── thread_id: "conversation-N"
    └── ...
```

## 时间旅行（Time Travel）

持久化使得"时间旅行"成为可能——可以查看历史状态或从历史状态重新执行。

### 获取历史状态

```python
# 获取完整状态历史
for state in app.get_state_history(config):
    print(f"节点: {state.next}")
    print(f"状态: {state.values}")
    print("---")
```

### 从历史状态重新执行

```python
# 获取某个历史状态
history_state = app.get_state(config)

# 修改状态
app.update_state(config, {"messages": [("user", "修改后的消息")]})

# 从修改后的状态继续执行
result = app.invoke(None, config=config)
```

## Checkpointer 选择指南

```
开发/测试？
├── 是 → InMemorySaver（零配置，快速）
└── 否 → 需要持久化存储
    ├── 已有 PostgreSQL？ → PostgresSaver（生产推荐）
    ├── 想要简单文件存储？ → SqliteSaver（轻量）
    └── 其他需求？ → 自定义 Checkpointer
```

### 详细对比

| 特性 | InMemorySaver | PostgresSaver | SqliteSaver |
|------|---------------|---------------|-------------|
| 持久化 | ❌（进程重启丢失） | ✅ | ✅ |
| 性能 | 最快（内存） | 高（网络开销） | 中 |
| 并发 | ❌ 单进程 | ✅ 高并发 | ⚠️ 有限 |
| 扩展性 | ❌ | ✅ 水平扩展 | ❌ 单文件 |
| 部署复杂度 | 零 | 中（需要 PG） | 低 |
| 适用环境 | 开发/测试 | 生产 | 单机生产 |
