# 图计算范式

## 概述

LangGraph 的核心思想是用**图（Graph）**来编排 AI 应用的执行流程。要理解为什么选择图而不是传统的线性链，我们需要从 LLM 应用的发展脉络说起。

## 从线性链到图：为什么需要进化

### 第一阶段：线性链（LCEL）

LangChain 最初使用 **LCEL（LangChain Expression Language）** 来组合组件：

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

# LCEL：用管道符 | 线性组合组件
chain = prompt | llm | output_parser

# 数据只能从左到右流动
result = chain.invoke({"topic": "LangGraph"})
```

```
输入 → [Prompt] → [LLM] → [OutputParser] → 输出
```

**优点**：简单直观，适合单步任务
**局限**：数据只能单向流动，无法回退、循环或分支

### 第二阶段：需要循环的场景

考虑 ReAct Agent 的场景：

```python
# 用 LCEL 实现 ReAct？几乎不可能
# 因为你需要：
# 1. 调用 LLM
# 2. 判断是否需要工具
# 3. 如果需要，调用工具
# 4. 把工具结果喂回 LLM
# 5. 重复 2-4 直到不需要工具
# 6. 返回最终答案

# LCEL 无法表达这种循环逻辑：
# prompt | llm | ??? | llm | ??? | ... | output_parser
#                    ↑              ↑
#               需要回退到 LLM    不确定循环几次
```

**核心问题**：LCEL 是 DAG（有向无环图），而 Agent 需要**循环**。

### 第三阶段：图（Graph）

LangGraph 用图来解决这个问题：

```python
from langgraph.graph import StateGraph, START, END

workflow = StateGraph(State)
workflow.add_node("agent", agent_node)
workflow.add_node("tools", tool_node)
workflow.add_edge(START, "agent")
workflow.add_conditional_edges("agent", should_continue, {
    "continue": "tools",
    "end": END,
})
workflow.add_edge("tools", "agent")  # ← 这就是循环！

app = workflow.compile()
```

## 三种图结构对比

### 1. DAG（有向无环图）

```
     ┌──→ [B] ──┐
     │          │
[A] ─┤          ├──→ [D]
     │          │
     └──→ [C] ──┘

特点：
- 数据单向流动
- 可以并行分支
- 不能回退
- 适合：ETL 管道、固定流程

LCEL 就是 DAG：
prompt | llm | parser
  [P]  → [L]  → [O]
```

### 2. 状态机（有限状态自动机）

```
         事件1
    ┌───────────┐
    │           ▼
  [状态A]    [状态B]
    ▲           │
    │    事件2   │
    └───────────┘

特点：
- 有明确的状态集合
- 通过事件触发状态转换
- 可以循环
- 适合：工作流引擎、协议实现
```

### 3. 有向循环图（LangGraph 使用的）

```
         ┌──────────────────────────┐
         │                          │
         ▼                          │
START → [节点A] ──→ [条件判断]       │
                      │             │
                ┌─────┴─────┐      │
                │           │      │
             条件1       条件2     │
                │           │      │
                ▼           ▼      │
            [节点B]     [END]      │
                │                  │
                └──────────────────┘

特点：
- 支持循环（核心优势）
- 支持条件分支
- 支持状态共享
- 适合：Agent、复杂工作流
```

## 为什么 Agent 需要循环

### ReAct 模式

```
┌─────────────────────────────────────────┐
│                                         │
│   用户输入                               │
│     │                                   │
│     ▼                                   │
│   [LLM 推理] ──→ 需要工具？              │
│     │              │                    │
│     │ 否          是                     │
│     │              │                    │
│     ▼              ▼                    │
│   [最终答案]   [执行工具]                 │
│                   │                     │
│                   │ 工具结果              │
│                   │                     │
│                   └────→ 回到 LLM ──────┘
│
└─────────────────────────────────────────┘
```

没有循环就无法实现 Agent 的核心逻辑——**反复推理和行动直到得到答案**。

### 多轮对话

```
┌─────────────────────────────────────────┐
│                                         │
│   用户消息                               │
│     │                                   │
│     ▼                                   │
│   [处理消息] ──→ [生成回复] ──→ 回复用户   │
│                                         │
│   用户新消息 ──→ 回到 [处理消息] ──────────┘
│
└─────────────────────────────────────────┘
```

每一轮对话都是对同一个图的又一次遍历。

### 自我纠错

```
┌─────────────────────────────────────────┐
│                                         │
│   [生成代码]                              │
│     │                                   │
│     ▼                                   │
│   [运行测试] ──→ 通过？                   │
│     │           │                       │
│     │ 是       否                        │
│     │           │                       │
│     ▼           ▼                       │
│   [输出]    [分析错误] ──→ 回到 [生成代码] │
│                                         │
└─────────────────────────────────────────┘
```

## 何时使用图

### 适合用图的场景

| 场景 | 为什么需要图 | 示例 |
|------|------------|------|
| Agent / ReAct | 需要推理-行动循环 | 搜索 Agent、代码 Agent |
| 多轮对话 | 需要状态持久化和循环 | 客服机器人、聊天助手 |
| 自我纠错 | 需要反馈循环 | 代码生成 + 测试 + 修复 |
| 多 Agent 协作 | 需要复杂路由 | 研究员 → 写手 → 审核员 |
| 人机交互 | 需要中断和恢复 | 审批流程、人工确认 |
| 复杂工作流 | 需要条件分支和并行 | 数据处理管道 |

### 不需要图的场景

| 场景 | 为什么不需要图 | 更好的选择 |
|------|--------------|-----------|
| 简单的问答 | 单次调用即可 | 直接调用 LLM |
| 固定的转换管道 | 无循环、无分支 | LCEL 链 |
| 单次 RAG | 固定流程：检索 → 生成 | LCEL 链 |
| 简单的格式化 | 纯数据处理 | 普通函数 |

## 图的核心组件

```python
from langgraph.graph import StateGraph, START, END

# 1. 状态（State）—— 图中流动的数据
class MyState(TypedDict):
    messages: Annotated[list, add_messages]
    context: str

# 2. 节点（Node）—— 处理数据的函数
def my_node(state: MyState) -> dict:
    # 读取状态
    messages = state["messages"]
    # 处理数据
    result = process(messages)
    # 返回状态更新
    return {"context": result}

# 3. 边（Edge）—— 节点之间的连接
graph = StateGraph(MyState)
graph.add_node("process", my_node)
graph.add_edge(START, "process")       # 固定边：A → B
graph.add_edge("process", END)

# 4. 条件边（Conditional Edge）—— 动态路由
graph.add_conditional_edges(
    "router_node",
    route_function,         # 路由函数
    {"path_a": "node_a", "path_b": "node_b"}  # 路由映射
)

# 5. 编译
app = graph.compile()
```

## 图的执行模型

```
┌─────────────────────────────────────────────────────┐
│                    图引擎                             │
│                                                     │
│  ┌─────────┐                                        │
│  │  状态    │ ← 全局共享的状态对象                     │
│  └────┬────┘                                        │
│       │                                             │
│       ▼                                             │
│  ┌─────────┐   读取状态   ┌──────────┐              │
│  │ 节点 A  │ ←────────── │  状态存储  │              │
│  └────┬────┘             └──────────┘              │
│       │                                            │
│       │ 返回更新                                     │
│       ▼                                            │
│  ┌──────────┐   合并更新                            │
│  │ Reducer  │ ──────────→ 更新状态存储               │
│  └──────────┘                                      │
│       │                                            │
│       ▼                                            │
│  ┌──────────┐                                      │
│  │  边判断  │ ──→ 决定下一个节点                      │
│  └──────────┘                                      │
│       │                                            │
│       ▼                                            │
│  ┌─────────┐                                       │
│  │ 节点 B  │ ──→ 重复上述过程                        │
│  └─────────┘                                       │
│                                                     │
└─────────────────────────────────────────────────────┘
```

每个步骤：
1. **读取状态**：节点从全局状态中获取需要的数据
2. **执行逻辑**：节点执行自己的处理逻辑
3. **返回更新**：节点返回状态的部分更新（不是完整状态）
4. **合并更新**：Reducer 将更新合并到全局状态
5. **路由决策**：边（或条件边）决定下一个节点
6. **重复**：直到到达 END

## 与其他编排方式的对比

| 特性 | LCEL 链 | 状态机 | LangGraph 图 |
|------|---------|--------|-------------|
| 循环支持 | 不支持 | 支持 | 支持 |
| 条件分支 | 有限（RunnableBranch） | 支持 | 支持（任意路由） |
| 状态管理 | 无（数据单向流动） | 内部状态 | 全局共享状态 |
| 持久化 | 不支持 | 需自行实现 | 内置 Checkpointer |
| 并行执行 | 支持（RunnableParallel） | 不支持 | 支持 |
| 人机交互 | 不支持 | 需自行实现 | 内置中断机制 |
| 流式输出 | 支持 | 需自行实现 | 内置多种流式模式 |
| 可视化 | 不支持 | 取决于实现 | 支持（Mermaid 导出） |
| 学习曲线 | 低 | 中 | 中 |

## ASCII 图示例集

### 简单链（DAG）

```
START → [A] → [B] → [C] → END
```

### 分支合并（DAG）

```
              ┌→ [B] ─┐
START → [A] ──┤       ├──→ [D] → END
              └→ [C] ─┘
```

### 条件路由（DAG）

```
              ┌─ 条件1 → [B] ─→ END
START → [A] ──┤
              └─ 条件2 → [C] ─→ END
```

### 循环（LangGraph 特有）

```
              ┌────────────┐
              │            │
START → [A] → [B] → [C] ──┘
              │
              └→ END
```

### ReAct Agent

```
              ┌────────────────────┐
              │                    │
START ──→ [Agent] ──→ [条件判断]    │
                         │         │
                    ┌────┴────┐   │
                    │         │   │
                 有工具     无工具  │
                    │         │   │
                    ▼         ▼   │
                [Tools]    END   │
                    │            │
                    └────────────┘
```

### 多 Agent 协作

```
START → [协调者] ──→ [条件路由]
                        │
              ┌─────────┼─────────┐
              │         │         │
              ▼         ▼         ▼
          [研究员]   [写手]    [审核员]
              │         │         │
              └─────────┼─────────┘
                        │
                        ▼
                    [协调者][[ ←── 汇总结果
                        │
                        ▼
                       END
```
