## 一、方法的定义

**方法（method）** 是一段可以被调用的代码块：接收若干输入，执行一段逻辑，返回一个结果。

```java
public class MethodDemo {

    // 完整结构：[访问修饰符] [static] 返回类型 方法名(参数列表) { 方法体 }
    public static int add(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        int sum = add(2, 3);      // 调用：写方法名和实参
        System.out.println(sum); // 5
    }
}
```

| 部分 | 说明 |
|------|------|
| **访问修饰符** | 决定谁能看到、谁能调用这个方法 |
| **返回类型** | 方法产出的结果的类型；没有结果写 `void` |
| **方法名** | 标识符，习惯用小驼峰 |
| **参数列表** | 形参（方法内部的变量名）+ 类型，可以为空 `()` |
| **方法体** | 真正执行的代码，用 `{}` 包起来 |

⚠️ **Java 里方法不能写在类外面**（这一点和 Python 不同）。所有方法必须属于某个类。

### 1.1 访问修饰符

| 修饰符 | 同类 | 同包 | 子类（其他包） | 任意类 |
|--------|------|------|--------------|--------|
| `private` | ✅ | ❌ | ❌ | ❌ |
| 无修饰符（**包私有**） | ✅ | ✅ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| `public` | ✅ | ✅ | ✅ | ✅ |

**包（package）** 是 Java 的代码组织单位，对应目录结构。`package com.example.demo;` 声明的类属于 `com.example.demo` 这个包，同包内互相可见包私有成员。

⚠️ **实践建议**：类里的方法默认给 `private`，只在确实需要外部调用时放宽到 `public`；工具类的纯函数方法常写成 `public static`。

### 1.2 返回值与 return

```java
public static int max(int a, int b) {
    if (a > b) {
        return a;        // 返回结果并立刻结束方法
    }
    return b;
}
```

- `return 值;`——把值交给调用方，并**终止**当前方法；
- `void` 方法可以用 `return;` 单独退出（后面不能跟值）；
- `void` 方法**不能**写 `return 值;`；
- **有返回类型的方法，所有路径都必须有返回值**——漏写一条路径会编译报错：

```java
public static int f(boolean flag) {
    if (flag) {
        return 1;
    }
    // ⚠️ 编译报错：missing return statement
}
```

⚠️ `return` 只让方法结束，**不会结束调用方**：

```java
public static void check(boolean ok) {
    if (!ok) {
        return;              // 只是自己提前退出
    }
    System.out.println("继续执行");
}

check(false);
System.out.println("调用方照常往下走");   // ✅ 这行照样打印
```

### 1.3 方法重载（overload）

**重载**指在**同一个类里**定义多个**名字相同、参数列表不同**的方法。

```java
public class OverloadDemo {

    public static int add(int a, int b) {          // 参数个数不同
        return a + b;
    }

    public static double add(double a, double b) { // 参数类型不同
        return a + b;
    }

    public static String add(String a, String b) { // 参数顺序/类型不同
        return a + b;
    }

    public static int add(int a, int b, int c) {   // 参数个数又不同
        return a + b + c;
    }
}
```

判定重载的依据只有一个：**参数列表（parameter list）**。参数列表由「参数的个数、类型、顺序」决定，**与返回类型无关，与参数名无关**。

⚠️ **只改返回类型不算重载，会编译报错**：

```java
public static int get(int x) { return x; }
public static String get(int x) { return "x"; }   // ❌ 编译报错：方法 get(int) 已被定义
```

因为调用方 `get(1)` 根本不知道该选哪个——**只看参数无法定位到唯一的方法**。

⚠️ 与之对比，**方法重写（override）**是父子类之间的「同签名覆盖」，见第 4 节。重载是「编译期多态」（静态绑定），重写是「运行期多态」（动态绑定）。

## 二、⭐ 参数传递：Java 一律是值传递

这是本章最重要、也是面试最高频的机制点。先给结论：

> ⭐ **Java 的参数传递方式只有一种：值传递（pass-by-value）。**
> 传对象时，传过去的是「**引用的副本**」——副本和原件指向**同一个对象**，但副本本身只是栈上的另一个地址值。

### 2.1 一段代码讲透

```java
public class PassByValueDemo {

    // 一个可变的"盒子"，用来观察对象内容变化
    static class Box {
        String name;
        Box(String name) { this.name = name; }
    }

    // 情况一：基本类型传参
    static void changeInt(int x) {
        x = 999;                  // 改的是形参这个副本
    }

    // 情况二：对象传参 —— 改对象的内容
    static void changeContent(Box b) {
        b.name = "改过了";          // ✅ 生效：b 和原变量指向同一个对象
    }

    // 情况三：对象传参 —— 换引用
    static void changeRef(Box b) {
        b = new Box("全新的盒子");   // ❌ 不生效：只改了副本里的地址
    }

    public static void main(String[] args) {
        int i = 1;
        changeInt(i);
        System.out.println(i);         // 1  —— 原变量毫发无损

        Box box = new Box("原来的");
        changeContent(box);
        System.out.println(box.name);  // 改过了  ✅ 内容变了

        Box box2 = new Box("原来的");
        changeRef(box2);
        System.out.println(box2.name); // 原来的  ❌ 引用没换
    }
}
```

### 2.2 为什么？看内存图

```text
调用方 main 的栈帧                被调方法的栈帧
┌──────────────────────┐        ┌──────────────────────┐
│ box = 0x1000         │        │ b = 0x1000           │  ← 复制了地址值
│  （指向堆里的 Box）    │        │  （副本，但地址相同）  │
└──────────┬───────────┘        └──────────┬───────────┘
           │                               │
           └───────────────┬───────────────┘
                           ▼
                ┌──────────────────────┐
                │ 堆上的 Box 对象       │
                │  name = "改过了"       │  ← 两个副本指向同一个对象
                │  地址 = 0x1000        │     所以改内容，双方都看得到
                └──────────────────────┘
```

⭐ **一句话记住**：

| 操作 | 生效吗 | 为什么 |
|------|-------|--------|
| 改基本类型的值 | ❌ | 改的是栈上副本的值 |
| 改对象**内部状态**（字段、集合元素） | ✅ | 副本和原件指向同一对象 |
| 把引用**换成另一个对象** | ❌ | 只改了副本里的地址值 |
| 改数组里的元素 | ✅ | 数组是对象，元素在对象里 |
| 改 `String` 的内容 | ❌ | `String` 不可变（见 [[java/01-入门阶段-基础教程/第01章-核心语法/1.4-字符串与包装类]]） |

### 2.3 三个常见衍生问题

**问题一：那 Java 到底有没有「引用传递」？**

严格说**没有**。很多书说「Java 对对象是引用传递」，那是**不严谨的说法**。准确的说法是：**Java 永远是值传递，只不过当被传的值本身是一个引用（地址）时，传过去的是这个地址的副本。**

**问题二：那 C++ 的引用传递（`void f(int& x)`）怎么在 Java 里模拟？**

模拟不了，也不需要——因为 Java 的引用本身就是对象地址，效果已经达到了。真要「换引用并让调用方看到」，唯一的办法是**返回新对象**：

```java
static Box changeRefAndReturn(Box b) {
    b = new Box("全新的盒子");
    return b;              // ✅ 通过返回值把新引用交出去
}

Box b = changeRefAndReturn(box);   // 调用方必须接收返回值
```

⭐ **这就是 Java 的设计取向**：没有「多个返回值」也没有「输出参数」，一切通过返回值传递。Java 也没有 Python 那种「函数修改调用方的变量」的效果（Python 的参数绑定也是引用绑定，但**重新赋值**同样不会影响调用方）。

**问题三：数组作为参数呢？**

数组是对象，所以元素修改会生效，但「换数组」不会：

```java
static void modifyArray(int[] arr) {
    arr[0] = 100;        // ✅ 生效：改的是数组对象的内容
    arr = new int[5];    // ❌ 不生效：换引用而已
}
```

## 三、可变参数 varargs

**可变参数（variable arguments，varargs）** 让方法接受「数量不定」的同类型参数，写法是在类型后面加三个点 `...`：

```java
public class VarargsDemo {

    static int sum(int... nums) {      // nums 的类型其实是 int[]
        int total = 0;
        for (int n : nums) {
            total += n;
        }
        return total;
    }

    public static void main(String[] args) {
        System.out.println(sum());                 // 0
        System.out.println(sum(1));                // 1
        System.out.println(sum(1, 2, 3));          // 6
        System.out.println(sum(new int[]{1, 2}));  // 3 —— 数组可以直接传
    }
}
```

规则与要点：

| 要点 | 说明 |
|------|------|
| **本质是数组** | `int... nums` 完全等价于 `int[] nums`，方法体里可以 `nums.length`、`nums[0]` |
| **只能放最后** | 一个方法最多有一个可变参数，且必须在参数列表末尾 |
| **可传零个** | `sum()` 合法，此时 `nums` 是长度为 0 的数组 |
| **调用时的歧义** | `sum()` 既能匹配 `sum(int...)` 也可能匹配 `sum(int)`——有重载时有歧义风险 |
| **不能和数组参数重载** | `sum(int[])` 与 `sum(int...)` 编译期签名相同，不能共存 |

⚠️ **调用 `println` 的重载陷阱**：

```java
System.out.println("x");      // ✅ 走 println(String)
System.out.println(1);         // ✅ 走 println(int)
System.out.println(1.0);       // ✅ 走 println(double)
```

`println` 有几十个重载版本，全靠编译器按实参类型挑一个。这也是为什么 `System.out.println('a')` 能打印出字符而不是数字——`char` 有专属重载。

⚠️ **可变参数和泛型不能同时用**：`List<String>...` 是非法的（`List` 是集合接口，`<String>` 是泛型写法「这个集合里放 `String`」，详见第 04 章的集合部分）——因为 Java 运行时无法为泛型数组创建安全的数组类型。

## 四、方法重写（override）

**重写**指子类对父类某个方法的重新实现（前提是父类方法可被重写）。这是「多态」的机制基础，第 02 章会展开讲继承与多态，这里先把规则记牢。

```java
class Animal {
    public String speak() {          // 父类方法
        return "...";
    }
}

class Dog extends Animal {
    @Override                          // 编译器帮你检查：真的重写了吗
    public String speak() {
        return "汪！";
    }
}
```

### 4.1 重写的 5 条规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **方法名必须相同、参数列表必须相同** | 否则是**重载**，不是重写 |
| 2 | **返回类型必须相同或是「协变」的** | 协变 = 子类返回父类返回类型的**子类型**（如父返回 `Object`、子返回 `String`）；`void` 不能被重写成有返回值 |
| 3 | **访问权限不能变得更严格** | 父类 `public` → 子类不能变 `protected`/`private`；父类 `protected` → 子类可以变 `public` |
| 4 | **受检异常的范围不能扩大** | 父类抛 `IOException`（受检的输入输出异常），子类不能抛 `SQLException`（受检的数据库异常）——可以抛 `IOException` 或其子类，或干脆不抛。受检异常见 [[java/01-入门阶段-基础教程/第03章-异常处理/3.1-异常体系与分类]] |
| 5 | **`private` / `final` / `static` 的方法不能被重写** | 见下表 |

| 父类方法形态 | 能否重写 | 原因 |
|-------------|---------|------|
| `public` | ✅ | |
| `protected` | ✅ | |
| 包私有（无修饰符） | ⚠️ 仅限**同一个包**内才能重写 | 跨包时这个方法「不可见」，子类看不到它 |
| `private` | ❌ | 子类根本看不到这个方法，谈不上覆盖 |
| `final` | ❌ | 明确禁止被覆盖 |
| `static` | ❌ | 静态方法属于**类**，不是对象；子类同名静态方法只是「隐藏（hiding）」，不是重写 |

⚠️ **`static` 方法不存在多态**：

```java
class Parent { static void hello() { System.out.println("父"); } }
class Child  extends Parent { static void hello() { System.out.println("子"); } }

Parent p = new Child();
p.hello();      // 输出「父」——静态方法在编译期按声明类型绑定
```

⚠️ **`private` 方法「看起来像」重写，其实不是**：

```java
class A { private void work() { System.out.println("A.work"); } }
class B extends A { public void work() { System.out.println("B.work"); } }  // ⚠️ 不是重写，是新方法
```

父类的 `work` 是 `private` 的，B 里的 `work` 是一个**全新的方法**。用 `A` 类型引用调用时，调的还是 A 的那个。

### 4.2 `@Override` 注解有什么用

`@Override` 是**可选的**（编译器不强制），但**强烈建议写**：

1. **让编译器帮你校验**：签名写错了立刻报错，而不是变成「重载」或「新方法」；
2. **可读性**：读代码的人一眼知道这是重写；
3. **重构保护**：将来父类方法改名，编译器立刻提示你这里也要改。

## 五、递归

**递归（recursion）** 是方法自己调用自己。

```java
public class RecursionDemo {

    // 阶乘：n! = n × (n-1)!
    static long factorial(int n) {
        if (n <= 1) {                 // ⚠️ 必须有终止条件（base case）
            return 1;
        }
        return n * factorial(n - 1);   // 递归调用自己
    }

    public static void main(String[] args) {
        System.out.println(factorial(5));   // 120
    }
}
```

递归的三要素：

1. **终止条件**——什么情况下不再递归；
2. **递归状态**——问题规模如何缩小（这里是 `n` 减 1）；
3. **递归出口**——把子问题的结果组合成当前结果。

### 5.1 栈溢出

⚠️ **递归太深会抛 `StackOverflowError`**（这是一个 `Error`，不是 `Exception`，属于 JVM 层面的致命错误）：

```java
static int boom(int n) {
    return boom(n + 1);      // ❌ 永远不终止
}

boom(1);   // java.lang.StackOverflowError
```

**原因**：每次方法调用都会在**调用栈（call stack）**上压入一个栈帧（stack frame），里面存着参数、局部变量、返回地址。栈空间有限，递归层数太深就把栈压爆了。

默认栈大小通常在几百 KB 到 1 MB 量级，对应**几千层**递归——比想象中少。

### 5.2 递归改迭代

大多数递归都能改写成循环，**性能更好**（省掉栈帧开销）、**不会栈溢出**：

```java
// 递归版
static long factorialRec(int n) {
    return n <= 1 ? 1 : n * factorialRec(n - 1);
}

// 迭代版
static long factorialIter(int n) {
    long result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

⭐ **什么时候该保留递归**：问题的结构本身就是递归的（树、图、分治），而且递归能显著提升可读性（详见第 02 章与第 04 章的树/图遍历场景）。**判断标准**：能用循环写清楚就写循环，写不清楚再考虑递归。

⚠️ **注意尾递归**：Java **不会**做尾递归优化——就算方法最后一行就是递归调用，JVM 也不会复用栈帧。所以 Python 里能写爆栈的递归深度，Java 一样会爆。

## 六、静态方法 vs 实例方法

| 维度 | 静态方法 `static` | 实例方法 |
|------|------------------|---------|
| 属于谁 | 属于**类**（一份，全类共享） | 属于**对象**（每个对象一份） |
| 怎么调用 | `ClassName.method()` | `obj.method()` |
| 能不能用 `this` | ❌ **不能**（没有当前对象） | ✅ 能 |
| 能不能用 `super` | ❌ 不能 | ✅ 能 |
| 能不能直接访问实例成员 | ❌ 不能（必须自己 new 一个对象） | ✅ 能 |
| 能不能访问静态成员 | ✅ 能 | ✅ 能 |
| 能不能被继承 | 能（但只能被**隐藏**，不是重写） | 能（能重写） |
| 生命周期 | 类加载后一直在（直到类被卸载） | 跟随对象 |

```java
public class StaticVsInstance {

    static int counter = 0;          // 静态字段：全类共享
    int id;                          // 实例字段：每个对象一份

    static void staticMethod() {
        counter++;                   // ✅ 能访问静态成员
        // this.id = 1;             // ❌ 编译报错：静态上下文不能引用 this
        // System.out.println(id);  // ❌ 编译报错：不能直接访问实例成员
    }

    void instanceMethod() {
        counter++;                   // ✅ 能访问静态成员
        System.out.println(id);      // ✅ 能访问实例成员
        staticMethod();              // ✅ 可以调用静态方法
    }
}
```

⚠️ **静态方法里 `this` 报错**的原因：`this` 代表「当前对象」，而静态方法可能是在**一个对象都不存在**的情况下被调用的（比如 `StaticVsInstance.staticMethod()` 直接用类名调），根本没有「当前对象」可言。

⚠️ **别把方法设成 static 只因为「它没用到成员变量」**——这会失去多态能力：子类想重写父类的这个方法时，如果父类是 static，子类就永远覆盖不了它（只能隐藏）。这是继承体系里的常见设计错误。

## 七、与 Python 的对照

| 场景 | Python | Java |
|------|--------|------|
| 方法定义 | 缩进，无返回类型 | `返回类型 方法名(参数) { }` |
| 默认返回 | 无返回值就是 `None` | 必须写 `void` |
| 方法归属 | 可以写在模块顶层（不在类里） | **必须**写在类里 |
| `self` | 显式第一个参数 | **隐式**的 `this`，不写在参数列表 |
| 静态方法 | `@staticmethod` 装饰器 | `static` 关键字 |
| 类方法 | `@classmethod` | 暂无完全对应（工厂方法模式近似） |
| 重载 | ❌ 不支持，靠默认参数/可变参数模拟 | ✅ 原生支持 |
| 关键字参数 | ✅ `f(a=1)` | ❌ 不支持 |
| 默认参数 | ✅ `def f(a=1)` | ❌ 不支持（用重载或可变参数模拟） |
| 参数传递 | 引用绑定（但重新赋值不影响调用方） | **一律值传递** |
| 方法内修改列表 | ✅ 生效（同一个列表对象） | ✅ 生效（同样是同一个对象） |
| 方法内重新赋值 | ❌ 调用方看不到 | ❌ 调用方看不到（原因不同） |
| 递归 | ✅ 同样会 `RecursionError` | ✅ 同样会 `StackOverflowError` |

```python
# Python 的可变默认参数陷阱，Java 没有对应物
def f(items=[]):     # ⚠️ 这个列表会被所有调用共享
    items.append(1)
    return items
```

```java
// Java 想要「默认值」只能用重载或可变参数
static List<String> f() { return f(new ArrayList<>()); }        // 空列表版本
static List<String> f(List<String> items) { items.add("x"); return items; }  // 指定版本
```

⭐ **Java 里「默认参数」的标准解法是重载**——这是很多 Java 库 API 的通用套路。

---

## 陷阱

1. **⚠️ 以为「Java 对象是引用传递」**——**Java 一律是值传递**；传对象时传的是**引用的副本**，所以「改内容生效、换引用不生效」；
2. **⚠️ 只改返回类型来「重载」**——编译报错；重载只看**参数列表**；
3. **⚠️ 把重载当重写**——重载是**同类内**同名不同参数（编译期决定），重写是**父子类**同签名（运行期决定）；
4. **⚠️ 漏写 `return` 导致编译报错**——有返回值的方法所有路径都要返回；
5. **⚠️ `return` 以为会终止整个程序**——它只终止**当前方法**（想终止程序用 `System.exit()`）；
6. **⚠️ 以为 `private` / `final` / `static` 方法能被重写**——都不能；`private` 子类里的同名方法只是新方法，`static` 只是「隐藏」；
7. **⚠️ `static` 方法里用 `this`**——编译报错，静态方法没有「当前对象」；
8. **⚠️ 递归没有终止条件**——直接 `StackOverflowError`；而且 **Java 不做尾递归优化**，别指望深层递归能撑住；
9. **⚠️ 可变参数后面还有别的参数**——语法错误，可变参数必须在最后；
10. **⚠️ 同时定义 `f(int[])` 和 `f(int...)`**——编译期签名相同，不能共存；
11. **⚠️ 用可变参数 + 重载产生歧义**——`f()` 既匹配 `f(int...)` 也匹配 `f(int)` 时调用会有歧义；
12. **⚠️ 以为 `varargs` 能和泛型一起用**——`List<String>...` 非法；
13. **⚠️ 以为改 `String` 参数的内容能生效**——`String` 不可变，`s = "新值"` 只是改了副本（见 [[java/01-入门阶段-基础教程/第01章-核心语法/1.4-字符串与包装类]]）。

## 小结

- 方法结构：`[修饰符] [static] 返回类型 方法名(参数列表) { }`；方法必须在类里
- 5 个访问修饰符的可见范围：`private` < 包私有 < `protected` < `public`
- `return` 终止**当前方法**；有返回值的方法所有路径都要 return
- **重载**：同类、同名、**参数列表不同**；与返回类型无关，编译期决定
- ⭐ **参数传递一律是值传递**：改对象内容生效，换引用不生效；想让调用方看到新对象就**返回它**
- `varargs`（`int... nums`）本质是 `int[]`，只能放最后，可以传数组
- **重写**：同名同参、返回类型相同或协变、访问权限不能更严、受检异常不能扩大；`private`/`final`/`static` 不可重写
- **递归**：必须有终止条件，否则 `StackOverflowError`；Java **不做尾递归优化**，能用循环就用循环
- **静态方法**属于类、无 `this`、不能直接访问实例成员、不参与多态

## 练习

1. 写 `swap(int a, int b)` 和 `swap(Integer a, Integer b)` 两个方法，都**无法**交换调用方的变量——用打印结果验证「值传递」，并解释为什么。
2. 写一个 `Box` 类（含 `name` 字段）和三个方法：改内容的、改引用的、返回新引用的，用同一个对象依次调用，打印每一步后的状态，画出你的理解。
3. 用重载实现一个 `print` 方法的四个版本：`print(int)`、`print(double)`、`print(String)`、`print(int...)`，验证 `print(1)` 和 `print(1, 2)` 分别命中哪个。
4. 写一个递归版和迭代版的「求数组最大值」方法，各写一个把递归深度调到 100000 的版本，观察 `StackOverflowError`。
5. 定义 `Animal`（`speak()` 返回 `"..."`）和 `Dog`、`Cat` 两个子类，用 `@Override` 覆盖 `speak()`，用一个 `Animal` 类型的数组统一调用，体会多态。
6. 试着在子类里定义一个和父类 `private` 方法同名的方法，用 `@Override` 标注它，观察编译器报错——解释为什么它不算重写。
7. 写一个 `static int count` 字段的静态方法和一个实例方法，各自调用 3 次，打印 `count` 和实例字段的值，说明两者的生命周期差异。
