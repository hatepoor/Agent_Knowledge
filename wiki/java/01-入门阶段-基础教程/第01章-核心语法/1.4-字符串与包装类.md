## 一、String 是什么

`String` 是 Java 里表示**文本序列**的类。它属于**引用类型**，所以：变量可以是 `null`、可以用 `.` 调用方法、可以用 `==` 比引用。

```java
String s = "Hello";     // 字面量
String t = new String("Hello");  // 显式创建对象
```

两者内容相同，但 `s == t` 是 `false`（原因见第三节）。

### 1.1 不可变性：String 一旦创建就不能改

**不可变（immutable）** 指的是对象创建后**内部状态再也不会改变**。`String` 的所有「修改」方法，**都不会改动原对象**，而是**返回一个新对象**：

```java
String s = "hello";
String t = s.toUpperCase();

System.out.println(s);   // hello  ← 原对象没变
System.out.println(t);   // HELLO  ← 新的对象
```

```java
// 更直观的证据
String s = "abc";
s = s.toUpperCase();     // ⚠️ 看起来像"修改"，其实是把新引用赋回 s
System.out.println(s);   // ABC
```

⚠️ 注意 `s` 的类型始终是 `String`——`String` 不可变，所以不存在「往里塞一个字符」这回事。

### 1.2 为什么设计成不可变

三个理由，面试常问：

| 理由 | 说明 |
|------|------|
| **字符串常量池能工作** | 字面量 `"abc"` 被全局共享。如果 `String` 可变，任何一处修改都会污染所有引用处，池就废了 |
| **天然线程安全** | 多个线程共享同一个 `String` 不需要加锁——没人能改它 |
| **`hashCode` 可以缓存** | 不可变 ⟹ 内容不变 ⟹ `hashCode` 恒定 ⟹ 可以缓存起来。`HashMap` 的键性能因此极高 |

⚠️ 代价：**每次「修改」都是新建对象 + 拷贝内容**。所以循环里反复拼接是大忌（见第五节）。

## 二、字符串常量池与 intern()

**字符串常量池（string constant pool / intern pool）** 是 JVM 在**堆**中专门用来存放字符串字面量的区域。类加载时，源码里的字符串字面量会被放进池里。

```java
String a = "hello";     // 字面量 → 池中
String b = "hello";     // 字面量 → 池中已有，直接复用
String c = new String("hello");   // 强制在堆上新建一个对象（不在池里）

System.out.println(a == b);        // true   ← 同一个池对象
System.out.println(a == c);        // false  ← c 是新对象
System.out.println(a.equals(c));   // true   ← 内容相同
```

```text
a ──┐
    ├──▶ 池中的 "hello"（地址 0x1000）
b ──┘

c ─────▶ 堆上新建的 String 对象（地址 0x2000），内容也是 "hello"
```

⚠️ **`new String("hello")` 的意义是什么？** 几乎为零——它绕过常量池，制造一个内容相同但身份不同的对象，只会浪费内存。**实际代码里永远不要用 `new String(...)`，直接写字面量。**

### 2.1 intern()：把字符串拉回池里

**`intern()`** 是 `String` 的一个方法：返回**池中**与当前内容相等的那个字符串的引用；如果池里没有，就把它放进去再返回。

```java
String c = new String("hello");
String d = c.intern();          // 拉回池

System.out.println(c == d);     // false —— c 还是那个新对象
System.out.println(d == "hello");// true  —— d 指向池中对象
```

⚠️ **`intern()` 的实际用途主要是省内存**：当字符串来自数据库、文件、网络时（这些内容不在池里），用 `intern()` 后相同内容就只存一份。但要注意：

- `intern()` 返回的是**池中**的引用，**不会改变原变量**（还是值传递，见 [[java/01-入门阶段-基础教程/第01章-核心语法/1.3-方法与参数传递]]）；
- JDK 7 起常量池从「永久代」挪到了**堆**里，`intern()` 的行为和空间开销与老版本有差异；
- 滥用 `intern()` 会让池无限膨胀，反而成为内存泄漏源。

⚠️ **面试经典题**：

```java
String s1 = new String("abc");
String s2 = new String("abc");
System.out.println(s1 == s2);              // false
System.out.println(s1.equals(s2));         // true
System.out.println(s1 == s1.intern());      // true
System.out.println(s1.intern() == s2.intern()); // true
```

## 三、`==` vs `equals()` vs `hashCode()`

### 3.1 `==`：比引用

`==` 对引用类型比较的是**两个变量是否指向同一个对象**（地址相等）。

```java
String a = "hi";
String b = "hi";
a == b;        // true  —— 都在池里，是同一个对象
a.equals(b);   // true  —— 内容也相同
```

### 3.2 `equals()`：比内容

`equals()` 是 `Object` 类定义的方法，默认实现就是 `==`；`String` **重写（override）**了它，改成逐字符比较内容。

```java
String a = new String("hi");
String b = new String("hi");
a == b;        // false
a.equals(b);   // true
```

⚠️ **`equals()` 可以被写成 `null` 安全吗？** 不能直接写 `a.equals(b)`，因为 `a` 可能是 `null` → NPE。安全写法：

```java
// ✅ 顺序：先判可能为 null 的那个
Objects.equals(a, b)          // 推荐，null-safe
"hi".equals(a)                // 也安全：常量在前
a.equals(b)                   // ⚠️ a 为 null 时 NPE
```

（`Objects` 是 `java.util` 下的工具类，`Objects.equals` 就是 null-safe 的 `equals`。）

### 3.3 `hashCode()`：算哈希值

**`hashCode()`** 把对象内容映射成一个 `int` 哈希值。`String` 重写了它：内容相同 → 哈希值相同。

⭐ **必须记住的契约（equals 与 hashCode 的关系）**：

> **如果两个对象的 `equals()` 返回 `true`，那么它们的 `hashCode()` 必须相同。**
> 反过来不成立——哈希值相同的两个对象，`equals()` 可能返回 `false`（哈希碰撞）。

```java
String a = new String("hi");
String b = new String("hi");
System.out.println(a.equals(b));    // true
System.out.println(a.hashCode() == b.hashCode());   // true  ← 必须成立
```

**为什么要这个契约？** 因为 `HashMap`（键值对容器，底层靠哈希表）和 `HashSet`（去重集合，底层也是哈希表）内部**靠 `hashCode` 定位桶、再靠 `equals` 确认**。两个步骤都必须「一致」，才能保证「用 `HashMap` 存进去、用 `equals` 查得回来」（集合体系详见第 04 章）。

⚠️ **如果你重写了 `equals()`，就必须同时重写 `hashCode()`**，否则会出现这种诡异 bug：

```java
class Student {
    String id;
    Student(String id) { this.id = id; }

    @Override
    public boolean equals(Object o) {
        // instanceof 带变量（模式匹配，Java 16+）：一边判断类型，一边把对象赋给 s
        return o instanceof Student s && id.equals(s.id);
    }
    // ⚠️ 忘了重写 hashCode —— 用了默认的（按地址算）
}

Set<Student> set = new HashSet<>();   // Set 是「不重复元素」的集合接口，HashSet 是它的哈希实现
set.add(new Student("A"));
System.out.println(set.contains(new Student("A")));   // false ！
```

`HashSet` 用 `hashCode` 找桶、`equals` 比内容——两者不一致，就找不到。

## 四、StringBuilder vs StringBuffer

如果要**频繁拼接**字符串，需要一个**可变**的字符串工具。

| | `StringBuilder` | `StringBuffer` |
|---|---|---|
| 可变性 | 可变 | 可变 |
| **线程安全** | ❌ **不安全** | ✅ **安全**（方法都加 `synchronized`） |
| 性能 | 更快 | 慢一些（有同步开销） |
| 用在哪 | **绝大多数场景**（单线程内拼接） | 极少（多线程共享同一个 builder） |

```java
public class BuilderDemo {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder();
        sb.append("Hello").append(' ').append("World");   // append 返回 this，可链式调用
        System.out.println(sb);                 // Hello World
        System.out.println(sb.length());        // 11
        System.out.println(sb.charAt(0));       // H
        System.out.println(sb.indexOf("World")); // 6
        System.out.println(sb.substring(0, 5));  // Hello（左闭右开）

        sb.insert(0, ">> ");                     // >> Hello World
        sb.reverse();                            // dlroW olleH >>
        sb.deleteCharAt(0);                      // lroW olleH >>
        sb.replace(0, 5, "HELLO");               // ⚠️ StringBuilder 的 replace(int, int, String)：按位置替换
        System.out.println(sb);                  // HELLO olleH >>
        System.out.println(sb.indexOf("World")); // -1（找不到）
        sb.setLength(0);                         // 清空
        System.out.println(sb.isEmpty());        // true
    }
}
```

常用方法：`append`（追加，返回 `this` 所以能链式调用）、`insert`、`delete`、`deleteCharAt`、`replace(int, int, String)`、`reverse`、`charAt`、`indexOf`、`length`、`setLength`、`substring`。

⚠️ **`StringBuilder.replace` 只有「按位置替换」这一个重载**（`replace(int start, int end, String str)`），**没有** `replace(CharSequence, CharSequence)` 那种「按内容替换」的版本——那是 `String` 才有的。想要按内容替换，先 `toString().replace(...)` 或用 `String` 自己拼。

### 4.1 ⚠️ 循环里 `+=` 的性能陷阱

```java
// ❌ 慢：每次循环都新建一个 String，拷贝前面的全部内容
String result = "";
for (int i = 0; i < 100000; i++) {
    result += "a";          // 复杂度 O(n²)
}

// ✅ 快：只在一个对象上追加
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 100000; i++) {
    sb.append("a");
}
String fast = sb.toString();   // 最后再转成 String
```

⚠️ **为什么 `+=` 慢**：`result += "a"` 每次都执行「新建一个更长的字符串 + 拷贝旧内容 + 丢弃旧对象」。1 万次拼接意味着累计拷贝约 5000 万个字符。

⚠️ **单次拼接不需要 `StringBuilder`**——`String a = "x" + y + "z";` 只有一次拼接时，编译器会用 `StringConcatFactory`（Java 9+）优化，性能没问题。**只有循环里的反复拼接才必须用 `StringBuilder`。**

⚠️ **`StringBuffer` 在单线程里几乎不用**——它每个方法都加锁，纯粹是历史包袱（Java 1.0 就有，那时还没有 `StringBuilder`）。

## 五、常用 String API

| 方法 | 作用 | ⚠️ 边界与陷阱 |
|------|------|-------------|
| `length()` | 字符个数（不是字节数） | 汉字算 1，`char` 数量 |
| `charAt(int i)` | 取第 i 个字符 | ⚠️ 下标越界抛 `StringIndexOutOfBoundsException`；没有 Python 的负索引 |
| `substring(int a)` | 从 a 到末尾 | |
| `substring(int a, int b)` | 取 `[a, b)` | ⚠️ **左闭右开**，b 不包含在内；`"hello".substring(0,2)` 是 `"he"` |
| `indexOf(String s)` | 首次出现的下标 | 找不到返回 `-1` |
| `lastIndexOf(String s)` | 最后一次出现的下标 | |
| `contains(CharSequence s)` | 是否包含 | 返回 `boolean` |
| `startsWith` / `endsWith` | 前/后缀判断 | |
| `replace(char, char)` / `replace(CharSequence, CharSequence)` | 替换 | ⚠️ 返回**新对象**，不改原串 |
| `split(String regex)` | 按正则切分 | ⚠️ **参数是正则表达式**，不是普通字符串；`"a,b".split(",")` ✅ 但 `"a.b".split(".")` 会得到空数组（`.` 匹配任意字符）；⚠️ 结果**不含尾部空字符串** |
| `trim()` | 去掉两端空白 | ⚠️ 只去 **ASCII 空格**（`<= ' '`），不去全角空格和其他 Unicode 空白 |
| `strip()` | 去掉两端空白 | ✅ **Java 11+**，按 `Character.isWhitespace` 判断，能处理全角空格等 Unicode 空白；`stripLeading()` / `stripTrailing()` 同版本 |
| `isBlank()` | 是否为空或只含空白 | ✅ **Java 11+**；`"".isBlank()` 和 `"   ".isBlank()` 都是 `true` |
| `isEmpty()` | 长度是否为 0 | 只有 `""` 是 `true`，`"   "` 是 `false` |
| `toUpperCase()` / `toLowerCase()` | 大小写转换 | 用 `Locale.ROOT`（`java.util.Locale` 表示「地区/语言」的常量类，`ROOT` 表示不绑定任何地区）可避免土耳其语 I 问题 |
| `equals` / `equalsIgnoreCase` | 内容比较 | `equalsIgnoreCase` 忽略大小写 |
| `hashCode()` | 内容哈希 | 与 `equals` 契约配套 |
| `concat(String s)` | 拼接 | 只接受 `String`，不像 `+` 能拼任意类型 |
| `chars()` | 返回字符的 `IntStream` | ✅ **Java 8+**；用于流式处理：`s.chars().mapToObj(c -> (char) c).forEach(...)` |
| `formatted(Object... args)` | 格式化字符串 | ✅ **Java 15+**；`"%s-%d".formatted("a", 1)` |
| `repeat(int count)` | 重复若干次 | ✅ **Java 11+**；`"ab".repeat(3)` → `"ababab"` |
| `valueOf(...)` | 任意类型转字符串 | `String.valueOf(123)` |

⚠️ **`split` 的两个坑**（面试常问）：

```java
"a,b,c".split(",");            // ["a", "b", "c"]
"a,b,,".split(",");            // ["a", "b"]  ⚠️ 尾部空串被丢弃
"a,b,,".split(",", -1);        // ["a", "b", "", ""]  ✅ 第二个参数 limit=-1 保留尾部空串
"a.b".split(".");              // []  ⚠️ "." 是正则元字符，匹配任意字符
"a.b".split("\\.");            // ["a", "b"]  ✅ 正则里的点要转义
```

⚠️ **需要 `null` 安全时用 `Objects.toString(obj, "默认值")`**，别用 `String.valueOf(obj)`（后者对 `null` 返回 `"null"` 字符串，容易掩盖问题）。

## 六、包装类

### 6.1 为什么需要包装类

Java 的 8 种基本类型**不是对象**，不能当泛型参数、不能放进集合、不能调方法。为了让它们能和对象世界打交道，Java 提供了对应的**包装类（wrapper class）**：

| 基本类型 | 包装类 | 所在包 |
|---------|--------|--------|
| `byte` | `Byte` | `java.lang` |
| `short` | `Short` | `java.lang` |
| `int` | **`Integer`** | `java.lang` |
| `long` | **`Long`** | `java.lang` |
| `float` | `Float` | `java.lang` |
| `double` | **`Double`** | `java.lang` |
| `char` | **`Character`** | `java.lang` |
| `boolean` | **`Boolean`** | `java.lang` |

⭐ 这些类都在 `java.lang` 包里，**不需要 import**。

包装类比基本类型多了一些能力：可以比较大小（`compareTo`）、可以转成字符串（`parseInt`、`valueOf`）、可以作为泛型参数、可以作为集合元素。

### 6.2 自动装箱与拆箱

**自动装箱（autoboxing）**：把基本类型自动转成对应的包装类对象。
**自动拆箱（unboxing）**：把包装类对象自动转回基本类型。

```java
Integer a = 10;         // 自动装箱：int → Integer
int b = a;               // 自动拆箱：Integer → int

List<Integer> list = new ArrayList<>();   // 集合里存的必须是对象，所以要装箱
list.add(10);           // 自动装箱
int first = list.get(0);// 自动拆箱
```

⚠️ **自动拆箱的 NPE 陷阱**：

```java
Integer maybeNull = null;
int value = maybeNull;      // ⚠️ 自动拆箱 null → NullPointerException！

System.out.println(maybeNull + 1);   // ⚠️ 同样 NPE（因为 + 会触发拆箱）
System.out.println(maybeNull);       // ✅ 打印 "null"（不走拆箱路径）
```

⚠️ **拆箱 NPE 的两种触发路径**：

```java
Map<String, Integer> map = new HashMap<>();   // 键 → 值 的映射表
int v = map.get("missing");    // ⚠️ get 返回 null → 拆箱 → NPE
int v2 = map.getOrDefault("missing", 0);   // ✅ 安全：没有这个键就返回默认值 0
```

```java
// 经典 bug：两个 Integer 相比较发生拆箱
Integer a = null;
Integer b = 1;
if (a == b) { ... }             // ⚠️ 这里会拆箱 a → NPE
```

⭐ **判断 `Integer` 是否为 null 要用 `!= null`，而不是拆箱比较**。

### 6.3 Integer 缓存：-128 ~ 127

JVM 会把 **`-128` 到 `127`** 之间的小 `Integer` 对象**缓存**起来——这些值被包装时，直接复用缓存里的对象，不新建。

```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b);     // true  ← 同一个缓存对象

Integer c = 128;
Integer d = 128;
System.out.println(c == d);     // false ⚠️ 超出缓存范围，是两个不同对象
System.out.println(c.equals(d));// true  ← 内容相同
```

⭐ **这个缓存范围可以用启动参数 `-XX:AutoBoxCacheMax=<size>` 调整**（上限 20000 左右），但默认就是 -128~127。

⚠️ **所以 `Integer` 用 `==` 比较是不可靠的**——值在缓存范围内碰巧 `true`，超范围就 `false`。**永远用 `equals()` 或 `.intValue()` 比较数值。**

⚠️ **同理，`Long` 也有 -128~127 的缓存**，但 `Double`、`Boolean` 的缓存规则不同（`Boolean` 缓存 `TRUE`/`FALSE` 两个实例，`Double` 不缓存）。

## 七、BigDecimal：算钱必须用它

### 7.1 double 的精度问题

`double` 是**二进制浮点数**，用 64 位表示一个实数。**十进制小数无法被精确表示**——这和 Python 的 `float` 是同一个问题。

```java
double a = 0.1 + 0.2;
System.out.println(a);                  // 0.30000000000000004  ⚠️
System.out.println(a == 0.3);           // false  ⚠️

float b = 0.1f + 0.2f;
System.out.println(b);                  // 0.30000004  ⚠️ 更糟
```

原因：`0.1` 在二进制里是无限循环小数 `0.0001100110011...`，只能截断存储。

⚠️ **金额绝不能用 `double` 或 `float`**——0.1 + 0.2 不等于 0.3 这种事，在对账时就是资损事故。

### 7.2 BigDecimal：十进制高精度

`BigDecimal` 用**十进制**表示数字，并用 `BigInteger` 保存有效数字部分，所以能**精确**表示 `0.1`。

```java
import java.math.BigDecimal;   // BigDecimal / RoundingMode 都在 java.math 包

BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
BigDecimal sum = a.add(b);
System.out.println(sum);            // 0.3  ✅ 精确
System.out.println(sum.equals(new BigDecimal("0.3")));   // true
```

⭐ **关键：一定要用 `String` 构造！**

```java
new BigDecimal("0.1");     // ✅ 精确表示 0.1
new BigDecimal(0.1);       // ❌ 传进来的是 double 的近似值 0.1000000000000000055511151231257827...
```

**`new BigDecimal(double)` 会把 double 的二进制近似值原样转成十进制**，等于把误差固化了下来。这是 BigDecimal 最隐蔽的坑。

常用 API：

| 方法 | 作用 |
|------|------|
| `add(BigDecimal)` | 加 |
| `subtract(BigDecimal)` | 减 |
| `multiply(BigDecimal)` | 乘 |
| `divide(BigDecimal)` | 除 |
| `divide(BigDecimal, int scale, RoundingMode mode)` | 除并指定精度与舍入方式 |
| `compareTo(BigDecimal)` | 比较（只比数值） |
| `equals(Object)` | 比较（比数值 **和标度 scale**） |
| `scale()` | 小数位数 |
| `setScale(int, RoundingMode)` | 设置精度并舍入 |
| `valueOf(double)` | 从 double 创建（走 `Double.toString`，比 `new BigDecimal(double)` 好，但仍不如直接传字符串） |
| `toPlainString()` | 转成不带科学计数法的字符串 |

### 7.3 ⚠️ compareTo vs equals 的差异

这是 BigDecimal 的第二大坑：

```java
BigDecimal x = new BigDecimal("1.0");
BigDecimal y = new BigDecimal("1.00");

System.out.println(x.compareTo(y));     // 0   ← 数值相等
System.out.println(x.equals(y));        // false ⚠️ scale 不同！
```

**原因**：`equals()` 要求**数值相同且标度（scale，即小数位数）相同**；`compareTo()` 只比较数值。

```text
1.0  → 有效数字 10，scale = 1
1.00 → 有效数字 100，scale = 2
```

⚠️ **所以 BigDecimal 做「是否相等」判断时要用 `compareTo() == 0`，不能用 `equals()`**。而做「放入 HashSet / HashMap 的 key」时，`equals` 的严格性反而是想要的（`1.0` 和 `1.00` 应该当两个不同的 key）。

### 7.4 ⚠️ divide 的除不尽异常

```java
BigDecimal a = new BigDecimal("1");
BigDecimal b = new BigDecimal("3");
a.divide(b);      // ⚠️ 抛 ArithmeticException: Non-terminating decimal expansion
```

因为 `1/3 = 0.333...` 是无限小数，无法精确表示。必须显式给出**精度和舍入模式**：

```java
BigDecimal result = a.divide(b, 2, RoundingMode.HALF_UP);   // 0.33
```

**舍入模式（`RoundingMode`）** 常用几个：

| 模式 | 含义 |
|------|------|
| `HALF_UP` | 四舍五入（最常用） |
| `HALF_EVEN` | 银行家舍入（中点取偶），会计场景常用 |
| `DOWN` | 直接截断 |
| `UP` | 向上进位 |
| `CEILING` | 正数向上、负数向零 |
| `FLOOR` | 正数向零、负数向下 |

⚠️ **`add` / `subtract` / `multiply` 不会抛异常**（结果永远是有限的十进制数），只有 `divide` 会。

## 八、Optional 概览

**`Optional<T>`**（`java.util` 包）是一个**容器**，专门用来表达「**这个值可能没有**」。

```java
import java.util.Optional;   // 可选：需要 import

Optional<String> name = Optional.of("张三");            // 一定非空
Optional<String> empty = Optional.empty();              // 一定为空
Optional<String> maybe = Optional.ofNullable(getName());// 可能为空
```

| 方法 | 作用 |
|------|------|
| `of(T)` | 包装一个**非 null** 值；传 null 立刻抛 NPE |
| `ofNullable(T)` | 包装，可能为 null |
| `empty()` | 空容器 |
| `isPresent()` | 是否有值 |
| `isEmpty()` | 是否无值（**Java 11+**） |
| `get()` | 取值；**没值时抛 `NoSuchElementException`** |
| `orElse(T other)` | 有值取它，没值返回**默认值**（无论有没有值，这个默认值都会被先算出来） |
| `orElseGet(Supplier)` | 没值时才调用工厂方法创建默认值（`Supplier` 是 `java.util.function` 下的「无参、有返回值」函数式接口，写作 `() -> 值`）（**默认值是昂贵的就用这个**） |
| `orElseThrow()` | 没值时抛异常 |

```java
String display = maybe.isPresent() ? maybe.get() : "匿名";

// 更简洁的写法
String display2 = maybe.orElse("匿名");
```

### 8.1 适用与不适用

| 场景 | 该不该用 | 理由 |
|------|---------|------|
| **方法返回值**可能为空 | ✅ **推荐** | 把「可能没有」写进签名，调用方被迫处理 |
| **方法参数** | ❌ **不要** | 会让每个调用方都得先包一层 `Optional.of(...)`，反而复杂 |
| **类的字段** | ❌ **不要** | 字段本来就能是 `null`；而且 `Optional` 本身**不可序列化**，很多框架（如某些 ORM、JSP 引擎）会出问题 |
| **集合元素** | ⚠️ 谨慎 | `List<Optional<String>>` 很难读，宁可允许集合里有 null |

⚠️ **`Optional` 不是「万能解药」**：

- 它**不是**用来「消灭所有 null」的——参数和字段里的 null 依然存在；
- `Optional.get()` 一定要先 `isPresent()` 检查，忘了就抛 `NoSuchElementException`（用 `orElse` / `orElseThrow` 更安全）；
- **`Optional` 的字段本身也可能是 `null`**（比如 `Optional<String> o = null;`），这会让代码更混乱。

⭐ **最佳实践**：把 `Optional` 当作**方法返回值的「可能为空」标记**用，配合 `orElse` / `map` / `filter` 让调用链优雅。

## 九、与 Python 的对照

| 概念 | Java | Python |
|------|------|--------|
| 字符串类型 | `String`（不可变类） | `str`（不可变） |
| 字符串操作 | `s.length()`（**方法**） | `len(s)`（**函数**） |
| 取字符 | `s.charAt(0)` | `s[0]` |
| 切片 | `s.substring(1, 3)`（**左闭右开**） | `s[1:3]`（左闭右开，一致） |
| 拼接 | `s + t` 或 `StringBuilder` | `s + t` 或 `''.join()` |
| 格式化 | `"%s".formatted(x)`（Java 15+）或 `String.format` | `f"{x}"` 或 `"%s" % x` |
| 查找 | `s.indexOf("x")` / `s.contains("x")` | `s.find("x")` / `"x" in s` |
| 分割 | `s.split(",")`（**是正则**） | `s.split(",")`（**不是正则**） |
| 去空白 | `s.strip()`（Java 11+，Unicode） | `s.strip()`（Python 3.9+，Unicode） |
| 整数 | `int`（**固定 32/64 位，会溢出**） | `int`（任意精度） |
| 小数 | `double`（二进制浮点，有误差） | `float`（二进制浮点，同样有误差） |
| 精确小数 | `BigDecimal` | `decimal.Decimal` |
| 空值 | `null` | `None` |
| 真假 | `true` / `false` | `True` / `False` |
| 可能为空 | `Optional<T>` | `Optional[T]`（类型标注用，不是运行时容器） |
| 字符串驻留 | `intern()` / 常量池 | Python 也有类似的驻留优化，但 API 不同 |

⚠️ **三处最容易踩的对照坑**：

1. **`s.length()` 是方法，`len(s)` 是函数**——Python 开发者写 Java 时最常犯的错；
2. **`split` 的参数语义不同**——Python 的 `split(",")` 按字面逗号切；Java 的 `split(",")` 按**正则**切，`.` `*` `+` `|` 等都要转义；
3. **Java 的 `int` 不会像 Python 那样自动变长**——从 Python 过来要时刻记得选 `long` 或 `BigDecimal`。

## 陷阱

1. **⚠️ 用 `==` 比较字符串**——`==` 比引用，内容比较必须 `equals()`；`new String("a") == "a"` 是 `false`；
2. **⚠️ 用 `==` 比较 `Integer`**——只有 -128~127 缓存范围内才碰巧为 `true`，永远用 `equals()` 或 `.intValue()`；
3. **⚠️ 以为 `String` 可变**——所有「修改」都返回新对象；改参数里的 `String` 也不生效（值传递 + 不可变，双重原因）；
4. **⚠️ 循环里用 `+=` 拼字符串**——O(n²)，改用 `StringBuilder`；
5. **⚠️ `new BigDecimal(0.1)`**——把 double 的近似误差固化了，必须用 `new BigDecimal("0.1")`；
6. **⚠️ 用 `BigDecimal.equals()` 判断数值相等**——`1.0` 和 `1.00` 不相等，要用 `compareTo() == 0`；
7. **⚠️ `BigDecimal.divide()` 忘了指定精度**——除不尽直接抛 `ArithmeticException`；
8. **⚠️ 自动拆箱触发 NPE**——`Integer x = null; int y = x;` 立刻 NPE；`map.get()` 返回 null 时同样中招；
9. **⚠️ 重写 `equals()` 忘了重写 `hashCode()`**——放进 `HashMap`/`HashSet` 后就找不回来了；
10. **⚠️ `split` 的参数是正则**——`"a.b".split(".")` 得到空数组，要写 `"\\."`；尾部空串默认被丢弃，要保留传 `-1`；
11. **⚠️ `trim()` 只去 ASCII 空格**——全角空格要去不掉，用 Java 11+ 的 `strip()`；
12. **⚠️ 用 `Optional` 做字段或参数**——会让代码层层包裹、框架兼容性变差；`Optional` 只该用于返回值；
13. **⚠️ `Optional.get()` 不先判空**——会抛 `NoSuchElementException`，优先用 `orElse` / `orElseGet` / `orElseThrow`；
14. **⚠️ 用 `String.valueOf(null)`**——得到字符串 `"null"`，容易掩盖问题，用 `Objects.toString(obj, "默认值")`。

## 小结

- `String` **不可变**：所有「修改」返回新对象；理由是常量池、线程安全、`hashCode` 可缓存
- **常量池**存放字面量；`new String("a")` 绕过池 → `==` 为 `false`；`intern()` 拉回池中
- `==` 比引用，`equals()` 比内容；**契约：equals 相等 ⇒ hashCode 相同**（重写 `equals` 必须重写 `hashCode`）
- `StringBuilder`（快、非线程安全）vs `StringBuffer`（慢、线程安全）；循环拼接必须用 `StringBuilder`
- 常用 API：`substring` 左闭右开、`split` 是正则、`trim` 只去 ASCII 空格、`strip`/`isBlank` 是 Java 11+、`formatted` Java 15+、`repeat` Java 11+、`chars` Java 8+
- 包装类：`Integer`/`Long`/`Double`/`Boolean`/`Character`；自动装箱拆箱；**拆箱 `null` 会 NPE**
- `Integer` 缓存 **-128~127**；超出范围 `==` 为 `false`
- 算钱用 **`BigDecimal`**，用 `String` 构造；`compareTo` vs `equals`；`divide` 要给精度和 `RoundingMode`
- `Optional` 只适合**返回值**，不适合字段和参数
