> **什么时候该读**：你看到别人代码里 `new Runnable() { ... }`、`list.forEach(item -> ...)`、`String::length` 这类写法想知道背后是什么；或者想把一段「只在一个方法里用一次」的逻辑从类里挪出来。

## 一、内部类：定义在另一个类内部的类

**内部类**（inner class）是定义在**另一个类的类体内部**的类。

```java
public class OuterIntro {
    // 成员内部类
    class Inner {
        void hello() { System.out.println("你好"); }
    }
}
```

内部类最大的特点：**它能直接访问外部类的所有成员，包括 `private` 私有的**。

```java
public class Counter {
    private int count = 0;

    public class Ticker {                 // 内部类
        void tick() {
            count++;                      // ✅ 直接访问外部类的 private 字段
        }
    }
}
```

⚠️ 内部类编译后其实是**独立的类文件**（`Outer$Inner.class`），只是在源码上「嵌套」在外部类里。

### 四种内部类对照表

| 形态 | 声明位置 | 持有外部类引用？ | 能否直接访问外部成员 | 典型用途 |
|------|---------|----------------|-------------------|---------|
| **成员内部类** | 类的成员位置 | ✅ **总是持有** | ✅ | 紧密绑定外部对象状态 |
| **静态内部类** | 类的成员位置 + `static` | ❌ **不持有** | ❌（要自己传对象进来） | 纯粹作为「外部类的命名空间」 |
| **局部内部类** | 方法体内部 | ✅ 持有 | ✅ | 只在某个方法里用的辅助逻辑 |
| **匿名内部类** | `new 接口() { ... }` | ✅ 持有 | ✅ | 一次性实现接口 |

### 成员内部类：隐式持有外部类引用

```java
public class Outer {
    private String name = "外部";

    class Inner {
        void print() {
            // ⭐ name 是外部类的字段，直接写就行，不用 Outer.this.name
            System.out.println(name);
        }
    }

    public static void main(String[] args) {
        Outer outer = new Outer();
        Outer.Inner inner = outer.new Inner();   // ⚠️ 创建成员内部类必须先有外部类实例
        inner.print();
    }
}
```

⚠️ **创建成员内部类对象要「先有外再有内」**：`outer.new Inner()`，不能直接 `new Inner()`。因为内部类对象需要知道「它属于哪个外部对象」。

⭐ **「隐式持有外部类引用」的含义**：每个 `Inner` 对象内部都存着一个指向它所属 `Outer` 对象的引用。这意味着——**外部对象只要还被内部对象引用着，外部对象就不会被 GC 回收**。这是 Java 里常见的「内存泄漏」来源之一。

### 静态内部类：不持有外部类引用

```java
public class OuterStatic {
    private static String shared = "静态的";

    static class Nested {                 // ⚠️ 必须加 static
        void print() {
            System.out.println(shared);   // ✅ 能访问静态成员
            // System.out.println(name);  // ❌ 不能访问外部类的实例成员
        }
    }
}
```

⭐ **静态内部类更像「一个独立的类，只是名字写在另一个类里面」**。创建时直接 `new Outer.Nested()`，不需要外部对象。

**什么时候用静态内部类**：当内部逻辑**跟外部对象的实例状态无关**时。写成静态内部类可以避免不必要的外部引用（内存泄漏风险更低），也能让编译器更自由地优化。

### 局部内部类：定义在方法里

```java
public class OuterLocal {
    public int calculate(int base) {
        // 局部内部类：只在 calculate 方法内有效
        class Adder {
            int add(int x) {
                return base + x;      // 捕获了外部方法的局部变量 base
            }
        }
        return new Adder().add(10);
    }
}
```

局部内部类的作用域**只限于那个方法**——出了方法就没法引用这个类型。

### 匿名内部类：一次性实现接口

**匿名内部类**（anonymous class）是在**创建对象的同时**就地写出的类，没有名字。

```java
Runnable task = new Runnable() {          // Runnable 是 JDK 自带接口
    @Override
    public void run() {
        System.out.println("我在跑");
    }
};
task.run();
```

⚠️ **花括号后面必须有分号**：`new Runnable() { ... };` —— 这是新手最常见的编译错误之一。

匿名内部类**只能实现一个接口**（或继承一个类），而且**必须实现全部抽象方法**。

## 二、内部类访问外部类成员 & 局部变量捕获

### 访问外部类成员

**规则**：内部类可以直接访问外部类的**所有**成员，包括 `private`（编译器为此生成了访问器）。反过来，外部类要访问内部类的成员，必须先有内部类实例：

```java
public class OuterPrivate {
    class Inner {
        private int value = 42;
    }

    void useInner() {
        OuterPrivate.Inner in = new OuterPrivate().new Inner();
        System.out.println(in.value);   // ⚠️ private，但同一个顶层类内部可以访问
    }
}
```

（Java 允许同一个顶层类里的类互相访问彼此的 `private` 成员——编译器为此生成了合成访问器。）

### ⚠️ 局部变量捕获必须是 effectively final

内部类可以捕获（capture）**外部方法**的局部变量，但那个变量必须是 **`effectively final`**（事实上不可变）的。

**`effectively final` 的定义**：变量**没有**被显式声明为 `final`，但**在初始化之后从未再被赋值**。

```java
public void demo() {
    int count = 10;         // 没有 final 关键字
    count = 20;             // ❌ 赋值了 → 不再 effectively final
    class Inner {
        void print() {
            System.out.println(count);   // ❌ 编译错误：局部变量 count 不是 effectively final
        }
    }
}
```

```java
public void demo() {
    final int count = 10;   // ✅ 显式 final
    class Inner {
        void print() {
            System.out.println(count);   // ✅ 可以
        }
    }
}
```

```java
public void demo() {
    int count = 10;         // ✅ 没有再赋值 → effectively final
    class Inner {
        void print() {
            System.out.println(count);   // ✅ 可以
        }
    }
}
```

### 为什么要求 effectively final？（讲清「为什么」）

⚠️ **这是本节最重要的部分。** 原因有两条：

**原因一：Java 8 之前根本做不到。** Java 8 之前内部类只能捕获 `final` 局部变量，限制太狠（循环里的变量、累加器全都捕获不了）。Java 8 放宽成「effectively final」——只要语义上没再改过，就允许捕获。

**原因二（真正的原因）：避免「捕获的变量和外部变量不一致」。**

```java
public void demo() {
    int count = 10;
    class Inner {
        void print() { System.out.println(count); }
    }
    Inner in = new Inner();
    count = 99;        // 如果允许这样写，in.print() 会打印 99 吗？
    in.print();
}
```

如果允许捕获后继续修改，语义就变得模糊了：

- 捕获时把值**拷贝**一份进去 → `in.print()` 打印 `10`，但外面 `count` 已经是 `99`，两个值不同步；
- 捕获的是**引用**（同一个变量） → 打印 `99`，但 `count` 是 `int`（基本类型），根本没有「引用」可捕获。

⭐ **关键结论**：Java 选择「**变量必须是 effectively final**」这条规则，是为了保证「**捕获的值 = 声明时看到的值 = 之后永远不变的值**」，语义唯一、没有歧义。

⚠️ **注意区分**：**实例字段**（`this.name`）不受此限制——内部类访问的是**对象的状态**，对象状态本来就会变。而**局部变量**是方法栈上的临时值，捕获它必须锁定。

### 增强 for 循环里的变量

```java
for (String name : names) {
    Runnable r = () -> System.out.println(name);   // ✅ 增强 for 的变量每次迭代是新变量
}
```

```java
for (int i = 0; i < 3; i++) {
    Runnable r = () -> System.out.println(i);   // ❌ i 被修改过，不是 effectively final
}
```

⚠️ 老式 `for (int i = 0; ...)` 里的 `i` 会被修改，所以捕获不了。**解法**：在循环体里复制一份 `final int j = i;` 再捕获 `j`。

## 三、函数式接口与 Lambda 表达式

### 函数式接口（Functional Interface）

**函数式接口**是「**只有一个抽象方法**」的接口。那个唯一的抽象方法叫 **SAM**（Single Abstract Method，单抽象方法）。

```java
@FunctionalInterface                      // 注解：告诉编译器"这是函数式接口"
public interface Calculator {
    int calculate(int a, int b);          // 唯一的抽象方法
}
```

⭐ **`@FunctionalInterface` 一定要写**。它让编译器帮你检查「是不是真的只有一个抽象方法」——如果不小心加了第二个抽象方法，编译报错。另外，从 Java 8 起，接口里的 `default` 方法和 `static` 方法**不算**抽象方法，所以函数式接口可以有它们。

### 常见内置函数式接口

`java.util.function` 包里提供了一整套现成的函数式接口：

| 接口 | 签名 | 语义 | 例子 |
|------|------|------|------|
| `Function<T, R>` | `R apply(T t)` | **有入有出**：输入 T，产出 R | `Function<String, Integer> len = String::length` |
| `Consumer<T>` | `void accept(T t)` | **只有入，没有出**：消费掉 | `Consumer<String> p = System.out::println` |
| `Supplier<T>` | `T get()` | **只有出，没有入**：生产 | `Supplier<List<String>> s = ArrayList::new` |
| `Predicate<T>` | `boolean test(T t)` | **判断**：返回真/假 | `Predicate<String> p = s -> s.isEmpty()` |
| `BiFunction<T, U, R>` | `R apply(T t, U u)` | 两个入，一个出 | `BiFunction<Integer,Integer,Integer> add = Integer::sum` |
| `BiConsumer<T, U>` | `void accept(T t, U u)` | 两个入，无出 | `BiConsumer<String,String> log = ...` |
| `UnaryOperator<T>` | `T apply(T t)` | 一入一出，**同类型** | `UnaryOperator<String> up = s -> s.toUpperCase()` |
| `BinaryOperator<T>` | `T apply(T a, T b)` | 两入一出，**同类型** | `BinaryOperator<Integer> max = Integer::max` |
| `Comparator<T>` | `int compare(T a, T b)` | 两个对象比较大小 | `Comparator<String> byLen = Comparator.comparingInt(String::length)` |

⚠️ **`Function` / `Consumer` / `Supplier` / `Predicate` 是"泛型"**——`<T, R>` 里的 `T` 是「输入类型」、`R` 是「输出类型」。泛型是后面的内容，这里先理解成「类型占位符」即可。

⚠️ **`Comparator` 在 `java.util` 包，不在 `java.util.function` 包**——它也是函数式接口（`compare` 是唯一抽象方法），但历史上被放在了 `java.util`。

### Lambda 表达式语法

**Lambda 表达式**是「**一段没有名字、但签名明确的函数**」的简写。

```
(参数列表) -> { 语句块 }
(参数列表) -> 表达式
```

```java
// 完整形式
Calculator add = (int a, int b) -> {
    int sum = a + b;
    return sum;
};

// 简写：单个表达式不需要大括号和 return
Calculator add2 = (a, b) -> a + b;      // ⭐ 最常见写法

// 无参数
Runnable r = () -> System.out.println("我什么参数都不要");

// 单参数可以省略括号
Consumer<String> printer = s -> System.out.println(s);
```

> 上面的 `Consumer` 是 JDK 自带的函数式接口（`java.util.function.Consumer`），`Runnable` 是 `java.lang.Runnable`。用的时候记得 `import java.util.function.Consumer;` 或用全限定名 `java.util.function.Consumer`。

### 类型推断（Type Inference）

Lambda 的参数类型**不用写**——编译器根据「赋值给哪个函数式接口」自动推断。

```java
Function<String, Integer> len = s -> s.length();     // s 自动推断为 String
```

⚠️ **这也意味着 Lambda 只能用在「目标类型已知」的位置**：

```java
// ❌ 编译错误：不知道该用哪个函数式接口
var f = x -> x + 1;
```

⚠️ **变量名遮蔽**：Lambda 参数名如果和外层局部变量同名，**不允许**（Java 禁止 Lambda 参数遮蔽外层变量）。这是 Java 与 Python 的显著差异——Python 的 Lambda 参数会**新建**作用域，Java 直接报错。

```java
int x = 1;
Consumer<Integer> c = x -> System.out.println(x);   // ❌ 编译错误：变量 x 已定义
```

### Lambda vs 匿名内部类：等价但不等同

**等价关系**：写一个 Lambda，编译器会把它**转换**成一个函数式接口的实现。

```java
import java.util.Comparator;
import java.util.function.BiFunction;

// 匿名内部类写法
Comparator<String> c1 = new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
};

// Lambda 写法
Comparator<String> c2 = (a, b) -> a.length() - b.length();
```

| | 匿名内部类 | Lambda |
|---|-----------|--------|
| 能实现多个接口吗 | ❌ 只能一个 | ❌ 只能一个 |
| 能有构造器吗 | ✅ 可以（有 `this` 指向自己） | ❌ 没有构造器 |
| 能有实例字段吗 | ✅ 可以（可以有状态） | ❌ **不能有状态**（不能定义字段） |
| 能重写多个方法吗 | ✅ 可以（实现接口 + 继承类的所有方法） | ❌ 只能实现**唯一那个抽象方法** |
| `this` 指向谁 | 指向**匿名类自己** | 指向**外围的那个对象**（就近的外层类实例） |
| 代码量 | 多 | 少 |

⭐ **一句话**：Lambda 是「**接口的单个方法的简写**」，匿名内部类是「**一个完整的类**」。需求超过「一个方法」就用匿名内部类。

⚠️ **Lambda 不能有状态**（不能定义字段），但**可以捕获外部的 effectively final 局部变量**。如果逻辑需要可变状态，就该用普通类或匿名内部类。

## 四、方法引用（Method Reference）

**方法引用**是 Lambda 的另一种简写形式——**引用一个已经存在的方法**，而不是现场写一段逻辑。

**四种形式**：

| 形式 | 语法 | 含义 | 例子 |
|------|------|------|------|
| ① 静态方法 | `类名::静态方法名` | 调用某个类的静态方法 | `Integer::parseInt` |
| ② 实例方法（对象已知） | `对象名::实例方法名` | 调用**已知对象**的实例方法 | `System.out::println` |
| ③ 构造器 | `类名::new` | 调用构造器创建对象 | `ArrayList::new` |
| ④ 实例方法（对象待定） | `类名::实例方法名` | 第一个参数作为接收者 | `String::length` |

```java
import java.util.ArrayList;
import java.util.List;
import java.util.function.Consumer;
import java.util.function.Function;
import java.util.function.Supplier;

public class MethodRefDemo {
    public static void main(String[] args) {
        // ① 静态方法：Integer::parseInt —— 把 "123" 转成 123
        Function<String, Integer> toInt = Integer::parseInt;

        // ② 实例方法，对象已知：System.out::println
        Consumer<String> print = System.out::println;

        // ③ 构造器：ArrayList::new —— 创建 ArrayList
        Supplier<List<String>> newList = ArrayList::new;

        // ④ 实例方法，对象待定：String::length —— 第一个参数是接收者
        Function<String, Integer> length = String::length;

        System.out.println(toInt.apply("123"));   // 123
        print.accept("你好");
        System.out.println(newList.get().size());  // 0
        System.out.println(length.apply("abcde")); // 5
    }
}
```

⭐ **理解第 ④ 种的关键**：当签名对不上时，编译器会自动把**第一个参数**当作接收者。

```java
// String::length 对应 Function<String, Integer>
// 但如果目标接口是 BiFunction<String, String, Integer> 呢？
BiFunction<String, String, Integer> cmp = String::length;   // ❌ 编译错误：参数不匹配
```

第 ④ 形式对应的是「一个实例方法被当成双参数函数」的场合：

```java
// String::compareTo 对应 BiFunction<String, String, Integer>
BiFunction<String, String, Integer> cmp = String::compareTo;   // ✅
// 等价于 (a, b) -> a.compareTo(b)
```

⚠️ **方法引用要求签名严格匹配**。签名对不上时编译器报 "incompatible types" 或 "invalid method reference"，这是常见报错来源。

## 五、Lambda 的底层实现：不是「创建了一个匿名内部类」

⚠️ **一个流传很广但并不准确的说法**：「Lambda 表达式在编译后就是一个匿名内部类」。**这个说法只对了一半**——

### 事实：Java 8 引入 `invokedynamic`

**`invokedynamic`** 是字节码层面的一条指令，让 JVM 在**第一次执行到该调用点时**动态决定调用哪个目标方法。这个能力是 Java 7 才加进 JVM 的（原本为了内部实现 lambda 之外的场景），Java 8 拿来实现 Lambda。

**LambdaMetafactory**（`java.lang.invoke.LambdaMetafactory`）是 JDK 提供的「引导方法」（bootstrap method），负责在运行期**动态生成**一个实现函数式接口的类。

```
源码:    list.forEach(s -> System.out.println(s));
   ↓  javac 编译
字节码:  invokedynamic #7, InvokeDynamic #0, BootstrapMethods
             ↑ 不指向任何具体类的方法，而是指向一个「引导方法」
   ↓  第一次执行到这一行时
运行期:  LambdaMetafactory 在内存中「生成」一个实现了 Consumer 的类
         （历史上生成的是隐藏类 hidden class）
```

### 为什么不用「匿名内部类」实现

如果真的编译成匿名内部类，会有这些问题：

| 问题 | 说明 |
|------|------|
| **启动开销** | 每个 Lambda 都要生成一个 class 文件，启动时加载这些类拖慢启动 |
| **无法优化** | JIT 难以下沉——动态生成的类不如编译期已知的类容易内联 |
| **无法跨 JVM 复用** | 匿名内部类每次重新编译都会生成新的类 |

用 `invokedynamic`，JVM 可以**在运行期直接生成类**（不落盘），还能针对「单态调用点」做专门的优化（**单态内联，monomorphic inlining**）——如果这个调用点始终只传同一种 Lambda，JVM 就能把它完全内联掉，性能比匿名内部类更好。

⭐ **对学习者的实际意义**：你知道「Lambda 底层有 `invokedynamic` 这条路」就够了。面试时能说清「不是简单的匿名内部类，而是运行期动态生成」这一层，就比大多数人深了。

⚠️ 但也别走极端：可以说 Lambda **语义上**等价于「一个函数式接口的实现」，只是**实现机制**不是「编译期生成匿名内部类」。

## 六、`enum` 枚举：比常量类更好的常量

### 用 `static final int` 定义常量的问题

传统的「常量类」写法：

```java
public class Status {
    public static final int PENDING = 0;
    public static final int PAID = 1;
    public static final int CANCELLED = 2;
}
```

用法：

```java
if (order.getStatus() == Status.PAID) { ... }
```

⚠️ **三个真实的问题**：

1. **类型不安全**：`setStatus(99)` 编译能过（`int` 什么都能装），运行时才炸；
2. **不知道传的是哪个**：`setStatus(0)` —— 0 是什么意思？读代码的人得去翻常量类；
3. **不能带行为**：一个状态如果要带「流转到下一状态的方法」，常量类就做不了（`static` 方法里没法做「当前实例」相关的逻辑）。

### `enum`：Java 内置的枚举类型

```java
// SimpleStatus.java —— 最简单的枚举写法
public enum SimpleStatus {
    PENDING,          // 待支付
    PAID,             // 已支付
    CANCELLED;        // 已取消
}
```

⭐ **`enum`（枚举）是 Java 的一个特殊类型**，它的每个枚举常量**本身就是该类型的一个对象实例**（不是常量，是对象）。

### 枚举的三个优势

| 优势 | 说明 |
|------|------|
| **① 类型安全** | `setStatus(OrderStatus.PAID)`——传错类型编译报错；`setStatus(99)` 根本编译不过（枚举不接受 int） |
| **② 可带构造参数** | 每个枚举常量可以有自己的数据和方法 |
| **③ 自带工具方法** | `values()` 和 `valueOf(String)` 开箱即用 |

### 带构造参数的枚举

```java
public enum OrderStatus {
    PENDING("待支付", 0),
    PAID("已支付", 1),
    CANCELLED("已取消", 2);

    private final String label;      // 每个枚举常量带的数据
    private final int code;

    // 构造器：⚠️ 枚举构造器默认 private，不能写修饰符
    OrderStatus(String label, int code) {
        this.label = label;
        this.code = code;
    }

    public String getLabel() { return label; }
    public int getCode() { return code; }

    // 可以有方法：每个常量各自一份
    public boolean canCancel() {
        return this == PENDING;
    }
}
```

```java
public class EnumDemo {
    public static void main(String[] args) {
        OrderStatus s = OrderStatus.PAID;

        // values()：返回该枚举所有常量组成的数组
        for (OrderStatus st : OrderStatus.values()) {
            System.out.println(st.name() + " -> " + st.getLabel());
        }

        // valueOf(String)：按名字取常量（⚠️ 名字不存在会抛 IllegalArgumentException）
        OrderStatus back = OrderStatus.valueOf("PENDING");
        System.out.println(back.getLabel());
        System.out.println(s.canCancel());     // false
    }
}
```

### 枚举自带的方法

| 方法 | 作用 |
|------|------|
| `values()` | 静态方法，返回所有枚举常量的数组（`OrderStatus[]`） |
| `valueOf(String name)` | 静态方法，按常量名取对应枚举；名字不存在抛 `IllegalArgumentException` |
| `name()` | 返回常量的名字字符串 |
| `ordinal()` | 返回常量的序号（**从 0 开始**，⚠️ 别拿它当持久化 ID，顺序变了数据就错位） |
| `compareTo(E other)` | 比较两个常量的先后（按 `ordinal`） |

⚠️ **`ordinal()` 的坑**：它是「声明顺序」，一旦你调整了枚举常量的顺序，数据库里存的数字就对不上了。要持久化就用 `getCode()` 这种自己定义的稳定值。

### 与常量类对照

| 维度 | `static final int` 常量类 | `enum` |
|------|----------------------|--------|
| 类型安全 | ❌ 传 `99` 也能编译 | ✅ 只能传枚举常量 |
| 可读性 | 差（`setStatus(0)`） | 好（`setStatus(PAID)`） |
| 能带数据 | ❌ | ✅ 每个常量有字段 |
| 能带行为 | ❌ | ✅ 每个常量有方法 |
| `switch` 支持 | 用 int，能写 | ⭐ Java 21+ 模式匹配 `switch` 直接匹配枚举常量，且能做穷尽性检查 |
| 内存 | 编译期常量，可能被内联 | 每个常量一个对象 |

⭐ **结论**：能用 `enum` 就用 `enum`。Java 5 引入枚举之后，「用常量类表示一组固定取值」基本已经过时。

⚠️ **`enum` 不能被继承**（隐式 `final`），也**不能被 lambda 化**——它是实实在在的对象。

### 顺带一提：`record` 与 `enum` 的分工

两个都是 Java 提供的「**把一类固定结构的数据打包**」的语法糖，但用途不同：

| | `record`（Java 16+） | `enum`（Java 5+） |
|---|---------------------|----------------|
| 表示什么 | 「一组**值**」——坐标、DTO | 「一组**选项**」——状态、类型 |
| 数量 | 无限（每 new 一个就是一个新值） | 固定（编译期就写死了几个常量） |
| 可变性 | 不可变（字段全是 `final`） | 每个常量是不可变的单例 |
| 适用 | 「这批数据没有先后、没有全集」 | 「这类东西全世界就这几样」 |

⭐ 判断口诀：**值 → `record`；选项 → `enum`。**

`record` 的完整介绍（自动生成的构造器/getter/equals/hashCode/toString）在 [[java/01-入门阶段-基础教程/第02章-面向对象/2.1-类与对象基础]] 的「`record`：Java 16+ 的『数据载体』简写」一节。

## 陷阱

1. **⚠️ 以为「Lambda 编译后就是一个匿名内部类」**——实际是 `invokedynamic` + `LambdaMetafactory` 在运行期动态生成实现类；
2. **⚠️ 在 Lambda 里想定义字段**——Lambda **不能有状态**，需要字段就改用匿名内部类或普通类；
3. **⚠️ 捕获非 effectively final 的局部变量**——编译报错；解法是复制一份 `final` 变量；
4. **⚠️ Lambda 参数名遮蔽外层变量**——Java 直接报错（Python 不会）；换个名字即可；
5. **⚠️ 以为「内部类可以直接用外层的局部变量，随便改」**——局部变量必须 effectively final；**实例字段**才可以随便访问和修改；
6. **⚠️ 忘记静态内部类要加 `static`**——不加就是成员内部类（隐式持有外部引用，创建方式也不同）；
7. **⚠️ 成员内部类创建写成 `new Inner()`**——必须先有外部对象：`outer.new Inner()`；
8. **⚠️ 匿名内部类后面忘了分号**——`new Runnable() { ... }` 结尾的 `;` 必须写；
9. **⚠️ 方法引用签名对不上**——`String::length` 不能赋给 `BiFunction<String,String,Integer>`，报 "invalid method reference"；
10. **⚠️ 用 `ordinal()` 当持久化 ID**——调整枚举顺序会让老数据全部错位，用自己定义的 `code`；
11. **⚠️ 用 `int` 常量类表示状态**——类型不安全，改用 `enum`。

## 小结

- **内部类四种**：成员内部类（⭐ 持有外部引用，创建要 `outer.new Inner()`）、静态内部类（不持有）、局部内部类（方法内）、匿名内部类（一次性实现接口，结尾别忘 `;`）
- ⚠️ **内部类持有外部类引用 → 外部对象不会被回收** → 内存泄漏来源
- **局部变量捕获要求 effectively final**——为了让「捕获的值」语义唯一、无歧义
- **函数式接口** = 只有一个抽象方法；`@FunctionalInterface` 让编译器帮你检查
- **内置函数式接口**：`Function`（入出）、`Consumer`（只入）、`Supplier`（只出）、`Predicate`（判断）、`BiFunction`（两入一出）、`Comparator`（比较，`java.util` 包）
- **Lambda** = `(参数) -> 表达式`；类型由目标接口推断；**不能有状态**
- **方法引用四形态**：`类名::静态方法`、`对象::实例方法`、`类名::new`、`类名::实例方法`（首参作接收者）
- ⭐ **Lambda 底层 = `invokedynamic` + `LambdaMetafactory` 运行期动态生成**，不是编译期匿名内部类
- **`enum` 优于 `static final int`**：类型安全、可带构造参数与行为、自带 `values()`/`valueOf()`
- **值用 `record`（Java 16+），选项用 `enum`（Java 5+）**
