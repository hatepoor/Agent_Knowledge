## 一、类 vs 对象：先把这个词掰开

这一节只做一件事：让你以后看到「类」和「对象」时不再混。

| 概念 | 英文 | 一句话定义 | 比喻 |
|------|------|-----------|------|
| **类** | class | 一份**描述/蓝图**，规定「这类东西有哪些字段、能做哪些事」 | 建筑图纸 |
| **对象** | object | 按蓝图造出来的**一个具体实体**，真正占有内存、承载数据 | 按图纸盖出来的那栋楼 |
| **实例** | instance | 对象的另一个说法：「某个类的某个对象」 | 「这栋楼是『住宅楼类』的一个实例」 |

⭐ **类在「方法区（元空间）」里，对象在「堆」里。** 一个类可以造出无数对象，一个对象一定属于某个类。

```
        类（一份蓝图，存放在方法区/元空间）
        ┌──────────────────────────────┐
        │ class Student                │
        │   字段：name, age            │  ← 只描述"有哪些位置"，不存具体值
        │   方法：introduce()          │
        └──────────────────────────────┘
                 │  new Student("张三", 20)   ← 按蓝图造实体
                 ▼  （可重复执行无数次）
   ┌──────────────┐        ┌──────────────┐
   │ 对象A         │        │ 对象B         │
   │ name="张三"   │        │ name="李四"   │   ← 每个对象各存各的值
   │ age=20        │        │ age=22        │
   └──────────────┘        └──────────────┘
        ↑ 都存在于堆中，各占一块内存
```

> 图里「类」的那份数据更准确地说是**类元数据（Class 对象）**，位置细节见 [[java/02-中段阶段-专题精讲/JVM/JVM内存区域与对象布局]] 的「方法区/元空间」和「对象头」两节。

### 与 Python 的对照

```python
# Python
class Student:
    def __init__(self, name, age):   # 初始化方法
        self.name = name              # self 就是「当前对象自己」
        self.age = age

    def introduce(self):
        print(f"我是{self.name}，今年{self.age}岁")

s = Student("张三", 20)
s.introduce()
```

```java
// Java —— Student.java
public class Student {
    // 成员字段（instance field）：每个对象各有一份
    String name;
    int age;

    // 构造器：创建对象时自动执行，负责初始化
    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // 成员方法
    public void introduce() {
        System.out.println("我是" + name + "，今年" + age + "岁");
    }

    public static void main(String[] args) {
        Student s = new Student("张三", 20);
        s.introduce();
    }
}
```

| Python | Java | 说明 |
|--------|------|------|
| `class Student:` | `public class Student { }` | 类的声明 |
| `def __init__(self, ...)` | `public Student(...) { }` | Java 里叫**构造器**，名字固定跟类名一样，不能另起名字 |
| `self` | `this`（可选） | `self` 必须显式写成第一个参数；Java 的 `this` 是**隐式**的，只在需要时写 |
| `self.name = name` | `this.name = name;` | 左边是「本对象的字段」，右边是「参数」 |
| `s = Student(...)` | `Student s = new Student(...);` | Java 要**先声明变量类型**，再 `new` |

⚠️ **两个 Java 独有的小规定**：
1. `public class Student` 里的类名必须和**文件名**一致——所以上面那段要存成 `Student.java`；
2. `System.out.println(...)` 是 Java 的标准输出写法，`System.out` 是「标准输出流」，`println` 是「打印一行并换行」。

## 二、类的声明与成员：一个类由什么组成

一个 Java 类里能有的成员，入门阶段先掌握这几类：

| 成员 | 写法 | 作用 | 归属 |
|------|------|------|------|
| **成员字段**（instance field） | `String name;` | 存数据，每个对象一份 | 属于对象 |
| **静态字段**（static field） | `static int count;` | 存数据，**整个类共用一份** | 属于类 |
| **成员方法**（instance method） | `void run() { }` | 对象能做的事，每个对象一份方法体 | 属于对象 |
| **静态方法**（static method） | `static void run() { }` | 类级别的方法，不需要对象也能调用 | 属于类 |
| **构造器**（constructor） | `Student() { }` | 创建对象时执行一次 | 属于类 |
| **初始化块** | `static { }` / `{ }` | 在特定时机执行一段代码 | 属于类 / 属于对象 |

> 「**静态**」= `static` 修饰符，中文里也叫「类成员」「类级别成员」。它表达的是：**这个成员属于类，而不是属于某个具体对象**。

### 实例字段 vs 静态字段（必考基础）

```java
// User.java
public class User {
    // 实例字段：每个 User 对象各有一份
    String name;

    // 静态字段：整个 User 类只有一份，所有对象共享
    static int userCount = 0;

    public User(String name) {
        this.name = name;
        userCount++;      // 每 new 一个就加 1
    }

    public static void main(String[] args) {
        User a = new User("张三");
        User b = new User("李四");
        System.out.println(a.userCount + " " + b.userCount);  // 2 2 —— 同一份
        System.out.println(User.userCount);                   // 2     —— 推荐写法
    }
}
```

| 维度 | 实例字段 | 静态字段 |
|------|---------|---------|
| 声明 | `String name;` | `static int count;` |
| 有几份 | **每个对象一份**（N 个对象 N 份） | **整个类一份**（无论多少对象） |
| 访问方式 | `obj.name`（推荐） | `ClassName.count`（推荐）；⚠️ `obj.count` 也能编译，但会被 IDE 警告「静态成员应通过类名访问」 |
| 能否在实例方法里直接用 | 能 | 能 |
| 能否在静态方法里直接用 | ⚠️ 不能（静态方法没有具体对象） | 能 |
| 典型用途 | 每个对象自己的数据 | 计数器、常量、工具方法、共享缓存 |

⚠️ **静态字段的坑：共享状态**。因为只有一份，多个对象改它会互相影响。典型的并发 bug 就出在这里：「用静态字段做计数器」在多线程下必然出错——多线程内容见 [[java/02-中段阶段-专题精讲/并发编程/02-线程安全与Java内存模型]]。

## 三、构造器（constructor）：只负责「出生时这一刻」

**构造器**（也叫构造方法、构造函数）是创建对象时自动执行的一段代码，作用是**把对象初始化成一个可用的状态**。

它的三个铁律：

1. **名字必须和类名完全一样**（`Student` 类的构造器就叫 `Student`）；
2. **没有返回类型**——注意是「没有」，不是「写成 `void`」。写 `void Student()` 是**语法错误**；
3. **可以有任意多个**，靠参数列表区分——这叫**重载**（overload）。

```java
// Coordinate.java —— 演示构造器重载
public class Coordinate {
    int x;
    int y;

    // 无参构造器
    public Coordinate() {
        this.x = 0;
        this.y = 0;
    }

    // 一个参数的构造器（重载 1）
    public Coordinate(int x) {
        this.x = x;
        this.y = 0;
    }

    // 两个参数的构造器（重载 2）
    public Coordinate(int x, int y) {
        this.x = x;
        this.y = y;
    }
}
```

### ⚠️ 高频坑：默认构造器

**默认构造器**（也叫「隐式构造器」「无参构造器」）是编译器在你没写任何构造器时**自动生成**的那个：它什么都不做，等价于 `public Student() { }`。

规则只有一句：

> **一旦你写了任何**一个**构造器（不管有没有参数），编译器就不再生成默认构造器。**

```java
public class Dog {
    String name;

    public Dog(String name) {   // 我写了构造器
        this.name = name;
    }
}

// 在别的类里：
Dog d1 = new Dog("旺财");   // ✅ 正常
Dog d2 = new Dog();         // ❌ 编译错误：constructor Dog in class Dog cannot be applied to given types
```

**为什么这是高频坑**：你在写 `Dog` 时觉得「我先写了个带参构造器」，后来框架代码（Spring、Jackson、测试框架）想用 `new Dog()` 或反射创建对象，就炸了。

**解法**：如果打算写带参构造器，**顺手也写一个无参构造器**（或用 Lombok 之类的工具生成——那是后面的内容）。

### 构造器链：`this()` 与 `super()`

一个类里多个构造器往往有重复代码。Java 提供两个「转交」关键字，让一个构造器可以把活儿交给另一个：

- **`this(...)`**：调用**同一个类**里的另一个构造器；
- **`super(...)`**：调用**父类**的构造器（父类 = 被继承的类，详见 [[java/01-入门阶段-基础教程/第02章-面向对象/2.2-封装继承与多态]]）。

```java
// Employee.java
public class Employee {
    String name;
    int age;

    // 主构造器：真正的活儿都在这
    public Employee(String name, int age) {
        this.name = name;
        this.age = age;
        System.out.println("主构造器执行完");
    }

    // 便捷构造器：转交给主构造器
    public Employee(String name) {
        this(name, 18);        // ⚠️ this(...) 必须是构造器的**第一句**
    }
}
```

执行 `new Employee("张三")` 的顺序是：

```
new Employee("张三")
   └─> Employee(String) 构造器
          └─> this("张三", 18)  →  转到 Employee(String, int)
                 ├─> this.name = "张三"
                 ├─> this.age = 18
                 └─> 打印「主构造器执行完」
          <- 转回来，Employee(String) 构造器体剩下的语句继续执行
```

⚠️ **两条硬规则**：
1. `this(...)` 和 `super(...)` **必须写在构造器的第一句**——写前面有别的语句就编译报错；
2. 二者**只能选一个**（`this(...)` 和 `super(...)` 不能同时出现在同一个构造器里），但**可以都出现在不同构造器里**：一个构造器调 `this(...)` 转交出去，被转交的那个构造器再调 `super(...)` 往上走。

### 构造器只能重载，不能继承

⚠️ **构造器**不是**方法**，它**不能被继承，也不能被重写（override）**。

- 子类构造器**不会**继承父类的构造器。父类的构造器只能被 `super(...)` 显式调用。
- 父类的构造器可以是 `private`（这样子类就完全用不上它——这是「禁止子类化」的一种手段）。
- 构造器只能**重载**（同名字不同参数），不能重写。

**为什么这样设计**：构造器负责的是「把对象造出来」，而**造对象的过程必须由最具体的那个类从头执行到底**。如果允许重写构造器，子类构造器运行到一半时父类部分的行为可以被换掉，对象就可能处于半初始化状态——这在 Java 里是必须避免的。

## 四、`this` 引用：指向「当前对象自己」

**`this`** 是一个**隐式引用**（引用 = 指向某个对象的"地址变量"），指向正在执行这个方法的那个对象。

它有两个用途：

**用途 1：区分同名的字段和参数。**

```java
public void setName(String name) {
    this.name = name;   // 左边 this.name 是本对象的字段，右边 name 是参数
}
```

不写 `this` 也能编译（Java 会按「最近的作用域」推断），但**同名时必须写**，否则你赋的是参数自己，字段还是 `null`。

**用途 2：把当前对象整个传出去。**

```java
public void register(Registry registry) {
    registry.add(this);   // 把「我自己」交出去
}
```

⚠️ **静态方法里不能用 `this`**。

原因很直接：静态方法属于**类**，不属于任何具体对象——调用它的时候根本不存在「当前对象」这个概念，`this` 无从指向。

```java
public static void demo() {
    // this.name = "张三";    // ❌ 编译错误：non-static variable this cannot be referenced from a static context
    System.out.println("静态方法里没有 this");
}
```

⚠️ 顺带记住：**实例方法里可以用 `ClassName.staticField`**（如 `User.userCount`），反过来**静态方法里不能直接用实例字段**（`name`）。

## 五、`static`：属于类的东西

`static` 修饰符把成员从「对象级」提升到「类级」。三处会用到：

### 1. 静态字段

见第二节。**全类共享一份**，典型用途是计数器、常量、配置。

### 2. 静态方法

```java
public class MathUtil {
    // 静态方法：不需要对象，直接用类名调用
    public static int max(int a, int b) {
        return a > b ? a : b;
    }

    public static void main(String[] args) {
        System.out.println(MathUtil.max(3, 7));   // 7
    }
}
```

⭐ **判断标准**：这个方法**需要对象里的数据**吗？
- 需要 → 实例方法（`obj.method()`）
- 不需要（纯计算/工具性质） → 静态方法（`Class.method()`）

`Math.max`、`Arrays.sort`、`Objects.requireNonNull` 都是静态方法。

### 3. 静态导入（`import static`）

正常情况下调静态方法要写类名：`MathUtil.max(...)`。用 **`import static`** 可以省略类名：

```java
import static java.lang.Math.max;    // 只导入 max 这一个静态方法
// import static java.lang.Math.*;   // 导入 Math 的所有静态成员

public class UseStaticImport {
    public static void main(String[] args) {
        System.out.println(max(3, 7));   // 像自己写的方法一样用
    }
}
```

⚠️ 两条注意：
1. `import static` 必须写在**文件开头的 import 区**，不能写在类里面；
2. 静态导入会**污染可读性**——团队代码里建议少用，容易看不懂 `max` 是谁的。

### 静态初始化块 vs 实例初始化块

两种「初始化块」都是没有名字、没有返回值的代码块，靠**位置**决定什么时候跑：

| | 静态初始化块 | 实例初始化块 |
|---|---|---|
| 写法 | `static { ... }` | `{ ... }` |
| 什么时候执行 | **类被加载时**，执行 **1 次** | **每创建一个对象**，执行 1 次 |
| 能访问实例字段吗 | ⚠️ 不能 | 能 |
| 能访问静态字段吗 | 能 | 能 |

```java
// InitOrder.java —— 专门看执行顺序
public class InitOrder {
    static int s = 10;                 // ① 静态字段初始化
    int i = 20;                        // ④ 实例字段初始化（每次 new 都跑）

    static {                           // ② 静态初始化块
        System.out.println("静态块 s=" + s);
    }
    {                                  // ⑤ 实例初始化块
        System.out.println("实例块 i=" + i);
    }

    public InitOrder() {               // ⑥ 构造器体
        System.out.println("构造器 i=" + i);
    }

    public static void main(String[] args) {
        System.out.println("main 开始");
        new InitOrder();
        new InitOrder();
    }
}
```

输出：

```
静态块 s=10          ← 类加载时，只一次
main 开始
实例块 i=20
构造器 i=20
实例块 i=20
构造器 i=20
```

⭐ **完整顺序口诀**（一次 new 的全过程）：

```
类加载时（仅一次）:  静态字段 → 静态初始化块（按代码书写顺序）
每次 new 一个对象:   ① 父类构造器 super()
                     ② 实例字段初始化 与 实例初始化块（按书写顺序交替执行）
                     ③ 子类构造器体
```

⚠️ 注意 ② 里「实例字段」和「实例初始化块」是**按书写顺序交替**执行的，不是「所有字段先执行完再执行块」。比如下面这段的输出顺序是 `B` → `C`：

```java
public class InitOrderDemo {
    static { System.out.println("A"); }   // 静态块
    { System.out.println("B"); }          // 实例块
    int x = 1;                            // 实例字段（不打印，但确实在这个位置执行）
    { System.out.println("C"); }          // 实例块
    static { System.out.println("D"); }   // 静态块
    public InitOrderDemo() { System.out.println("E" + x); }
    public static void main(String[] args) { new InitOrderDemo(); }
}
// 输出：A D B C E1
```

## 六、`final` 字段与 JavaBean 规范

### `final` 字段：赋值之后不可再改

`final` 修饰字段 = 该字段**只能赋值一次**。三种赋值时机：

```java
public class Config {
    // ① 声明时直接给值
    final String version = "1.0";

    // ② 构造器里赋值
    final int timeout;

    // ③ 静态初始化块里赋值
    static final int MAX;

    static {
        MAX = 100;
    }

    public Config(int timeout) {
        this.timeout = timeout;   // 构造器里赋值是 final 字段的合法时机
    }
}
```

⚠️ `final` 字段**必须在构造器结束前被赋值**，否则编译报错（"variable might not have been initialized"）。`static final` 字段则必须在**类初始化完成前**赋值。

⭐ **命名约定**：`static final` 的常量习惯用**全大写 + 下划线**（`MAX_RETRY_COUNT`），这叫「常量」——它在编译期可能被直接内联进调用方代码，所以一旦发布就不要再改值。

### JavaBean 规范：给私有字段配一对 getter/setter

**JavaBean** 是一种约定俗成的**类格式**：属性（字段）私有，对外暴露一对读方法和写方法。

| 部分 | 规则 | 例 |
|------|------|-----|
| 类 | 公有类，有**无参构造器** | `public class User { }` |
| 属性 | `private` 修饰的字段 | `private String name;` |
| 读方法 | `getXxx()` / `boolean` 用 `isXxx()` | `getName()`、`isActive()` |
| 写方法 | `setXxx(值)`，返回 `void` | `setName(String name)` |

```java
// UserBean.java —— 标准的 JavaBean 写法
public class UserBean {
    private String name;      // 私有：外部不能直接改，必须经过 setter
    private int age;
    private boolean active;

    public UserBean() { }                  // ⭐ JavaBean 必须有无参构造器

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }

    public boolean isActive() { return active; }     // boolean 用 is
    public void setActive(boolean active) { this.active = active; }
}
```

⭐ **为什么要有这一层？** 三个理由：

1. **控制写入入口**——可以在 setter 里做校验、加日志、触发联动；
2. **将来换实现不改调用方**——今天 `getAge()` 直接返回字段，将来要改成从数据库查，调用方代码一行都不用动（这是「面向接口编程」的第一层体感，见 [[java/01-入门阶段-基础教程/第02章-面向对象/2.3-抽象类与接口]]）；
3. **框架需要**——Spring、Jackson（JSON 序列化）、JSP 等大量框架靠 getter/setter 自动映射属性。

⚠️ `record`（下一节）打破了这个约定：它生成的读方法叫 `x()` 而不是 `getX()`。

## 七、`record`：Java 16+ 的「数据载体」简写

**记录类**（record）是 Java 16 正式引入的语法糖，用来表达「**一组不可变的数据**」——非常适合 DTO（数据传输对象）、坐标、订单快照这类东西。

```java
// Point.java
public record Point(int x, int y) {
    // 就这一行！
}
```

编译器自动帮你生成了：

| 自动生成的东西 | 相当于手写了 |
|---------------|------------|
| `private final int x; private final int y;` | 私有 final 字段 |
| `public Point(int x, int y) { ... }` | 全参构造器 |
| `public int x() { return x; }` | 读方法（⚠️ **不是** `getX()`） |
| `public boolean equals(Object o)` | 值相等比较（比的是内容） |
| `public int hashCode()` | 与 `equals` 配套的哈希值 |
| `public String toString()` | 打印用字符串 |

```java
public class RecordDemo {
    public static void main(String[] args) {
        Point p1 = new Point(3, 4);
        Point p2 = new Point(3, 4);
        System.out.println(p1);                    // Point[x=3, y=4]
        System.out.println(p1.x());                // 3 —— 注意没有 get
        System.out.println(p1.equals(p2));         // true —— 值相等
    }
}
```

⚠️ **record 的三条限制**：字段全部隐式 `private final`（不能改）、不能继承别的类（但可以实现接口）、不能声明额外的实例字段。

⭐ 本篇只讲到「它能替代一串 getter/setter」为止。record 在「集合里放不可变元素」的场景还会再出现，见 [[java/01-入门阶段-基础教程/第04章-集合框架/4.1-集合接口总览与选型]]。

## 八、对象的生命周期：从生到死

一个对象的一生只有四个阶段：

```
   ① 创建                ② 使用                 ③ 不可达              ④ 被 GC 回收
      │                     │                      │                     │
 new Student(...)   s.introduce()      s = null;              堆内存被释放
      │                     │      （或离开作用域）                │
      ▼                     ▼                      ▼                     ▼
 分配内存 → 零值初始化   对象持有数据、    没有任何引用指向它     内存归还给 JVM，
 → 设置对象头 → 执行构造器  方法能正常调用   （注意：对象还在堆里！   下次分配可复用
```

⚠️ **关键认知：第 ③ 步到第 ④ 步不是立即发生的。** 对象变成「不可达」（unreachable，指没有任何引用指向它）之后，它**仍然占着内存**，直到垃圾收集器（GC，Garbage Collector）下一次运行时才把它收走。这就是 Java **不需要** `delete` / `free` 的原因——**内存回收由 JVM 负责，不是程序员负责**。

GC 的具体算法、哪些对象会被回收、分代回收策略，属于后面的内容：
- 对象的内存布局、堆与元空间 → [[java/02-中段阶段-专题精讲/JVM/JVM内存区域与对象布局]]
- 垃圾回收算法与调优 → [[java/02-中段阶段-专题精讲/JVM/垃圾回收与调优]]

⭐ **实用推论**：因为回收时机不确定，**不要在对象里保存「创建时刻的资源」**（比如文件句柄、数据库连接）。这些应该用 `try-with-resources` 之类的确定性释放方式管理，见 [[java/01-入门阶段-基础教程/第03章-异常处理/3.2-捕获处理与自定义异常]]。

## 陷阱

1. **⚠️ 以为「写了带参构造器，还能 `new Dog()`」**——一旦你写了任何构造器，编译器**不再生成**默认无参构造器，`new Dog()` 直接编译报错。要么补一个无参构造器，要么接受「只能用带参的」；
2. **⚠️ 在静态方法里用 `this`**——静态方法没有「当前对象」，`this` 编译报错。同理静态方法也不能直接访问实例字段；
3. **⚠️ 把构造器当方法**——构造器**没有返回类型**（写 `void` 是语法错误）、**不能被继承、不能被重写**，只能重载；
4. **⚠️ 把 `this(...)` 和 `super(...)` 写在同一个构造器里**——二者只能选一个，且都**必须是第一句**；
5. **⚠️ 用静态字段当「每个对象自己的数据」**——静态字段**全类只有一份**，对象 A 改了对象 B 也能看见；用静态字段做计数器在多线程下必然出错；
6. **⚠️ 以为「对象不可达就立刻释放内存」**——GC 不保证立即回收，`System.gc()` 也只是「建议」；但这不代表可以不管内存泄漏（长期持有引用就是泄漏）；
7. **⚠️ 以为 `record` 的读方法叫 `getX()`**——它叫 `x()`，和 JavaBean 规范不一致，序列化框架要额外配置；
8. **⚠️ 忘了 `public class` 的类名必须与文件名一致**——编译报「class X is public, should be declared in a file named X.java」。

## 小结

- **类 = 蓝图（方法区）**，**对象 = 实体（堆）**，实例 = 某个具体对象
- 成员分「对象级」（实例字段/实例方法）和「类级」（`static` 字段/方法/初始化块）
- **静态字段全类共享一份**，实例字段每个对象一份
- **构造器**：名同类名、无返回类型、可重载、**不可继承不可重写**
- ⚠️ **写了任何构造器 → 编译器不再生成默认无参构造器**（高频坑）
- `this(...)` / `super(...)`：**只能选一个，且必须是第一句**
- `this` 只在实例方法里有意义，静态方法禁用
- 初始化顺序：静态字段 → 静态块（一次）；super() → 实例字段与实例块**按书写顺序交替** → 构造器体（每次 new）
- `final` 字段赋值后不可改；`static final` 全大写命名是常量
- **JavaBean** = 私有字段 + `getXxx()`/`setXxx()`，是框架生态的通用契约
- `record`（Java 16+）= 不可变数据载体的语法糖，读方法名是 `x()`
- 对象生命周期：创建 → 使用 → 不可达 → **被 GC 回收**（回收时机由 JVM 决定）
