## 一、封装（Encapsulation）：把数据关起来，把门开好

### 为什么需要封装

**封装**指「**隐藏内部细节，只暴露必要的操作入口**」。

假设有个 `BankAccount` 类，如果字段是 `public` 的：

```java
public class BankAccount {
    public double balance;   // ❌ 任何人可以 balance = -999999;
}
```

问题一目了然：**余额可以被随意改，甚至改成负数**。把字段设为 `private`（私有）+ 提供受控的 `setter`（写入口），才能加上校验：

```java
public class BankAccount {
    private double balance;   // ✅ 外部读不到、改不了

    public double getBalance() { return balance; }

    public void withdraw(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("取款额必须为正");
        if (amount > balance) throw new IllegalStateException("余额不足");
        this.balance -= amount;   // 只有类内部能改，改的时候顺便做校验
    }
}
```

⭐ 封装带来的三个具体好处：

1. **保护不变式**（invariant）：类的内部数据永远处于「合法状态」，不可能被外部破坏；
2. **可演进**：将来 `balance` 要改成用 `BigDecimal` 精确存储，对外接口不变，调用方零改动；
3. **降低耦合**：外部只知道「有 `withdraw` 这个动作」，不关心数据怎么存。

### 四个访问修饰符

**访问修饰符**（access modifier）决定「谁能看到这个成员」。Java 有四个：

| 修饰符 | 同类 | 同包 | 子类（不同包） | 任意类 | 归属 |
|--------|------|------|--------------|--------|------|
| `private` | ✅ | ❌ | ❌ | ❌ | **类内可见** |
| 不写（**默认 / package-private**） | ✅ | ✅ | ❌ | ❌ | **包内可见** |
| `protected` | ✅ | ✅ | ✅ | ❌ | **子类 + 包内可见** |
| `public` | ✅ | ✅ | ✅ | ✅ | **完全公开** |

「包」（package）是 Java 的**命名空间机制**：用 `package com.example.demo;` 声明的类属于 `com.example` 这个包，同包 = 同目录结构下的同一命名空间。

### ⚠️ 「默认访问权限」是 package-private

Java 的历史原因：类成员**不写任何修饰符**时，默认不是 `public` 也不是 `private`，而是「**默认访问 / package-private（包私有）**」——**同包可见，跨包不可见**。

```java
package com.example.demo;

public class Account {
    private double balance;      // 只有 Account 内部能用
    double owner;                // ⚠️ 没写修饰符 = package-private
    protected String id;         // 同包 + 子类可见
    public String bankName;      // 谁都能用
}
```

⚠️ **高频误解**：很多人以为「不写修饰符就是 public」。JavaScript 里不写确实是 public，但 **Java 不是**。

**实务建议**：现代 Java 代码里几乎所有成员都应该显式写 `private` 或 `public`，**别依赖默认权限**。依赖默认权限会让人误判「这个字段是公开的」，而实际上同包的其他类偷偷在用。

## 二、继承（Inheritance）：复用 + 「是一个」关系

### `extends` 建立父子关系

```java
// Animal.java —— 父类
public class Animal {
    protected String name;               // protected：子类能直接访问

    public Animal(String name) {
        this.name = name;
    }

    public void eat() {
        System.out.println(name + " 在吃东西");
    }

    public void makeSound() {
        System.out.println(name + " 发出声音");
    }
}
```

```java
// Dog.java —— 子类
public class Dog extends Animal {        // extends：继承 Animal
    private String breed;

    public Dog(String name, String breed) {
        super(name);                     // ⚠️ 隐式调用 super()，但必须显式写时就是第一句
        this.breed = breed;
    }

    public void fetch() {                // 子类新增的能力
        System.out.println(name + " 去捡球");
    }
}
```

> 本篇后面所有示例都继续用这一对 `Animal` / `Dog`，读者可以一路跟下去。

术语对照：

| 术语 | 也叫 | 含义 |
|------|------|------|
| 父类 | 超类、基类（superclass / base class） | 被继承的类，这里是 `Animal` |
| 子类 | 派生类（subclass / derived class） | 继承别人的类，这里是 `Dog` |
| `extends` | — | 子类声明「我要继承谁」的关键字 |

### ⚠️ `super()` 必须是第一句

**规则**：子类构造器**必须**先调用父类构造器。

- 如果父类**有**无参构造器 → 子类可以**省略**这行，编译器自动插入 `super();`；
- 如果父类**没有**无参构造器 → 编译器**不会**自动插入，你必须**显式**写 `super(参数...)`，而且**必须是构造器的第一句**。

```java
public class Dog extends Animal {
    public Dog(String name, String breed) {
        // System.out.println("先做点别的");   // ❌ 报错：super() 必须是第一条语句
        super(name);                          // ✅ 第一句
        this.breed = breed;
    }
}
```

⚠️ **这与 2.1 的「默认构造器」坑叠加**：如果 `Animal` 只写了 `Animal(String name)`，那么 `Dog` 必须显式写 `super(name)`；而且 `Animal` 自己的无参构造器也不存在了，别人想 `new Animal()` 也会编译报错。

### 方法重写（Override）：子类改写父类的行为

**重写**指子类重新实现父类已有的方法。签名（方法名 + 参数列表）必须**完全一致**，只有方法体不同。

```java
public class Dog extends Animal {
    @Override                              // @Override 是注解（annotation）：给编译器看的标记
    public void makeSound() {
        System.out.println(name + "：汪汪！");   // 父类打印"发出声音"，子类换成"汪汪"
    }
}
```

⭐ **`@Override` 一定要写**。它不是必须的，但作用是：**一旦方法名或参数写错，编译器立刻报错**。没有它，方法名拼错会被当成「新增方法」，静默地不生效——这是最难查的 bug 之一。

### 重写的三条规则

| 规则 | 说明 | 例子 |
|------|------|------|
| **① 返回类型可以协变** | 子类返回类型可以是父类返回类型的**子类型** | 父类 `Animal clone()`，子类 `Dog clone()` ✅ |
| **② 抛出的异常不能扩大** | 子类重写方法抛的异常必须是父类方法异常的**子集** | 父类抛 `IOException`，子类抛 `FileNotFoundException` ✅；子类抛 `Exception` ❌ |
| **③ 有些方法不能重写** | `private`、`final`、`static` 方法都不能重写 | 见下 |

⚠️ **不能重写的方法**：

- **`private` 方法**：父类的 private 方法对子类「不存在」，子类里同名方法只是**新方法**；
- **`final` 方法**：子类**必须**继承父类的实现，想改就别在父类标 `final`；
- **`static` 方法**：**隐藏（hiding）**而不是重写——因为静态方法属于类，调用是 `父类.静态方法()` 写死的。

### ⚠️ 字段隐藏 vs 方法重写（关键差异）

这是本篇最容易考、也最容易懵的一点。

| | 字段（属性） | 方法 |
|---|-------------|------|
| 父子都有同名的 | **字段隐藏**（field hiding）——子类字段「盖住」父类字段 | **方法重写**（override）——子类实现替换父类实现 |
| 决定调用哪个的 | **看「引用变量的声明类型」**（编译期就定死） | **看「对象实际是什么类型」**（运行期决定） |
| 加 `@Override` | ❌ 编译报错 | ✅ 必须加 |

```java
// Base.java —— 用一对简化的类专门演示这个区别
public class Base {
    String tag = "base";                     // 父类字段

    public void hello() {
        System.out.println("Base");
    }

    public void identify() {                 // 打印自己的运行时类型
        System.out.println("我是 Base，运行时类型=" + getClass().getSimpleName());
    }
}

// Derived.java —— ⚠️ 子类又声明了一个同名的 tag 字段（这就是「字段隐藏」）
public class Derived extends Base {
    String tag = "derived";                  // 与父类的 tag 是两块独立内存

    @Override
    public void hello() {
        System.out.println("Derived");
    }
}
```

```java
public class Demo {
    public static void main(String[] args) {
        Base ref = new Derived();             // 引用类型是 Base，实际对象是 Derived

        System.out.println(ref.tag);          // 输出「base」    —— 字段隐藏，看声明类型
        ref.hello();                          // 输出「Derived」 —— 方法重写，看运行时类型
    }
}
```

⚠️ 注意 `Derived.hello()` 里如果要用字段，得写 `this.tag` 才能明确指「子类自己那块」；而通过 `ref.tag` 访问时，编译器只认 `Base` 的声明，找到的是 `Base.tag` = 「base」。

⚠️ **父子类各自持有独立的 tag 字段内存**——`Base.tag` 和 `Derived.tag` 是两块不同的存储，不是同一个被覆盖了。

## 三、多态（Polymorphism）：同一个调用，不同的行为

**多态**指「**同一份代码调用，在运行期表现出不同的行为**」。Java 的多态靠「**向上转型 + 方法重写**」实现。

### 向上转型

**向上转型**（upcasting）：把子类对象的引用赋给父类型的变量。

```java
Animal ref = new Dog("旺财", "柴犬");   // 右边是 Dog，左边声明为 Animal
```

这**不是**「把 Dog 变成 Animal」，而是「**用一个 Animal 的视角去看一个 Dog 对象**」——对象本身还是 Dog，只是引用的类型是 Animal。

它的意义：**调用方不需要知道具体是哪个子类**。

```java
public static void speakAll(List<Animal> animals) {
    for (Animal a : animals) {     // 这里只认 Animal
        a.makeSound();             // 运行时各调各的实现
    }
}
```

### ⭐ 核心规律：方法看运行时类型，字段看声明类型

用一段代码彻底讲透。继续用上面那对 `Base` / `Derived`（它们专门演示「字段隐藏 vs 方法重写」）。

```java
// PolyDemo.java
public class PolyDemo {
    public static void main(String[] args) {
        Base ref = new Derived();     // 引用声明类型 = Base；运行时类型 = Derived

        System.out.println(ref.tag);   // ① 输出「base」——字段看声明类型
        ref.hello();                    // ② 输出「Derived」——方法看运行时类型
        ref.identify();                 // ③ 输出「我是 Base，运行时类型=Derived」
    }
}
```

### ASCII 图：为什么会出现这种差异

```
        编译期视角                          运行期视角
   ┌──────────────────┐              ┌──────────────────┐
   │  变量 ref         │              │  变量 ref         │
   │  声明类型: Base   │              │  声明类型: Base   │   ← 字段查找的依据
   │  ─────────────── │              │  ─────────────── │
   │  指向的引用 ──────────►┌──────────────────┐
   └──────────────────┘     │ 堆里的 Derived 对象│
                            │ ┌──────────────┐ │
                            │ │ Base.tag     │ │  ← 父类那块内存（"base"）
                            │ ├──────────────┤ │
                            │ │ Derived.tag  │ │  ← 子类自己那块（"derived"）
                            │ ├──────────────┤ │
                            │ │ hello()      │ │  ← Derived 的实现（运行时查到的是这个）
                            │ └──────────────┘ │
                            └──────────────────┘
                              ↑ 运行时类型 = Derived
```

```
访问 ref.tag   →  沿「声明类型 Base」去找字段  →  找到 Base.tag = "base"        ⇒「base」
访问 ref.hello() → 沿「声明类型 Base」找到方法签名 →  再看对象的运行时类型 Derived
                 →  实际执行 Derived.hello()                                    ⇒「Derived」
```

⚠️ **为什么方法能动态分发、字段不能？**

- **方法**在调用时，JVM 有一条指令会查对象的**实际类型**，找到那个类型上「真正覆盖了」的实现再执行——这叫**动态绑定 / 动态分派**（dynamic dispatch）。
- **字段**本质是「对象里的一块内存」，**没有「覆盖」这回事**。子类声明同名字段，只是**另开了一块内存**，两块内存并存。取哪个，取决于你的代码里写的是什么类型。

**一句话记忆**：**方法看「实际是啥」，字段看「你写的是啥」。**

### ⚠️ 常见误解澄清

| 误解 | 事实 |
|------|------|
| 「向上转型后子类特有方法就不能用了」 | ⚠️ 只能通过父类型引用调用。对象本身没变，用向下转型可以拿回来（下一节） |
| 「子类同名字段就是重写」 | ⚠️ 是**字段隐藏**，行为完全不同：字段看声明类型，方法看运行时类型 |
| 「多态 = 父类引用指向子类」 | 多态的**效果**是「同一调用不同行为」，向上转型只是实现手段 |
| 「`final` 类/方法也能重写」 | ⚠️ `final` **禁止**重写（类则禁止被继承） |
| 「`private` 方法子类能重写」 | ⚠️ `private` 对子类不可见，子类同名方法只是新方法 |

## 四、`instanceof` 与向下转型

### 向上转型的代价

```java
Animal ref = new Dog("旺财", "柴犬");
ref.fetch();    // ❌ 编译错误：找不到符号 fetch() —— Animal 类型里没有这个方法
```

因为 `ref` 的**声明类型**是 `Animal`，编译器只允许你调用 `Animal` 上有的方法。

### `instanceof`：先判断，再操作

**`instanceof`** 用来判断「这个引用指向的对象，是不是某个类型（或其子类型）的实例」，返回布尔值。

```java
if (ref instanceof Dog) {
    Dog d = (Dog) ref;    // 向下转型
    d.fetch();
}
```

### ⭐ Java 16+ 的模式匹配 `instanceof`

Java 16 起，可以在 `instanceof` 里**直接声明变量**，把「判断 + 强转」合成一步：

```java
// Java 16+ 推荐写法
if (ref instanceof Dog d) {   // 判断的同时把结果赋给 d
    d.fetch();
}
```

⚠️ Java 16 **之前**只能写成两行：

```java
if (ref instanceof Dog) {
    Dog d = (Dog) ref;
    d.fetch();
}
```

### 向下转型与 `ClassCastException`

**向下转型**（downcasting）是把父类型引用转成子类型引用，取回子类特有的能力。

```java
// 假设还有一个 Animal 的子类 Cat
Animal ref = new Dog("旺财", "柴犬");
Cat c = (Cat) ref;    // ⚠️ 运行时抛 ClassCastException —— ref 里装的是 Dog，不是 Cat
```

⚠️ **`ClassCastException`（类转换异常）是运行时异常**——编译能过，运行才炸。原因：编译器无法知道 `ref` 里到底是哪个子类，**强转是「盲目下注」**，只有运行到这一行、看清对象的真实类型才知道对不对。

```java
public class CastDemo {
    public static void main(String[] args) {
        Animal ref = new Dog("旺财", "柴犬");
        if (ref instanceof Dog d) {   // ✅ 安全：先确认再转
            d.fetch();                 // fetch() 是 Dog 独有的方法
        }
    }
}
```

⚠️ **注意顺序**：必须先 `instanceof` 判断，**再**转型。反过来写（先转型再判断）是错的——转型那行已经抛异常了。

## 五、`Object` 类：所有类的共同祖先

Java 里**每个类都隐式继承 `Object`**（`java.lang.Object`），它定义了几个人人都会用到的方法。

| 方法 | 作用 | 默认实现 | 何时需要重写 |
|------|------|---------|------------|
| `equals(Object o)` | 判断「两个对象是不是同一个值」 | 走 `==`，比引用地址 | ⚠️ 自定义值语义时**必须**同时重写 `hashCode` |
| `hashCode()` | 返回对象的哈希值（供 `HashMap`、`HashSet` 用） | 由对象地址推导 | 同上 |
| `toString()` | 转成可读字符串 | 打印 `类名@哈希值` | 几乎总要重写，方便调试 |
| `getClass()` | 返回「这个对象的运行时类型」对应的 `Class` 对象 | 不可重写（`final`） | 不需要 |
| `clone()` / `finalize()` | 复制对象 / 回收前回调 | `clone` 需 `Cloneable`；`finalize` 已废弃 | ⚠️ 都不推荐用 |

### ⚠️ `equals` 与 `hashCode` 的契约

**契约**（两条必须同时成立）：

1. `a.equals(b)` 为 `true` ⟹ `a.hashCode() == b.hashCode()`；
2. `a.equals(a)` 必须为 `true`。

⚠️ **只重写 `equals` 不重写 `hashCode` 是最经典的 bug**：对象放进 `HashSet` 时按 `hashCode` 分桶，之后你用 `equals` 判断「明明是同一个对象，却查不到」。

```java
import java.util.Objects;      // Objects 是 JDK 自带工具类

public class Student {
    private String name;
    private int age;

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                  // 先比引用，省一次字段比较
        if (!(o instanceof Student)) return false;   // 类型不对直接否
        Student other = (Student) o;
        return this.name.equals(other.name) && this.age == other.age;
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);              // 字段参与，规则与 equals 一致
    }

    @Override
    public String toString() {
        return "Student{name='" + name + "', age=" + age + "}";
    }
}
```

⭐ `instanceof` 配合模式匹配（Java 16+）可以把 `equals` 写得更短：`if (!(o instanceof Student other)) return false;`

### `getClass()`：取运行时类型

```java
Animal ref = new Dog("旺财", "柴犬");
System.out.println(ref.getClass().getSimpleName());   // "Dog" —— 运行时真实类型
System.out.println(ref.getClass().getName());          // "Dog"
```

它的典型用途是**分支判断**——但更好的做法见下一节的 `sealed` + 模式匹配 `switch`（[[java/01-入门阶段-基础教程/第02章-面向对象/2.3-抽象类与接口]]）。

## 六、组合优于继承：什么时候该用哪个

Java **只支持单继承**（一个类只能继承一个父类），但可以 `implements` 多个接口（见 [[java/01-入门阶段-基础教程/第02章-面向对象/2.3-抽象类与接口]]）。这本身就限制了继承的灵活性。

**组合**（composition）指「**把另一个类的对象作为自己的成员变量持有**，而不是继承它」。

### 继承表达 is-a，组合表达 has-a

| | 继承 | 组合 |
|---|------|------|
| 语义 | **is-a**（是一个）：`Dog is a Animal` | **has-a**（拥有一个）：`Car has a Engine` |
| 代码形态 | `class Dog extends Animal` | `class Car { private Engine engine; }` |
| 耦合度 | **高**——子类依赖父类的内部实现（父类改字段，子类可能崩） | **低**——只依赖对方**对外暴露**的方法 |
| 灵活性 | 受限：单继承，父类定死了子类的形状 | 自由：运行时可替换不同实现 |

### 一个能说明问题的例子

```java
// 用继承：想换发动机？只能改继承体系
public class Car extends Vehicle {
    // 发动机被写死在继承体系里
}
```

```java
// 用组合：想换发动机？换个对象就行
public class Car {
    private Engine engine;              // has-a：持有者

    public Car(Engine engine) {
        this.engine = engine;           // 从外部注入，可替换
    }

    public void start() {
        engine.start();
    }
}
```

组合版的好处：可以传 `ElectricEngine`，也可以传 `FuelEngine`——**运行时可替换、测试可注入 mock**。

### 选型判断

| 场景 | 选谁 |
|------|------|
| 真的「是一个」，子类能完全替代父类，且不打算频繁变 | 继承 |
| 「拥有一个」，组件可能独立变化、可能有多种实现 | ⭐ **组合** |
| 想要多继承的效果 | 接口 + 组合 |
| 父类由别人控制、你想避免被它的改动牵连 | 组合 |

⭐ **现代 Java 的主流倾向**：**优先用接口定义行为 + 组合持有实现**，把继承留给真正的 is-a 关系。原因是继承把父子类「焊死」在编译期——父类加一个字段可能让所有子类编译失败。

## 陷阱

1. **⚠️ 以为「不写修饰符就是 public」**——默认是 **package-private（同包可见）**，跨包就不可见；
2. **⚠️ 子类构造器里 `super()` 不写在一开始**——`super(...)` 必须是**第一条语句**，写前面就编译报错；
3. **⚠️ 以为子类不写构造器就「什么都不做」**——编译器会**自动插入** `super()`，所以父类**必须**有可访问的无参构造器，否则编译报错；
4. **⚠️ 把「字段隐藏」当成「方法重写」**——字段看**声明类型**（编译期定死），方法看**运行时类型**（运行期分派），这是本篇最大的坑；
5. **⚠️ 忘记给重写方法加 `@Override`**——方法名拼错时编译器不报错，静默不生效；
6. **⚠️ 以为 `private` / `final` / `static` 方法能重写**——`private` 不可见、`final` 禁止、`static` 是「隐藏」不是「重写」；
7. **⚠️ 先强转再 `instanceof`**——`ClassCastException` 在强转那行就抛了，顺序必须是「先判断，再转换」；
8. **⚠️ 只重写 `equals` 不重写 `hashCode`**——放进 `HashSet`/`HashMap` 的 key 后会「明明相等却查不到」；
9. **⚠️ 重写方法扩大了异常范围**——子类抛的异常只能是父类异常的子集，否则编译报错；
10. **⚠️ 滥用继承**——把「拥有」写成「继承」会换来高耦合；能用组合就用组合。

## 小结

- **封装**：隐藏细节，用 `private` + 受控方法保护数据的不变式
- **访问修饰符**：`private` < 默认(package-private) < `protected` < `public`
- ⚠️ **不写修饰符 = package-private（包内可见），不是 public**
- **继承**：`extends`；子类构造器必须先 `super()`（可省略则自动插入）
- **重写**：签名相同 + `@Override`；返回类型可协变、异常不得扩大、`private/final/static` 不可重写
- ⭐ **字段隐藏 vs 方法重写**：字段看**声明类型**，方法看**运行时类型**
- **向上转型**：`Animal ref = new Dog()`，调用方只认父类型；**向下转型**要靠 `instanceof`（Java 16+ 用模式匹配）保护，否则 `ClassCastException`
- **`Object`**：`equals`/`hashCode`/`toString`/`getClass`；`equals` 与 `hashCode` 必须一起重写
- **继承 is-a，组合 has-a**——优先用「接口 + 组合」
