# Java 与 Python 的差异

> **什么时候该读**：有 Python 基础，要快速上手 Java；或者想避免「把 Python 习惯照搬进 Java」的坑。

## 学习目标

读完本篇，你应当能够：

1. 说出两种语言在类型系统、并发模型、工程化上的根本差异
2. 把一段 Python 逻辑正确改写成 Java
3. 避开五个最容易照搬踩坑的点

## 一、根本差异：一句话概括

| 维度 | Java | Python |
|------|------|--------|
| 类型系统 | **静态强类型**——变量有类型，编译期检查 | 动态类型——运行时才检查 |
| 执行方式 | 编译成字节码 + JVM 解释/JIT | 解释器直接解释源码 |
| 并发 | 真多线程（无 GIL）+ 虚拟线程 | GIL 限制，多进程/异步为主 |
| 工程化 | 强约束（Maven + 接口 + 类型） | 灵活（pip + 约定 + 测试兜底） |
| 适合 | 大团队、长生命周期、高并发后端 | 小步快跑、AI/数据、脚本 |

⭐ **一句话**：Java 把错误挡在**编译期**，Python 把错误留给**运行期**——这决定了两种语言的全部行为差异。

## 二、逐项对照

### 1. 变量与类型

```python
# Python
age = 25
name = "张三"
age = "二十五"     # 合法：类型可变
```

```java
// Java
int age = 25;
String name = "张三";
age = "二十五";    // ❌ 编译报错：incompatible types
```

⚠️ Java 变量类型**一旦声明永不改变**——这是「编译期发现问题」的代价与收益。

### 2. 字符串比较（最经典的坑）

```python
a = "abc"
b = "abc"
a == b        # True——Python 的 == 比内容
```

```java
String a = "abc";
String b = new String("abc");
a == b              // ❌ false！比的是引用地址
a.equals(b)         // ✅ true，比内容
```

⚠️ **Java 里字符串比较永远用 `equals()`**，`==` 只用于基本类型（int/boolean 等）。这是 Python 开发者最常踩的坑，没有之一。

### 3. 集合对应关系

| Python | Java | 说明 |
|--------|------|------|
| `list` | `ArrayList` | 有序可重复；⚠️ 取值用 `get(i)` |
| `dict` | `HashMap` | 键值对；`getOrDefault` 对标 `dict.get(k, default)` |
| `set` | `HashSet` | 去重 |
| `tuple` | `record` / 不可变 List | Java 没有原生元组 |
| 列表推导式 | `stream().map().filter().collect()` | 写法更长，但同样声明式 |

```java
// Java 的「列表推导式」等价物
List<String> names = users.stream()
    .filter(u -> u.getAge() > 18)
    .map(User::getName)
    .collect(Collectors.toList());
```

### 4. 空值

```python
# Python
name = None
if name is None:
    ...
```

```java
String name = null;         // 合法但危险
if (name == null) { ... }   // 必须显式判空
// 或返回 Optional 强制调用方处理
Optional<String> maybe = Optional.ofNullable(name);
String v = maybe.orElse("默认值");
```

⚠️ Java 的 `null` 调用任何方法都抛 `NullPointerException`（NPE）——**最常见的线上异常**。现代写法用 `Optional` 表达「可能为空」。

### 5. 异常：受检 vs 非受检

```python
# Python：所有异常都不强制处理
try:
    f = open("x.txt")
except FileNotFoundError:
    pass
```

```java
// Java：IOException 是「受检异常」——不处理就编译不过
try {
    Files.readString(Path.of("x.txt"));
} catch (IOException e) {          // 必须 catch 或 throws 声明
    e.printStackTrace();
}
```

⭐ **受检异常（checked exception）是 Java 独有概念**：编译器强制你处理 `IOException`、`SQLException` 这类「可恢复的外部故障」；而 `NullPointerException`、`IllegalArgumentException` 是「非受检」的，不强制。

### 6. 并发模型

| | Java | Python |
|---|------|--------|
| 多线程 | ⭐ 真并行（无 GIL） | 受 GIL 限制，CPU 密集无效 |
| 高并发 | 线程池 + **虚拟线程**（Java 21+） | asyncio 协程 / 多进程 |
| 典型写法 | `ThreadPoolExecutor` / `@Async` | `asyncio.gather` / `multiprocessing` |

⭐ Java 21 的虚拟线程让「一个请求一个线程」重新可行（10 万级并发），这是 Python 的 asyncio 之外另一条路——机制见 [[java/README]] 版本基线。

### 7. 工程化

| 维度 | Java | Python |
|------|------|--------|
| 依赖管理 | Maven（`pom.xml`）/ Gradle | pip + `pyproject.toml` |
| 虚拟环境 | 不需要（依赖隔离靠版本） | venv / conda |
| 打包 | jar（可执行） | wheel / zipapp |
| 运行 | `java -jar app.jar` | `python app.py` |
| 目录约定 | `src/main/java/...` 强制 | 自由 |

## 三、五个最容易照搬踩坑的点

1. **⚠️ 用 `==` 比较字符串**——必须 `equals()`（`==` 比地址）；
2. **⚠️ 忘了声明类型**——Java 没有「动态赋值」，`var` 也只是推断，类型不随赋值改变；
3. **⚠️ 把 `list` 当数组用**——`names[0]` 编译不过，要 `names.get(0)`；
4. **⚠️ 忽略受检异常**——`IOException` 不处理编译不过，这是 Java 在「逼你考虑失败路径」；
5. **⚠️ 用 `double` 算钱**——Python 里 `round(0.1+0.2, 2)` 的坑在 Java 一样存在，金额必须 `BigDecimal`。

## 四、一段代码的对照改写

**Python**：

```python
def top_names(users, limit=3):
    adults = [u for u in users if u["age"] >= 18]
    adults.sort(key=lambda u: u["score"], reverse=True)
    return [u["name"] for u in adults[:limit]]
```

**Java**：

```java
public List<String> topNames(List<User> users, int limit) {
    return users.stream()
        .filter(u -> u.getAge() >= 18)
        .sorted(Comparator.comparingInt(User::getScore).reversed())
        .limit(limit)
        .map(User::getName)
        .collect(Collectors.toList());
}
```

⭐ 同样的语义：Python 用推导式 + `sorted`，Java 用 Stream 链——**思路完全一致，只是语法外壳不同**。

## 五、陷阱

1. **⚠️ 以为 Java 只是「语法更啰嗦的 Python」**——类型系统与异常模型改变的是**设计方式**（接口先行、编译期约束），不只是写法；
2. **⚠️ 用 Python 的「先写后补类型」习惯写 Java**——Java 必须一开始就设计好类型与接口；
3. **⚠️ 觉得 `Optional` 是万能解药**——它只适合返回值，不适合字段和参数（会层层包裹）；
4. **⚠️ 把 GIL 的经验带进来**——Java 多线程是真并行，需要考虑线程安全（`synchronized`、`ConcurrentHashMap`），Python 里「反正有 GIL」的侥幸心理在这里会出事故。

## 小结

- 根本差异：**静态强类型 + 编译期检查** vs 动态类型 + 运行期检查
- 五个必踩坑：`equals`、类型声明、`get(0)`、受检异常、金额用 `BigDecimal`
- 集合与流式处理：`List/Map` ↔ `list/dict`；Stream ↔ 推导式
- 并发：Java 真多线程 + 虚拟线程；Python 受 GIL 约束
- 迁移思路：**语义不变，语法重写**——先想清楚类型，再套 Java 写法
