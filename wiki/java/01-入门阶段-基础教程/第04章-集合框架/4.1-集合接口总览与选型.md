# 集合接口总览与选型

> **什么时候该读**：你开始处理「一组数据」——用户列表、去重的标签、键值对应的配置——但不知道该用 `List`、`Set` 还是 `Map`，也不知道 `ArrayList` 和 `HashMap` 有什么区别。
> **阅读门槛**：会写 `main` 方法、能编译运行一个 Java 程序；知道「类」和「接口」的基本区别即可，看不懂接口概念可回到 [[java/01-入门阶段-基础教程/第02章-面向对象/2.3-抽象类与接口]]。泛型写法看不懂也没关系，本篇会带一句解释。

## 一、为什么需要集合框架

在 Python 里，你用 `list`、`dict`、`set` 装一组数据，几乎不需要思考。但 Java 起步时常见的第一课是**数组**：

```java
String[] names = new String[3];   // 长度写死了 3，装不下第 4 个
```

数组有四个绕不开的局限：

| 局限 | 后果 |
|------|------|
| **长度固定** | 装满了只能 `new` 一个更大的数组，把旧数据全部复制过去 |
| **只能存同一种类型** | `Object[]` 能装任意类型，但取出来全是 `Object`，还得强制转换 |
| **API 只有下标** | 想要「按下标找到它的位置」「在中间插入」「去重」，全得自己写循环 |
| **不能装基本类型** | `int[]` 和 `Integer[]` 是两种东西，装 `int` 要先装箱成 `Integer` |

**集合框架（Collection Framework）** 就是 Java 给出的答案：JDK 1.2 起提供的一整套「容器 API」，包含三部分——

1. **接口**：规定容器「能做什么」（`List`、`Set`、`Map`……）
2. **实现类**：决定容器「怎么做得快」（`ArrayList`、`HashMap`……）
3. **工具类**：提供容器上的通用算法（`Collections.sort`……）

⭐ 集合框架最关键的设计是**面向接口编程**：代码里声明的永远是接口，接口背后可以换实现。

```java
List<String> list = new ArrayList<>();   // 左边是接口，右边是实现
// 万一发现 ArrayList 不够用，只要改右边这一行：
// List<String> list = new LinkedList<>();
```

这就是为什么 JDK 文档里所有集合类的第一行都写着「implements List」而不是别的——**接口是契约，实现是策略**。

## 二、两大顶层接口：`Collection` 与 `Map`

Java 的集合分成**两族**，而不是一棵树。

```text
Collection
├── List（有序、可重复：ArrayList / LinkedList / Vector / CopyOnWriteArrayList）
├── Set（不可重复：HashSet / LinkedHashSet / TreeSet）
└── Queue / Deque（队列双端：PriorityQueue / ArrayDeque / LinkedList）
Map（键值对，与 Collection 无继承关系）：HashMap / LinkedHashMap / TreeMap / ConcurrentHashMap
```

**第一族：`Collection`** —— 装「一个个的元素」。

`Collection` 是所有单元素容器的顶层接口，直接有三个子接口：

- **`List`（列表）**：像 Python 的 `list`。**有序、允许重复**。按位置存取是它的招牌能力。
- **`Set`（集合）**：像 Python 的 `set`。**不允许重复**，天然去重。
- **`Queue`（队列）** 与 **`Deque`（双端队列）**：排队取元素的模型。`Queue` 是先进先出（FIFO，First In First Out），`Deque`（Double Ended Queue）两头都能进出。`LinkedList` 同时实现了 `List` 和 `Deque`，所以它既是列表也是队列。

**第二族：`Map`** —— 装「键值对」。

`Map` **不继承 `Collection`**，这是很多初学者的盲点。它的每个元素不是「一个东西」，而是「一把钥匙 → 一个抽屉」：`key` 用来查找，`value` 是查到的内容。

为什么单独成族？因为 `List`/`Set` 的核心操作是「按位置或按内容找元素」，而 `Map` 的核心操作是「按键找值」——前者装的是被查的对象，后者装的是「查找规则」。`Collection` 的 `add`/`remove`/`contains` 在 `Map` 上完全没有意义，所以没必要塞进同一棵树。

⚠️ 由此推出一条实践常识：**凡是写 `Collection` 开头的参数（比如 `Collections.sort(list)`），就不能传 `Map` 进去**——编译期就会报错，这不是设计缺陷，是刻意的类型隔离。

### 集合家族与常见实现速查

| 接口 | 核心承诺 | 常见实现 |
|------|---------|---------|
| `List` | 有序、可重复、按下标存取 | `ArrayList`、`LinkedList`、`Vector`、`CopyOnWriteArrayList` |
| `Set` | 不可重复 | `HashSet`、`LinkedHashSet`、`TreeSet` |
| `Queue` / `Deque` | 按排队规则进出 | `PriorityQueue`、`ArrayDeque`、`LinkedList` |
| `Map` | 键值映射，键不可重复 | `HashMap`、`LinkedHashMap`、`TreeMap`、`ConcurrentHashMap` |

各实现类的细节分别在 [[java/01-入门阶段-基础教程/第04章-集合框架/4.2-List集合详解]]、[[java/01-入门阶段-基础教程/第04章-集合框架/4.3-Set与Map集合详解]] 展开；`HashMap` 的内部原理在 [[java/01-入门阶段-基础教程/第04章-集合框架/4.4-HashMap底层原理]]。

## 三、各接口的语义契约

「语义契约」指这个接口**承诺**的行为规则。选型时只看名字容易选错，必须看清这五项。

| 接口 | 有序性 | 允许重复 | 允许 `null` | 支持随机访问 | 迭代顺序 |
|------|-------|---------|------------|-------------|---------|
| `List`（`ArrayList`） | 有序 | ✅ 允许 | ✅ 允许 | ✅ O(1) | 插入顺序 |
| `List`（`LinkedList`） | 有序 | ✅ 允许 | ✅ 允许 | ❌ O(n) | 插入顺序 |
| `Set`（`HashSet`） | 无序 | ❌ 不允许 | ⚠️ 最多一个 | ❌ | 哈希顺序，**不保证与插入顺序一致** |
| `Set`（`LinkedHashSet`） | 有序 | ❌ 不允许 | ⚠️ 最多一个 | ❌ | **插入顺序** |
| `Set`（`TreeSet`） | 有序 | ❌ 不允许 | ❌ 自然排序下会抛 `NullPointerException` | ❌ | **排序顺序** |
| `Queue` / `Deque`（`ArrayDeque`） | 有序 | ✅ 允许 | ❌ 不允许（`null` 被内部当作哨兵） | ❌ | 先进先出 / 双端进出 |
| `Map`（`HashMap`） | 无序 | ❌ key 不重复 | ✅ 允许一个 `null` key、多个 `null` value | — | 哈希顺序，**不保证与插入顺序一致** |
| `Map`（`LinkedHashMap`） | 有序 | ❌ key 不重复 | ✅ 允许 | — | **插入顺序**（或访问顺序，见 4.3） |
| `Map`（`TreeMap`） | 有序 | ❌ key 不重复 | ❌ 自然排序下 key 不允许 `null` | — | **排序顺序** |

三个必须讲清的词：

- **随机访问（Random Access）**：能否**按下标**在**常数时间**（O(1)）取到元素。`ArrayList` 底层是数组，取第 i 个就是取第 i 格 → O(1)；`LinkedList` 底层是链表，取第 i 个必须从头走过去 → O(n)。JDK 用一个标记接口 `RandomAccess` 来表达「我支持随机访问」，高级 API（如 `Collections.binarySearch`）靠它自动切换算法。
- **迭代顺序（Iteration Order）**：用 `for (元素 : 集合)` 遍历时，元素**出现的先后顺序**。这是最容易踩坑的一项——`HashSet` 和 `HashMap` 的迭代顺序由哈希值决定，**既不是插入顺序，也不是排序顺序**，看起来「随机」但对同一批数据是稳定的。
- **允许 `null`**：能否装入 Java 的空引用。`HashMap` 能装 `null` key 和 `null` value；`TreeMap`/`TreeSet` 在自然排序下不能，因为排序需要拿元素跟别人比大小，`null` 没法比。`ArrayDeque` 不能装 `null`，因为它内部用 `null` 标记队列边界。

## 四、⭐ 选型决策表

需求 → 选择，这是本篇最实用的一张表。按需求找到行，直接取右列的类。

| 你的需求 | 选它 | 为什么 |
|---------|------|--------|
| **按下标随机取元素**（如取第 3 个用户） | `ArrayList` | 数组结构，O(1) 取值 |
| **频繁在中间增删** | `LinkedList` | 链表结构，中间插入只需改指针，不用搬移后续元素 |
| **列表 + 去重** | `HashSet` | 哈希去重，平均 O(1) |
| **去重 + 保持插入顺序** | `LinkedHashSet` | 内部用链表记录插入次序 |
| **去重 + 按元素大小排序** | `TreeSet` | 红黑树，元素天然有序（详见 4.3） |
| **键值映射**（按键查值） | `HashMap` | 哈希表，平均 O(1) 存取 |
| **键值映射 + 保持插入顺序** | `LinkedHashMap` | 在 `HashMap` 基础上多维护一条顺序链表 |
| **键值映射 + 按 key 排序** | `TreeMap` | key 有序的红黑树 |
| **多线程并发读写同一个映射** | `ConcurrentHashMap` | 线程安全的 `Map`（详见 [[java/02-中段阶段-专题精讲/并发编程/05-并发容器与虚拟线程]]） |
| **多线程并发读多写少的列表** | `CopyOnWriteArrayList` | 写时复制，读不加锁（详见 4.2） |
| **按优先级取元素**（任务队列） | `PriorityQueue` | 每次取出优先级最高的元素 |
| **当栈用 / 双端进出** | `ArrayDeque` | 栈和队列的统一实现，性能优于 `LinkedList` |

### 决策的三条经验规则

1. **默认选 `HashMap` + `ArrayList`**。绝大多数业务代码用这两个就够了，拿不准时不要一上来就上 `TreeMap` 或 `LinkedList`——它们更慢且约束更多。
2. **需要排序时不要手动排序容器**。用 `TreeMap`/`TreeSet`，或用 `List` + `Collections.sort` 一次排好；不要在循环里反复排序。
3. ⚠️ **`LinkedList` 被严重高估**。它只有在「已经拿到迭代器位置、紧接着在中间插入」这种场景才真正快；而实际业务里更常见的是「按下标遍历 + 随机访问」，那正是 `ArrayList` 的主场。**不确定就用 `ArrayList`**。

## 五、`Collections` 工具类

`Collections` 是 `java.util` 下的工具类（注意复数），提供一组操作集合的静态方法。它和 `Collection` 接口是两回事：前者是「工具箱」，后者是「规范」。

| 方法 | 作用 | 注意 |
|------|------|------|
| `Collections.sort(list)` | 原地升序排序 | 会**改动原列表**；元素必须可比较（实现 `Comparable`）或给 `list.sort(comparator)` 传比较器 |
| `Collections.reverse(list)` | 原地反转 | 同样改动原列表 |
| `Collections.shuffle(list)` | 原地随机打乱 | 常用「随机抽签」；⚠️ 每次结果不同，且会改动原列表 |
| `Collections.max(list)` / `min(list)` | 返回最大 / 最小元素 | 同样依赖可比较性；空集合会抛 `NoSuchElementException` |
| `Collections.unmodifiableList(list)` | 返回**只读视图** | 不是拷贝，原列表改了它跟着改；但不能通过它改内容 |
| `Collections.synchronizedList(list)` | 返回**加锁包装**的列表 | 让单个方法调用线程安全，但**遍历时仍要手动 `synchronized (list)`** |
| `Collections.binarySearch(list, key)` | 二分查找下标 | ⚠️ **列表必须已排序**，否则结果无意义（详见 4.2） |
| `Collections.emptyList()` | 返回空列表 | 常用于「无结果」返回值，避免返回 `null` |

```java
import java.util.*;

public class CollectionsDemo {
    public static void main(String[] args) {
        List<Integer> nums = new ArrayList<>(List.of(3, 1, 4, 1, 5, 9, 2, 6));

        Collections.sort(nums);
        System.out.println(nums);            // [1, 1, 2, 3, 4, 5, 6, 9]

        Collections.reverse(nums);
        System.out.println(nums);            // [9, 6, 5, 4, 3, 2, 1, 1]

        System.out.println(Collections.max(nums));   // 9
        System.out.println(Collections.min(nums));   // 1

        // 只读视图：底层还是同一个 list
        List<Integer> readOnly = Collections.unmodifiableList(nums);
        nums.add(100);                        // 改原列表
        System.out.println(readOnly.size());  // 9 —— 视图跟着变了
        // readOnly.add(1);                   // ❌ UnsupportedOperationException

        Collections.shuffle(nums);
        System.out.println(nums);            // 顺序被打乱
    }
}
```

⚠️ **`unmodifiableList` 是「只读视图」不是「不可变拷贝」**——这两者的区别在下一节展开，是高频面试点。

## 六、⭐ 创建列表的三种方式：`Arrays.asList` vs `List.of` vs `new ArrayList<>()`

这三个都能造出一个 `List`，但**可变性和长度是否固定完全不同**。

| 写法 | 长度 | 能否 `set` 改元素 | 能否 `add`/`remove` | 能否存 `null` | 与原数组是否共享 |
|------|-----|----------------|------------------|-------------|----------------|
| `Arrays.asList(arr)` | **固定**（= 数组长度） | ✅ 可以 | ❌ 抛 `UnsupportedOperationException` | ✅ 可以 | ✅ **共享**，改一个另一个跟着变 |
| `List.of(a, b)`（Java 9+） | **固定** | ❌ 抛异常 | ❌ 抛异常 | ❌ 抛 `NullPointerException` | — |
| `new ArrayList<>(...)` | **可变** | ✅ 可以 | ✅ 可以 | ✅ 可以 | ❌ 独立副本 |

三段代码，一个比一个严格：

```java
import java.util.*;

public class ListCreationDemo {
    public static void main(String[] args) {
        // ① Arrays.asList：固定长度视图，改元素会改到原数组
        String[] arr = {"A", "B"};
        List<String> asList = Arrays.asList(arr);
        asList.set(0, "X");
        System.out.println(arr[0]);        // X —— 原数组被改了
        // asList.add("C");               // ❌ UnsupportedOperationException
        // asList.remove("A");            // ❌ UnsupportedOperationException

        // ② List.of：彻底不可变，连 set 都不行，也不接受 null
        List<String> of = List.of("A", "B");
        // of.set(0, "X");                // ❌ UnsupportedOperationException
        // of.add("C");                    // ❌ UnsupportedOperationException
        // List.of(null);                  // ❌ NullPointerException

        // ③ new ArrayList<>()：真正的可变集合
        List<String> mutable = new ArrayList<>(List.of("A", "B"));
        mutable.add("C");
        mutable.remove("A");
        System.out.println(mutable);      // [B, C]
    }
}
```

⚠️ **`Arrays.asList` 的核心陷阱**：它支持 `set`（因为长度不变，改元素不破坏结构），但**不支持 `add`/`remove`**（这两个会改变长度）。新手常见写法是「`Arrays.asList` 返回的 list 可以随便改」——错。`Arrays.asList` 存在的典型场景是**给现有数组套一个 List 视图**去传给只读 API，不是拿来当可变集合用。

⭐ **`List.of` 的两个限制要记牢**：
- **不可变**——不是「定长」，是「连元素都改不了」；
- **不允许 `null`**——`List.of(null)` 直接抛 `NullPointerException`。而 `Arrays.asList(null)` 是合法的。

（`List.of` 是 Java 9 引入的；如果项目要兼容 Java 8，用 `Arrays.asList` 或 `Collections.unmodifiableList`。）

## 七、可变集合 vs 不可变集合

**不可变集合（Immutable Collection）** 指创建后**内容永不改变**——不能增、不能删、也不能改元素。好处是：可以安全地共享给多线程、可以安全地当作常量、可以放心地作为方法参数传出去（别人改不了你的东西）。

三种获得不可变集合的方式，语义不同：

| 方式 | 是拷贝还是视图 | 底层改了会怎样 |
|------|--------------|--------------|
| `List.of(...)` / `Map.of(...)` | 独立数据（自己就是数据源） | 无关 |
| `Collections.unmodifiableList(list)` | **视图**，包着原集合 | ⚠️ **原集合改了，它跟着变** |
| `new ArrayList<>(list)` 后包 `unmodifiableList` | 视图，但包的是**副本** | 无关 |

```java
import java.util.*;

public class ImmutabilityDemo {
    public static void main(String[] args) {
        List<String> source = new ArrayList<>(List.of("A", "B"));

        // 视图型：看起来不可变，实际跟着源走
        List<String> view = Collections.unmodifiableList(source);
        source.add("C");
        System.out.println(view);            // [A, B, C] —— 变了！只是没人能通过 view 去改

        // 快照型：真正的不可变
        List<String> snapshot = Collections.unmodifiableList(new ArrayList<>(source));
        source.add("D");
        System.out.println(snapshot);        // [A, B, C] —— 不变
    }
}
```

**取舍原则**：

- **对外暴露的 API 返回值、跨线程传递的数据、定义为常量的数据** → 用不可变集合（`List.of` / `Map.of`）。这能挡掉「别人偷偷改了我的数据」这类极难排查的 bug。
- **方法内部要反复增删的数据** → 用可变集合（`new ArrayList<>()`），最后一步再转成不可变返回。
- ⚠️ **不要用 `unmodifiableList` 假装「线程安全」**——它只是不许你通过这个引用改，原列表被别的线程改，它照样变。

## 八、与 Python 的对照

如果你会 Python，这一节能把已有直觉直接搬过来。

| Python | Java 对应 | 关键差异 |
|--------|-----------|---------|
| `list` | `List` / `ArrayList` | 取值用 `get(i)` 而非 `x[i]`；⚠️ Java 的 `List` 接口不含 `dict` 的键值语义 |
| `dict` | `Map` / `HashMap` | `dict[k]` → `map.get(k)`（返回 `null` 而非抛错）；`d.get(k, default)` → `map.getOrDefault(k, default)` |
| `set` | `Set` / `HashSet` | 基本一致；Java 的 `HashSet` 迭代顺序不保证与插入一致 |
| `tuple` | `record`（Java 16+）或不可变 `List` | Java 没有原生元组，见 [[java/01-入门阶段-基础教程/第02章-面向对象/2.4-内部类与Lambda表达式]] |
| 列表推导式 `[f(x) for x in xs]` | `xs.stream().map(f).collect(...)` | 写法更长，语义一致 |
| `sorted(xs, key=f)` | `xs.sort(Comparator.comparing(f))` | Java 用 `Comparator`（比较器）表达排序规则 |
| `collections.OrderedDict` | `LinkedHashMap` | Python 3.7+ 的 `dict` 本身就保序，Java 的 `HashMap` **不保序** |
| `collections.Counter` | `HashMap` + `merge` | 见 4.3 的 `merge` 用法 |
| `len(xs)` | `xs.size()` | |

```python
# Python
counts = {}
for word in words:
    counts[word] = counts.get(word, 0) + 1
```

```java
// Java
Map<String, Integer> counts = new HashMap<>();
for (String word : words) {
    counts.merge(word, 1, Integer::sum);   // 一行顶 Python 两行
}
```

⚠️ **最容易照搬错的不是语法，是「顺序」**：Python 的 `dict` 从 3.7 起保证插入顺序，Java 的 `HashMap` **不保证**。如果你依赖「按插入顺序输出」，必须显式改用 `LinkedHashMap`。

---

## 陷阱

1. **⚠️ 以为 `Map` 是 `Collection` 的子类**——`Map` 不继承 `Collection`；把 `Map` 传给 `Collections.sort` 这类收 `Collection` 的方法，编译期就会报错；
2. **⚠️ 用 `Arrays.asList` 的结果当可变列表**——固定长度，`add`/`remove` 全抛 `UnsupportedOperationException`，只有 `set` 能用；
3. **⚠️ 以为 `List.of` 只是「定长」**——它是彻底不可变，连 `set` 都不行，而且**不接受 `null`**；
4. **⚠️ 以为 `Collections.unmodifiableList` 是不可变集合**——它是**视图**，底层原列表一改它就跟着变；真正要隔离得先复制再包装；
5. **⚠️ 依赖 `HashSet`/`HashMap` 的迭代顺序**——它是哈希顺序，不是插入顺序；需要插入顺序请用 `LinkedHashSet`/`LinkedHashMap`；
6. **⚠️ 用 `LinkedList` 替代 `ArrayList`「因为要频繁插入」**——绝大多数场景 `ArrayList` 更快；`LinkedList` 真正占优的场景非常窄（详见 4.2）；
7. **⚠️ 在多线程里直接用 `ArrayList`/`HashMap`**——它们**不是线程安全的**；并发场景请用 `ConcurrentHashMap` 等并发容器（见 [[java/02-中段阶段-专题精讲/并发编程/05-并发容器与虚拟线程]]）。

## 小结

- 集合框架 = **接口定契约 + 实现定性能 + 工具类给算法**，变量类型永远写接口
- 两族分家：`Collection` 装元素（`List`/`Set`/`Queue`），`Map` 装键值对，**无继承关系**
- 选型五问：**有序吗？允许重复吗？允许 null 吗？按下标取吗？迭代顺序是什么？**
- 默认组合：`ArrayList` + `HashMap`；要排序用 `TreeMap`/`TreeSet` 或 `Collections.sort`；要保序用 `LinkedHashMap`/`LinkedHashSet`
- 三种造 List 的方式：`Arrays.asList` 定长视图（可 `set`）、`List.of` 彻底不可变且禁 `null`、`new ArrayList<>()` 完全可变
- 不可变集合用于对外暴露与跨线程；⚠️ `unmodifiableList` 是视图不是快照
