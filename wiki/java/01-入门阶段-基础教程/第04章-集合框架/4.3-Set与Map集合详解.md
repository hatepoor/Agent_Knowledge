# Set 与 Map 集合详解

> **什么时候该读**：你需要「去重」「排序」「按键查找」这三种能力中的任意一种，或者想知道 `HashMap` 的 `keySet()`、`values()`、`entrySet()` 到底返回的是什么。

## 一、`Set` 家族：去重的三种方式

**去重的判定依据**是 `equals()` 与 `hashCode()` 这一对组合（原理见 4.4）：两个对象「相等」当且仅当 `equals()` 返回 `true`。对 `Set` 来说，**已经存在的元素再 `add` 一次不会增加集合大小**。

三个实现类的差别，本质上就是**「顺序」这一项**的不同选择。

| 实现 | 底层结构 | 迭代顺序 | 典型用途 |
|------|---------|---------|---------|
| `HashSet` | `HashMap` 的 key 集合 | **哈希顺序**（不保证与插入顺序一致） | 纯去重、成员判断 |
| `LinkedHashSet` | `LinkedHashMap` 的 key 集合 | **插入顺序** | 去重但要保留录入顺序 |
| `TreeSet` | `TreeMap` 的 key 集合 | **排序顺序** | 去重 + 范围查询 |

### 1. `HashSet`：底层就是 `HashMap` 的 key 集合

`HashSet` 内部持有一个 `HashMap`，你 `add` 的元素被当作这个 `HashMap` 的 **key** 存进去，value 统一是一个无意义的占位对象。查一个元素在不在集合里，走的是 `HashMap` 的 `containsKey`。

```java
import java.util.*;

public class HashSetDemo {
    public static void main(String[] args) {
        Set<String> set = new HashSet<>();
        System.out.println(set.add("Tom"));    // true —— 之前没有
        System.out.println(set.add("Tom"));    // false —— 重复了，集合没变
        System.out.println(set.size());        // 1

        // 去重统计：把重复项合并
        List<String> raw = List.of("a", "b", "a", "c", "b");
        Set<String> unique = new HashSet<>(raw);
        System.out.println(unique);            // [a, b, c] —— 顺序不保证
    }
}
```

### 2. `LinkedHashSet`：多维护一条插入顺序链

`LinkedHashSet` 内部用的是 `LinkedHashMap`——它比 `HashMap` 多一条**双向链表**把 key 按插入顺序串起来。所以去重的同时**保留了首次出现的顺序**。

```java
Set<String> set = new LinkedHashSet<>(List.of("c", "a", "b", "a"));
System.out.println(set);      // [c, a, b] —— 保持首次插入顺序
```

### 3. `TreeSet`：红黑树实现，元素必须可比较

`TreeSet` 底层是 `TreeMap`——一棵**红黑树（Red-Black Tree）**。红黑树是一种**平衡二叉搜索树**，它通过特定的着色规则保证树高不超过 `2·log(n)`，从而让「查找 / 插入 / 删除」都稳定在 **O(log n)**。

> 关于红黑树的具体旋转与变色规则，本篇不展开——那属于数据结构专题。**你需要记住的只有一句：它是一棵有序的平衡二叉搜索树，保证查询 O(log n)。** 本篇只关心它带来的能力：**元素天然有序 + 支持范围查询**。

⚠️ **`TreeSet` 的元素必须能互相比较大小**，否则运行期抛 `ClassCastException`（类型转换异常）。Java 提供两种方式：

| 方式 | 做法 | 说明 |
|------|------|------|
| **自然排序**（`Comparable`） | 元素类实现 `Comparable` 接口 | `String`、`Integer`、`Double` 等 JDK 内置类都已实现；`compareTo` 返回负数表示"我小"，正数表示"我大"，0 表示相等 |
| **外部排序**（`Comparator`） | 构造 `TreeSet` 时传入比较器 | 适合「元素类不能改」或「同一类要有多种排序规则」的场景 |

```java
import java.util.*;

public class TreeSetDemo {
    public static void main(String[] args) {
        // ① 自然排序：String 已经实现了 Comparable
        TreeSet<String> names = new TreeSet<>(List.of("bob", "alice", "charlie"));
        System.out.println(names);                 // [alice, bob, charlie] —— 自动排好

        // ② 外部排序：按字符串长度排
        TreeSet<String> byLen = new TreeSet<>(Comparator.comparingInt(String::length));
        byLen.addAll(List.of("bb", "a", "ccc"));
        System.out.println(byLen);                  // [a, bb, ccc]

        // ③ 自定义对象：用 Comparable
        TreeSet<Student> byScore = new TreeSet<>();
        byScore.add(new Student("Tom", 92));
        byScore.add(new Student("Amy", 88));
        System.out.println(byScore.first());        // Amy —— 分数最低的排第一
    }

    static class Student implements Comparable<Student> {
        final String name;
        final int score;
        Student(String name, int score) { this.name = name; this.score = score; }

        @Override
        public int compareTo(Student o) {
            return Integer.compare(this.score, o.score);   // ⚠️ 必须实现
        }
        @Override
        public String toString() { return name + "(" + score + ")"; }
    }
}
```

⚠️ **两个必知细节**：

1. **`compareTo` 返回 0 会被当成「相等」**——`TreeSet` 会认为这两个元素是同一个，第二个 `add` 不会成功。所以 `compareTo` 只比较了 `name` 而忽略了 `score`，就会导致分数丢失；
2. ⚠️ **`compareTo` 实现不严谨会直接破坏集合**——如果 `compareTo(a, b)` 返回正数但 `compareTo(b, a)` 也返回正数，树的顺序就乱了，后续 `get`/`remove` 会找错位置。规范做法是用 `Integer.compare`、`a.name.compareTo(b.name)` 这类**自带对称性**的写法。

⚠️ **`TreeSet` 不接受 `null`**——排序需要拿元素跟别人比大小，`null` 没法比，`add(null)` 会抛 `NullPointerException`。（`HashSet` 可以放一个 `null`。）

### `TreeSet` 的范围查询

这是 `TreeSet` 最值钱的能力——因为它内部有序，所以能问出「比 X 大的最小值」这类问题。

| 方法 | 含义 | 找不到时 |
|------|------|---------|
| `first()` | 最小元素 | 空集合抛 `NoSuchElementException` |
| `last()` | 最大元素 | 同上 |
| `floor(e)` | **小于等于** e 的最大元素 | 返回 `null` |
| `ceiling(e)` | **大于等于** e 的最小元素 | 返回 `null` |
| `higher(e)` | 严格大于 e 的最小元素 | 返回 `null` |
| `lower(e)` | 严格小于 e 的最大元素 | 返回 `null` |
| `subSet(from, to)` | 区间 `[from, to)` 子集（**左闭右开**） | — |
| `headSet(to)` | 所有小于 `to` 的元素 | — |
| `tailSet(from)` | 所有大于等于 `from` 的元素 | — |

```java
TreeSet<Integer> scores = new TreeSet<>(List.of(30, 50, 70, 90, 95));
System.out.println(scores.floor(72));      // 70   —— ≤72 的最大
System.out.println(scores.ceiling(72));    // 90   —— ≥72 的最小
System.out.println(scores.higher(90));     // 95   —— 严格大于 90 的最小
System.out.println(scores.subSet(50, 90)); // [50, 70] —— 含 50 不含 90
```

## 二、`Map` 家族：键值映射的三种选择

`Map` 的接口方法：`get`、`put`、`remove`、`containsKey`、`containsValue`、`size`、`isEmpty`、`keySet`、`values`、`entrySet`。

| 实现 | key 的顺序 | value 有序？ | 底层结构 |
|------|-----------|-------------|---------|
| `HashMap` | 无序（哈希顺序） | 无序 | 哈希表（数组 + 链表 + 红黑树） |
| `LinkedHashMap` | **插入顺序**（可切换为访问顺序） | 无序 | 哈希表 + 双向链表 |
| `TreeMap` | **排序顺序** | 无序 | 红黑树 |

### 1. `HashMap`：默认选择

```java
import java.util.*;

public class HashMapDemo {
    public static void main(String[] args) {
        Map<String, Integer> ages = new HashMap<>();
        ages.put("Tom", 25);
        ages.put("Amy", 30);
        ages.put("Tom", 26);            // 同 key 覆盖 → 最终 Tom = 26

        System.out.println(ages.get("Tom"));        // 26
        System.out.println(ages.get("Nobody"));     // null —— key 不存在返回 null
        System.out.println(ages.containsKey("Amy"));  // true
        System.out.println(ages.containsValue(30));   // true —— 按值找，比按 key 找慢
        System.out.println(ages.size());             // 2

        Integer removed = ages.remove("Amy");
        System.out.println(removed + " → " + ages); // 30 → {Tom=26}
    }
}
```

⚠️ **`get` 返回 `null` 有两种含义**：「key 不存在」和「key 存在但值就是 `null`」。要区分，用 `containsKey`：

```java
Map<String, String> m = new HashMap<>();
m.put("k", null);
System.out.println(m.get("k"));              // null
System.out.println(m.containsKey("k"));      // true  —— 键确实在
```

### 2. `LinkedHashMap`：插入顺序 + LRU

`LinkedHashMap` 在 `HashMap` 的哈希表之外，多维护一条**双向链表**记录 key 的顺序。

⭐ **关键设计：顺序可以通过构造参数切换成「访问顺序」（access order）**。

```java
// 第三个参数 true = 按访问顺序重排（最近访问的排到末尾）
LinkedHashMap<String, Integer> lru = new LinkedHashMap<>(16, 0.75f, true);
lru.put("a", 1);
lru.put("b", 2);
lru.put("c", 3);

lru.get("a");                 // 访问 a → 它被移到末尾
System.out.println(lru.keySet());   // [b, c, a] —— 访问顺序变了
```

把「访问顺序」和「超过容量就淘汰最久未访问的」组合起来，就是一个标准的 **LRU 缓存（Least Recently Used，最近最少使用缓存）**——这需要重写 `removeEldestEntry` 方法：

```java
import java.util.*;

public class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LruCache(int capacity) {
        super(16, 0.75f, true);        // accessOrder = true
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;      // 超出容量就淘汰最久未访问的
    }

    public static void main(String[] args) {
        LruCache<String, Integer> cache = new LruCache<>(2);
        cache.put("a", 1);
        cache.put("b", 2);
        cache.put("c", 3);              // 超容量 → 淘汰 "a"
        System.out.println(cache.keySet());   // [b, c]
    }
}
```

### 3. `TreeMap`：按键排序 + 范围查询

`TreeMap` 和 `TreeSet` 一样，底层是红黑树，因此：

- key 必须可比较（实现 `Comparable` 或传入 `Comparator`），否则抛 `ClassCastException`；
- key **不允许 `null`**；
- 支持与 `TreeSet` 对应的范围查询：`firstKey()`、`lastKey()`、`floorKey()`、`ceilingKey()`、`higherKey()`、`lowerKey()`、`subMap()`、`headMap()`、`tailMap()`。

```java
TreeMap<String, Integer> scores = new TreeMap<>(Map.of("amy", 90, "bob", 75, "cid", 88));
System.out.println(scores.firstKey());      // amy
System.out.println(scores.floorKey("cz"));  // cid —— ≤"cz" 的最大 key
System.out.println(scores.headMap("bob"));  // {amy=90}
```

## 三、⭐ `Map` 的三种遍历方式

`Map` 不实现 `Iterable`，所以**不能直接用 `for (元素 : map)`**。必须先「拆」成三个集合视图之一。

| 方式 | 写法 | 得到什么 | 场景 |
|------|------|---------|------|
| 按 key 遍历 | `for (K k : map.keySet())` | key 的集合 | 只需要 key |
| 按 value 遍历 | `for (V v : map.values())` | value 的集合 | 只需要 value |
| 按键值对遍历 | `for (Map.Entry<K,V> e : map.entrySet())` | `Entry` 集合 | ⭐ **同时需要 key 和 value** |

**`Map.Entry<K,V>`** 是 `Map` 里定义的一个嵌套接口，一个 `Entry` 表示一组键值对，常用方法：`getKey()`、`getValue()`、`setValue(v)`（**通过它改 value 会同步改回 map**）。

⭐ **推荐 `entrySet()`**，因为：

1. `keySet()` 遍历时，若循环体内要 `map.get(key)` 取值，会**多做一次哈希查找**；`entrySet()` 一次遍历就同时拿到 key 和 value；
2. `values()` 是**弱集合视图**——它不是值的拷贝，而是 map 的一层「窗户」，**map 变了它跟着变**（详见下一节）；
3. `keySet()` 同样不是拷贝，`keySet().remove(x)` **会真的把 x 从 map 里删掉**。

### ⚠️ 视图（View）不是拷贝

⭐ 这是 `Map` 最容易被误解的一点。

```java
import java.util.*;

public class MapViewDemo {
    public static void main(String[] args) {
        Map<String, Integer> map = new HashMap<>(Map.of("a", 1, "b", 2));

        Set<String> keys = map.keySet();
        Collection<Integer> values = map.values();

        // ⚠️ 通过 keySet 删除 key → 真的从 map 里删掉了
        keys.remove("a");
        System.out.println(map);          // {b=2} —— map 被改了！

        // 视图是"活"的：map 变了，视图跟着变
        map.put("c", 3);
        System.out.println(values);       // [2, 3] —— 自动包含新值
        System.out.println(keys.size());  // 2
    }
}
```

⚠️ 后果与对策：

- **不要**把 `keySet()` 当成「key 的快照」保存起来然后指望它不变；
- 需要独立副本时显式复制：`new ArrayList<>(map.keySet())`；
- ⚠️ **遍历 `keySet()` 时不要在里面 `map.remove(key)`**——这属于「遍历时结构性修改」，会触发 4.2 讲过的 fail-fast 机制，抛 `ConcurrentModificationException`。

## 四、⭐ `computeIfAbsent` / `merge` / `putIfAbsent` / `getOrDefault`

这四个方法是 Java 8 起 `Map` 新增的「计算型 API」，它们把「先查再写」压缩成一次调用，**并且在并发场景下是原子的**。

| 方法 | 键存在时 | 键不存在时 | 原子性 |
|------|---------|-----------|--------|
| `getOrDefault(k, def)` | 返回原值 | 返回 `def`（**不写入 map**） | ❌ 只是读 |
| `putIfAbsent(k, v)` | 返回原值，**不覆盖** | 写入 `v`，返回 `null` | ✅ |
| `computeIfAbsent(k, fn)` | 返回原值，**不调用** `fn` | 用 `fn` 算出值写入 | ✅ |
| `merge(k, v, fn)` | 用 `fn(旧值, v)` 合并后写入 | 直接写入 `v` | ✅ |

```java
import java.util.*;

public class ComputeApiDemo {
    public static void main(String[] args) {
        Map<String, List<String>> groups = new HashMap<>();

        // computeIfAbsent：键不存在时才计算并写入
        for (String word : List.of("apple", "avocado", "banana", "blueberry")) {
            groups.computeIfAbsent(word.substring(0, 1), k -> new ArrayList<>())
                  .add(word);
        }
        System.out.println(groups);      // {a=[apple, avocado], b=[banana, blueberry]}

        // merge：累加
        Map<String, Integer> counts = new HashMap<>();
        for (String w : List.of("a", "b", "a", "c", "a")) {
            counts.merge(w, 1, Integer::sum);
        }
        System.out.println(counts);       // {a=3, b=1, c=1}

        // getOrDefault：只读，不写入
        Map<String, String> cfg = new HashMap<>();
        System.out.println(cfg.getOrDefault("theme", "dark"));   // dark
        System.out.println(cfg.size());                          // 0 —— 没有被写入

        // putIfAbsent：只在不存在时写入
        Map<String, String> m = new HashMap<>();
        m.put("k", "old");
        m.putIfAbsent("k", "new");
        System.out.println(m.get("k"));    // old —— 没有被覆盖
    }
}
```

### 原子性差异（重要）

⭐ **「原子性」= 一个操作要么完整执行、要么完全没执行，中间不会被其他线程插进来。**

| 写法 | 单线程 | 多线程 |
|------|-------|--------|
| `if (!map.containsKey(k)) map.put(k, v);` | ✅ 正确 | ❌ **不安全**：两个线程可能都判定「不存在」，然后互相覆盖 |
| `map.putIfAbsent(k, v);` | ✅ 正确 | ✅ **原子**：只有一个线程能写进去 |
| `map.computeIfAbsent(k, fn);` | ✅ 正确 | ✅ **原子**：函数对同一个 key **只会被调用一次** |
| `map.merge(k, v, fn);` | ✅ 正确 | ✅ **原子**：读-改-写整个过程不会被打断 |

⚠️ **注意**：这里的「原子」只在**底层是 `ConcurrentHashMap`** 时才成立。**普通 `HashMap` 没有任何原子性保证**——`HashMap` 本身就不是线程安全的，多线程共用一个 `HashMap` 可能导致数据丢失、链表成环（Java 7 及更早）、甚至 `ConcurrentModificationException`。

💡 **选型建议**：

- **统计计数 / 分组** → `merge`（最直观）；
- **按 key 懒初始化一个复杂对象**（避免每次 `new`） → `computeIfAbsent`；
- **「没有才写，有就别动」** → `putIfAbsent`；
- **「没有就给个默认值，但别写进 map」** → `getOrDefault`；
- ⚠️ **`computeIfAbsent` 的函数里不要再去操作同一个 map**——会死锁或抛异常；函数应该纯粹地「算一个值出来」。

⚠️ **`computeIfAbsent` 返回 `null` 时不会写入**——这是设计如此，不要用它做「缓存 null 值」。

## 五、完整示例

```java
import java.util.*;

public class SetMapPractice {
    public static void main(String[] args) {
        // ① 用 TreeMap 做有序分组
        TreeMap<Integer, List<String>> byLength = new TreeMap<>();
        for (String w : List.of("bb", "a", "ccc", "dd")) {
            byLength.computeIfAbsent(w.length(), k -> new ArrayList<>()).add(w);
        }
        System.out.println(byLength);   // {1=[a], 2=[bb, dd], 3=[ccc]}

        // ② 用 LinkedHashMap 保持插入顺序
        LinkedHashMap<String, Integer> stock = new LinkedHashMap<>();
        stock.put("Tom", 3);
        stock.put("Amy", 5);
        stock.put("Bob", 2);
        System.out.println(stock);      // {Tom=3, Amy=5, Bob=2}

        // ③ 推荐用 entrySet 遍历
        stock.forEach((k, v) -> System.out.println(k + " has " + v));

        // ④ Set 判断成员，比 List.contains 快得多
        Set<String> allowed = new HashSet<>(List.of("admin", "root"));
        System.out.println(allowed.contains("admin"));   // true
    }
}
```

## 陷阱

1. **⚠️ 以为 `TreeSet`/`TreeMap` 元素不比较只是「不排序」**——是**直接抛 `ClassCastException`**，而且是运行期才抛，编译期无感知；
2. **⚠️ `compareTo` 只比较部分字段**——返回 0 会被当作相等，`TreeSet` 认为重复、`TreeMap` 会**覆盖原值**；
3. **⚠️ 往 `TreeSet`/`TreeMap` 里放 `null`**——抛 `NullPointerException`（`HashSet`/`HashMap` 可以放）；
4. **⚠️ 以为 `keySet()`/`values()` 是拷贝**——它们是**视图**，map 改动它们跟着变；`keySet().remove(k)` **会真的删掉 map 里的键**；
5. **⚠️ 遍历 `keySet()` 的同时 `map.remove(k)`**——触发 fail-fast，抛 `ConcurrentModificationException`；
6. **⚠️ 在 `HashMap` 里用可变对象当 key**——key 的哈希值变了就再也找不到了（细节见 4.4 的 `equals`/`hashCode` 契约）；
7. **⚠️ 用 `if (!containsKey(k)) put(k, v)` 做「检查再写入」**——多线程下会互相覆盖，用 `putIfAbsent`/`computeIfAbsent` 替代；
8. **⚠️ 在 `computeIfAbsent` 的函数里操作同一个 map**——会死锁或抛异常，函数应纯粹；
9. **⚠️ 依赖 `HashMap`/`HashSet` 的迭代顺序**——它是哈希顺序，不是插入顺序，要顺序用 `LinkedHashMap`/`LinkedHashSet`。

## 小结

- `Set` 三兄弟只差「顺序」：`HashSet` 哈希序、`LinkedHashSet` 插入序、`TreeSet` 排序序；前两者底层是 `HashMap`/`LinkedHashMap` 的 key 集合
- `TreeSet`/`TreeMap` 是**红黑树**（平衡二叉搜索树，查询 O(log n)）；元素必须可比较，否则 `ClassCastException`；不支持 `null`
- `TreeSet`/`TreeMap` 的价值在**范围查询**：`floor`/`ceiling`/`higher`/`lower`/`subSet`
- `Map` 遍历三种方式，⭐ **推荐 `entrySet()`**；`keySet()`/`values()` 是**视图不是拷贝**
- ⭐ **`get` 返回 `null` 有两种含义**，用 `containsKey` 区分
- `LinkedHashMap` 的 `accessOrder=true` + 重写 `removeEldestEntry` = LRU 缓存
- ⭐ **计算型 API**：`merge` 计数、`computeIfAbsent` 懒初始化、`putIfAbsent` 不覆盖、`getOrDefault` 只读默认；原子性只在 `ConcurrentHashMap` 上成立

## 练习

1. 写一个方法 `Map<Character, Integer> countChars(String s)`，用 `merge` 实现字符计数；再用 `get`+`put` 实现一遍，对比代码量。
2. 用 `TreeSet<Integer>` 存一组成绩，实现一个方法返回「及格（≥60）的人数」和「最高分」；思考如果不排序能不能做，代价是什么。
3. 自定义 `Employee` 类（字段 `id`、`name`、`salary`），用 `TreeSet` 存 5 个员工，分别用「实现 `Comparable`」和「传 `Comparator`」两种方式排序，对比可读性。
4. 验证 `keySet()` 是视图：创建 `keys = map.keySet()`，然后 `map.put("new", ...)`，观察 `keys` 是否自动包含新 key；再试试 `keys.remove(...)` 后 map 的变化。
5. 用 `computeIfAbsent` 实现「按首字母分组单词」，再用 `merge` 实现「按首字母统计词频」，对比两者的数据结构差异。
6. 写一个 `LinkedHashMap` 实现的 LRU 缓存，容量 3，依次放入 a/b/c/d，验证 d 进来后 a 被淘汰；再 `get` 一次 b，验证 b 变成最近使用。
7. 思考题：`ConcurrentHashMap` 真的完全线程安全吗？`map.get(k)` 之后再 `map.put(k, v)` 这一整个操作序列是原子的吗？（提示：原子性是**单个方法**的性质）
