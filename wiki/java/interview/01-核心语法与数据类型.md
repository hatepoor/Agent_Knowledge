# 核心语法与数据类型

> **什么时候该读**：面试第一轮几乎必问的类型系统与字符串题；或者你想搞清楚「为什么这里要写 `Integer` 而不是 `int`」「为什么两个字符串 `==` 不相等」。
> **答题主线**：**值 vs 引用**。Java 只有两种数据形态——基本类型是「值」，引用类型是「地址」；本篇所有题都在这条主线上打转。把「什么时候发生装箱、什么时候发生拷贝」讲清楚，这一半的题就过了。

---

## Q1. Java 有哪几种数据类型？基本类型和引用类型的本质区别是什么？

**答：**

Java 的类型系统只有两层：**8 种基本类型（primitive）** 和 **一切都是对象（引用类型）**。

| 类别 | 类型 | 大小 | 取值范围/说明 | 默认值 |
|------|------|------|-------------|--------|
| 整型 | `byte` | 1 字节 | -128 ~ 127 | 0 |
| 整型 | `short` | 2 字节 | -32768 ~ 32767 | 0 |
| 整型 | `int` | 4 字节 | 约 -21 亿 ~ 21 亿 | 0 |
| 整型 | `long` | 8 字节 | 约 -900 亿亿 ~ 900 亿亿 | 0 |
| 浮点 | `float` | 4 字节 | 单精度，精度约 7 位有效数字 | 0.0f |
| 浮点 | `double` | 8 字节 | 双精度，精度约 15~16 位有效数字 | 0.0d |
| 字符 | `char` | 2 字节 | 0 ~ 65535（Unicode 码点） | `'\u0000'` |
| 布尔 | `boolean` | JVM 实现相关 | 只有 `true` / `false` | `false` |

**本质区别**：

| | 基本类型 | 引用类型 |
|---|---------|---------|
| 内存里放什么 | **值本身**（栈上/寄存器） | **引用（地址）**，对象本体在堆上 |
| 传参 | 传值的**副本** | 传**地址的副本**（指向同一个对象） |
| 有默认值 | 有（字段场景） | 有（`null`） |
| 有方法 | ❌ 没有 | ✅ 有（`int` 没有 `equals`，`Integer` 有） |
| 内存开销 | 小 | 大（对象头 + 对齐，详见 [[java/02-中段阶段-专题精讲/JVM/JVM内存区域与对象布局]]） |

⚠️ 三个最容易说错的地方：

1. **`char` 是 2 字节且无符号**，能存一个汉字（`'中'` 合法），但**不能存超过 65535 的码点**（如某些生僻字、emoji 需要用 `String` 或转义）；
2. **`boolean` 大小没有明确规定**，JVM 实现通常用 1 字节，面试里说「大小由 JVM 实现决定」比说「1 字节」更稳；
3. **字段有默认值，局部变量没有**——局部变量必须赋值后才能用，这是编译期检查。

**追问：`float` 和 `double` 为什么不能表示精确小数？金额怎么算？**
→ 因为它们本质是二进制浮点，只能用有限位的二进制表示十进制小数，`0.1` 存进去不是精确的 0.1，所以 `0.1 + 0.2 != 0.3`。**金额必须用 `BigDecimal`（`new BigDecimal("0.1")`，用字符串构造而不是 double 构造）**，它的内部是 `long` 尾数 + `int` 精度，代价是比基本类型慢。

**追问：基本类型和包装类型什么时候互相转换？**
→ 编译器在合适的位置自动插入装箱（`int` → `Integer`）或拆箱（`Integer` → `int`），所以平时感觉不到。但**拆箱遇到 `null` 会直接抛 `NullPointerException`**——这是包装类型最大的坑，机制见 [[java/01-入门阶段-基础教程/第01章-核心语法/1.4-字符串与包装类]]。

## Q2. 自动装箱和拆箱的底层是什么？为什么 `Integer` 有缓存？

**答：**

**结论：装箱就是调 `valueOf()`，拆箱就是调 `xxxValue()`，都是编译器自动插入的方法调用。**

```java
Integer a = 100;          // 编译后等价于：Integer.valueOf(100)
int b = a;                // 编译后等价于：a.intValue()
```

| 方向 | 编译后等价代码 | 触发点 |
|------|---------------|--------|
| 装箱 | `Integer.valueOf(100)` | 赋给包装类型、传参给 `Object`、放进泛型容器 |
| 拆箱 | `a.intValue()` | 赋给基本类型、参与基本类型运算、`==` 与基本类型比较 |

**`Integer` 缓存**：`Integer.valueOf()` 对 `-128 ~ 127` 区间内的值**直接返回缓存的实例**，超出区间才 `new Integer(...)`（JDK 9+ 已弃用这个构造器，但缓存逻辑保留）。

```java
Integer x = 127, y = 127;
Integer a = 128, b = 128;
System.out.println(x == y);   // true  ← 同一个缓存实例
System.out.println(a == b);   // false ← 两个不同对象
```

⚠️ 三个连带后果：

1. **缓存范围可用 `-XX:AutoBoxCacheMax=<size>` 调大**（只影响启动时构建缓存），但面试里不要主动改它——生产上用 `Integer` 比较大小一律走 `equals()` 或直接用 `int`；
2. **`Boolean` 缓存两个实例**（`TRUE`/`FALSE`），所以 `Boolean` 用 `==` 恰好是对的；
3. **`Long`/`Short`/`Byte`/`Character` 也有缓存**（`Character` 缓存 0~127），**`Double`/`Float` 没有缓存**（浮点相等本身不可靠，用 `Double.compare`）。

**追问：为什么 `Integer` 要做缓存？**
→ **减少对象创建**。小整数在代码里出现频率极高（循环计数、`-1/0/1` 状态码），缓存后自动装箱不再每次分配对象，直接从缓存取，省内存也省 GC 压力。`String` 的常量池（intern）是同一个思路。

**追问：`new Integer(100) == Integer.valueOf(100)` 结果是什么？**
→ `false`（`new` 一定绕过缓存造新对象）。但这个写法本身在 **JDK 9 起已被弃用**（`Integer(int)` 构造器废弃），现在只能走 `valueOf`。

## Q3. 类型转换有哪些规则？什么情况会丢失精度或溢出？

**答：**

Java 的转换分三类：

| 类别 | 含义 | 例子 |
|------|------|------|
| **隐式 widening（加宽）** | 小类型自动转大类型，永远安全 | `int → long`、`float → double` |
| **隐式 narrowing（窄化）** | **不允许**（编译期报错），但**编译期常量**除外 | `byte b = 100;` ✅ 合法（常量在范围内） |
| **显式强转（cast）** | 手动指定，可能丢数据 | `long → int`、`double → int` |

**常量的「窄化特例」**：编译期已知的字面常量，如果目标类型能装下，允许直接赋值——这就是为什么 `byte b = 127;` 通过而 `byte b = 128;` 报错。**但变量不行**：`int x = 128; byte b = x;` 必须显式强转。

**精度丢失的三个典型场景**：

```java
public class CastDemo {
    public static void main(String[] args) {
        int i = 300;
        byte b = (byte) i;      // 溢出：300 截断低 8 位 = 44
        System.out.println(b);   // 44

        double d = 3.99;
        int j = (int) d;         // 窄化：直接截断，不是四舍五入 = 3
        System.out.println(j);

        long big = 3_000_000_000L;
        int k = (int) big;       // 截断高 32 位，可能得到负数
        System.out.println(k);   // 负数
    }
}
```

⚠️ **浮点 → 整型是截断，不是四舍五入**——这是笔试和实际业务里都高频踩的点。金额取整要显式 `Math.round()`（返回 long）或 `BigDecimal.setScale`。

**追问：`char` 和 `int` 怎么互相转换？**
→ 直接用强制转换，因为 `char` 的底层就是 16 位无符号整数：`int code = 'A';` 得到 65；反向 `char c = (char) 65;` 得到 `'A'`。Java **没有** Python 那样的一等公民 `str`，字符和整数的转换必须显式写。

**追问：`long` 和 `float` 相加结果是什么类型？**
→ `float`。加法规则是「**向更大精度靠**」，`long(8字节) + float(4字节)` 的结果类型是 `float`——⚠️ 这里会发生精度损失，因为结果只有 32 位尾数。**正确做法：和 `double` 混算**，或金额一律走 `BigDecimal`。

## Q4. String 为什么不可变？字符串常量池是怎么工作的？

**答：**

**结论：`String` 不可变是刻意的设计——它让 `String` 可以安全地做缓存键、可以共享、可以被安全发布。**

不可变体现在三处：`String` 类是 `final`（不能被继承改写）；字符数据存在一个 `final byte[]` 里；所有看起来会"改"它的方法（`concat`、`replace`、`trim`、`substring`）**都返回新对象**，原对象毫发无损。

**常量池的工作方式**：

```java
String a = "hello";        // 字面量 → 去常量池查/建 → 返回池中引用
String b = "hello";        // 池里已有 → 返回同一个引用
String c = new String("hello");  // ⚠️ 强制在堆上 new 一个新对象，不入池

System.out.println(a == b);   // true  （同一个对象）
System.out.println(a == c);   // false （不同对象）
System.out.println(a.equals(c)); // true（内容相同）
```

| 写法 | 是否入池 | `==` 对比两个相同字面量 |
|------|---------|---------------------|
| `"hello"` | ✅ 入池 | true |
| `new String("hello")` | ❌ 不入池 | false |
| `"hel" + "lo"` | ✅ 编译期就折叠成一个常量 | true |
| `s1 + s2`（变量） | ❌ 运行时 new | false |
| `"hello".intern()` | ✅ 显式入池并返回池中引用 | true |

⚠️ **JVM 层面的两个关键点**：

1. **字符串字面量在类加载时进入常量池**，属于「运行时常量池」的一部分，不是编译期的「常量池」；
2. **JDK 7 起常量池从永久代搬到了堆里**，所以字面量可以被 GC 回收（永久代被元空间取代后尤其明显）。这条常被问成「String 存在哪里」——**答案：引用在栈/字段里，对象本体和字面量在堆里**。

**追问：为什么 `String` 不可变对 `HashMap` 至关重要？**
→ 因为 `String` 的 `hashCode` 是在**第一次计算时缓存**的（`hash` 字段）。如果字符串内容能变，hash 就对不上了，放进 `HashMap` 后再改内容，key 就再也找不回来。**不可变 → hashCode 稳定 → 可以安全当 Map 键**。

**追问：`StringBuilder` 和 `StringBuffer` 有什么区别？**
→ 都是可变字符序列，但 `StringBuilder` **不是线程安全的**（无同步开销，性能更好），`StringBuffer` 的方法都加了 `synchronized`。**结论：单线程用 `StringBuilder`，需要线程安全才用 `StringBuffer`**——绝大多数场景是单线程的，优先 `StringBuilder`。

## Q5. `==` 和 `equals` 有什么区别？为什么 String 要重写 equals？

**答：**

**一句话：`==` 比「是不是同一个对象」，`equals` 比「内容（业务意义上）是不是一样」。**

| | `==` | `equals()` |
|---|------|------------|
| 比较对象 | **引用地址** | 逻辑内容（可被重写） |
| 基本类型 | 比较**值**（`int a=1, b=1` → true） | 不适用（`int` 没这个方法） |
| 引用类型 | 比较是否**同一个实例** | 默认实现就是 `==`，子类可重写 |
| null 安全 | 会 NPE | 可安全处理 null |

```java
public class EqualsDemo {
    public static void main(String[] args) {
        String a = "hello";
        String b = new String("hello");
        System.out.println(a == b);        // false：两个不同对象
        System.out.println(a.equals(b));   // true ：内容相同

        Integer x = 128, y = 128;
        System.out.println(x == y);        // false：缓存范围外，各 new 一个
    }
}
```

**为什么 `String` 必须重写 `equals`**：`Object` 的默认实现是 `this == obj`（比地址）。但字符串的意义是「内容」，两个内容相同的字符串在业务上就该被认为相等——不重写就没法放进 `HashMap` 当键、没法用 `List.contains()`。

⚠️ **重写 `equals` 必须同时重写 `hashCode`**——这是 Java 强制性的契约（也是 HashMap 能工作的前提）。违反它的后果很隐蔽：`equals` 相等的两个对象 `hashCode` 不同 → 在 `HashMap` 里落到不同的桶 → `map.get(key)` 找不到自己刚放进去的 key。机制见 [[java/01-入门阶段-基础教程/第04章-集合框架/4.4-HashMap底层原理]]。

**追问：`equals` 和 `hashCode` 的契约具体是什么？**
→ 两条：**① `equals` 相等的对象，`hashCode` 必须相等**（相等 ⇒ 哈希相等）；**② `hashCode` 相等的对象，`equals` 可能不等**（哈希相等 ⇏ 内容相等）。哈希冲突是允许的，违反第一条是 bug。

**追问：为什么 `Integer` 用 `==` 有时对有时错？**
→ 因为有缓存。`-128 ~ 127` 范围内 `valueOf` 返回同一实例，`==` 为 true；超出范围每个都 `new`，`==` 为 false。**所以包装类型比较大小一律用 `equals()`（或 `.intValue()`）**，基本类型才用 `==`。

## Q6. final 到底有哪些用法？final 修饰的变量一定不可变吗？

**答：**

`final` 有三类用法，语义完全不同：

| 用法 | 含义 | 记忆点 |
|------|------|--------|
| `final` 修饰**局部变量** | 只能赋值一次 | 必须在声明时或每个构造路径上恰好赋值一次 |
| `final` 修饰**字段** | 只能赋值一次 | 必须在**构造器或初始化块**里赋值（对象创建时定死） |
| `final` 修饰**类** | 不能被继承 | 如 `String`、`Integer` |
| `final` 修饰**方法** | 不能被重写 | 「锁死契约」 |

```java
public class FinalDemo {
    // ⚠️ final 字段的三种赋值方式：声明处 / 静态初始化块 / 构造器
    private final String name;
    private static final int MAX = 100;   // 常量命名惯例：大写 + 下划线

    public FinalDemo(String name) {
        this.name = name;    // 构造器里赋值
    }

    public static void main(String[] args) {
        final int x = 10;
        // x = 20;           // 编译错误：cannot assign a value to final variable
        System.out.println(MAX);
    }
}
```

**⚠️ 关键陷阱：`final` 修饰的「引用不可变」，但「引用指向的对象可变」**：

```java
final List<String> list = new ArrayList<>();
list.add("a");        // ✅ 合法：改的是对象内容，不是引用
// list = new ArrayList<>();  // ❌ 编译错误：引用不能重新指向
```

所以 `final` 保证的是「**这个引用不会改指向**」，不是「这个对象不会变」。**想要真正的不可变对象，字段全 `final` + 不暴露任何修改入口 + 内部集合也要不可变**（用 `List.of()` / `Collections.unmodifiableList()`）。

**追问：`final` 有什么用？除了「不可变」还有什么价值？**
→ 三个实打实的好处：① **编译期常量折叠**——`static final int MAX = 100` 会被直接内联到调用处，运行期零开销（注意：这是**常量**，不是所有 `final` 字段都会被内联）；② **安全发布**——`final` 字段有「初始化安全保证」：对象构造完成时写入的 `final` 字段，其他线程读到该引用后一定能看到正确值（JMM 的 final 字段语义）；③ **便于 JIT 优化**——不可变对象更容易被做逃逸分析、栈上分配。

**追问：`static final` 和 `final` 的区别？**
→ `static final` 是「**类级**的常量，一个类一份」；`final` 实例字段是「**每个对象各一份**的常量」。所以 `static final` 才能被常量折叠进调用方字节码，实例 `final` 字段不能。

## Q7. Java 的运算符和流程控制有哪些容易踩的坑？

**答：**

**运算符三大坑**：

| 坑 | 例子 | 说明 |
|----|------|------|
| **浮点精度** | `0.1 + 0.2 == 0.3` → false | 二进制无法精确表示 0.1 |
| **整数溢出** | `int` 溢出后回绕 | `Integer.MAX_VALUE + 1` 变成 `Integer.MIN_VALUE`，**不抛异常** |
| **短路与位运算混淆** | `a && b` vs `a & b` | `&&` 短路（右侧不求值），`&` 两侧都求值 |

```java
public class OperatorDemo {
    public static void main(String[] args) {
        // 1. 短路：右侧有副作用时结果不同
        int count = 0;
        boolean r1 = false && (count++ > 0);   // count 仍为 0
        boolean r2 = false & (count++ > 0);    // count 变成 1
        System.out.println(count);             // 1

        // 2. 移位：>> 补符号位，>>> 不补
        int neg = -8;
        System.out.println(neg >> 1);          // -4（算术右移，保持负号）
        System.out.println(neg >>> 1);         // 2147483644（逻辑右移，补 0）

        // 3. 复合赋值隐含强转
        byte b = 10;
        // b = b + 1;   // ❌ 编译错误：int 不能隐式转 byte
        b += 1;          // ✅ 合法：等价于 b = (byte)(b + 1)
        System.out.println(b);
    }
}
```

⚠️ **`+=` 会隐含一次窄化强转**，而 `+` 不会——这是 Java 里少见的「运算符行为不一致」，写字节累加时特别容易踩。

**流程控制三大坑**：

| 坑 | 说明 | 正确做法 |
|----|------|---------|
| **增强 for 循环里删除元素** | 抛 `ConcurrentModificationException` | 用 `iterator.remove()` 或 `removeIf()` |
| **`switch` 忘写 `break`** | 贯穿（fall-through）到下一个 case | 每个 case 结尾 `break`（或用箭头语法） |
| **`for-each` 遍历时修改集合结构** | 同上，fail-fast 机制 | 先收集、后统一删除 |

**追问：`switch` 在 Java 14 之后有什么变化？**
→ **switch 表达式**（Java 14 正式，17/21 持续增强）：可以用箭头 `case` 语法（`case X -> ...`）省掉 `break`（不会贯穿），多个值可以合并（`case A, B -> ...`），并且**能直接作为表达式返回值**。Java 21 起还支持**模式匹配的 switch**（对 `sealed` 类做穷尽匹配）。详见 [[java/01-入门阶段-基础教程/第01章-核心语法/1.2-运算符与流程控制]]。

**追问：`&` 和 `&&`、`|` 和 `||` 到底怎么选？**
→ **`&&`/`||` 是逻辑运算符，有短路，右侧可能是有副作用的表达式时优先用它们**；**`&`/`|` 是位运算符，两侧一定都求值**——只在需要「两边都要算」的场景（比如两个 boolean 都要参与计算）才用。

## Q8. `final`、`static`、`transient`、`volatile` 这几个修饰符各自是什么意思？

**答：**

四个修饰符管的是四件不同的事，一张表讲清：

| 修饰符 | 作用对象 | 含义 | 典型用法 |
|--------|---------|------|---------|
| `final` | 变量 / 类 / 方法 | 不可重新赋值 / 不可继承 / 不可重写 | 常量、不可变对象 |
| `static` | 变量 / 方法 / 内部类 / 导入 | **属于类**而非实例 | 工具方法、计数器 |
| `transient` | 字段 | **序列化时忽略** | 缓存、连接、临时对象 |
| `volatile` | 字段 | 保证**可见性和有序性**，不保证原子性 | 并发标志位 |

**`static` 的两个坑**：

```java
public class StaticDemo {
    private static int counter = 0;      // 类变量：整个 JVM 一份（准确说是每个 Class 一份）
    private int id = ++counter;          // ⚠️ 每个新对象都拿到递增后的 id

    public static void main(String[] args) {
        StaticDemo a = new StaticDemo();
        StaticDemo b = new StaticDemo();
        System.out.println(a.id + " " + b.id);   // 1 2
    }
}
```

1. **`static` 变量在类加载的「初始化」阶段就赋好值**，不是对象创建时；
2. **`static` 方法里不能直接用 `this`/`super`**——因为它不属于任何实例。

**`transient` 的实际用途**：一个对象里有些字段不该进持久化（连接对象、临时缓存、Spring 的注入依赖），标 `transient` 即可。⚠️ 注意它**只对 Java 原生序列化生效**，JSON 序列化（Jackson）默认不认这个标记。

**`volatile` 只做两件事**（详细机制见 [[java/02-中段阶段-专题精讲/并发编程/02-线程安全与Java内存模型]]）：

1. 保证**可见性**：一个线程改了 `volatile` 变量，其他线程立刻能读到最新值（不缓存）；
2. 保证**有序性**：禁止指令重排序越过 volatile 读写。

**⚠️ 但它不保证原子性**——`count++` 是「读-改-写」三步，volatile 挡不住。**要么用 `AtomicInteger`，要么用 `synchronized`**。

**追问：`static` 变量的初始化顺序是什么？**
→ 顺序是：① 静态字段声明处按书写顺序赋值；② 静态初始化块按书写顺序执行；两者**交替**进行（谁写在前面谁先执行）。类初始化（`<clinit>`）在**首次主动使用**这个类时触发且只执行一次。机制见 [[java/02-中段阶段-专题精讲/JVM/类加载机制]]。

**追问：`static` 和 `final` 一起用（`static final`）是什么？**
→ **常量**。命名用全大写 + 下划线。因为是编译期常量，**会被直接内联到使用方的字节码里**——所以改了这个常量的值，所有调用方都要重新编译才生效（这是 `static final` 常量「改了不生效」的经典原因）。

## Q9. 为什么 `char` 是 2 字节能存一个汉字，但 `String` 的长度还是按字符算？

**答：**

**结论：`String.length()` 返回的是 UTF-16 代码单元（code unit）的个数，不是「人眼看到的字符数」。**

Java 的字符串内部用 UTF-16 编码（`compact strings` 之前），一个字符占 2 字节：

| 字符类型 | UTF-16 占用 | `length()` 计数 |
|---------|-----------|----------------|
| ASCII（`'a'`、`'1'`） | 1 个 code unit | 1 |
| **常用汉字**（`'中'`，在 BMP 范围内） | 1 个 code unit | 1 |
| **生僻字 / 某些 emoji**（超过 U+FFFF，如 `𠮷`、😀） | **2 个 code unit（代理对）** | **2** |

```java
public class CharDemo {
    public static void main(String[] args) {
        String s = "中";            // 常用汉字
        System.out.println(s.length());        // 1

        String emoji = "😀";        // 超过 BMP
        System.out.println(emoji.length());    // 2  ← ⚠️ 不是 1
        System.out.println(emoji.codePointCount(0, emoji.length())); // 1 ← 真正的字符数
    }
}
```

⚠️ **这个坑的实际影响**：校验「用户名长度不超过 16 个字符」时，如果用 `length()`，一个 emoji 会被算成 2；数据库 `VARCHAR(16)` 按字符存又是 1。**跨端校验和入库时可能出现不一致**。

**追问：Java 里的字符编码体系是什么？**
→ 依次是：`char`（单个 UTF-16 码元）→ `String`（UTF-16 序列）→ `Charset`（编码规则，如 UTF-8、GBK）→ `byte[]`（编码后的字节）。**关键认知：字符集（Character Set）和字符编码（Character Encoding）是两回事**——UTF-8 是 Unicode 的一种编码方式。

**追问：`String` 内部为什么用 UTF-16 而不是 UTF-8？**
→ **因为 Java 诞生于 1995 年，当时 Unicode 还是 UCS-2（每个字符固定 2 字节）**，UTF-16 是 UCS-2 的自然延伸（保持兼容）。后来 Unicode 超过 65536 个码点后，UTF-16 只能用代理对表示扩展区字符。

## Q10. Java 里有哪些「看起来一样但行为不同」的 API？String 拼接、`char` 运算、`+` 号重载都是什么坑？

**答：**

**三个高频的「以为会这样、其实不是」**：

| 场景 | 直觉 | 实际 |
|------|------|------|
| `"a" + 1` | 得到 `"a1"` | ✅ 是 `"a1"`（**字符串**），但 `1 + "a"` 也是 `"1a"`——**`+` 遇到字符串就变拼接** |
| `"a" + 1 + 2` | 拼接结果 | `"a12"`——**左结合，从左往右**，`"a"+1` 先变成 `"a1"`，再拼 `2` |
| `1 + 2 + "a"` | 也是拼接 | `"3a"`——前两个先算成 `3` |

```java
public class PlusDemo {
    public static void main(String[] args) {
        System.out.println("a" + 1 + 2);   // a12（左结合）
        System.out.println(1 + 2 + "a");   // 3a（先算加法）
        System.out.println('a' + 1);        // 97  ← ⚠️ char 参与算术运算会提升为 int！
        System.out.println("a" + 'b');      // ab ← ⚠️ 有 String 在就变字符串拼接
    }
}
```

⚠️ **第 3 行是最经典的坑**：`'a' + 1` 结果是 `97`（`char` 被**数值提升**为 `int`），不是 `"a1"`。这跟 Python 的 `str + int` 直接报错完全不同。

**`char` 的数值提升规则**（二元算术运算中）：

- 如果两侧有一个是 `double` → 结果 `double`
- 否则如果有一侧是 `float` → 结果 `float`
- 否则如果有一侧是 `long` → 结果 `long`
- **否则按二元数值提升 → `int`**（`byte`/`short`/`char` 全部提升为 `int`）

所以 `byte + byte` 的结果类型是 `int`，不是 `byte`——这也是为什么 `b + b` 不能直接赋给 `byte`。

**追问：字符串拼接的底层是什么？性能怎么样？**
→ 两种情况：**编译期能确定的常量拼接**（`"a" + "b"`）直接被编译器折叠成一个常量，运行时零开销；**运行期拼接**（`s + i`）编译成 `StringBuilder.append()` 链（或 JDK 9+ 的 `invokedynamic` + `StringConcatFactory`），⚠️ **在循环里反复拼接会每次新建 StringBuilder，是 O(n²)**——循环里必须自己声明一个 `StringBuilder` 复用。

**追问：Java 有运算符重载吗？**
→ **没有**。Java 不支持用户自定义运算符重载（这是它比 C++ 简洁的地方，也是它被吐槽「表达力弱」的地方）。替代方案是：接受 `BigDecimal`/`BigInteger` 这类**标准库提供的类**（它们内部实现了运算），或用 `String` 拼接，或用 `Optional`/`Stream` 组合。
