# Java 面试题库

> **本目录的定位：把 Java 的知识点变成「面试能说出口的答案」。**
>
> 与教程正文（[[java/README|Java 知识库]]）的分工：**教程讲「机制是什么、为什么这样设计」，本目录讲「面试官问什么、怎么答、追问到哪一层」。**
> 每题格式统一为「先问题、后答案、再追问」，**每篇 10 题，且同篇只讲一个主题**。

---

## 一、版本口径（2026-10-22 核实）

| 项 | 说明 |
|---|---|
| 语言基线 | **Java 25 LTS**（2025-09-16 GA，Oracle Premier 支持至 2030-09，Extended 至 2033-09） |
| 上一 LTS | Java 21（2023-09）、Java 17（2021-09，企业存量最大） |
| 特性版 | Java 26（2026-03）、Java 27（2026-09）——**非 LTS，仅 6 个月支持期** |
| 框架基线 | **Spring Boot 4.1.x**（Spring Framework 7 / Jakarta EE 11），⚠️ 仅支持 Java 17–26 |
| 答题建议 | 机制题不依赖版本；提到新特性时明确说「Java 21 才有」「Java 25 才转正」，避免把预览特性当通用能力 |

⚠️ **三个必须记住的版本坑**（答错会被追问）：

1. **虚拟线程**：Java 21 正式但**存在 pinning 问题**，JDK 24 的 JEP 491 才修复 → Java 25 是第一个含修复的 LTS；
2. **偏向锁**：JDK 15 起默认禁用并废弃（JEP 374）——讲锁升级时不要说「还有偏向锁」；
3. **分代 ZGC**：自 JDK 23 起为默认模式（JEP 474）。

⚠️ **不要背具体默认参数值**（如 G1 的堆占比、线程池推荐核心数）。说「按压测调、按 IO/CPU 密集区分」更稳。

## 三、使用方式

```
第一遍：只看问题，口述答案，卡住做标记
第二遍：读答案，重点看「追问」——面试真正考的是追问层
第三遍：回到教程正文补机制，能用自己的话讲清「为什么」才算过
```

**判断标准**：每题能用「**结论 → 机制 → 边界/代价**」三段式讲完，才算过。
只会背结论不背机制，面试官一个追问就会露底。

**时间安排建议**：70 题按主题拆成 7 轮，每轮 1 小时（40 分钟过题 + 20 分钟查漏）。

## 四、题目来源与筛选口径

参考（2026-10 核对）：

| 来源 | 用途 |
|------|------|
| 牛客网面经 | 真实提问顺序与追问深度 |
| 面试鸭（mianshiya.com） | 国内后端岗高频题分布 |
| CSDN / 掘金 | 长尾题、线上事故类题目 |
| Java 官方文档与 JEP 提案 | **事实核对基准**，社区文章与官方冲突时以官方为准 |
| Oracle Java SE Support Roadmap | 版本支持期限的权威来源 |

⚠️ **筛选原则**：

1. **只收机制题、选型题、排查题**，不收「某个注解叫什么」的记忆题；
2. **必带追问**——一道没有追问的题说明还没挖到面试的深度；
3. **版本敏感题必须标版本**，不标版本的答案在面试里等于错答案；
4. 涉及线上事故的题（OOM、CPU 100%、死锁、事务失效）优先级最高——这类题最能区分「看过书」和「干过活」。

## 六、答题总原则

| 原则 | 说明 |
|------|------|
| **先说结论，再说机制** | 「HashMap 数组+链表+红黑树，负载因子 0.75 触发 2 倍扩容」比先讲 JDK 历史更抓人 |
| **机制 → 现象 → 手段** | 每个答案都落到「所以线上会出现什么、怎么定位、怎么修」 |
| **主动给边界和代价** | 「用 `ConcurrentHashMap` 更好，但**内存占用高于 `HashMap`**」——只讲优点会被追问击穿 |
| **区分版本** | 「Java 21 才引入虚拟线程，且 JDK 24 前有 pinning 问题」比笼统说「Java 支持虚拟线程」可信得多 |
| **不编数字** | 参数、阈值记不准就说「量级」或「按压测调」，别报精确值 |
| **诚实说边界** | 不知道就说「这块我只用过 API，机制没深挖」——比硬编强，面试官反而会给台阶 |
