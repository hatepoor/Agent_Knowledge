# 自动摘要与上下文卸载

DeepAgents 上下文管理的两个核心机制：自动卸载（20k tokens）和自动摘要（85% 容量），以及 Prompt Caching 的实际收益。

## 一、双层机制

```
Agent 运行中:
  │
  ├── 卸载层（20k tokens 触发）
  │   工具返回 > 20k tokens → 写入文件系统 → 上下文只保留文件路径引用
  │   效果: Agent 仍能 read_file 取回内容，但上下文窗口不占
  │
  └── 摘要层（85% 容量触发）
      上下文达模型窗口 85% → 压缩旧消息为结构化摘要 → 保留最近消息
      效果: Agent 知道历史，但不超出 token 限制
```

## 二、卸载机制详解

当单个工具返回超过 ~20k tokens 时：

```
Before（上下文爆炸）:
  ToolMessage: "搜索结果: {50 页 × 2000 字 = 100K tokens}"
  上下文直接撑到 100K → 旧信息全丢

After（自动卸载）:
  1. 结果写入 /results/search_20260729_001.txt
  2. ToolMessage 改为: "结果已保存到 /results/search_20260729_001.txt，共 50 页"
  3. Agent 按需 read_file("/results/search_20260729_001.txt", offset=0, limit=50)
  4. 上下文只占 ~50 tokens（路径引用），而非 ~100K tokens
```

## 三、摘要机制详解

当上下文达到模型窗口的 85% 时触发：

```python
# 自定义触发策略
from deepagents.middleware import SummarizationMiddleware

agent = create_deep_agent(
    model=llm,
    middleware=[
        SummarizationMiddleware(
            model=summary_llm,
            trigger=("tokens", 100000),     # 超 100k tokens 触发
            keep=("messages", 20),           # 保留最近 20 条
        ),
    ],
)
```

摘要内容保留：
- ✅ 当前待办列表及状态
- ✅ 关键发现和决策
- ✅ 已创建/修改的文件路径
- ✅ 未完成的任务和依赖
- ❌ 详细的工具调用日志
- ❌ 重复的搜索尝试

## 四、Prompt Caching 的实际收益

Anthropic/Bedrock 模型自动启用 Prompt Caching。**CallSphere 生产数据**：

| 指标 | 无 Caching | 有 Caching |
|------|-----------|-----------|
| 每调用成本 | $0.012 | **$0.0072** |
| 节省 | — | **40%** |
| 配置改动 | — | **零**（自动生效） |

Caching 覆盖的静态内容：system prompt、工具定义、skills、memory 文件。
