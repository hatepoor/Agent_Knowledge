# DeepAgents 文件系统后端

Backend 决定了 Agent 的文件系统工具（ls/read/write/edit）操作的是**什么样的存储**。从内存到磁盘到沙箱，可插拔切换。

## 一、6 种内置后端（官方 deepagents>=0.7 定义）

> 官方将后端分为 **6 种内置后端** + **1 个独立的 Sandbox 家族**（隔离沙箱，非内置后端）。Sandbox 是 BackendProtocol 的特殊实现类别。

| 后端         | 类                   | 存储位置                   |  持久化  | execute |   风险   | 适用场景                            |
| ---------- | ------------------- | ---------------------- | :---: | :-----: | :----: | ------------------------------- |
| State      | `StateBackend`      | LangGraph AgentState 中 |  线程内  |    ❌    |   低    | 默认，线程内跨轮保留（配 checkpointer），不跨线程 |
| Filesystem | `FilesystemBackend` | 本地磁盘 root_dir          |   ✅   |    ❌    |   中    | 需要真实文件、虚拟路径隔离                   |
| LocalShell | `LocalShellBackend` | 本地磁盘 + 宿主机 shell       |   ✅   |  ✅ 宿主机  | **极高** | 受信任本地环境；生产禁用                    |
| Store      | `StoreBackend`      | LangGraph Store        | ✅ 跨线程 |    ❌    |   低    | 跨线程持久记忆，namespace 隔离            |
| ContextHub | `ContextHubBackend` | LangSmith Hub 仓库       | ✅ 云端  |    ❌    |   低    | 远程持久化、多机共享                      |
| Composite  | `CompositeBackend`  | 按路径路由到多个后端             |  按路由  |   按路由   |  按成员   | ⭐ 生产标配（临时+长期+落盘分级）              |

### 1.1 官方 2026 版补充要点

- **StateBackend**：同 thread_id 内跨轮持久（依赖 checkpointer），换 thread 即隔离——不是"每次请求清空"
- **FilesystemBackend**：`virtual_mode=True` 启用虚拟路径（`/` 开头）；官方推荐包进 CompositeBackend，防止内部数据（卸载的工具结果、对话历史）混写进项目文件
- **LocalShellBackend**：唯一在**宿主机**上提供 `execute` 的后端（"unrestricted shell execution on your host"），风险等级最高
- **StoreBackend**：`namespace` 是数据隔离关键——多用户部署必须用 namespace 工厂（`lambda rt: (rt.server_info.user.identity,)`）；`store` 参数传给 `create_deep_agent(store=...)` 而非 backend
- **ContextHubBackend**：文件存 LangSmith Hub 仓库，跨环境/跨进程访问

### 1.2 Sandbox 家族（独立类别，6 个提供商）

Sandbox 不是第 7 种内置后端，而是**一类特殊后端**：独立文件系统 + `execute` 工具 + 容器/VM 隔离。

| 提供商 | 安装包 | 特点 |
|--------|--------|------|
| LangSmith | `langsmith[sandbox]` | microVM 级隔离，<1s 启动 |
| Daytona | `langchain-daytona` | 开发环境即服务 |
| E2B | `langchain-e2b` | 云沙箱 |
| Modal | `langchain-modal` | 无服务器容器 |
| Runloop | `langchain-runloop` | Devbox 即沙箱 |
| Vercel | `langchain-vercel-sandbox` | 按需运行时 |

## 二、StateBackend（默认）

```python
from deepagents import create_deep_agent

# 默认 StateBackend —— 不需要配置
agent = create_deep_agent(model=llm)
# 文件存在 LangGraph agent state 的 messages 中
# 线程结束 → 文件消失
```

## 三、FilesystemBackend（本地磁盘）

```python
from deepagents.backends import FilesystemBackend
from pathlib import Path

agent = create_deep_agent(
    model=llm,
    backend=FilesystemBackend(root_dir=Path("/tmp/agent-workspace")),
)
# 文件存在 /tmp/agent-workspace/ 下
# 重启后文件仍存在
```

## 四、StoreBackend（跨线程持久化）

```python
from deepagents.backends import StoreBackend
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()  # 生产用 PostgresStore

agent = create_deep_agent(
    model=llm,
    backend=StoreBackend(store=store),
)
# 文件存在 LangGraph Store 中
# 不同 thread_id 之间可以共享（通过 store 接口查询）
```

## 五、CompositeBackend（多后端混合）

按路径前缀把不同请求路由到不同后端：

```python
from deepagents.backends import (
    StateBackend, StoreBackend, CompositeBackend
)

agent = create_deep_agent(
    model=llm,
    backend=CompositeBackend(
        default=StateBackend(),           # / 下用 State（临时）
        routes={
            "/memories/": StoreBackend(),  # /memories/ 下用 Store（长期）
            "/cache/": FilesystemBackend(  # /cache/ 下用本地磁盘
                root_dir=Path("/tmp/cache")
            ),
        },
    ),
)
```

路径路由规则：
- `write_file("/report.md")` → 走 `StateBackend`（默认路由）
- `write_file("/memories/user_prefs.json")` → 走 `StoreBackend`（匹配 `/memories/`）
- `write_file("/cache/large_data.csv")` → 走 `FilesystemBackend`

## 六、LocalShellBackend（本地磁盘 + shell 执行）⚠️

在 FilesystemBackend 基础上多一个 `execute` 工具——Agent 能在**宿主机**上直接执行 shell 命令：

```python
from deepagents.backends import LocalShellBackend

agent = create_deep_agent(
    model=llm,
    backend=LocalShellBackend(
        root_dir=".",
        virtual_mode=True,
        env={"PATH": "/usr/bin:/bin"},
    ),
)
```

| 特征 | 说明 |
|------|------|
| 能力 | 文件工具 + `execute` 命令执行 |
| 风险等级 | **最高**——官方原文 "unrestricted shell execution on your host" |
| 适合 | 受信任的本地开发环境 |
| 生产 | ❌ 禁用。需要代码执行请用 Sandbox 家族（隔离环境） |

> 与 Docker 沙箱方案的关系：LocalShellBackend = 无沙箱裸奔；Sandbox = 隔离执行（见 [[docker/沙箱/Docker沙箱概述]]）。

## 七、Sandbox 家族（隔离执行，独立类别）

Sandbox 后端提供完整的文件系统 + `execute` 工具，运行在隔离的容器/VM 中：

```python
from deepagents.backends.langsmith import LangSmithSandbox
from langsmith.sandbox import SandboxClient

client = SandboxClient()
ls_sandbox = client.create_sandbox()

agent = create_deep_agent(
    model=llm,
    backend=LangSmithSandbox(sandbox=ls_sandbox),
    # Agent 自动获得 execute 工具（沙箱内执行）
)
```

支持的沙箱提供商：

| 提供商 | 安装包 |
|--------|--------|
| LangSmith | `langsmith[sandbox]` |
| Daytona | `langchain-daytona` |
| E2B | `langchain-e2b` |
| Modal | `langchain-modal` |
| Runloop | `langchain-runloop` |
| Vercel | `langchain-vercel-sandbox` |

## 八、选择决策

```
需要执行代码？
  ├── 是，且不可信        → Sandbox 家族（隔离环境）
  ├── 是，且本机可信       → LocalShellBackend（慎用）
  └── 否 →
      需要跨线程长期记忆？  → StoreBackend
      需要真实文件落盘？    → FilesystemBackend
      需要云端共享？        → ContextHubBackend
      只是临时/开发？       → StateBackend（默认，零配置）
      ⭐ 生产通用方案       → CompositeBackend（临时+长期+落盘分级）
```
