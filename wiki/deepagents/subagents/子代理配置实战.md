# 子代理配置实战

生产级的子代理 prompt 和配置——CallSphere 的实际迁移经验："200 token 的子代理 prompt 花对了，十倍回报"。

## 一、子代理 prompt 设计原则

对比通用 prompt 和生产级 prompt：

```python
# ❌ 通用prompt — 效果不稳定
{"system_prompt": "你是研究子代理。搜索相关信息。"}

# ✅ 生产级 prompt — 明确输入/输出/格式
{"system_prompt": """你是研究子代理。返回 3 个关键发现和 2 个风险，JSON 格式。

## 输入
你会收到一个公司名称。

## 输出
{
  "key_findings": ["发现1", "发现2", "发现3"],
  "risks": ["风险1", "风险2"],
  "sources": ["来源URL1", "来源URL2"]
}

## 规则
- 信息来源必须是最近 6 个月
- 风险要具体可操作
- 不充分的信息不编造，标为 'Unknown'"""}
```

## 二、多角色子代理协同

```python
from deepagents import create_deep_agent, SubAgent

agent = create_deep_agent(
    model="claude-sonnet-4-6",
    tools=[web_search, read_email, send_email],
    subagents=[
        SubAgent(
            name="researcher",
            description="研究公司背景：搜索公司信息、财务状况、最近新闻",
            system_prompt="""你是研究分析师。输入公司名，返回：
- 3 个关键事实（来源注明）
- 2 个潜在风险
- 1 句话总结市值/融资情况""",
            tools=[web_search],
        ),
        SubAgent(
            name="drafter",
            description="起草邮件：根据研究结果和客户信息写个性化邮件",
            system_prompt="""你是邮件起草专家。根据研究结果写邮件：
- 主题行吸引打开
- 正文 3 段：问候+价值点+CTA
- 语气专业但友好""",
            tools=[read_email],  # 只读邮件，不发
        ),
        SubAgent(
            name="reviewer",
            description="审查邮件草稿：检查语法、调性、合规性",
            system_prompt="""你是合规审查员。检查邮件：
- 是否有虚假声明
- 是否符合 GDPR/CAN-SPAM
- 调性是否匹配客户类型
返回: {approved: bool, issues: [str], suggestions: [str]}""",
            tools=[],  # 纯审查，不需要工具
        ),
    ],
)
```

## 三、子代理返回格式标准化

```python
SubAgent(
    name="code_reviewer",
    system_prompt="""你审查代码。严格按以下 JSON 格式返回：

{
  "score": 7,
  "issues": [
    {"severity": "high", "line": 42, "category": "security", "description": "SQL注入风险", "fix": "用参数化查询"}
  ],
  "summary": "代码结构清晰，但安全需加强。评分 7/10。"
}

不要返回任何 JSON 之外的文字。""",
)
```

## 四、主 Agent 的调度 system prompt

```python
main_prompt = """你是客户沟通主管。工作流：

1. 收到客户请求 → task("researcher", description="研究公司信息")
2. 拿到研究结果 → task("drafter", description="起草个性化邮件")
3. 拿到草稿 → task("reviewer", description="审查邮件")
4. 审查通过 → send_email 发送
   审查不通过 → 回到 drafter 修改

每步完成后汇报进度。"""
```

## 五、生产数据——CallSphere 的迁移经验

从原始 LangGraph 迁移到 deepagents 的实际结果：

| 指标 | 迁移前 | 迁移后 |
|------|--------|--------|
| 监督节点代码 | ~80 行手动 ReAct | 1 行 `create_deep_agent` |
| 每调用 token（Claude Sonnet 4） | $0.012 | **$0.0072**（↓40%，Prompt Caching 自动） |
| 工具定义改动 | 0（`@tool` 直接复用） |
