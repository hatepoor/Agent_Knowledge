# DeepAgents 组件依赖全景

**本文是全库的"导航中枢"**——回答一个核心问题：`create_deep_agent` 传的每个参数，最终变成了什么？各个组件之间怎么互相依赖？

> 阅读顺序：先看本文建立全局观，再按需跳转到各专题页。

## 一、一句话全景

```
create_deep_agent(参数)
    │
    ├── 参数 → 中间件（13 层栈）→ 工具（Agent 的工具面）
    ├── backend → 文件落到哪（内存/磁盘/Store/沙箱）
    ├── checkpointer → 状态存哪（thread 恢复）
    ├── store → 长期记忆存哪（跨 thread）
    └── subagents/skills/memory → 能力扩展
```

**核心关系链**：`参数 → 中间件 → 工具 → backend → 存储`，每一步都决定下一步。

## 二、参数 → 中间件 → 工具 完整映射

这是全库最重要的表：**每个参数产生哪个中间件，每个中间件提供哪些工具**。

| 参数 | 中间件 | 提供的工具 | 依赖的组件 |
|------|--------|-----------|-----------|
| `tools=` | —（直接并入） | 自定义工具 + MCP 工具 | 无 |
| `skills=` | `SkillsMiddleware` | 无工具（指引模型用 `read_file`） | **FilesystemMiddleware**（跨中间件依赖） |
| `memory=` | `MemoryMiddleware` | 无工具（加载 AGENTS.md 注入 prompt） | **backend**（读记忆文件） |
| `subagents=` | `SubAgentMiddleware` | `task` | backend、subagents 列表 |
| （默认） | `TodoListMiddleware` | `write_todos` | AgentState |
| （默认） | `FilesystemMiddleware` | `ls/read_file/write_file/edit_file/glob/grep` | **backend**（文件落点） |
| （默认） | `SummarizationMiddleware` | 无工具（摘要钩子） | model（摘要模型）、**backend**（卸载落盘） |
| （默认） | `PatchToolCallsMiddleware` | 无工具（状态修复） | — |
| `backend=`（沙箱） | —（backend 提供） | `execute` | 仅 Sandbox/LocalShell 后端 |
| `interrupt_on=` | `HumanInTheLoopMiddleware` | 无工具（拦截别的工具） | **checkpointer**（必需） |
| `checkpointer=` | —（图级配置） | — | 会话持久化 |
| `store=` | `StoreBackend`（经 backend） | — | 长期记忆 |

## 三、工具归属链（谁提供、谁使用）

### 3.1 文件系统工具 `read_file` 的完整生命周期

这是全库被引用最多的工具，一条链串起 5 个组件：

```
FilesystemMiddleware 提供 read_file
    │
    ├── ① SkillsMiddleware 指引模型用它读 SKILL.md 技能全文
    ├── ② MemoryMiddleware 用它读 AGENTS.md 记忆文件
    ├── ③ SummarizationMiddleware 卸载大输出后，模型用它按需取回
    ├── ④ SubAgentMiddleware 派生的子代理继承它
    └── ⑤ 模型自主用它读取用户要求的文件
```

> 关键结论：**`read_file` 只有一个生产者（FilesystemMiddleware），但有 5 个消费者**。自定义架构若移除 FilesystemMiddleware，Skills/Memory 的读取通道也会断裂（需自补 `load_skill` 工具）。

### 3.2 `execute` 的来源

`execute` 是**唯一由 backend 而非中间件提供**的工具：

```
backend 类型决定 execute 是否存在：
  ├── StateBackend / FilesystemBackend / StoreBackend / ContextHubBackend / CompositeBackend
  │     └── ❌ 无 execute（文件工具照常）
  └── LangSmithSandbox / Daytona / E2B / Modal / LocalShellBackend
        └── ✅ 有 execute（在沙箱/宿主机执行命令）
```

## 四、存储分层（文件 / 状态 / 记忆 三通道）

DeepAgents 有三条独立的持久化通道，**不要混淆**：

| 通道 | 组件 | 存什么 | 生命周期 | 参数 |
|------|------|--------|---------|------|
| **文件** | backend | Agent 写的文件（ls/read/write 的对象） | 取决于后端（线程/磁盘/Store/沙箱） | `backend=` |
| **状态** | checkpointer | AgentState 快照（消息、todo、文件索引） | 按 thread_id 恢复 | `checkpointer=` |
| **长期记忆** | store | 跨 thread 的持久数据（经 StoreBackend） | 永久 | `store=` |

```
用户请求（thread_id="t1"）
    │
    ├── checkpointer 恢复 t1 的状态快照（消息历史）
    ├── backend 提供文件空间（/memories/ → Store，其余 → State）
    ├── store 提供长期记忆读写
    └── 执行完 → checkpointer 写入新快照
```

> ⚠️ 常见混淆：`backend=StoreBackend` 与 `store=` 是两个东西——前者决定**文件**落点，后者是**长期记忆**的存储实例。见 [[deepagents/backend/后端概述]]。

## 五、一次请求的完整数据流（端到端）

以"审查代码并写报告"为例：

```
用户: "审查这段代码并保存报告"
  │
  ▼
① 启动：MemoryMiddleware 读 AGENTS.md（经 backend）→ 注入 system prompt
  │
② 规划：模型调 write_todos（TodoListMiddleware）→ 拆解任务
  │
③ 识别技能：模型看 skills 元数据 → 调 read_file 读 SKILL.md（FilesystemMiddleware + backend）
  │
④ 读代码：模型调 read_file 读用户代码（同一工具，不同文件）
  │
⑤ 派发：复杂子任务 → task 派给 code_reviewer 子代理（SubAgentMiddleware）
  │     └── 子代理独立上下文，只返回报告
  │
⑥ 写报告：模型调 write_file（FilesystemMiddleware + backend）
  │
⑦ 收尾：SummarizationMiddleware 若上下文超阈值 → 摘要/卸载（model + backend）
  │
⑧ 持久化：checkpointer 存状态快照，store 存长期记忆
  │
最终：返回报告给用户
```

**每一步都依赖前一步的组件**——这就是"组件关联"的实际含义。
