# DeepAgents 错误处理与重试

Agent 运行的错误来源：**LLM API 故障**、**工具执行异常**、**超时**、**状态不一致**。分层处理策略：工具层 try/except → Agent 层 retry → 服务层超时兜底。

## 一、错误类型全景

| 错误类型 | 来源 | 典型表现 |
|----------|------|----------|
| LLM API 错误 | 模型服务不可用/限流 | `RateLimitError`、`TimeoutError` |
| 工具执行错误 | 工具内部异常 | 任意 Exception，被包装成 ToolMessage |
| 工具输入错误 | LLM 传错参数 | pydantic 校验失败 |
| 图执行错误 | 中间件/状态异常 | `GraphInterrupt`、`GraphRecursionError` |
| 超时 | 整体运行超时 | `TimeoutError` |
| 输入过长 | 上下文超限 | `ContextWindowExceededError` |

## 二、工具层：错误返回给 LLM（推荐）

**工具错误不要抛出，返回错误文本**——LLM 看到错误文本可以自我纠正：

```python
from langchain_core.tools import tool
import json

@tool
def query_database(sql: str) -> str:
    """执行 SQL 查询，返回结果"""
    try:
        result = db.execute(sql)
        return json.dumps(result, ensure_ascii=False)
    except Exception as e:
        # 把错误信息返回给 LLM，LLM 会尝试修复 SQL
        return f"[数据库错误] {e}. 请检查 SQL 语法。"
```

这样 Agent 的流程：

```
LLM: query_database("SELECT FROM")         ← 写错 SQL
工具: [数据库错误] syntax error at or near "FROM"
LLM: 我犯了语法错误，修正为 SELECT * FROM users
工具: 返回数据
LLM: 给出最终回答
```

**注意**：只有"LLM 能自我纠正"的错误才用这个模式。安全敏感错误（认证失败）不要暴露细节。

## 三、Agent 层：重试装饰器

```python
import asyncio
from functools import wraps

def retry_agent(max_retries: int = 3, delay: float = 2.0):
    """Agent 调用重试装饰器：网络抖动/限流时重试"""
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return await func(*args, **kwargs)
                except (TimeoutError, RateLimitError) as e:
                    if attempt == max_retries - 1:
                        raise
                    print(f"[重试 {attempt+1}/{max_retries}] {e}")
                    await asyncio.sleep(delay * (2 ** attempt))  # 指数退避
            return None
        return wrapper
    return decorator

@retry_agent(max_retries=3)
async def run_agent(agent, messages, config):
    return await agent.ainvoke({"messages": messages}, config=config)
```

**只重试可恢复的错误**（限流、超时、5xx），不重试逻辑错误（参数错误、校验失败）——重试只会浪费 token。

## 四、超时控制

### Agent 整体超时

```python
import asyncio

async def invoke_with_timeout(agent, messages, config, timeout: float = 120.0):
    """Agent 调用超时控制，超时返回错误信息而不是崩溃"""
    try:
        return await asyncio.wait_for(
            agent.ainvoke({"messages": messages}, config=config),
            timeout=timeout,
        )
    except asyncio.TimeoutError:
        return {"error": "Agent 执行超时", "timeout": timeout}
```

### FastAPI 层兜底

```python
@app.post("/chat")
async def chat(req: ChatRequest):
    try:
        result = await asyncio.wait_for(
            agent.ainvoke(
                {"messages": [{"role": "user", "content": req.message}]},
                config={"configurable": {"thread_id": req.thread_id}},
            ),
            timeout=120,
        )
        return {"reply": result["messages"][-1].content}
    except asyncio.TimeoutError:
        return {"reply": "请求超时，请重试", "status": "timeout"}
    except Exception as e:
        # 兜底：不把内部错误细节暴露给用户
        return {"reply": "服务异常，请稍后重试", "status": "error"}
```

生产建议：Agent 层 120s + HTTP 层 130s（留出余量），见 [[deepagents/production/生产部署]]。

## 五、Streaming 中的错误捕获

```python
async for event in agent.astream_events(input, version="v3"):
    if event["event"] == "on_tool_error":
        # 工具失败事件
        print(f"工具 {event['name']} 失败: {event['data'].get('error')}")
        # 可以选择：记录日志、通知前端、继续等待 LLM 自我纠正

    if event["event"] == "on_chain_error":
        # 节点失败
        print(f"节点 {event['name']} 失败")

    # 注意：on_tool_error 后 LLM 通常会收到错误信息并自我纠正
    # 所以大多数情况不需要中断整个流程
```

## 六、LLM 递归限制（防死循环）

Agent 无限循环会烧钱。LangChain 内置限制中间件：

```python
from langchain.agents.middleware import ModelCallLimitMiddleware

agent = create_deep_agent(
    model=llm,
    middleware=[
        ModelCallLimitMiddleware(
            thread_limit=20,      # 每个线程最多 20 次模型调用
            error_message="已达到最大模型调用次数，停止执行。",
        ),
    ],
)
```

也可以捕获 `GraphRecursionError`：

```python
from langgraph.errors import GraphRecursionError

try:
    result = agent.invoke(input, config)
except GraphRecursionError:
    print("Agent 循环过深，已停止")
    # 返回部分结果或错误提示
```

## 七、结构化错误响应（面向 API 消费者）

```python
from pydantic import BaseModel
from typing import Any

class AgentError(BaseModel):
    code: str                    # timeout | tool_error | llm_error | unknown
    message: str                 # 用户可读信息
    retryable: bool              # 是否建议重试
    details: dict[str, Any] | None = None  # 内部细节（日志用）

async def safe_agent_invoke(agent, messages, config):
    try:
        result = await agent.ainvoke({"messages": messages}, config=config)
        return {"ok": True, "data": result}
    except asyncio.TimeoutError:
        return {"ok": False, "error": AgentError(
            code="timeout", message="处理超时", retryable=True)}
    except RateLimitError as e:
        return {"ok": False, "error": AgentError(
            code="llm_error", message="模型限流", retryable=True)}
    except GraphRecursionError:
        return {"ok": False, "error": AgentError(
            code="loop", message="任务过于复杂，请拆分成小任务", retryable=False)}
    except Exception as e:
        return {"ok": False, "error": AgentError(
            code="unknown", message="内部错误", retryable=False,
            details={"type": type(e).__name__, "msg": str(e)})}
```

## 八、日志与可观测

```python
import structlog

logger = structlog.get_logger()

async def invoke_with_logging(agent, messages, config):
    thread_id = config["configurable"]["thread_id"]
    logger.info("agent_start", thread_id=thread_id)
    try:
        result = await agent.ainvoke({"messages": messages}, config=config)
        logger.info("agent_success", thread_id=thread_id,
                    msg_count=len(result["messages"]))
        return result
    except Exception as e:
        logger.error("agent_failed", thread_id=thread_id,
                     error=type(e).__name__, msg=str(e))
        raise
```
