# 中间件概述（Middleware）

中间件是 LangChain v1.0+ 提供的 **Agent 执行流程拦截机制**。通过在 Agent 运行的关键节点（钩子 hooks）插入回调函数，可以实现日志记录、上下文压缩、权限审批、PII 脱敏、模型回退等横切关注点（cross-cutting concerns），而无需修改 Agent 本身的业务代码。

> **一句话理解**：中间件 = 围绕 Agent 的"AOP（面向切面编程）"，在 Model/工具调用的前后插入通用逻辑。

## 一、为什么需要中间件

没有中间件时，Agent 流程是一个黑盒——模型决定调哪个工具，工具执行，结果塞回历史，循环往复。中间件解决了以下问题：

| 痛点 | 不用中间件 | 用中间件 |
|------|-----------|---------|
| **可观测性** | 不知道模型何时被调、用了多少 token | 自动记录每次模型/工具调用的输入输出 |
| **上下文管理** | 长对话让 LLM 撑爆 | 自动摘要压缩 / 清除旧工具输出 |
| **成本控制** | 模型陷入死循环，账单爆炸 | 限制模型/工具调用次数 |
| **可靠性** | 工具偶尔失败，整个 Agent 挂掉 | 自动重试 + 主备模型切换 |
| **安全合规** | 用户输入可能含 PII，工具可能误删文件 | 输入脱敏 + 关键操作人工审批 |
| **可扩展性** | 每个 Agent 都重复写日志、校验代码 | 写一次中间件，多个 Agent 复用 |

## 二、核心设计：6 个钩子（Hooks）

中间件在 Agent 的 **6 个关键节点** 暴露钩子，分两类风格：

### 2.1 Node-style 钩子（顺序执行）

按 Agent 执行的特定节点顺序触发，适合日志、校验、状态更新：

| 钩子 | 触发时机 | 典型用途 |
|------|----------|----------|
| `before_agent` | Agent **启动前**（每次调用执行一次） | 初始化资源、加载用户上下文 |
| `before_model` | **每次模型调用前** | 摘要压缩、改写 prompt、PII 脱敏、工具筛选 |
| `after_model` | **每次模型响应后** | 输出校验、记录 token 用量、检测工具调用 |
| `after_agent` | Agent **完成后**（每次调用执行一次） | 清理资源、持久化结果、发送通知 |

### 2.2 Wrap-style 钩子（包装执行）

包裹每次调用，可控制 handler 执行 0 次（短路）、1 次（正常）、N 次（重试），适合重试、缓存、转换：

| 钩子 | 触发时机 | 典型用途 |
|------|----------|----------|
| `wrap_model_call` | 包裹**每次模型调用** | 模型重试、模型回退、动态模型选择、缓存 |
| `wrap_tool_call` | 包裹**每次工具调用** | 工具重试、参数校验、HITL 审批、日志 |

> **官方文档说明**：`before_tool` / `after_tool` 钩子未单独列出。工具调用的拦截主要通过 `wrap_tool_call` 实现——在 handler 调用前后插入逻辑，等效于 `before_tool` + `after_tool` 组合。

### 2.3 完整执行时序

```
用户输入 → before_agent → ┌─ before_model → [模型调用] → after_model ─┐
                          │         ↓ wrap_model_call 包裹          │
                          │  [工具调用决策？]                          │
                          │   ├─ 是 → wrap_tool_call → [工具执行]   │
                          │   └─ 否 → after_agent → 输出结果       │
                          └──────────────────────────────────────┘
```

## 三、4 种使用模式

| 模式 | 适用场景 | 实现方式 |
|------|---------|----------|
| **1. 直接用内置中间件** | 大多数生产场景 | `create_agent(middleware=[SummarizationMiddleware(...)])` |
| **2. 装饰器自定义** | 单一钩子、快速原型 | `@before_model` / `@wrap_tool_call` 等装饰器 |
| **3. 类继承自定义** | 多钩子组合、复杂配置 | 继承 `AgentMiddleware` 基类 |
| **4. 第三方中间件** | 跨项目复用 | 从 `langchain-deepagents` 等包导入 |

## 九、基础用法示例

```python
from langchain.agents import create_agent
from langchain.agents.middleware import (
    SummarizationMiddleware,
    HumanInTheLoopMiddleware,
)
from langchain_deepseek import ChatDeepSeek

summary_llm = ChatDeepSeek(model="deepseek-v4-flash", temperature=0.0)

agent = create_agent(
    model="deepseek-v4-flash",
    tools=[...],
    middleware=[
        SummarizationMiddleware(
            model=summary_llm,
            trigger=("tokens", 4000),    # 触发摘要的阈值
            keep=("messages", 20),       # 摘要后保留的最近消息数
        ),
        HumanInTheLoopMiddleware(
            interrupt_on={"send_email": True},
        ),
    ],
)
```

## 十、在 LangGraph 中嵌入

中间件不是独立运行时——钩子在 `create_agent` 返回的编译好的 LangGraph 图**内部**运行。可以将整个 Agent 作为节点嵌入更大的图：

```python
from langgraph.graph import START, StateGraph

email_agent = create_agent(
    model="claude-sonnet-4-6",
    tools=[read_email, send_email],
    middleware=[HumanInTheLoopMiddleware(interrupt_on={"send_email": True})],
)

graph = (
    StateGraph(AgentState)
    .add_node("classify", classify_node)
    .add_node("email_agent", email_agent)
    .add_edge(START, "classify")
    .add_conditional_edges("classify", route)
    .compile()
)
```
