# 钩子机制详解（Hook Mechanism）

中间件的**核心抽象**是**钩子**（Hook）——Agent 执行流程中的可拦截点。理解钩子机制是编写自定义中间件的前提。

## 一、两类钩子风格

LangChain 提供**两种风格的钩子**：

| 风格 | 钩子 | 特点 | 适用场景 |
|------|------|------|----------|
| **Node-style** | `before_agent` / `before_model` / `after_model` / `after_agent` | **顺序执行**，按时间点触发 | 日志、验证、状态更新 |
| **Wrap-style** | `wrap_model_call` / `wrap_tool_call` | **包装执行**，控制 handler 次数（0/1/N） | 重试、缓存、动态模型选择 |

> **关键区别**：Node-style 钩子**不**能拦截"是否调用模型"——模型总是被调用；Wrap-style 可以让 handler 调用 0 次（短路）、1 次（正常）、N 次（重试）。

## 二、6 个钩子详解

### 2.1 before_agent

**触发时机**：Agent **启动前**，每次 `agent.invoke()` 调用执行一次

**典型用途**：
- 初始化资源（数据库连接、文件句柄）
- 加载用户上下文（从 store 读用户偏好）
- 记录调用开始时间
- 设置初始 state 字段

**签名**：
```python
def before_agent(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    ...

# 或异步
async def abefore_agent(state, runtime) -> dict | None: ...
```

### 2.2 before_model

**触发时机**：**每次模型调用前**

**典型用途**：
- 摘要压缩（SummarizationMiddleware 在这里工作）
- 改写系统提示
- PII 脱敏
- 工具筛选
- 动态注入上下文

**签名**：同 before_agent

### 2.3 after_model

**触发时机**：**每次模型响应后**

**典型用途**：
- 校验输出（检测幻觉、敏感词）
- 记录 token 用量
- 拦截"危险"的工具调用
- 触发"完成"评估（RubricMiddleware）

**签名**：同 before_agent

### 2.4 wrap_model_call

**触发时机**：**包裹每次模型调用**

**典型用途**：
- 模型重试（ModelRetryMiddleware）
- 模型回退（ModelFallbackMiddleware）
- 动态模型选择
- 提示缓存
- 工具集筛选

**签名**：
```python
def wrap_model_call(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    ...

# 异步
async def awrap_model_call(request, handler) -> ModelResponse: ...
```

**示例**（重试）：
```python
@wrap_model_call
def retry(request, handler):
    for attempt in range(3):
        try:
            return handler(request)
        except Exception as e:
            if attempt == 2:
                raise
            time.sleep(1)
```

### 2.5 wrap_tool_call

**触发时机**：**包裹每次工具调用**

**典型用途**：
- 工具重试（ToolRetryMiddleware）
- HITL 审批（HumanInTheLoopMiddleware）
- 参数校验
- 工具调用日志

**签名**：
```python
def wrap_tool_call(
    request: ToolCallRequest,
    handler: Callable[[ToolCallRequest], ToolMessage | Command],
) -> ToolMessage | Command:
    ...

# 异步
async def awrap_tool_call(request, handler) -> ToolMessage | Command: ...
```

> **官方说明**：`before_tool` / `after_tool` 钩子未单独列出。工具调用的拦截通过 `wrap_tool_call` 在 handler 调用前后插入逻辑实现。

### 2.6 after_agent

**触发时机**：Agent **完成后**，每次 `agent.invoke()` 调用执行一次

**典型用途**：
- 清理资源
- 持久化最终结果
- 发送完成通知
- 记录总耗时

**签名**：同 before_agent

## 三、完整执行时序

```
用户调用 agent.invoke(input, config)
  │
  ├── middleware1.before_agent(state, runtime)
  ├── middleware2.before_agent(state, runtime)
  ├── middleware3.before_agent(state, runtime)
  │
  ├── [循环开始] ← 每次用户消息
  │   ├── middleware1.before_model(state, runtime)
  │   ├── middleware2.before_model(state, runtime)
  │   ├── middleware3.before_model(state, runtime)
  │   │
  │   ├── middleware1.wrap_model_call()  ← 嵌套
  │   │   └── middleware2.wrap_model_call()
  │   │       └── middleware3.wrap_model_call()
  │   │           └── [实际模型调用] → response
  │   │       └── [处理 response]
  │   │   └── [处理 response]
  │   │   [处理 response]
  │   │
  │   ├── middleware3.after_model()  ← 逆序
  │   ├── middleware2.after_model()
  │   ├── middleware1.after_model()
  │   │
  │   ├── [模型决定调工具？]
  │   │   ├── 是 → middleware1.wrap_tool_call()
  │   │   │       └── ... (嵌套)
  │   │   │           └── [实际工具执行] → ToolMessage
  │   │   │       └── ... (返回)
  │   │   └── 否 → 跳到 after_agent
  │   │
  │   └── [循环结束或继续]
  │
  ├── middleware3.after_agent()  ← 逆序
  ├── middleware2.after_agent()
  ├── middleware1.after_agent()
  │
  └── 返回最终结果
```

## 四、关键执行规则

| 钩子类型 | 顺序 |
|----------|------|
| `before_*` 钩子 | **正序**（先注册先执行） |
| `after_*` 钩子 | **逆序**（后注册先执行，类似栈） |
| `wrap_*` 钩子 | **嵌套**（第一个中间件包裹所有其他） |

> **为什么逆序？**：类似 `try-finally` 模式——外层中间件先注册，理论上应该最后清理（虽然实际清理逻辑是单独的，但执行顺序保持对称）。

## 五、状态更新机制

### 5.1 Node-style 钩子的状态更新

**直接返回 dict**，通过图的 reducers 合并到 state：

```python
@after_model
def track_calls(state: AgentState, runtime: Runtime) -> dict[str, Any]:
    return {"model_call_count": state.get("model_call_count", 0) + 1}
```

返回的 dict 会与现有 state 合并（按 reducer 规则）。

### 5.2 Wrap-style 钩子的状态更新

**必须返回 `ExtendedModelResponse`** 包裹 `Command`：

```python
from langchain.agents.middleware import wrap_model_call, ExtendedModelResponse
from langgraph.types import Command

@wrap_model_call
def track_usage(request, handler) -> ExtendedModelResponse:
    response = handler(request)
    return ExtendedModelResponse(
        model_response=response,
        command=Command(update={"last_tokens": 150}),
    )
```

> **重要**：`Command` 流经图的 reducers，消息以**追加**方式合并而非替换。

### 5.3 多中间件冲突时

- **通过 reducers 应用**：每个 `Command` 是独立的状态更新
- **冲突时外部优先**：非 reducer 字段按"内层先、外层后"应用，**最外层中间件的值在冲突键上获胜**
- **重试安全**：外层中间件多次调用 `handler()`（如重试），早期调用的命令会被丢弃

## 六、自定义状态 Schema

中间件可扩展 Agent state，跨钩子共享数据。

**装饰器版**：
```python
class CustomState(AgentState):
    model_call_count: NotRequired[int]
    user_id: NotRequired[str]

@before_model(state_schema=CustomState, can_jump_to=["end"])
def check_limit(state: CustomState, runtime: Runtime):
    if state.get("model_call_count", 0) > 10:
        return {"jump_to": "end"}
    return None

@after_model(state_schema=CustomState)
def increment(state: CustomState, runtime: Runtime):
    return {"model_call_count": state.get("model_call_count", 0) + 1}
```

## 七、Agent Jumps（提前跳转）

通过返回 `jump_to` 字段实现提前退出。

| 目标值 | 行为 |
|--------|------|
| `'end'` | 跳到执行结束（或第一个 `after_agent` 钩子） |
| `'tools'` | 跳到工具节点 |
| `'model'` | 跳到模型节点（或第一个 `before_model` 钩子） |

**示例**：
```python
from langchain.agents.middleware import after_model, hook_config, AgentState
from langchain.messages import AIMessage
from langgraph.runtime import Runtime

@after_model
@hook_config(can_jump_to=["end"])
def check_blocked(state: AgentState, runtime: Runtime):
    last_message = state["messages"][-1]
    if "BLOCKED" in last_message.content:
        return {
            "messages": [AIMessage("I cannot respond to that request.")],
            "jump_to": "end",
        }
    return None
```

> 注意：`can_jump_to=["end"]` 必须在 `@hook_config` 中显式声明，否则会抛 `ValueError`。
