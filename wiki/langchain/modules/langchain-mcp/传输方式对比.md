# 传输方式对比

MCP 客户端支持多种传输方式，适用于不同的部署和通信场景。

## 对比总览

| 传输方式 | 适用场景 | 配置方式 | 特点 |
|----------|---------|----------|------|
| `stdio` | 本地进程 | `command` + `args` | 通过标准输入输出通信 |
| `sse` | 服务端推送 | `url` | HTTP 长连接，服务器单向推送 |
| `websocket` | 双向实时 | `url` | 双向实时通信 |
| `streamable_http` | HTTP 流式 | `url` | 新版 HTTP 流式协议 |

## stdio -- 本地进程通信

最基础的传输方式，通过启动本地子进程并用标准输入/输出通信：

```python
config = {
    "github": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"][[,
        "env": {"GITHUB_TOKEN": "ghp_..."},
        "transport": "stdio",
    },
}
```

**特点：**
- 无需网络服务，直接启动进程
- 子进程生命周期由客户端管理
- `env` 用于设置子进程环境变量
- 适合本地开发工具

## SSE -- 服务端推送事件

基于 HTTP 的服务端推送，适合已有 HTTP 服务的场景：

```python
config = {
    "filesystem": {
        "url": "http://localhost:3000/sse",
        "transport": "sse",
    },
}
```

**特点：**
- 服务器单向推送事件到客户端
- 基于 HTTP 长连接
- 服务器需要独立启动并保持运行
- 适合内部服务

## WebSocket -- 双向实时通信

全双工通信，适合需要实时交互的场景：

```python
config = {
    "database": {
        "url": "ws://localhost:8000/ws",
        "transport": "websocket",
    },
}
```

**特点：**
- 双向实时通信
- 低延迟
- 适合高频交互场景
- 服务器需支持 WebSocket 协议

## streamable_http -- HTTP 流式（新版）

新版 HTTP 流式协议，结合了 HTTP 的简单性和流式的效率：

```python
config = {
    "weather": {
        "url": "https://weather-mcp.example.com/mcp",
        "transport": "streamable_http",
    },
}
```

**特点：**
- 基于标准 HTTP，易于部署
- 支持流式响应
- 适合云服务和远程 API
- 是 MCP 协议推荐的新传输方式

## 选型建议

| 场景 | 推荐传输 |
|------|---------|
| 本地开发工具（GitHub、FS） | `stdio` |
| 内部微服务 | `sse` 或 `websocket` |
| 远程云服务 | `streamable_http` |
| 高频双向交互 | `websocket` |
| 简单单向数据流 | `sse` |

## 注意事项

- `stdio` 类型的服务器在客户端启动时自动创建子进程
- `sse`、`websocket`、`streamable_http` 类型的服务器需要预先启动
- 不同传输方式可以混合使用（同一 `MultiServerMCPClient` 中）
- stdio 的 `env` 参数仅影响子进程的环境变量
