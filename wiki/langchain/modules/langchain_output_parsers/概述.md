# output_parsers 模块

## 是什么

`langchain.output_parsers`（底层 `langchain_core.output_parsers`）将 LLM 的**字符串输出解析为结构化数据**，如 JSON、Pydantic 对象、列表、枚举等。

解析器本质上是 `Runnable`，可以像其他组件一样通过 `|` 管道符串联成链：`prompt | model | parser`。

## 有什么用

- 把 LLM 文本输出转为可编程的结构化对象（dict、Pydantic 实例、列表等）
- 自动类型校验与字段约束（Pydantic 解析器）
- 生成 `format_instructions` 注入提示词，引导 LLM 输出正确格式
- 与 ChatModel 链式组合（`prompt | model | parser`）
- 配合 `OutputFixingParser` 实现自动重试与错误修正

## 导入路径

所有核心解析器均从 `langchain_core.output_parsers` 导入，**不需要**安装额外的包：

```python
# 核心解析器 — 来自 langchain_core
from langchain_core.output_parsers import (
    StrOutputParser,
    JsonOutputParser,
    PydanticOutputParser,
    ListOutputParser,
    CommaSeparatedListOutputParser,
    EnumOutputParser,
    OutputFixingParser,
    RetryWithErrorOutputParser,
    PydanticToolsParser,
)

# StructuredOutputParser 来自 langchain（非 core）
from langchain.output_parsers import StructuredOutputParser
```

> **注意**：`langchain` 包会 re-export `langchain_core` 中的解析器，所以 `from langchain.output_parsers import StrOutputParser` 也能用，但推荐直接从 `langchain_core` 导入，依赖更清晰。

## 关键类

| 类 | 导入来源 | 输出类型 | 描述 | 典型场景 |
|-----|---------|---------|------|---------|
| `StrOutputParser` | `langchain_core` | `str` | 直接提取 `AIMessage.content` 字符串，无任何解析 | 聊天回复、文本生成、摘要 |
| `JsonOutputParser` | `langchain_core` | `dict` | 将 LLM 输出解析为 JSON 字典，可选传入 `pydantic_object` 做 schema 约束 | 快速提取 JSON 字段、轻量结构化输出 |
| `PydanticOutputParser` | `langchain_core` | `BaseModel` 实例 | 将 LLM 输出解析为 Pydantic 模型实例，自动类型校验 | 强类型数据提取、生产环境结构化输出 |
| `ListOutputParser` | `langchain_core` | `list[str]` | 基类，将输出按分隔符拆分为列表 | 自定义列表解析逻辑 |
| `CommaSeparatedListOutputParser` | `langchain_core` | `list[str]` | 按逗号分隔解析列表 | 提取标签、关键词、人名列表 |
| `EnumOutputParser` | `langchain_core` | `Enum` 值 | 将输出映射到预定义的枚举值 | 分类任务、情感分析（正/负/中） |
| `StructuredOutputParser` | `langchain` | `dict` | 通过 `ResponseSchema` 列表定义字段结构，无需 Pydantic | 不想用 Pydantic 但需要字段约束 |
| `OutputFixingParser` | `langchain_core` | 取决于内部 parser | 包装另一个解析器，解析失败时调用 LLM 自动修正输出 | 生产环境容错、处理不稳定的 LLM 输出 |
| `RetryWithErrorOutputParser` | `langchain_core` | 取决于内部 parser | 解析失败时将错误信息反馈给 LLM 重新生成 | 高可靠性要求的链式调用 |
| `PydanticToolsParser` | `langchain_core` | `list[BaseModel]` | 从模型的工具调用（tool calls）中提取 Pydantic 对象 | `with_structured_output` 的底层组件、function calling 场景 |

## 基础用法

```python
from langchain_core.output_parsers import StrOutputParser
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate

model = ChatOpenAI(model="gpt-4o-mini")

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个有帮助的助手。"),
    ("human", "给我讲一个关于{topic}的笑话。"),
])

# 管道链：prompt → model → parser
chain = prompt | model | StrOutputParser()
result = chain.invoke({"topic": "AI"})
print(result)  # 纯文本字符串
```

### PydanticOutputParser 用法示例

```python
from langchain_core.output_parsers import PydanticOutputParser
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate
from pydantic import BaseModel, Field

model = ChatOpenAI(model="gpt-4o-mini")

class Joke(BaseModel):
    """一个笑话的结构"""
    setup: str = Field(description="笑话的铺垫部分")
    punchline: str = Field(description="笑话的包袱/笑点")
    rating: int = Field(description="搞笑程度，1-10分", ge=1, le=10)

parser = PydanticOutputParser(pydantic_object=Joke)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个喜剧演员。回答用户的问题。\n{format_instructions}"),
    ("human", "{query}"),
]).partial(format_instructions=parser.get_format_instructions())

chain = prompt | model | parser
joke = chain.invoke({"query": "给我讲一个关于程序员的冷笑话"})
print(joke.setup)        # 字符串
print(joke.punchline)    # 字符串
print(joke.rating)       # 整数
```

## 选型指南

### 决策树

```
你需要结构化输出吗？
├── 不需要，只要纯文本
│   └── → StrOutputParser
│
└── 需要结构化输出
    ├── 模型支持 tool calling / function calling 吗？
    │   └── 是 → 优先用 model.with_structured_output(PydanticModel)
    │            （见下方"Parser vs with_structured_output 对比"）
    │
    └── 不支持 tool calling，或使用链式调用
        ├── 需要强类型校验 + Pydantic 模型？
        │   ├── 是 → PydanticOutputParser
        │   └── 否，只要 dict → JsonOutputParser
        │
        ├── 只需要一个列表？
        │   └── → CommaSeparatedListOutputParser
        │
        ├── 只需要一个枚举值？
        │   └── → EnumOutputParser
        │
        └── 担心 LLM 输出不稳定？
            └── → 在上述 parser 外包裹 OutputFixingParser
```

### 按场景选型表

| 场景 | 推荐解析器 | 说明 |
|------|----------|------|
| 简单文本回复、聊天机器人 | `StrOutputParser` | 最轻量，直接取 content |
| 快速原型、提取 JSON 字段 | `JsonOutputParser` | 无需定义 Pydantic 模型 |
| 生产环境强类型数据 | `PydanticOutputParser` | 自动类型校验，字段约束 |
| 模型支持 tool calling 的结构化输出 | `model.with_structured_output()` | **现代推荐方式**，见下方对比 |
| 提取标签、关键词列表 | `CommaSeparatedListOutputParser` | 简单高效 |
| 分类任务（正/负/中） | `EnumOutputParser` | 限定输出范围 |
| 不想用 Pydantic 但要字段约束 | `StructuredOutputParser` | 通过 ResponseSchema 定义 |
| LLM 输出不稳定需自动修正 | `OutputFixingParser` | 包裹其他 parser，失败时调 LLM 修正 |
| 高可靠性场景 | `RetryWithErrorOutputParser` | 将错误反馈给 LLM 重试 |
| Agent 结构化响应 | `create_agent(response_format=...)` | Agent 专用 |

## Parser vs with_structured_output 对比

LangChain 提供了两种方式获取结构化输出，各有适用场景：

### 方式一：手动 Parser（传统方式）

```python
from langchain_core.output_parsers import PydanticOutputParser
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate
from pydantic import BaseModel, Field

class Movie(BaseModel):
    title: str = Field(description="电影名称")
    year: int = Field(description="上映年份")

model = ChatOpenAI(model="gpt-4o-mini")
parser = PydanticOutputParser(pydantic_object=Movie)

prompt = ChatPromptTemplate.from_messages([
    ("system", "回答用户问题。\n{format_instructions}"),
    ("human", "{query}"),
]).partial(format_instructions=parser.get_format_instructions())

chain = prompt | model | parser
movie = chain.invoke({"query": "推荐一部经典电影"})
```

### 方式二：with_structured_output（现代推荐方式）

```python
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

class Movie(BaseModel):
    title: str = Field(description="电影名称")
    year: int = Field(description="上映年份")

model = ChatOpenAI(model="gpt-4o-mini")

# 直接让模型输出结构化数据，无需手动写 format_instructions
structured_model = model.with_structured_output(Movie)
movie = structured_model.invoke("推荐一部经典电影")
print(movie.title, movie.year)
```

### 对比表

| 维度 | 手动 Parser | with_structured_output |
|------|-----------|----------------------|
| **原理** | 在提示词中注入格式说明，LLM 输出文本后由 parser 解析 | 利用模型的 tool calling / JSON mode 原生能力 |
| **可靠性** | 中等，LLM 可能不遵循格式说明 | 高，模型原生保证输出结构 |
| **需要 format_instructions** | 是，必须注入提示词 | 否，自动处理 |
| **模型要求** | 任何模型 | 需要模型支持 tool calling 或 JSON mode |
| **灵活性** | 高，可自定义解析逻辑 | 中，依赖模型能力 |
| **适用模型** | 所有 LLM（包括不支持 tool calling 的） | OpenAI、Anthropic、Google 等主流模型 |
| **流式支持** | 有限（JSON 流式拼接复杂） | 好（部分策略支持） |
| **推荐程度** | 兼容旧模型时使用 | **生产环境首选** |

> **总结**：如果你的模型支持 tool calling（如 GPT-4o、Claude、Gemini），**优先使用 `with_structured_output`**。手动 Parser 主要用于不支持 tool calling 的模型，或需要高度自定义解析逻辑的场景。

## 错误处理

所有解析器在解析失败时都会抛出 `OutputParserException`，务必在关键路径上捕获：

```python
from langchain_core.exceptions import OutputParserException
from langchain_core.output_parsers import JsonOutputParser
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate

model = ChatOpenAI(model="gpt-4o-mini")
parser = JsonOutputParser()

prompt = ChatPromptTemplate.from_messages([
    ("system", "输出 JSON 格式：{{\"name\": ..., \"age\": ...}}"),
    ("human", "{query}"),
][[)

chain = prompt | model | parser

try:
    result = chain.invoke({"query": "介绍爱因斯坦"})
    print(result)
except OutputParserException as e:
    print(f"解析失败: {e}")
    print(f"LLM 原始输出: {e.llm_output}")      # LLM 的实际 text output
    print(f"错误详情: {e.observation}")          # 人类可读的错误描述
    # 可以在这里做降级处理、重试、或通知用户
```

### 自动修正模式

用 `OutputFixingParser` 包裹解析器，解析失败时自动调用 LLM 修正：

```python
from langchain_core.output_parsers import PydanticOutputParser, OutputFixingParser
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

model = ChatOpenAI(model="gpt-4o-mini")

class Answer(BaseModel):
    result: str = Field(description="答案")
    confidence: float = Field(description="置信度 0-1", ge=0, le=1)

base_parser = PydanticOutputParser(pydantic_object=Answer)

# 包裹一层：解析失败时自动让 LLM 修正
fixing_parser = OutputFixingParser.from_llm(
    parser=base_parser,
    llm=model,
)

# fixing_parser 会：
# 1. 尝试用 base_parser 解析
# 2. 如果失败，把错误信息和原始输出发给 LLM
# 3. LLM 返回修正后的输出
# 4. 再次尝试解析
```

## 注意事项

- 解析器**不会**调用 LLM，仅做格式转换（`OutputFixingParser` 和 `RetryWithErrorOutputParser` 例外）
- 使用 `PydanticOutputParser` / `JsonOutputParser(pydantic_object=...)` 时，提示词中需包含 `format_instructions`（通过 `get_format_instructions()` 生成并注入）
- 对于支持 tool calling 的现代模型，**优先使用 `with_structured_output`** 而非手动 parser
- `Field(description=...)` 的描述内容会直接传给 LLM，写清楚、写准确能显著提高解析成功率
- 流式输出时，`JsonOutputParser` 和 `PydanticOutputParser` 只有在 JSON 完整后才会 yield 结果
