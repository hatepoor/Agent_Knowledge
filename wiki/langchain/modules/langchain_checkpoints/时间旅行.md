# 时间旅行

时间旅行允许 Agent **回到历史检查点**，从某个旧状态重新开始执行，实现对话分支和状态回溯。

## 原理

1. Checkpointer 保存每一步的完整状态快照
2. 通过 `list()` 获取所有历史检查点
3. 选择目标检查点的 config，用它 invoke Agent
4. Agent 从该检查点继续执行（创建新的分支）

## 基本用法

```python
import os
os.environ["OPENAI_API_KEY"] = "sk-..."

from langgraph.checkpoint.memory import InMemorySaver
from langchain.agents import create_agent

checkpointer = InMemorySaver()
agent = create_agent("openai:gpt-5.5", tools=[], checkpointer=checkpointer)

config = {"configurable": {"thread_id": "user-1-session"}}

# 执行多轮对话，积累检查点
agent.invoke({"messages": [{"role": "user", "content": "Step 1"}]}, config)
agent.invoke({"messages": [{"role": "user", "content": "Step 2"}]}, config)
agent.invoke({"messages": [{"role": "user", "content": "Step 3"}]}, config)
```

## 获取历史检查点

```python
# 列出所有检查点
checkpoints = list(checkpointer.list(config))

# 按时间排序（最新在前）
for i, cp in enumerate(checkpoints):
    print(f"[{i}] Step {cp.metadata['step']}: {cp.config}")
```

## 回到旧检查点

```python
# 选择第 3 个检查点（索引 2）
old_config = checkpoints[2].config

# 从旧检查点重新 invoke -- 创建新的执行分支
r4 = agent.invoke(
    {"messages": [{"role": "user", "content": "Alternative question"}][[},
    old_config,
)
# Agent 从第 2 步的状态继续，而不是从最新状态继续
```

## 使用场景

| 场景 | 说明 |
|------|------|
| 对话分支 | 从某个历史点创建不同的对话路径 |
| 状态回溯 | 撤销最近的操作，回到之前的状态 |
| 调试 | 检查 Agent 在某一步的状态 |
| A/B 测试 | 从同一状态尝试不同策略 |

## 注意事项

- 时间旅行会**创建新的执行分支**，不影响原有检查点历史
- 新分支的检查点会引用 `parent_config` 指向原始检查点
- 检查点包含完整状态，大量步骤时存储开销较大
- `parent_config` 字段可用于追溯分支的原始来源
