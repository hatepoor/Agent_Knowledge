# A2A 速查索引

> **本页定位：给签名与骨架，不给解释。** 方法名、状态名、字段名的速查表。
> 含义与机制在正文，详见 [[a2a/A2A术语与关键字手册]] 的「详解」列指向。

---

## 一、Task 状态速查

| 状态 | 类型 | 触发条件 | 客户端该做什么 |
|------|------|---------|--------------|
| `submitted` | 非终态 | 服务端已接收，未开始处理 | 等待或轮询 |
| `working` | 非终态 | 正在执行 | 等待 / 订阅流 / 等推送 |
| `input-required` | 非终态 | 缺信息，需要调用方补充 | **发新 Message 补齐信息** |
| `auth-required` | 非终态 | 鉴权失效 | **重新取 token 后重试** |
| `completed` | 终态 | 成功，Artifact 已挂载 | 读取 Artifact |
| `failed` | 终态 | 处理中出错 | 排查；重试需新建 Task |
| `canceled` | 终态 | 客户端取消 | 结束 |
| `rejected` | 终态 | 服务端开始前拒绝（策略/不支持/限流） | 换 Agent 或退避后重试 |

⚠️ **终态不可再变。** 重试必须新建 Task，不能「复活」旧 Task。

## 二、核心方法名（JSON-RPC 绑定）

| 方法 | 作用 | 返回 |
|------|------|------|
| `message/send` | 发送消息，同步等结果 | Task 或 Message |
| `message/stream` | 发送消息，SSE 流式收增量 | 流式 Task 事件 |
| `tasks/get` | 拉取指定 Task 当前状态 | Task |
| `tasks/list` | 列出 Task（v1.0 起） | Task 列表 |
| `tasks/cancel` | 请求取消 Task | Task（终态） |
| `tasks/subscribe` | 订阅已有 Task 的流式更新 | SSE 流 |
| `tasks/pushNotificationConfig/set` | 设置推送 webhook | 配置对象 |
| `tasks/pushNotificationConfig/get` | 读取推送配置 | 配置对象 |
| `tasks/pushNotificationConfig/list` | 列出推送配置 | 配置列表 |
| `tasks/pushNotificationConfig/delete` | 删除推送配置 | 空 |
| `agent/getAuthenticatedExtendedCard` | 认证后拉取扩展版 Agent Card | Agent Card |

> gRPC 与 REST 绑定暴露**同一组操作**，只是命名风格不同（gRPC 为 `GetTask` 等方法名，REST 为 `GET /tasks/{id}` 风格路径）。

## 三、Agent Card 字段速查

| 字段 | 必填 | 说明 |
|------|------|------|
| `protocolVersion` | ✔ | 协议版本，如 `"1.0"` |
| `name` | ✔ | Agent 名称 |
| `description` | ✔ | 一句话描述 |
| `version` | ✔ | Agent 自身版本，与协议版本无关 |
| `provider` | | 组织名与网址 |
| `supportedInterfaces[]` | ✔ | 可用接口列表：`url` / `protocolBinding` / `protocolVersion` |
| `url` | | 单接口简写（多绑定时用 `supportedInterfaces`） |
| `capabilities.streaming` | | 是否支持 SSE 流式 |
| `capabilities.pushNotifications` | | 是否支持 webhook 推送 |
| `capabilities.extendedAgentCard` | | 是否提供认证后可拉的扩展卡 |
| `securitySchemes` | | 接受的鉴权方式（`oauth2` / `openIdConnect` / `apiKey` / `http` / `mutualTLS`） |
| `security` | | 具体哪个方案对应哪些 scope |
| `defaultInputModes[]` | | 默认接受的 MIME 类型 |
| `defaultOutputModes[]` | | 默认产出的 MIME 类型 |
| `skills[]` | ✔ | 能力清单：`id` / `name` / `description` / `tags` / `examples` |
| `signatures[]` | | 加密签名（v1.0 新增），字段含 `alg` / `kid` / `signature` |
| `extensions[]` | | 扩展声明，`uri` + `required` |
| `preferredTransport` | | 首选绑定（v1.0） |

## 四、Part 四种形态

| `type` | 字段 | 用途 |
|--------|------|------|
| `text` | `text` | 纯文本 / Markdown |
| `file`（内联） | `bytes`（base64） | 小文件直接塞进报文 |
| `file`（引用） | `url` + `mimeType` | 大文件给 URL（推荐） |
| `data` | `data`（任意 JSON） | **结构化数据，程序可直接消费** |

⚠️ 内联文件会撑大报文。跨网络传文件一律优先用 URL 引用。

## 七、安全速查

| 项 | 要求 |
|---|------|
| 传输加密 | **必须**。HTTP 绑定用 HTTPS，gRPC 用 TLS |
| 授权检查 | **每个操作**都要查，且结果限制在调用方有权范围内 |
| 授权模型 | 由各 Agent 自定，**协议不强制** |
| 可声明的鉴权 | API Key / HTTP Auth / OAuth 2.0(2.1) / OpenID Connect / mTLS |
| 凭证传递 | 走 HTTP 头，与 A2A 报文分离 |
| webhook | 服务端须**校验 URL 防 SSRF**；客户端须**校验通知真实性** |
| Agent Card | 公开可抓取，**禁止写密钥** |

## 八、A2A / MCP 一句话判定

| 情况 | 选 |
|------|-----|
| 被调用方是个「完全可以写成 REST 端点的函数」 | **MCP** |
| 被调用方会自己推理、规划，且可能再调别的工具或 Agent | **A2A** |
| Agent 都在你自己的代码库里 | **都不需要**，直接函数调用 |
| 要跨团队 / 跨厂商 / 跨云 | **A2A** |

## 十、Python SDK 代码符号速查

> 下面这些是**代码里会看到的类名和函数名**。全部来自 `a2a-sdk`，示例见 [[a2a/01-入门阶段-协议基础/第02章-工程实践/2.1-Python-SDK最小可用实现]]。

### 服务端要用的

| 符号 | 类型 | 作用 |
|------|------|------|
| `AgentExecutor` | 抽象基类 | **你要实现的两个方法**：`execute(context, event_queue)` 和 `cancel(context, event_queue)` |
| `RequestContext` | 参数 | `execute` 的第一个参数，从它取 `context.current_task` 和 `context.message` |
| `EventQueue` | 参数 | `execute` 的第二个参数，事件出口 |
| `TaskUpdater` | 类 | 状态与产出的更新器：`update_status()` / `add_artifact()` |
| `new_task_from_user_message` | 函数 | 用 Message 建新 Task |
| `new_text_message` | 函数 | 造一条 `role` 为 agent 的文本 Message |
| `new_text_part` | 函数 | 造一个文本 Part |
| `DefaultRequestHandler` | 类 | 协议层：路由 RPC、管理 task 生命周期、校验 Agent Card 声明的能力 |
| `InMemoryTaskStore` | 类 | Task 存储。⚠️ **重启即丢，生产必须换掉** |
| `create_agent_card_routes` | 函数 | 把 Agent Card 发布到 `/.well-known/agent-card.json` |
| `create_jsonrpc_routes` | 函数 | 暴露 JSON-RPC 方法（同族还有 `create_grpc_routes` / `create_rest_routes`） |

### 类型对象

| 符号 | 对应 JSON 字段 |
|------|--------------|
| `AgentCard` | 整张卡 |
| `AgentSkill` | `skills[]` 的一项 |
| `AgentInterface` | `supportedInterfaces[]` 的一项 |
| `AgentCapabilities` | `capabilities` |
| `TaskState` | 状态枚举，成员形如 `TASK_STATE_WORKING` |

### 客户端要用的

| 符号 | 作用 |
|------|------|
| `A2ACardResolver` | 按 base_url 拉取 Agent Card（`get_agent_card()`） |
| `create_client` | 按卡片的 `supportedInterfaces` 建客户端，自动选绑定 |
| `ClientConfig(streaming=...)` | 客户端配置，`streaming=True` 走 SSE |
| `SendMessageRequest` | 请求包装，字段 `message` |
| `Role.ROLE_USER` / `Role.ROLE_AGENT` | 消息角色枚举 |

### 命名的坑

| 位置 | 风格 | 例子 |
|------|------|------|
| **Python 代码** | snake_case | `supported_interfaces`、`protocol_binding`、`default_input_modes`、`extended_agent_card` |
| **JSON / 文档** | camelCase | `supportedInterfaces`、`protocolBinding`、`defaultInputModes`、`extendedAgentCard` |

⚠️ **同一份卡片在代码里是 snake_case，在 JSON 里是 camelCase。** 这是翻文档时最常见的困惑来源。
