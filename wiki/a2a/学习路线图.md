# A2A 学习路线图

> 本页给出**两条路径**，按你的目的选一条，不要两条都走。
> 入门阶段知识有强依赖，第00章 → 第01章 → 第02章必须按顺序读；中段专题可跳读。

---

## 一、先判断你属于哪种学法

| 你的目的 | 走哪条 | 大约篇数 |
|---------|-------|---------|
| **面试要能讲清 A2A 是什么、和 MCP 什么关系** | 路径 A · 概念优先 | 6 篇 |
| **手上项目要接一个别人写的 Agent** | 路径 B · 落地优先 | 8 篇 |
| **只为判断自己该不该用** | 只读 [[a2a/02-中段阶段-生产实践/04-落地时机与不适用场景]] | 1 篇 |

## 二、路径 A · 概念优先（面试 / 体系认知）

```
0.1 A2A是什么                    ← 定位、与 MCP 的关系、官方明确的「不是什么」
   ↓
0.2 为什么需要A2A                ← 它解决的四类具体困境
   ↓
0.3 版本演进与治理历程            ← Google→LF→AAIF、v1.0 带来了什么
   ↓
1.1 AgentCard 与智能体发现        ← 契约与发现机制
   ↓
1.2 Task / Message / Part / Artifact  ← 四个数据对象
   ↓
1.4 Task 生命周期与状态机          ← A2A 与 MCP 最大的差异点
   ↓
【到此已足够应付绝大多数面试追问】
   ↓ 可选
03 A2A 与 MCP 选型决策树          ← 决策维度总结
```

**这条路径结束后你应该能回答：**
1. A2A 和 MCP 的区别，用一句话怎么说？
2. Agent Card 里最关键的三个字段是什么？
3. A2A 的 Task 有哪 8 个状态？哪些是终态？
4. 什么场景该用 A2A，什么场景不该用？
5. v1.0 相比 v0.3 最大的变化是什么？

## 三、路径 B · 落地优先（真要接一个远端 Agent）

```
读完 README 的门槛声明
   ↓
0.1 → 0.2（快速过）→ 1.1 → 1.2 → 1.3 → 1.4   （核心对象，跳过 0.3）
   ↓
2.1 Python SDK 最小可用实现        ← 跑通一个服务端 + 一个客户端
   ↓
2.2 把远端 Agent 包装成本地工具      ← 接入你现有 LangGraph 系统的正确姿势
   ↓
01 安全模型与鉴权                  ← 上生产前必读
   ↓
02 版本演进与迁移陷阱               ← 有存量 0.3 实现才需要
   ↓
04 落地时机与不适用场景             ← 上线前最后一次自检
   ↓
06 生态现状与厂商支持               ← 选 SDK / 选平台时看
```

**这条路径结束后你应该能：**
1. 用 `a2a-sdk` 起一个最小 A2A 服务端，自动发布 Agent Card
2. 说清本地双进程练手与真实跨组织场景的差别在哪
3. 把远端 Agent 接进现有 LangGraph Agent，且不污染原有架构
4. 列出上线前必须检查的安全项

## 四、阶段划分与前置关系

### 01 入门阶段 · 协议基础（9 篇）

> **零基础起点，不要求任何前置知识**（但默认你听说过 Agent 和工具调用）。
> **知识有线性依赖，必须按章节顺序推进**，不要跳读第01章。

- **第00章 学前准备（3 篇）** — 定位、动机、版本史
- **第01章 核心对象（4 篇）** — Agent Card / 四件套 / 交互机制 / 状态机
- **第02章 工程实践（2 篇）** — SDK 最小实现 / 包装成本地工具

### 02 中段阶段 · 生产实践（6 专题 + 导航）

> **平行专题，无依赖，可跳读。前置：入门阶段已学完。**
> 每篇含「什么时候该读」标注。

| 专题 | 什么时候必读 |
|------|------------|
| 01 安全模型与鉴权 | **要上生产就必读** |
| 02 版本演进与迁移陷阱 | 已有 0.3 实现 |
| 03 A2A 与 MCP 选型决策树 | 做技术选型 |
| 04 落地时机与不适用场景 | 上线前自检 |
| 05 与 LangGraph 多智能体的关系 | 你在做多智能体 |
| 06 生态现状与厂商支持 | 选 SDK / 选云平台 |

## 五、毕业自测清单

学完入门阶段后，逐条自问。**答不上来的，回对应页面重读。**

- [ ] 我能用一句话说清 A2A 解决什么问题？（不查资料）
- [ ] 我能画出「Agent → MCP → 工具」和「Agent → A2A → Agent」的区别吗？
- [ ] 我知道 Agent Card 放在哪个 URL、包含哪几类信息吗？
- [ ] 我能解释为什么 Part 要支持 `data`（结构化数据）而不是只有文本？
- [ ] 我能说出 Task 的 8 个状态，并指出哪个是「被对方拒绝」而不是「出错」
- [ ] 我知道终态能不能复活吗？
- [ ] 我能说出三种交互机制各自适合什么场景吗？
- [ ] 我知道 `rejected` 和 `failed` 的区别吗？
- [ ] 我能解释「为什么我现在的多智能体项目不需要 A2A」吗？
- [ ] 我知道官方明确说了 A2A **不是**什么吗？

**及格线：10 条里答对 8 条。** 答不对 3 条以上说明第01章没读透，回去重读。
