## 一、完整时间线

先建立时间轴，后面的细节都挂在这上面。

| 日期 | 事件 | 为什么重要 |
|------|------|-----------|
| 2024-11 | Anthropic 发布 **MCP** | 纵向（agent→tool）这条线的起点 |
| **2025-04-09** | Google 在 Cloud Next 发布 **A2A**，50+ 首批伙伴 | 横向（agent→agent）这条线的起点 |
| **2025-06-23** | Google Cloud 把 A2A 捐赠给 **Linux Foundation** | 从「Google 的协议」变成「中立协议」 |
| 2025-08 | IBM 的 **ACP** 并入 A2A | 横向协议竞争结束，不再有两套标准 |
| 2025-12-09 | Linux Foundation 成立 **AAIF**（Agentic AI Foundation），MCP 成为首个项目 | Agent 协议开始统一治理 |
| **2026-03-12** | **A2A v1.0.0** 发布，首个稳定版 | 从「能互通」变成「可生产依赖」 |
| 2026-05-28 | v1.0.1 补丁版 | 当前最新 |
| **2026-08-17** | AAIF 接纳 A2A 为 **Growth Stage 项目** | 与 MCP 同一屋檐下 |

### 首批 50 家伙伴里值得注意的几家

Atlassian、Box、Intuit、**LangChain**、MongoDB、PayPal、Salesforce、SAP、ServiceNow、Workday，以及一批咨询公司（Accenture、BCG、Deloitte、KPMG、McKinsey、PwC 等）。

> 出现 LangChain 值得留意——这意味着这个生态和你的技术栈不是割裂的。

## 二、三步走：为什么治理变更比发布更重要

### 第一步：Google 私有协议（2025-04）

A2A 最初由 Google 开发发布，一开始就宣称是「开放、社区所有的标准」，并邀请其他厂商参与。

**但它有个致命问题**：一个协议如果由某家公司实际控制，别人不敢依赖。这就像「Google 出的规范随时可能为了自家产品而改」。

### 第二步：捐赠给 Linux Foundation（2025-06-23）

Google Cloud 把规范、SDK、开发工具**全部**捐给了 Linux Foundation。协议由一个技术指导委员会（TSC）维护，委员会由八家公司代表组成：

**AWS、Cisco、Google、IBM Research、Microsoft、Salesforce、SAP、ServiceNow**

⚠️ **注意这个名单里没有 Anthropic 和 OpenAI**——它们两家当时都未公开声明支持 A2A。这在理解「生态热度」时是个重要事实。

**这一步的意义**：协议的所有权归基金会，不归任何单一公司。厂商想改协议，得经过 TSC，不能自己拍板。

### 第三步：并入 AAIF（2026-08-17）

AAIF（Agentic AI Foundation）是 Linux Foundation 2025-12-09 成立的子基金会。它同时托管：

| 项目 | 干什么 |
|------|--------|
| **MCP** | agent → tool |
| **A2A** | agent → agent |
| **AGENTS.md** | OpenAI 的纯文本约定，告诉编码 agent 如何在仓库里工作 |
| **goose** | Block 的开源 agent 运行时 |
| **agentgateway** | agent 流量的路由、策略与可观测性代理 |

**这一步的意义**：MCP 和 A2A 从此在同一个中立治理框架下。这大幅降低了「押错边」的风险——你不用再赌「万一 A2A 倒了怎么办」。

> ⚠️ **一个容易被媒体标题误导的点**：这不是一次「新捐赠」。A2A 从 2025-06-23 起就已经是 Linux Foundation 的财产了。2026-08 的变化只是**从基金会顶层移到子基金会**。有第三方评测指出，A2A 仓库的 `GOVERNANCE.md` 在这次变动后仍描述着同一个 8 席 TSC、都没提 AAIF——说明治理实质变化很小，变化的是组织归属。

## 三、v1.0 带来了什么

v1.0.0（2026-03-12）是首个「稳定、生产可用」版本。相比 v0.3，重点有五项：

| 变化 | 解决什么 |
|------|---------|
| **多协议绑定** | 数据模型与传输解耦，三套绑定（JSON-RPC / gRPC / HTTP+JSON）暴露同一组操作 |
| **版本协商** | Agent Card 里带 `protocolVersion`，双方能对齐版本再通信 |
| **企业多租户** | 同一个 Agent 服务多个租户时的隔离支持 |
| **签名 Agent Card** | `signatures` 字段 + 扩展卡机制，防止恶意代理返回假卡片冒名 |
| **现代化安全流程** | 授权检查、webhook URL 校验等要求被写得更明确 |

**为什么 v1.0 反而有破坏性变更？** 因为 0.x 阶段语义还没冻结（semver 语义化版本里 `0.y.z` 不承诺兼容）。冻结版本时把之前模糊的地方定死，就会破坏旧实现。**这不是设计缺陷，是 0.x 阶段的正常代价。**

### 版本对照

| 版本 | 时间 | 说明 |
|------|------|------|
| 0.1.0 | 2025 年初 | 初版 |
| 0.2.6 | — | 迭代版 |
| 0.3.0 | 2025-07-30 | 加入 gRPC 与签名 Agent Card |
| **1.0.0** | **2026-03-12** | 首个稳定版 |
| **1.0.1** | **2026-05-28** | 当前最新 |

## 四、写新代码该对着哪个版本

**对着 v1.0.x。** 具体做法：

| 场景 | 做法 |
|------|------|
| 官方文档 / 教程 | 认准标注 `v1.0` 或 `protocolVersion: "1.0"` 的部分 |
| 搜到 2025 年的旧博客 | ⚠️ 大概率是 0.3 内容，注意 `url` 单字段 vs `supportedInterfaces` 数组的差别 |
| Agent Registry 里同时看到 1.0 和 0.3 两种 schema | Google Cloud Agent Registry 目前两者都接受，但**别把它当成「可以一直不迁移」** |
| 你有 0.3 的存量实现 | 见 [[a2a/02-中段阶段-生产实践/02-版本演进与迁移陷阱]] |

**识别老内容的信号**：Agent Card 里只有单个 `url` 字段（v1.0 用 `supportedInterfaces` 数组）、`protocolVersion` 写成 `"0.3.0"`、方法名是旧的 `tasks/send` 风格而非 v1.0 的重命名。

## 五、真实的生态热度

这一节写得保守些，因为宣传口径和实际使用量差距不小。

**支持与生态（项目方口径）**：

- 支持组织从 50+ 涨到 **150+**
- 官方 SDK 覆盖 **5~6 种语言**（Python / JS / Java / C#·.NET / Go / Rust）
- 核心仓库 GitHub star 超过 22000
- 已有生产落地：华为 Celia 与鸿蒙应用 Agent、Azure AI Foundry、AWS Bedrock AgentCore、Google Cloud（ADK / Agent Engine / Cloud Run / GKE）

**实际采用度（第三方实测数据）**：

| 指标 | A2A | MCP | 比值 |
|------|-----|-----|------|
| SDK 周下载量 | 约 450 万 | 约 9220 万 | **21 : 1** |
| GitHub 标签仓库数 | 593（`a2a-protocol`） | 34043（`mcp-server`） | **57 : 1** |
| 23 家被追踪厂商中已支持 | 8 家 | 广泛 | — |

⚠️ **两个必须诚实面对的事实：**

1. **23 家里支持的那 8 家，全部同时支持 MCP。** 没有一家「只支持 A2A 不支持 MCP」。
2. **Anthropic、OpenAI、Mistral、xAI 至今没有公开的 A2A 支持声明。**（这是第三方评测的观测，不是官方声明。）

**结论怎么下？** A2A 是**正确的长期架构边界**，但短期内它更像「必须理解的架构语言」，而不是「明天就要上手的工具」。学习它是为了在架构决策时不被落下，不是为了明天就替换掉现有的 REST 调用。

## 六、陷阱

1. **别照着 2025 年的博客学 A2A。** 那多半是 0.3 的内容，字段名和方法名都变了。
2. **别把「并入 AAIF」理解成「Google 刚把 A2A 开源」。** 顺序错了——捐赠发生在 2025-06-23，2026-08 只是组织归属调整。
3. **别被「150+ 支持组织」当成生产可用度。** 支持 ≠ 部署。要判断落地情况，看 SDK 下载量和仓库标签数。
4. **别因为 Anthropic / OpenAI 没表态就觉得 A2A 要黄。** 它们没做的是「兼容」，不是「反对」。横向协议最终只能有一个。
5. **别忽略 ACP 已经并入这件事的含义。** 它说明横向协议已经从「多套竞争」收敛到「一套」，这比任何单家的支持声明都更能说明 A2A 的位置。

---

## 小结

- 时间线：2025-04 发布 → 06 捐 LF → 08 收 ACP → 12 成立 AAIF → 2026-03 v1.0 → 08 并入 AAIF
- 三步治理的意义：私有 → 中立 → 统一，押错边的风险大幅降低
- v1.0 五项变化：多绑定、版本协商、多租户、签名 Agent Card、安全流程
- **v1.0 有破坏性变更**，新代码一律对着 1.0.x 写
- 生态热度要分开看：支持组织 150+，但 SDK 下载量只有 MCP 的 1/21
