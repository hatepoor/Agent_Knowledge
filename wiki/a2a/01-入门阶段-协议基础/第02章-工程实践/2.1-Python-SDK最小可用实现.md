# Python SDK 最小可用实现

## 学习目标

读完本篇，你应当能够：

1. 用 `a2a-sdk` 起一个能发布 Agent Card 的服务端
2. 用客户端拉卡、建连、发消息、读到 Task 对象
3. **亲眼看到** `submitted → working → completed` 的状态流转
4. 说清 `AgentExecutor` 里五步各自在干什么
5. 知道本地跑通和真实跨组织场景的差别在哪

## 一、先说清楚这篇的定位

⚠️ **本篇的目标是「看懂协议语义」，不是「搭生产级 A2A 系统」。**

跑通这一篇之后你会发现：**在本地两个进程之间走 A2A，比你想象的麻烦得多**——多一层序列化、多一次网络往返、多一套状态管理。这正好印证了 [[a2a/01-入门阶段-协议基础/第00章-学前准备/0.1-A2A是什么]] 的判断：**同一代码库内的 Agent 不该套 A2A。**

真正的价值在于：亲手看到 Task 状态机真的在动，看到 `input-required` 是怎么实现的。这些是纯读文档学不到的。

## 三、服务端：三块拼装

A2A 服务端在 SDK 里被拆成三个可替换的部件：

| 部件 | 作用 |
|------|------|
| **AgentExecutor** | 你的业务逻辑：收到消息后干什么 |
| **DefaultRequestHandler** | 协议层：把 RPC 调用路由到 executor，管理 task 生命周期 |
| **create_*_routes** | 传输层：把 handler 挂到 HTTP 路由上 |

### 3.1 写业务逻辑（Agent）

这就是一个普通的异步类，跟 A2A 无关：

```python
# agent.py
class HelloWorldAgent:
    """业务逻辑：真正干活的地方。"""

    async def invoke(self, user_request: str) -> str:
        return f'Hello, World! I have received your request ({user_request})'
```

### 3.2 写 Executor（协议适配层）★ 本篇核心

这是唯一需要理解 A2A 语义的地方：

```python
# agent_executor.py
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.tasks import TaskUpdater, new_text_message, new_task_from_user_message
from a2a.types import TaskState, Part


class HelloWorldAgentExecutor(AgentExecutor):

    def __init__(self):
        self.agent = HelloWorldAgent()

    async def execute(self, context: RequestContext, event_queue: EventQueue) -> None:
        # ① 取 Task：没有就新建一个
        if context.current_task:
            task = context.current_task
        else:
            task = new_task_from_user_message(context.message)
            await event_queue.enqueue_event(task)

        # ② 状态置为 working
        task_updater = TaskUpdater(
            event_queue=event_queue,
            task_id=task.id,
            context_id=task.context_id,
        )
        await task_updater.update_status(
            state=TaskState.TASK_STATE_WORKING,
            message=new_text_message('Processing request...'),
        )

        # ③ 跑业务逻辑
        query = get_message_text(context.message)
        result = await self.agent.invoke(user_request=query) if query else 'No text input!'

        # ④ 产出 Artifact
        await task_updater.add_artifact(
            parts=[new_text_part(text=result, media_type='text/plain')]
        )

        # ⑤ 置为 completed
        await task_updater.update_status(
            state=TaskState.TASK_STATE_COMPLETED,
            message=new_text_message('Request is completed!'),
        )

    async def cancel(self, context: RequestContext, event_queue: EventQueue) -> None:
        # 取消路径：把任务置为终态 canceled
        task_updater = TaskUpdater(
            event_queue=event_queue,
            task_id=context.current_task.id,
            context_id=context.current_task.context_id,
        )
        await task_updater.update_status(
            state=TaskState.TASK_STATE_CANCELLED,
            message=new_text_message('Task cancelled by client.'),
        )
```

**①②③④⑤ 各自对应什么**：

| 步骤 | 代码 | 对应概念 |
|------|------|---------|
| ① | `new_task_from_user_message` | 创建 Task → 状态 `submitted` |
| ② | `update_status(WORKING)` | 状态流转 `submitted → working` |
| ③ | `self.agent.invoke()` | 你的业务逻辑，A2A 不关心里面是什么 |
| ④ | `add_artifact(...)` | 产出交付物，挂在 Task 上 |
| ⑤ | `update_status(COMPLETED)` | 状态流转 `working → completed` |

📐 **记忆锚点**：这五步就是 [[a2a/01-入门阶段-协议基础/第01章-核心对象/1.4-Task生命周期与状态机]] 里那张状态图在代码中的投影。

⚠️ **`execute` 一个方法同时处理了「发消息」和「发流式消息」两种请求**——官方教程明确说明了这点。这也是为什么你用流式客户端调用时，`execute` 的代码完全不变，差别只在客户端侧。

### 3.3 组装服务端

```python
# __main__.py
import uvicorn
from starlette.applications import Starlette

from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_agent_card_routes, create_jsonrpc_routes
from a2a.server.tasks import InMemoryTaskStore
from a2a.types import AgentCapabilities, AgentCard, AgentInterface, AgentSkill
from agent_executor import HelloWorldAgentExecutor


skill = AgentSkill(
    id='echo_bot',
    name='Echo Bot',
    description='An example agent that acknowledges client request and responds.',
    input_modes=['text/plain'],
    output_modes=['text/plain'],
    tags=['a2a', 'echo-example'],
    examples=['hi', 'how are you'],
)

# 扩展卡：只对已认证客户端可见的额外技能
extended_skill = AgentSkill(
    id='echo_bot_super_mode',
    name='Echo Bot (Super Mode)',
    description='Responds with extra enthusiasm!',
    tags=['a2a', 'echo-example', 'extended'],
    examples=['super hi'],
)

public_agent_card = AgentCard(
    name='Hello World Agent',
    description='Just a hello world agent',
    version='0.0.1',
    default_input_modes=['text/plain'],
    default_output_modes=['text/plain'],
    capabilities=AgentCapabilities(streaming=True, extended_agent_card=True),
    supported_interfaces=[
        AgentInterface(
            protocol_binding='JSONRPC',
            url='http://127.0.0.1:9999',
            protocol_version='1.0',
        )
    ],
    skills=[skill],
)

extended_agent_card = AgentCard(
    name='Hello World Agent - Extended Edition',
    description='Full-featured hello world agent for authenticated users.',
    version='0.0.2',
    default_input_modes=['text/plain'],
    default_output_modes=['text/plain'],
    capabilities=AgentCapabilities(streaming=True, extended_agent_card=True),
    supported_interfaces=[
        AgentInterface(
            protocol_binding='JSONRPC',
            url='http://127.0.0.1:9999',
            protocol_version='1.0',
        )
    ],
    skills=[skill, extended_skill],
)

request_handler = DefaultRequestHandler(
    agent_executor=HelloWorldAgentExecutor(),
    task_store=InMemoryTaskStore(),        # ← 见下方「陷阱 1」
    agent_card=public_agent_card,
    extended_agent_card=extended_agent_card,
)

routes = []
routes.extend(create_agent_card_routes(public_agent_card))   # 暴露 /.well-known/agent-card.json
routes.extend(create_jsonrpc_routes(request_handler, '/'))    # 暴露 JSON-RPC 方法

app = Starlette(routes=routes)

if __name__ == '__main__':
    uvicorn.run(app, host='127.0.0.1', port=9999)
```

**几个必须注意的对应关系**：

| 代码 | 规范概念 |
|------|---------|
| `AgentInterface(protocol_binding='JSONRPC', ..., protocol_version='1.0')` | `supportedInterfaces[]` |
| `AgentCapabilities(streaming=True)` | `capabilities.streaming` |
| `create_agent_card_routes(...)` | 把 Agent Card 发布到 `/.well-known/agent-card.json` |
| `create_jsonrpc_routes(...)` | 选哪套协议绑定（也有 `create_grpc_routes` / `create_rest_routes`） |

⚠️ **路由可以直接挂到 FastAPI 上**，官方说明支持 Starlette 和 FastAPI 等 ASGI 框架。对你来说这很关键——FastAPI 的鉴权、限流、日志、OpenAPI 都能直接用。

## 四、客户端：四步走

```python
# test_client.py
import asyncio
import httpx

from a2a.client import A2ACardResolver, ClientConfig, create_client
from a2a.helpers import new_text_message
from a2a.types import Role, SendMessageRequest


async def main():
    # ① 拉 Agent Card（发现）
    async with httpx.AsyncClient() as httpx_client:
        resolver = A2ACardResolver(
            httpx_client=httpx_client,
            base_url='http://127.0.0.1:9999',
        )
        public_agent_card = await resolver.get_agent_card()
        print(public_agent_card)

        # ② 建客户端（非流式）
        client = await create_client(
            agent=public_agent_card,
            client_config=ClientConfig(streaming=False),
        )

        # ③ 发消息
        message = new_text_message('Say hello.', role=Role.ROLE_USER)
        request = SendMessageRequest(message=message)

        # ④ 收结果
        print('Response:')
        async for chunk in client.send_message(request):
            print(chunk)


asyncio.run(main())
```

**四步对应什么**：

| 步骤 | 代码 | 现实含义 |
|------|------|---------|
| ① | `A2ACardResolver.get_agent_card()` | 知道对方是谁、能干什么 |
| ② | `create_client(agent=card, ...)` | **根据卡片内容决定用哪套绑定**——这就是「协商」 |
| ③ | `new_text_message` + `SendMessageRequest` | 构造 Message，发起 Task |
| ④ | `async for chunk in client.send_message(...)` | 收结果。非流式只 yield 一个 |

⚠️ **第 ④ 步永远是 `async for`。** 这是初学者最容易卡住的地方——即使是非流式调用，SDK 的接口也是异步迭代器，你只是只迭代一次。写成 `result = await client.send_message(...)` 会报类型错。

### 换成流式：只改一行

```python
client = await create_client(
    agent=public_agent_card,
    client_config=ClientConfig(streaming=True),   # ← 只改这里
)
```

服务端代码**完全不用动**。你会收到四个 chunk：

```
task              ← 初始（submitted）
status_update     ← working
artifact_update   ← 产物
status_update     ← completed
```

> 这四个 chunk 就是 [[a2a/01-入门阶段-协议基础/第01章-核心对象/1.4-Task生命周期与状态机]] 的状态机在网络上的实时投影。建议对照着看一遍源码输出。

⚠️ **流式客户端用完记得关闭**：`await streaming_client.close()`，否则底层 HTTP 连接不释放。

## 五、自己动手加一个 `input-required`

这是本篇**最有价值的练习**。在 `execute` 里加一个分支，体验「远端中途反问」：

```python
async def execute(self, context, event_queue):
    if context.current_task:
        task = context.current_task
    else:
        task = new_task_from_user_message(context.message)
        await event_queue.enqueue_event(task)

    task_updater = TaskUpdater(
        event_queue=event_queue, task_id=task.id, context_id=task.context_id
    )
    await task_updater.update_status(
        state=TaskState.TASK_STATE_WORKING,
        message=new_text_message('Processing...'),
    )

    query = get_message_text(context.message)

    # ★ 关键：如果消息里带 confirmed 标记，说明是补充答复，走完成路径
    if query and query.startswith('confirmed:'):
        answer = query[len('confirmed:'):]
    else:
        # ★ 第一次进来：反问，把任务挂起
        await task_updater.update_status(
            state=TaskState.TASK_STATE_INPUT_REQUIRED,
            message=new_text_message('Please confirm: what should I greet?'),
        )
        return    # ← 提前返回，任务停在 input-required

    await task_updater.add_artifact(
        parts=[new_text_part(text=f'Hello, {answer}!', media_type='text/plain')]
    )
    await task_updater.update_status(
        state=TaskState.TASK_STATE_COMPLETED,
        message=new_text_message('Done.'),
    )
```

**跑一下你会看到什么**：

1. 第一次发消息 → Task 停在 `input-required`，`history` 里有一条 `ROLE_AGENT` 的反问
2. 带 `confirmed: World` 再发一次 → 同一个 Task 变成 `completed`，Artifact 是 `Hello, World!`

**这一段代码解释了 `input-required` 的全部实现要点**：

| 要点 | 为什么 |
|------|--------|
| 状态设为 `INPUT_REQUIRED` 后**提前 return** | 不 return 就会继续往下跑完，任务永远等不到补充信息 |
| 第二次进来要走 `context.current_task` 分支 | 这样新消息会**挂在同一个 Task 上**，而不是新建 |
| 反问用 `ROLE_AGENT` 的 Message | 服务端也会说话，这是 A2A 角色对称的设计 |

⚠️ **这就是「实现服务端时把 `input-required` 做成死胡同」的坑**——如果你每次都 `new_task_from_user_message`，客户端补信息时任务 ID 会变，之前的上下文全丢。

## 六、本地跑通 vs 真实跨组织

⚠️ **必须诚实说明：本地双进程跑通 ≠ 你已经会做跨组织 A2A 集成了。** 差别在这张表里：

| 维度 | 本地双进程（你刚跑的） | 真实跨组织 |
|------|---------------------|-----------|
| 网络 | localhost | 跨公网，有延迟和丢包 |
| 鉴权 | **无** | OAuth 2.0 / mTLS / API Key，必须实现 |
| TLS | 无 | **必须**，HTTP 绑定要求 HTTPS |
| Task 存储 | `InMemoryTaskStore` | 持久化存储（重启不能丢） |
| Agent Card | 本地可达 | 公网暴露 + 签名防冒名 |
| 多租户 | 无 | v1.0 支持，但你得实现隔离 |
| 授权 | 无 | **每个操作都要检查** |
| 限流/重试 | 无 | 必须有 |
| Agent Card 里的内部端点 | 随便写 | 要用扩展卡藏起来 |

**最短路径建议**：先用本地双进程把 Task 状态机玩熟（半天），然后直接读 [[a2a/02-中段阶段-生产实践/01-安全模型与鉴权]]。中间那些服务端代码（鉴权、限流、多租户）在真实项目里没人会从零写，都是在成熟框架的中间件里做。

## 七、陷阱

1. **`InMemoryTaskStore` 进程重启就丢。** 生产必须换持久化实现。这是最容易「本地好好的、一上线就崩」的点。
2. **`pip install a2a-sdk`，`import a2a`。** 包名带连字符，导入名不带。
3. **`send_message` 是异步迭代器，不是返回值的函数。** 即使非流式也要 `async for`。
4. **流式客户端用完要 `close()`。** 否则连接泄漏。
5. **`update_status(INPUT_REQUIRED)` 之后必须 return。** 忘了 return 任务会继续跑完。
6. **记得处理 `cancel`。** `AgentExecutor` 有两个方法，`cancel` 不实现的话取消请求会失败。
7. **路由挂 FastAPI 是完全支持的**，官方明确说明。别自己造轮子写 ASGI 适配。
8. **端口要和 `AgentInterface.url` 里的写一致。** 官方教程专门提醒了这点——不一致的话 Agent Card 声明的地址和服务实际监听地址对不上。

## 小结

- 服务端三件拼装：AgentExecutor（你的逻辑）+ DefaultRequestHandler（协议层）+ create_*_routes（传输层）
- `execute` 的五步：建 Task → 置 working → 跑逻辑 → 加 Artifact → 置 completed
- 客户端四步：`A2ACardResolver` 拉卡 → `create_client` 建连 → `SendMessageRequest` 发消息 → `async for` 收结果
- 流式只改客户端一行配置，服务端不动
- **`input-required` 的实现关键是「置状态 + return + 复用 current_task」三件事**
- 本地跑通只是理解协议语义，生产还差鉴权、持久化、TLS、多租户、授权
