# 生态现状与厂商支持

> **什么时候该读**：要选 SDK 或选云平台时；要做趋势判断时；要在面试里谈行业现状时。

## 学习目标

读完本篇，你应当能够：

1. 用**量化数据**而非宣传口径判断 A2A 的真实成熟度
2. 说出主流云平台对 A2A 的支持情况
3. 知道有哪些官方 SDK 和工具
4. 说清 AAIF 下的 agent 协议栈全景
5. 判断「现在投入 A2A 学习/集成」的时间窗是否合理

---

## 一、先说数据的来源和可信度

⚠️ **这一节最容易被宣传口径带偏，所以先把口径分清楚。**

| 来源 | 典型内容 | 可信度 |
|------|---------|--------|
| **项目方口径** | 「150+ 支持组织」「22000 stars」「SDK 生产就绪」 | ✅ 真实，但只反映**支持意愿**，不反映使用量 |
| **第三方实测** | SDK 下载量、GitHub 标签数、厂商支持扫描 | ✅ 更接近真实采用度，但样本有限 |
| **厂商案例** | 「某某公司已在生产环境大规模使用」 | ⚠️ 可能是试点或局部场景 |

**下面第四节全部用第三方实测数据**，并标明口径。做决策时用实测，做面试答调用项目方口径 + 实测一起说。

---

## 二、AAIF 的 agent 协议栈全景

理解 A2A 的位置，先看它和邻居的关系。**AAIF（Agentic AI Foundation）** 现在托管的项目：

| 项目 | 覆盖的层 | 干什么 |
|------|---------|--------|
| **AGENTS.md** | 指令与上下文 | 纯文本约定，告诉编码 Agent 如何在仓库里工作（OpenAI 贡献） |
| **goose** | Agent 运行时 | Agent 推理、规划、调用能力、执行工作的环境（Block 贡献） |
| **MCP** | Agent ↔ 工具 | 连接工具、数据源、应用、服务 |
| **agentgateway** | 流量治理 | 路由、策略、可观测性 |
| **A2A** | Agent ↔ Agent | 独立 Agent 之间发现、通信、委派、交换结果 |

**分层的记法**：

```
AGENTS.md   →  给 Agent 的说明书
goose       →  Agent 在哪跑
MCP         →  Agent 用什么
A2A         →  Agent 找谁帮忙
agentgateway →  Agent 的流量怎么管
```

**这说明一件事**：Agent 生态正在快速分层，A2A 是其中一层，不是全部。**它不替代 MCP，也不替代 Agent 运行时。**

> 相关：[[deepagents/overview/DeepAgents概述]] 属于「Agent 运行时」这一层。

## 三、量化数据：真实成熟度

### 项目方口径（2026 年数据）

| 指标 | 数值 |
|------|------|
| 支持组织 | 50+（2025-04 首发）→ **150+**（2026 年） |
| GitHub stars | 22000+ |
| 官方 SDK | Python / JS / Java / C#·.NET / Go / Rust（6 种） |
| 治理 | AAIF Growth Stage 项目，8 席 TSC |

### 第三方实测数据 ⚠️ 这组更能说明问题

| 指标 | A2A | MCP | 比值 |
|------|-----|-----|------|
| **SDK 周下载量** | 约 **450 万** | 约 **9220 万** | **21 : 1** |
| **GitHub 标签仓库数** | 593（`a2a-protocol`） | 34043（`mcp-server`） | **57 : 1** |
| **被追踪厂商支持数** | 8 / 23 | 广泛 | — |

**增长数据**：

- A2A Python SDK 同比增长 **1308%**——**增速比 MCP 的任一 SDK 都快**

⚠️ 这个数字要两面看：**高增速来自低基数**。从 10 万涨到 140 万是 +1300%，从 1000 万涨到 1300 万只是 +30%。**增速高说明势头好，绝对量说明还差得远。**

### 两个必须诚实面对的事实

| 事实 | 含义 |
|------|------|
| **23 家里支持 A2A 的那 8 家，全部同时支持 MCP** | 没有一家把 A2A 当成 MCP 的替代 |
| **Anthropic、OpenAI、Mistral、xAI 无公开 A2A 支持声明** | ⚠️ 这是第三方评测观测，不是官方声明。但两个头部模型厂商都没表态，值得注意 |

**为什么这两条重要**：MCP 的普及度有 Anthropic 的强力推动。A2A 目前**没有同级别的单一厂商推手**，靠的是联盟共识和云平台支持。这既是它的优势（中立），也是它的劣势（缺少一家死磕的推广者）。

## 四、云平台支持

已有真实支持的主要云平台：

| 平台 | 支持方式 |
|------|---------|
| **Google Cloud** | 通过 ADK 开发部署；Agent Engine、Cloud Run、GKE 都支持 |
| **Microsoft Azure** | Azure AI Foundry 可暴露 A2A 端点，也能发现外部 Agent |
| **AWS** | Bedrock AgentCore 可托管并运行 A2A 服务端 |

⚠️ 有报道称 Google Cloud、Azure AI Foundry、AWS Bedrock AgentCore 均已支持 A2A。**三家主流云都支持**，这是 A2A 相比一般新协议的重要背书——意味着它是**可以上企业采购清单**的状态。

### 移动与 OS 场景

一个有意思的落地：**华为**把 A2A 标准化为 Celia（鸿蒙 OS 级 AI 助手）与应用内 Agent 之间的协议，场景包括 Celia 派发长任务给应用 Agent、控制应用 UI 请求上下文推荐。腾讯微信是首批与华为及其他 Android OEM 助手通过 A2A 集成的应用之一，流程带双重授权。

**这个案例的战略含义**：A2A 在移动 OS 层面拿到了实际位置。这是从消费级入口倒逼出来的需求，不是厂商自己造的。

### 支付层：AP2

Google 的 **AP2（Agent Payments Protocol）** 建在 A2A 之上，为 agentic commerce 提供支付授权层：购物 Agent 和商家 Agent 在商品发现、定价、订单履约全流程用 A2A 通信，AP2 管支付授权。Coinbase 的 **x402** 是另一个同层协议。

**这是 A2A 生态里一个正在成型的扩展方向**，也说明 A2A 正在从「能通信」走向「能交易」。

## 五、SDK 与工具

### 官方 SDK

| 语言 | 仓库 |
|------|------|
| Python | `a2aproject/a2a-python` |
| JavaScript | `a2aproject/a2a-js` |
| Java | `a2aproject/a2a-java` |
| C#/.NET | `a2aproject/a2a-dotnet` |
| Go | `a2aproject/a2a-go` |
| Rust | `a2aproject/a2a-rs` |

⚠️ **六个 SDK 的成熟度不一定一致。** Python 最成熟（也是最常用的）；其他语言的 API 可能与 Python 有差异。选型时**以你用的语言的官方仓库为准**，别照 Python 教程硬套。

### 配套资源

| 资源 | 地址 | 用途 |
|------|------|------|
| **Python SDK** | `pip install a2a-sdk` | 库 |
| **示例仓库** | `github.com/a2aproject/a2a-samples` | 含与 LangGraph / CrewAI / Google ADK 的集成范例 |
| **命令行工具** | `github.com/a2aproject/a2a-cli` | 在终端里发现、发消息、管理任意 A2A Agent |
| **协议主页** | `a2a-protocol.org` | 规范、教程、博客 |
| **DeepLearning.AI 课程** | deeplearning.ai | Intro to A2A 入门课 |

⚠️ **注意区分 `a2a-python` 和 `a2a-sdk`。** PyPI 上装的是 `a2a-sdk`，GitHub 仓库叫 `a2a-python`。找资料时两个都搜。

### ⚠️ 其他标准的历史包袱

**ACP（Agent Communication Protocol）** 是 IBM 的横向协议，2025-08 已并入 A2A，独立发展已终止。**看到讲 ACP 的老资料可以跳过。**

**ANP（Agent Network Protocol）** 是面向开放互联网的去中心化 Agent 发现协议，早期阶段，定位是「未来的 Agent 市场基础设施」，不是 2026-2027 年多数企业需要规划的。

⚠️ **另外要注意缩写撞车**：`ACP` 这个缩写在支付领域另有所指（Agentic Commerce Protocol）。看到带 ACP 的资料先确认是哪个。

## 六、给学习者的建议

### 什么时间窗

| 判断 | 说明 |
|------|------|
| **值得投入学习** | ✅ 是。架构正确性已确立，三大云都支持，方向不会错 |
| **值得投入生产集成** | ⚠️ 谨慎。等真实跨边界需求出现 |
| **值得现在重构现有系统** | ❌ 不。你的 Agent 都在代码库内，见 [[a2a/02-中段阶段-生产实践/04-落地时机与不适用场景]] |

### 学习性价比排序

| 优先级 | 内容 | 理由 |
|--------|------|------|
| ⭐⭐⭐ | A2A vs MCP 的边界判断 | 直接影响你的架构决策，且不需要真写代码 |
| ⭐⭐⭐ | 五个核心对象 + Task 状态机 | 面试高频，理解成本低 |
| ⭐⭐ | 本地 SDK 跑通一次 | 半天时间，让概念变具体 |
| ⭐ | 安全模型与授权设计 | 有跨边界需求时再深入 |
| ⭐ | 版本迁移 | 有存量实现时再深入 |

### 面试里怎么答

如果被问「怎么看 A2A」，一个既不吹也不贬的答法：

> A2A 的架构定位是清晰的——MCP 管 agent 到工具，A2A 管 agent 到 agent，两者分层互补。现在它归到 Linux Foundation 的 AAIF 下和 MCP 同一屋檐，Google Cloud、Azure、Bedrock AgentCore 都支持，协议方向上不会有问题。但从实测数据看，它的采用度比 MCP 差一个量级（SDK 周下载量约 1/21），而且是较新的标准。所以我的做法是：把它理解透，在架构评审时能用它做判断，但不会主动在自己的代码库里引入它——跨治理边界才是它该出现的地方。

## 七、陷阱

1. **❌ 只看「150+ 支持组织」就以为生态很成熟。** 要看 SDK 下载量。
2. **❌ 把高增长率当成熟度。** 1308% 增长来自低基数。
3. **❌ 假设所有 SDK 成熟度一致。** Python 最成熟，其他语言的 API 可能有差异。
4. **❌ 照 Python 教程写 Go/Java 代码。** 先看对应语言的官方仓库。
5. **❌ 混淆 `a2a-python`（仓库名）和 `a2a-sdk`（PyPI 包名）。**
6. **❌ 看到 ACP 资料以为是新标准。** IBM 的 ACP 已并入 A2A。
7. **❌ 把 Anthropic/OpenAI 的沉默解读成 A2A 要黄。** 没做兼容 ≠ 反对。
8. **❌ 以为 A2A 会取代 MCP。** 分层互补，AAIF 同时托管两者就是答案。

## 小段

- **AAIF 项目栈**：AGENTS.md / goose / MCP / agentgateway / A2A，分层互补
- **量化对比**：SDK 周下载量 A2A:MCP ≈ **1:21**；GitHub 标签仓库 ≈ **1:57**
- 8 家厂商支持，**全部同时支持 MCP**；Anthropic、OpenAI、Mistral、xAI 无公开声明
- 三大云（Google Cloud / Azure AI Foundry / Bedrock AgentCore）均支持 —— **可上企业采购清单**
- 华为 Celia 把 A2A 用在鸿蒙 OS 层；AP2 建在 A2A 上做 agentic commerce 支付层
- **值得学、谨慎用、不重构**
