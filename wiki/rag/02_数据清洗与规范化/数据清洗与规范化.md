# 数据清洗与规范化（Cleaning & Normalization）

> 凡是进向量库的脏数据，都会在检索与生成端放大成错误；清洗是把不可控数据变成可控数据的关口。

## 核心结论

清洗环节是 RAG 管线里**最后一道还能放心「做删减」的关口**。

在这之前——接入、加载——你面对的是原始文件，删了还能重来；可一旦跨过清洗进入**切分（chunking）**，每一个删改动作都会沿着 `分块 → embedding → 索引` 整条链路传播：你删掉一段，它就不会出现在任何 chunk 里，也就不会进向量库，要补救只能**重新跑一遍全流程**。因此「该不该删」「删什么」的决策应当尽量在清洗阶段做完、做对，而不是留给下游去擦屁股。

更现实的一点是：下游是**混合检索**（智谱 embedding-3 稠密向量 + jieba/BM25 稀疏）。稠密向量对噪声相对钝感，但 **BM25 对高频重复词极度敏感**——这就是为什么本环节里「噪声剔除」与「去重」比在纯向量方案里更重要（详见 [[rag/02_数据清洗与规范化/噪声剔除|噪声剔除]] 与 [[rag/02_数据清洗与规范化/去重策略|去重策略]]）。

## 两条并行线

清洗不是单一动作，而是两条彼此配合的线：

- **向量线（标准 RAG）**：`清洗 → 分块 → embedding → 索引`。目标产出是给语义检索用的文本块。这条线要求文本干净、可比、无噪声，否则检索精度直接受损。
- **结构化线（结构化检索 / 图谱）**：在清洗阶段，把**可结构化的信息**——表格、实体、字段、键值——单独抽出，存进结构化存储（数据库 / 图谱），供 [[rag/05_查询转换与改写/查询结构化与槽位映射|结构化查询]] 与 [[rag/14_范式与前沿/GraphRAG与知识图谱|GraphRAG]] 使用。

两条线并行、互为补充：**向量线回答「这段话讲了什么」，结构化线回答「这个字段/实体是什么、和谁关联」**。一份 Word 文档既会被切成文本块进向量库，它的表格也可能被抽成行记录进结构化库。清洗阶段要同时服务于两者，而不是只考虑某一头的需要。

## 按数据源选清洗模板

不同来源的噪声特征差异巨大，清洗模板要对症下药。下表在原有基础上补了「展开页」列，方便按源查对应动作。

| 数据源 | 典型噪声 | 清洗重点 | 工具 | 展开页 |
|--------|----------|----------|------|--------|
| 网页 | HTML 标签、导航栏、广告、Cookie 提示、侧栏 | 正文抽取 + 正则剥离导航/广告 | `BeautifulSoup` / `html2text` | [[rag/02_数据清洗与规范化/噪声剔除\|噪声剔除]] |
| PDF | 页眉页脚、水印、多栏排版、公式渲染残留 | 按版面区域剥离 + 表格单独提取 | `PyMuPDF` / `unstructured` | [[rag/02_数据清洗与规范化/噪声剔除\|噪声剔除]] |
| Word（中英混排、含表格图片） | 修订标记、批注、样式冗余、模板页眉页脚 | 转 Markdown 保留标题层级，剥离模板噪声 | `pandoc` / `python-docx` | [[rag/02_数据清洗与规范化/文本规范化\|文本规范化]] |
| 数据库导出 | 字段拼接、NULL 值、编码混乱 | 类型统一 + 空值处理 | SQL + Python | [[rag/02_数据清洗与规范化/质量过滤\|质量过滤]] |
| API JSON | 嵌套层级、字段名不统一 | 拍平为统一 schema | `jq` / Python | [[rag/02_数据清洗与规范化/质量过滤\|质量过滤]] |

> 你的素材以**中英混排 Word 文档**为主（含表格与图片），PDF 次要。这意味着「文本规范化」与「噪声剔除（页眉页脚）」是最高优先级的两条动作，因为它们直接决定 BM25 检索质量。

## 陷阱与边界

- **过度清洗损伤语义**：把"必要的上下文"当成噪声删掉，会让下游回答缺胳膊少腿。校验标准是「下游能不能回答」，而不是「文本变短了」。详见 [[rag/02_数据清洗与规范化/噪声剔除|噪声剔除]] 的陷阱。
- **只清洗一次导致全链路泄漏**：脱敏只在清洗阶段做一次，但索引、缓存、日志、监控里若还有原文，等于没脱敏。见 [[rag/02_数据清洗与规范化/脱敏与隐私|脱敏与隐私]]。
- **去重键不稳**：以「内容 hash」为主、元数据为辅，避免同一文档在不同路径下被误判重复，也避免被误判为不同。去重比噪声剔除更危险——删的是整块内容，见 [[rag/02_数据清洗与规范化/去重策略|去重策略]]。
- **清洗不可重放**：程序化清洗应幂等、可重放，同样的输入永远产出同样的输出，并配合 [[rag/04_混合索引构建/索引与部署流水线|索引流水线]] 的版本化。否则换了环境或重跑一遍，结果对不上，事后无法追溯。
- **规范化顺序错乱**：先全半角再 Unicode 归一会漏处理（见 [[rag/02_数据清洗与规范化/文本规范化|文本规范化]]），这类"看起来没问题但悄悄失效"的坑最容易被忽略。
