# 去重策略（Deduplication Strategy）

> 去重决定"同一份知识在库里出现几次"。它比噪声剔除更危险——删的是整块内容，删错就永久丢失信息。正确做法是分层、按代价递增地兜底。

## 核心结论

去重分三个层次，代价从低到高、能发现的重复从"完全相同"到"换了说法也认得"。**不要一上来就上语义去重**——先用几乎免费的精确去重滤掉绝大多数副本，再用近重复兜住"改了几个字"的，最后才用贵的语义去重处理"同义改写"。三层是互补而非替代关系。

一个必须记住的反例：**中英对照文档不是重复**，应当各存一份、靠跨语言 embedding 对齐来召回（见下文）。还有：去重键要稳，否则要么漏去重、要么误删。

## 机制与原理

### 去重的三个层次

| 层次 | 方法 | 能发现 | 代价 |
|------|------|--------|------|
| 精确去重 | 内容 hash（对归一化后的正文算） | 完全相同的副本 | 极低（O(n) 查集合） |
| 近重复去重 | MinHash + LSH / SimHash / Jaccard 相似度 | 改动少量文字的副本 | 中（需维护签名与分桶索引） |
| 语义去重 | embedding 余弦相似度 > 阈值 | 换了说法但意思相同的段落 | 高（需 embedding + 近邻检索） |

### MinHash 的机制（近重复的核心）

目标：快速估计两篇文档的 **Jaccard 相似度** `J(A,B) = |A∩B| / |A∪B|`，其中 A、B 是文档的 shingle（n-gram 词集合）集合。

朴素做法是对每对文档算 Jaccard，复杂度 O(n²)，对成千上万 chunk 不可接受。MinHash 用概率方法近似：

1. 取 N 个独立的哈希函数 `h₁…hₙ`。
2. 对文档 D 的 shingle 集合 S，每个哈希函数取最小值：`sigᵢ(D) = min_{s∈S} hᵢ(s)`，得到长度为 N 的**签名向量**。
3. 两个文档签名向量的**重合比例**（`sigᵢ 相等` 的比例）在期望上等于它们的 Jaccard 相似度。

直觉：两个集合越重叠，它们各自的最小哈希值越可能落在同一个共有元素上，于是签名越容易相等。

**LSH（局部敏感哈希）** 用来避免两两比较：把签名向量按"波段（band）"分桶，只有落入同一桶的文档才两两比较。这样把 O(n²) 降到近似 O(n)，能在大规模语料上跑近重复检测。SimHash 是另一种思路（把文档映射成一个指纹位向量，用海明距离判断近重复），更适合"海量文档两两"场景，但精度与参数调校更敏感。

### 中文场景的特殊问题

英文近重复靠字面/词形就能抓得不错，但中文有额外干扰让"字面不同、语义相同"变得普遍：

- **简繁混用**：「云」vs「雲」、「计算」vs「計算」——同一语义不同字形。
- **全半角差异**：全角标点/字母 vs 半角，肉眼同、比特异。
- **标点差异**：中英文标点混用、空格有无。

这意味着：**中文场景里精确去重的作用比英文低**——很多该去重的副本，因上述差异逃过内容 hash。所以中文 RAG 更需要**近重复（MinHash/SimHash）或语义去重兜底**，单纯精确 hash 会留下大量近似副本，稀释检索相关度。前置动作是 [[rag/02_数据清洗与规范化/文本规范化|文本规范化]]（统一全半角、简繁建议也归一），能从源头减少这类伪差异。

### 反例：中英对照文档不要当重复去重

你此前讨论过这个坑，值得单独钉死：**一份中英对照的产品文档，不要因为"内容高度相似"就当重复删掉**。

正确做法：中英两份视为**独立文档各存一份**。现代多语言 embedding（如你用的智谱 embedding-3 具备跨语言对齐能力）会把同一语义的不同语言表述映射到相近向量，于是：中文用户用中文问，召回中文段；英文用户用英文问，召回英文段——**两者都能被召回，这是提升召回的免费加成**，而不是冗余。

若误把它们当重复去重，等于主动砍掉一半语言的覆盖，得不偿失。判定标准：两份文本是"翻译对照"关系（语义等价、语言不同），而非"复制粘贴"关系（字面相同）。

### 去重键的设计

- **以内容 hash 为主**：对**归一化后**的正文（先走文本规范化）算 hash，避免全半角/空白差异导致同文档被判不同。
- **元数据为辅**：仅用 hash 可能在"不同路径下的同一文件"或"同一内容不同格式"上判断不稳。可组合 `(归一正文hash, 源类型)` 作为复合键；但不要把"文件路径"本身纳入去重键，否则同文档换个目录就被当不同、漏去重。
- **语义去重用向量近邻**：候选由 MinHash 粗筛，再对候选算 embedding 余弦，超阈值判重复，避免对全量两两算 embedding。

### 过期去重（版本）

同一份文档迭代出 v1/v2/v3，如何处理？

| 策略 | 做法 | 取舍 |
|------|------|------|
| 只索引最新 | 检索只进最新版，旧版归档 | 干净，但丢失历史表述 |
| 全保留 | 各版本都进库 | 易召回过时内容，需版本元数据过滤 |
| 推荐折中 | 检索只索引最新；历史版本归档并保留版本关系便于追溯 | 兼顾准确与可追溯 |

建议：**检索时只索引最新，历史版本归档，但保留版本关系**（如 `doc_id + version` 关联），既避免旧内容污染召回，又在需要时能查"某说法哪版改的"。

## 实操

```python
import hashlib
from datasketch import MinHash, MinHashLSH   # 近重复:MinHash+LSH

def content_hash(text: str) -> str:
    norm = text.strip().lower()              # 依赖前置规范化
    return hashlib.sha256(norm.encode()).hexdigest()

def build_minhash(text: str, num_perm: int = 128):
    m = MinHash(num_perm=num_perm)
    for shingle in set(text.split()) :       # 以词为 shingle(可按需改 n-gram)
        m.update(shingle.encode('utf8'))
    return m

# 精确去重(先跑,几乎免费)
def exact_dedup(docs):
    seen, out = set(), []
    for d in docs:
        h = content_hash(d['text'])
        if h not in seen:
            seen.add(h); out.append(d)
    return out

# 近重复(LSH 分桶,避免 O(n^2))
def near_dup_lsh(docs, threshold=0.85):
    lsh = MinHashLSH(threshold=threshold, num_perm=128)
    unique, i = [], 0
    for d in docs:
        key = f"d{i}"; i += 1
        mh = build_minhash(d['text'])
        if lsh.query(mh):                    # 已有近重复
            continue
        lsh.insert(key, mh); unique.append(d)
    return unique
```

> 语义去重建议复用检索用的 embedding 模型与近邻索引（如 FAISS / Milvus），对 MinHash 候选集算余弦，避免独立再建一套。

## 陷阱与边界

- **误删导致信息永久丢失**：去重比噪声剔除更危险，因为删的是整块内容。务必先"标记 + 审计"再决定删，保留被删项摘要与位置（同 [[rag/02_数据清洗与规范化/噪声剔除|噪声剔除]] 的审计要求）。
- **阈值不可移植**：相似度阈值与 embedding 模型强相关。换 embedding（如从一版换到另一版）必须**重新校准**阈值，不能沿用旧值，否则要么漏去重、要么误删。
- **中英对照被误删**：如前所述，翻译对照不是重复。上线前用抽样人工核对"被判重复"的配对。
- **只在归一前算 hash**：未归一的正文因全半角/空白差异，同文档 hash 不同 → 漏去重。hash 必须建在归一文本之上。
- **近重复参数误设**：`num_perm` 太小签名不稳、`threshold` 太高漏检太低误删，需按语料规模与可接受误差调（待核实：具体取值建议按召回率实验确定）。
