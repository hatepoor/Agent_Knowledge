# 质量过滤（Quality Filtering）

> 质量过滤决定"谁有资格进向量库"。它和去重、噪声剔除是不同维度：噪声是"有字无信息"，低质量是"信息不够格"，重复是"已经有了一份"。三者合起来，才把脏数据挡在切分之前或之中。

## 核心结论

不是所有清洗后的文本都该进向量库。太短的残块（如只剩「2.3 节」）、纯乱码、纯导航、语言错配的块，进库只会稀释相关度、浪费存储与检索算力。质量过滤要**在切分之前（文档级粗筛）和之后（块级精筛）两级都做**：文档级先砍掉明显不合格的整篇，省算力；块级再对切出来的 chunk 做精确判定，因为很多噪声是切分后才暴露的。

核心提醒：**长度要按有效字符数，不要按字节数**；语言检测要**按 chunk 粒度**，不要按文档粒度。这两点对你这种中英混排 Word 素材尤其关键。

## 机制与原理

### 过滤维度总表

| 维度 | 判定思路 | 典型阈值（需按域校准） |
|------|----------|------------------------|
| 长度 | 按有效字符数判断，太短无价值、太长会截断 | 短：< 15–30 字丢弃；长：> 1500 字考虑再切（需校准） |
| 语言 | 按 chunk 检测语言，错配/低置信标记 `und` | 置信度 < 0.5 标 `und`，走字符级兜底 |
| 信息密度 | 停用词占比、独特词占比、标点占比 | 停用词占比 > 80% 或独特词占比过低 → 疑似无信息 |
| 乱码率 | 替换字符 U+FFFD 占比、非预期字符集占比 | U+FFFD 占比 > 1% 标记乱码（需校准） |
| 重复率 | 块内/块间自重复（见 [[rag/02_数据清洗与规范化/去重策略\|去重策略]]） | 块内连续重复行占比过高 → 剔除 |
| 结构完整性 | 是否残缺（断句、孤立编号、半截表格） | 仅含编号/标题残片 → 丢弃或合并上游 |

### 长度过滤

- **按有效字符数，不按字节数**：中文一个字通常占 3 字节（UTF-8）。若用 `len(bytes)` 比长度，中文块会被系统性高估 3 倍，导致"其实够长"的中文块被误删、"其实很短"的被放过。统一用字符数（`len(text)` 在 Python 对 str 即字符数）。
- **太短的残块无检索价值**：切分边界常产出只剩「2.3 节」「见图 1」的碎片，它们匹配任何查询都无意义，反而污染 top-k。
- **太长的会被截断**：超过 embedding 模型最大长度（如 8k/32k token）的块会被截断，截断处语义断裂。长块应在分块阶段就用更小窗口再切，而不是硬塞。

### 语言检测

工具选型：**`lingua` 准确率优于 `fastText` / `CLD3`**，尤其对短文本、对中文与邻近语言（日文、韩文）的区分更稳。`fastText` 在短文本上容易误判，`CLD3` 已不再积极维护。

**关键实践：按 chunk 粒度检测，不按文档粒度。** 你的素材是中英混排 Word 文档——一篇文档内部语言会切换（中文正文夹英文术语、英文摘要、代码注释）。若按"整篇文档一个语言标签"打标，要么整篇标错、要么中英混排被标成 `und` 全丢掉。正确做法：

- 每个 chunk 单独检测语言与置信度。
- 置信度低于阈值（如 0.5）的标 `und`，不直接删，而是走**字符级兜底**：代码块、公式、专有名词本就不该被语言判定，保留它们。
- 检索时若用单语 query，可据此路由——但中英混排本身应保留双语召回能力（参见 [[rag/02_数据清洗与规范化/去重策略|去重策略]] 跨语言对齐思路）。

### 信息密度

识别"看起来有字但没有信息"的内容（导航文本、菜单项、表格符号残留）。指标：

| 指标 | 含义 | 低信息信号 |
|------|------|------------|
| 停用词占比 | 的/了/是/and/the 等占比 | 过高（>80%）可能纯填充 |
| 独特词占比 | 不重复词 / 总词数 | 过低说明翻来覆去就那几个词 |
| 标点/符号占比 | 标点、特殊符号占比 | 过高（如一堆 `|`、`·`、箭头）像表格残片 |

注意：高停用词占比不等于该删——自然语言正文本就停用词多。要结合独特词占比一起看，并用"下游能不能回答"校验（同 [[rag/02_数据清洗与规范化/噪声剔除|噪声剔除]] 原则）。

### 乱码检测

- **替换字符占比**：U+FFFD（�）是解码失败的标志，占比异常高即乱码。
- **非预期字符集占比**：中文语料里突现大段西里尔字母、阿拉伯字母等，可能是编码错乱或 OCR 串扰。
- 边界：少量乱码可局部清洗，大面积乱码应整块标记待人工核查（标记 `（待核实）` 或丢弃），不要强行"修复"不可逆乱码。

### 文档级 vs 块级：两级都做

| 阶段 | 做什么 | 为什么 |
|------|--------|--------|
| 文档级（切分前） | 粗筛：整篇乱码、整篇过短、整篇语言不符 | 省算力，避免对明显垃圾做切分+embedding |
| 块级（切分后） | 精筛：残块、块内噪声、块级语言/密度 | 切分后才暴露的边界碎片，块级最准 |

取舍建议：**两级都做**。只做文档级会放过切分产生的残块；只做块级则白跑一遍切分（算力浪费）。文档级粗筛挡掉大头，块级精筛兜底——这是性价比最高的组合。

## 实操

```python
from lingua import Language, LanguageDetectorBuilder

detector = (LanguageDetectorBuilder
            .from_languages(Language.CHINESE, Language.ENGLISH)
            .with_minimum_relative_distance(0.5)   # 距离太小=>置信低
            .build())

def filter_chunk(text: str, min_chars: int = 15):
    # 1) 长度:按字符数
    if len(text.strip()) < min_chars:
        return False, "too_short"
    # 2) 语言:按 chunk 检测
    lang = detector.detect_language_of(text)
    if lang is None:
        return True, "und"          # 低置信,保留走字符级兜底
    # 3) 乱码:替换字符占比
    if text.count('\ufffd') / max(1, len(text)) > 0.01:
        return False, "garbled"
    # 4) 信息密度(示例:停用词占比)
    stop = sum(text.count(w) for w in ['的','了','是','and','the'])
    if stop / max(1, len(text)) > 0.4:    # 阈值需按域校准
        return False, "low_density"
    return True, str(lang)
```

## 陷阱与边界

- **阈值不可移植**：所有阈值（长度、密度、乱码率、语言置信度）都强依赖语料领域。技术文档 vs 小说 vs 法律文本，合理区间差异巨大，必须**按你的域做抽样校准**，不能直接抄表里的数字。
- **把短但有价值的元数据块误删**：术语定义、参数说明常是短块，但检索价值高。短阈值别一刀切，可结合"是否含定义性结构（如 `：`、`=`）"放行。
- **按字节数比长度**：如前所述，中文 3 字节/字会让阈值系统性偏移。统一用字符数。
- **对中英混排用单一语言阈值**：整篇打一个语言标签会误杀混排内容。务必 chunk 级检测 + `und` 兜底。
- **只在切分后过滤**：若只在块级过滤，前期切分+embedding 已对垃圾块花钱。文档级粗筛应前置。
