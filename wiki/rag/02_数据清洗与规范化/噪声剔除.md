# 噪声剔除（Noise Removal）

> 噪声是"占着 token、却不提供信息"的文本——它不报错、不崩溃，只会悄悄拉low检索质量。在混合检索里，最危险的一类噪声是页眉页脚。

## 核心结论

下游是 **BM25 + 稠密 embedding 的混合检索**。稠密向量对噪声相对钝感（语义大致还在），但 **BM25 是词频统计模型，对"高频重复词"极度敏感**。噪声剔除的第一目标，不是"让文本看起来干净"，而是**保住 BM25 的 IDF 区分度**——尤其要干掉那些几乎出现在每个 chunk 里的页眉页脚文本。

如果只做一件事，就做页眉页脚清洗；如果只记一个结论，就记：**页眉页脚是 BM25 的隐形杀手，它不报错，只是让所有检索结果整体变差，然后你花两周调 embedding 阈值也调不回来。**

## 机制与原理

### 噪声按来源分类

| 来源 | 典型形态 | 危害 |
|------|----------|------|
| 页眉 / 页脚 | 产品名、公司名、章节名、网址 | 高频重复，压垮 IDF（最危险） |
| 目录页 | 多行"标题…页码" | 纯导航文本，无检索价值 |
| 水印 | 短文本高频重复、每页同位置 | 同页眉，且更难用规则发现 |
| 导航栏 / 侧栏（网页） | 菜单、面包屑、登录入口 | 占据大量 chunk，稀释相关度 |
| 广告 / 赞助 | 推广文案 | 纯噪声 |
| 版权声明 | "Copyright / 版权所有" | 每文档重复，低频但无用 |
| 页码 | "第 12 页 / 12" | 数字噪声，干扰 term |
| 超链接残留 | `[文字](#)`、`href` 文本 | 导航文本残留 |
| 公式渲染残留 | 截图 alt、LaTeX 碎片 | 不可读碎片 |

### 为什么页眉页脚排第一危险（务必理解）

BM25 的核心权重是 **IDF（逆文档频率）**：一个词在越多文档里出现，它的区分度越低，IDF 越接近 0。IDF 公式大致是 `log((N - df + 0.5) / (df + 0.5))`，其中 `df` 是该词出现的文档数，`N` 是总文档数。

设想一份 50 页的产品手册，每页页眉都印着产品名「XCloud」。那么：

1. **df 被污染**：这个词出现在全部（或绝大多数）文档的几乎每一页，于是 `df ≈ N`，IDF 掉到接近 0。它对所有文档"一视同仁"，**彻底丧失区分能力**——本该靠产品名精确定位文档的机制废了。
2. **分数基线被整体抬高**：页眉页脚出现在**几乎每个 chunk** 里。BM25（以及很多重排序）对包含某词的 chunk 加分；当这个词在每个 chunk 都出现时，它给每个 chunk 都加了一份"无痛分"，等于把**所有 chunk 的相关性分数整体上抬了一个常数**。

后果是：真正相关的 chunk 和无关的 chunk 之间，因为都白捡了这份页眉分数，**相对差距被压缩**，真正该排第一的 chunk 再也"凸显"不出来。你看到的现象是：检索结果整体变平庸、top-k 里混入大量弱相关页、可调参也救不回来——因为根因不在排序，而在索引里混进了恒定噪声。

> 这正是一开始就该在清洗阶段解决的问题：它**不报错、不崩溃**，只是让检索" silently worse"，最容易被误判为"embedding 不行"或"分块策略不对"。

### 识别方法：跨页 / 跨段重复行检测

机制：把文档按行切开，对每一行（或先归一化后再看）统计它在整个文档中出现的次数；出现频率超过阈值的行，判为噪声。

阈值怎么定（与页数挂钩，而非固定值）：

| 文档规模 | 建议阈值（出现次数） | 思路 |
|----------|----------------------|------|
| 短文档（<10 页） | ≥ 3 次 | 短文档里重复 3 次已异常 |
| 中等（10–50 页） | ≥ 页数 × 0.6 | 出现在六成以上页面即高度可疑 |
| 长文档（>50 页） | ≥ 页数 × 0.5 | 长文档允许少量合法重复，阈值放宽 |

实现要点：
- **先归一化再比对**：用 [[rag/02_数据清洗与规范化/文本规范化|文本规范化]] 把全半角、空白压掉，否则同一页眉因微小空格差异被判成不同行，漏检。
- **按"行指纹"而非原始行**：对行做 strip + 归一后算 hash，比逐字符比较稳。
- **保留位置信息**：记录噪声出现在哪些页/行，供审计（见下文）。

例外——会被误伤的情况：
- **表格中的重复表头**：每页表格都带表头行，会被当成页眉删掉，但它是真实数据，不能删。
- **代码中的重复语句**：如日志格式行、循环体，会被误判。
- **合法重复短语**：如法律文本的"本合同"反复出现。

对策：对表格区域、代码围栏区域**豁免**重复行检测；或对"本身就是数据"的行降低敏感度。

### 目录页识别

特征：多行以「省略号 / 点号 + 数字页码」结尾，且**点号密度异常高**。例如：

```
1. 引言 .................... 3
2. 背景 .................... 7
3. 方法 ................... 12
```

判定思路：一行内若同时满足「末尾是数字」「中间点号（`.` 或 `…` 或 `·`）占比超过某阈值（如 >30%）」「连续多行同构」，则整体判为目录，整块剔除。注意区分"真的目录"和"带编号的列表"——列表行末尾通常没有页码、点号密度低。

### 水印识别

特征：一段**短文本在文档中高频重复**，且**位置规律**（每页相同相对位置，如居中、页脚）。与页眉的区别在于水印更短、更可能是图片 OCR 出的碎片文字或透明浮层文本。识别可结合「重复行检测 + 位置聚集度」：既高频、又总出现在固定坐标区间，判为水印。

### 可审计性

清洗必须记录"删了什么"。建议每条删除留存：

- 被删文本的摘要（前 N 字）
- 所在文档、页码 / 行号范围
- 命中规则（重复行 / 目录 / 正则）
- 时间戳

否则事后无法回答「为什么某条信息检索不到」——可能它根本没进库，也可能被你当噪声删了。审计日志还能在误删后回滚。这与 [[rag/11_安全审核与日志/审核与审计日志|审核与审计日志]] 的留痕要求是同一套思路。

## 实操

```python
import re, hashlib

def line_fingerprint(line: str) -> str:
    s = line.strip().replace('\u3000', ' ')
    s = re.sub(r'\s+', ' ', s).lower()      # 归一:去全角空格+压空白+小写
    return hashlib.md5(s.encode()).hexdigest()

def detect_repeated_lines(text: str, page_count: int, ratio: float = 0.6):
    lines = text.split('\n')
    fp_count = {}
    for ln in lines:
        if len(ln.strip()) < 2:            # 忽略空/极短行
            continue
        fp = line_fingerprint(ln)
        fp_count[fp] = fp_count.get(fp, 0) + 1
    threshold = max(3, int(page_count * ratio))
    noise_fps = {fp for fp, c in fp_count.items() if c >= threshold}
    return noise_fps

def remove_noise_lines(text: str, noise_fps):
    kept = []
    for ln in text.split('\n'):
        if line_fingerprint(ln) in noise_fps and len(ln.strip()) >= 2:
            continue                       # 记审计日志后再跳
        kept.append(ln)
    return '\n'.join(kept)
```

目录页快速判定（点号密度）：

```python
def looks_like_toc_block(lines, dot_ratio=0.30, min_rows=3):
    hits = [l for l in lines if re.search(r'\.+\s*\d+$', l.strip())
            or re.search(r'．+\s*\d+$', l.strip())]
    if len(hits) < min_rows:
        return False
    dense = sum(1 for l in hits
                if (l.count('.') + l.count('．')) / max(1, len(l)) > dot_ratio)
    return dense >= min_rows
```

## 陷阱与边界

- **把"必要的上下文"当噪声删掉**：页眉里偶尔夹带章节主题词，删了反而丢上下文。校验标准始终是「下游能不能回答」，而不是「文本变短了」。先小批量跑、用召回率验证，再全量。
- **表格里的重复表头被误删**：前述重复行检测会伤到表格表头。务必对识别出的表格区域豁免，或把"行本身是结构化数据"的行排除出噪声候选。
- **代码块中的重复语句被误判**：日志格式行、SQL 模板行等。对围栏代码块（``` 之间）整体跳过重复行检测。
- **只删正文不删残留超链接**：网页清洗常漏掉 `href` 文本或 `[文字]` 残留，它们变成无意义的导航 token，同样污染 BM25。正则剥离后建议再跑一遍重复行检测兜底。
- **阈值与文档规模强耦合**：用固定次数（如"出现 5 次就删"）在长文档会误杀、在短文档会漏检。务必用「页数 × ratio」这种相对阈值（见上表）。
