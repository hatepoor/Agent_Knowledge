# 生成校验与防幻觉（Groundedness & Verification）

> LLM 生成第 10 步的出口把关。在答案交付前，用两道相互独立的关卡验证"答案是否忠于证据"。生成本身的组装/提示词见 [[rag/10_LLM生成/LLM生成]]；批量回归度量见 [[rag/12_评估与监控/评估体系与RAGAS|RAG 评估体系]]。

## 概述

双重校验（double verification）指答案**交付给用户之前**经过的两道独立关卡：

1. **证据侧校验**——检索回来的块是否真的与问题相关、是否足够回答（对应 [[rag/14_范式与前沿/Agentic_RAG|Agentic RAG]] 的 grade-docs 节点、[[rag/09_上下文构建与溯源/上下文压缩|分块过滤]]）；
2. **生成侧校验**——答案是否**忠于**证据、每个论断是否有出处支撑（Groundedness / 引用核验 / CoVe）。

与 [[rag/12_评估与监控/评估体系与RAGAS|离线评估]] 的关系：同一机制（LLM-as-judge 判 Faithfulness/Groundedness），**离线评估是批量回归，双重校验是在线单例守门**。校验的目标不是让模型更聪明，而是**不让坏答案出门**。

## 一、理论依据：CoVe（Chain-of-Verification）

Meta 的 CoVe 论文（arXiv:2309.11495，ACL 2024 Findings）给出"模型可以自己核查自己"的系统证据，流程四步：

```
① Draft：生成初稿答案
② Plan：针对初稿规划一组验证问题（verification questions）
③ Execute：独立回答每个验证问题（关键：与初稿隔离，防被原错误污染）
④ Revise：依据验证结果生成最终修正答案
```

论文报告（Llama 65B）：Wikidata 列表任务精确率 0.17 → 0.36；MultiSpanQA F1 0.39 → 0.48；传记长文 FactScore 55.9 → 71.4。其中 **factored 变体**（验证问题独立作答、不复用初稿上下文）效果最好——这是"校验器必须与被校验对象隔离"的经典出处。

## 二、生产落地形态

### 1. 逐句/逐论断引用核验（最实用）

```python
# 生成后把答案拆成论断，逐条对照证据块判定 supported / not_supported
from pydantic import BaseModel
from langchain_openai import ChatOpenAI

class ClaimCheck(BaseModel):
    supported: bool          # 该论断是否被注入的证据块支持
    evidence_id: str | None  # 支持它的资料编号；无则置空
    reason: str

verifier = ChatOpenAI(model="gpt-4o", temperature=0).with_structured_output(ClaimCheck)

def verify_answer(answer: str, context_blocks: dict[str, str]) -> list[ClaimCheck]:
    results = []
    for claim in split_claims(answer):            # 按论断（非单句）切分
        results.append(verifier.invoke(
            f"证据：\n{context_blocks}\n\n待核验论断：{claim}\n"
            f"判定该论断是否被证据支持，并给出支持它的资料编号。"))
    return results
# 任何 supported=False 且无兜底说明的论断 → 拒答/重生成/降级输出
```

### 2. 在线 RAG Triad（TruLens 三元组）
Context Relevance（证据相关吗）→ Groundedness（答案有据吗）→ Answer Relevance（切题吗）在线打分，任一低分触发干预；离线则作为回归指标。

### 3. 校验失败的动作分级
| 校验结果 | 动作 |
|----------|------|
| 个别论断无据 | 删除该论断或标注"证据不足"后输出 |
| 核心论断无据 | 触发重检索/查询改写一轮（限次） |
| 仍失败 | 明确拒答并给出已确认部分 + 建议换问法 |

> 拒答是合法输出。宁可"资料中未找到"，不可输出无据生成。

## 三、成本与分级策略

双重校验每答案增加 1–N 次 LLM 调用，生产按风险分级：
- **全量**：仅规则校验（引用编号是否存在于证据清单、格式是否合法）——零成本，必做；
- **抽样/条件触发**：事实型答案、高风险领域（金融/医疗/法务）、低检索置信时，启用 LLM 逐句核验（可用小模型当校验器）；
- **全量 LLM 校验**：只给高价值/高风险链路。

## 四、常见问题

**Q1：校验器自己也会幻觉，双重校验不是自欺欺人吗？**
校验器与生成器**不必同模型**（用更强或不同供应商），且校验任务是"封闭世界判定"（只比对给定证据），比开放式生成难出错得多。CoVe 的 factored 设计证明"隔离作答"能显著降低继承性错误。仍需定期人工抽检对拍。

**Q2：双重校验和 Self-RAG/CRAG 重复吗？**
不重复：Self-RAG/CRAG 的校验发生在**循环中**（决定要不要重检索）；双重校验发生在**出口处**（决定答案能不能交付）。生产完备管线两者都有——循环内省成本，出口守质量。

**Q3：逐句核验会不会把答案拆得太碎、误杀合理表述？**
按"论断"而非"句子"切分（合并指代同一事实的连续句）；判定 prompt 明确"允许同义改写，不允许新增实体/数字/结论"；对否定句与条件句单独给示例（few-shot）。

**Q4：校验结果要不要给用户看？**
建议给轻量版：引用编号本就展示（证据链透明）；"证据不足"的论断直接不出现而非打标签——内部完整记录校验明细供观测（[[rag/12_评估与监控/在线监控与可观测性|可观测性]]），对外保持答案干净。

## 五、最佳实践

1. **规则校验先行，LLM 校验分级**：引用编号合法性、格式、敏感词是零成本必做项；LLM 逐句核验按风险触发。
2. **校验器与生成器隔离**（不同模型/不同上下文）——CoVe factored 变体的核心教训。
3. **把"校验拦截率"当质量观测指标**：拦截率突增通常意味着检索/索引侧出问题，而非生成变差。
4. **被拦下的坏答案自动回流 golden set**（[[rag/12_评估与监控/在线监控与可观测性|反馈闭环]]）——每一条被拦的坏答案都应变成一条回归测试。
