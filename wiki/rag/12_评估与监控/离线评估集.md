# 离线评估集（Golden Set & Regression）

> RAG 流程第 12 步一侧。**改变任何检索/生成环节之前，先有一份可重复跑的标注评测集**——否则优化就是在凭感觉调参。指标定义与 RAGAS 见 [[rag/12_评估与监控/评估体系与RAGAS|评估体系与RAGAS]]；线上实时观测见 [[rag/12_评估与监控/在线监控与可观测性|在线监控与可观测性]]。

## 概述

离线评估（offline evaluation）用一份固定、标注过的 "golden set" 对 RAG 系统批量打分，产出一个**可复现的回归基线**。它是"改检索参数、换分块、换 embedding"后判断"变没变好"的唯一客观依据。

## 一、golden set 三要素

| 要素 | 内容 |
|------|------|
| 查询 | 覆盖真实分布的 query（常见 + 边界 + 多跳 + 无答案） |
| 期望证据/答案 | 人工标注：每条 query 应命中哪些块（或标准答案） |
| 元属性 | 领域、难度、类型（事实型/推理型/检索型）——用来按切片分析 |

- **数量**：质量 > 数量，先做几百条高质量，再随坏样例回流扩增。
- **覆盖面**：必须包含"应拒答/资料不足"的用例，否则系统会倾向强行编答案。

## 二、回归跑法

1. **基线先行**：首次搭好即全量跑一遍，固化当前分数作为基线。
2. **成对比较（delta）**：凡是动检索/分块/改写，都在同一 golden set 上对比新旧分（Recall、Faithfulness、端到端 RAGAS 分…）。
3. **按切片归因**：不只看总分，按领域/类型切片看变化，定位"改好哪类、改坏哪类"。
4. **CI 门禁**：把 golden set 回归接入流水线，重要变更不达标禁止上线。

## 三、坏样本回流（数据集成长）

- **线上被拦截的坏答案**（[[rag/10_LLM生成/生成校验与防幻觉|校验拦截]]、用户反馈）自动回流 golden set——每一条失败都变成一条回归用例。
- **周期间抽样对拍**：抽样线上输出 → 人工打标 → 核对"离线分数是否还可信"（防 eval drift）。

## 四、常见问答

**Q1：离线指标好，线上却不行？**
可能 golden set 与真实分布偏移、或 LLM-as-judge 跑分与真实用户感知不一致。对策：golden set 定期翻新 + 线上闭环指标交叉验证。

**Q2：改一个分块参数，为什么总分别几乎没动？**
总分掩盖了局部变化——用切片分 + 具体用例 diff（哪个 query 命中变了）定位真实影响。

**Q3：要不要用更强的模型当 judge？**
judge 与生成模型最好不同/更强，且定期人工抽检对拍（[[rag/12_评估与监控/评估体系与RAGAS|RAGAS 裁判可信度]]）。


**覆盖面要求**：

| 类型 | 占比 | 作用 |
|------|------|------|
| 事实型 | ~40% | 验证基础召回 |
| 推理型 | ~20% | 验证多跳/组合 |
| 无答案型 | ~20% | 验证拒答能力（防幻觉） |
| 边界型 | ~20% | 验证近义/歧义查询 |

### 用 RAGAS 跑评估

```python
# pip install ragas
from ragas import evaluate
from ragas.metrics import (
    faithfulness,           # 忠实度：答案是否仅基于检索内容
    answer_relevancy,      # 答案相关性：答案是否切题
    context_precision,     # 上下文精确率：检索结果中有多少是相关的
    context_recall,        # 上下文召回率：期望答案中有多少被检索到
)
from datasets import Dataset

# 1. 用你的 RAG 系统跑 golden set，拿到检索结果和生成答案
rag_results = []
for item in golden_set:
    question = item["question"]
    # 检索
    retrieved_docs = ensemble_retriever.invoke(question)
    retrieved_contexts = [d.page_content for d in retrieved_docs]
    # 生成
    answer = rag_chain.invoke({"context": retrieved_contexts, "question": question})
    
    rag_results.append({
        "question": question,
        "answer": answer,
        "contexts": retrieved_contexts,
        "ground_truth": item["ground_truth"],
        "ground_truth_contexts": item["ground_truth_contexts"],
    })

# 2. 转成 RAGAS 格式
eval_dataset = Dataset.from_list(rag_results)

# 3. 跑评估
scores = evaluate(
    eval_dataset,
    metrics=[faithfulness, answer_relevancy, context_precision, context_recall],
)

print(scores)
# 输出示例：
# {'faithfulness': 0.92, 'answer_relevancy': 0.88,
#  'context_precision': 0.75, 'context_recall': 0.81}
```

### 回归对比：改了之后好不好

```python
import json

def regression_report(old_scores: dict, new_scores: dict) -> str:
    """对比新旧分数，输出 delta 报告"""
    report = []
    for metric in old_scores:
        old_v = old_scores[metric]
        new_v = new_scores[metric]
        delta = new_v - old_v
        arrow = "↑" if delta > 0 else "↓" if delta < 0 else "→"
        report.append(f"{metric}: {old_v:.3f} → {new_v:.3f} {arrow} ({delta:+.3f})")
    return "\n".join(report)

# 改分块参数前跑一次 → old_scores
# 改完后跑一次 → new_scores
print(regression_report(old_scores, new_scores))
# 输出示例：
# faithfulness:      0.920 → 0.945 ↑ (+0.025)
# answer_relevancy:  0.880 → 0.890 ↑ (+0.010)
# context_precision: 0.750 → 0.820 ↑ (+0.070)  ← 分块改对了
# context_recall:    0.810 → 0.790 ↓ (-0.020)   ← 但召回略降
```

### 四个核心指标含义

| 指标 | 衡量什么 | 什么时好 | 对应环节 |
|------|----------|----------|----------|
| **Faithfulness** | 答案是否忠实于检索内容（不编造） | 越高越好 | 生成 + [[rag/10_LLM生成/生成校验与防幻觉|校验]] |
| **Answer Relevancy** | 答案是否切题回答了用户问题 | 越高越好 | 生成 |
| **Context Precision** | 检索结果中相关的占比 | 越高越好 | 检索精度 |
| **Context Recall** | 期望答案所需的信息被检索到的比例 | 越高越好 | 检索召回 |

**诊断思路**：
- Context Recall 低 → 检索召回不够 → 加大 k、换 embedding、加分块
- Context Precision 低 → 检索噪声多 → 上 Rerank、调 RRF 权重
- Faithfulness 低 → LLM 编造 → 换 prompt、降温度、上校验
- Answer Relevancy 低 → 答非所问 → 换 prompt 或检查查询改写

## 六、最佳实践

1. **评估先行**：任何优化动作前先有 golden set 与基线。
2. **冻结测试查询，回归才可比**：golden set 版本化，别边改边加（新加进新版本）。
3. **把"拒答正确率"也纳入**，防止系统学坏（该答不答 / 不该答硬答）。
