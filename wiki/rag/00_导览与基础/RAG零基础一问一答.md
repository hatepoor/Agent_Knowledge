# RAG 零基础·一问一答（全链路关系线）

> 这篇是给**刚接触 RAG 的小白**读的"开卷导读"：把你的问题用一问一答讲清楚，并**在每句话后面告诉你"这是哪一步、为什么重要、和上一题是什么关系、详细版在哪个页面"**。读完能从"问题"一路串到"答案"，而不是一堆孤立的知识点。概念原理见 [[rag/00_导览与基础/RAG基础与演进全景|RAG基础与演进全景]]，想按步走通看 [[rag/RAG_学习路径导航|RAG 学习路径导航]]。

## 0. 先建立一个心智模型：RAG ≈ 开卷考试

RAG（检索增强生成）本质是**开卷考试**：LLM 不靠"背下来的记忆"答题，而是每次都要先**翻开资料库找证据**，再**照着证据写答案**。

```
提问
 │ ① 先把问题转成能检索的形式（查询改写）         ← 05 环节
 ▼
② 去资料库里"翻书"找最相关的几段（检索）      ← 03/04/06 环节
 │      └─ 有可能同时用"关键词找"和"语义找"，合并排序
 ▼
③ 把找到的证据整理好塞进提示词（上下文构建）    ← 09 环节
 ▼
④ LLM 照着证据作答，并标注出处（生成+溯源）     ← 10 环节
 ▼
⑤ 判断答得好不好、有没有成本问题（评估/监控）    ← 12 环节
```

这 5 句粗箭头对应的就是知识库 `wiki/rag/` 里的一条**完整流程**（编号 01→12）。下面所有问题，都落在其中某一步上。

## 1. 前提：为什么不用长上下文硬塞，非要 RAG？

- **Q：让模型一次性把整个知识库读进去不行吗？** 不行。知识库可能上万篇，远超模型上下文窗口，且每次都要重塞、贵、慢。
- **一句话**：RAG 的思路是**先精准找到相关的那几段，再只喂这几段**，海量知识只存不读。
- **关系和链接**：这是整个 RAG 存在的根本前提 → 概念详述见 [[rag/00_导览与基础/RAG基础与演进全景|RAG基础与演进全景]]；"长上下文 vs RAG"其实是互补不是互斥 → [[rag/14_范式与前沿/多模态与长上下文RAG|多模态与长上下文RAG]]。

## 2. 数据接入：RAG 的"资料"从哪来、怎么读

### 怎么处理 Word 文档、PDF 文档？
- **Q：我的知识是 Word/PDF，RAG 怎么读它们？** 读文件分两步：**先"解析"出可用的文本/结构，再"切块"建索引**。解析属于接入环节（本页 01），切块是下一环节（03）。
- **一句话**：Word 用 `python-docx` 或转 Markdown 读取；PDF 有文本层的用 PyMuPDF/pdfplumber，扫描件要上 **OCR/视觉模型**；**关键是把格式（表格、图片、标题）保真地挖出来，而不是拍平成一堆字**。
- **关系和链接**：这部分是本页 01 环节的核心内容 → 详细实操见 [[rag/01_多源数据接入/文档解析_PDF_Word_图片与表格|文档解析：PDF/Word 的文本表格与图片]]；接入的通用流程（Loader/Parser/元数据）见 [[rag/01_多源数据接入/多源数据接入|多源数据接入]]。

### PDF、Word 里的图片、表格、格式怎么处理？
- **Q：里面还有图表和表格，光抽文字够吗？** 不够。**表格**拍平成文本会丢掉"列和行的对应关系"（检索会漏、答案会错）；**图片**（扫描件/示意图）纯文字解析根本读不出来。
- **一句话**：表格要**保留 Markdown/HTML 结构**或转成"表格→自然语言描述"；图片用 **OCR 提文字 + 视觉大模型生成描述**，必要时把图片本身交给多模态模型。
- **关系和链接**：这部分是文档解析的难点 → 同样在 [[rag/01_多源数据接入/文档解析_PDF_Word_图片与表格|文档解析：PDF/Word 的文本表格与图片]]；"解析完还要清洗去噪"→ [[rag/02_数据清洗与规范化/数据清洗与规范化|数据清洗与规范化]]；"多模态/图文模型接入"→ [[rag/14_范式与前沿/多模态与长上下文RAG|多模态与长上下文RAG]]。

## 3. 核心概念：BM25 vs 向量检索——先说清"检索有两条路"

> 在讲"为什么用 BM25"之前，先建立关键前提：**RAG 的"翻书"有两种互不相同的检索方式**，BM25 是其中一种（词法路），另一种是向量检索（语义路）。二者各有所长，所以才有"为什么用 BM25"和"为什么不能只用 BM25"这两个问题。

### 为什么采用 BM25？
- **Q：明明有向量检索，为什么还要 BM25？** 因为**语义检索对"精确的专有词"常常失效**。比如查"型号 A100-80G 的显存"，向量模型可能把"显存"理解成别的，而 BM25 **数关键词**，能精确命中"只差一个字"的术语、编号、代码、产品型号。
- **一句话**：BM25 擅长**词面精确匹配 + 快 + 无需训练 + 可解释**，专治"向量检索记不住词面"的盲区。
- **关系和链接**：BM25 属于混合检索的一路 → 详细原理与代码见 [[rag/06_混合检索/混合检索|混合检索]]；它的打分身世（词频/逆文档频率）见 [[rag/04_混合索引构建/Embedding与向量检索|Embedding与向量检索]] 的对照。

### 单独使用 BM25 的话有什么缺陷？
- **Q：那只用 BM25 行不行？** 不行，有"词汇鸿沟"：**换个说法就搜不到**。查"成本"，文档写"费用"，BM25 完全不知道两者一个意思；还会把"词面撞车但语义无关"的段落带回来（噪声）。
- **一句话**：BM25 只看见"词面"，看不见"意思"——所以不能单独用。
- **关系和链接**：这是"为什么要混合检索"的半个理由 → [[rag/06_混合检索/混合检索|混合检索]]。

### 反之，单独用向量检索有什么缺陷？
- **Q：既然 BM25 有缺点，单独用向量检索呢？** 向量检索擅长语义近似，但**对专有名词/编号/生僻术语"无感"**，小语料下泛化也差，且要建向量索引、模型升级要全量重建。
- **一句话**：向量只看见"语义"，看不见"词面"——也不能单独用。
- **关系和链接**：向量检索的原理（Embedding/相似度/ANN 索引）→ [[rag/04_混合索引构建/Embedding与向量检索|Embedding与向量检索]]；缺陷与选型 → [[rag/04_混合索引构建/检索索引类型与混合索引|索引类型与混合索引]]。

### 那"混合检索 + RRF 融合"是什么？
- **Q：两条路都有短板，怎么办？** 两条路**一起跑**：BM25 召回 + 向量召回，再用 **RRF（倒数排名融合）**把两份排名合并成一份。
- **一句话**：RRF **只比名次不比分数**，天然解决"两份分数尺度不同没法直接比"的问题；**在两边都排前面的文档**胜出。
- **关系和链接**：这是第 6 环节的核心 → 公式推导与代码见 [[rag/06_混合检索/混合检索|混合检索]]。

### 为什么还嫌"检索不够准"，要再加"重排（Rerank）"？
- **Q：混合检索完了还不够吗？** 混合检索是大海捞针式的"**粗召回**"，质量一般；**重排**用更强的模型把 Top-K 精排一遍，只留最相关的 N 段，压低噪声。
- **一句话**：粗召回追求"别漏"（Recall 高），精排追求"别错"（Precision 高），两条工序配合。
- **关系和链接**：重排是第 7/8 环节 → [[rag/08_交叉编码器重排/重排序与交叉编码器|重排序与交叉编码器]]；它和混合检索的搭配节奏见 [[rag/06_混合检索/混合检索|混合检索]]。

## 4. 分块：为什么检索前要把长文切成块、切多大

### 为什么要分块？分多大？
- **Q：检索的单位是什么？** 是一段段的"块（chunk）"。整篇文档太长没法直接检索，所以要**切成小段**，每段切完变成"可被检索的一个条目"。
- **Q：切多大合适？** 没有万能值，经验起点 **单块 200–600 token**，配 20–50 的 overlap（重叠）。**太小吃不饱上下文、太大语义被稀释**，两个极端都有问题。
- **一句话**：块要"**大到语义完整、小到检索精准**"。
- **关系和链接**：分块的 5 种方法与大小调优 → [[rag/03_智能分块/文档分块策略|文档分块策略]]；"小块检索+大块返回"的生产姿势 → [[rag/03_智能分块/层级父子与句子窗口检索|层级父子与句子窗口检索]]。

### 分块有哪几种方法，怎么选？
- **一句话**：固定长度（兜底）→ 句子/段落（规范文本）→ 结构感知（Markdown/代码）→ 语义分块（主题跳跃、要高精度）→ 父子分块（问答、要上下文），按语料结构往右挑。
- **关系和链接**：每种的实现与适用时机的取舍，详见 [[rag/03_智能分块/文档分块策略|文档分块策略]]。

## 5. 检索之后：找到的证据要不要全塞给 LLM？

- **Q：检索出的 Top-K 直接拼给模型行吗？** 不一定。证据里常有**重复、无关、冲突**的段落，直接塞反而会"污染"答案。
- **一句话**：生成前通常要做**上下文构建（去重/组装）**和**压缩（只留最相关句子）**，必要时做**元数据过滤**。
- **关系和链接**：上下文组装 → [[rag/09_上下文构建与溯源/上下文构建|上下文构建]]；压缩 → [[rag/09_上下文构建与溯源/上下文压缩|上下文压缩]]；按来源/时间/类型过滤 → [[rag/07_元数据过滤/元数据过滤|元数据过滤]]。

## 6. 生成与可信：怎么防止"照着错的来源答 + 瞎编"？

- **Q：RAG 还会幻觉吗？** 会削弱、但不会消灭。要**要求模型只依据证据作答，并给出出处**，再做**引用校验**（答案是否真被找回的证据支持）。
- **一句话**：把"可信"从"靠模型自觉"变成"靠流程校验"。
- **关系和链接**：生成提示词 → [[rag/10_LLM生成/LLM生成|LLM生成]]；防幻觉的生成校验 → [[rag/10_LLM生成/生成校验与防幻觉|生成校验与防幻觉]]；出处引用 → [[rag/09_上下文构建与溯源/溯源与引用|溯源与引用]]。

## 7. 收尾：怎么知道 RAG 好不好，上线要注意什么

- **Q：怎么衡量 RAG 做得好不好？** 用**离线测试集 + RAGAS 指标**（召回 Recall@k、忠实度 Faithfulness 等）量化，而不是凭感觉。任何改动都要先有基线再对比。
- **一句话**：**先定指标，再动结构**。
- **关系和链接**：建测试集 → [[rag/12_评估与监控/离线评估集|离线评估集]]；指标体系 → [[rag/12_评估与监控/评估体系与RAGAS|评估体系与RAGAS]]；线上监控 → [[rag/12_评估与监控/在线监控与可观测性|在线监控与可观测性]]。
- **Q：上线还要注意什么？** 权限与敏感数据（**LLM08 向量投毒等安全面**）、延迟/成本（多路检索会翻倍）、多用户并发。→ [[rag/11_安全审核与日志/安全与合规|安全与合规]] · [[rag/13_工程横切/性能与成本优化|性能与成本优化]] · [[rag/13_工程横切/生产级RAG系统架构|生产级系统架构]]。

1. **第一遍**：顺着 0→7 走一遍，只要求"每个问题都答得上"，不追求记住细节。
