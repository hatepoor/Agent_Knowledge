# 溯源与引用（Provenance & Citation）

> RAG 流程第 9 步后半段。让"答案里的每一句都能指回证据来源"——既是信任的基础，也是 [[rag/10_LLM生成/生成校验与防幻觉|生成校验]] 能落地的前提。上下文组装见 [[rag/09_上下文构建与溯源/上下文构建]]。

## 概述

溯源的实质是：**保持"生成内容 ↔ 证据块 ↔ 原始文档"三者可追踪的映射**。没有溯源，检索质量再好用户也无法核验，错误也无法回溯修复。

## 一、三层溯源链路

```
答案论断 ──► 证据块(引用编号 [i]) ──► 原始文档(metadata: source/版本/时间/权限)
```

- **块级引用**：上下文组装时给每个证据块编号（`[i] (来源)`），生成强制标注编号。
- **文档级溯源**：每块 metadata 保留 `source`（路径/ID）、版本、时间、权限域。
- **生成级校验**：断言每个论断都被某个块支持 → [[rag/10_LLM生成/生成校验与防幻觉|生成校验]]。

## 二、引用协议设计

1. **引用编号必须"存在且不重复"**：生成只用组装时给定的编号；未出现在证据清单的编号可被机器判非法（零成本规则校验）。
2. **同时给文本引用 + 版本**：`[3]` 指向第 3 块，块 metadata 带版本/日期，模型可判断"哪份更新/官方"。
3. **允许同义改写，不允许新增实体/数字/结论**：引用校验 prompt 的判定边界，避免误杀合理表述。
4. **被压缩/提取的块保留原始映射**：[[rag/09_上下文构建与溯源/上下文压缩|压缩]] 后的文本是改写产物，需可回到原始块。

## 四、完整代码：从引用编号到溯源校验

### 组装时：给每块编号并注入元数据

```python
from langchain_core.documents import Document

def build_context_with_citations(retrieved_docs: list[Document]) -> str:
    """把检索结果组装成带引用编号的上下文"""
    blocks = []
    for i, doc in enumerate(retrieved_docs):
        src = doc.metadata.get("source", "未知来源")
        page = doc.metadata.get("page", "")
        loc = f" 第{page}页" if page else ""
        blocks.append(f"[{i}] (来源:{src}{loc})\n{doc.page_content}")
    return "\n\n---\n\n".join(blocks)

# 使用
context = build_context_with_citations(results)
# 输出示例：
# [0] (来源:product_manual.pdf 第12页)
# A100 的显存为 80GB，采用 HBM2e 高带宽内存...
#
# [1] (来源:tech_review.md)
# A100 在推理任务中表现出色，带宽达 2TB/s...
```

### 生成后：校验引用合法性

```python
import re

def validate_citations(answer: str, context: str) -> dict:
    """校验答案里的引用编号是否都存在于上下文中"""
    # 提取上下文里的合法编号
    valid_ids = set(int(m) for m in re.findall(r"\[(\d+)\]\s*\(", context))
    # 提取答案里用到的编号
    used_ids = set(int(m) for m in re.findall(r"\[(\d+)\]", answer))
    
    illegal = used_ids - valid_ids          # 用了不存在的编号
    unused = valid_ids - used_ids           # 有证据但没引用
    
    return {
        "valid": len(illegal) == 0,
        "illegal_citations": illegal,      # 编造的引用
        "uncited_evidence": unused,         # 没被引用的证据
        "citation_count": len(used_ids),
    }

# 使用
check = validate_citations(answer, context)
if not check["valid"]:
    print(f"警告：答案使用了不存在的引用编号 {check['illegal_citations']}")
```

### 前端展示：可点击的引用链

```python
def render_with_citations(answer: str, retrieved_docs: list[Document]) -> str:
    """把 [i] 渲染成可点击的引用链接"""
    import re
    def replace_citation(match):
        i = int(match.group(1))
        if i < len(retrieved_docs):
            src = retrieved_docs[i].metadata.get("source", "")
            return f'<sup><a href="#cite-{i}">[{i+1}]</a></sup>'
        return match.group(0)
    return re.sub(r"\[(\d+)\]", replace_citation, answer)

# 前端渲染后：
# A100 的显存为 80GB [1]，带宽达 2TB/s [2]
# [1] [2] 可点击跳转到原文档
```

## 五、常见问题

**Q1：LLM 不按格式标注引用怎么办？**
两个方案：(1) 用 `with_structured_output` 绑定 Pydantic schema，强制输出结构化引用；(2) 在 prompt 里给 Few-shot 示例，让模型"照着学"。后者更轻量，前者更可靠。

**Q2：引用校验拦截率太高，很多合理答案被误杀？**
检查校验规则是否过严——允许同义改写（如"80GB"→"80 G"），只拦截"新增资料中不存在的实体/数字/结论"，而非措辞完全一致。

**Q3：压缩后的块怎么溯源？**
压缩（[[rag/09_上下文构建与溯源/上下文压缩|压缩]]）是改写产物，需在 metadata 里保留 `original_chunk_id`，校验时回查原始块而非压缩后的文本。

**Q4：多轮对话怎么管理引用？**
每轮的引用编号独立计数；上一轮的引用在后续轮次中可标注为"[2, 上轮]"，避免编号冲突。同时在对话历史里保留每轮的 `context_snapshot`（证据块列表），供回溯。

## 六、最佳实践

1. **溯源是硬约束而非加分项**：无出处的论断默认不可输出。
2. **元数据即证据**：时间/版本/作者随块进 prompt（[[rag/09_上下文构建与溯源/上下文构建|上下文构建军规]]）。
3. **溯源与安全联动**：低信任来源（[[rag/01_多源数据接入/多源数据接入|接入]] 标记的 `trust_level`）在溯源里显式可见，供合规评估。
4. **引用编号在前端可交互**：点击跳转原文、悬停预览摘要——让用户能验证而非只能信任。
