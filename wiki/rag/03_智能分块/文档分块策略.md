# 文档分块策略（总览与决策）

> 分块是 RAG 里少数「改一个参数就影响全链路」的环节——它同时决定检索粒度、上下文完整性与索引成本。

## 核心结论

2026 年的主流选择很清晰：**递归字符分块 @ 512 token + 10~20% overlap 作为默认基线**。在规模最大的现实文档分块评测中，这一配置取得约 **69% 检索准确率**，领先固定分块，且与更贵的方法相比仍有竞争力。

但「基线」不是「终点」。所有进阶策略的正确用法是**叠加而非替换**：

- 文档**有结构** → 叠 **结构感知分块**（零成本，直接捕获章节边界）；
- 检索**精度成瓶颈**（召回够但粒度太粗） → 叠 **父子分块**（技术文档 recall@10 73%、客服 70%、法律 64%，比递归高约 5 个百分点，幻觉率降 30%）；
- **预算允许** → 再叠 **Contextual Retrieval**（每块加一次 LLM 前缀，检索失败率相对降 49%，叠加重排降 67%）或 **Late Chunking**（先长上下文编码再切，让短块带全文语境）；
- 特殊内容（代码、表格、图片） → 走 **特殊内容分块** 的分流。

一句话：**先有能跑的递归基线，再按瓶颈往上叠。**

## 三维分类框架

把全部分块方法放进三个正交维度，就能看清每个方法的「位置」和「可组合性」：

| 维度 | 取值 |
|---|---|
| 切在哪里 | 长度 → 符号 → 语义 → 模型决定 |
| 粒度关系 | 单粒度 / 父子 / 句子窗口 / 元素分流 |
| 嵌入时机 | Early（先切后嵌）/ Late（先嵌后切）/ Contextual（切后加前缀再嵌） |

- **切在哪里**：最粗的是纯长度（固定分块），然后是符号（递归、结构），再上是语义（相邻句向量距离突变点），最上是模型决定边界（LLM 辅助切分）。越靠右越贵、越准。
- **粒度关系**：单粒度是默认；**父子**（小块检索、大块返回）和**句子窗口**（命中句 + 邻近句回填）解决「检索细但上下文碎」的张力；**元素分流**把标题/表格/代码分别处理。
- **嵌入时机**（这是 2026 年特别关键的一维）：
  - **Early Chunking**：先切成块、再逐块 embed——最常见，但每块丢失全文语境；
  - **Late Chunking**：整文档先经长上下文编码，在句边界池化切块——短块也带全文语境，需要长上下文 embedding 模型（如 jina-embeddings-v3、voyage-3-large，注意你用的智谱 embedding-3 是否支持长上下文需核实）；
  - **Contextual Retrieval**：切后由 LLM 给每块写一段「这块在全文讲什么」的前缀，再 embed——代价是每块一次 LLM 调用。

> 三个维度可以任意组合。例如「结构感知（切在哪里=符号）+ 父子（粒度）+ Early（嵌入时机）」是技术文档的常见黄金组合。

## 选型决策路径

下面是一张文字流程图，按「文档长什么样」一路分流：

```
文档有结构标记吗？
├─ 有（Markdown/HTML/Word）→ 结构感知分块
└─ 没有 → 有段落/句子标点吗？
          ├─ 有 → 递归分块
          └─ 没有（连续口语/OCR 噪声）→ 语义分块
代码 → AST 分块（独立分支）
需要更高精度时叠加：父子分块 / 元素级分流 / Contextual Retrieval
```

把这个路径落到具体操作：

1. **先看结构化标记**：Word 的标题样式、Markdown 的 `#`、HTML 的 `<h1>`~`<h6>`、LaTeX 的 `\section{}`、代码的 AST 节点——只要有，一律走结构感知（见 [[rag/03_智能分块/结构感知分块]]）。
2. **退一步看自然边界**：没有结构但还有段落/句子（绝大部分正文文档），递归分块足够（见 [[rag/03_智能分块/固定与递归分块]]）。
3. **最差情况**：完全是连续口语、OCR 噪声、没有标点断句，才动用语义分块（见 [[rag/03_智能分块/语义分块]]）。
4. **代码永远独立分支**：按函数/类/AST 节点切，不要塞进通用递归器（属于特殊内容分块）。
5. **精度不够时再叠加**：父子分块解决粒度，Contextual Retrieval 解决语义模糊，Late Chunking 解决短块缺语境。

## 反直觉判断：语义分块是被滥用最多的策略

这是 2026 年最值得反复强调的一条结论：

**语义分块是「最被讨论、也最被滥用」的策略。**

- 它的索引开销比递归分块**慢约 14 倍**（要为每个句子做一次 embedding）；
- 准确率增益**往往小到测不出来**；
- 而当你把文档整理得「有结构、话题统一」时，递归或结构感知分块能**免费**捕获同样的边界。

所以「一上来就上语义分块」是这一年最典型的误用。它只在一个窄场景真正发光：**内容话题突变且无结构可用**——研究报告在方法论/结果/政策含义间反复跳转、多来源拼接的法规、话题跳跃的客服通话。其余情况，先递归、再结构，已经够了。
