# 重排序与交叉编码器（Cross-Encoder Rerank）

> 检索链路第 8 步。多路召回见 [[rag/06_混合检索/混合检索]]；在融合后（或单路）用更强的交互式模型做精排，直接决定"喂给 LLM 的 Top-N 干不干净"。

## 概述

分两段完成"召回→精排"：
- **双塔（bi-encoder，即 Embedding）先粗召回**：Top-50~100，便宜、快，只管"像"；
- **Cross-Encoder 重排**把查询与每个候选拼接后过一遍 Transformer 精排（Top-5~10），交互建模远强于双塔，是 2025 生产 RAG 的标准动作。

从"像"（semantic similarity）到"真相关"（query-document relevance），重排用更强的交互建模换取更准的排序。

## 一、为什么需要重排

| 阶段 | 模型 | 速度 | 精度 | 角色 |
|------|------|------|------|------|
| 粗召回 | bi-encoder（Embedding 相似度） | 快、可 ANN | 像≠相关 | 放大概率，召回 50–100 个候选 |
| 精排 | Cross-Encoder | 慢（交互过一遍 Transformer） | 相关性强 | 只留 5–10 个最相关的 |

> **默认选型（先照这个走）**：中文 / 自托管 → **bge-reranker-v2-m3**（中文效果好、可本地部署）；托管 API → **Cohere Rerank v3.x**（开箱即用、表现稳定）。只有明确需要（数据不出境 / 超大吞吐 / 领域差异明显）才考虑 Jina、Voyage、Qwen3-Reranker 等替换。

## 二、代码示例

```python
# 用 LangChain + Cohere Rerank（或本地 bge-reranker）做"粗召回 → 精排"
# pip install -qU langchain-cohere
from langchain_cohere import CohereRerank
from langchain.retrievers import ContextualCompressionRetriever

base = vectorstore.as_retriever(search_kwargs={"k": 50})   # 粗召回放大候选
reranker = CohereRerank(model="rerank-v3.5", top_n=5)      # 精排只留 5
compressor = ContextualCompressionRetriever(
    base_compressor=reranker, base_retriever=base
)
final = compressor.invoke("query")
```

## 三、三条关键认知

1. **重排只负责"排序更准"，不负责"召回更多"**——召回上限由粗召回决定，所以粗召回 k 要给足（50–100）。
2. **重排增加一次模型推理延迟（几十~几百 ms）与成本**：用"小候选集 + Cross-Encoder"与"重排结果缓存"缓解。
3. **重排分数与向量相似度不可混比**：别拿重排分数做全局阈值（分数分布含义不同）。
4. **重排 + LLM listwise**：零样本 listwise 重排（LLM 对整列候选排序取 Top-k，arXiv:2305.02156）可作为无托管 Cross-Encoder 时的备选，需模型支持 structured output。

## 四、何时需要重排

- 混合或多路召回后有大量噪声 → 必上（保 Precision）；
- 对延迟极敏感 → 缩到 `top_n=3` 或用小模型；
- 候选本身已经很准、查询模式单一 → 可评估后省略。

## 五、常见问题

**Q1：重排模型要不要领域微调？**
通用重排模型基线已强；数据量大且有明确领域后，可用领域 Pairwise 数据微调 bge-reranker 系，收益常高于微调 Embedding。

**Q2：过滤、压缩、重排的执行顺序？**
先 [[rag/07_元数据过滤/元数据过滤|过滤]]（便宜、缩候选）→ 再重排（Cross-Encoder 一次见全体做全局比较）→ 需要时再压缩。顺序见 [[rag/09_上下文构建与溯源/上下文压缩|上下文压缩]] 的管线。

## 六、最佳实践

1. **管线顺序固定**：粗召回（大 k、混合）→ RRF 融合 → Cross-Encoder 精排（小 top_n）→ 上下文压缩。
2. **记录重排分数分布与 top_n 留存率**：可观测到"第 N 名与第 N+1 名差距"是否值得扩大候选窗。
3. **结果保留来源元数据**，供生成环节做引用与置信过滤（[[rag/10_LLM生成/生成校验与防幻觉|生成校验]]）。
